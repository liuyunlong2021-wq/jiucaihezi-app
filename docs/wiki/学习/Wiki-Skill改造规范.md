# Wiki Skill 改造规范

本规范用于把 Wiki Skill 改造成记忆工作台的模型能力外挂。用户只说目标，模型根据内容、项目状态和工具自主决定做什么；Skill 负责提供能力、边界和可验证的输出标准，而不是把专业流程和选择题交给用户。

## 1. 名称与目录、发现

- `SKILL.md` 的 `name`、目录名、注册表 `id` 与 `name` 必须完全一致，且使用 1-64 个小写字母、数字和连字符。
- `description` 以 `Use when ...` 开头，覆盖用户自然会说的目标词，不要求用户记忆 Skill 名称或流程术语。
- 删除欢迎闸门和能力菜单。用户目标明确时直接工作；只有事实冲突、不可逆操作、权限不足或目标确实不明时才提问。

## 2. 模型自主决策

每个 Wiki Skill 必须明确：**用户只表达目标，模型自主判断方法。**

1. 读取用户内容、现有 Wiki、Raw 与项目状态。
2. 判断内容语境和信息状态，而不是要求用户选择“小说模式”“关系图模式”。
3. 从可用能力中组合必要动作；不需要的能力不做。
4. 按能力标准输出、验证并报告实际结果。

Skill 可以给出“何时有价值”的判断信号，但不能把它写成“用户说某口令才允许做”。模型的判断不等于随意：事实来源、安全边界、输出格式和验证要求必须固定。

## 3. Reference 按需存在

默认只保留 `SKILL.md`。只有模型本身不知道、任务反复需要且无法用少量正文表达的产品协议，才增加 Reference 或脚本。

- 不按小说、漫剧、开发、广告等项目类型预置目录模板；现有 Wiki 结构和用户目标是真实依据。
- 不把一个 Skill 的职责拆成大量“能力标准”后再强制全部路由；先判断这些能力是否应该属于同一个 Skill。
- Canvas、Bases 等文件格式不是新建 Skill 或 Reference 的理由；Skill 按用户任务划分。
- Reference 不得复制模型常识、用户教程、历史设计过程或未来可能需要的模板。

## 4. 主 Skill 的写法

主 `SKILL.md` 必须清楚写出：

1. **功能说明与边界**：解决什么、不解决什么。
2. **用户入口**：用户可用自然语言表达的目标。
3. **输入范围**：模型读取什么，以及明确不默认扫描什么。
4. **不可破坏规则**：事实、权限、原文、已有结构与冲突处理。
5. **Reference 索引**：仅在包内确有 Reference 时提供。
6. **验证与报告**：实际写入、验证命令和未验证项必须如实报告。

不要把小说、开发、Canvas 等模型已知细节堆进主 Skill；也不要用固定线性步骤压制模型根据任务选择最少动作。

## 5. Raw 与派生 Wiki

- Raw 是原始过程与证据，保留在真实位置；Wiki 是结论、结构和导航。
- Raw 不复制、不移动、不删除。记忆工作台对话只从当前项目 `.raw/对话记录/*.md` 定位，Markdown 是唯一持久化真源；VS Code 使用当前项目工作区的 `chatSessions/`。
- 重要 Wiki 结论必须可通过 `来源索引.md` 回到 Raw、原始文件、SDD、代码、Git 或测试证据。
- 新证据统一登记 Wiki 章节、来源角色、真实来源、已处理范围、写入时完整 SHA-256 和带时区记录时间；项目内来源使用 App 原生 `wiki evidence` 按原始字节计算。原件和 Markdown 可读副本分行登记，无法计算时写明原因，不伪造指纹。
- Raw Wiki 只沉淀确认信息。关系图和标准 `.canvas` 由查询 Skill 生成；普通统计由查询 Skill 回答或按需保存为 Markdown 表格。App 支持 `.base` 解析与显示前不生成 `.base`。
- 不得创建 `对话记录/`、会话摘要页或聊天转录页来复制 Raw。用户明确交付或确认的正式作品正文可以进入其正式正文目录，但不能把含讨论的整段会话搬进去。

## 6. 写入与安全

- 先接管已有 Wiki；不存在时由模型调用建库 Skill 建立骨架，再继续填充。禁止创建平行目录或假装已写入。
- 只写有来源的结论。已有正文不整篇覆盖；内容冲突、正式稿判定、合并、移动、删除必须向用户确认。
- 沿用项目已有 `docs/wiki/` 或 `wiki/`；新建记忆空间由 App 建立 `wiki/`，Skill 不创建平行库。
- 语义判断由模型完成；只有重复、脆弱且需要确定性的操作才增加脚本。

## 7. 验证与留痕

改造前先补会失败的契约测试，至少覆盖：

- 名称、目录和注册表一致；
- 主 Skill 明确“用户说目标、模型自主判断”；
- Skill 包只包含实际需要的文件，Reference 和脚本没有空壳或重复内容；
- 输入范围、来源追溯、已有 Wiki 安全和跨 Skill 交接；
- 注册表、旧路径检索和 `git diff --check`；有脚本时再验证脚本行为和语法。
- 涉及重要结论时，验证 Raw 写后登记、Cha 两层引用和 Jian 来源状态巡检；来源变化只标记待复查，不自动判定事实错误。

从旧 Skill 改造时，契约测试还必须验证：旧目录、旧名称、旧 Reference 路径和旧 Skill 引用均已清零；注册表只列出实际存在的文件；旧的启动闸门、欢迎语和 A/B/C 菜单已删除。

测试通过只代表合同与脚本通过；没有进行的模型质量或人工验收必须明确标为未验证。
