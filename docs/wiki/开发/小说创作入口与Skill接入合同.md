# 小说创作入口与 Skill 接入合同

> 2026-10-22 现行接入合同：三个按钮只圈定 `public/skills/production-skills.json` 中的业务 Skill 白名单，由官方目录与 skill 工具渐进加载；无自建路由、每轮自动调用或旧路由规则迁移。漫剧14个、短剧4个、小说1个。电脑操作沿原设置开关，默认关闭。业务 Skill 正文与资源原样保留，Wiki/present能力保留。队列、恢复、多会话、子任务和历史兼容的源码实现与本地验证见 [[三创作入口删除自建路由与DSH官方Skill范围接入TDD-2026-10-22]]。未发布，真实安装版/跨平台/用户数据升级未验收。

## 现行入口规则

按钮只选择范围，不选择一个“总入口Skill”，不在每轮自动加载正文。手动选择Wiki仍有效，创作按钮不再自动注入Wiki索引；业务交付按实际加载的业务Skill与用户请求执行，不从旧路由补回公共规则。历史按钮ID只恢复选择，旧记录不清洗、不重放为新路由调用。

## 用户入口

- Desktop 输入框下沿创作入口顺序为「漫剧制作」「短剧写作」「小说创作」。
- 点击按钮只切换模式，不自动读取项目或生成内容。用户明确提出续写、修订、规划或复盘时直接进入相应任务；只有任务未定且无可承接节点时才展示 A/B/C。
- 小说模式自动选择 `jc-novel` 与其必需依赖 `wiki-memory`；若用户此前手动选择了 `wiki-memory`，退出时保留它，否则移除自动加入的依赖。
- 三个创作路由互斥。会话目录分别记录 `manju`、`shortDrama` 和 `novel` 偏好；切换时自动处理短剧历史偏好并保留原会话路由状态。
- 小说模式的 Skill 选择器只展示 `jc-novel`、`wiki-memory`；用户通过三个模式按钮切换路由。

## Skill 与文件树

- `public/skills/jc-novel` 是唯一准源，完整保留全部 references/engines；`public/skills/index.json` 登记整个包。用户于 2026-10-09 明确允许删除个人目录副本，来源历史保留在 Git 与既有开发记录。
- `jc-novel` 负责小说创作，`wiki-memory` 负责读取当前项目 Wiki 与归档规则；Agent scope 内的 `wiki_save_artifact` 依据共享产物映射落盘。短剧和漫剧模式复用同一工具、根选择与索引合同。
- 创作规划和资产使用类型化映射保存；章节先落在 `创作/章节草稿/<作品>/第NNN章.md`。用户明确确认且传入正文与草稿完全相同后，才追加到 `原始材料/<作品>/原文.md`；发现已有相同章节时不重复追加，不同内容时拒绝覆盖。
- 来源追加验证成功后，原草稿页转换成确认记录，包含 SHA-256 指纹与指向正式原文的双链，避免在 Wiki 里留两份相同正文。转换失败时保留草稿并返回 `saved_with_warnings`；重试会检测已有章节并补齐转换，不重复追加。
- 故事拆分与章节分析沿用原生工具，不手工创建 source node 或 source hash。章节确认和拆分仍是两个不同动作；章节保存不自动启动分析。
- 共享工具的成功回执包含真实项目相对路径；Harness 对三条创作入口统一刷新并定位当前项目文件树。

## 变更边界与验收状态

- 任务优先路由、参考读取条件与引擎选择已升级；默认逐章确认继续保留，Runtime 校验确认正文与已保存草稿完全一致。分批输出、短回复或“继续”不自动确认章节。
- 100个引擎按真实相对链接可达；基础任务可读0个，需要时选1个主引擎与最多2个条件引擎。当前任务共用最多3个不同引擎的读取额度，不再要求正文四阶段固定连调二十多个引擎。
- 升级范围、失效资源修正及典型请求验收见 [[开发/小说创作Skill路由升级与验收-2026-10-09]]；包索引在构建脚本重建，归档继续由内置 Wiki 规则和共享 Runtime 执行。
- 聚焦自动化已覆盖小说路由、共享工具注册、草稿／确认／来源追加、索引与确认记录恢复。真实模型、Desktop 按钮和文件树人工验收、跨平台安装包尚未完成。
