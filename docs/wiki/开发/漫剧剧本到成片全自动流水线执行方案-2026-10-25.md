# 漫剧剧本到成片全自动流水线执行方案

> 2026-10-25 规划稿。P0 已实施；P1 调度内核已实施、尚未接入触发入口（见 §7）；P2–P3 未实施。用户提出：资产提示词生成后立即提交生图、不等待；视频提示词写完后再检查资产、补生成，资产齐全后按@图顺序提交视频、不等待；随后直接进入下一集。本方案在此基础上补全缺失环节。
>
> **这是合同变更**：[[开发/漫剧制作合同]] 2026-10-21 条款规定“漫剧路线只交付文字与提示词，不调用生成或提交工具”。实施前须由用户确认取代该条款，并在合同页写明新边界。

## 0. 核心决策：媒体调度交给程序，不交给模型

| 职责 | 负责方 | 原因 |
| --- | --- | --- |
| 写资产、工程、视频提示词 | 模型 + 现有 Skill（`jc-manju-pipeline`） | 现在已经能用，保持不动 |
| 提交、轮询、重试、按图号排序、预算控制 | **宿主程序里的“集调度器”**（确定性代码） | 模型回合会结束，做不到“半小时后再查”；让模型去对@图号容易对错；付费动作必须可审计、可防重复 |

这样做能直接复用的现有能力：
- `submit_creation_task`（`src/runtime/creation/creationMcpBridge.ts`）：提交后立即返回 taskId，用 `requestId` 去重。
- `mediaTaskStore`：后台自动轮询（视频有 `CREATION_VIDEO_POLL_MAX_SEC` 窗口），任务持久化，重启后可 `refreshTaskResult` / `resumeDynamicSubmission` 恢复，结果下载到项目 `.raw/jc-media/`。
- `pipeline_checkpoint`：程序校验阶段顺序，模型不能随意跳过。

也就是说，“不等待”已经是现成行为：提交后由 store 在后台轮询。调度器只需在固定节点**读取状态**，自己不用写轮询循环。

## 1. 单集状态机（扩展 `第x集进度.json`）

```text
plan → materials → style → assets ─┬→ engineering → prompts → asset_gate → video_submit → prompts_done
                                   └→ [asset_submit：程序在后台提交生图，不阻塞]
video_submit 之后：视频任务在后台跑，不阻塞下一集；单独记录 video_status，等全部完成才标记 episode_done
```

| 阶段 | 执行者 | 行为 |
| --- | --- | --- |
| assets | 模型 | 照旧写资产提示词。checkpoint 新增 `assets:[{asset_id, kind, prompt_path, prompt_hash}]` |
| asset_submit | 调度器 | 收到 assets checkpoint 后，为每个**需要出图**的资产提交生图，立即返回。已存在且 prompt_hash 未变的资产跳过（跨集复用） |
| engineering / prompts | 模型 | 照旧。prompts checkpoint 每段新增 `refs:["char_顾云舟","scene_石道",...]`，顺序与正文 @图1..N 一致 |
| asset_gate | 调度器 | 查本集 refs 涉及的全部资产：成功→登记图片路径；失败或超时→重提（上限 N 次）；仍在跑→等到成功或超时为止。全部就绪才往下走 |
| video_submit | 调度器 | 每段按 refs 顺序取图片路径，组成 `images[]` 提交，立即返回 |
| （下一集） | 调度器 | 不等视频，直接让模型开始写下一集 |
| video_check | 调度器 | 每集开始前、以及定时（例如 30 分钟）扫一遍未完成的视频：成功→登记；可重试的失败→重提一次；内容审核类失败→不重试，标记出来交给人处理 |

## 2. 现在缺的环节（按优先级）

### 2.1 资产注册表（最关键，没有它就做不到按图号排序）
现在 @图 行只写了资产**名字**，生成出来的图片也只以 prompt 前 50 字命名（`saveMediaToFileTree`），程序无法把“@图2 = 石道”对应到具体文件。

新增项目级 `制作流水线/资产注册表.json`：
```json
{ "char_顾云舟": { "kind": "character", "prompt_path": "wiki/资产/角色/顾云舟.md", "prompt_hash": "…",
    "image_path": ".raw/jc-media/…png", "task_id": "…", "status": "ready|pending|failed|locked", "attempts": 1 } }
```
- `asset_id` 由程序根据实体类型和名字生成，模型只负责引用。
- `locked`：用户手动换图或确认过的图片，永远不再自动重新生成。
- 修改资产提示词（hash 变化）→ 生成新版本，已提交的旧视频不受影响。

### 2.2 结构化 refs，提示词正文保持干净
`jc-seedance` 规定正文不得写制作备注，所以图号和资产的对应关系放在 checkpoint 的 `segments[].refs`，不放进正文。程序校验三点：refs 数量 = 正文 @图行数；每个 ref 都在注册表里；不超过所选视频模型 `asset_slots` 的上限。

### 2.3 提交防重复（防止重复扣费）
`requestId` 用确定性规则生成：`{项目}:{集}:{段}:{prompt_hash}:{refs_hash}:{attempt}`。
⚠ 需要先核实：`submissions` 去重表只存在内存里；重启后去重只对带 `plan.protocol` 的动态能力生效（`store.tasks.find(...protocol.requestId)`）。静态模型重启后可能被重复提交，需要补测试，再补一份持久化去重。

### 2.4 在 plan 阶段锁定运行参数
plan 阶段必须确定：生图模型 ID（角色 / 场景 / 道具可以分开）、视频模型 ID、比例、分辨率、单段时长、每集最多提交次数、整次运行的预算上限。中途不允许由模型自行切换型号。

### 2.5 一次授权 + 预算闸门
现在的规则是：只有选中 @影音 芯片时才注册 `submit_creation_task`。自动流水线改成**启动时一次授权**，弹窗写明“第 a–b 集，生图约 X 张，视频约 Y 段，预计费用 Z，上限 W”。超过上限就自动暂停（状态记为 blocked），不再继续悄悄扣费。

### 2.6 集循环由宿主驱动，不让一个模型回合跑完整季
每集是一次全新的模型运行（只读 Wiki 和进度文件，不带上一集的聊天上下文），调度器负责把集与集串起来。这样可以避开长回合的上下文膨胀和五分钟空闲超时（参见 [[排障/模型请求五分钟空闲超时与重试次数显示错误-2026-10-22]]）。中断后从进度文件续做。

### 2.7 “成片”还差最后一步：拼接
你的规划止于“提交视频任务”。要真正得到一集成片，还需要：分段视频全部成功 → 按 segments 顺序拼接（时间轴已经在 checkpoint 里）→（可选）配乐、字幕 → 输出 `第x集成片.mp4`。建议作为 P3 单独做，可以先用 ffmpeg 做无损拼接。

### 2.8 质量闸门（建议）
任务“生成成功”不等于图片能用。角色图会决定之后所有集的一致性，建议默认：**第 1 集资产出齐后暂停一次，等人审图**；审过的图自动 `locked`，之后各集全自动。这个审图暂停可以在设置里关掉。

## 3. 分期实施

```text
P0 资产注册表 + refs 校验（不花钱）    → 验证：跑 2 集只写文字，程序能 100% 把每段 @图 对应到注册表条目
P1 生图自动提交 + asset_gate          → 验证：断网/失败注入后能重试；重启不重复扣费；locked 不被覆盖
P2 视频自动提交 + 后台 video_check     → 验证：图片顺序与 @图 一致（抽查请求体）；审核失败不重试
P3 多集循环 + 预算闸门 + 进度面板 + 拼接成片 → 验证：3 集连续无人值守，中途关闭 App 后能续做
```
每期先写测试（遵循 AGENTS.md 的 TDD 要求），真实付费平台的验证单独记录，不写成“已通过”。

## 4. 用户决策（2026-10-25 已确认）

1. 不取代 10-21 条款，而是新增“全自动成片”模式：漫剧制作默认仍只出提示词，全自动成片作为可选模式。
2. 重试上限：生图失败重提 2 次，视频失败重提 1 次；内容审核类失败不重试。
3. 第 1 集资产出齐后暂停审图，默认开启；审过的图自动锁定。
4. 预算上限按每集计算。
5. 拼接成片纳入本次范围，使用本机 ffmpeg 按段顺序无损拼接；配乐和字幕推后。

## 5. 入口 UI

“漫剧制作”按钮改为与“权限”按钮同一套向上弹出菜单（复用 `.memory-command-more` / `.memory-permission-menu`）：

| 菜单项 | 说明 |
| --- | --- |
| 提示词模式（默认） | 只写文字与提示词，不调用生成，不产生费用 |
| 全自动成片 | 自动生图、生视频并拼接成片；按集计费，启动前确认预算 |
| 退出漫剧制作 | 仅在已选中时显示 |

- 按钮常驻显示当前模式：`漫剧制作` / `漫剧·全自动`。全自动模式使用醒目配色（类似完全权限的 danger 态），让用户一眼看出当前会花钱。
- **选中模式不等于开始花钱。** 用户在全自动模式下发出“第 1–10 集”这类指令后，宿主弹出启动确认卡（形式同“确认启用完全权限”）：集数范围、生图模型、视频模型、比例、分辨率、单集预算上限、预计费用。确认后才开始执行；这张卡同时承担 §2.4 的参数锁定和 §2.5 的一次授权。
- 运行中在输入框上方显示进度条：当前集，资产 x/y，视频 x/y，成片状态；包含“暂停”按钮，以及审图暂停时的“继续”按钮。
- 代价：原来单击即可开关漫剧制作，现在需要两次点击。这样做换来了与权限按钮一致的交互，用户也不会误入付费模式。

## 6. 剧本入稿与启动流程

### 6.1 三种剧本来源都支持，统一归一到“分集剧本”

| 来源 | 现有能力 | 入稿后 |
| --- | --- | --- |
| 粘贴到对话框 | 用 `source_material` 原样保存 | 适合一到几集；整季内容太长时提示改用附件 |
| 上传附件 | `importAttachmentFiles` 落盘到 `原始材料/`，Office/PDF 转成 Markdown | 最常见：一个文档里装着整季剧本 |
| 引用文件树中的文件 | `referencedFiles` | 剧本已经在项目里 |
| 什么都不给 | — | 直接使用 Wiki 中已有的 `项目资料/分集剧本/` |

不管从哪个来源进来，调度器只认一种输入：`项目资料/分集剧本/第N集分集剧本.md`（`episode_source_script`）。所以新增 **第 0 步“入稿拆集”**：模型把原稿按集拆开并原样保存（不改写），然后报告识别出的集列表，例如“共 12 集，第 3 集约 1800 字”。这一步免费，不提交任何生成。

### 6.2 发送什么指令：不需要专门的指令格式

1. 用户切到“全自动成片”，提供剧本（三种方式任选），发送一句自然语言，例如“全自动做 1–10 集”；只发附件、不写文字也可以。
2. 模型执行第 0 步：入稿拆集，并检查 Wiki 里有没有已确认的比例和风格。**所有需要人回答的问题都在这一步问完**，例如风格尚未确认。全自动运行开始后，不再停下来提问（第 1 集审图除外）。
3. 宿主弹出启动确认卡。卡上的值由宿主从 Wiki 和消息中预填，用户可以修改：
   - 集数范围：勾选识别出的集
   - 生图模型、视频模型（下拉菜单，数据来自 `list_creation_models`）
   - 比例、分辨率、风格（只读显示，已在 Wiki 中确认）
   - 单集预算上限、预计费用
4. 用户点“开始全自动”后，由调度器逐集驱动。

钱相关的参数（集数、模型、预算）**以确认卡为准，不以模型对自然语言的理解为准**：模型只负责预填，用户点确认才算数。

### 6.3 运行中的对话框
- 运行中用户发的消息进入现有会话队列，不打断调度；暂停、继续、停止通过进度条上的按钮操作。
- 中断后再次进入全自动模式时，确认卡会显示“从第 N 集续做”，已完成的集不会重复执行。
