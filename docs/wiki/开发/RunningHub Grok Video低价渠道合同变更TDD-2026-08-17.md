# RunningHub Grok Video 低价渠道合同变更 TDD

> 状态：代码与自动化验收已完成；待部署和真实渠道验收
> 建立：2026-08-17；收口：2026-08-18
> 范围：`rhart-video-g/text-to-video`、`rhart-video-g/image-to-video` 及 RH 创作模型注册

## 目标

根据指定上游文档的新合同，精准同步文生和图生两个 RunningHub 模型：

- 时长统一为 `6-15` 秒，禁止发送超出范围的值。
- 图生最多 `7` 张参考图，每张不超过 `10 MB`；文生不接收参考图。
- UI 价格统一显示 `0.25/秒`。
- 保留现有 RH 适配器、上传和轮询链路，不新建协议或计费服务。

## 红灯验收

1. 当前注册仍为 `6-30` 秒、图生最多 `3` 张、价格 `0.08/秒`。
2. 计划必须在网络请求前拒绝 `duration=16` 和图生第 8 张参考图。
3. 文生计划不能携带参考图；图生单图超过 `10 MB` 必须在提交前拒绝。

## 绿灯验收

1. 两个模型能力表、前端注册和 RH 适配器共享同一端点合同：`6-15` 秒。
2. 图生接受 `1-7` 张图并校验单图 `10 MB`；文生仍为纯提示词。
3. 两个模型 `displayModelPrice()` 均返回 `0.25/秒`，映射与轮询回归不变。

## 边界

本地自动化只证明合同和请求构造；真实 RH 低价渠道可用性、生产部署和真实账单仍待执行。

## 实施结果

- 前端两个模型均改为 `6-15` 秒，UI 价格为 `0.25/秒`。
- 图生视频改为 `1-7` 张参考图、单图 `10 MB`；第 8 张会在创建 RunPlan 时失败。
- 前端与 RH adapter 两份 capabilities JSON 的对应 `duration.max` 均从 `30` 改为 `15`。
- RH 标准 payload 过去只校验枚举，没有通用执行数值参数的 `min/max`；现在在共享构造器统一拒绝越界的 `INT/FLOAT`，`duration=16` 无法绕过 UI 到达上游。
- endpoint、模型 ID、上传、NewAPI 提交和 RH 轮询均未改变。

## 问题与经验

1. 上游合同变化不能只改 UI 控件。模型注册、前端 capability、适配器 capability 和适配器边界必须一致，否则旧计划或直接请求仍能发送非法值。
2. 素材合同要同时约束数量与单文件大小。只把图生上限从 3 改成 7 会遗漏上游的单图 `10 MB` 边界。
3. capability 是数据，不等于校验已经生效。本次红灯证明 `max=15` 即使写进 JSON，payload 构造器未读取 `min/max` 时仍会放行 16 秒；修复应落在共享构造器，而不是为 Grok 写端点特例。
4. 精确修改后必须检查 diff。第一次按邻近 `price: 0.08` 替换误命中 FLUX Klein，已立即恢复；后续按模型 ID 上下文定位，避免同值字段串改。
5. 价格文案与真实计费是两条证据链。本次只确认 App UI 显示 `0.25/秒`，不声称 NewAPI 生产价格或账单已经配置成功。
