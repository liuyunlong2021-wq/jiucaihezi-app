## 1. 本轮结论

- iPhone 文件树显示的“电脑中打开”来自 `isTauriRuntime()` 把 iOS 也判为 Desktop；该入口在移动端没有意义，现已隐藏。
- 图 2 的直接根因是“导出所选资源”无条件进入 Desktop 分支并调用 Tauri 目录选择器。iOS 没有 `rfd` 文件夹选择器，因此报 `Folder picker is not implemented on mobile`。
- 移动端导出现改为读取已选文件后调用系统 `navigator.share({ files })`；系统不支持多文件分享时逐文件触发浏览器下载，不再调用 `showDirectoryPicker()` 或 Desktop Rust 导出命令。
- 整项目导出复用同一移动端文件分享路径，不建立第二套导出器。

## 2. 手机文件树边界

手机项目只存在于 Tauri App 管理目录 `app_data_dir()/projects/<name>`。文件树通过现有 `dev_list_files`、`dev_list_directory`、`dev_read_file`、`dev_write_file_if_revision` 和批量操作命令读写，Web、Desktop 的项目适配不改变。

移动端不提供以下 Desktop 专属动作：选择电脑项目文件夹、在 Finder/系统默认应用中打开、选择外部导出文件夹。手机仍保留文件上传、文件树编辑、预览、删除、项目新建/切换和云文字覆盖。

## 3. 双向覆盖合同

### 上传并覆盖云端

1. 在项目中心确认后，以当前手机项目路径作为唯一 `owner`。
2. `ProjectTextSync.open(owner, name)` 读取固定 `.raw/.sync/state.json`；没有绑定时创建一个云项目。
3. 读取本地完整可同步文字快照，与远端完整快照按相对路径和 SHA-256 比较。
4. 本地存在的文字执行 `upsert`，云端独有文字执行 `delete`；使用远端 revision 做乐观并发校验，409 时重新拉取后最多重试两次。
5. 所有 mutation 成功后才写回 `.raw/.sync/state.json`，刷新项目中心并显示上传摘要。

### 下载并覆盖本地

1. 点击云项目并确认后，手机先按 `.raw/.sync/state.json` 的 `cloudProjectId` 精确定位本地目录。
2. 找不到精确绑定时新建一个不重复的 App 管理项目；不再仅凭同名复用手机目录，避免两个同名云项目互相覆盖。
3. `ProjectTextSync.connect()` 或 `downloadNow()` 拉取云端完整文字快照：存在的文字原子覆盖，不存在的本地可同步文字删除。
4. 只有本地写入、删除全部成功后才持久化 cursor、revision、hash 和云项目 ID；过程中失败保留原状态并在项目中心显示真实错误。
5. 完成后切换到目标手机项目，文件树重新加载；成功摘要为“已下载并覆盖本地”。

### 明确排除

两条覆盖动作都不处理媒体、空目录、凭据、设置、Skill、MCP、Provider、Session 和 `.raw/.sync`；不合并正文、不生成冲突副本、不自动双向同步。
