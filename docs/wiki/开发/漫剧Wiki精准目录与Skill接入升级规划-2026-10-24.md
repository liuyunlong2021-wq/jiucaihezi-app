影片比例与风格建议合为一份权威文档，避免下游取到不同版本。应明确：全片比例、最终媒介、视觉风格、时代地域、色彩/光线、摄影与表演、声音路线及明确的局部例外；初始内容标记待填写，不擅自填 16:9 或写实。现有用户项目若已采用独立比例/风格两页，应先提供明确索引映射，不自动覆盖、改名或复制出第二份权威资料。

`制作进度.md` 和短剧 `改编方案/` 等既有能力可继续保留；上述树聚焦本轮指定的漫剧读写主链，不借此删除其他产品能力。

## 4. 实施顺序与验收

### G0：先固定共享路径和命名合同

把类型、路线、路径、实体/集数/片段字段、所属 Skill 的映射统一进现有共享合同，创建目录与自动归档共同使用。

- 拆开影片风格、角色形象、角色格式与声音等类型；不能只改 UI 目录，而让归档仍写旧路径。
- 固定“第1集001视频提示词.md”形式，集号为实际集数、片段序号三位补零；H3/Seedance 分目录避免同名互相覆盖。
- 同一集声音稿可分段创作，但保存到同集文档时保留各段，不能让后段把前段替换掉。
- 同名实体沿实际 index 唯一定位，不把安全文件名推导当成实体消歧。
- 旧合同仍可读取；已有文件不在创建时批量搬迁或删除。

验证：所有输出类型可唯一定位；不同角色、集数、模型和片段互不覆盖；角色形象与格式写入不同文档。

### G1：完善右键“创建漫剧制作 Wiki”

只创建静态目录、逐层 index，以及标明待填写的影片比例/风格入口模板。人物、场景、道具和集号在有真实内容时再建对应目录/文件。索引精确链接，不写虚构事实或完成状态。

验证：空项目一键创建、重复创建不覆盖、已有 Wiki 增量补齐、多个根拒绝、文件占用不破坏原件；与统一归档的真实目标一致。

### G2：升级 jc-xiangmuziliao，先打通“来源 → 项目资料”

严格按用户指定位置输出资料。每个人物/场景/道具独立文档，标明来源和真实覆盖范围；各自 index 登记实际文件，资料之间用真实双链关联。

用户提供现成分集剧本时按真实集号保存/登记；只有小说来源时，项目资料 Skill 不自行改写成分集文学剧本，继续由短剧路线或用户提供该项。分集梗概不能冒充分集剧本。已存在原作/改编版资料的项目仍区分版本，不为套新骨架混在一起。

验证：任一人物/场景/道具可从资料 index 精准找到；来源提取不改剧情；未覆盖内容明确标记。用一集、两个人物、一个场景、一个道具的小 fixture 检查实际文件与索引。

### G3：升级项目风格，锁住全片公共依据

让 jc-film-style 读取故事梗概与本轮消息、写入专门比例/风格文档；修订时读取目标原页以保留用户已定字段。其他视觉 Skill 在判断缺信息或采用默认值之前，先读取该文档的当前值。

验证：设定为 9:16/二维后，本轮不重说比例和画风，角色/场景/道具仍继承；只改画幅不丢其他风格内容。

### G4：按顺序接入角色、三格、场景、道具、角色声音

每个 Skill 明确读哪类页面、哪些字段，写哪个独立文档。修订读取原文保留其他内容；不同产物文件之间不互相替换。

验证：生成三格角色提示词后原形象提示词仍在；修改角色声音不影响任何生图提示词；场景/道具分别继承对应剧情说明，不混实体。

### G5：接入工程剧本与声音导演

工程稿主要从现成分集剧本起步，有外部/既有声音稿时可作为替代输入；声音导演从已生成工程稿继续。二者不是互相强制先存在的循环依赖，修订一方也不静默重写另一方。

工程剧本输出升级为：影片比例与风格、整集所需资产清单、原有逐镜工程正文。资产清单按角色（含造型/状态）、场景、道具列名称、用途/使用镜号及已有 Wiki 引用；仅列实际需要的资产，不虚构已生成图片。局部修改同步维护受影响资产清单，保存时保留整集其他内容。

验证：相同集号定位一致；原台词、人物身份和工程镜号承接；资产清单与镜头实际使用逐项对应；局部修订保留其他镜头/声音段；每集各自独立文件。

### G6：接入两条分镜/视频分支

先工程到分镜，再允许工程或分镜到视频。参考图已由用户准备，本阶段只保证对象占位与职责准确，不重复生成图片或引入媒体执行。

- 占位清单明确“图号/占位、对象名、角色/场景/道具职责、适用镜号或格位”；图号只在本条提示词实际绑定清单中有效。
- 不把角色三格排版、场景介绍或占位符名称混成画面剧情；不虚构已上传的图号/文件。
- 工程稿或实际参考映射不足以确定对象时列明缺项，不凭空绑定另一个角色。
- 分镜只记录瞬间而缺完整台词/动作时，视频 Skill 回查对应工程段落，避免凭静帧重新编戏。

验证：同集不同片段/模型文件独立、参考对象不串、镜号与格位对应、对白保真、命名完全符合约定。

### G7：真实创作闭环验收后再讨论上下文

按“建 Wiki → 整理资料 → 定比例风格 → 资产 → 工程/声音 → 两种分镜/视频”的小样执行。逐步核对真实读写路径、修改后文件与 index，覆盖缺页/同名/旧目录/中断/重复保存。

先测试缺陷复现再实现，运行相关回归、类型检查和桌面构建；真实模型、原生点击、Windows/Intel Mac 分别记录。上述主链完成后再设计上下文保留与压缩，本规划不提前改上下文。

## 6. 两条提示词流水线（已实现，待真实创作验收）

输入为用户提供的剧本和已确认的影片比例/风格。共同前段：导入剧本/建Wiki → jc-xiangmuziliao 形成对应项目资料 → 将用户已确认比例风格填入专门文档（不重新创作另一套方向）→ 角色/格式/场景/道具资产提示词 → 工程剧本（含全片规格、整集资产清单与镜头）→ 分组 → 目标模型提示词。

- Seedance：每份视频提示词按用户产品策略不超过30秒，保存第x集001、002等独立文档。
- MiniMax/H3：每份视频提示词按用户产品策略不超过15秒，同样按集与片段独立保存。
- 30/15秒是本产品要求的分段上限，不在此宣称任意渠道/型号都支持；真实提交时还需服从所选型号能力。本阶段终点是资产及视频提示词，未授权自动付费生图/视频。
- 目标路线在工程编排前明确，优先在自然动作、对白落点与场景转换处设计可分组镜头。不用固定字数、直接截断对白、删除动作或加速念词满足时长。
- 无实测音频时按自然对白和动作估算并标预算，不冒称精确实测；单个单位超限时需按保持内容/因果的方式重新拆镜或报告具体冲突。
- 每段有首尾状态、角色站位、持物、场景与声音承接，保留原工程镜号，分段时间从0换算；同模型片段序号与真实输出路径一致。
- 可从已有资料/资产/工程稿继续；每步真实保存与读回后推进，失败报告具体步骤和路径，不从头重复执行、不把未完成步骤报成功。
- 分镜图提示词路线作为按需分支，不自动强迫每个用户在工程与视频之间多做一套分镜；参考占位必须明确对象与职责。

先完成精准Wiki与各Skill的单步读写，再以已验证步骤组合流水线；不为流水线恢复已经关闭的通用目标/子代理/后台工作流工具。
