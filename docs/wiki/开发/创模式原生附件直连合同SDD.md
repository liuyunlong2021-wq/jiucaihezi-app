# 创模式 NewAPI 原生附件合同 SDD

> 日期：2026-07-22
> 状态：待实施、审计和真实验收
> 范围：Web / Desktop 创模式；不改文、武模式
> 核心原则：当前模型优先，产品只修正发送合同和错误状态。
> 硬边界：不自动换模型，不寻找 Gemini 补位，不用本地工具自动降级。
> NewAPI 边界：继续使用 `calciumion/new-api:latest` 官方镜像；不维护 Fork，不实现官方尚未支持的 `/v1/files`。

## 1. 一句话目标

用户在创模式选定模型并发送文字或附件后，韭菜盒子只把请求按 NewAPI 官方合同交给**当前选中的模型**：能读就由它回答，不能读就明确说明当前模型不支持。产品不代替用户换模型，不自动运行工具，不加业务输出格式。

## 2. 本轮只修什么

2026-07-21 真实 UI 回归确认了六个基础问题：

1. `.mov` 在浏览器中常被标记为 `video/quicktime`，NewAPI 官方 Gemini 转换器接受的是 `video/mov`。
2. 产品没有一份完整的 NewAPI 官方 MIME 归一化合同，附件元数据和 `data:` 头可能不一致。
3. 直传 Base64 会扩大最终 JSON 请求，当前上传控件大小不等于实际传输边界。
4. 历史附件重发只恢复 `text/images/files`，没有从 `cachePath/resource` 恢复真实 `modelAttachments`。
5. 非 2xx 响应丢失 NewAPI 错误正文；`content_filter` 又被统一显示成“模型没有返回内容”。
6. 网络错误被写成 assistant 正文并进入下一轮模型历史，导致一次失败污染后续纯文字请求。

本轮只修上述六项，并删除现行创模式中“当前模型不支持时自动寻找 Gemini、再询问本地工具”的过度设计。

## 3. 唯一发送链路

```text
用户选定模型并点击发送
  -> ChatPanel 冻结本轮文字和附件原件
  -> 按 NewAPI 官方集合归一化 MIME
  -> 确认当前模型的已知输入能力
       -> 明确不支持：显示“当前模型不支持该附件”，保留附件
       -> 支持或能力未明：继续交给当前模型
  -> buildCreativeContext()
  -> buildDirectMessages()
  -> runDirectChatCompletion()
       -> 成功：显示模型自由回答
       -> 上游拒绝或失败：显示真实可行动错误，保留附件
```

上述链路只有一个模型身份、一份 Provider/K 和一次主请求。运行时不搜索其他模型，不修改模型选择器，不发起跨模型确认，不弹出媒体本地工具补位提示。

### 3.1 模型能力的处理

- 当前 Provider 已有经过验证的输入模态时，可在发网前阻止明确不支持的附件。
- 能力信息缺失时，不根据模型名称猜测；按官方消息合同发给当前模型，由 NewAPI 和上游返回结果。
- 当前模型不支持或上游拒绝时，本轮结束。用户是否手动换模型、选 Skill 或要求工具，由用户自己决定。

### 3.2 工具与 Skill 边界

创模式原有的“模型回复 -> 模型要工具 -> 执行工具 -> 结果回模型”循环保留。但工具是普通模型循环的可选能力，不是附件不支持时的产品级自动补位。本 SDD 不新增工具、Skill、视频抽帧、转写或 OCR 流程。

### 3.3 媒体生成边界

对话中的生图、生视频和生音频仍走现有媒体计划、确认卡和 Creation Runtime。它们不参与普通附件理解，本轮不修改。

## 4. NewAPI 官方附件合同

### 4.1 现行请求格式

- 图片：`image_url`。
- 视频、音频、PDF 和文件：`file.file_data`。
- 模型不支持 function calling 时只省略 `tools`，不得一起删掉附件。

生产已用极小 PNG、MP4 和 WAV 证明该合同可经 NewAPI 到达用户手动选中的 `gemini-3.5-flash`。`video_url` 虽可返回 200，但生产复测中模型没有收到视频，不作为本轮合同。

### 4.2 官方 Gemini 转换器 MIME 集合

```text
application/pdf
audio/mpeg audio/mp3 audio/wav
image/png image/jpeg image/jpg image/webp image/heic image/heif
text/plain
video/mov video/mpeg video/mp4 video/mpg video/avi video/wmv video/mpegps video/flv
```

这份集合是 NewAPI 官方 Gemini 转换器的格式边界，不代表所有模型都能读取这些附件。最终是否可读仍由用户当前选中的模型和渠道决定。

### 4.3 MIME 归一化

产品必须只维护一份权威归一化表，由上传状态、附件元数据、`data:` 头和消息构造共用。判断同时使用扩展名、浏览器 MIME 和 `data:` 头，至少覆盖：

```text
video/quicktime -> video/mov
audio/x-wav     -> audio/wav
image/jpg       -> image/jpeg
```

归一化后，附件 `mime` 和 `file_data` 的 `data:<mime>;base64,...` 必须一致。不在官方集合内的格式在发网前明确说明限制，不交给上游返回模糊 500。产品不自动转码或改写媒体内容。

### 4.4 最终请求预算

发送前按最终序列化 JSON 大小判断，包含 Base64 膨胀、系统提示和会话历史，不用原文件大小或上传控件的 100 MB 上限冒充传输预算。

超过已验证传输边界时：

- 在输入框上方使用现有轻量提示条；
- 说明文件和当前直传限制；
- 保留附件；
- 不自动压缩、转码、换模型或调工具。

## 5. 会话、错误与重发

### 5.1 错误状态不是模型正文

- 非 2xx 响应安全读取 NewAPI JSON 或文本错误、请求 ID 和 HTTP 状态。
- 限制错误长度，移除 HTML、K、Base64、本地路径和私人内容。
- `network_error`、`abort`、无正文 `content_filter` 和正常空内容分开显示。
- NewAPI 可能把多种上游终止原因聚合为 `content_filter`，界面不得自行判定为用户违规。
- 失败状态可以在界面显示，但不作为 assistant 正文进入下一次 `buildCreativeContext()`。

### 5.2 附件恢复

创模式重发和重新生成共用一份附件恢复函数：

- Desktop 从媒体缓存或项目资源恢复原件。
- Web 从仍有效的项目资源或 OPFS 恢复原件。
- 原件不存在时保留用户文字并要求重新选择附件。
- 不把文件名、MIME、时长、尺寸或文本摘要当作原件发给模型。

### 5.3 持久化边界

- `modelAttachments` 只存在于当轮发送态。
- 会话持久化只保存轻量 `attachments`、`cachePath/resource` 和可恢复的素材身份。
- SQLite、Wiki、日志和媒体计划不得保存 `data:`、`blob:`、`File`、`Blob` 或 `ArrayBuffer`。

## 6. 成功标准

1. 纯文字请求仍只调用用户当前选中的模型。
2. 已验证支持图片、视频、音频或 PDF 的当前模型能收到对应原件。
3. 当前模型明确不支持附件时，本轮只显示不支持；不产生第二个模型请求，不弹本地工具补位提示。
4. 能力未明时不按模型名称猜测，只发给当前模型并保留上游真实结果。
5. NewAPI 官方 MIME 集合有唯一归一化表和完整消息构造测试。
6. `.mov` 的 `video/quicktime` 在附件元数据和 `data:` 头中同时归一化为 `video/mov`。
7. 最终 JSON 请求体积在发网前可计算；超限请求不产生 500、524 或长时间无响应。
8. HTTP 400/413/415/500/524 显示脱敏后的错误类型、安全摘要和请求 ID，不再只显示状态码。
9. `content_filter`、网络错误、用户取消和正常空内容分开显示。
10. 一次附件失败后，同一会话继续发送普通文字能正常回复。
11. 旧会话附件可恢复时真实重发；不可恢复时要求重新选择，不用摘要冒充原件。
12. 生产仍可直接升级 `calciumion/new-api:latest`，不依赖私有 NewAPI 代码、镜像或数据库改造。

## 7. 实施任务

### Task 1：冻结失败测试和删除越权路由

1. 为当前模型不支持视频写失败测试：当前实现会发起 Gemini 媒体专家或本地工具补位。
2. 为 `video/quicktime` MOV、HTTP 500 正文、`content_filter`、失败后纯文字续发和历史附件重发分别写单一行为失败测试。
3. 从创模式发送链路移除自动 `mediaSpecialist`、跨模型确认和“没有 Gemini 就询问本地工具”分支。
4. 只删除因这条路由产生的死引用、设置和文案；不重构普通工具循环。

验收：当前模型不支持附件时，测试只观察到当前模型结果或本地不支持错误，没有第二个模型请求和自动工具提示。

### Task 2：建立唯一 NewAPI MIME 与请求预算

1. 建立一个 MIME 归一化函数和官方支持集合，由上传、附件元数据、data URL 和消息构造共用。
2. 完整覆盖官方 MIME 集合、常见浏览器别名和扩展名。
3. 保持图片 `image_url`、其他附件 `file.file_data` 的现行官方合同。
4. 发送前计算最终序列化 JSON 体积，超限时使用现有轻量提示条并保留附件。
5. 不新增 `video_url`、`file_id`、Google Files API、第三方上传或新依赖。

验收：目标 MOV 不再因 `video/quicktime` 进入上游；超限时在发网前停止，不自动改变附件或模型。

### Task 3：修正错误、历史和重发

1. 安全读取非 2xx 错误正文和请求 ID，限制长度并脱敏。
2. 将 UI 错误状态与 assistant 模型正文分离，失败轮次不进入后续模型历史。
3. 正确区分 `content_filter`、`network_error`、`abort` 和正常空内容。
4. 让重发和重新生成共用附件恢复函数；原件不存在时只要求重新选择。

验收：同一会话先制造附件失败，再发送普通文字，当前模型正常回复；旧附件只在恢复到原件后重发。

### Task 4：门禁与真实验收

自动门禁覆盖：MIME 矩阵、请求预算、当前模型单一路由、错误解析、失败历史过滤、附件恢复和持久化脱字节。真实验收至少包含：

| 场景 | 预期 |
|---|---|
| 纯文字 | 只调用当前选中模型，正常回复 |
| 当前模型支持图片 | 原图进入当前模型 |
| 用户手动选中支持视频的模型 | MP4、MOV 和另一种官方视频格式进入该模型 |
| 用户手动选中支持音频或 PDF 的模型 | 原件进入该模型 |
| 当前模型明确不支持 | 只提示当前模型不支持；无第二模型、无本地工具补位 |
| 17.1 MB、127 秒 MOV | 不再因 MIME 别名返回模糊 500；明确记录实际结果 |
| 超过直传预算 | 发网前明确停止，附件保留 |
| 附件失败后纯文字 | 同一会话正常回复，错误 UI 文本不进入模型历史 |
| 旧会话重发，原件存在 | 恢复原件后重发 |
| 旧会话重发，原件失效 | 要求重新选择，不发摘要 |
| NewAPI 400/413/415/500/524 | 显示脱敏真实错误和请求 ID |
| `content_filter` 无正文 | 显示真实终止类别，不显示“模型没有返回内容” |
| 官方镜像升级 | 无 NewAPI 源码、镜像或数据库定制依赖 |

内容质量不是本 SDD 验收项。模型收到原件后回答什么、是否输出剧本、时间轴或其他格式，由当前模型、用户提示和后续 Skill/工具决定。

## 8. 明确不做

- 不自动切换到 Gemini 或任何其他模型。
- 不建立媒体专家、跨模型确认、智能媒体增强或模型协作状态。
- 不在当前模型不支持时询问是否使用本地工具。
- 不自动运行 FFmpeg、转写、OCR、视觉模型或终端。
- 不规定剧本、时间轴、分镜、台词或 JSON 输出合同。
- 不修改媒体生成、CreationPanel 或创作面板。
- 不修改文、武模式或 OpenCode。
- 不把 Base64 写入 SQLite、Wiki、日志或项目文件。
- 不私改 NewAPI，不维护 NewAPI Fork，不替换官方镜像。
- 不实现 `/v1/files`、Google Files API、`file_id` 或第三方上传服务。
- 不引入 LangChain、Python 运行时或新依赖。

## 9. 风险与取舍

### 9.1 当前模型不一定支持附件

这是模型和用户所选渠道的现实能力边界，不是创模式需要补齐的服务。本轮用清晰错误换取简单、可预期和不代用户做决定。

### 9.2 Base64 有体积和内存成本

NewAPI 官方尚未实现 `/v1/files`。本轮接受 `file.file_data` 的直传边界，对超限请求明确停止，不用私有文件服务换取表面支持。

### 9.3 历史附件可能失效

会话不持久化 Base64 是正确边界。原件无法恢复时，必须要求用户重新选择，不用摘要伪造模型已读取。

## 10. 完成后的架构

```text
用户文字 + 原始附件
  -> NewAPI 官方格式归一化
  -> 用户当前选中的模型
       -> 支持：自由回答 / 按正常循环请求工具
       -> 不支持：明确错误，本轮结束
```

没有隐式模型切换，没有媒体专家，没有自动工具降级，没有业务输出格式。
