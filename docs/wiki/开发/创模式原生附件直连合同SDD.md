# 创模式 NewAPI 原生附件合同 SDD

> 日期：2026-07-22
> 状态：实现与自动验证完成，Desktop 真实验收通过，Web 真实 Provider 待验收
> 范围：Web / Desktop 创模式；不改文、武模式，不改 NewAPI
> 一句话原则：附件只交给用户当前选中的模型和当前 Provider/K；产品修正传输合同，不替模型判断能力。

## 1. 目标

用户在创模式发送文字、图片、视频、音频或文件后，韭菜盒子按 NewAPI 官方现有合同，把本轮原件交给当前模型：

- 模型能读，由模型自由回答。
- 模型或渠道不能读，显示 NewAPI 或上游的真实错误，本轮结束。
- 不自动换模型，不寻找 Gemini 补位，不询问本地工具降级。
- 不规定剧本、时间轴、分镜或 JSON 等业务输出格式。

## 2. 根因

2026-07-21 的真实测试暴露了四个基础合同问题：

1. 现行代码在当前模型不能读取附件时，会自动寻找 Gemini 或提示本地工具，越过了用户选择的模型。
2. 浏览器常把 `.mov` 标为 `video/quicktime`，而当前 NewAPI Gemini 转换层使用 `video/mov`。
3. 非 2xx 响应会丢失 NewAPI 错误正文，`content_filter` 又可能被显示成“模型没有返回内容”。
4. UI 错误可能作为 assistant 正文进入下一轮上下文，导致一次附件失败后普通文字也继续失败。

本轮只修这四个根因，以及它们直接造成的失败后附件保留问题。

## 3. 唯一发送合同

```text
用户点击发送
  -> 冻结本轮文字和附件原件
  -> 归一化已知 MIME 别名，并同步修正 data: 头
  -> 构造 NewAPI 消息
       图片：image_url
       视频、音频、PDF、其他文件：file.file_data
  -> 序列化最终 JSON，并检查 NewAPI 默认请求体上限
  -> 只请求当前模型 + 当前 Provider/K
       成功：显示模型自由回答
       失败：显示安全的真实错误，保留本轮附件
```

创模式不根据模型名称猜输入能力，也不在前端根据 `inputModalities` 阻止发送。模型和渠道是否支持附件，由 NewAPI 与上游真实响应决定。

普通“模型回复 -> 模型请求工具 -> 执行工具 -> 结果回模型”循环不变。但附件失败不会自动触发任何工具。

## 4. NewAPI 真实边界

### 4.1 消息格式

- 图片继续使用 `image_url`。
- 视频、音频、PDF 和其他文件继续使用 `file.file_data`。
- 模型不支持 function calling 时，只省略 `tools`，不能一起删除附件。
- 不新增 `video_url`、`file_id`、Google Files API、第三方上传或 NewAPI Fork。

### 4.2 MIME 归一化

上传态、附件元数据、`data:` 头和消息构造共用一份别名归一化函数，至少覆盖：

```text
video/quicktime -> video/mov
audio/x-wav     -> audio/wav
image/jpg       -> image/jpeg
```

当前 NewAPI Gemini 转换层允许的视频 MIME 包括：

```text
video/mp4
video/mov
video/mpeg
video/mpg
video/avi
video/wmv
video/mpegps
video/flv
```

这份列表只说明当前 Gemini 转换层的能力，不是创模式对所有 Provider 的全局白名单。未知或其他格式仍交给当前模型和 NewAPI，不在前端统一禁止。

### 4.3 大小边界

当前 NewAPI 真实默认值：

- 下载直链上限：`MAX_FILE_DOWNLOAD_MB = 64 MB`。
- HTTP 请求体上限：`MAX_REQUEST_BODY_MB = 128 MB`。
- 反向代理的 `client_max_body_size` 可能更低。
- Base64 通常比原文件膨胀约三分之一。

因此：

1. 发网前按最终序列化 JSON 的 UTF-8 字节数检查 `128 MB`，不能只看原文件大小。
2. 超过 `128 MB` 时停止发送，使用输入框上方现有提示条说明限制并保留附件。
3. 未超过 `128 MB` 也可能被更低的反向代理或上游模型拒绝，此时显示真实上游错误。
4. `524` 是上游响应超时，不等于请求体过大；本 SDD 不承诺用大小检查消灭 `524`。
5. 短时有效直链能减少 Base64 膨胀，但本轮不新建上传服务；只有现有 NewAPI 合同已经提供可用直链时才复用。

上游模型仍可能有自己的文件大小、时长、配额和格式限制，产品不伪装成统一能力。

## 5. 错误与会话

### 5.1 错误显示

- 非 2xx 响应显示 HTTP 状态、安全的 NewAPI 错误摘要和已有请求 ID。
- 错误摘要限制长度，并移除 HTML、API Key、Base64 和本地绝对路径。
- `content_filter`、网络错误、用户取消和正常空回复分别显示。
- 不自行把 `content_filter` 判定为用户违规。

优先复用现有错误构造函数；只有现有函数确实缺失的行为才补充，不新建通用错误框架。

### 5.2 历史隔离

- 错误可以显示在 UI，但不能作为模型 assistant 正文进入下一轮 `buildCreativeContext()`。
- 一次附件失败后，同一会话继续发送普通文字必须正常。
- 失败或取消时，输入区保留本轮附件，便于用户直接重试。

### 5.3 历史附件边界

- 会话不持久化 Base64、Blob、File 或 ArrayBuffer。
- 当前原件仍可访问时可以重发。
- 旧会话原件已经失效时，明确要求用户重新选择附件。
- 本轮不建设 Desktop 缓存、项目资源和 Web OPFS 的统一历史恢复系统。
- 不用文件名、MIME、尺寸、时长或摘要冒充模型已经读取原件。

## 6. 实施任务

### Task 1：删除越权路由

1. 删除创模式自动 Gemini 媒体专家、跨模型确认和本地工具补位分支。
2. 删除只为该路由存在的设置、文案、状态和死引用。
3. 保留当前模型请求与普通工具循环。

验证：一次发送最多只有当前模型请求；没有第二模型，也没有附件失败后的自动工具提示。

### Task 2：修正 NewAPI 发送合同

1. 建立唯一 MIME 别名归一化函数。
2. 保持图片 `image_url`、其他原件 `file.file_data`。
3. 让附件元数据与 `data:` 头使用同一 MIME。
4. 发送前计算最终 JSON UTF-8 字节数，只使用 NewAPI 已确认的 `128 MB` 默认上限。
5. 不用 Gemini MIME 列表拦截其他 Provider，不增加上传服务或依赖。

验证：MOV 以 `video/mov` 到达当前模型；未知格式仍发往当前模型；超过 `128 MB` 时发网次数为零。

### Task 3：修正错误和失败历史

1. 复用并补齐现有错误函数，保留安全的上游正文和请求 ID。
2. 区分 `content_filter`、网络错误、用户取消和正常空回复。
3. UI 错误不进入下一轮模型历史。
4. 失败或取消保留输入区附件；原件失效时要求重新选择。

验证：先制造一次附件失败，再在同一会话发送普通文字，当前模型正常回复。

## 7. 验收标准

| 场景 | 预期 |
|---|---|
| 纯文字 | 只调用当前模型，正常回复 |
| MP4 | 原件按 `file.file_data` 进入当前模型 |
| MOV / `video/quicktime` | 元数据和 `data:` 头都变为 `video/mov` |
| 当前模型或渠道不支持 | 显示真实错误，不换模型、不调工具 |
| 未知 MIME | 不用 Gemini 白名单提前拦截，由当前 NewAPI/上游决定 |
| 最终 JSON 超过 `128 MB` | 发网前停止，附件保留 |
| 反向代理限制低于 `128 MB` | 显示真实 413 或上游错误 |
| `content_filter` | 显示终止类别，不显示“模型没有返回内容” |
| 附件失败后发送文字 | 同一会话正常回复，错误 UI 不进入模型历史 |
| 旧附件原件失效 | 要求重新选择，不发送摘要冒充原件 |

自动测试不能代替真实 Web/Desktop 和真实 Provider 验收。

## 8. 明确不做

- 不自动切换 Gemini 或其他模型。
- 不根据模型名称猜附件能力。
- 不用 `inputModalities` 在创模式前端拦截附件。
- 不自动运行 FFmpeg、转写、OCR 或本地视觉工具。
- 不建立媒体专家、智能媒体增强或模型协作状态。
- 不规定剧本、时间轴、分镜或 JSON 输出。
- 不把 Gemini MIME 集合变成所有 Provider 的白名单。
- 不建设跨 Desktop/Web 的历史附件恢复系统。
- 不私改 NewAPI，不维护 Fork，不实现 `/v1/files`。
- 不新增第三方上传服务、LangChain、Python 运行时或其他依赖。
- 不承诺通过请求体检查解决 524。

## 9. 完成后的架构

```text
用户文字 + 原始附件
  -> 最小 MIME 归一化
  -> NewAPI 官方现有合同
  -> 用户当前模型 + 当前 Provider/K
       -> 成功：模型自由回答或正常请求工具
       -> 失败：显示真实错误，本轮结束
```

产品只修路，不替模型开车。
