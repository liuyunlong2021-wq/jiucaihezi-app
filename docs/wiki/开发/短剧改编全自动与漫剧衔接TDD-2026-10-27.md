# 短剧改编：全自动与漫剧衔接TDD

> 2026-10-27。状态：**用户已确认，源码已实施，自动化回归与类型检查通过；真实界面与模型未验**（见第3节）。解决短剧改编现有三个限制中的前两个；第三个（真实质量）由用户实测。三个都完成后，把使用流程写进新手指导Skill（`jc-new-user-guide`）作为参考文件，用户问“怎么用短剧写作”时直接发送。

## 0. 两个限制

1. **还不是全自动**：现在由模型在一个对话回合里自己往下推，一批100章内容多，中途会停，需要用户回复“继续”。
2. **和漫剧全自动接不上**：漫剧全自动只扫描`项目资料/分集剧本/第N集分集剧本.md`，单集指令也写死这个路径；短剧改编的剧本存在`剧本/第NNN集/分集剧本.md`，确认卡显示“还没有分集剧本”。

先做第2项（改动小），再做第1项。

## 1. 漫剧全自动识别短剧剧本

- `useManjuAuto.prepare()`同时扫描两种剧本：`项目资料/分集剧本/第N集分集剧本.md`和`剧本/第NNN集/分集剧本.md`，合并成集列表，并记下每集剧本的实际路径。
- `episodeInstruction()`改为使用这一集的实际剧本路径，不再写死。
- 同一集两处都有剧本时，以`项目资料/分集剧本`为准（这是漫剧入稿时用户明确交付的剧本），确认卡在这一集旁提示“有两份剧本，使用入稿剧本”。
- 只有短剧剧本、没有漫剧入稿时，切到漫剧全自动直接弹确认卡，不需要再入稿拆集。

测试（先红后绿）：

1. 只有`剧本/第001集/分集剧本.md`、`剧本/第002集/分集剧本.md`时，`prepare`得到第1、2集。
2. 单集指令里的剧本路径是该集的实际路径。
3. 两处都有时使用入稿剧本，并带提示。

## 2. 短剧全自动·改编

### 2.1 入口

“短剧改编”按钮改成和漫剧相同的弹出菜单：

| 菜单项 | 说明 |
| --- | --- |
| 自由改编（默认） | 现在的用法：在对话里按需改编，想做哪步做哪步 |
| 全自动·改编 | 程序按批次推进，每批规划书暂停给用户审，审过自动切分、逐集写剧本 |
| 退出短剧改编 | 已选中时显示 |

短剧只产出文字，不花钱。

### 2.2 启动

1. 用户在全自动模式下发送原文路径（长篇的拆分节点或原文）或短篇全文，可以附上改编思路。
2. 这一回合是**入稿回合**：模型只做原文入库（source_material）并保存source进度，不往下做。
3. 回合结束后弹出**确认卡**：
   - 识别到的章节（短篇显示“全文”），勾选本次改编范围；
   - 每批章数（默认100）；
   - 每次读章数（默认20）；
   - 每批规划书暂停审阅（默认开启，可以关）；
   - 有未完成的运行时，显示“从第N批第M步续做”。
4. 点“开始”后，程序按下面的步骤逐个发指令，每条指令是一个新回合，模型只从Wiki读取需要的文件。

### 2.3 每批的步骤（程序驱动）

| 步骤 | 程序发出的指令 | 程序怎么判断完成 |
| --- | --- | --- |
| 资料 | 【全自动改编·资料】第a–b章 | 进度到materials |
| 规划 | 【全自动改编·规划】第a–b章（按每次读章数分成多条） | 进度为scheme，且新增字段`planned_through`已到这一段的最后一章 |
| 审阅 | 不发指令，弹出审阅卡：主题、发动机、篇章、分集表的摘要，以及“确认”按钮 | 用户点确认，或在对话里提出修改、模型改完后再点确认 |
| 切分 | 【全自动改编·切分】第x–y集 | 进度到cuts，episodes覆盖这几集 |
| 写作 | 【全自动改编·第N集】（每集一条） | `剧本/第NNN集/分集剧本.md`在本次运行中已写入 |
| 收尾 | 【全自动改编·收尾】 | 进度为complete |

一批完成后，自动进入下一批（source传新的chapter_range，集号接着上一批）。

失败处理：

- 一步结束后判断未完成：同一步重发一次；仍未完成就暂停，写明卡在哪一步、原因（进度里的blocked原因或最后的报错）。
- 模型保存blocked：暂停，显示原因。
- 用户点停止：当前回合结束后停止。
- 运行状态写在`改编方案/全自动运行.json`，关闭App或停止后可以从确认卡续做。

### 2.4 运行中显示

输入框上方显示进度条：当前批次、当前步骤（规划第21–40章、待审、切分、第N集、收尾），每集一个状态芯片，以及“停止”按钮。审阅时显示审阅卡。

### 2.5 程序改动

- 运行时（`manju-wiki.mjs`）：scheme进度新增可选字段`planned_through`（章标题，必须是目标范围内的章），程序保存。
- 桌面：
  - 新增`src/runtime/duanjuAuto/autoRunner.ts`（纯逻辑，依赖注入）；
  - 新增`useDuanjuAuto.ts`（准备、开始、停止、审阅确认）；
  - 新增`DuanjuAutoPanel.vue`（确认卡、进度条、审阅卡）；
  - `MemoryWorkbench.vue`中短剧按钮改为菜单，并接入入稿前缀和面板。
  - 菜单、按钮样式、进度条复用漫剧全自动的写法。运行逻辑不和漫剧运行器合并：漫剧运行器大部分是生图、出片和预算逻辑，短剧用不上。
- Skill：`jc-duanju-pipeline`新增“全自动改编”一节，规定入稿回合和各条指令只做指令里的那一步，做完保存进度就结束回合，中途不向用户提问；规划指令要保存`planned_through`。

### 2.6 不做的

- 手机端控制（漫剧全自动有）：这次不做，桌面先跑通。
- 改编完自动接着做漫剧成片：仍放在后面，现在先做到漫剧全自动能识别短剧剧本（第1节）。

### 2.7 测试（先红后绿）

运行器（纯逻辑，模拟依赖）：

1. 两批、每批两段规划：指令顺序为资料→规划×2→（审阅暂停）→切分→逐集→收尾→下一批资料。
2. 审阅开启时停在审阅，确认后继续；关闭审阅时不停。
3. 某一步重发一次仍未完成就暂停并写明原因；模型保存blocked时暂停。
4. 停止后从保存的状态续做，已完成的步骤不重做。
5. 写作步骤只看本次运行中写入的剧本，旧文件不算完成。

运行时：

6. `planned_through`不在目标范围内时拒绝，在范围内时保存。

界面源码合同：

7. 短剧按钮为菜单，含三项；全自动模式下发送的消息带入稿前缀；面板接入。

回归：focused全量、`vue-tsc -b`。

验收边界：自动化测试证明调度顺序、暂停、续做正确；真实界面点击流程和真实模型能否按指令只做一步，需要用户实测。

## 3. 实施与证据

### 漫剧衔接

- `autoRunner.ts`新增`scanEpisodeScripts`，同时识别漫剧入稿剧本与短剧剧本，同集两份时用入稿剧本并列入`duplicates`；`episodeInstruction`新增剧本路径参数，默认仍为入稿路径。
- `useManjuAuto.prepare`改用`scanEpisodeScripts`，确认卡数据带`scripts`与`duplicates`；单集指令使用该集实际剧本路径；`ManjuAutoPanel`在确认卡内提示重复剧本。
- 先红后绿：新增2项（扫描与路径），实施后通过；更新1项旧断言（单集指令调用）与远程测试的确认卡数据。

### 短剧全自动·改编

- 运行器`src/runtime/duanjuAuto/autoRunner.ts`：按批次生成资料、分段规划、审阅、切分、逐集写作、收尾指令；每步读执行进度或本集剧本判断完成，未完成重发一次后暂停，模型保存blocked立即暂停；状态落盘在`改编方案/全自动运行.json`，停止后从原步骤续做；写作只认本次运行中变化过的剧本。
- 运行时：scheme进度新增`planned_through`，必须是目标范围内的章标题。
- 控制器`useDuanjuAuto.ts`、面板`DuanjuAutoPanel.vue`（确认卡、审阅卡、进度条）；`MemoryWorkbench.vue`中短剧按钮改为菜单（自由改编 / 全自动·改编 / 退出），全自动模式下发送的原文带`【全自动改编·入稿】`前缀，入稿回合结束后弹确认卡。
- `jc-duanju-pipeline`新增“全自动改编”一节，规定入稿与各条指令只做一步。
- 先红后绿：运行器5项、`planned_through`1项（并入短剧SDK用例）、界面源码合同1项先失败，实施后通过；短剧按钮旧断言改为菜单。
- 回归：focused 2399项，2396通过、2跳过、1失败（工作区里进行中的iOS任务引起）；scripts测试218项通过；`vue-tsc -b`通过。
- 已知限制：指令发到当前打开的对话，长批次会让同一对话变长；停止在当前回合结束后生效；手机端不能控制。
- 未验证：真实界面点击流程；真实模型能否按指令一次只做一步、按时保存`planned_through`和各阶段进度。由用户实测。
