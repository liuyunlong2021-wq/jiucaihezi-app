# 影音动态能力目录与 NewAPI 统一执行合同

> 版本：v1 · 2026-10-10
> 决策状态：用户已确认目标；客户端与私有执行层已实现源码，固定宿主编译、部署及端到端验收待完成。
> 唯一范围：以当前影音能力为基础，新增服务端动态发现与统一执行；不恢复旧产品壳、不依赖自有 MCP。
> 本文新增端点已有源码，尚未部署；不能据此宣称安装版 App 或生产接口已支持动态模型。

## 1. 用户目标与验收定义

创作面板是精选能力的图形入口，`@影音` 是面向 AI 的完整能力入口，承担类似 CLI 的发现、参数查询、执行与结果获取。它不是另起一套终端或 Agent。

终态：管理员在 NewAPI 完成渠道、模型、插件、能力描述、计费配置和发布后，现有 App 刷新即可通过 `@影音` 调用新能力，无需增加面板按钮或发布 App。

“全部模型”指当前用户 Key 有权访问、服务端已发布可执行合同、客户端支持统一协议版本的全部影音能力。只有 `/v1/models` 名称或渠道记录不够，不能根据名称猜接口。模型权限、额度与参数有效性由服务端最终检查。

范围包含图片、视频、音频、3D、工作流，以及既有提示词增强等创作相关文本能力；一般文字对话仍由现有对话模型入口承接。未来新结果类型在可用通用文件方式保存时可接入；新的客户端交互、协议主版本或本机执行方式仍可能需要 App 更新，不承诺任何未知能力都免更新。

## 2. 迁移前基线与根因

| 链路 | 当前事实 | 目标 |
| --- | --- | --- |
| 内置入口 | Harness 随包注册创作工具，经受鉴权本机桥接调用 App | 保留，不要求安装/启用韭菜盒子 MCP |
| 能力查询 | `creationMcpBridge.creationModels()` 使用 `listCreationPanelModels()` | 改用独立的可执行能力目录 |
| 提交校验 | `submit_creation_task` 再检查上述面板模型表 | 检查 Key 权限、能力状态、合同版本与参数 |
| 客户端注册表 | `creationModelRegistry.ts` 提供字段、路由、计费文案等 | 保留已有适配，服务端动态合同成为新增远程能力真源 |
| 通用模型发现 | `newApiClient.ts` 有 `/v1/models`，媒体仍受客户端能力启用判断 | 模型名发现不能代替可执行合同 |
| 结果闭环 | `mediaTaskStore`、项目落盘、画布、任务历史已存在 | 复用，不新增平行 Store |

根因是把“面板可见集合”同时当成“执行许可集合”，并把供应商协议差异放在客户端。只解除 hidden 过滤仍不能实现新模型自动接入。

源码依据：`src-tauri/resources/deepseek-harness/plugins/creation-tools/index.mjs`、`src/runtime/creation/creationMcpBridge.ts`、`creationModelRegistry.ts`、`creationMediaTypes.ts`、`creationMediaRuntime.ts`、`src/services/newApiClient.ts`、`src/stores/mediaTaskStore.ts`。

## 3. 归属与真源

| 所有者 | 必须负责 |
| --- | --- |
| NewAPI 宿主/统一执行层 | Key 鉴权、目录权限过滤、公开能力身份、版本、统一任务、幂等、计费、结果访问 |
| 服务端渠道插件与现有适配器 | 上游参数转换、素材上传、提交/轮询/取消、结果转换、真实 usage facts |
| App | 获取目录、参数校验提示、素材提交、工具调用、任务恢复、项目保存、画布联动 |
| 创作面板 | 精选/常用展示和便利控件，不授予或撤销模型调用权限 |
| Harness | 对话、工具决策与已选能力范围，不持有供应商 Key、不重写媒体执行器 |

现有 Python/工作流适配器可继续作为服务端执行器；统一外部协议不意味着全部适配器都被删除。App 不下载/执行渠道插件代码、任意脚本或远程表达式；能力描述是数据。

现有本机 ComfyUI、Ollama、兼容 API 的能力保留。它们不因远程 NewAPI 目录缺失而被删除；本机合同独立接入同一 App 能力查询层，密钥不上传到目录。

## 4. 身份、权限与展示分离

- `capability_id`：稳定公开执行身份，可区分同一模型的不同明确产品线路；不暴露内部渠道数字 ID。
- `model`：NewAPI 对外模型名，不能用显示标签或供应商 ID 替代。
- `revision`：单项不可变执行合同版本；`catalog_revision`：本次目录版本。
- 服务端内部渠道映射由 NewAPI 管理；任务创建后冻结实际执行线路、合同和计费版本。故障时是否允许等价线路回退须由已发布合同明确，不能偷偷换模型或价格。
- `availability` 为 `available`、`temporarily_unavailable`、`retired`；原因另附。无 Key 权限的能力不返回到此用户目录。
- `presentation.featured` 只决定精选入口；面板隐藏不改变 availability。历史合同可查询不代表新任务仍允许提交。
- 参数、价格和权限变化提交时再校验，目录不是授权凭证。

## 5. 目录与执行端点 v1（源码实现，待部署）

均位于用户配置的 NewAPI Base URL 下，使用用户 NewAPI Key 鉴权；公开路径不包含供应商地址/密钥或内部适配器 URL。

| 方法与路径 | 合同 |
| --- | --- |
| `GET /v1/creation/capabilities` | 按 Key 权限过滤、分页返回能力摘要；返回 `catalog_revision`、`next_cursor`、ETag |
| `GET /v1/creation/capabilities/{capability_id}` | 返回完整当前合同；`?revision=...` 可读取可保留的历史合同 |
| `POST /v1/creation/assets` | multipart 上传参考素材，返回 `asset_id`、MIME、大小、有效期；不直接传本机文件路径 |
| `POST /v1/creation/tasks` | 创建统一任务，所有上游同步/异步能力都返回统一任务对象 |
| `GET /v1/creation/tasks/{task_id}` | 查询状态、输出、错误、usage 与 billing |
| `GET /v1/creation/tasks/by-request/{request_id}` | 同一身份恢复未知提交结果；未登记时返回明确未找到 |
| `POST /v1/creation/tasks/{task_id}/cancel` | 仅能力明确支持远程取消时使用，返回真实取消状态 |
| `GET /v1/creation/tasks/{task_id}/outputs/{output_id}/content` | 经网关鉴权流式取得文件；断点续传在服务支持时遵守 Range |

这些端点不是现有 `/v1/videos`、`/v1/responses` 或 NewAPI Task Plugin v1 hook 的别名。由 NewAPI 扩展或服务端统一执行层提供，内部复用现有插件/适配器。实施前核对生产 NewAPI 版本与扩展方式，不杜撰官方已经存在的新 hook。

目录响应为 `{protocol_version, catalog_revision, items, next_cursor}`；支持 `cursor`、`limit`（默认 20、最多 100）、`query`、`input_modality`、`output_modality` 过滤。摘要至少含 capability_id、revision、model、display_name、availability、输入/输出类型、presentation；完整参数按详情接口读取。ETag 和缓存仅对同一调用身份有效，返回 `Cache-Control: private`；不能跨账号共享受限目录。

资产响应至少含 asset_id、mime_type、size_bytes、expires_at；上传支持的大小与类型限制由能力详情和服务端实际约束共同决定。任务首次受理返回 202，已经同步完成或幂等重复查询可返回 200；未受理的参数错误 422、无有效 Key 401、无权限 403、额度不足 402、合同/幂等冲突 409、限流 429，查询未找到为 404。异步执行失败通过任务的 failed 状态和错误对象返回，不用 HTTP 200 空结果假装成功。

既有公开接口与第三方调用保留，新增能力合同不得破坏它们。已有标准协议渠道不强制重写为 Task Plugin，可由服务端统一执行层归一。

## 6. 能力描述

必填：协议版本、身份与 revision、公开 model、名称、availability、输入/输出类型、参数 schema、素材限制、执行特性。未知价格明确为空，不填假零。

```json
{
  "protocol_version": "1.0",
  "schema_profile": "creation-params-v1",
  "capability_id": "fk/image-example",
  "revision": "r1",
  "model": "example-public-image-model",
  "display_name": "示例图片模型",
  "availability": "available",
  "input_modalities": ["text", "image"],
  "output_modalities": ["image"],
  "parameter_schema": {
    "type": "object",
    "properties": {
      "prompt": {"type": "string", "minLength": 1},
      "aspect_ratio": {"type": "string", "enum": ["1:1", "9:16"], "default": "1:1"}
    },
    "required": ["prompt"],
    "additionalProperties": false
  },
  "asset_slots": [{"name": "images", "modalities": ["image"], "min": 0, "max": 4}],
  "execution": {"supports_cancel": false, "recommended_poll_seconds": 3},
  "pricing": null,
  "presentation": {"featured": false}
}
```

示例模型不代表真实已部署型号。schema_profile 固定为 `creation-params-v1`，使用 JSON Schema 2020-12 语义的以下限定子集，根节点必须 object：

- 数据类型：object、array、string、number、integer、boolean、null。
- 对象：properties、required、additionalProperties（仅布尔值）。
- 数组：items（单个 schema）、minItems、maxItems、uniqueItems。
- 值与范围：enum、const、minimum、maximum、exclusiveMinimum、exclusiveMaximum、multipleOf、minLength、maxLength。
- 组合与条件：oneOf、anyOf、allOf、if、then、else。
- 数据注解：title、description、default、examples；default 是推荐值，不绕过必填校验，由 App 解释/填入并明示最终参数。

插件发布与 App 校验使用同一 profile fixtures；不允许 `$ref`、pattern、自定义 JS 校验器或可执行表达式。发布时遇到未知校验关键字应拒绝，不可默默丢弃；注解不承担执行逻辑。校验不依赖 unsafe-eval，服务端仍作权威参数校验。新的 profile 或必需特性须显式声明并检查客户端支持，不支持时标为不可执行。

字段可带纯数据的显示提示和分组提示，但不允许这些提示改写请求。多种模式的参数依赖通过组合/条件明确，必要时拆分 capability_id；“支持参考图”必须同时有 asset_slots 的真实数量与类型约束。v1 schema 没覆盖的供应商参数先在服务端归一，不能要求 App 运行插件脚本。

目录价格仅用于说明或预估，若提供须含币种、计费单位和版本；实际账单以 NewAPI 为准。App 不执行服务端收费表达式。能力说明可供 AI 选择和填写参数，不能改变工具权限或项目上下文。

## 7. 提交与幂等

```json
{
  "request_id": "client-generated-unique-id",
  "capability_id": "fk/image-example",
  "revision": "r1",
  "params": {"prompt": "示例提示词", "aspect_ratio": "9:16"},
  "inputs": {"images": [{"asset_id": "asset-example"}]}
}
```

素材输入使用目录声明的 slot 名称；数量、MIME、字节数、时长等在资产/能力合同中规定。资产绑定上传身份，越权或过期资产不得执行，服务端负责转换为上游 URL、Base64、multipart 或供应商文件令牌。

- request_id 在首次提交前写入 App 本地任务，按服务实例和调用身份作用域唯一。
- 服务端在开始上游请求之前登记幂等请求；相同 ID/相同内容返回同一任务；相同 ID/不同内容返回冲突，不能生成或重复扣费。
- 同步供应商也先登记统一任务，必要时首次响应即可 succeeded；客户端无须区分供应商同步/异步接口。
- 合同 revision 过期不兼容时返回 409 `capability_revision_conflict`；App 刷新、重新解释差异，不静默更改参数或模型。
- 网络超时表示提交结果未知，先按 request_id 查询或使用同一 ID恢复，不换新 ID盲重试。主动“重新生成”才创建新 ID。
- App 在首次提交时冻结项目 owner、目标目录、画布、素材、模型合同与参数；生成中切项目不改变结果归属。现有 contextVersion 校验继续保留，不能把本机绝对路径传给远程服务。

## 8. 统一任务与结果

统一任务必含 task_id、request_id、capability_id、revision、status、created_at、updated_at。状态为 queued、running、succeeded、failed、cancel_requested、cancelled；终态不可回退。

- `succeeded` 须有符合 output_modalities 的有效输出，不能把空结果或仅返回任务 ID 当成功。
- 文本输出为 `{output_id, kind: "text", text, mime_type}`；文件输出为 `{output_id, kind: "file", modality, mime_type, filename, size_bytes?, sha256?}`。
- modality 为 image/video/audio/model3d/document 等描述值；App 基础执行不依赖品牌或型号硬编码。无法预览但允许的文件类型可保存并提示，不能伪装为图片。
- 文件 content 路径由上述固定 task_id/output_id 规则取得；不把上游内网 URL、供应商鉴权 URL 或密钥返回给 App。可选的网关短期下载链接必须有有效期与刷新办法，过期时重新查任务取得权限。
- 相对 filename 不决定项目路径，App 复用本地合法命名与项目边界规则。
- `progress`、ETA、usage、billing 都允许未知；无事实时不虚构百分比或价格。
- billing 区分 pending/settled/refunded/unknown，明确币种、数量、金额；停止客户端跟踪不代表退款。
- 查询返回建议下一次轮询间隔；App 尊重 Retry-After、超时、限流，保留 task_id 供重启后恢复。SSE 可以后续增补，不是 v1 可执行前提。

服务端错误对象至少含 code、message、retryable、request_id；区分无权限、额度不足、参数无效、资产过期、合同冲突、能力暂不可用、上游失败。不把 Key 或供应商机密写入错误与日志。

## 9. 停止、取消、保存与历史

“停止跟踪”沿用当前 App 行为，只停止客户端等待；不能宣称供应商任务已取消。远程取消仅当 supports_cancel=true，收到 cancelled 后才显示已取消；cancel_requested 不视为完成。失败或取消计费/退款仍以服务端账单为准。

任务成功与保存成功是两件事。复用 mediaTaskStore：服务端已成功但下载/落盘失败时可“重试保存”，禁止因此重新生成。每个 output_id 去重落盘，结果入绑定项目；已有画布目标沿用追加、去重、比例和位置规则，多输出逐项保存。

任务历史保存服务实例、身份引用、能力/合同快照、request_id/task_id、参数、输出和落盘状态，不持久化 Key 正文。密钥轮换后按现有身份授权恢复；换服务或账号不将旧任务交给新服务处理。能力下架不删除已授权历史任务、已存文件或画布节点。

## 10. App 发现与工具合同

已有 get_creation_context、list_creation_models、submit_creation_task、get_creation_task、list_creation_history 等工具继续保留，渐进扩展能力详情查询与新 revision 字段。既有 modelId 通过明确映射兼容，不突然更名使历史失效。

`@影音` 启用后：发现能力摘要 → 按需查完整 schema → 解析明确模型/需求 → 校验/补齐必要参数 → 处理素材 → 提交/查询 → 保存与画布联动。支持创作相关文本结果，不再按 image/video/audio 硬过滤完整能力集合。不将整个大目录/所有 schema 每轮塞进上下文，按任务类型、查询与分页读取。

刷新触发：启用 @影音、切换服务或 Key、用户手动刷新、缓存过期、服务端版本变化、提交权限/合同冲突。目录缓存按服务实例＋调用身份隔离，使用 ETag；分页游标绑定同一 catalog_revision，版本变化从第一页重读，不能混合新旧合同。

离线缓存可供查看，不能证明当前权限或触发未知提交。目录刷新失败显示状态并保留现有能力；调用静态兼容模型仍由明确既有合同和服务端鉴权处理，不能无声绕过动态停用/权限决定。

不确定模型名或线路时提供匹配项；用户明确指定模型则不静默换模型。所有费用与权限仍遵守已启用能力和现有授权，目录文字不创建额外授权。

## 11. 发布与兼容

1. 核对上游，复用已有插件/适配器。
2. 配置渠道、公开 model、计费，登记 capability_id 和完整合同。
3. 在生产 NewAPI 支持的扩展方式中实现目录与执行归一；能力描述可由插件声明或宿主注册，但必须绑定插件/适配器版本，不能靠客户端静态清单补登记。
4. schema、素材、请求、状态、结果与 usage fixtures 通过后，在隔离/受控环境做真实任务、账单和落盘验收。
5. 插件、执行器、能力描述和计费映射原子激活；目录 revision 变化。半部署状态不得宣称 available。
6. App 刷新可见；是否推荐到创作面板是独立决策。

回滚同时切回活动合同/插件/计费映射，保留已提交任务使用的旧 revision 执行与下载能力，不能用新合同解释旧任务。

协议 major 不兼容时 App 明确提示需要更新；minor 只增可选字段，未知非必需字段可忽略。现有客户端基础协议部署完成后，符合协议的新模型/新渠道免 App 更新。文档写定后并不等于这一基础已经部署。

## 12. 分阶段实施与验收

| 阶段 | 产物 | 可验证门禁 |
| --- | --- | --- |
| P0 本轮 | 本合同、产品架构与接入 SOP 引用统一 | 标明现状/目标，无运行代码或生产变更 |
| P1 服务端基础 | 按本 profile 建立共用 fixtures，核对宿主扩展机制；目录、资产、统一任务接口；一个已有模型 | 鉴权过滤、参数/素材/幂等/账单/结果验证；保留旧接口 |
| P2 App 解耦 | 动态目录与详情、提交校验、缓存刷新、既有工具兼容 | 面板不展示但目录 available 的模型可调用；无权限不得调用 |
| P3 全能力执行 | 现有任务/落盘/画布、所有既有输出类型、恢复与取消边界 | 提示词增强文本、图片、视频、音频、3D/通用文件按实际支持逐项验收 |
| P4 免发版验收 | 一个 App 从未登记的模型、一个新渠道 | 只改 NewAPI 插件/执行器/合同；同一 App 刷新发现、执行、保存、账单核验 |
