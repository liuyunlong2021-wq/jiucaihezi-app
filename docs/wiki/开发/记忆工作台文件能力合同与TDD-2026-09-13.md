## 2. 合同（现行，10 条）

1. `@文件` 是**用户侧唯一的本机操作开关**，一开即全权：`read`、`glob`、`grep`、`write`、`edit`、`write_text_batch`、`mkdir`、`move`、`copy`、`delete`、`terminal`、`skill_run_script`、`export_3d_scene_video`。
   - 已知旁路（未修，见 §8）：选中任意 Skill 会注入 `read`；Skill 声明 `allowed-tools: file` 会展开成完整文件集（`wiki-memory` 就声明了）。
2. 授权**只能**来自用户消息里出现的**绝对路径**。程序不猜路径；模型不得自行扩大范围。
3. 文件工具的授权粒度是**路径前缀**，比较前必须先折叠 `.` 与 `..`：
   - 给**目录** → 该目录及其整个子树可读、可写、可建目录、可移动、可复制、可删除；
   - 给**文件** → 仅该文件。
4. 相对路径**只在项目内**解析（`relative → <projectRoot>/relative`）。项目外必须写绝对路径。
5. 授权在本会话内**累积**；会话切换即失效。
6. **零弹窗**：上述 13 项工具与 MCP 工具一律免确认。判断函数只在“文件工具碰到未授权项目外路径”时报错，不再有“需要审批”的分支。
7. 文件工具的授权范围外一律**硬失败**，返回可读提示（“请把目标路径发给我”），不得静默降级为项目内路径。比较前折叠 `.`/`..`；符号链接逃逸**按用户决策不修**（见 §8）。
   - **终端不适用本条**：终端命令不做路径扫描，拿到就可以在任意路径执行（用户 2026-09-13 显式决策）。
8. `read` 返回**原始文本**。行号只能作为显式可选的展示信息，不得混进可编辑内容。
9. **文件权限规则只允许写在系统层。任何 Skill 不得声明、限制或绕过文件权限。**
   - 用户决策（2026-09-13）：`wiki-memory` 声明 `allowed-tools: file` 的行为**保留不动**；Skill 声明只能在本产品已有的工具白名单内选取，不能扩大项目外路径的授权。
10. **搬移类任务必须走 `copy` 或终端**，不得逐个读出来再重写：单文件、整目录都用 `copy(src, dst)`；目标已存在时拒绝，不静默覆盖。

### 2.1 能力划分（二次定稿）

区分标准是“**动本机**”还是“**生成内容**”：

| 类别 | 归属 | 内容 |
| --- | --- | --- |
| 操作类 | `@文件`（全权） | 文件十项、终端、Skill 脚本、本地 3D 渲染导出 |
| 生成类 | 保持独立开关 | `@图文`（文档/HTML/导图）、`@影音`、`@3D` 的 `create_3d_scene` / `edit_3d_scene` |
| 方法 | `@Skill` | 只提供方法约束，不增减权限 |
| 外部工具 | `@MCP` | 用户勾选具体工具即授权 |

不合并生成类的理由：它们不涉及本机权限，合并只会让每次文件操作都背着 7 个用不上的工具，模型选择变多、准确率下降。

### 2.2 明确不做

- **Web Search / Fetch**：2026-08-07 用户已把 Jina `web_search`/`read_url` 迁出产品，仓库有测试锁着（`scripts/__tests__/memory-product-separation.test.mjs`）；本轮不恢复。
- **Subagent**：用户列出的 9 个模块里，`git`、代码搜索、测试/Build、Issue/Ticket 都是 **shell 命令的别名**，放开终端即自动获得；只有 Web 与 Subagent 是真新能力。Subagent 需要改引擎（嵌套 loop、配额、取消传播），而当前场景是串行简单任务，收益不成比例。
- **终端命令级路径扫描**：用户显式选择“不管”（见 §1 决策 5）。

补充边界：

- `delete` 走系统废纸篓（可恢复）；`copy` 目标已存在时拒绝，避免静默覆盖。
- `maxToolRounds` = **64**（引擎默认值）。旧值 12 装不下“整理一个目录”这类批量活，到顶会静默收走工具、逼模型空口收尾。
- 约束**换地方而不是消失**：权限层不再设限，行为靠 Skill 规则与用户指令约束；系统提示新增两句，要求直接用工具完事、搬移用 `copy`/终端。
- Web 端没有本机文件能力，继续使用既有浏览器存储与草稿/安装卡链路，不伪造 Desktop 落盘。

## 4. 目标行为（两个场景）

**场景 A（用户给路径，主路径）**
设置 → Skill → 我的 Skill → 「修改」→ 输入框自动带 `@skill-creator` + `@文件` + Skill 目录绝对路径 + 空的"修改要求" → 用户打字即可让模型读 `SKILL.md`、读改 `references/*`、新建文件，**零弹窗**，改完即生效。

**场景 B（用户只给 Skill 名，便捷路径）**
`skill_creator_load_installed_skill` 仍按精确 ID 只读加载 → 草稿 → 安装卡。此路径保留，但**不再是唯一入口**。
