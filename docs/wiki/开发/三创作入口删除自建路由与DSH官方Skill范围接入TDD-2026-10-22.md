# 三创作入口删除自建路由与 DSH 官方 Skill 范围接入 TDD

> 日期：2026-10-22；按用户最新要求收敛。
> 状态：源码实施及本地自动化完成；真实安装版、跨平台和生产模型验收未执行，未发布。
> 本次只做四件事：撤掉自建路由和每轮自动调用；三个按钮只限定 Skill 集合；电脑操作设置默认关闭；保证队列、重启恢复、多会话、子任务和历史兼容。

## 1. 目标与边界

点击「漫剧制作／短剧写作／小说创作」只决定当前可用的 Skill 集合。Agent 经官方目录看到名称与用途，按官方规则调用 skill 加载正文，再按需读取资源、完成任务。退出创作模式后恢复普通 Skill 使用。

彻底删除自建路由，不迁移其规则：不把旧路由的内容搬到其他 Skill、系统提示、目录描述、Wiki 或隐藏公共规则中。现有业务 Skill 正文和资源原样保留；原生 Wiki、present 以及必要的文件/图片读取等工具保持现状。本次不重写创作方法、默认模型、归档约定或业务流程。

不新增分类模型、关键词路由器、路由正文去重层、上下文引擎、@电脑操控或新的授权流程。DSH 的 Agent 循环、Skill 渲染、目录更新、压缩、子代理调度和等待机制继续用官方实现。

## 2. 改动一：撤掉自建路由和每轮自动调用

- deepSeekPrompt 不再把三个创作按钮转成 /jc-manju-zhizuo、/jc-duanju、/jc-novel。普通发送、运行中排队、编辑重发和桌面远程控制都覆盖。
- 删除宿主从消息正文解析这些自动手势、据此运行自建路由的链路。内置包来源绑定仅保留供 Skill 集合与官方加载使用的必要部分。
- 移除纯路由 jc-manju-zhizuo、jc-duanju 的生产打包、目录、加载路径和引用，不留自动执行的兼容路由。其附加规则直接退出，不复制到其他地方。
- 清单改成允许的业务 Skill 名称，不包含 router 字段、执行顺序、自动阶段或下一步规则。
- jc-novel 含实际小说创作方法，保留为按需加载的业务 Skill；不因原先被当作按钮入口而删除它的正文和参考引擎。
- 用户自己输入有效业务 /name 时仍按官方显式调用；旧纯路由不重新启用。

## 3. 改动二：三个按钮只限定 Skill 集合

| 入口 | 可选集合 |
| --- | --- |
| 漫剧制作 | 现有14个业务 Skill，排除纯路由 jc-manju-zhizuo |
| 短剧写作 | jc-xiangmuziliao、jc-duanju-cehua、jc-duanju-fenji、jc-duanju-xiezuo |
| 小说创作 | 现有业务 Skill jc-novel及其包内参考资源 |
| 单独选择Skill | 只允许选中名称；官方目录/skill渐进加载，个人与项目Skill同样支持 |
| 未选创作入口且未选Skill | 原有普通发现 |

模式作为结构化选项传递，不伪装成提示词或根据历史内容猜测。复用现有会话创作偏好和SDK桥接，不另存一套对话或消息正文。

保留官方 skill 工具。范围必须同时作用于目录和加载：只隐藏目录、仍能按名字加载范围外 Skill 不合格；只注册高优先级内置 provider、却让其他 provider 的全部名称混进来也不合格。

优先复用官方配置、作用域和 provider；当前版本没有 skills.restrict API，不得臆造调用。确需接入适配时只做名称范围检查，允许项继续委托官方加载和正文渲染；不得复制官方加载器、改写其选择规则或再次屏蔽 skill 工具。范围按会话/Agent隔离，不改工作区全局目录影响其他会话。

目录只发布现有名称和用途元数据；正文命中后由官方读取，资源按需读取。用户切换入口后沿官方目录更新，不重复注入全部正文，不改现有业务 Skill 的命中描述来塞回旧路由规则。

## 4. 改动三：电脑操作设置默认关闭

保留设置页原开关：缺少 jc_computer_use 或值为0时关闭，明确保存为1时开启。旧版“没有记录所以默认开”的用户改为关闭；明确的用户选择继续保留。

关闭时不注册电脑插件、不启动其原生提供方，实际模型请求里没有 cua_driver_native__ 工具。用户在设置中开启后，现有电脑操作完整可用，关闭后后续请求撤销注册。配置交接沿用现有生命周期，不杀掉其他会话正在执行的任务。

不开新的@入口、不每轮弹窗、不在任务结束后擅自改回开关。操作系统权限和现有权限机制保持现状。

## 5. 改动四：兼容现有运行链路

- 队列：每条消息保留发送时选择的 Skill 范围；编辑和删除一起处理，出队不误读后来切换的按钮。
- 运行中输入：不在当前步骤中途改变可用范围；继续使用官方排队/steer语义，范围切换在安全边界生效。
- 重启恢复：复用原Session和消息身份，恢复创作选择及待办范围；不创建替代会话、不重放历史路由为新调用。
- 多会话：同工作区不同会话互不污染，不因切换按钮重启共享Runtime、打断后台任务。
- 子任务：沿用官方委派、执行、等待和取消；业务 Skill 范围继承所属任务，不越过集合，也不丢包内资源。
- 历史：完整对话、确认内容、项目文件及旧产物保留。旧路由文字只是历史，不新执行；不批量清洗用户记录。后续上下文收敛继续交给官方机制。
- 现有工具：Wiki/present、文件/图片、MCP、影音、3D、画布、权限、多窗口及远程控制保持原有能力和入口，不额外扩展或删减。

## 7. 最小实施顺序

1. 锁定自动路由与默认电脑工具的失败测试；确认官方skill恢复保持。
2. 三入口传结构化范围，撤掉自动手势与自建路由执行链；接通官方目录/加载范围。
3. 删除纯路由文件和生产引用，不迁移、不复制旧规则；业务Skill和资源保留。
4. 设置电脑操作缺省关闭，核对手动开启、关闭及后台任务交接。
5. 完成队列、恢复、多会话、子任务和历史兼容回归，检查真实请求，更新文档。

本地自动化通过只登记源码接入完成；真实平台与用户升级验收继续单列。安装版生效与发布单独记录，仍随用户下次更新一并发布。本次不动服务器、计费、模型协议/容量/重试或压缩策略，也不声称请求变小就解决了全部上游卡顿。

## 9. 追加：单选Skill也只圈定白名单（2026-10-22）
