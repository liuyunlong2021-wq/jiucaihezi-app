## 1. 目标

`v2.1.2` 收口以下已确认问题：

1. 修复创作画布切换主题后仍停留在旧背景色的问题。
2. 为已确认迁站的 `rh-grok-image-video` 增加 RunningHub 全球站路由，中国站与全球站按模型并存。
3. 修复 Veo 受保护视频在 Desktop 无法本地化、预览和下载的问题。
4. 把通用 AI 应用从“默认视频”改为可信的 `image/audio/video` 输出合同。
5. 修复记忆工作台首次回复闪空、长任务缺少过程反馈、联网搜索默认抢占工具，以及设置页缺少版本号的问题。

完成后发布 Web、Mac Apple Silicon、Mac Intel、Windows x64 `v2.1.2`。iPhone/iPad 在本版本稳定后继续；Android 不进入本轮。

## 2. 不做事项

- 不把 RunningHub `.cn` 全局替换成 `.ai`。
- 不在本版本接入 ZX Grok 1.5 三模型；待真实合同和计费确认后另行实施。
- 不在本版本迁移尚未逐个确认的其他国外模型。
- 不对付费 POST 做“失败后换站自动重试”，避免重复任务和重复扣费。
- 不让 ZX 自动接管 RunningHub 已提交或失败的任务；ZX 是用户主动选择的备选模型。
- 不在客户端保存渠道 ID、全球站 Key、ZX Key 或上游真实模型名。
- 不接入三角色 TTS；该需求已取消。
- 不为单个 AI 应用硬编码一套独立表单、轮询器或媒体存储。
- 不新增媒体数据库、任务数据库或第二套历史系统。
- 不把当前界面主题写入 `.jccanvas`，不修改用户节点颜色或媒体导出颜色。
- 不因为本轮修改重写 NewAPI、创作运行时或 ProjectFileService。

## 3. 已确认事实

### 3.1 RunningHub 双站

- 标准 API 当前统一使用 `RH_BASE_URL=https://www.runninghub.cn`。
- AI App 的运行、状态和结果已经使用 `runninghub.ai`，节点发现和上传仍有 `.cn` 端点。
- RunningHub 公告确认部分模型 API 于 `2026-07-30 23:59:59` 后迁往全球站；页面快捷创作和 RHTV 不受影响。
- 已确认 `rhart-video-g/image-to-video` 属于迁移模型；同家族文生、编辑以及 Sora2 各端点仍必须逐个核验，不能根据名称推断。
- 当前创作面板中的 Grok Video 活跃项只有文生、图生；`rh-grok-video-edit` 已从产品注册表移除。
- 当前 Sora2 活跃项为文生、图生、角色上传；`rh-sora2-realistic` 已从产品注册表移除。
- `rh-adapter` 仍残留 `rh-grok-video-edit`、`rh-sora2-realistic` 等 mapping，属于待清理的后端死引用，不代表恢复产品模型。

### 3.2 ZX 三个候选模型

供应商页面显示：

| 供应商页面展示名（拟作为 NewAPI 对外名） | 页面标价 | 当前判断 |
| --- | --- | --- |
| `grok-1.5-video-6s` | `$0.120/次` | 候选；先做真实验证 |
| `grok-1.5-video-10s` | `$0.088/次` | 候选；6 秒通过后再验证 |
| `grok-1.5-video-15s` | `$0.065/次` | 候选；6 秒通过后再验证 |

页面同时写有“一次是一秒的价格”，与“按次”和模型名中的固定秒数存在歧义。上述价格只能作为供应商页面证据，不能直接成为韭菜盒子售价；真实计费单位、总成本和 NewAPI 价格配置必须单独核对。

最新 ZX OpenAPI 已提供：

- 提交：`POST /v1/videos`
- 兼容提交：`POST /v1/videos/generations`、`POST /v1/video/generations`
- 查询：`GET /v1/videos/{id}`
- 内容：`GET /v1/videos/{id}/content`
- 状态：`queued / in_progress / completed / failed`
- 完成结果：`video_url`
- 单图可以使用字符串 URL/DataURL，文档也声明兼容 `{url}`、`{image_url}` 和多种数组形式。

当前请求合同没有输入视频字段，因此三个模型只能作为文生视频、图生视频备选，不能替代 Grok 视频编辑、Sora2 角色上传或其他视频编辑能力。

但是 OpenAPI 的上游模型枚举只有 `grok-imagine-video`、`grok-imagine-video-1.5`、`sora-2`、`sora-2-pro`，没有截图中的三个 `grok-1.5-video-*` 名称。因此实施前必须确认三个名称是：

1. ZX 新增的真实上游模型名；或
2. NewAPI 渠道模型别名，需要映射到 `grok-imagine-video-1.5` 并固定时长。

未确认模型映射和时长注入前，不得把三个名称加入创作面板。

### 3.3 ZX 上次失败不能算已修

2026-07-21 的真实单图任务返回：

```text
HTTP 400: json: cannot unmarshal object into Go struct field .Alias.image of type string
```

本地曾分别修改上传路径、运行时请求体和序列化前归一化，mock、类型检查和构建均通过，但真实付费任务仍失败。最新 ZX 文档声称上游已兼容字符串、对象和数组，这构成重新验证的理由，不构成成功证据。

当前产品注册表已不包含这三个模型。本轮不得恢复旧计划或旧提交中的注册代码；只能根据本 SDD 重新取得真实合同证据后，以最小改动接入。

本轮必须在三个边界记录脱敏证据：

```text
Creation Runtime 序列化前字段类型
  → NewAPI 收到的字段类型
  → ZX 上游响应的任务 ID / 错误类型
```

日志只能记录字段名、类型、数组长度和 URL 主机，禁止记录 Key、完整 DataURL、用户图片或签名查询串。

### 3.4 AI 应用输出类型

- `rh-adapter` 已能为自定义 AI App 声明 `output_type=image|video|audio`。
- 前端通用 `rh-aiapp` 仍把 `task=ai-app` 映射成视频任务，这是图片/音频 AI 应用的根因。
- 输出类型不能由节点名称、结果扩展名或第一个返回 URL猜测，必须来自服务器注册的可信应用目录。

### 3.5 三角色千问 TTS

需求已取消，本版本不注册应用、不增加白名单、不改前端。

### 3.6 创作画布主题没有刷新

## 4. 设计决策

### 4.1 RunningHub 按模型选择站点

每个 RunningHub mapping 增加明确的 `site=cn|global`，由模型注册决定提交前的站点：

```text
model
  → mapping(endpoint, site, output_type)
  → 对应站点上传
  → 对应站点提交
  → poll URL 保留 site
  → 对应站点查询和取结果
```

中国站和全球站允许使用不同环境变量 Key。站点信息必须进入可恢复的 poll URL 或任务元数据，不能只保存在 adapter 内存映射里；adapter 重启后仍应继续查询旧任务。

如果某模型全球站合同尚未验证，先在 NewAPI 渠道中移除该模型名，使前端显示不可用，不从代码永久删除。验证完成后恢复；长期没有可用合同再讨论删除。

### 4.2 ZX 是独立可选备份，不是自动回退

三个 ZX 模型仍把截图中的模型名原样发送给 NewAPI，由 NewAPI 选择 ZX 渠道并完成必要的上游模型映射。客户端不出现渠道 ID，也不发送 `grok-imagine-video-1.5` 代替用户选择的模型名。

备选范围明确限定为文生视频和单图视频；不在 UI 上标记成视频编辑模型。

三个模型共用一份参数合同：

- `prompt`：文生必填，单图模式可选但产品仍要求填写，避免不可控结果。
- `images`：0–1 张；无图为文生视频，有图为图生视频。
- `duration`：由模型名固定为 6/10/15，不显示可调滑块。
- `aspect_ratio`：只提供上游明确支持的比例。
- `resolution`：首轮只开放真实验证通过的分辨率，不因文档列出 1080p 就默认开放。
- 提交统一使用 `/v1/videos`，轮询统一使用 `/v1/videos/{id}`。

禁止三个模型一起先注册再测试。验收顺序固定为：

1. 6 秒文生视频真实成功。
2. 6 秒单图视频真实成功，确认 `image` 到 ZX 边界仍为字符串或上游已兼容的形态。
3. 确认视频落当前项目、预览、下载、画布和历史恢复。
4. 再用同一合同分别验证 10 秒、15 秒。
5. 三个都通过后才同时显示在正式创作面板。

### 4.3 通用 AI 应用使用服务器目录

AI 应用目录的最小合同为：

```text
webappId
label
outputType: image | audio | video
billingModel
```

服务器目录是唯一事实源，前端不再维护另一份应用到输出类型/计费模型的硬编码映射。节点发现继续使用现有 `app-info -> nodeInfoList -> 动态表单`，运行时根据 `outputType` 进入已有图片、音频或视频提交、轮询、保存和播放器链路。

未注册输出类型的任意 `webappId` 必须拒绝运行，不能回退成视频。

### 4.4 三角色 TTS

取消，不实施。

### 4.5 Veo 只补共享下载认证

现有 Desktop 下载命令增加可选请求头；仅韭菜盒子 API 同源受保护 `/content` 携带当前 Bearer Token，第三方 CDN 不携带 Token。成功后仍一次写入当前项目，复用现有预览、下载和画布合同，不新增 Veo 专用下载器。

### 4.6 画布只刷新运行时主题

继续复用现有 CSS 变量和 `MutationObserver`。主题变化时更新 Leafer 当前 renderer 的背景色并触发重绘，同时刷新选择框、媒体边框和运行时文字色；不重建 Leafer App，不保存主题色到画布文档，不改用户主动设置的画笔、箭头、文字和标记颜色。
