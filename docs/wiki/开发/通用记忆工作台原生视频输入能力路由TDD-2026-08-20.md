# 通用记忆工作台 Gemini 原生视频能力声明 TDD

> 状态：待实施（元数据一致性，不作为 NewAPI 视频故障修复）
> 日期：2026-08-20
> 范围：Desktop 记忆工作台的 Gateway Gemini 对话模型能力声明与 MP4 回归保护

## 1. 目标

1. 韭菜盒子 Gateway 下所有 Gemini 对话模型统一声明支持 `text`、`image`、`video`、`audio`、`file` 输入，不维护单型号白名单。
2. 记忆工作台使用 Gemini 发送 MP4 时，继续按现有 OpenAI 兼容格式构造 `video_url`，不静默丢弃视频。
3. 本轮只修正能力声明，不改变图片、音频、Office/PDF、通用文件、未知 MIME 和非 Gemini 模型的现有发送行为。

本轮不增加 FFmpeg、Whisper、Skill、MCP、本地视频处理、模型自动切换或 NewAPI 配置管理。

## 2. 已确认现状与根因

- `src/utils/directMessageBuilder.ts` 已会将 `video/*` 附件构造为 `video_url`；MP4 不是被 Studio 丢弃或转成普通文字。
- `src/runtime/memory/memoryChat.ts` 已把记忆模式中的原生附件交给共享消息构造器，再通过 `/v1/chat/completions` 发往 Gateway。
- `src/runtime/direct/modelInputCapabilities.ts` 只把 `jiucaihezi:gemini-3.5-flash` 登记为五模态，其他 Gateway Gemini 只被解析为 `text + image`。这是当前需要修正的代码不一致。
- 本次 MP4 失败的 NewAPI 请求透传配置已由用户手动修正，不属于本 TDD 的实施范围。
- 历史提交 `424dfe85` 、`ab7fa414` 和 `0e57db10` 已因模型能力数据不完整而删除通用附件过滤。重新引入五模态本地预检会重现已修过的回归。

因此，本次视频故障的根因修复是已完成的 NewAPI 配置更正。App 侧剩余工作只是更正 Gateway Gemini 对话模型的能力元数据，并锁定已有 MP4 消息形状；该元数据当前不参与记忆工作台的附件发送决策，不得宣称它单独修复了 MP4 读取。

## 3. 产品合同

### 3.1 Gemini 能力声明

- 仅对 `providerId === "jiucaihezi"` 且 `capability === "text"` 的可执行对话模型应用 Gemini 家族规则。
- 模型 ID 中以独立家族名出现的 `gemini`（大小写不敏感）统一声明 `text + image + video + audio + file`。
- `gemini-3.1-flash-lite-preview`、`gemini-3.1-pro-preview`、`gemini-3.5-flash` 和以后新增的 Gateway Gemini 对话型号共用同一条规则。
- Gateway Gemini 对话家族合同高于模型目录中可能缺字段的 `inputModalities`；不能因目录只返回 `text + image` 而再次丢失视频能力。
- 图片、视频等媒体生成模型不得因名称含 `gemini` 而被识别为对话视频输入模型。
- 自定义 Provider 和本地模型不因名称含 `gemini` 继承 Gateway 声明；它们继续使用自身显式 `inputModalities`。
- 非 Gemini Gateway 模型继续使用现有解析结果，不在本轮推断新能力。

### 3.2 附件行为保持不变

- MP4 继续保留真实 MIME 和 Base64 数据，构造为 `video_url`。
- WebM 等其他 `video/*` MIME 继续按现有合同原样透传，不增加 Studio 静态白名单。
- GIF 和其他图片、MP3/WAV/M4A 等音频、PDF 与通用二进制文件的消息形状保持不变。
- Office/PDF 已转为项目 Markdown 或 `textContent` 的稳定主链保持不变，不重新发送已转换的原始二进制。
- 不使用新的能力声明过滤、删除、转码或替换当前附件。Gateway/上游仍负责拒绝其实际不支持的 MIME 或请求体。

### 3.3 失败边界

- 真实渠道返回 400、413、415 时，继续使用现有附件错误解析，不误报为本地解码失败。
- 不把模型名称、文字请求成功或渠道健康检查当成真实 MP4 验收证据。
- 不自动把视频改成图片 MIME，不截帧、转码、删除附件或改选模型。

## 4. 最小技术设计

### 4.1 仅修正能力真源

- 在 `resolveModelInputModalities()` 的输入中加入已有的模型 `capability`，用 Gateway + 对话模型 + Gemini 家族三个条件替代当前单型号白名单。
- `agentStore.normalizeGatewayModelEntries()` 已知道归一化后的 `capability`，只需将其交给现有解析器。
- Gateway Gemini 对话家族规则先于显式 `inputModalities`；非 Gemini 和自定义 Provider 的显式声明优先级保持不变。不新建能力表、Provider 适配器或 MIME 注册表。

### 4.2 不修改请求构造

- `directMessageBuilder.ts`、`memoryChat.ts` 和 `newApiAttachments.ts` 本轮不修改。
- 不恢复 `resolveCurrentModelAttachments()`，不将五模态能力表接入共享附件发送前置过滤。
- 旧缓存中的 `inputModalities` 本轮不做迁移：该字段当前不参与附件发送决策，Gateway 模型目录刷新后会覆盖它。

## 5. TDD 验收

### 5.1 能力解析测试

1. 红灯：当前只有 `gemini-3.5-flash` 获得五种输入能力，其他 Gateway Gemini 对话模型缺少 `video`、`audio`、`file`。
2. 绿灯：Gateway 下的 `gemini-3.1-flash-lite-preview`、`gemini-3.1-pro-preview`、`gemini-3.5-flash` 和一个未来型号 `gemini-3.6-flash` 均精确返回 `text`、`image`、`video`、`audio`、`file`。
3. Gateway Gemini 对话模型即使携带残缺的显式 `inputModalities: ['text', 'image']`，仍按家族合同返回五模态。
4. Gateway 中 capability 为 `image` 或 `video` 的生成模型即使名称含 `gemini` 也不套用对话模态。
5. 自定义 Provider 的 `gemini-*` 不自动继承 Gateway 能力；显式声明仍原样保留。
6. `gpt-*`、Claude、DeepSeek 等非 Gemini 模型的现有解析结果不变。

### 5.2 附件静态回归

1. 现有 MP4 测试继续得到 `video_url: data:video/mp4;base64,...`。
2. 现有“未知视频 MIME 原样保留并继续构造 `video_url`”测试继续通过，不将 WebM 改成本地错误。
3. 图片、GIF、音频、通用文件和 Office/PDF `textContent` 的现有消息形状测试继续通过。
4. 静态扫描确认没有重新引入 `resolveCurrentModelAttachments()`、全附件能力预检或 NewAPI MIME 白名单。
5. `memoryWorkbench` 现有附件导入、文档转换、发送后保留项目原件的测试继续通过。

### 5.3 真实平台验收

1. 先在不修改 App 业务代码的情况下，Desktop 分别选择一个 Gemini Flash 和一个 Gemini Pro，通过已更正配置的 NewAPI 发送同一个短 MP4。
2. 提问视频中的可验证内容，两个模型都必须基于视频回答；不以上传成功、文字回答或渠道健康代替内容验证。
3. 实际请求中必须仍包含 MP4 `video_url`；失败时记录 Gateway 返回的原始状态码和错误，不写成 App 已通过。
4. 跑现有图片和 Office/PDF 各一条 Desktop 核心流程，确认没有因本次能力声明发生行为变化。
5. 若第 1 步已通过，用户可见的视频问题已由 NewAPI 配置解决；后续元数据改动不得扩大为请求路由重构。
6. 若第 1 步仍失败，先比对 Studio 最终 JSON、NewAPI 转换后请求和 Gemini 原始错误，另立根因 TDD；不从本能力元数据方案中猜测增加补丁。

## 7. 审计结论与禁入边界

- 删除 NewAPI 配置章节：已手动完成，继续写入实施 TDD 会造成静态、重复的部署真源。
- 禁止本地 MIME 白名单：它会直接破坏 WebM、GIF、M4A 和通用文件的现有透传合同。
- 禁止通用五模态发送前预检：能力数据并非 Gateway 的完整实时合同，强制过滤会误伤已能工作的附件。
- 禁止修改文档主链：Office/PDF 转 Markdown/文字是已确认产品决策，与 MP4 问题无关。
- 禁止扩大到 Web、Mobile、音频或通用文件验收：本轮只解决 Desktop Gateway Gemini 的视频能力声明和 MP4 回归保护。
- 非 Gemini 的本地视频拦截延后：只有当 Gateway 能稳定返回权威 `input_modalities`，且其完整性有真实渠道测试保障时，才另立 TDD 评估。
- 不增加或删除现有媒体工具，不实现本地抽帧、转写、转码、切镜或合并。
