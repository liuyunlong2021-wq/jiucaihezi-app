## 2. 交互流程（定案）

1. **触发**
   - 全局快捷键（默认 `Control+Shift+A`），应用进程运行且注册成功时可触发，不要求工作台在前台
   - 设置面板「截图」节里的「截一张」按钮（应用内入口，用户已定放设置里）
2. **准备与框选**：固定目标显示器和来源工作台/项目 → 检查权限 → 抓取目标屏幕快照 → 覆盖窗显示快照与暗色遮罩 → 拖出矩形 → 松手仅预览，工具条贴着选区出现
   （选区下方放不下就放上方；始终在可视区域内）
3. **工具条**：`复制` / `另存为…` / `保存到项目` / `取消`
   - `保存到项目` 在触发时没有项目，或所属工作台关闭/已切换项目时**禁用**；不自动改存到另一项目
   - 点复制成功后结束；另存为/存项目成功后结束，自动复制开启时在保存成功后复制一次
   - 保存失败或另存为对话框取消时保留选区供重试；保存成功但自动复制失败，明确提示“已保存，复制失败”，不删除已保存文件
4. **取消**：`Esc`、或点遮罩空白 → 关闭覆盖窗并释放缓存、清理临时文件，不留截图文件、不动剪贴板；松手不自动复制，取消另存为也不复制
5. 选区裁剪后的最小尺寸为 **2×2 物理像素**（防手抖误点产生空图）

## 3. 实现

### 3.1 两端统一自绘覆盖窗（这是关键选择）

**不用** macOS 的 `screencapture -i` 原生框选。理由：那样 mac 弹系统遮罩、Windows 弹我们的遮罩，
两套交互、两处维护、工具条行为还不一致。**统一自绘**，只在「取像素」这一步按平台分流。

覆盖窗（新窗口 label `shot-<n>`）：

| 配置 | 值 | 说明 |
| --- | --- | --- |
| `decorations` | `false` | 无边框 |
| `transparent` | `false` | 底层显示冻结的屏幕快照，暗色遮罩与选区在页面内绘制，不依赖透明窗或 macOS 私有透明 API |
| `always_on_top` | `true` | 盖住别的应用 |
| `skip_taskbar` | `true` | 不进任务栏 |
| `resizable` | `false` | |
| 尺寸/位置 | **鼠标所在显示器的 bounds** | v1 只覆盖一块屏，见 §6 |
| `focus` | `true` | 要接键盘 `Esc` |

实际采用独立页面 `screenshot/index.html` → `src/screenshot.ts` → `ScreenshotOverlay.vue`，直接创建 Vue 根组件；不经过 `App.vue` 的 label 分流。Rust 使用 `/screenshot/index.html` 路径，避免开发服务器 `/try/` 基址把它解析到工作台目录。
分流必须同时隔离初始化：截图窗不挂载 `MemoryWorkbench`、全局搜索、安装向导，也不执行 `App.vue` 里的 Gateway 绑定、对话发布、项目拖入监听和更新提示。覆盖窗先隐藏创建，快照载入就绪后再显示/聚焦，避免白屏闪烁；取消或关闭时清理截图任务。不得借用 `spawn_workbench_window` 的工作台初始化而引入第二份运行时。

### 3.2 取像素：按平台分流

| 平台 | 手段 | 理由 |
| --- | --- | --- |
| Windows | `xcap`（Rust crate，枚举显示器 + 抓 RGBA） | 无需外部程序；目标显示器与捕获图必须来自同一次选择 |
| macOS | `/usr/sbin/screencapture -x -D <displayIndex> -t png <临时文件>` 抓目标屏 → `png` crate 解码 | `-D` 明确选屏，`-x` 关快门声；原生显示器 ID 与命令行显示器序号不同，不直接混用 |

准备阶段抓屏且仅抓一次，后续框选、预览、复制和保存均使用同一快照，不在覆盖窗显示后再次抓屏。macOS 必须先核实目标显示器 ID 到 `-D` 序号的映射（本机 `man screencapture`：1 为主屏，2 为副屏）；以副屏实测作为 P0 闸门，不能失败后静默回落主屏。命令用参数数组调用，不经 shell 拼接；临时文件使用任务独有路径，在成功解码、失败、取消时清理，并给进程等待与 PNG 解码设置资源边界。

**坐标换算**（最容易出 bug 的一步，必须写单测）：

- 前端给的是**逻辑像素**（CSS px），多屏混合 DPI 时每块屏的 `scale_factor` 可能不同。
- 前端传选区两端点和快照展示区域的 CSS 尺寸；选区坐标以该区域左上角为原点，不是桌面全局坐标。
- Rust 保存目标屏幕位置、缩放与捕获图实际宽高，用**实际捕获宽高 / 展示区域 CSS 宽高**换算物理坐标，并核对显示器缩放；不要只盲乘 `scale_factor`，也不要信任前端传入的物理坐标。
- 支持四个方向拖拽；先排序两端点，再对左/上取 floor、右/下取 ceil，裁到图像边界；拒绝非有限数、无效展示尺寸、零面积及不足 2×2 物理像素的选区。图像尺寸乘法使用 checked arithmetic，并校验 RGBA 长度与 PNG 解码资源上限。
- 桌面全局负坐标只用于选屏/放置覆盖窗，不混进图内裁剪。任务期间目标屏拔出、分辨率或缩放变化则取消并提示重新截图，避免旧快照与新几何错配。
- Rust 返回 `{ width, height, pngBase64 }` 给前端做预览（返回 PNG 而不是原始 RGBA：
  PNG 大小取决于内容，不能保证 4K 图只需几百 KB；base64 还会增加约三分之一体积。原始 RGBA 保留在 Rust，重复拖拽不反复传全屏图）。

### 3.3 动作拆分：捕获与复制在 Rust，保存类在前端

| 动作 | 落在哪 | 理由 |
| --- | --- | --- |
| 准备截图（快捷键 Rust 入口 / `screenshot_begin` 设置入口） | Rust | 固定目标屏、来源工作台与项目，抓完整快照，再建覆盖窗；来源窗口取调用者身份，不接受任意 label 冒充 |
| `screenshot_crop(sessionId, selection)` | Rust | 只裁剪已有快照，返回选区 PNG；不再次捕获桌面 |
| `screenshot_copy(sessionId)` | Rust | 用该任务选区 RGBA 走既有的 `arboard` 通道，不让 RGBA 过 IPC |
| `另存为…` | 前端 | `dialog.save()` + `fs.writeFile(bytes)` 都已授权；PNG 字节前端已有（预览那份） |
| `保存到项目` | 所属工作台前端 | 定向交回触发时工作台，核对任务/窗口/项目仍匹配，走 `files.importBinary` + `nextMaterialPath`，同秒重名不覆盖；成功回执后才结束截图任务 |
| `screenshot_end(sessionId)` | Rust | 成功结束/取消/窗口销毁统一释放缓存和临时文件，重复结束无副作用 |

进程只保留一个活动截图任务：缓存中包含任务 ID、显示器快照/几何、来源窗口/项目和当前选区。活动期间再次触发只聚焦现有覆盖窗，不新抓屏、不覆盖缓存。裁剪、复制、保存回执均核对任务 ID 和调用窗口，拒绝旧任务/其他窗口的请求；显示器捕获与 PNG 编解码放到阻塞任务中，不长时间持锁或阻塞 UI。

设置按钮以调用者为来源；全局快捷键以最近聚焦且仍存活的非截图工作台为来源，项目由该窗口确认，不能用窗口 label 推导项目或读取共享“最近项目”。没有来源项目时仍可复制/另存为。普通截图窗关闭仅尝试恢复来源窗口焦点，不新建窗口；从其他应用触发时不得强制激活后台工作台。

### 3.4 全局快捷键

- 依赖：仅 `tauri-plugin-global-shortcut`（Rust）；进程启动时统一注册一次，设置前端用自有命令读写配置。各工作台及截图窗不重复注册，不需要前端插件包。
- 默认值 `Control+Shift+A`；由 Rust 原子写入应用数据目录 `screenshot-settings.json`（同时保存自动复制与默认目录）
- **注册失败必须冒泡**：被别的软件占用时要能在设置里看到「这个组合已被占用」，并允许改。
  （静默失灵是这类功能的头号投诉来源。）
- 改快捷键：相同值直接返回；**先 register 新的，成功后再 unregister 旧的**，全部成功后才持久化。新键注册失败保持旧键；旧键注销失败则撤销新键并报告错误，回滚失败也必须可见，不假报成功。
- 回调只处理 `Pressed`，忽略 `Released`；录制快捷键期间不触发截图，`Esc` 只退出录制。
- Rust 依赖、插件注册和命令实现限定 Windows/macOS；Web/Mobile 不加载，现有 Linux 能力不受影响。设置值由 Rust 使用既有应用配置存储方式持久化，修改结果同步到已开的工作台，不只更新某个窗口的 localStorage。

### 3.5 设置面板新增「截图」节

现有 tab：账号 / 同步 / Skill / MCP / 手机 / 主题 → 新增 **截图**（仅 Windows/macOS 桌面可见，使用 `screenshotRuntime` 平台条件）。

| 项 | 类型 | 说明 |
| --- | --- | --- |
| 全局快捷键 | 录制控件 | 点一下进入录制 → 按组合键 → 显示规范化结果 + 冲突提示；`Esc` 取消录制 |
| 保存成功后自动复制到剪贴板 | 开关 | 默认**开**；仅另存为/存项目成功后执行，松手预览、取消和保存失败均不复制 |
| 另存为的默认目录 | 目录选择 | 默认记忆上次选择 |
| 截一张 | 按钮 | 应用内入口（已定放这里） |
| macOS 权限说明 | 文案 + 按钮 | 未授权时显示引导（见 §4） |

### 3.6 命令与授权登记

1. 工作台拥有准备截图、权限检查/申请、快捷键设置等命令；截图窗只拥有当前任务所需的快照读取、裁剪、复制、定向请求保存与结束命令。实现时同步登记命令、invoke handler 和对应权限；命令名与 §3.3 生命周期一致。
2. **不把 `shot-*` 加入 `default.json`**。新增独立截图 capability，仅匹配 `shot-*` 且限定 Windows/macOS；只授权必要截图命令、窗口操作及另存为所需 dialog/fs。用户通过保存对话框选择的路径必须按插件实际 scope 机制授权，不能为另存为开放整个磁盘。项目写入由所属工作台既有权限完成，截图窗不继承 Shell、SQL、全量自有命令或工作台文件范围。
3. 新增依赖：`png`（Rust）、`xcap`（仅 Windows，写进 `[target.'cfg(windows)'.dependencies]`）、
   `tauri-plugin-global-shortcut`（仅桌面 Rust）。不新增前端快捷键插件或 macOS 私有透明 API。

## 4. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| **macOS 屏幕录制授权（TCC）** | 未授权时无法捕获其他应用内容 | 用 `CGPreflightScreenCaptureAccess` 检查；用户首次触发/点授权时调用 `CGRequestScreenCaptureAccess`，拒绝后给系统设置引导；返回应用时重查，需要重启时明确提示。不用黑图判权限，不在启动时主动截图；签名安装包上的权限归属须真机确认 |
| **多显示器 + DPI 缩放** | 框选位置与截出内容错位 | 坐标换算只在 Rust 做（§3.2），配单测；验收覆盖 125%/150% 与副屏 |
| **全局快捷键冲突** | 按了没反应，且用户不知道原因 | 注册失败必须可见（§3.4） |
| **覆盖窗置顶/焦点** | 盖不住某些全民级置顶窗口（任务管理器、部分游戏） | 已知限制，写进文档；不承诺"一定盖住一切" |
| **截到自己** | 遮罩/工具条可能进画面 | 快照完成后才显示覆盖窗；所有输出裁自同一快照；覆盖窗显示后不再抓屏 |
| **`always_on_top` + 全屏应用** | 某些全屏独占程序下覆盖窗不可见 | 已知限制 |
| **体积** | `xcap` 会增加安装包 | 可接受；只进 Windows target |
| **缓存/保存失败与任务串线** | 截图保存到错误项目，或失败后残留屏幕图像 | 单任务 + 来源绑定 + 任务 ID 校验；结束统一清理，失败保留选区仅供当前任务重试，不写日志/持久存储中的屏幕图像 |

## 6. 本次不做（附理由）

- **全屏 / 窗口捕获**：v1 只框选（用户定）；内部整屏快照只是实现步骤，不提供全屏输出入口，不预留未要求的分支。
- **标注**：工作量比整条链路还大（要一套矢量编辑 + 重绘），单独一期。
- **多屏跨屏框选**：v1 只覆盖鼠标所在那一块屏。跨屏要处理混合 DPI 的坐标拼接，先不做，写进已知限制。
- **滚动截图 / 录屏 / OCR**：不是同一类能力，别混进来。
- **把截图直接塞进对话**：v1 不做；之后可作 attachment 走既有链路。

## 8. 验收清单（可执行，实施后逐条打勾）

1. 按默认快捷键 → 屏幕变暗、能拖框、松手出工具条；`Esc` 取消后不留文件、不动剪贴板
2. 点「复制」→ 在别的软件里 `Ctrl/Cmd+V` 粘出图片；尺寸等于 §3.2 裁剪后的**物理像素**宽高，内容与冻结快照一致
3. 「另存为…」→ 得到能正常打开的 PNG
4. 「保存到项目」→ 文件出现在 `.raw/jc-media/图片/截图-*.png`，文件树里能看到
5. 副屏框选 → 位置正确（不偏移）
6. Windows 缩放 125% / 150% → 位置与尺寸正确
7. 快捷键被占用 → 设置里能改，且能提示冲突

9. 覆盖窗不进任务栏、就绪后才显示；应用内触发结束后恢复来源窗口，从其他应用触发不强制激活后台工作台
10. 打开两个工作台，按住/松开快捷键或重复触发 → 仅一个截图窗、一个活动任务；旧任务的裁剪/复制/保存回执被拒绝
11. 截图窗不启动 Gateway、Harness 或工作台初始化；取消、关窗、捕获失败后缓存/临时文件释放，剪贴板不变
12. 四方向拖拽、边缘越界、负坐标副屏、Retina/混合 DPI 均正确；非法/非有限坐标、零尺寸被拒绝；拔屏或改缩放时取消并提示重试
13. 工作台 A 项目触发后切到 B 或关闭 A → 禁止写入其他项目；同秒连续存图用既有重名规则生成不同路径，树刷新
14. 松手预览/取消另存为/写入失败不复制；保存成功后自动复制一次，复制失败明确提示已保存；另存为对话框不被置顶覆盖窗遮挡，取消后可继续操作
15. 截图窗可执行必要操作，但不能调用工作台 Shell/SQL/无关文件命令；重新设置快捷键失败后旧键仍可用，多窗口设置同步；Windows、macOS Intel/Apple Silicon 分别验收，未执行的平台不得标通过
