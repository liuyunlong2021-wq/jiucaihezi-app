# 韭菜盒子截图功能 SDD

> 状态：**设计定案，未实施** —— 本文只有设计与查证，没有代码改动、没有构建、没有真机验证。
> 日期：2026-10-03
> 范围：桌面端（Windows + macOS）系统截图：框选 → 复制 / 另存为 / 保存到当前项目
> 已定决策（用户 2026-10-03）：
> 1. 捕获范围：**框选**（v1 不做全屏、不做窗口捕获）
> 2. 快捷键：**给默认值**，可在设置里改
> 3. v1 **不做标注**（箭头 / 矩形 / 文字 / 马赛克留 v2）
> 4. 应用内入口：**放在设置里**（不新占工作台顶栏 / 文件树）

## 1. 先复用：这一节是查证结果，不是印象

| 需要的部件 | 现状（查过） | 结论 |
| --- | --- | --- |
| 图片写剪贴板 | `src-tauri/src/commands/clipboard.rs` 已在用 `arboard`，`read_clipboard_image` 已实现并登记 | ✅ **只加一个函数，零新依赖** |
| 另存为对话框 | `tauri-plugin-dialog` 已装，`dialog:allow-save` 已授权 | ✅ 复用 |

| 保存到项目 | `.raw/jc-media/图片` 是既有约定（3D 编辑器 `saveSceneScreenshot` 就写这里） | ✅ 复用既有写入链路 |
| 多窗口 | `spawn_workbench_window` / `workbench_window_config` 已有；窗口 label 约定 `ws-*` / `win-*` | ✅ 覆盖窗照它加 |
| 全局快捷键 | **没有**（`tauri-plugin-global-shortcut` 不在 `Cargo.toml`，也没有对应的前端包） | ❌ 需新增（官方插件） |

⚠️ 仓库里已有的「截图」是 **3D 场景取景框截图**（`Scene3DEditor.vue` → `emit('screenshot')` → `saveSceneScreenshot`），
和系统截图无关，**不要复用也不要混称**。

## 2. 交互流程（定案）

1. **触发**
   - 全局快捷键（默认 `CommandOrControl+Shift+A`），任何时候按都能起
   - 设置面板「截图」节里的「截一张」按钮（应用内入口，用户已定放设置里）
2. **框选**：屏幕变暗（我们的覆盖窗）→ 拖出矩形 → 松手，工具条贴着选区出现
   （选区下方放不下就放上方；始终在可视区域内）
3. **工具条**：`复制` / `另存为…` / `保存到项目` / `取消`
   - `保存到项目` 在没有打开工作区时**禁用**（不是隐藏，避免用户找不到）
4. **取消**：`Esc`、或点遮罩空白 → 关掉覆盖窗，不留任何文件、不动剪贴板
5. 选区最小尺寸 2×2 像素（防手抖误点产生空图）

## 3. 实现

### 3.1 两端统一自绘覆盖窗（这是关键选择）

**不用** macOS 的 `screencapture -i` 原生框选。理由：那样 mac 弹系统遮罩、Windows 弹我们的遮罩，
两套交互、两处维护、工具条行为还不一致。**统一自绘**，只在「取像素」这一步按平台分流。

覆盖窗（新窗口 label `shot-<n>`）：

| 配置 | 值 | 说明 |
| --- | --- | --- |
| `decorations` | `false` | 无边框 |
| `transparent` | `true` | 需要它才能做"半透明遮罩" |
| `always_on_top` | `true` | 盖住别的应用 |
| `skip_taskbar` | `true` | 不进任务栏 |
| `resizable` | `false` | |
| 尺寸/位置 | **鼠标所在显示器的 bounds** | v1 只覆盖一块屏，见 §6 |
| `focus` | `true` | 要接键盘 `Esc` |

前端分流：`getCurrentWindow().label.startsWith('shot-')` → 渲染 `ScreenshotOverlay.vue`，否则渲染工作台。
（label 同步可读：`window.__TAURI_INTERNALS__.metadata.currentWindow.label`，与
[[开发/韭菜盒子多窗口多开SDD-2026-09-29]] §6 第 4 步同一手法。）

### 3.2 取像素：按平台分流

| 平台 | 手段 | 理由 |
| --- | --- | --- |
| Windows | `xcap`（纯 Rust，枚举显示器 + 抓 RGBA） | 无需外部程序；多显示器/DPI 信息齐全 |
| macOS | `/usr/sbin/screencapture -x -t png <临时文件>` 抓整屏 → `png` crate 解码 | 系统级、稳；`-x` 关快门声、非交互 |

**坐标换算**（最容易出 bug 的一步，必须写单测）：

- 前端给的是**逻辑像素**（CSS px），多屏混合 DPI 时每块屏的 `scale_factor` 可能不同。
- Rust 侧用 `monitor.scale_factor()` 把选区换算成**物理像素**再做裁剪；**不要**信任前端算好的物理坐标。
- Rust 返回 `{ width, height, pngBase64 }` 给前端做预览（返回 PNG 而不是原始 RGBA：
  4K 选区的 RGBA 走 IPC 是几十 MB，PNG 是几百 KB）。

### 3.3 动作拆分：捕获与复制在 Rust，保存类在前端

| 动作 | 落在哪 | 理由 |
| --- | --- | --- |
| `screenshot_capture_region(monitorId, x, y, w, h)` | Rust | 像素本来就在 Rust 手里；**顺手把 RGBA 缓存**在 Rust（`Mutex<Option<CapturedImage>>`，只留最近一次） |
| `screenshot_copy()` | Rust | 用缓存里的 RGBA 走既有的 `arboard` 通道；16 MB 的 buffer **不用**过 IPC |
| `另存为…` | 前端 | `dialog.save()` + `fs.writeFile(bytes)` 都已授权；PNG 字节前端已有（预览那份） |
| `保存到项目` | 前端 | **必须走既有的项目写入链路**（`.raw/jc-media/图片/截图-YYYYMMDD-HHMMSS.png`），不要另开一条 Rust 写盘路径绕过它 |

这样 Rust 侧只有一个缓存和一个 arboard 调用，前端不碰 RGBA。

### 3.4 全局快捷键

- 依赖：`tauri-plugin-global-shortcut`（Rust）+ `@tauri-apps/plugin-global-shortcut`（前端）
- 默认值 `CommandOrControl+Shift+A`；持久化键 `jc_screenshot_shortcut`
- **注册失败必须冒泡**：被别的软件占用时要能在设置里看到「这个组合已被占用」，并允许改。
  （静默失灵是这类功能的头号投诉来源。）
- 改快捷键：**先 unregister 旧的再 register 新的**，失败要回滚到旧值，不能两个都留着。
- 只在桌面端注册（`isTauriRuntime() && !isTauriMobileRuntime()`）。

### 3.5 设置面板新增「截图」节

现有 tab：账号 / 同步 / Skill / MCP / 手机 / 主题 → 新增 **截图**（仅桌面可见，和 Skill/MCP 同样用 `v-if="desktopRuntime"`）。

| 项 | 类型 | 说明 |
| --- | --- | --- |
| 全局快捷键 | 录制控件 | 点一下进入录制 → 按组合键 → 显示规范化结果 + 冲突提示；`Esc` 取消录制 |
| 截图后自动复制到剪贴板 | 开关 | 默认**开**（多数人截完就是要粘贴） |
| 另存为的默认目录 | 目录选择 | 默认记忆上次选择 |
| 截一张 | 按钮 | 应用内入口（已定放这里） |
| macOS 权限说明 | 文案 + 按钮 | 未授权时显示引导（见 §4） |

### 3.6 命令与授权登记

1. `src-tauri/permissions/app-commands.json` 的 `allow` 列表加新命令：
   `screenshot_capture_region`、`screenshot_copy`
   （另存为/保存到项目走 fs + dialog，不新增自有命令。）
2. `src-tauri/capabilities/default.json` 的 `"windows": ["main", "ws-*", "win-*"]` **加 `"shot-*"`** ——
   不加就是「覆盖窗没有任何权限」，起来直接不能用（和 [[开发/韭菜盒子多窗口多开SDD-2026-09-29]] §6 第 3 步同一个坑）。
3. 新增依赖：`png`（Rust）、`xcap`（仅 Windows，写进 `[target.'cfg(windows)'.dependencies]`）、
   `tauri-plugin-global-shortcut`（Rust + 前端各一份）。

## 4. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| **macOS 屏幕录制授权（TCC）** | 未授权时截出来是空图/黑图，用户以为功能坏了 | 启动时探测（截 1×1 看是否全黑/失败）→ 设置里给「去系统设置授权」引导；文案明确写清 |
| **多显示器 + DPI 缩放** | 框选位置与截出内容错位 | 坐标换算只在 Rust 做（§3.2），配单测；验收覆盖 125%/150% 与副屏 |
| **全局快捷键冲突** | 按了没反应，且用户不知道原因 | 注册失败必须可见（§3.4） |
| **覆盖窗置顶/焦点** | 盖不住某些全民级置顶窗口（任务管理器、部分游戏） | 已知限制，写进文档；不承诺"一定盖住一切" |
| **截到自己** | 覆盖窗本身可能进画面 | 覆盖窗是半透明遮罩，取像素发生在**遮罩渲染前**（先抓屏再显示遮罩），顺序不能反 |
| **`always_on_top` + 全屏应用** | 某些全屏独占程序下覆盖窗不可见 | 已知限制 |
| **体积** | `xcap` 会增加安装包 | 可接受；只进 Windows target |

## 6. 本次不做（附理由）

- **全屏 / 窗口捕获**：v1 只框选（用户定）。之后要做就是多一个快捷键分支，成本低，先留口子。
- **标注**：工作量比整条链路还大（要一套矢量编辑 + 重绘），单独一期。
- **多屏跨屏框选**：v1 只覆盖鼠标所在那一块屏。跨屏要处理混合 DPI 的坐标拼接，先不做，写进已知限制。
- **滚动截图 / 录屏 / OCR**：不是同一类能力，别混进来。
- **把截图直接塞进对话**：v1 不做；之后可作 attachment 走既有链路。

## 7. 工作量

| 块 | 规模 |
| --- | --- |
| Rust：覆盖窗创建 + 捕获 + 裁剪 + PNG 编码 + 缓存 + 复制 | 约 200 行 |
| Rust：全局快捷键注册/重注册 + 冲突回报 | 约 60 行 |
| 前端：`ScreenshotOverlay.vue`（遮罩 + 拖拽 + 工具条） | 约 250 行 |
| 前端：设置节（录制控件 + 开关 + 目录） | 约 120 行 |
| 配置：命令登记 + capability + 依赖 | 约 15 行 |
| 测试：坐标换算单测 + 契约测试 | 约 80 行 |

合计约 700 行，跨 Rust + 前端 + 配置。**这是本仓库少见的"两侧都要动"的功能**，不要按纯前端估算。

## 8. 验收清单（可执行，实施后逐条打勾）

1. 按默认快捷键 → 屏幕变暗、能拖框、松手出工具条；`Esc` 取消后不留文件、不动剪贴板
2. 点「复制」→ 在别的软件里 `Ctrl/Cmd+V` 粘出图片，**尺寸与选区 1:1 像素**
3. 「另存为…」→ 得到能正常打开的 PNG
4. 「保存到项目」→ 文件出现在 `.raw/jc-media/图片/截图-*.png`，文件树里能看到
5. 副屏框选 → 位置正确（不偏移）
6. Windows 缩放 125% / 150% → 位置与尺寸正确
7. 快捷键被占用 → 设置里能改，且能提示冲突
8. macOS 未授权 → 给出明确引导，不是"按了没反应"
9. 覆盖窗不进任务栏、不抢焦点乱跳；关掉覆盖窗后原窗口焦点回来
