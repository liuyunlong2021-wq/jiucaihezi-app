# 通用记忆工作台文件树排序与定位 TDD

> 日期：2026-09-19
> 状态：已实施；自动化验证通过，真实 Desktop/Web 人工验收待执行
> 范围：`src/components/filetree/ProjectFileTree.vue`、`src/utils/fileSort.ts`、`src/stores/mediaTaskStore.ts`
> 不涉及：媒体资产目录规范、Raw 持久化、云端/网络列表排序

## 1. 用户目标

1. 生成的图片/视频在文件树里找不到，希望点一下就能跳到它面前。
2. 文件树要能排序（照 macOS 访达的「排序方式」），而不是只能按名字排。

## 2. 根因审计

### 2.1 主因：定位不滚动，而且列表是虚拟滚动的

`locateProjectResource()` 会逐级 `ensureDirectoryLoaded()` + `expanded = true` + 设置 `selectedPaths/focusedPath`，但**整份文件没有一处 `scrollIntoView` / `scrollTop`**（grep 全文 0 处）。

更关键的是列表用 `@tanstack/vue-virtual` 虚拟滚动（`virtualVisibleNodes` + 绝对定位 `translateY`），**只渲染可见行**。所以目标行连 DOM 都不存在，"定位"唯一的效果是把选中行设到屏幕外。用户视角就是：点了「在文件树中查看」→ 没反应。

### 2.2 生成完成后不会自动定位

`emitEvent('project-filetree:locate')` 的发出方只有两处，且都是用户手点：`MediaTaskBubble.revealInTree()`（「在文件树中查看」按钮）与 `MemoryWorkbench` 的文档定位。生成物落盘（`mediaTaskStore` 的 `downloadProjectMedia` / `writeProjectMedia` / Web `importMedia`）之后没有任何定位动作。

### 2.3 文件按名字升序，最新的永远在最底下

`sortTreeChildren()`：目录优先 → 同级目录按 `updatedAt` 倒序 → **文件按 `path.localeCompare` 升序**。生成物命名是 `2026-08-15_163057_xxx.png`（时间戳前缀），升序 = 最旧的在前，最新的沉在几十条之后。

### 2.4 定位失败静默返回

`if (!child) return`，没有任何提示，用户无法区分「没这条」和「没反应」。

### 2.5 仓库里已有一份没人用的排序实现

`src/utils/fileSort.ts` 有 `FileSortMode`（`time-desc | time-asc | name-asc | name-desc`）、`FILE_SORT_OPTIONS`（带 icon / shortLabel / title）、`isFileSortMode`、`compareFileEntries`，**全仓 0 个调用者**（单产品化时被割断的孤儿）。排序不需要从零写。

## 3. 目标合同

### 3.1 排序：显示层是唯一真源

```text
flattenVisible() → sortedChildren(children, fileSortMode)
```

- `sortedChildren()`：**目录永远优先**（混排会把目录冲散，且 `nodeMap` 找不到父节点会静默丢节点），同级再按当前模式。
- 排序放在**展开视图**这一步，而不是加载时：换排序不需要重读目录，也不会漏掉 `buildTree` / `ensureDirectoryLoaded` / `refreshDirectory` 里某一条加载路径。加载时的 `sortTreeChildren()` 保留，只作为基础顺序（原有 3 个调用点与其测试钉子都不动）。
- 模式持久化在 `localStorage` 的 `jcFileTreeSortMode`；非法值（版本变更、手改）回默认，不抛错。
- 默认 `time-desc`（修改日期·最新在前）：目录行为与改动前完全一致（目录本来就是 mtime 倒序），只有文件从「名字升序」变成「最新在前」。

菜单项**只列数据支持得起的维度**（树节点有 `name / size / updatedAt / mimeType`）：

| 访达的项 | 结论 |
| --- | --- |
| 名称 | 做（A→Z / Z→A，中文用 zh-CN 数字序） |
| 修改日期 | 做（最新在前 / 最早在前），设为默认 |
| 大小 | 做（目录无 size，只在文件之间生效） |
| 种类 | 做（先看 mimeType，缺失时退回扩展名：图片→视频→音频→文档→其他） |
| 无 | **不做**：桌面 `dev_list_directory` 按字节序返回，真「不排序」会让中文名全部沉底 |
| 应用程序 / 上次打开日期 / 添加日期 / 标签 | **不做**：树上没有这些数据，项目文件也不归访达管 |

菜单复用右键菜单的条目样式（`.pft-ctx-item`）与浮层词汇，不新造控件。

### 3.2 定位：要跳到眼前，失败要说话

`locateProjectResource(path, quiet = false)`：

1. 逐级加载并展开祖先（原有行为）。
2. 目标被筛选过滤掉时**先摘掉筛选**，否则「定位」看起来又像没反应。
3. 设置选中/焦点。
4. **`fileTreeVirtualizer.scrollToIndex(index, { align: 'center' })`** —— 虚拟列表只能通过虚拟器滚动，`querySelector + scrollIntoView` 对未渲染的行无效。
5. 找不到时：`quiet=false` 写 `statusMsg`（**不能写 `errorMsg`**：那条 `v-show="!errorMsg"` 会把整棵树藏起来）；`quiet=true` 静默。

事件 `project-filetree:locate` 支持两个可选字段：

- `owner`：与当前 `projectKey` 不同则整条忽略（不碰树、不抱怨）。
- `quiet`：自动动作置 true，避免留下赶不走的提示。

### 3.3 生成物落盘后自动定位

`mediaTaskStore` 的三条落盘路径（Web `importMedia`、桌面 `downloadProjectMedia`、桌面 `writeProjectMedia`）统一调用 `revealMediaResultInFileTree(task)`，以 `quiet: true` + `owner: task.directory || task.projectId` 发出定位请求。

选择在**落盘赋值点**触发而不是 `emitSettled()`：后者可能在落盘 promise 还在飞的时候执行，`projectPath` 可能还是空的。

## 9. 完成标准

- 生成物落盘后自动跳到文件树里它所在的位置。
- 手动定位对任意深度的路径都能滚到眼前。
- 排序可切换、被记住，且目录永远优先。
- 不提供真「不排序」，中文名不会因字节序沉底。
- 定位失败有可见且不破坏树的提示。
- 排序不影响 Raw、模型与 Skill 读文件。

## 10. 实施结果

- `fileSort.ts` 从孤儿变成唯一排序真源：7 个模式 + 种类判定 + 菜单文案，树只负责「目录优先 + 调它」。
- 树的显示顺序改由 `sortedChildren()` 在展开层决定，加载时的 `sortTreeChildren()` 与其 3 个调用点保持不变（既有测试钉子未动）。
- 定位补齐滚动（虚拟器 `scrollToIndex`）、筛选摘除、quiet 语义、跨项目忽略。
- 生成物落盘三处统一自动定位。
- 新增工具栏排序入口，菜单项直接来自 `FILE_SORT_OPTIONS`。

## 11. 已知边界与取舍

- **批量生成时自动定位以最后一个为准**：多个结果连续落盘会连续定位，用户看到的是最新的那个。要改成「只定位第一次」或「聚合提示」再加去抖。
- **大小排序对目录无效**：目录没有 size，同为大小时回退名称序。
- **`sortTreeChildren` 与 `sortedChildren` 同时存在**：前者是加载时的基础序（供非展示路径使用），后者是屏幕顺序的真源。两者职责已写进注释，改之前先读注释。
- **自动定位会展开目录**：即使用户当前在别的目录操作，树也会跳过去。这是本轮要的效果；若以后嫌打扰，可加「仅当文件树可见且未在拖拽/改名时」的条件。
