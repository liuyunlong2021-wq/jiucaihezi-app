## 1. 决断

先把现有韭菜盒子换成一个极简的通用记忆对话工作台：

```text
项目文件树 + 顶部对话选择器 + 中央内容区 + 隐藏设置
```

用户通过顶部对话选择器切换对话，通过文件树浏览资料：

```text
顶部对话选择器 -> 中央区显示完整聊天记录和输入框
Markdown/文本  -> 临时预览层显示文档阅读器
图片/视频/音频 -> 临时预览层显示预览或播放器
其他文件       -> 临时预览层显示安全打开/下载动作
```

文件树只负责资料导航和文件动作；顶部对话选择器只负责切换 Raw 对话。两者共用同一项目文件真源，不建立第二份对话数据库或索引。不增加项目选择器、应用级模式导航、编辑区、创作面板或第三栏设置区。输入框上方只保留控制下一次发送的 `快速 | 记忆` 两段式开关。

产品能力仍然完整：登录、模型、Skill 仓库、MCP、附件、Wiki 读写和对话内图片/视频/音频生成都保留，只把设置收进按钮，把媒体生成收进对话。

## 2. 为什么这是正确边界

### 2.1 对话导航与文件导航必须分离

每个对话本来就是 `.raw/对话记录/` 下的一个真实文件，但用户不应该为了继续聊天进入系统 Raw 目录寻找文件。顶部选择器只是 `.raw/对话记录/` 的 UI 投影，不是第二份存储。它读取对话标题、稳定 ID 和更新时间，完成创建、选择、重命名、删除和恢复；文件树不再承担对话切换。

### 2.2 所有文件都能临时预览，但不能都按聊天显示

“中央区”保持当前对话不被销毁；点击普通 Markdown、图片或其他文件时，打开统一的临时预览层。只有对话 Raw 才显示聊天气泡和输入框。

这样同时满足：

- 用户点任何可支持文件都能看到内容；
- 普通文档不会被误认为聊天记录；
- 不需要把系统 Raw 暴露成资料导航；
- 不需要重新引入独立编辑区或创作面板。

关闭预览层必须恢复原对话、滚动位置、输入草稿和附件状态。

### 2.3 资源判断只能有一个入口

现有 `openProjectResource()` 已经统一处理文档、媒体、画布和二进制。实现时只在这个共享路由增加 `conversation` 结果，不允许文件树、聊天区和移动端分别复制路径判断。

```text
ProjectFileTree
  -> openProjectResource(resource)
  -> conversation | document | media | binary
  -> CentralContentHost 切换对应视图
```

## 3. 产品边界

### 3.1 用户可以做什么

- 创建、导入或打开一个项目，并在下次启动恢复最近项目。
- 在文件树中浏览项目的 Raw、Wiki、媒体和其他文件。
- 新建任意名称的对话，点击任意对话继续聊天。
- 点击 Markdown、文本、图片、视频和音频直接查看。
- 选择模型和一个可选专业 Skill。
- 上传当前模型支持的附件。
- 每轮可选择直接回答，或由模型根据当前对话自主查询 Wiki 后回答。
- 明确同意后，把确认内容写入指定或确认的 Wiki 路径。
- 用自然语言生成图片、视频或音频，并在对话内确认费用、查看进度和结果。
- 从设置按钮登录、配置 Provider、管理 Skill、连接 MCP 和查看通用设置。

### 3.2 明确不做

- 不显示文、武、创、道四种模式。
- 不使用 OpenCode Agent、`ses_*`、sidecar 或 OpenCode 会话数据库。
- 不建立独立项目选择器、第二份对话存储或第二份对话索引；顶部对话选择器是允许的唯一对话导航 UI。
- 不把所有文件渲染成聊天消息。
- 不建立向量库、隐藏摘要、第二套记忆或跨对话隐式拼接。
- 不自动把讨论、猜测或草稿写入 Wiki。
- 不加载 `CreationPanel`、画布、编辑区、画廊或媒体工作台。
- 不新增媒体 API、任务 Store、轮询器或音频专用流程。
- 不做媒体、Skill、MCP 凭据、Provider 或界面设置的跨设备同步；第四阶段只同步项目文字。
- 当前阶段不创建新域名、Bundle ID、Deep Link、签名身份或更新通道。

## 4. 唯一真源

| 内容 | 唯一真源 |
| --- | --- |
| 完整对话 | 当前项目 `.raw/对话记录/*.md` |
| 已确认知识 | 当前项目现有 `wiki/` 或 `docs/wiki/` |
| 当前打开资源 | 页面存活期间的 UI 状态；重启后从最近项目和文件树恢复 |
| 项目文件 | `ProjectFileService` 背后的当前平台存储 |
| 跨设备文字副本 | Cloudflare `SYNC_DB`；只接受已登录账号名下项目，不取代本地项目文件 |
| 模型与 Provider | 现有公共模型/Provider 配置 |
| 产品内置 Skill | `public/skills/` 与现有只读 loader；不进入仓库或选择器 |
| 用户已安装 Skill | Web `agentStore` 的 `jc_web_skills_v1`；与内置 Skill 合并为模型可发现目录 |
| MCP | 现有 `mcpStore`、`mcpClient` 与安全凭据存储 |
| 生成媒体 | 当前项目 `jc-media/` |
| 在途媒体任务 | 现有 `mediaTaskStore` |

App 不再把同一份对话正文保存进 conversations/messages 数据库。清除页面状态后，只要项目目录还在，就必须能从 Raw 恢复全部对话，从 Wiki 恢复确认知识，从 `jc-media/` 恢复已生成媒体。第四阶段的 D1 是跨设备传输和恢复副本，不是模型直接读取的新记忆库；同步下载后仍由 `ProjectFileService` 读写本地文件。

## 5. 项目文件合同

### 5.1 最小骨架

```text
项目根/
├── .raw/
│   └── 对话记录/
│       ├── chat_01J0A7F3.md
│       └── chat_01J0B2K9.md
├── jc-media/                 # 首次生成媒体后按需创建
│   ├── images/
│   ├── videos/
│   └── audios/
└── wiki/                     # 已有 docs/wiki/ 时接管原位置
    ├── CLAUDE.md
    ├── index.md
    ├── hot.md
    ├── log.md
    └── 来源索引.md
```

新建通用 Wiki 不预设“资料、主题、参考”等业务目录。用户需要什么，模型在用户确认后创建什么。已有 Wiki 只接管，不迁移、不删除、不覆盖。

### 5.2 对话身份

对话文件使用稳定 ID 文件名，首个 H1 是用户看到的标题：

```markdown
# 聊聊历史

<!-- jc:conversation id="chat_01J0B2K9" created-at="2026-07-24T15:00:00+08:00" -->

<!-- jc:turn id="turn_01J0B31A" role="user" created-at="2026-07-24T15:01:00+08:00" -->
## 用户

秦朝为什么灭亡得这么快？
<!-- /jc:turn -->
```

一个文件只有同时满足以下两项才是对话：

1. 路径位于 `.raw/对话记录/`；
2. 文件内容含可解析的 `jc:conversation` 元数据标记。

普通 `.md` 文件不能只因扩展名相同就成为对话。路径正确但标记缺失、标记存在但路径错误，都按普通文档打开；不得猜测或自动改写。

### 5.3 Raw 边界

Raw 只追加用户可见内容：

- 用户输入和模型完整最终回复；
- 用户可见附件的项目相对路径、名称和类型；
- 用户发送该轮使用的 `quick | memory` 模式；
- 已确认媒体计划及最终成功、失败或取消结果；
- 用户确认了哪项 Wiki 写入。

Raw 不保存系统提示词、隐藏推理、模型内部加载的产品 Skill 正文、Wiki 查询结果、工具参数、工具回执、流式片段、轮询快照、鉴权地址或附件二进制副本。用户明确要求创建并用于安装确认卡的 `jc-skill-install` 块属于用户可见回复，随该轮 Raw 保存。

### 5.4 项目级附件引用

用户上传或粘贴附件时，附件不再只存在于当前页面内存：

1. 第一次出现附件时按需创建 `jc-media/uploads/`，并将原文件只写入一次；新建空记忆空间时不预建空目录。
2. Raw 附件元数据保存 `id / name / mime / size / kind / projectPath`；`projectPath` 必须是 `jc-media/` 下不含 `.`、`..` 或空路径段的项目相对路径。
3. Raw 不保存 Base64、Blob URL 或远程鉴权 URL；项目文件是附件二进制唯一真源。
4. 每轮请求从当前对话 Raw 重建历史图片和视频的受控 `referenceId` 清单。当前轮附件默认显式选中；历史附件只作为候选，由模型按用户指代写入 `referenceIds`。
5. “这张图 / 之前那张图”只有一个同类候选时可直接复用；多个候选且上下文不能唯一确定时必须询问，不得静默选择旧图。
6. 媒体确认卡持有项目定位器。切换模型、比例、分辨率、时长或再次生成，只修改任务参数，不清空素材引用；刷新或重开项目后按 `projectPath` 重新读取。

这是一套 Wiki 项目文件系统内的稳定引用关系，不是第二套附件数据库：Raw 记录附件在哪轮出现，`jc-media/uploads/` 保存附件本体，媒体计划保存受控引用。

## 6. 文件树与中央内容区

### 6.1 导航职责

当前项目打开后，对话切换由顶部对话选择器触发，资料切换由文件树触发。两者都不创建第二份数据源。

- 桌面和大屏：左侧文件树，顶部对话选择器，右侧中央内容区。
- 手机：文件树放入抽屉，中央内容区占满屏幕。
- 设置：顶部账号/齿轮按钮打开抽屉或覆盖层；关闭后回到原资源。

文件树只负责资料导航和文件动作，不显示或切换对话 Raw。记忆空间初始化后，顶部选择器旁始终显示“新建对话”；没有项目时，中央区显示选择项目文件夹的空状态。

### 6.2 统一打开路由

| 路由结果 | 识别规则 | 中央区行为 |
| --- | --- | --- |
| `conversation` | `.raw/对话记录/` + 有效 `jc:conversation` | 完整聊天记录、模型/Skill、附件、输入框 |
| `document` | 可安全完整读取的 Markdown/文本 | 只读文档视图；Markdown 渲染，纯文本保留格式 |
| `media` | 图片、视频或音频 MIME/扩展名 | 图片预览、视频播放器或音频播放器 |
| `binary` | 其他格式、超大或含 NUL 的内容 | 文件信息与安全打开、另存为或下载 |

`.jccanvas` 在本产品没有画布承载面，按不支持的结构化文件处理，只提供安全操作，不加载创作面板。

### 6.3 对话在文件树中的显示

- 文件真实路径和稳定 ID 不变，但 `.raw/对话记录/` 默认作为系统目录从资料文件树隐藏。
- 顶部对话选择器读取 `.raw/对话记录/` 下有效对话的首个 H1、稳定 ID 和更新时间，显示用户标题而不是 `chat_*.md`。
- 选择器内部 key 仍是 `owner + path`，标题只是显示别名；不建立标题数据库。
- 设置中的“显示系统文件”可让高级用户查看 Raw 原文，但查看 Raw 不改变当前对话，普通文档预览规则仍适用。

### 6.4 新建、重命名、删除与恢复

新建对话：

```text
点击顶部对话选择器旁“新建对话”
  -> ProjectFileService 创建稳定 ID Raw
  -> 写入 H1 和 jc:conversation 标记
  -> 文件树选中该文件
  -> 中央区进入空对话
```

首条消息可直接取首段文本作为标题，不调用额外模型。用户重命名对话时只修改首个 H1，不修改稳定文件名或 conversation ID。

删除仍走现有文件删除确认和 `ProjectFileService` 事件；当前对话被删除后回到空状态或打开剩余最近对话，不保留隐藏副本。刷新、重启或清除 UI 状态后，App 重新扫描 Raw 文件恢复对话；已经删除的 Raw 只能从用户自己的项目备份或导出恢复。

普通文档的重命名仍是文件路径重命名，不能套用“只改 H1”的对话规则。

### 6.5 对话选择器与统一预览层

#### 对话选择器

顶部固定显示当前对话标题、下拉箭头和“新建对话”：

```text
[ 当前对话：你好 ▾ ]  [＋ 新建对话]                       [模型] [设置]
```

展开后提供当前项目的对话搜索和最近对话列表。选择对话时读取对应 Raw，恢复完整聊天、最后一次 `快速 | 记忆` 状态、输入草稿和附件；不调用额外模型，不复制正文。

选择器支持新建、切换、重命名和删除。删除当前对话后打开剩余最近对话；没有剩余对话时显示新建入口。对话标题修改只写 Raw 首个 H1，稳定文件名和 ID 不变。

#### 统一预览层

从文件树打开任何非对话资源，都在当前对话之上打开临时预览层，不销毁或替换对话组件：

```text
当前对话
  -> 点击文件
  -> 预览层覆盖当前对话
  -> 返回 / Esc / 关闭
  -> 原对话、滚动位置、草稿和附件完整恢复
```

预览层顶部统一为：

```text
← 返回对话    文件名                              下载 / 编辑 / 关闭
```

图片、视频、音频、Markdown、纯文本、PDF 和其他安全文件使用各自阅读器，但共享返回、下载和关闭合同。点击预览层内另一文件只替换当前资源，不改变返回目标。

普通文件默认只读；只有用户点击“编辑”才进入现有编辑器。`.raw/对话记录/` 是唯一例外：通过顶部选择器切换对话，不从普通预览层进入聊天。

运行时最小状态：

```ts
activeConversationId: string
previewResource?: ProjectResource
previewReturn: { conversationId: string; scrollTop: number; draft: string; attachments: Attachment[] }
```

`previewReturn` 只保存页面存活期间的 UI 状态，不写入 Wiki、Raw 或第二套存储。

## 7. 对话运行合同

### 7.1 正确时序

```text
用户点击发送
  -> App 把用户消息及 quick | memory 模式追加到当前 Raw
  -> App 读取当前对话 Raw
  -> 快速：当前对话 + 本轮消息/附件，无 Skill/Wiki/MCP 工具
  -> 记忆：当前对话 + 本轮消息/附件 + Wiki/Skill/MCP 工具
  -> 模型按 Skill description 自主判断是否调用 skill(name) 加载 SKILL.md
  -> 模型按任务需要决定是否查询 Wiki 或调用其他工具
  -> 模型生成最终回答
  -> App 把完整最终回答追加到当前 Raw
```

App 不在模型之前猜关键词，不提前查询 Wiki，不把固定查询结果拼进请求。最新用户消息只出现一次。

`快速` 和 `记忆` 共用同一份 Raw；开关只影响下一次发送。新对话默认 `记忆`，重开对话恢复最后一个带模式的用户 turn。用户要求修改当前回答时，当前 Raw 全文和最新意见仍进入同一个模型请求。

### 7.2 Skill 调用条件

记忆模式遵循官方 Skill 渐进披露：首轮只提供可用 Skill 的名称和 description；模型判断任务匹配后调用统一的 `skill(name)` 加载对应 `SKILL.md`，再按 Skill 指引使用项目工具。任务不匹配任何 Skill 时直接回答，不强制加载 Skill，不强制查询 Wiki，也不设置回复出口门禁。App 不做关键词路由，不把任何 Skill 正文预塞进普通请求。

输入框的 `@` 是统一的本轮引用入口，动态列出当前项目可用文件和用户已安装 Skill。选择项目文档后读取真实内容作为本轮 `files` 引用；选择项目媒体后复用现有附件物化合同；选择 Skill 后自动进入记忆模式，并在首轮模型请求之前用标准 assistant tool call + tool result 协议精确执行 `skill(name)`。这是用户明确选择，不是关键词路由，也不把产品内置 Skill 暴露到选择器。切换到快速模式必须清除已选 Skill。

快速模式保持纯直连，不提供 Skill、项目或 MCP 工具。不支持工具调用的模型可以用于快速模式，但不能进入记忆模式伪装成具有 Skill 能力。

### 7.3 上下文

- Raw 永远保存当前对话完整原文。
- 每轮先读取当前 Raw，不创建隐藏摘要或第二套记忆。
- 请求沿用现有模型上下文装配；超出模型容量时只在请求边界保留最新完整 turns，不修改 Raw。
- 不阻止用户继续发送，也不增加专用“对话过长”流程。
- 跨对话知识只通过 Wiki 查询取得，不自动拼入其他对话。
- Provider 返回容量错误时如实显示，不伪造回答，不写 assistant Raw。

## 8. Wiki 与 Skill

### 8.1 系统 Skill

| 动作 | 自动使用 |
| --- | --- |
| 新建或接管 Wiki | `jc-everything-wiki` |
| 用户任务需要查询长期记忆 | `jc-cha-wiki` |
| 用户确认写入新知识 | `jc-raw-wiki` |
| 用户确认修正错误 | `jc-xiu-wiki` |
| 用户要求巡检 | `jc-jian-wiki` |

这些系统 Skill 与 `skill-creator`、`jc-new-user-guide` 等产品能力继续放在 `public/skills/`，由产品或模型按动作调用，不进入 Skill 仓库和 Skill 选择器。`public/skills/index.json` 只服务内部路由，不再作为用户 Skill 列表。

### 8.2 用户 Skill

Skill 仓库与输入框 `@` 菜单都读取 `agentStore.getCustomSkills()`；新增、编辑和删除后，记忆运行时下一轮生成的 Skill 目录及 `@` 菜单立即同步。仓库和 `@` 菜单都不读取或展示 `public/skills/index.json`。

Web 用户 Skill 写入浏览器可写存储 `jc_web_skills_v1`。不得把 `public/zijian/skills/` 设计成用户安装真源，因为 `public/` 在发布后是只读静态资源，浏览器无法把运行时生成的 Skill 写回该目录。Desktop 阶段复用现有 Central Skill 用户目录 `~/.agents/skills`。内置 Skill 优先解决同名冲突，用户 Skill 补充同一模型目录。

用户已安装 Skill 与产品内置 Skill 使用完全相同的自动发现合同：名称和 description 进入目录，正文只在模型调用 `skill(name)` 后加载。额外允许用户从 `@` 菜单明确选择已安装 Skill；该动作只对本轮生效并精确执行同一个 `skill(name)`，不增加关键词命中或固定 Skill 绑定。

`skill-creator` 生成的 Skill 只有在用户明确说“安装”后，才输出包含完整单文件 `SKILL.md` 的 `jc-skill-install` 块。界面把它解析为“安装到我的 Skill / 继续修改”确认卡；只有用户点击安装后才调用现有 `createAgent()` 写入用户 Skill Store，不能静默安装。第一版不安装 `references/`、`scripts/` 或 `assets/`；需要这些资源时必须先把必要规则收进自包含 `SKILL.md`。仓库现有手动自建入口继续保留。

### 8.3 Wiki 写入

普通对话只提供 Wiki 只读工具。只有以下情况进入受限写入轮次：

- 用户明确要求写入或修改 Wiki；
- 用户指定路径；
- 用户确认模型建议的路径和内容；
- 用户通过现有工具审批。

未指定路径时，模型先查询现有 Wiki，优先复用已有页面；没有合适位置时提出一个最小新路径，等待确认。写入后更新必要入口、`hot.md`、`log.md` 和 `来源索引.md`，重要结论可追溯到 Raw 文件及 turn 范围。

## 10. 对话内媒体

媒体生成是基础能力，不依赖创作面板或特定 Skill。用户要求生成图片、视频或音频时：

```text
模型按当前快速/记忆合同回答
  -> 上传附件先写入当前项目 jc-media/uploads/
  -> 当前 Raw 记录项目相对路径
  -> 本轮及历史图片/视频附件注册为受控 referenceId
  -> 生成公共 MediaPlan(image | video | audio)
  -> 对话内确认模型、提示词、参数、素材和价格
  -> 用户点击“开始生成”
  -> preparePublicMediaPlan()
  -> mediaTaskStore.submitTask()
  -> 对话内显示进度、取消、失败和结果
  -> 结果写入当前项目 jc-media/
  -> Raw 追加最终可见结果和项目相对路径
```

- 三种媒体都使用现有模型注册表、公共计划、确认卡、任务 Store 和轮询恢复。
- 单个媒体任务使用一个计划对象；同一轮包含多个独立媒体任务时，`jc-media-plan` 使用对象数组，工作台逐项显示确认卡并以“回复轮次 + 计划序号”隔离提交、失败和任务进度。解析成功后技术 JSON 块不进入可见正文；解析失败时保留原文，不静默隐藏错误。
- 聊天模型看懂附件不等于媒体模型收到附件；计划必须经 `buildExplicitMediaReferences -> materializeMediaPlanReferences` 物化，确认卡才能进入图生图或图生视频。
- 历史上传附件从 Raw 的 `projectPath` 重建项目定位器；付费提交前重新读取项目文件，不依赖首次上传页面尚未释放的 Data URL。
- 音频按现有模型字段进入 `buildCreationRunPlan()` 和 `audioParams`，不另造音频合同。
- 所有可能扣费的任务必须先由用户确认。
- 不持久化临时远程 URL；成功结果先落项目，再写 Raw。
- 成功卡以项目文件为真源，显示 `已保存到 jc-media/...`，并只提供“下载副本”和“在文件树中查看”；不再显示含义重复的“保存”。
- Raw 只写成功任务的项目相对路径，不写 CDN URL；远程 URL 只是内部下载源和旧任务降级通道。
- 媒体计划的生成按钮、任务图标、进度条和操作悬停色统一使用 `--olive*` 主题变量，不写死紫色。
- 任务状态库丢失时，已成功媒体仍可从 Raw 相对路径和 `jc-media/` 恢复。
- 不加载 `CreationPanel`、画布、画廊或第二套媒体引擎。

### 12.4 同账号文字云同步

#### 产品边界

同步的不是“聊天数据库”，而是项目里的安全文本文件：

| 内容 | 是否同步 | 说明 |
| --- | --- | --- |
| `.raw/对话记录/*.md` | 是 | 对话标题、用户/助手 turn 和媒体项目相对路径一起同步 |
| `wiki/**`、`docs/wiki/**` | 是 | 否则手机与 Mac 的长期记忆会分叉 |
| 普通 Markdown、纯文本、JSON、YAML、CSV 等安全文本 | 是 | 使用扩展名/MIME 白名单和单文件大小上限 |
| `jc-media/**` 图片、视频、音频、3D、上传附件 | 否 | 只留在生成或上传它的设备 |
| 用户 Skill、MCP、Provider、API Key、Session、界面设置 | 否 | 继续使用各平台现有安全存储；凭据绝不进入同步库 |
| 二进制、未知格式、`.env` 和其他敏感文件 | 否 | 不读取、不上传、不猜测 |

另一设备打开含媒体引用的 Raw 时，正常显示文字和一张“媒体仅保存在原设备”的占位卡，不把缺失的 `jc-media/...` 当作损坏项目，不自动访问历史临时 URL。用户可在当前设备重新上传或重新生成媒体。

#### Cloudflare 边界

可以并且应该使用 Cloudflare D1，但不改 NewAPI：

```text
Web / Mac / Mobile
  -> 现有 api.jiucaihezi.studio Gateway
  -> requireWebUser() 校验现有韭菜盒子 Session
  -> /sync/projects 与 /sync/projects/:id/files
  -> 独立 D1 binding: SYNC_DB
```

- 复用现有 Gateway、`jc_session` / `X-JC-Session` 和 NewAPI 账号 ID，不再注册第二个账号。
- 新建独立 `SYNC_DB`，不把大量项目正文混入现有登录数据库 `DB`；同一个 Worker 绑定两个 D1 即可。
- 不启用 R2。只有未来明确要求媒体跨设备时，才单独评估 R2、流量、生命周期和用户配额。
- 所有查询必须带 `user_id` 所有权条件；客户端提交的 user ID 不可信，用户身份只能来自服务端 Session。
- Worker 只接受允许的相对路径、UTF-8 文本、大小上限和内容哈希；拒绝 `..`、绝对路径、NUL、凭据路径和媒体目录。
- 第一版服务端合同为 `GET/POST /sync/projects`、`GET/POST /sync/projects/:id/files`、`POST /sync/projects/:id/delete` 与 `POST /sync/projects/:id/restore`。单文件上限 2MB，单批 1-100 项，单次拉取最多 200 个路径。

最小数据模型：

```sql
projects(id, user_id, name, created_at, updated_at, deleted_at)
text_files(project_id, path, content, content_hash, revision, updated_at, deleted_at)
sync_mutations(id, project_id, device_id, created_at)
```

`projects(user_id, updated_at)`、`text_files(project_id, path)` 和 `sync_mutations(id)` 建唯一/查询索引。`mutation id` 保证网络重试不会重复写入；`revision` 是乐观并发条件，不以客户端时钟判断谁覆盖谁。

#### 同步时序

本地项目文件始终先落盘；同步失败不能阻止离线聊天：

```text
本地创建/修改/删除安全文本
  -> ProjectFileService 成功
  -> 写入本地待同步队列（mutation id + expected revision）
  -> 在线时推送到 Gateway
  -> D1 原子校验账号、路径、mutation id 和 revision
  -> 返回新 revision / 冲突

登录、打开项目、App 回到前台、用户点“立即同步”
  -> 按 cursor 拉取远端变更
  -> 写入本地 ProjectFileService
  -> 更新本地 cursor
```

第一版不做 WebSocket、字符级实时协同、后台常驻进程或 CRDT。产品目标是“手机用完，Mac 打开后接着用”，不是两台设备同时编辑同一行。

#### 冲突与删除

- 服务端更新必须携带 `expectedRevision`；不一致返回 `409`，绝不静默最后写入覆盖。
- Raw 对话仅在能按稳定 turn ID 无歧义合并时自动合并；否则保留本地版本，并生成可见冲突副本等待用户选择。
- Wiki 和普通文档第一版不做语义自动合并；冲突时保留两份，模型不能替用户猜哪份正确。
- 删除使用 tombstone，至少保留 30 天，防止离线设备把旧文件重新上传；恢复和永久删除后续复用同一 revision 合同。
- 项目列表、文件正文和 tombstone 都按账号隔离；退出登录后停止同步，但不删除用户本地项目。

#### 项目身份

D1 为每个云项目生成稳定 `project_id`。每台设备只在本地保存 `本地 owner -> cloud project_id + cursor` 映射；文件路径仍由 `ProjectFileService` 管理，不把绝对路径上传云端。新设备从云项目列表选择项目后，在 App 管理目录创建本地副本，再进入现有工作台。

## 13. 错误与并发

| 情况 | 行为 |
| --- | --- |
| 用户消息 Raw 追加失败 | 不发模型请求，保留输入并允许重试 |
| 对话读取失败 | 不请求模型，显示真实文件错误 |
| Wiki 查询失败或未发生 | 不接受候选回答，不追加 assistant |
| 模型失败、取消或流式中断 | 用户消息保留，不写不完整 assistant |
| assistant Raw 追加失败 | 保留可见结果并阻止下一轮，直到落盘成功 |
| Wiki 审批拒绝或写入失败 | 不回滚 Raw；拒绝则不写，失败可按相同来源重试 |
| 媒体失败或取消 | Raw 追加最终状态，不写成功路径 |
| 媒体成功但项目落盘失败 | 保留生成成功与原始结果，单独显示保存警告和“重试保存” |
| MCP 未连接或调用失败 | 不伪造外部结果，显示真实错误 |
| 多窗口同时追加 | revision 冲突后重读，按 turn ID 去重重试 |
| 文字同步离线或超时 | 本地写入照常成功，保留待同步状态；恢复网络后按同一 mutation id 重试 |
| 云端 revision 冲突 | 返回 409，保留两份并显式提示；禁止最后写入静默覆盖 |
| 另一设备缺少媒体 | 文字继续可读，媒体显示“仅保存在原设备”，不把缺失媒体当成同步失败 |
| Session 失效 | 停止同步并要求重新登录，不删除本地文件、不退化为公共数据 |
| Provider 容量错误 | 原样显示，不新增隐藏摘要流程 |

### 14.6 导航职责分离决策记录（2026-07-26）

用户实际使用发现：把对话 Raw 和普通资料放在同一文件树中，会迫使用户先找 `.raw/对话记录/` 再回到原对话，造成不必要的导航成本。本次决策修正为：

- 顶部新增轻量对话选择器，负责当前项目内对话的搜索、切换、新建、重命名和删除；它只是 Raw 的实时投影，不建立第二份存储或索引。
- `.raw/对话记录/` 默认从普通资料文件树隐藏；高级用户可通过“显示系统文件”查看原文。
- 文件树只负责 Wiki、Markdown、媒体、画布和其他项目资料；点击资料打开统一临时预览层。
- 预览层不销毁当前对话，顶部固定提供“返回对话”；支持 Esc/关闭返回，并恢复原对话、滚动位置、输入草稿和附件。
- 普通资料预览与对话切换是两条清晰路径；只有顶部对话选择器可以进入聊天，不从普通文档预览层猜测或切换对话。

实施时优先复用现有 `ProjectFileService`、Raw 解析器和中央内容壳，只新增 `ConversationSwitcher` 与 `previewResource` UI 状态。

### 14.7 已验证的产品与工程经验（2026-07-26）

这一阶段最有价值的产出不是某个按钮，而是一组经过真实使用、失败截图和跨端构建验证的工作台原则。后续漫剧、电商和制作工作台可以复用这些原则，但不能机械复制本工作台的业务目录。

#### 经验一：文件是真源，界面只是投影

- Wiki 是项目长期确定性记忆，Raw 是每个对话的完整原始记录；不再增加第二套会话数据库、摘要记忆或隐藏项目状态。
- 对话选择器直接投影 `.raw/对话记录/`，文件树直接投影项目资料。创建、重命名、删除和恢复都回到同一文件合同，避免 UI 状态与磁盘事实分叉。
- 临时附件、远程媒体 URL、工具过程和轮询快照不是项目事实，不应伪装成长期记忆。媒体成功后先写项目文件，再把相对路径写入 Raw。

#### 经验二：同一对话允许不同执行深度

- `快速` 与 `记忆` 不是两个会话或两个产品模式，而是当前一轮的执行策略；两者必须写入同一个 Raw，用户切换时不能丢上下文。
- 快速路径保留完整对话、附件和媒体规划但不提供工具；记忆路径提供 Skill/项目/MCP 工具，由模型按任务自主决定是否调用。
- “快”来自少一次不必要的工具循环，不来自删掉附件、媒体、模型选择或对话历史。

#### 经验三：导航按用户目标分工，不按文件类型堆入口

- 对话选择器只负责回到和管理对话；文件树只负责浏览项目资料；设置抽屉只负责账号、Skill、MCP、主题和模型相关配置。
- 点击文档或媒体进入覆盖式临时预览，而不是销毁对话或把所有文件强塞进聊天渲染器。返回后必须保留滚动、草稿、附件和引用。
- 高频动作必须出现在其对象旁边：新建对话紧邻对话选择器；新建文件、新建文件夹和刷新位于文件树项目身份下方。不能要求用户理解 `.raw` 目录结构才能完成日常操作。

#### 经验四：AI 输出是外部输入，解析器不能只相信理想提示词

- 系统提示规定输出格式，只能提高遵守概率，不能替代解析层兼容和校验。模型可能返回单对象、对象数组或非法内容，应用必须显式区分。
- 同一轮多个独立媒体任务使用一个 `jc-media-plan` 对象数组；工作台逐项物化确认卡，并以“回复轮次 + 计划序号”隔离价格确认、提交、失败和进度。
- 只有成功解析并形成确认卡后才隐藏技术块；解析失败必须保留原文用于排障。禁止 `catch {}` 之后既不显示错误、又把机器 JSON 当普通正文长期留在界面。

#### 经验五：聊天模型看见素材，不代表执行模型收到素材

- 上传、粘贴和项目媒体统一先形成受控 `referenceId`，再通过 `buildExplicitMediaReferences -> materializeMediaPlanReferences -> preparePublicMediaPlan` 进入公共媒体任务合同。
- 不能根据“模型已经描述了图片”推断图生图或图生视频已经成立；确认卡必须展示实际引用素材、执行模型、参数和价格，用户确认后才提交付费任务。
- 图片、视频、音频和 3D 共享模型注册表、确认卡、任务 Store、失败终态和落盘链路；工作台不复制创作面板，也不另造媒体引擎。

#### 经验六：失败必须尽早成为明确终态

- 上游已经明确失败时，adapter 和 App 都必须停止轮询并显示真实原因；不能把明确失败包装成临时 HTTP 故障后无限等待。
- 媒体计划解析失败、参考素材失效、模型未注册、价格合同不完整和项目落盘失败都必须在付费前或结果卡上可见。
- 原始链接只作为旧任务或下载失败的降级出口；不能为了界面干净而删除唯一可取回结果的通道，也不能未经基础 HTTPS 检查直接信任任意模型文本中的 URL。

#### 经验七：视觉对称来自职责和基线，不来自强行拉齐所有线

- 左侧项目身份与中央对话顶栏共用同一高度和主分界线；文件动作和搜索属于线下次级层，不要求所有内部辅助线跨越整个页面。
- Logo 与文字采用光学而非纯数学居中；本次 `2px` 下沉是在桌面与窄屏截图中验证后的视觉修正。
- 固定格式控件必须有稳定高度、响应式上限和独立滚动容器。文件树、文档预览、模型菜单和 Skill 菜单各自滚动，不能依赖整页滚动兜底。

#### 经验八：发布证据必须对应真实交付物

- 源码测试、`vite preview`、Cloudflare Preview 和 Production 是四种不同证据；本地页面正常不等于正式域名已更新。
- `4174` 当前是 `vite preview`，源码修改后必须重新构建 `dist/` 才会变化；不能把旧产物误判为新代码的视觉结果。
- 发布前至少完成本次相关定向回归、TypeScript、正式 Web 构建、产物审计、桌面与 `390x844` 浏览器检查。全仓若有已知旧合同失败，必须明确列出且证明与本次差异无关，不能笼统声称全量通过。
- Production 必须使用 `npx wrangler pages deploy dist --branch=main`，保留部署 URL 和上一版回滚点；Git commit、Git push 与 Web 部署分别记录，不能混为一个动作。

#### 经验九：完整文字历史不等于完整媒体上下文

- Raw 中有附件名称，只能证明“曾经上传过”，不能让后续模型重新取得附件本体；附件必须先成为项目文件，再由 Raw 保存稳定定位器。
- 不能每轮重发全部历史图片二进制：这会放大请求、增加成本，并在多图时制造指代歧义。正确做法是向模型提供受控引用清单，只在确认卡和执行边界读取被选中的素材。
- 页面内存中的 Data URL 只服务当前轮预览和模型识图，不是长期记忆。刷新恢复、隔轮复用和卡内换模型必须依赖 `jc-media/uploads/ + Raw projectPath`。

#### 经验十：生成、取回与保存是三个状态，确认卡是可复用参数单

- 上游生成成功、浏览器取回结果、写入项目文件是三个阶段。后两步失败不能把已经付费完成的生成任务改写成“生成失败”；必须保留原始结果，并单独提供“重试保存”。
- `api.jiucaihezi.studio` 返回的 `/v1/videos/{task}/content` 等结果地址可能仍需当前用户 Token。浏览器只对韭菜盒子 API 同源结果下载附加现有认证，不能把 Token 发往第三方 CDN；聊天结果卡直接显示受信执行链返回的安全 HTTPS 地址，项目副本只在用户点击下载、文件树预览或再次引用时读取。
- 媒体确认卡不是一次性按钮，而是当前提示词、参考素材、模型、比例、分辨率和时长的可复用参数单。提交后仍可调整参数并“再次生成”，旧结果不能被新任务覆盖。
- 图片支持一次生成 `1-5` 张；每张都是独立付费任务、独立进度和独立结果。批量提交发生部分失败时，已经提交的任务必须立即显示，并明确提示成功提交数量；视频、音频和 3D 暂不提供批量入口，避免高成本误操作。

#### 经验十一：落盘不是展示缓存，媒体卡不得主动搬运项目文件

- 2026-07-26 两次 Chrome Renderer 崩溃 dump 明确记录 `OOM (CALL_AND_RETRY_LAST)`、V8 `allocation failure` 和当前 `gpt-image-2-vip` 任务。生成请求已返回 HTTP 200、项目文件已保存，崩溃发生在结果展示阶段。
- 根因是每个成功任务卡挂载时都从 OPFS 读取完整媒体，再依次复制为 `ArrayBuffer -> Uint8Array -> Blob -> Object URL` 并解码；批量图片和历史任务卡会并发放大峰值。`URL.revokeObjectURL()` 只能在卸载后释放，不能阻止挂载时的峰值。
- 第一轮止血只取消了任务卡自动读取 OPFS，仍让完整历史和每个视频/音频播放器长期挂载；`preload="metadata"` 不能释放媒体元素、解码上下文和 GPU 资源，因此不是最终架构。

#### 经验十一补充：任务、资产、轻量卡片、按需预览必须分层

横向依据：

- OpenCode `message-timeline.tsx` 使用 `@tanstack/solid-virtual`；LobeHub `VirtualizedList.tsx` 使用 `virtua`。两者都只挂载可视消息，并为生成中或用户正在选择的消息保留例外。
- Open WebUI 默认只挂载最近 8 条消息，向上滚动再扩展，并用 `content-visibility` 降低非可视布局成本。
- ComfyUI 的任务资产列表使用 `@tanstack/vue-virtual`；`LazyImage.vue` 通过 `IntersectionObserver` 进入视口才取得媒体，离开后释放 Blob URL；视频播放器只存在于结果查看组件。
- InvokeAI Gallery 使用 `react-virtuoso` 的 windowed list，只为当前可视范围批量取得完整 DTO，原图进入独立 Viewer。
- 本项目主 App 已采用同一原则：文件树虚拟化；视频在画布中只保存项目路径、静态首帧和播放按钮；Desktop 首帧由后台 `ffmpeg` 单通道生成；点击后才建立唯一预览播放器。

公共媒体合同：

```text
媒体任务：状态、模型、提示词、参数、进度、错误
  -> 媒体资产：assetId、项目路径、MIME、缩略图/封面、原始结果地址
  -> 轻量载体：对话卡、文件树、画布只消费元数据和缩略图
  -> 按需查看：用户点击后读取本地项目文件，并建立唯一预览实例
```

- Raw 只保存稳定任务/资产身份和项目相对路径，不保存媒体二进制、Data URL、Blob URL 或播放器状态。
- 记忆对话复用项目现有 `@tanstack/vue-virtual` 动态高度时间线，只挂载可视区及 overscan；运行中的轮询属于 Store，不依赖任务卡是否挂载。
- 图片卡可使用安全 HTTPS 缩略展示，但必须 `loading="lazy" + decoding="async"`；视频、音频和 3D 卡只展示静态类型、模型、保存状态和操作，不在时间线建立播放器或渲染器。
- 点击已落项目的结果统一进入现有中央资源预览；任何时刻最多存在一个视频、音频或 3D 预览实例。关闭预览、切换资源或切换对话必须停止播放并释放本地 Object URL。
- 项目文件是设备内持久化真源，远程结果地址只负责刚完成时的轻量图片展示和保存失败兜底；下载、打开和再次引用才读取项目二进制。
- Desktop、Web、Mobile 共享上述身份和生命周期合同，但缩略图实现允许按平台不同：Desktop 后台 `ffmpeg`，Web 无缩略图时显示静态视频封面，Mobile 后续使用原生媒体框架。

压力验收：同一对话至少覆盖 100 轮文字、50 张图片、20 个视频；未打开预览时 DOM 中不得存在 `video`/`audio`，打开时同类播放器最多 1 个；连续滚动、切换对话和关闭预览后不再持有离屏播放器、Blob URL 或已完成任务轮询。Web Chrome、Mac App 和手机真机必须共用这组门禁。

#### 经验十二：项目二进制重读必须恢复真实 MIME

- 2026-07-26 Mac 2.0.1 再次提交历史参考图时，RH 明确返回 `Unsupported file type: application/octet-stream`；这不是渠道集体失效，而是 Desktop 文件读取只返回字节和大小，计划重建的项目定位器又没有 MIME。
- Raw 虽然正确保存了原附件 `image/jpeg`，媒体计划只持有项目路径；付费提交重新读取后若不从明确元数据或受控扩展名恢复 MIME，数据 URL 就会退化为 `application/octet-stream`。
- 正确边界在共享 `ProjectFileActions.readMediaDataUrl()`：存储层 MIME 优先，其次资源 MIME，最后才按受控媒体扩展名推断。不得在 Seedance、RH adapter 或单个模型分支里打补丁。

#### 经验十三：媒体确认卡确认的是用户意志，不是模型改写

- 用户明确写出提示词或动作描述时，媒体计划必须原样使用；只有用户明确要求优化，或没有提供可执行描述时，模型才可以补全。专业化 Skill 是可选增强，不能默认覆盖用户原话。
- 付费提交前的提示词必须和模型、比例、分辨率、时长一样可编辑；确认卡里的当前值才是最终提交真源。
- 模型 ID 和路由不能为了视觉简洁被隐藏成无法区分的同名项。同一展示名来自不同执行来源时，下拉菜单必须补充“直连 / RunningHub”，但不新增渠道分组或改变路由。

## 15. 验收标准

### 15.1 导航与资源

1. 页面没有项目选择器和四模式入口；顶部只有一个基于 Raw 的对话选择器。
2. 选择器可搜索、切换、新建、重命名和删除当前项目对话，且不创建第二份对话存储。
3. 只有选择有效对话 Raw 才出现聊天记录和输入框。
4. 普通 Markdown/文本在临时预览层按文档显示，不出现聊天输入框。
5. 图片、视频、音频分别可预览或播放。
6. 二进制、超大文本和 `.jccanvas` 不进入聊天或可写文档，只有安全动作。
7. 选择器显示 H1 标题，但真实文件名和 ID 不变。
8. 刷新后只根据项目文件恢复，不依赖第二份对话列表数据库。
9. 文件树第一排显示 Logo、当前项目名/切换入口和隐藏按钮，第二排只显示新建文件、新建文件夹和刷新；“新建对话”紧邻顶部对话选择器。
10. 点击文件树中的资料打开统一预览层；返回、Esc 或关闭后恢复原对话、滚动位置、草稿和附件。

### 15.2 对话与 Wiki

1. 新建对话立即创建带有效标记的唯一 Raw。
2. 用户消息先写 Raw，再发模型；完整回复后写 assistant Raw。
3. 模型看到当前对话和 Skill 目录后，按 description 自主决定是否调用 `jc-cha-wiki` 或其他 Skill；App 不预查关键词、不强制调用。
4. 模型只有实际调用并成功取得工具结果后，才可声称查询或修改了项目；普通回答无需工具门禁。
5. 普通聊天不写 Wiki；用户确认后可写合理路径并追溯到 Raw turn。
6. 清除 UI 状态后，全部对话仍可从 Raw 恢复。
7. 普通文本文件可引用到当前对话；引用只进入本轮模型请求，原文件保持不变。
8. 绑定普通文件夹不自动写入；点击“新建记忆空间”后才建立 Wiki/Raw，点击“新建对话”后才建立对话 Raw。

### 15.3 设置、Skill 与 MCP

1. 账号/齿轮按钮可打开登录、Provider、模型、Skill 仓库、MCP 和通用设置。
2. 设置不是常驻第三栏，关闭后回到原资源。
3. Skill 仓库和输入框 `@` 菜单只显示用户已安装 Skill；新增、编辑或删除后自动发现目录与菜单立即同步。`@` 同时可引用当前项目文件和媒体。
4. `public/skills/` 中的产品内置 Skill 不在仓库出现，但与用户 Skill 一样由模型按 description 自主调用。
5. 用户明确要求安装后才出现安装确认卡；点击“继续修改”不写入，点击“安装到我的 Skill”才写入并同步两处列表。
6. 只有 `enabled + connected` 的 MCP 工具进入模型候选池。
7. Web 不显示不可执行的本地 `stdio`；Desktop 可使用现有本地与远程 MCP。
8. 凭据不进入 Raw、Wiki、日志或模型上下文。
9. 设置提供白色、浅色、黑夜和护眼四主题；记忆 Web 首次启动默认护眼绿色。
10. 输入框只显示一个 Skill 入口；列表向上浮动、不改变输入框尺寸、不越出中央内容区，选择或点击外部后关闭。
11. “新建对话”不显示装饰图标；文本模型列表按 Claude、GPT、Gemini、Grok、DeepSeek、通义、智谱、豆包、本地模型和其他分组，不显示 RunningHub 媒体模型；触发框随当前模型名称自适应，展开浮层与其左对齐。
12. 文件树和文档预览内容超出可见区时，两者均可用鼠标滚轮独立上下滚动，并显示可拖动的竖向滚动条。

### 15.4 媒体

1. 不选择媒体 Skill 也能自然语言生成图片、视频和音频。
2. 三种媒体使用同一公共计划、确认卡、`mediaTaskStore` 和落盘合同。
3. 未确认付费不提交任务。
4. 对话内能看到进度、取消、失败和最终媒体。
5. 结果分别写入 `jc-media/images`、`videos`、`audios`，Raw 只记项目相对路径。
6. 成功卡可一键下载副本，也可定位并打开文件树中的项目文件；界面不暴露远程 URL。
7. 开始生成与生成中的强调色随当前主题变化，不出现独立紫色。
8. 不加载 `CreationPanel`、画布、画廊或第二套任务引擎。
9. 已提交的确认卡可改模型、比例、分辨率或时长后再次生成，历史任务和结果继续保留在原卡下。
10. 图片确认卡可选择一次生成 `1-5` 张，每张显示独立任务状态；部分提交失败不隐藏已提交任务。
11. 上传或粘贴的图片、视频立即保存到 `jc-media/uploads/`，Raw 只保存项目相对路径和附件元数据，不保存二进制副本。
12. 隔多轮后可用明确指代复用历史上传素材；只有一个候选时直接进入带缩略图的确认卡，多个歧义候选时不得静默选错。
13. 刷新页面、重新打开对话或在原确认卡切换模型和参数后，图生图/图生视频仍使用原项目素材。
11. 上游生成成功但项目保存失败时，结果仍按成功展示，并提供原始结果与“重试保存”；不得显示为“生成失败”。
12. 韭菜盒子 API 的受保护结果下载携带当前 Token，第三方媒体域名绝不携带该 Token；播放优先使用项目内已保存副本。

### 15.5 发布

1. Mac 私测必须先于 Web 正式发布，且使用本机测试构建，不触发正式更新通道。
2. RH 3D 真实验收前，服务器必须完成新版 `rh-adapter` 重建，以及 NewAPI 的 `rh-3d-text` / `rh-3d-image` 模型和价格配置。
3. Web 正式发布前，必须先完成同一 Pages 项目的预览部署和真实浏览器验收。
4. Web 预览验收通过后，正式发布到 <https://jiucaihezi.studio>；旧部署保留用于回滚。
5. Mobile 在 Web 正式发布稳定后再建立移动发布配置。
6. 当前阶段不存在 `chat.jiucaihezi.studio`、`com.jiucaihezi.chat`、`jiucaihezi-chat://`、`chat-v*` 或 `/updates/chat/`。
7. 现有主 App 源码、签名身份和历史发布可用于回退。

### 15.6 跨设备文字同步与 Mobile

1. 同一账号在 Web、Mac 和 Mobile 看到相同的云项目列表；不同账号即使猜中 project ID 也只能得到统一的不可见响应。
2. `.raw/对话记录/`、Wiki 和允许的普通文本可双向增量同步；媒体二进制、Skill、MCP、Provider、API Key、Session 和设置不会进入请求或 D1。
3. 手机新增一个用户 turn 和完整 assistant turn 后，Mac 拉取即可继续同一对话；Mac 写入 Wiki 后，手机拉取能用于下一轮记忆查询。
4. 断网发送和 Wiki 写入先在本地成功并显示“待同步”；恢复网络后按同一 mutation id 上传，不生成重复 turn 或重复文件。
5. 两台设备基于同一 revision 修改同一文件时，后一提交收到 409；Raw 只有稳定 turn 可无歧义合并时才自动合并，其他文件保留冲突副本。
6. 删除同步到离线设备后不会被旧副本复活；30 天 tombstone 期间可以恢复。
7. 新设备打开含 `jc-media/...` 引用的对话时，文字和计划正常显示，缺失媒体明确标注“仅保存在原设备”，无自动远程下载和崩溃。
8. D1 中没有绝对路径、二进制/Base64、临时媒体 URL、系统提示词、隐藏推理或任何凭据。
9. Mobile 使用 App 管理目录和同一 `ProjectFileService` 语义；不因平台不同复制 Raw 解析、Wiki 工具或媒体计划实现。
10. iPhone 真实设备完成登录、前后台恢复、断网重试、文字双向同步、对话、Wiki、附件和本地媒体闭环后，才开始 Android 发布矩阵。

## 16. 成功路径

```text
打开 https://jiucaihezi.studio
  -> 创建或导入项目
  -> 若项目尚未初始化，点击“新建记忆空间”（仅此时写入 Wiki/Raw 骨架）
  -> 文件树出现 wiki 和已有资料；对话选择器读取 .raw/对话记录/
  -> 点击顶部“新建对话”并开始聊天
  -> 用户消息写入当前 Raw
  -> 模型读取当前对话并自主查询 Wiki
  -> 模型回复写回同一个 Raw
  -> 从顶部选择器切换另一个对话，中央区恢复并继续该对话
  -> 点击 Wiki 文档，打开临时预览层；返回后继续原对话
  -> 点击图片/视频/音频，打开临时预览层或播放器；返回后继续原对话
  -> 从设置登录、选模型、管理 Skill 和 MCP
  -> 在对话内确认并生成媒体，结果落当前项目
  -> 用户确认后把结论写入 Wiki
  -> 本地 Raw/Wiki 变更进入待同步队列并上传 D1
  -> 同账号手机从云项目列表拉取文字副本，继续同一对话
  -> 手机本地媒体不上传；Mac 只显示“媒体仅保存在原设备”
  -> Mac 再次打开后增量拉取手机新增文字并继续
  -> 关闭重开，仍先从本地项目 Raw、Wiki 和媒体恢复
```

这条路径成立，就说明第一个工作台完成跨设备闭环。第四阶段必须先让 Web 与 Mac 通过同一同步合同，再接 Mobile；不提前创建三套业务代码，不让手机成为第二个数据孤岛。
