# 通用记忆工作台 3D 白膜场景基础工具 SDD

> 日期：2026-08-01
> 状态：现有能力与主要人物白膜升级已实施；自动验证和 Web 桌面/移动视口验收完成，三平台安装包矩阵待补
> 范围：通用记忆工作台 Web / Desktop 的本地可编辑 3D 白膜场景；不改 AI 媒体生成、GLB 模型生成和现有 2D 画布。

## 1. 目标

让普通用户直接用自然语言搭建空间关系：

```text
用户描述场景
  -> 模型调用一个常驻基础工具，给出积木、位置和排列
  -> App 用本地 Three.js 立即生成白膜场景
  -> 用户旋转镜头、拖动对象或分组
  -> 截取当前视角，保存为项目图片并用于后续生图参考
```

它服务的是构图、人物关系、机位和空间调度，不追求精细建模。

## 2. 产品决断

1. 这是本地基础工具，不是 AI 媒体任务，不调用 RunningHub，不计 3D 生成费用，也不弹媒体确认卡。
2. 复用项目已有的 `three`、项目文件服务和 `.raw/jc-media`，不新增 3D 引擎、素材库或运行时依赖。
3. 白膜场景以 JSON 内容保存为可再次打开的 `.jcscene` 文件；截图保存为 PNG，自动动画和手动运镜保存为 MP4。可编辑源文件进入 `.raw/jc-media/文档`，截图进入 `.raw/jc-media/图片`，视频进入 `.raw/jc-media/视频`，不增加第五类素材目录。
4. 现有 `Model3DViewer` 继续只负责查看 GLB/GLTF。白膜编辑使用独立的按需加载组件，不把 Three.js 塞进 LeaferJS 画布，也不改现有 AI 3D 链路。
5. 基础工具只表达通用几何和空间关系。宫殿、王座、汽车、楼房等具体物品均由通用积木组合，不进入内置素材库。
6. Three.js 已在现有产品中并按需分包；白膜编辑器同样只在打开 `.jcscene` 时加载。机位、灯光、阴影、网格和截图均使用 Three.js 自带能力，不增加依赖、浏览器内核或素材包，普通对话和启动路径不加载场景渲染器。

## 3. 通用积木

| 积木 | 表达内容 | 最小属性 |
| --- | --- | --- |
| 人物 | 角色、群众、军队 | 颜色、标签、朝向、站/坐/蹲/躺 |
| 方块 | 建筑、车辆、家具、台阶、箱体 | 长宽高、颜色 |
| 平面 | 地面、道路、水面、广场、舞台 | 长宽、颜色 |
| 墙面 | 墙、围挡、空间边界 | 长度、高度、厚度、朝向 |
| 入口 | 门、出口、通道位置 | 宽度、高度、朝向、标签 |
| 圆柱 | 柱子、树干、路灯、桶 | 半径、高度、颜色 |
| 球体 | 树冠、石块、空间标记 | 半径、颜色 |
| 圆锥 | 山体、树冠、警示物 | 半径、高度、颜色 |
| 线条/箭头 | 道路标线、行动路线、视线、方向 | 起点、终点、颜色 |

`入口` 只做清楚可见的门框或入口标记，不做布尔挖洞。需要真实通透的墙时，由模型用多个墙段围出开口。

### 3.1 主要人物白膜（2026-08-02，已实施）

独立主要人物在不改变场景数据协议的前提下升级为最小人形：

- 胶囊躯干。
- 球形头部。
- 两条细胶囊手臂。
- 两条细胶囊腿。
- 保留现有朝向标记。

站、坐、蹲、躺继续使用现有 `pose`，只为躯干和四肢设置简单位置与旋转，不增加关节参数、骨骼、动画或动作编辑器。人物颜色、标签、选择、拖动、分组、保存和截图合同不变。

该升级只作用于需要单独调整的独立人物。军队、群众等批量阵列继续使用胶囊躯干与球形头部的 `InstancedMesh`，不增加四肢，避免大规模场景增加绘制对象和内存占用。不引入 `three-stdlib`、人体模型或第三方人物库；继续直接使用项目已有 Three.js 几何体。

### 3.2 Storyboarder 导演预演人物（2026-08-08，已实施）

独立主要人物现在可以选择 Storyboarder 锁定快照中的成年男、成年女、少年男、少年女和儿童五个原始 GLB。用户可以切换模型、移动、转向、缩放身高，应用原始全身姿势和左右手手势，并用现有 `TransformControls` 旋转导演构图需要的头、颈、手臂、腿和食指骨骼。

GLB 只作为 Tauri Desktop 资源打包，原始姿势和手势只随按需加载的 3D 编辑器块加载；普通启动、对话和 Web 不加载五个 GLB。场景保存最终骨骼四元数，旧积木人物和批量阵列合同不变。来源、哈希、测试和实施边界见 [[开发/通用记忆工作台Storyboarder五人物导演预演TDD]]。

## 4. 排列、组合与标签

### 4.1 排列

重复对象不让模型逐个输出坐标，而使用四种排列：

- `line`：单排或多排，例如道路两侧站人。
- `grid`：方阵，例如军队、观众席、停车场。
- `circle`：环形，例如围观、会议、包围。
- `scatter`：在指定区域内固定随机种子散布，例如行人、树林、石块。

排列包含数量、间距、朝向和起点。模型说“左右各十名大臣”时生成两个排列；说“两军对阵”时生成两个方阵。大批相同对象使用 Three.js `InstancedMesh` 本地绘制，避免上千个独立模型和上千条工具参数。

### 4.2 组合与分组

- 多个基础积木可以组成一个有名称的分组，例如“桌子”“主位”“车辆”“城门”。
- 重要人物作为独立对象，可单独拖动。
- 军队、群众等排列默认作为整体移动，不在第一版提供上千人的逐个编辑。
- 分组只是场景数据中的父子关系，不引入预制件系统或素材市场。

### 4.3 标签与颜色

- 每个对象或分组可以有标签和颜色，便于区分身份和阵营。
- 标签始终朝向镜头，截图前可一键显示或隐藏。
- 颜色只使用一组稳定的基础色，也允许模型传入合法 CSS 颜色；不做材质编辑器。

## 5. 场景数据与基础工具

新增一个记忆模式常驻基础工具 `create_3d_scene`。它与 `read / write / create_html` 同级，任何 Skill 都能组合调用，不需要先加载专用 Skill。

工具只接收以下稳定信息：

```text
title
existingPath?       # 修改已有场景时使用，只允许当前项目内的场景文件
objects[]           # 独立人物和通用几何
formations[]        # line / grid / circle / scatter 排列
groups[]            # 对象与排列的简单分组
camera?             # 可选初始机位
savedCameras?       # 可选的多个命名机位
lighting?           # 可选的固定方向和强度
canvas?             # 画幅、网格和吸附设置
```

App 负责校验类型、数量、尺寸、颜色、项目路径和唯一 ID，再写入版本化 `.jcscene`。首次创建同名保留两份；`existingPath` 只在用户明确要求完整重做时覆盖同一场景。普通增加、移动、删除和镜头调整必须使用 `edit_3d_scene` 原子操作，验证全部通过后一次写回。需要单独调整的人物必须是独立对象；大批量阵列只整体调整。

工具描述必须明确区分两类需求：

- 空间排位、白膜、机位、构图参考 -> `create_3d_scene`。
- 创作精细图片、视频或真实 3D 模型 -> 现有 AI 媒体能力。

不增加关键词分类器、二选一弹窗或专用 Skill，由模型根据本轮用户任务选择工具。

## 6. 编辑器交互

第一版只提供完成目标所需的操作：

1. 鼠标或触控旋转、平移和缩放镜头。
2. 点击选择独立对象或分组，拖动改变位置；选中状态清楚可见。
3. 显示/隐藏标签。
4. 恢复默认视角。
5. 保存当前场景；拖动结束后同步更新当前场景 JSON。
6. 截取当前视角为非空 PNG，并保存到 `.raw/jc-media/图片`。
7. 打开场景时在编辑器下方直接输入修改要求；普通修改增量写回并刷新同一场景，明确“重做”才完整覆盖。

### 6.1 机位与画幅

- 提供俯拍、平视、低机位和四个正侧视方向，不做自由镜头参数面板。
- 提供广角、标准、长焦三档视角，以及透视/正交两种投影。
- 提供 `16:9 / 9:16 / 1:1 / 4:3 / 3:4` 画幅框；只改变构图预览和截图比例，不改变场景。

### 6.2 简单灯光与阴影

- 固定提供均匀环境光，以及左侧、右侧、正面、背面、顶部五个主光方向。
- 只允许调整主光方向、开关阴影和三档亮度，不做灯具对象、颜色、专业灯光参数或阴影烘焙。
- 灯光只帮助看清体积和空间，不模拟最终生图画风。

### 6.3 网格与对齐

- 地面网格可显示或隐藏，默认开启。
- 拖动时默认吸附到网格；可临时关闭吸附。
- 不做尺寸标注、磁性参考线或复杂工程测量。

### 6.4 多机位

- 用户可把当前镜头保存为命名机位、切换机位、删除机位并分别截图。
- 底部默认直接提供九个通用机位：全景、正面中景、俯拍、低机位、双人中景、两个人物的过肩和近景；人物名称优先取场景实际标签。
- 机位只保存相机位置、观察目标、投影、视角和画幅，不复制场景。
- 不做时间线、镜头运动或自动分镜。

### 6.5 标签显示

- 标签使用固定屏幕尺寸，镜头靠近时不随世界尺寸无限放大。
- 人物标签锚定在头顶，并参与正常深度遮挡，不穿墙显示。
- 保留工具栏现有的一键显示/隐藏；不增加自动避让、大小滑块或设置面板。

### 6.6 小白入口

用户不需要知道工具名。记忆模式下直接说“创建一个 3D 白膜”“帮我摆人物站位”“搭一个可旋转的构图草模”或其他清楚表达空间排位目的的话，模型即可调用 `create_3d_scene`；不存在必须命中的固定口令。

工具成功后，对话时间线只显示轻量“白膜场景”结果卡，包含场景名称、对象/排列数量和“打开场景”按钮，不在对话卡内运行 WebGL。点击后进入中央白膜编辑器；关闭后回到对话。项目树中的 `.jcscene` 是第二个重开入口。

```text
自然语言创建或修改
  -> 对话结果卡“打开场景”
  -> 中央白膜编辑器旋转、拖动、切换机位
  -> 截图保存到图片目录并可作为生图参考
```

`.jcscene` 从项目树打开后进入白膜编辑器；普通 JSON、GLB/GLTF 和现有媒体预览行为不变。截图沿用现有项目图片和参考图流程，不新增一套附件系统。

第一版不做对象素材面板、复杂属性面板、时间线、撤销历史、多人协作或快捷键系统。用户新增、删除、改色、改朝向和改排列，继续通过自然语言完成。

## 7. 明确不做

- 不做 Blender、SketchUp 或游戏关卡编辑器。
- 不做服装、表情、IK、动画或自行制作人物与动作；独立主要人物只复用 Storyboarder 锁定快照的五个原始 GLB、姿势和手势。
- 不做纹理、材质、专业灯光编辑、阴影烘焙和物理模拟。
- 不内置宫殿、王座、桌椅、车辆、树木等具体模型。
- 不下载第三方 3D 素材，不引入 `mannequin.js` 等额外库。
- 不导出 GLB/GLTF；出现真实复用需求后再单独评估。
- 不保证生图模型百分之百复刻人数和位置；截图只作为更稳定的构图与空间参考。

### 8.1 v2.1.4 Web 崩溃根因与修复边界

Chrome“错误代码 5”不是项目文件移动或 Web 文件系统本身崩溃，而是新加入的 `.jcscene` 打开链路连续抛出未处理异常：

1. 场景文件为空或写入未完成时，资源入口直接 `JSON.parse`，`Unexpected end of JSON input` 击穿打开流程。
2. 完整场景进入编辑器后，只对最外层调用 `toRaw`，嵌套 Vue Proxy 仍使 `structuredClone` 抛出 `DataCloneError`。
3. 两类异常发生在组件挂载和 Vue 调度期间，随后更新队列报错，最终表现为 Chrome 渲染进程崩溃。

最小修复只守住两个共同入口：无效 `.jcscene` 降级为可检查的纯文本，不进入 WebGL；编辑器统一通过现有 `parseScene3DDocument` 得到已校验的纯数据，不再克隆响应式对象。不增加重试、恢复队列、文件监听或新的错误系统。

## 10. 实施结果（2026-08-01）

本节记录 2026-08-01 原始能力与 2026-08-02 主要人物白膜升级的实际结果。

- `create_3d_scene` 已作为记忆模式常驻基础工具接入 Web/Desktop；场景写入 `.raw/jc-media/文档/*.jcscene`，同名创建保留两份，传入 `existingPath` 时更新原文件。
- `.jcscene` 已接入项目树和按需加载的 Three.js 编辑器；通用积木、四种排列、分组、标签、拖动、网格吸附、固定机位、透视/正交、五种画幅、灯光、阴影、多机位和 PNG 截图均已落地。
- 对话只显示轻量结果卡，不在消息流加载 WebGL；截图写入 `.raw/jc-media/图片`，未新增依赖、素材库或媒体任务分支。
- 自动验证：focused 1422 通过、0 失败、8 跳过；`vue-tsc -b`、Web quick build、Desktop quick build和两端产物审计通过；图标审计无缺失。
- 浏览器实景验收：含人物方阵、入口、地面、墙面和命名机位的场景可见且可交互；透视/正交与 `9:16` 切换有效；截图为非空 `621 x 1104` PNG 并可从项目图片重新打开。
- v2.1.4 稳定性复验：空白或截断 `.jcscene` 不再击穿资源打开流程；响应式场景进入编辑器不再触发 `DataCloneError`；Web 实景可正常打开、切换九个默认机位，标签保持小尺寸且服从深度遮挡。前端 focused 1424 通过、0 失败、8 跳过，3D/资源入口定向回归 53/53。
- 待人工验收：真实模型自然语言选中本工具、Desktop 真机持久化，以及 Windows / Intel Mac / Apple Silicon 安装包交互矩阵。
- 2026-08-02 主要人物升级：独立人物增加两条细胶囊手臂和两条细胶囊腿，站、坐、蹲、躺继续复用原 `pose`；头部、胶囊躯干和朝向标记保留，场景协议未变化。
