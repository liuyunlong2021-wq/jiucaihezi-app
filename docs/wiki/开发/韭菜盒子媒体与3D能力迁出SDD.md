# 韭菜盒子媒体与 3D 能力迁出 SDD（决策撤销记录）

> 日期：2026-08-06
> 状态：**迁出决策已撤销，未实施；本文件只保留决策来路，不得作为执行合同**
> 现行依据：用户 2026-08-06 最终决定、[[架构/产品架构]]、[[hot]]

## 1. 现行决策

媒体生成、创作画布、3D 白膜、GLB/GLTF 查看和本地三维动画继续属于韭菜盒子的现有能力闭包，不迁入短视频工厂，也不创建第三个独立 App。

韭菜盒子的主定位仍是**个人与企业的可追溯 AI 知识库**。媒体与 3D 是项目内可调用的创作和表达工具，不需要因为它们不是知识库主流程就删除。唯一产品边界仍是：记忆工作台现在拥有的全部功能都保留；记忆工作台现在没有的功能全部迁出。

## 2. 撤销原因

1. 3D 场景需要项目上下文、模型、工具、文件管理和对话编排，单独迁出后仍需重建这些公共能力。
2. NewAPI 支持媒体接口，但其游乐场不能替代韭菜盒子的项目文件、参考素材、媒体任务恢复、画布和 3D 工作流。
3. 现有媒体与 3D 已按需加载并属于用户正在使用的能力；迁出会制造跨产品数据与工作流断点。
4. 老电脑适配应优化空闲资源和加载时机，不应通过删除功能、降低最终质量或限制高性能电脑来实现。

## 3. 保留范围

- 图片、视频、音频和 3D 模型生成；
- `CreationPanel`、`mediaTaskStore`、任务历史、轮询恢复和项目落盘；
- `.jccanvas` 创作画布及媒体结果写入；
- `.jcscene`、Three.js 白膜、机位、截图和动画；
- GLB/GLTF 查看和 Desktop FFmpeg MP4 导出；
- Gateway、NewAPI、RunningHub 及现有模型注册与计费链路；
- 用户已有媒体、3D 文件和项目数据。

上述能力不得依据本文件旧标题迁出、删除或从发布产物排除。

## 4. 性能方向

性能优化必须同时满足：高性能设备保持完整功能、最终质量和正常并发；低性能设备只在真实测量证明有必要时减少空闲刷新、隐藏预览或同时加载的非活动资源。

当前已经确认的基础包括：创作面板和 3D 组件按需加载，面板关闭后卸载，Three.js 资源在卸载时释放。后续若优化 3D 空闲渲染、媒体任务启动或预览资源，必须另写性能 TDD，先锁定功能与最终质量不退化。
