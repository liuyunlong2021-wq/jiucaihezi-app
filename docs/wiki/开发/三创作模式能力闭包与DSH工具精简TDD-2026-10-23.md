# 三创作模式能力闭包与 DSH 工具精简 TDD

> 日期：2026-10-23。
> 状态：**已按用户“执行 TDD”实施，仓库自动回归及桌面快速构建通过，尚未发布。** 原生 GUI、真实创作性能、Windows/Intel Mac 和正式历史升级仍待实机验收。
> 用户要求：选中漫剧制作、短剧写作或小说创作后，只使用该路线 Skill 群所需的功能，其他能力退出当前任务；目标是增速与稳定。
> 实施方向：复用当前 DSH，通过现有 Agent 作用域收窄能力；本期不换回 `1001-shoujiweb` Runtime，不深拆官方执行核心。

## 1. 根因与本次变更

现有 [[三创作入口删除自建路由与DSH官方Skill范围接入TDD-2026-10-22]] 明确规定“按钮只限定 Skill 集合，其他工具保持”。当前实现对应这份旧合同：

1. `production-skills.mjs` 检查 Skill 名称和来源；没有约束模型工具表、通用文件读取或共享归档类型。
2. `runner.mjs` 默认启动官方 `sdk` profile，继承 `dsh-base` 的终端、子代理、目标、后台作业、Web 和 workflow 等工具。
3. 影音、Office、3D、MCP 由独立芯片控制，电脑操控由设置控制；创作按钮不撤销这些能力在本轮的暴露。
4. `wiki_save_artifact` 枚举共享合同全部 36 种类型，没有按创作路线检查。

本合同将**三个创作按钮的含义**升级为“当前任务完整能力范围”。保留旧合同中的删除纯路由、禁止每轮强制调用、官方渐进加载、持久会话与历史兼容；替代其中“三个按钮只限制 Skill、其他工具照常加入当前任务”的条款。旧文档的实施证据保留。

### 1.1 已取得的隔离证据

使用随包 DSH `0.2.1-rc.2`、真实 SDK、本地 HTTP 模型替身与临时项目，无生产调用或付费媒体：

| --- | --- |

| 漫剧 `skill(name="jc-novel")` | 被拒绝 |
| 漫剧普通 `read` 读取 `jc-novel/SKILL.md` | 成功，说明 Skill 加载白名单没有覆盖资源读取通道 |

## 3. 一份消息范围贯穿全部链路

### 3.1 保留路线身份，避免单选绕过

当前 `productionMode()` 在模式内点选业务 Skill 后返回 `skills:<名称>`，因此仅判断值是否为 `manju/short-drama/novel` 会丢失按钮路线。

沿现有 Inbox `source` 增加兼容旧记录的可选 `productionRoute` 字段，值为 `none/manju/short-drama/novel`；新版发送必须写入明确值。已有 `productionMode` 继续表达完整群或单选/多选名称范围，不另建目录、消息库或任务配置数据库。

- `productionRoute=manju` + `productionMode=manju`：漫剧群与最小工具。
- `productionRoute=manju` + `productionMode=skills:jc-juese-sheji`：该单 Skill 与同一漫剧工具/资源/归档边界。
- `productionRoute=none` + `productionMode=skills:<个人Skill>`：现有普通单选行为，不按名称猜成创作模式。
- 发送时校验路线和名称集合一致；伪造矛盾元数据、群外名称或未知值在执行前失败，不降级成普通模式。

前端主发送、运行中排队、编辑重发、远程发送、runner、SDK Server、官方 Inbox、恢复和当前 Agent 使用同一份发送快照。不得执行时再读后来切换的按钮或全局芯片。

复用现有 `session/production-scope` 握手并提升范围版本；只支持旧 Skill 白名单的运行时不能声称支持完整能力收口。创作发送在握手不兼容时明确失败并提示重新连接/升级，不降级发送；新协议的目录、执行和资源边界必须一起生效。

### 3.2 UI 与有效工具保持一致

进入三个模式时，清除本轮已选影音/Office/3D/MCP 芯片；模式内这些入口不可启用，提示先退出当前创作模式。文件、图片和项目引用继续保留。电脑操控全局设置不被改写，但在当前创作 Agent 中无效，设置展示应说明这一点。

后端同样按消息范围约束，不能只靠 UI 清除芯片。旧历史里的芯片不能重新扩大新一轮能力。退出模式不自动重开先前芯片或重放旧调用；普通功能入口仍可使用，用户明确保存的电脑设置保留。

切换按钮在下一条消息/下一轮安全边界生效，不改变正在执行步骤的工具集。不同路线即使单选同一个共享 Skill，也不能强行 steer 进当前步骤；沿官方队列处理。

### 3.3 历史与冷恢复

保留 Session 身份、已受理消息 ID、完整历史、文件、交付与未完成状态。旧 source 为明确 `manju/short-drama/novel` 时可等价恢复路线；不解析正文中的旧 `/name`，不凭 Skill 名字猜路线。

旧待办仅有 `skills:<名称>`、且所属会话仍标记创作模式而无法找回发送时路线时，保留原待办并报告“创作范围缺失”，明确路线后续原待办；不得扩大成普通能力自动运行。普通单选会话保持原行为。历史消息只用于阅读，不重放为新调用；不删改历史中的工具正文来制造隔离通过。

## 4. 工具、资源和归档三个执行边界

### 4.1 工具目录与执行

扩展现有 `production-skills.mjs` 的 Agent 状态来拥有当前路线的工具范围和释放句柄；工具常量只维护一份。实测发现官方循环先组装工具快照、后发出 `agent/pre-step`，因此准备脚本在快照之前调用 `prepareProductionStep`；保留官方 claim/assemble/请求/执行过程，仅提前准备范围，避免模型仍收到上一范围的工具。保留官方 SkillRegistry、工具注册表、装载、Agent 循环与 SDK 生命周期。

优先使用官方 `agent.ctx` 下的 `tools.restrict({ allow })` 限制继承工具。**该 API 不过滤本 Agent 自己注册的工具**：原生 Wiki/present 是允许项；其他直属注册必须在其挂载点受同一路线约束，不能仅靠一个 allow 掩码宣称全部隔离。

再复用官方工具执行 guard，拒绝不属于允许集合的直接调用和程序化调用；guard 不代替真实请求里的 schema 收缩。检查迟注册插件、名字冲突与后续 MCP 工具变化；不复制官方工具注册表或添加独立的 schema 伪装目录。

关闭能力也不应继续注入鼓励使用它的当前工具指导。通用模型身份、权限与历史事实保留，本期不新增 persona，不迁回旧业务总路由。

隐藏 goal 工具还不足以关闭已有 goal 的自动续轮：同一范围须约束官方 goal-round-driver 的续轮入口，创作 Agent 不自动产生 goal 消息。没有公开的按 Agent 门槛时，允许在准备脚本中加最小、幂等的范围判定，继续委托官方驱动；普通会话行为不变。已有 goal 待办保留为暂停执行状态，不自动续作、不丢弃或擅自标记完成。

共享 Runtime 下不为一个创作会话全局卸载其他会话正在使用的插件，不因切换按钮重启工作区。独立创作任务不得主动启动无关 MCP/电脑提供方；已有共享实例不能因此获得本会话调用权。删除全局依赖包或更换官方 profile 不在本期实施范围。

`runtimeKey` 目前包含芯片与电脑设置；进入模式清除有效芯片时，不能据此强制换掉已有 Runtime。同模型/provider/协议及基础配置兼容时复用已有进程，以 Agent 范围屏蔽其额外能力；冷启动按最小需求装载。普通任务后来需要尚未装载的插件时，仍按既有忙时保护处理，不改当前创作步骤。真实测试须覆盖“已开启额外能力的普通会话 + 同工作区创作会话”，不能只测空进程。

### 4.2 Skill 资源读取

保留官方名称/来源检查，并对实际可读 Skill 资源范围收口：

1. 群内内置 Skill 的实际包目录及其包内文件；模式内单选时仍允许当前路线群内真实交接所需的包内参考，不自动加载其他正文。
2. 原生 Wiki 规则与归档合同等明确共享资源。
3. 当前项目素材、索引、作品与显式引用附件，沿原权限读取；其他路线已保存的作品可作为输入，例如漫剧读取小说原文或已写短剧，不等同于加载其 Skill。

对已发现的系统、个人、项目 Skill 根目录，群外 Skill 正文和资源不得经 `read/read_image/glob/grep` 旁路获取。群内 Skill 包只读，不在创作模式改写 Skill。本期不构建全机文件 ACL 或按小说内容识别文件的语义防火墙。

使用实际 provider 根目录和现有文件系统解析，统一处理绝对/相对路径、`..`、符号链接、Windows 分隔符与大小写；不只匹配路径字符串前缀。`grep` 读取内容前就过滤禁止目录，`glob` 不泄漏群外 Skill 文件条目。不得通过放开整个 skills 父目录来解决一个包内参考失败。

写入仍保留原来的项目授权、先读后改与版本校验。普通 `write/edit` 用于记录和明确文件修订；正式创作产物遵守共享归档合同。本期不承诺通用文件工具能够判断一段文本属于什么体裁，也不删除已加载历史或阻断跨路线作品复用。

### 4.3 归档类型与字段

继续使用 `wiki-artifacts.json` 唯一合同，在每种类型上增加允许路线元数据；不复制出三个归档实现。SDK 根据当前路线生成 enum/字段，并在 `execute` 前再次验证，不信任模型传来的路线参数。普通模式保留全部现有类型。

路线切换在 pre-step 安全边界更新本 Agent 的归档 schema 与资源范围：先释放自己上一份注册句柄，再挂载新的定义，不重复注册同名工具、不替换整个 Runtime，也不影响其他会话。执行端以本条消息已冻结的范围验证。

| 范围 | 允许的 artifact_kind |
| --- | --- |
| 三路线共享 | `source_material`、`production_progress` |
| 漫剧/短剧共享资料 | `story_summary`、`episode_summaries`、`story_background`、`world_rules`、`character_bio`、`scene_research`、`prop_research`、`event_timeline`、`research_coverage`、`project_overview` |
| 漫剧制作 | 以上共享项，加 `engineering_script`、`video_prompt`、`storyboard_prompt`、`character_voice`、`sound_direction`、`character_asset`、`scene_asset`、`prop_asset` |
| 短剧写作 | 以上共享项，加 `screenplay`、`adaptation_episode_plan` |
| 小说创作 | 三路线共享项，加 `novel_idea`、`novel_market_analysis`、`novel_core_premise`、`novel_world_setting`、`novel_outline`、`novel_chapter_outline`、`novel_foreshadow`、`novel_packaging`、`novel_manuscript_review`、`novel_character`、`novel_scene`、`novel_prop`、`novel_chapter_draft`、`novel_chapter_source` |

当前集合对应漫剧 20、短剧 14、小说 16 种；36 个现有类型全部有明确归属，不因类型前缀自动放行未来新增项。`source_material` 保留粘贴来源按原消息截取，不把小说章节确认追加改走该类型；文件/附件导入和手动故事拆分保留。

漫剧/短剧不暴露小说专用 `chapter_number/chapter_title/user_confirmed`；小说不暴露只服务分集影音的字段。`work_name` 还用于共享来源，不能因隐藏小说章节字段一并删除。其余字段依现有类型合同保留，项目总纲仍先读后完整 update，不能用精简覆盖其他路线已有章节。

小说必须继续验证确认对象、草稿存在、正文一致、来源不重复和回执警告；归档可见范围不增加确认授权。归档失败、索引部分失败和取消均不得谎报完成或重提媒体任务。

## 10. 并发审计修复（2026-10-24）

用户要求立即修复并发审计确认的两项 P1 和一项 P2。先将审计复现加入正式回归，再实施根因修复；本节不改写第 9 节初次实施的历史测试数。

1. **P1：当前目录与守卫解析基准不一致。** 普通模式 `working_directory` 改目录后，官方文件工具按当前目录解析相对路径，原守卫却按 Session 初始目录检查。现守卫复用官方 `workingDirectory.ensure`，资源根同时覆盖初始与当前项目；项目内及项目外的群外 Skill 相对路径 read/write/glob 实测均被拒绝，原文件不变。
2. **P1：准备失败丢失已接收的输入。** 官方 Inbox 已 claim 后新增准备/组装校验抛错，原消息既不在待办，也未进入用户历史。现仅在准备或组装失败、且没有显式取消时，使用官方 Inbox splice 将 claimed 输入按原 target、次序、ID 和 source 恢复；不唤醒自动重试。准备失败和组装失败分别验证：零模型请求、原 ID 留在待办、冷恢复保留，修复配置后原 ID 只进入用户历史一次。
3. **P2：旧别名把普通单选误识别为整条路线。** 新发送只从 `production:*` 提取路线；旧 `jc-*` 别名只由既有历史恢复函数迁移。普通选择保存显式关闭的路线偏好，重新打开/编辑时不再把同名 Skill 当作旧按钮。普通 `jc-novel` 与个人 `jc-duanju` 可各自加载正文，Office/MCP 保留；未选择时仍隐藏已退役的内置纯路由，严格创作群也不能加载它们。
