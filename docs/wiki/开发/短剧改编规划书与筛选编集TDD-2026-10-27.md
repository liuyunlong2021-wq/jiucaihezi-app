# 短剧改编：规划书与筛选编集TDD

> 2026-10-27。状态：**用户已确认，源码已实施，自动化回归通过；真实规划与剧本效果未验**（见第7节）。取代 [[开发/短剧改编逐章切分与逐集改编升级TDD-2026-10-24]] 中“整章全覆盖、不跨章拼集”的规则；行号切分（[[开发/短剧改编行号切集与章节范围TDD-2026-10-27]]）在此基础上扩展为多段。

## 0. 用户口径

- 目标：发一部小说，最终拿到**每一集都是“开头—冲突/爽点—钩子”的剧本**。
- 规划是第一步，也是最重要的一步。小说常常又臭又长，设定介绍占大篇幅，这些不需要。
- 每集最好冲突和爽点都有，至少有一项。开头立刻呈现冲突或爽点，结尾留钩子吸引看下一集。手机竖屏决定了这个节奏。
- 改编规则（用户同意）：可以删减、压缩、跨章组成一集，允许倒叙开场；不编造事件、能力和结果，不改因果。
- 主题先行：故事都是那些故事，脱颖而出靠主题赋予的气质（如“莫欺少年穷”），但主题不能说教，要隐含在角色性格里。
- 人物取长补短：原作者想象力强、人物塑造弱，改编时赋予每个角色性格。可以用本我、自我、超我的相互转化来写人物；成长经历决定说话办事的逻辑；台词意思不变，性格不同，表达方式就不同。
- 规划完成后先停下来给用户审，审过再切原文、写剧本。

## 1. 用户要审的内容：改编规划书

规划书由两份文件组成：`改编方案/项目总纲.md`（整体）和分集规划（逐集）。用户只需要读这两份。用户提出的四项为1、5、6、2；其余为补充。

### 项目总纲

1. **主题**：一句话（如“莫欺少年穷”），以及它分别落在哪些人物的性格和选择上。不写成口号，不让人物说教。
2. **卖点发动机**（补充）：
   - 爽点发动机：观众追着看的那件事，如塔防里“新种子进化出新功能”，相当于钢铁侠的新装备。
   - 冲突发动机：如生存压力、兽灾。
   - 两者怎么互相推动：为了活下去，才必须进化出新的防御。
   - 爽点升级路线：能力、装备、阵地按集数怎么一级级变强。
   - 对手阶梯：敌人和威胁按集数怎么一级级变强。
3. **人物**：每个主要角色写——
   - 成长经历，以及它决定的说话办事逻辑；
   - 本我（想要什么）、超我（觉得应该怎样）、自我（实际怎么做），以及三者在哪些集发生转化；
   - 说话方式卡（补充）：句子长短、语气、口头禅、对上级和对下属分别怎么说；
   - 人物弧光（补充）：起点、终点和关键转变发生在第几集；
   - 取长补短：原作哪里扁平、怎么补。只补性格和表达，不改事件。
4. **必要设定清单**（补充）：观众必须知道的最少规则。每条写明在第几集、用什么画面或哪句台词带出，不单独成戏。
5. **大结构**：篇章表，比如“第1–10集：对抗兽灾”。每篇写篇章目标、核心冲突、篇章高潮、结尾转折。

### 分集规划

6. **分集表**：每集一行——集号｜这集讲什么（一句话）｜冲突｜爽点｜开头（前15秒呈现什么）｜钩子｜原文出处（章节和行号，可以多段，倒叙片段单独标注）｜预估时长。
7. **删减清单**（补充）：删掉或压缩了哪些原文（章节和行号）、属于什么类型（设定、过渡、日常、支线、重复）、为什么删。
8. **倒叙开场说明**（补充，用到时才写）：哪一集把哪段后面的高潮提前到开头，以及正片在哪一集回到这里。

## 2. 规划方法（模型怎么做出规划书）

1. **卖点分析**（全书做一次）：通读梗概和前几章，写出总纲第1–4项。
2. **事件筛选**（每批章节做一次，如每批100章）：把原文拆成事件，每个事件标出行号、类型（冲突、爽点、设定、过渡、日常、支线）和强度，决定保留、压缩还是删除。设定和水文默认删除，写进删减清单；确实需要的设定挂到用到它的那场戏。
3. **编集**：保留的事件按原文顺序组成集，每集三段：
   - 开头：前15秒直接出现冲突或爽点，不铺垫背景；
   - 中段：冲突和爽点至少一项，最好互相推动；
   - 钩子：卡在“问题已经抛出、答案还没给”的位置。
   一集里冲突和爽点都没有，就并入相邻集或删掉。第1集直接进入核心冲突，或者亮出爽点发动机；必要时用倒叙开场。每集不超过3分钟。
4. **划篇章**：按篇章目标和高潮把集分组，写出大结构。
5. **暂停审阅**：保存规划书后停下来，向用户汇报总纲要点和分集表，等用户确认或修改。

## 3. 改编规则（更新）

- **可以**：删减、压缩、跨章把相邻章节的事件组成一集；倒叙开场；把设定化成画面或一句台词随用随给；补强人物性格和表达方式。
- **不可以**：编造原作没有的事件、能力、胜负、关系；改变因果；改变台词的意思和信息差。
- 除倒叙片段外，原文按顺序呈现，集与集之间不重复使用同一段原文。

## 4. 程序改动

| 改动 | 现状 | 改为 |
| --- | --- | --- |
| 切分 | 一集只能取一章内一段连续原文 | 一集由多段组成：`segments:[{source_path, chapter_heading, start_line, end_line, flashback?}]`，可以跨章；程序按段截取原文、拼接，并在每段前标注出处 |
| 顺序与重复 | 同章各集必须首尾相接 | 全部非倒叙片段按原文顺序递增，集与集之间不重叠；倒叙片段（`flashback:true`）可以引用后文，也可以和正片重叠 |
| 覆盖 | 每个目标章节的原文必须全部切完，否则拒绝 | 不再要求全覆盖；程序算出目标章节中没被使用的行号范围，写进进度文件的`unused`，供用户和删减清单对照 |
| 规划所在阶段 | 分集规划在cuts阶段保存 | 移到scheme阶段：scheme必须登记项目总纲和分集规划；cuts只登记切分 |
| 审阅暂停 | 流水线没完成就自动催促继续，只有blocked会停 | scheme阶段允许`status:"review"`并写明原因；自动续跑遇到review就停，等用户回复；用户在消息中明确不用审时可以直接继续 |
| 分集规划路径 | 新库为`改编方案/逐章规划.md` | 新库改回`改编方案/分集规划.md`（名称和内容一致）；已有的`逐章规划.md`继续原位使用 |

切分记录保存每段的来源、章节、行号和字符位置；校验时逐段重新截取比对，原文改动后仍会拒绝。
