# KIK 视频提交超时与远程结果链接 TDD

> 状态：已实施并通过自动验证；生产 KIK 与复制粘贴人工验收待执行
> 日期：2026-08-16
> 范围：KIK Seedance 适配器、Desktop/Web 创作任务历史

## 1. 目标

1. KIK 上游提交任务 ID 偶发慢于 60 秒时，Desktop 不得先中断与网关的请求并显示“网站连接失败”。
2. 成功但未保存到项目、且持有安全远程结果 URL 的任务，用户可在任务历史一键复制链接。
3. 每一条可复现的创作任务，无论成功或失败，用户均可从任务历史选择 `重新生成`。

不修改 NewAPI 渠道 `111`、KIK Key、模型映射、Nginx 或任务轮询协议；不增加下载、缓存、自动重试或第二套任务状态。

## 2. 已确认根因

2026-08-16 `21:06:20` 左右，App 的 `POST /v1/videos` 已进入 NewAPI；NewAPI 正确命中渠道 `111` 和 KIK 适配器。适配器调用 KIK 上游等待 60 秒后将 `httpx` 异常统一包装为 `502 KIK video service is unavailable`；NewAPI 在 `63.6` 秒后记录该 502。

Desktop 的 Rust HTTP 桥对 `POST /v1/videos` 同样只有 60 秒总超时，因而在 NewAPI 返回前主动断开；Nginx 记录 `499`，App 只看到 `error sending request for url (https://api.jiucaihezi.studio/v1/videos)`。这不是 App 未到达网站、NewAPI 未命中渠道或适配器容器不健康；现有适配器健康检查正常。当前适配器没有记录原始 `httpx` 异常类型，无法从生产日志区分读取超时、连接超时或 TLS 错误。

任务记录为空符合该链路：KIK 尚未返回任务 ID，NewAPI 没有可持久化的异步任务。

实施后审计又发现两个根因：`httpx.Timeout(120)` 只是连接、读、写等阶段时限，不是严格总时限，若 Desktop 也使用 120 秒仍会重现客户端先断开的竞态；适配器还把缺失的图片、视频或音频回退为空数组并交给必填校验，导致纯文字及单一参考类型在进入上游前错误返回 400。本 TDD 的最终合同已同时修正这两点。

## 3. 设计决断

### 3.1 KIK 仅延长提交等待，不自动重试

- KIK 适配器以标准库 `asyncio.timeout()` 将提交严格限制为 `120` 秒总时限；`httpx` 各阶段超时为 `120` 秒，连接超时仍为 `10` 秒。
- Desktop `safeFetch` 对 `POST /v1/videos` 的 Rust 总超时由 `60` 秒调整为 `150` 秒，为适配器、NewAPI 和 Nginx 返回留出 30 秒余量；Web 已有 300 秒 AbortSignal，不修改。
- 适配器捕获 `httpx.HTTPError` 时只向容器日志记录异常类型和耗时，不记录 Key、Authorization、提示词、参考图 URL 或请求体；返回给 NewAPI 的错误格式保持现有 `502` 合同。
- 不自动重试 KIK 提交。超时前上游可能已经受理并创建任务，重复提交可能重复扣费；用户仍使用既有“重新生成”显式动作。
- 不改 Nginx。现有 Nginx 已允许请求超过 60 秒到达 NewAPI；`499` 是 Desktop 客户端先取消的结果，不是反向代理超时。

### 3.2 任务历史仅增加复制远程链接入口

- 在 `CreationPanel` 的任务历史中，仅当任务成功、没有 `assetUri` / `projectPath` 且 `resultUrl` 通过 `isSafePublicHttpUrl()` 时显示 `复制链接`；`data:`、本机和内网地址不属于远程结果链接。
- 点击复用共享 `writeClipboardText()`，兼容 Desktop Tauri 原生剪贴板、浏览器 Clipboard API 和既有降级路径；复制成功或失败只显示短暂当前面板提示。
- 该动作不下载结果、不请求上游、不读项目文件、不创建 Blob URL，也不改变任务或媒体资产状态。
- 已保存到项目的任务继续使用预览、放到画布和打开文件夹；媒体预览器既有 `复制 URL` 能力保持不变，不重复建设另一套复制实现。

### 3.3 重新生成不再只限失败任务

- `重新生成` 仅对创作来源、状态为成功或失败且存在 `planSnapshot` 的任务显示；排队中、生成中和已取消任务不显示，成功任务与失败任务共用已有 `regenerateTask()`。
- 点击只回填原任务的任务类型、模型、提示词和已保存参数，关闭历史弹层；不自动提交、不复制已生成文件、不重新下载结果。
- 参考素材仍遵守既有安全边界：历史计划只恢复参数，用户重新选择当前项目中的参考素材后再明确点击生成。
- 早期历史任务若没有 `planSnapshot`，无法准确复现，按钮不显示；不猜测旧模型、参数或参考图。

## 4. TDD 验收

### 红灯测试

1. KIK 适配器模拟 `httpx.ReadTimeout`：现有实现只输出笼统 502，日志没有异常类别与耗时。
2. Desktop HTTP 超时合同：`POST /v1/videos` 当前解析为 60 秒，慢于 60 秒的 KIK 提交会先取消。
3. 任务历史合同：成功、未保存且有安全 `resultUrl` 的任务没有 `复制链接` 入口；不安全 URL 或已保存任务不得显示。
4. 任务历史合同：成功任务因 `task.status === 'failed'` 不显示 `重新生成`；没有 `planSnapshot` 的历史任务不得被猜测性回填。
5. KIK 输入合同：纯文字及只有图片、视频或音频任一参考类型的请求，当前会因其他缺失类型的空数组被错误拒绝。

### 绿灯测试

1. KIK 提交使用严格 120 秒总时限、120 秒阶段超时和 10 秒连接超时；`ReadTimeout` / 总时限耗尽保持 502 响应合同并产生不含敏感内容的诊断日志。
2. Desktop `POST /v1/videos` 使用 150 秒外层总时限；模型探测、轮询和其他 HTTP URL 的现有超时不改变。
3. 任务历史按钮调用 `writeClipboardText(task.resultUrl)`；安全远程任务显示，已保存或不安全 URL 隐藏；点击不触发下载、保存或重新生成。
4. 成功和失败的创作任务只要有 `planSnapshot` 都显示 `重新生成`，排队中、生成中、已取消及没有快照的旧任务隐藏，点击不自动提交。
5. KIK 纯文字、仅图片、仅视频、仅音频和多模态请求均只转发实际存在的参考素材；缺失的可选类型不得触发 400。

### 真实验收

1. 部署新版 KIK 适配器后，用带参考图的 KIK 任务验证：提交在 60-120 秒内返回任务 ID 时，App 不再出现 `499` / `error sending request`，随后按既有轮询完成。
2. 人为或真实上游超时后，容器日志可见异常类别与耗时，NewAPI 仍返回现有 502，不泄漏密钥或请求内容。
3. 对一个只返回第三方 MP4 URL 且保存失败的成功任务，任务历史点击 `复制链接` 后可直接粘贴到浏览器；不产生项目副本或额外网络请求。
4. 对一条已成功并保存到项目的任务点击 `重新生成`，面板回填原模型、提示词和参数；用户重新选择参考素材并显式确认后才创建新任务。

## 5. 禁入边界

- 不把 150 秒应用到全部 API、图片、音频或轮询请求。
- 不把 KIK 提交改为客户端轮询前的后台队列；只有收到 KIK 任务 ID 后才进入现有 NewAPI 异步任务链路。
- 不显示或复制本地绝对路径、`jc-media:`、`blob:`、`file:`、内网地址或未通过 URL 安全校验的值。
- 不把“复制链接”添加到文件树，不生成缩略图，不改已有文件名。
- 不让重新生成绕过付费确认、参考素材选择或当前项目归属校验。
