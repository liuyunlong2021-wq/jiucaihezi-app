# 通用记忆工作台对话记忆索引正确链路设计

> 日期：2026-09-01  
> 状态：V2 代码已实施，待真实模型与跨端验收  
> 范围：当前对话单条 assistant 输出的索引创建与精准查询  
> 历史实现：[[通用记忆工作台对话记忆索引按钮TDD-2026-09-01]]

## 1. 目标

用户点击某条 assistant 回答后的“写入索引”后，只处理这条回答：模型生成简介和关键词，程序生成指向该回答的 Raw 正链，并写入当前 conversation 的固定索引文件。

后续选择 `jc-jiyi` Skill 时，查询先匹配索引，再沿命中的正链读取对应 assistant 输出。

```text
Raw 对话记录 = 完整正文唯一事实源
对话记忆索引 = 简介、关键词与正链组成的导航
jc-jiyi Skill = 使用索引精准取得原始回答的方法
```

## 2. 设计原则

1. 当前 assistant 输出是索引模型的唯一正文输入对象。
2. index 只负责导航，Raw 继续保存完整正文。
3. 正链中的 Raw 路径和 assistant turn 锚点是唯一定位依据。
4. 写入时不读取或解析 Raw，不扫描项目文件和索引目录。
5. 查询时由 conversation ID 计算固定索引路径，只读取该索引。
6. 先用简介和关键词确定命中，再读取命中正链对应的 Raw；未命中时不读 Raw。
7. 时间、轮次顺序和 `userTurnId` 不参与索引定位、匹配或返回。

“正链直接读取”指先由链接确定唯一 Raw 文件和 assistant turn，再从 Markdown 中提取该 turn。当前文件服务没有字节范围读取能力时，底层仍可读取该 Raw 文件全文，但不会扫描目录、猜测文件或解析其它对话。

## 3. 正确写入链路

```text
用户点击某条回答的“写入索引”
  -> UI 直接提供 conversationId、assistantTurnId、assistantContent
  -> 一次模型请求，只生成 summary + keywords
  -> 程序校验 summary + keywords
  -> 程序由 conversationId 和 assistantTurnId 生成固定索引路径与 Raw 正链
  -> 直接创建或更新 .raw/记忆索引/<conversation-id>.md
  -> 返回成功或真实失败状态
```

模型输入：

```json
{
  "assistantContent": "当前这条 assistant 的完整输出"
}
```

模型输出：

```json
{
  "summary": "这条回答确定了对话记忆索引的最小实现方式。",
  "keywords": ["记忆索引", "Skill", "正链"]
}
```

conversation ID、assistant turn ID、Raw 路径和 Markdown 格式全部由程序从当前 UI 状态生成，模型不生成这些可信字段。

索引文件已存在时，程序可按固定路径读取一次现有索引，以完成幂等更新和乐观 revision 写入；这不是目录扫描，也不读取 Raw。幂等键直接使用正链中的 assistant turn 锚点。

写入性能目标：

```text
一次模型请求 + 一次固定路径索引更新
```

## 4. 索引格式

每个 conversation 只有一个固定索引文件：

```text
.raw/记忆索引/<conversation-id>.md
```

V2 格式：

```md
# 对话记忆索引

<!-- jc:conversation-memory-index conversation-id="conversation-xxx" source="../对话记录/conversation-xxx.md" version="2" -->

- 简介：确定了对话记忆索引的最小实现方式。
  - 关键词：记忆索引、Skill、正链
  - 正链：[查看这条回答](../对话记录/conversation-xxx.md#jc-turn-a124)
```

文件级 `conversation-id`、`source` 和 `version` 用于身份校验与格式迁移。单条记录只保留简介、关键词和正链；assistant turn ID 已包含在正链锚点中，不再重复保存。

## 5. 正确查询链路

```text
jc-jiyi 收到当前 conversationId 和查询词
  -> 计算 .raw/记忆索引/<conversation-id>.md
  -> 读取这一个固定索引文件
  -> 只匹配简介和关键词
  -> 取得少量命中项的 Raw 路径与 assistant turn 锚点
  -> 读取命中的 Raw 文件并提取对应 assistant 输出
  -> 返回原始回答及可复查来源
```

查询性能目标：

```text
一次固定索引读取 + 命中后一次 Raw 读取
```

同一查询命中同一个 Raw 中的多条记录时，只读取一次该 Raw，再提取多个 assistant turn。没有索引或没有命中时返回空结果，不读取 Raw。

主返回结构：

```json
{
  "conversationId": "conversation-xxx",
  "matches": [
    {
      "summary": "索引中的简介",
      "keywords": ["记忆索引"],
      "rawPath": ".raw/对话记录/conversation-xxx.md",
      "assistantTurnId": "a124",
      "content": "对应的 assistant 原始输出"
    }
  ]
}
```

默认只返回 assistant 输出。后续任务确实需要问题背景时，可以沿 Raw 中相邻 turn 取得上下文，但 `userTurnId` 不成为索引必需字段，也不扩大默认查询结果。

## 6. 与 `jc-jiyi` Skill 的匹配关系

`jc-jiyi` 的能力保持为精准查询：它先理解本轮已选 Skill 所需资料，再调用 `conversation_memory_query`，把返回的原始回答交给其它 Skill 使用。

V2 只收缩它依赖的索引合同：

| 项目 | V1 当前实现 | V2 正确链路 |
| --- | --- | --- |
| 索引输入 | user + assistant | 当前 assistant 输出 |
| 单条字段 | 时间、简介、关键词、user/assistant ID | 简介、关键词、正链 |
| 匹配范围 | 索引与完整 Raw 正文 | 索引简介与关键词 |
| 默认返回 | user/assistant pair | assistant 原始输出 |
| 定位依据 | 多个重复元数据字段 | 正链中的 Raw 路径与 assistant 锚点 |

多 Skill 的加载和工作方式保持现状；本设计不增加编排协议。记忆查询结果就是其它 Skill 可直接使用的资料输入。

## 7. 当前实现差距

V2 已移除写入和查询的目录扫描；仍保留以下兼容边界：

- 旧 V1 索引仍允许兼容解析，新写入统一 V2。
- 当前 Markdown 文件服务按文件读取全文后按 assistant 锚点提取；底层尚未提供字节范围读取。
- 真实模型、Web/Desktop/Mobile 和编辑删除后的孤链场景仍需验收。

旧 TDD 保留为 V1 实施记录，不覆盖、不改写历史事实。

## 8. TDD 实施顺序

1. T1：先用测试固定 V2 的“简介 + 关键词 + 正链”格式，并覆盖旧 V1 读取或一次性兼容策略。
2. T2：写入接口直接接收当前 assistant 内容和身份；测试禁止写前 Raw 读取与项目目录扫描。
3. T3：查询按固定索引路径读取；先匹配索引，命中后按正链提取 assistant turn；测试空命中不读 Raw。
4. T4：同步更新 `jc-jiyi` 合同，覆盖成功、失败、重复点击和回答被编辑或删除后的孤链行为。
5. T5：记录真实模型与 Web/Desktop/Mobile 验收耗时；自动测试不替代真实平台验收。

## 9. 明确不做

- 后台自动索引、全量重建或索引编辑器。
- 向量库、Embedding、独立数据库或复杂缓存。
- 为进度 UI 伪造百分比。
- 扫描其它 conversation 或跨项目搜索。
- 在索引中复制 assistant 正文。
- 新增多 Skill 编排协议。
