# 桌面安装包 R2 分发合同

> 日期：2026-10-22。状态：源码与回归完成，R2 基础设施和专用凭据已准备；用户决定随下次更新一并发布，本次不切换现有下载链路。

## 1. 决策与范围

桌面安装包接入现有 R2 基础设施，通过专用下载域名及 CDN 分发，大文件不再由 API 服务器承担持续传输。复用现有 R2 账号与发布能力，不新增通用下载代理或存储抽象。具体桶、域名与缓存配置在实施前核对现有部署后确定，不将尚未配置的地址写成已上线。

覆盖 macOS Apple Silicon、macOS Intel、Windows 的现行正式发布资产：DMG、Windows 安装器与便携 ZIP、官方自动更新包、对应签名及 SHA-256 校验文件。保留 GitHub Release、签名、公证、原生启动和官方升级检查，不削减桌面或任何现行发布平台能力。

安装包是公开、按版本长期保留的发布资产，与私有临时创作素材隔离访问权限、对象目录和生命周期。复用 R2 不等于开放现有私有素材桶；不得套用临时素材的上传大小限制、短期签名或自动过期清理。优先使用独立发布桶；如复用既有发布桶，必须先核验权限与生命周期满足本合同。

## 2. 兼容与分发

- 保留现有 `https://api.jiucaihezi.studio/updates/{version}/{filename}` 地址，已迁移且校验通过的版本由服务端重定向到对应 R2 下载地址，文件名和版本映射保持一致。兼容官网、旧版 App 与官方自动更新客户端；重定向方式须经真实客户端验证。
- `latest.json` 与 `updater.json` 保持现有入口、字段结构、公钥及独立推广规则。安装包存储迁移不触发正式 OTA 推广，不改变用户升级渠道。
- 尚未复制并校验的历史文件继续由现有来源提供；逐版本迁移，未验证前不得统一重定向或删除源文件。
- 版本对象不可覆盖；同版本同文件名存在时比对长度与 SHA-256，相同才可复用，不同则停止发布。清单使用现有受控刷新规则，版本文件按不可变资产缓存。
- 下载域名必须提供 HTTPS、GET、HEAD、Range/206、正确文件总长及稳定 ETag/Last-Modified，验证 If-Range 和中断续传；缓存、重定向不得损坏二进制、签名或平台文件名。浏览器所需跨域响应按实际调用方式核验。

## 3. 发布与回滚

沿用当前三平台构建、最终签名及公证流程，上传的是最终发布字节：

```text
三平台最终资产与签名就绪
→ 计算长度和 SHA-256
→ 发布流程上传 R2 的固定版本对象
→ 通过公开下载域名完整取回并核对字节/摘要
→ 验证旧地址重定向、HEAD/Range 与客户端兼容
→ 原子推广官网下载清单
→ 官方 OTA 仍按既有独立门禁和授权推广
```

R2 上传凭据只留在现有 CI/服务端秘密配置中，不写入客户端、公开清单或日志。任一必需资产缺失、上传失败或校验失败，停止清单推广，保持上一可用版本。

切换前备份现行下载映射和清单，保留已验证源文件。失败时恢复上一可用清单及下载映射，不重建或覆盖签名包；源文件清理须等历史链接、三平台升级和回滚验收完成后另行记录。此次合同更新不执行数据删除。

## 4. 验收与证据

1. 发布流程先覆盖上传失败、缺文件、同名不同摘要、公开取回摘要不符及推广失败场景，确认失败不推广清单。
2. 对三平台全部现行发布资产完整取回，记录版本、文件名、长度与 SHA-256；校验签名、Mac 公证及原有发布门禁保持通过。
3. 分别验证官网直接下载、旧下载 URL、官方更新客户端下载与安装；Mac ARM、Intel、Windows 分项记录。CI 构建或单平台成功不能替代真实平台验收。
4. 实测 HEAD、Range/206、If-Range、中断续传、缓存刷新与回滚；确认大文件字节由 R2 分发，不经 API 服务器反向代理传输。
5. 在相同网络与时间窗口比较迁移前后首字节、平均速度、完整下载耗时和失败率，并记录国内实际用户网络结果。R2/CDN 接入不等于国内线路已加速，不承诺未经实测的速度或完成时间。

## 7. 2026-10-22 实施记录（持续更新）

### 源码与发布门禁

- `.github/workflows/build.yml`：复用发布任务与部署 SSH，新增 Windows 便携 ZIP；通过专用桶凭据从 CI 直传 R2。上传、S3 完整读回、公开域名完整 SHA-256 和续传检查依次成功，才安装旧 URL 精确重定向并推广官网清单。重定向检查或推广失败自动恢复此次 Nginx 配置；正式 OTA 门禁保持独立。
- `scripts/publish-r2-updates.py`：使用官方 boto3 S3 接口，固定账号与独立发布桶，完整资产/签名/摘要基线校验；`If-None-Match: *` 禁止覆盖，已存在对象必须完整读回并核对长度与 SHA-256。私有素材桶被明确拒绝。
- 历史 `SHA256SUMS` 保持字节不变；新增 `R2-SHA256SUMS` 覆盖所有发布资产、便携 ZIP 和历史摘要本身。不是改写历史签名包或原校验文件。
- `scripts/verify-online-updates.mjs`：覆盖 ZIP 与两份摘要，逐段完整 SHA-256、HEAD、强 ETag/Last-Modified、If-Range 匹配续传和不匹配整文件响应；旧地址必须精确 302 到对应 R2 对象。
- `scripts/configure-r2-downloads.py`：仅为已验证版本/文件增加精确 Nginx location；保留未迁移版本及清单路由，重定向 no-store、跨域头保留；配置检查/重载失败恢复备份，另提供本次切换回滚入口。
- 发布任务全局串行，避免并行修改映射；已有 tag 只选择资产，发布工具使用本次工作流源码。迁移验收完成前暂停该任务的源文件自动清理，R2 不自动删除版本。
