# 通用记忆工作台对话记忆索引摘要模型接口约束 TDD

> 日期：2026-09-03；修订：2026-09-16
> 状态：已实施，待真实失败模型验收
> 范围：点击“记录对话”后，当前 assistant 输出的索引摘要

## 1. 目标与根因

索引写入失败的根因不在 Wiki 文件，而在摘要请求把 JSON Schema、Ollama `format` 和 Opus 强制工具调用作为前置条件；部分模型或网关不支持或不遵守这些协议。

模型只负责产出可读文字，程序负责固定 `summary + keywords` 数据结构、长度、去重、索引路径与 Markdown。不要要求模型生成 JSON，也不为修 JSON 再发一次请求。

## 2. 请求合同

只发送当前待索引的 assistant 正文。所有 Provider 使用同一段 System Prompt：

```text
你是对话记忆索引器。
请只根据用户消息中的这条 assistant 回答生成可检索的对话记忆索引。
只输出两行纯文本：
简介：用中文写一条可独立理解的事实简介，概括这条回答确定了什么或解决了什么，1-2句，最多240个字符。
关键词：1-12个简洁关键词，用顿号分隔；关键词必须来自或明确概括这条回答中的主题、实体、路径、技术名词或决策，每个最多32个字符。
不要补充输入中没有的事实，不要写 Markdown、解释或代码围栏。
```

- 远程兼容接口：`/v1/chat/completions`，`stream:false`、`temperature:0.2`、`max_tokens:800`；不发送 `response_format`、`tools` 或 `tool_choice`。
- Ollama：继续走原生 `/api/chat`，`stream:false`、`think:false`、`temperature:0.2`、`num_predict:256`；不发送 `format`。

## 3. 程序合同

1. 只读取可见 `message.content`；推理字段和工具调用不是摘要正文。
2. 读取“简介：”与“关键词：”两行；模型只给普通简介时，该简介仍可写入。
3. 程序清洗换行、截断简介到 240 字、拆分/去重关键词并限制为 12 项和每项 32 字；关键词行缺失时，用简介片段和回答中的技术标识补齐。
4. `conversationId`、turn ID、Raw 路径、正链与 Markdown 均由程序生成；模型不能提供或覆盖。
5. 只有摘要文本可见且索引文件写入成功，才显示“已记录对话”。

## 4. 测试与验收

1. 远程、Opus 与 Ollama 请求均不携带结构化输出字段。
2. 两行文本、仅简介文本和 Ollama 原生 `message.content` 都能生成既有 `summary + keywords`。
3. 空正文、拒答与截断仍拒绝，且不会写入索引。
4. 索引格式、查询、正链和重复点击幂等更新保持不变。

本地自动验证完成后，仍需用本次失败的模型在 Desktop 重试“记录对话”；不把自动测试写成真实模型验收。
