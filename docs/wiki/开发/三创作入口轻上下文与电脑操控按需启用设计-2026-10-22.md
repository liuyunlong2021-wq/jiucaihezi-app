# 三创作入口 Skill 范围与电脑操作默认关闭设计

> 后续实施与验收统一进入 [[三创作入口删除自建路由与DSH官方Skill范围接入TDD-2026-10-22]]；本页保留设计来由，最终源码与验证以TDD§8为准。

> 2026-10-22，按用户最新澄清修订；状态：源码与本地自动化已完成；真实安装版/跨平台/生产模型未验收，未发布。
> 核心：遵循 DSH 官方使用 Skill 的规则，产品只决定当前可用的 Skill 集合。电脑操作保留设置开关，默认关闭，不新增 @电脑操控、不设置任务级自动开启。
> 本文取代本轮较早提出的“维护单份路由正文”和“@电脑操控为本次任务开启”建议。

## 1. 为什么改

改造前 App 将选中创作按钮映射为每轮自动追加 /jc-manju-zhizuo、/jc-duanju 或 /jc-novel。DSH 把每个 /name 视为本轮显式调用，因此重复展开正文并追加历史。同一真实会话已展开路由15次，累计138229字符。

另一个偏差在 prepare-deepseek-harness.mjs 的 applyPinnedSkillScope：识别选中 Skill 后执行 tools.restrict({deny:['skill']})，屏蔽官方加载器，导致业务子 Skill 主要靠路由文件中的链接读取。仅去掉斜杠而保留此限制，会让渐进加载失效；仅解除限制而不收窄目录，则会把范围外个人/项目 Skill 暴露给模型。

## 2. 用户入口与执行流程

漫剧制作、短剧写作、小说创作三个按钮继续互斥，作为当前会话的 Skill 范围选择。选择按钮不自动执行任务、不生成文件、不调用一个路由 Skill，也不增加一次分类模型请求。

执行链：选择创作范围 → DSH 发布该范围的 Skill 名称与用途目录 → Agent 结合用户需求和相关上下文选用 → 官方 skill 工具加载命中正文 → 按需读取其资源 → 处理当前任务 → 按现有合同归档或交付。

用户手动输入 /name 的官方显式调用语义保留，但按钮不再自动伪造这个调用。通过独立的结构化模式状态传递范围，不从提示词或历史关键词猜测。

## 3. 三个范围的内容

| 入口 | 目录内容 | 装载方式 |
| --- | --- | --- |
| 漫剧制作 | 现有14个业务 Skill 的名称与用途，排除纯路由 jc-manju-zhizuo | DSH 按任务调用 skill；必要参考文件随后读取 |
| 短剧写作 | 项目资料、策划、分集、正文等实际业务 Skill，纯路由不自动加载 | 同上；保留原创、改编、续写、修改及现有制作规则 |
| 小说创作 | 当前真实存在的小说业务 Skill 名称与用途 | jc-novel 含有实际创作方法，命中后正常加载，不把100个参考引擎伪装成100个独立 Skill |

目录基于官方 SkillSummary 的 description/whenToUse 表达用途和触发场景，不另写关键词分类器，也不根据名称相似扩展到范围外。包内资源依赖与通用文件读取继续可用。

产品范围须同时约束官方目录发布和 skill 工具的名称解析。只在提示词中要求“不要用其他 Skill”不算实现范围；注册一个更高优先级 provider 也不自动排除其他 provider 的目录。当前同版本没有现成 skills.restrict API，实施须先用现有 scoped provider/consumer 接口测试可行的最小边界，不臆造接口、不通过屏蔽 skill 工具代替范围限制、不复制整个官方加载器。

## 4. 纯路由直接退出

按用户最新澄清，删除纯路由及每轮自动调用，不迁移其附加规则。不得把旧路由内容搬进业务Skill、命中描述、系统提示、Wiki或另一层公共规则。现有业务Skill正文与资源保持原样，官方目录和加载器按所选集合工作。

## 5. 工具与电脑操作

Skill 是知识/流程，工具是执行能力，两者分开。默认保留官方 skill 加载器、必要文件/图片读取、原生 wiki_read_guidance、wiki_save_artifact、present 及现有桌面通用能力。不把“等必要工具”误解成仅剩 Wiki 和 present，否则无法读取 Skill、项目文件和参考图。没有新的授权，不顺手裁掉终端、子代理、MCP、画布等现有能力。

电脑操作完全沿用设置页开关：缺省关闭，用户手动开启后按开关状态使用；不开新的 @入口，不每轮弹窗，不在任务结束后自动改用户设置。默认关闭时，原生电脑提供方不装载，模型请求里不出现55个 cua_driver_native__工具。开关变化沿现有运行时交接生效，不中途粗暴杀掉正在运行的任务。

旧数据中缺少该键的用户必须关闭；明确保存的开启值仍视为用户选择并在设置页清楚显示。历史版本默认开启但未记录选择的状态，不能继续视为用户明确开启。系统权限与文件/终端权限继续按现有机制工作，开关不替代系统授权。

## 6. 上下文与官方运行机制

保持 DSH 的目录去重、Skill装载、Agent循环、上下文压缩、工具结果裁剪与图片卸载；本设计不再叠加一套自定义路由、模式记忆或按轮去重引擎。消除每轮自动 /name，是直接去掉重复注入的来源。

官方渐进加载不保证正文永远只读一次，也不保证长会话不会增长；实际任务需要重新加载、上下文压缩后重读、用户显式重调用都可能合法发生。不能为追求“15轮只出现一次”而改变官方语义。验收关注按钮不再制造15次强制调用、未命中的正文不预装、目录不无故重复。

用户完整对话、确认内容与项目数据保留。路由优化不代表两小时卡顿或本地估算结算已解决，超时/取消/结算仍按独立证据验收。
