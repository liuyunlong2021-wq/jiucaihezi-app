# 通用记忆工作台项目地图 SDD

> 日期：2026-08-02
> 状态：第一阶段已实施；自动验证和 Web 桌面/移动视口验收完成，三平台安装包矩阵待补
> 范围：通用记忆工作台 Web / Desktop 的标准 JSON Canvas 项目地图；不改旧主 Studio 创作画布内部协议，不修改内置 Wiki Skill。

## 1. 目标

把标准 `.canvas` 从只能交给 Obsidian 查看的 Wiki 关系图，升级为记忆工作台内连接整个项目的“项目地图”：

```text
项目地图 .canvas
  -> Markdown / Wiki 页面
  -> 普通文档与媒体
  -> 创作画布 .jccanvas
  -> 3D 白膜场景 .jcscene
```

项目地图只回答“项目里有什么、它们在哪里、彼此有什么已确认关系”。点击节点后，由现有项目资源路由打开对应阅读器或专用编辑器。它不是第四套内容编辑器，也不把不同文件强行合并成万能画布。

## 2. 统一产品模型

| 层级 | 文件或视图 | 责任 |
| --- | --- | --- |
| 事实层 | Markdown / Wiki | 项目身份、正文、事实和来源的唯一真源 |
| 文档层 | Markdown 正文、大纲、内嵌 Mermaid | 阅读单篇文档和定位章节 |
| 地图层 | 标准 `.canvas` | 跨页面、跨文件、跨产物的导航和关系视图 |
| 2D 生产层 | `.jccanvas` | 图片、视频、音频和生成结果的视觉编排 |
| 3D 生产层 | `.jcscene` | 人物、物体、机位、灯光和空间构图 |

项目地图统一的是入口、导航和基础空间交互，不统一上述文件的数据模型。相关边界继续以 [[开发/通用记忆工作台本地作品生成基础工具SDD]] 和 [[开发/通用记忆工作台3D白膜场景基础工具SDD]] 为准。

## 3. 文件与事实边界

1. 项目地图使用 Obsidian 兼容的标准 JSON Canvas，继续保留 `.canvas` 扩展名；不转换成 `.jccanvas`。
2. Markdown / Wiki 仍是唯一事实源。项目地图是可以从页面、双链和项目资源重新生成的派生视图，不进入 `wiki_search` 检索正文。
3. 地图节点可引用项目内 Markdown、文档、媒体、`.jccanvas` 和 `.jcscene`；第一阶段不嵌入这些文件的完整编辑器，只显示名称、类型和必要摘要。
4. 路径必须是当前项目内的规范相对路径。目标缺失时显示“文件已不存在”，不猜测替代文件或静默删除节点。
5. 兼容现有 Wiki Skill 生成的 `text` 节点与 `[[双链]]`，也支持标准 JSON Canvas `file` 节点；不要求先修改五个内置 Wiki Skill。

## 4. 地图内容

项目地图不是把整个项目的每个文件一次性铺满。默认只纳入：

- `CLAUDE.md` 中的稳定入口和核心 Wiki 页面。
- 用户明确要求查看关系的页面、实体和资料。
- 与当前任务直接相关的重要文档、媒体、创作画布和 3D 场景。
- 已有双链或确认关系连接到上述节点的必要页面。

没有稳定关系时不生成空地图。大型项目优先生成围绕当前主题的局部地图，不做自动全库毛线团。

## 5. 打开与导航

1. 文件树把 `.canvas` 识别为“项目地图”，与 `.jccanvas`“创作画布”使用不同资源类型和图标。
2. 点击 `.canvas` 后在记忆工作台中央区域按需加载项目地图，不跳出 App，不要求安装 Obsidian 插件。
3. 地图节点点击后复用现有 `openProjectResource()` 路由：Markdown 进入阅读器，媒体进入预览，`.jccanvas` 进入创作画布，`.jcscene` 进入 3D 白膜编辑器。
4. 从节点进入资源后保留一层返回位置，用户可返回原地图和原视口；再返回才回到对话。
5. 模型生成或更新地图后，对话只显示轻量“项目地图”结果卡和“打开地图”按钮，不在消息流运行空间渲染器。

## 6. 第一阶段交互

- 平移、缩放、适配全部节点。
- 显示文本节点、文件节点、分组、连线和关系标签。
- 点击节点打开项目资源。
- 拖动节点只修改 `x / y` 布局，并保存回原 `.canvas`。
- Wiki 工具或 Skill 增量更新地图时保留未涉及节点的位置，不全量重排用户布局。

第一阶段不提供手工创建、删除节点和连线，不直接编辑关系含义。事实或关系变化继续通过 Markdown、Wiki 工具或对话完成；直接拖动布局是用户明确操作，不经过模型工具审批。

## 7. 最小实现

1. 为标准 `.canvas` 增加独立的项目资源识别和安全解析，不复用 `.jccanvas` 的 `CanvasDocumentV3`。
2. 新增按需加载的轻量项目地图查看器，使用浏览器原生 DOM、SVG 和指针事件完成基础图元、连线、平移、缩放与拖动；不加载旧 `CreationPanel`，不提前抽象通用空间引擎。
3. 文件读取、布局保存、版本冲突和资源刷新继续复用 `ProjectFileService`，不建立第二套 Canvas 存储服务。
4. 查看地图自动执行；模型生成或更新 `.canvas` 继续按现有 Wiki 写入审批合同执行。
5. 普通对话、Markdown 阅读、创作画布和 3D 场景不加载项目地图运行时。

## 8. 明确不做

- 不把 `.canvas`、`.jccanvas` 和 `.jcscene` 合并为一种文件。
- 不做 Obsidian Canvas 的完整编辑器、便签系统、自由画笔或插件生态。
- 不在项目地图内运行视频编辑、媒体生成任务或 Three.js 场景。
- 不允许 Canvas 成为与 Markdown 并列的事实正文。
- 不自动扫描并铺开项目全部文件，不增加地图筛选器、时间线或多人协作。
- 本阶段不修改五个内置 Wiki Skill；现有标准 JSON Canvas 输出必须直接可打开。

## 9. 验收

1. Web/Desktop 可从文件树打开现有 Wiki Skill 生成的标准 `.canvas`，节点和边正确显示；损坏文件降级为可检查文本，不击穿工作台。
2. 文本节点中的 Wiki 双链和标准 `file` 节点均可打开真实项目资源；缺失、越界和绝对路径不会被打开。
3. 平移、缩放、适配视口和节点拖动有效；重开后布局一致，增量更新不重排无关节点。
4. 从项目地图进入 Markdown、媒体、创作画布和 3D 场景后，可返回原地图与原视口。
5. `.jccanvas` 和 `.jcscene` 的文件协议、保存链路、现有测试和打开行为无回归；项目地图不加载 `CreationPanel` 或 Three.js。
6. 普通聊天首屏不包含项目地图运行时；定向测试、类型检查、Web/Desktop 构建和产物审计通过后可标记代码已实施，三平台人工交互矩阵通过后才能标记跨平台交付闭环。

## 10. 实施结果（2026-08-02）

- `.canvas` 已作为独立 `project-map` 资源类型进入文件树和 `openProjectResource()`；`.jccanvas` 继续使用原创作画布协议，`.jcscene` 继续使用原 3D 场景协议。
- 查看器支持标准 JSON Canvas 的 `text / file / link / group / edges`，显示关系标签，并兼容文本节点中的 `[[双链]]`。损坏文件降级为可检查纯文本；绝对路径和包含 `..` 的越界路径不会打开。
- 原生平移、缩放、适配、节点拖动已实现；拖动只写回 `x / y` 并使用 `ProjectFileService.writeText` 的 revision 冲突保护。Markdown、媒体和 3D 场景复用现有预览，从节点进入后可返回原地图视口；`.jccanvas` 复用现有 `canvas:open` 创作入口，地图不加载 `CreationPanel`。
- 项目地图组件按需加载，普通对话首屏不加载；定向回归、TypeScript、Web/Desktop quick build、两端产物审计和 Web 桌面/移动视口渲染通过。
- 未验证：Windows/Intel Mac/Apple Silicon 安装包交互矩阵，以及真实大型 Wiki 地图性能。第一阶段不增加筛选器、自动全库铺图或通用空间引擎。
