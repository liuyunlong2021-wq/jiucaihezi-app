# Gemini Omni RH 三模型接入 TDD

> 状态：代码与自动化验收已完成；真实 RH/NewAPI 账单验收待生产凭证
> 日期：2026-08-17
> 范围：RH 适配器、创作面板、NewAPI 视频任务计费

## 1. 目标

在现有 RH 标准 API 链路中增加三个独立计费模型，不新建适配器或轮询协议：

| 模型 ID | 模式 | 固定参数 | 素材合同 | UI 价格 |
| --- | --- | --- | --- | --- |
| `rh-gemini-omni-text-video` | 文生视频 | `1080p`、`10` 秒 | 无参考图和视频 | `2.5元/次` |
| `rh-gemini-omni-image-video` | 图生视频 | `1080p`、`10` 秒 | 参考图仅允许 `1` 或 `3` 张 | `2.5元/次` |
| `rh-gemini-omni-video-edit` | 视频编辑 | `1080p` | 视频必填且最多 1 段；图片允许 `0`、`1` 或 `3` 张 | `0.4元/秒` |

三个模型均保留 `16:9` 和 `9:16` 比例选择，提示词上限为 2048 字符，单个图片或视频文件不超过 10 MB。

## 2. 现有链路与根因

- `gemini-omni-flash/text-to-video`、`image-to-video` 和 `video-edit` 已存在于 RH capabilities 数据。
- 现有 `rh-adapter` 已能按 capability 构造 `imageUrls`、`videoUrl`、`resolution`、`duration` 和 `aspectRatio`，并复用现有上传与轮询。
- 本次不需要新协议层；只需增加三个模型映射和前端注册。
- 现有 RH 计划在参数缺失时可回退到通用 `720p`，不能只靠 UI 默认值保证固定 `1080p`。固定值必须在共享计划归一化中生效。
- NewAPI 计费与 UI 价格文案是两条链路。视频编辑不得因未传计费时长而按默认秒数扣费。

## 3. 计费合同

### 3.1 固定时长视频

- 文生视频和图生视频的上游参数固定为 `duration=10`、`resolution=1080p`。
- UI 显示 `2.5元/次`，每次成功提交的计费目标为 2.5 元。
- NewAPI 后台可以用“10 个计费秒×0.25 元”或等价的按次配置实现；以生产账单实测为准，不在未验证前假定 NewAPI 具体配置。

### 3.2 视频编辑

- 计费时长来自实际输入视频媒体元数据，不使用用户手填值、输出时长或 NewAPI 默认值。
- 本次计费合同按整数秒结算：`billingSeconds = ceil(输入视频真实时长)`，最小为 1 秒。
- 计费目标为 `billingSeconds × 0.4元`。例如输入 7.2 秒，按 8 秒计费，UI 价格仍显示 `0.4元/秒`。
- 媒体元数据无法读取或时长非法时必须阻止付费提交，不回退到 4 秒或任意猜测值。
- `seconds` 是 NewAPI 计费字段，RH 适配器不得将它冒充为上游 `duration`。

## 4. TDD 验收

### 红灯测试

1. 三个模型 ID 当前未注册，RH 适配器无法解析对应端点。
2. 文生/图生模型未传参数时，计划不能保证 `1080p/10秒`；传入其他值时也必须拒绝。
3. 图生视频的 2 张图和视频编辑的 2 张图必须在发起网络请求前被拒绝。
4. 视频编辑无视频、视频超过 1 段或无法读取真实时长时必须阻止提交。
5. 输入 7.2 秒视频时，NewAPI 请求必须使用 `seconds=8`；RH 上游 payload 不得出现计费字段。

### 绿灯测试

1. 三个模型分别映射到 `text-to-video`、`image-to-video` 和 `video-edit` 官方端点。
2. 文生/图生计划总是生成 `resolution=1080p`、`duration=10`，UI 不显示时长或分辨率可编辑控件。
3. 图生视频仅接受 1 或 3 张图；视频编辑接受 0、1 或 3 张图及 1 段视频。
4. 视频编辑读取输入视频时长并向上取整，以 `seconds` 参与 NewAPI 计费，上游仅收到官方视频编辑参数。
5. 价格文案分别为 `2.5/次`、`2.5/次`、`0.4/秒`。

## 8. 可复用成功经验

- 先用小 TDD 锁定模型 ID、固定参数、素材数量、文件大小、UI 价格和计费字段，再修改实现；这样能区分“文档已写”与“运行边界真的生效”。
- 固定上游参数不能只靠 UI 默认值。共享 RH payload 必须补默认值并拒绝冲突值，防止旧计划、缓存参数或直接请求绕过前端。
- UI 价格与真实计费字段必须分开处理。视频编辑的 `seconds` 只在读取输入视频真实元数据后生成，不能保存为可编辑字段，也不能转发为 RH 的 `duration`。
- 媒体限制必须覆盖直接文件、项目媒体、画布原图和标注导出 Blob；只校验文件选择器会留下其他提交入口。
- 审计应主动测试脏状态：旧 `duration`、旧 `seconds`、超大媒体和冲突固定参数。真正的根因修复应落在共享归一化或适配器边界，而不是在每个调用者加补丁。
- 自动化通过后仍要保留生产边界：本地测试不能替代 RH/NewAPI 真实账单、渠道可用性、部署和结果质量验收。
