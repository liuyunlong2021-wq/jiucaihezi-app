> 状态：文档阅读、项目骨架、四类归档、隐藏保护及历史文档定位续聊均已实施
> 依据：`AGENTS.md`、[[开发/通用记忆对话独立App SDD]]、[[开发/Web文档转换服务SDD]]、[[开发/文件系统/索引]]

## 1. 决断

文档上传、格式转换、项目存储和模型阅读是四件事，不能继续合并成“把转换后的全文塞进本轮对话”。

```text
用户上传文档
  -> App 自动保存原件
  -> App 自动转换出模型可读 Markdown
  -> 对话只保存名称、类型和项目相对路径
  -> 普通问答由模型按需 grep/read
  -> 全文任务按顺序分页读取并检查覆盖范围
  -> 用户确认后，Wiki Skill 才把结论写入 Wiki
```

转换是上传基础设施，不新增 `@格式转换`、按钮或 Skill。用户只需要上传并提问。

**本页是通用记忆工作台项目骨架与素材归档的唯一事实源。** 修改项目初始化、文件树、上传、AI 生成、对话、画布或同步代码前必须先读本页；主 Studio、旧主 Web、媒体工作台及历史 SDD 中与本页冲突的目录或可见性描述只作历史记录，不得覆盖本合同。

## 2. 用户看到什么

`.raw` 是原始资料唯一根目录，文件名和界面名称都固定为 `.raw`，绝不改名或显示成“JC 原始素材”。项目骨架固定如下，不再保留 `jc-materials/`、项目根级 `jc-media/` 或按来源拆分的第二套素材目录：

```text
项目根/
├── .raw/                         # 文件树可见；系统骨架，不可改名、移动或删除
│   ├── jc-media/                 # 文件树可见；所有上传与 AI 生成素材的唯一根目录
│   │   ├── 图片/                 # 上传图片、AI 图片、Markdown 长图
│   │   ├── 视频/                 # 上传视频、AI 视频
│   │   ├── 音频/                 # 上传音频、AI 音频
│   │   └── 文档/                 # 上传文档、AI 生成文档及可读副本
│   ├── 对话记录/                 # 文件树隐藏；只由顶部对话选择器管理
│   └── .sync/                    # 文件树隐藏；只由同步链路管理
├── jc-canvas/                    # 文件树隐藏；只由画布选择器管理
└── wiki/                         # 文件树可见；系统骨架，由 Wiki 链路管理
```

- `.raw`、`.raw/jc-media`、四个中文分类、`.raw/对话记录`、`.raw/.sync`、`jc-canvas` 和 `wiki` 都是系统骨架。文件树、右键菜单、模型项目工具和 Wiki Skill 均不得将这些目录改名、移动或删除；缺失时由 App 创建或修复。
- 文件树只隐藏 `.raw/对话记录`、`.raw/.sync`、`jc-canvas` 和 `.DS_Store`。对话与画布仍是真实项目文件，但分别只通过顶部对话选择器和画布选择器创建、切换、重命名或删除。
- 四个媒体分类内的普通文件允许用户重命名、移动或删除；保护目录骨架不等于锁死其中内容。`.raw/.sync` 只允许同步链路管理。
- 用户可在 `.raw/` 内新建其他普通资料目录，但上传和 AI 生成的媒体不得绕过 `.raw/jc-media/` 四类合同。

上传完成后，附件卡只显示用户能理解的状态：

```text
✓ 已保存 · 已解析 83,017 字
```

不向用户暴露 MarkItDown、本地/云端转换、Token 上限、字符截断或 Markdown 中间格式。

## 3. 文件合同

### 3.1 分类

| 文件类型 | 保存位置 | 来源与可读副本 |
| --- | --- | --- |
| Markdown、纯文本及现有可直接读取文本 | `.raw/jc-media/文档/` | 上传与 AI 生成同路；直接读取原件，不复制第二份 |
| Office、PDF、RTF、ODF 等需转换文档 | `.raw/jc-media/文档/` | 上传与 AI 生成同路；同目录保存 Markdown 副本 |
| 图片 | `.raw/jc-media/图片/` | 上传、AI 生成和 Markdown 长图同路 |
| 视频 | `.raw/jc-media/视频/` | 上传与 AI 生成同路 |
| 音频 | `.raw/jc-media/音频/` | 上传与 AI 生成同路 |

只按文件类型分类，不按“上传 / AI 生成 / 对话生成 / 创作面板生成 / 画布生成”等来源分类。不得建立 `generated/`、`uploads/`、`images/`、`videos/`、`audios/`、`models/` 或其他第五分类；出现四类之外的新文件类型时，必须先修订本合同，不能由某个功能自行发明目录。原始二进制可以且只应进入 `.raw/jc-media/` 对应分类，绝不进入 `wiki/`、`.raw/对话记录/` 或 `jc-canvas/`。

### 3.2 命名与对应关系

- 保留用户文件名；上传入口先查询现有路径，重名时生成 `名称 (1).扩展名`，再调用 `ProjectFileService`。现有单文件创建接口本身不保证 keep-both，不能直接依赖它。
- 转换副本与原件同处 `.raw/jc-media/文档/`，使用原件最终文件名加 `.md`，例如 `会议纪要.docx` 对应 `会议纪要.docx.md`，避免不同扩展名同名碰撞。
- 对话附件元数据保存 `projectPath`；需转换文档再保存可选 `readablePath` 和 `characterCount`。
- 所有路径必须是当前项目内的相对路径，不保存绝对路径、Blob URL、Base64、临时缓存路径或鉴权 URL。
- 原件保存成功但转换失败时保留原件，附件卡显示“转换失败，可重试”，不得删除用户文件或假装模型已经读取。
- 转换返回 `truncated=true` 时不得进入“已解析”成功态，也不得保存残缺副本冒充全文；应明确提示“文档超过当前安全解析上限”，保留原件并结束本次提交。解析上限已从旧的 50 万/100 万字符提高到 2000 万字符，只防止 20 MB 压缩文档异常膨胀，不再承担模型上下文裁剪职责。

### 3.3 生命周期

- 上传一次，只转换一次；后续对话复用同一 `readablePath`。
- 从对话中移除附件只取消本轮引用，不删除 `.raw/jc-media/` 文件。
- 用户在文件树删除原件时，必须沿用现有删除确认；本期不自动连带删除 Markdown 副本，避免误删用户可能编辑过的内容。
- 用户删除 Markdown 副本后再次引用原件，App 可重新转换并生成新副本。
- 本期不做哈希去重、版本管理、后台索引或向量数据库；同名保护已经足够避免覆盖。

## 4. 对话与模型阅读合同

### 4.1 Raw 只记定位，不记全文

对话 Raw 中附件只记录：

```text
id / name / mime / size / kind / projectPath / readablePath / characterCount
```

转换后的正文不写入用户消息，不随历史消息反复发送，也不生成第二份聊天数据库。刷新、重开项目或切换设备后，模型仍可通过项目路径重新找到资料。

### 4.2 记忆模式

记忆模式已有 `grep`、`read(path, offset, limit)`、Wiki 和项目文件工具，直接复用：

- 摘要、问答、找人物或找条款：先 `grep` 定位，再 `read` 相邻段落。
- 用户明确要求“全文阅读、逐章拆分、不要遗漏”：从第一行开始连续分页 `read`，直到文件末尾；输出前检查已读取区间连续且到达末尾。
- 系统提示只告诉模型本轮附件的 `readablePath`、字符数和任务规则，不注入全文。
- 后续轮次只把当前已装入上下文的历史文档名称和 `readablePath` 交给模型，不重复注入正文；用户说“这个文档”或追问原文细节时，模型使用同一路径重新 `grep/read`。已被上下文容量整体淘汰的旧轮次不单独复活，必要时继续按现有合同查询对话 Raw。
- 运行状态沿用现有工具步骤，显示“正在搜索资料”“正在读取 方案.docx”“正在整理回答”。

普通问答节省 Token，但“全文且不遗漏”的任务仍会消耗阅读全文所需 Token；产品不承诺零 Token，只消除无意义的重复注入。

### 4.3 快速模式

快速模式只开放只读 `wiki_search`，不接收文档附件或项目文件引用，也不开放 `read/grep`、Skill、MCP、`write/edit` 或终端。需要阅读原始文档时使用记忆模式。

两种模式共享当前对话上下文；快速模式只能搜索 Wiki，记忆模式才能按需分页阅读项目文档。任何长度的文档都不再整篇注入，也不需要按任务措辞猜测是否自动切换模式。绝不静默 `slice` 到固定字符数；读不完整就继续分页或明确失败。

现有 `read` 结果只有行号，没有总行数或 EOF。实施时给这一个共享回执补上 `lines/total/eof` 元数据，让模型能确定已经读到末尾；不新增“全文阅读工具”。

## 5. Wiki 边界

原始资料和 Wiki 不是同一层：

```text
.raw = 对话、文档、图片、视频、音频及用户自建内容等完整原始资料
wiki = AI 从 .raw 或其他真实来源提炼、并经用户确认的长期知识
```

- 上传和转换不会自动写 Wiki。
- `.raw/对话记录/` 属于原始资料，不属于 Wiki；它只是由顶部对话选择器导航并受 App 专用保护。
- 用户说“整理成 Wiki”时才调用现有 Wiki Skill，读取 `.raw` 中的真实来源后预览并按现有确认合同写入。
- Wiki 应记录来源相对路径，便于回查；不得复制原始二进制，也不要求把整篇转换稿再次复制进 Wiki。

## 6. 双端与同步

### 6.1 Desktop

优先使用现有本地转换；本地不可用时继续走已经上线的 `/documents/markdown` 云端转换。两条路径返回同一 Markdown 结果并写入 `.raw/jc-media/文档/`。

### 6.2 Web

继续使用现有云端转换服务。服务只处理临时文件并删除临时目录；转换结果由浏览器项目文件系统保存，不在转换服务器留档。

### 6.3 跨设备

现有项目文字同步允许安全 Markdown，但明确阻止二进制媒体：

- 不超过现有同步单文件 2 MB 上限的 `.raw/jc-media/文档/*.md` 可作为安全文本同步，使另一台设备可以继续问答；更大的可读副本本期仍留在当前设备，界面不得误报已同步。
- `.raw/jc-media/` 中的二进制原件和媒体本期不同步，仍在上传设备；Web 项目导入导出仍可由用户显式搬运完整项目。
- 另一台设备只有 Markdown 副本时，界面显示“可阅读副本”，不得显示“原件已同步”。

本期不扩展服务器二进制存储。只有用户明确需要原件自动跨设备时，再单独设计容量、隐私、计费、断点续传和删除合同。

## 7. 安全与故障

- 保留现有允许扩展名、20 MB 上传上限、90 秒转换超时、Bearer 校验和临时目录清理。
- 当前记忆上传没有接通 OCR 回退；扫描版 PDF、加密/损坏文档和空正文必须明确失败，不能假装已解析。OCR 不是本期目标，确有需求时再复用现有格式转换器另立验收。表格、幻灯片和复杂排版只承诺提取可读内容，不承诺还原原版式。
- 文件名必须经过项目相对路径安全处理，拒绝空路径、绝对路径、`.`、`..` 和 NUL。
- 转换服务不得返回或记录用户绝对路径、Key、正文和临时目录。
- 一个批次中某个文件转换失败时，其余成功文件仍可加入附件；失败文件明确列出，不整批假成功。
- 模型工具只能读取当前项目或用户本轮明确批准的外部路径，不能通过附件元数据扩大文件权限。
- 系统骨架目录不得通过普通文件动作改名、移动或删除；`.raw/对话记录/` 与 `jc-canvas/` 中的记录分别只能由对话选择器和画布选择器写入、重命名或删除，`.raw/.sync/` 只能由同步链路写入。

## 9. 验收标准

1. 上传 Office 后，项目同时存在原件和完整 Markdown；关闭 App 再打开仍能读取。转换返回截断时不能产生伪完整副本。
2. 对话 Raw 只有附件路径与元数据，没有转换正文、Base64、绝对路径或临时地址。
3. 第二轮追问会携带当前上下文中历史文档的名称和 `readablePath`，不会再次把整篇文档或上一轮工具结果自动注入请求；记忆模式可按该路径重新读取。
4. 普通问答实际调用 `grep/read`；全文任务读取区间从首行连续覆盖到末行，无 8,000/120,000 字符静默截断。
5. 选择或上传文档会进入记忆模式并由模型按需调用 `read/grep`；快速模式不接收文档，只提供只读 `wiki_search`。
6. 转换失败保留原件并可重试；重名上传不覆盖已有资料。
7. Desktop 本地优先/云端回退和 Web 云端转换均写入 `.raw/jc-media/文档/`。
8. 跨端同步后可阅读 Markdown 副本，并准确提示原件是否在本机。
9. 上传、对话生成、创作面板生成和画布生成的文档、图片、视频、音频均只按文件类型进入 `.raw/jc-media/` 对应中文分类，不产生来源目录、项目根 `jc-media/`、`jc-materials/` 或第五分类。
10. 文件树隐藏 `.raw/对话记录`、`.raw/.sync`、`jc-canvas` 与 `.DS_Store`；对话和画布只能通过各自选择器管理。
