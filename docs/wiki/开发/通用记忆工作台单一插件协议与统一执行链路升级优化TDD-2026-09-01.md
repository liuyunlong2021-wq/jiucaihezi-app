# 通用记忆工作台单一插件协议与统一执行链路升级优化 TDD

> 日期：2026-09-01  
> 状态：已实施，待真实平台验收  
> 范围：Skill 工具声明、普通文件能力、统一 Agent Loop、旧领域专用协议退役

## 1. 最终合同

```text
用户信息 + 模型 = 基础输出

用户信息 + 模型 + Skill + Skill 声明的工具 + 用户追加插件
  = 按 Skill 规则执行并输出
```

- Skill 是最核心的插件，是本轮必须服从的执行合同。
- Skill 可以声明并驱动文件、MCP、媒体、3D、Terminal 等工具。
- 项目知识、资料、脚本和产物都是普通文件，不拥有独立 Agent、Runtime 或模型协议。
- 所有插件共用 `runDirectChatCompletion`，不存在领域专用第二阶段。
- Skill 或用户授权决定业务工具集合；平台、连接、路径、审批和取消构成通用安全边界。

## 2. 根因测试

旧实现把普通文件任务切到专用二阶段模型协议：

```text
普通任务 -> 专用入口预读 -> 专用 JSON 计划 -> 再包装任务协议 -> 专用 Runtime
```

因此简单创建文件架构也可能在中间计划解析阶段失败，文件工具根本没有得到执行机会。根因不是某个字段校验，而是重复路由、重复协议和重复 Runtime。

### RED

- 选中 Skill 后，Skill 声明的 `read/edit/delete` 没有进入工具集合。
- 选中 Skill 后，未声明工具被全量开放。
- 普通文件任务进入专用二阶段协议，而不是 Direct Loop。
- MCP 工具受领域专用服务器白名单限制。
- 项目初始化强制创建领域专用目录和模板。
- 保存模型回答只能写入领域专用目录。

### GREEN

- `SKILL.md` 支持 `allowed-tools` 列表。
- 本地和产品 Skill 的工具声明都进入本轮授权集合。
- 授权集合为“Skill 声明 + 用户追加插件”，再经过注册、平台、连接和安全过滤。
- 所有任务统一进入 `runDirectChatCompletion`。
- 文件能力只使用 `read/glob/grep/write/edit/mkdir/move/delete`。
- 项目初始化只创建记忆工作台自身必需目录。
- 模型回答可保存到任意项目 Markdown 文件。

## 3. Skill TDD

输入：

```yaml
---
name: file-architecture
description: 创建并维护项目文件架构
allowed-tools:
  - read
  - write
  - edit
  - mkdir
  - delete
---
```

断言：

- `parseSkillMd()` 返回完整 `allowedTools`。
- `serializeToSkillMd()` 保留 `allowed-tools`。
- Connection frontmatter 解析器支持 YAML 列表。
- Skill 声明 `read/edit` 时只开放这两个工具。
- Skill 声明具体 MCP 工具时，该工具可进入授权集合。
- Skill 未声明的 Terminal、媒体和 3D 工具保持关闭。
- 用户显式追加的插件与 Skill 声明合并，不覆盖 Skill 工具。
- 完整 Skill 正文作为强制合同进入模型上下文。
- Skill 要求删除或移动时，执行通用审批；拒绝后返回取消 Observation。
- 工具失败时模型收到真实错误，不得显示成功状态。

## 4. 文件 TDD

- `read/glob/grep` 可读取和检索用户授权的项目文件。
- `write/edit/mkdir/move/delete` 可完成创建、修改、移动和删除。
- 项目外路径必须由用户在当前消息明确提供。
- 删除、Terminal 和需要审批的外部副作用保持确认。
- Raw 对话和 App 管理目录继续受保护。
- 保存模型回答使用普通 Markdown 文件服务，支持新建和追加。
- 并发写入冲突返回真实失败，不覆盖其他窗口的新内容。

## 5. 统一 Loop TDD

- 无插件请求不暴露工具，只发送当前用户任务。
- 有插件请求只使用一个 `runDirectChatCompletion`。
- 同阶段独立只读文件操作可以并行。
- 写入、删除、Terminal 和审批调用形成串行屏障。
- 每个 tool call 都有配对 Observation。
- 成功、失败和取消都来自实际工具结果。
- 达到工具轮次上限时使用统一收尾，不进入另一套协议。
- 同一 Direct Loop 中，已成功的 `edit` 被模型原样重复调用时返回幂等成功结果，不再次执行文件写入，也不把已达到目标状态的文件标记为失败。

## 7. 回归矩阵

| 场景 | 授权来源 | 预期 |
| --- | --- | --- |
| 普通问答 | 无插件 | 无工具，模型直接输出 |
| 创建文件架构 | Skill 声明文件工具 | 同一 Loop 创建目录和文件 |
| 查询项目资料 | Skill 或用户选择文件 | `glob/grep/read` 后回答 |
| 修改文档 | Skill 声明 `edit` | 修改并返回真实回执 |
| 删除文档 | Skill 声明 `delete` | 进入审批，执行或取消 |
| Skill + MCP | Skill 声明具体 MCP | 同一 Loop 调用 MCP |
| Skill + 3D | Skill 声明 3D 工具 | 同一 Loop 创建或编辑场景 |
| Skill + 媒体 | Skill 声明媒体工具 | 同一 Loop 生成产物 |
| 未声明工具调用 | 无授权 | 失败 Observation，无副作用 |
| 工具不可用 | 平台或连接缺失 | 真实失败，不伪造完成 |
| 成功后的重复编辑 | 同一 `edit` 签名再次调用 | 返回“已是目标状态”成功结果，底层只写入一次 |

## 9. 禁止事项

- 不新增 `SkillAgent`、`FileAgent` 或其他并列 Agent。
- 不为任何文件目录增加专用模型协议或 Runtime。
- 不把 Skill 降级成只能提供文字规则的被动资料。
- 不因选中 Skill 而开放全部工具。
- 不让正文文字绕过工具注册、平台能力、连接、安全和审批边界。
- 不删除用户现有项目文件或历史设计证据。

## 10. 完成定义

1. 只有一个 Agent Loop。
2. Skill 声明的合法工具真实可用。
3. 项目知识和资料只作为文件处理。
4. 旧领域专用 Agent、协议、Runtime 和工具不存在生产引用。
5. 自动测试、类型检查和差异检查通过。
