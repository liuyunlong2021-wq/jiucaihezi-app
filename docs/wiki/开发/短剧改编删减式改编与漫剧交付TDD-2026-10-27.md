# 短剧改编：删减式改编与漫剧交付TDD

> 2026-10-27。状态：**用户已确认，源码已实施，自动化回归通过；真实试跑未验**（见第6节）。取代 [[开发/短剧改编规划书与筛选编集TDD-2026-10-27]] 中“规划后逐集改写成剧本”的默认流程；逐集改写保留为可选。建立在 [[开发/短剧改编全自动与漫剧衔接TDD-2026-10-27]] 及其实测修正之上（节点目录来源、按章号排序、每段只读本段章节、全自动不催促）。

## 0. 用户口径

- 第一性原理：短剧改编的产物是给漫剧制作工作流执行的，不是给人拍的。小说本身有描写、有对白，把文字变成画面是漫剧“工程剧本”的工作。所以这一步**只切集、只删减，不改写、不新增**。
- **删减后置**：先切事件、给出分集建议，由用户决定每个事件切几集；再按用户的决定切集，最后才删减。
- 分集文档只放切好、删好的小说原文，不含任何说明文字。
- 现有的逐集改写（说明书剧本）保留为可选，给文笔差、确实需要重写的小说用。

## 1. 流程

**第一步：程序分章，统计数据。** 来源可以是章节点目录或原文文件，章节按章号排序。程序统计每章字数、对白字数（引号内），供模型参考。

**第二步：模型每次读20章，写入Wiki，然后暂停等用户决定。**

| 文档 | 落位 | 内容 |
| --- | --- | --- |
| 事件文档 | `改编方案/事件/E03_噗叽偷食被收服.md`，一个事件一个文档，文件名为“序号_一句话概述” | 章节与行号范围；涉及的人物、场景、道具（链到档案）；冲突；爽点；可切开的位置（原文里局势变化、新问题被抛出的行号） |
| 人物小传 | `项目资料/原作/人物小传/`（不限于人类） | 身份、外形、服装、**造型表**（造型名、从第几章开始、原文依据）、性格、关系、**声音特征**（原文写到的年龄感、嗓音、说话习惯，没写的留空） |
| 场景 | `项目资料/原作/场景/` | 空间、材质、光线，**陈设**（日常物件），**人群**（群体名、人数、服制、站位） |
| 重要道具 | `项目资料/原作/道具/` | 只收剧情道具和角色标志物；属于场景的写进场景陈设 |
| 世界规则 | `项目资料/原作/世界规则.md` | 规则本身，以及**能力的视觉规则**：每种能力、每次进化的颜色、光效、形态、尺寸，原文有的照录，没写的标“待设计” |
| 故事梗概 | `项目资料/原作/故事梗概.md` | 漫剧定画面风格时只读这一份 |
| 项目总纲 | `改编方案/项目总纲.md` | 给用户看：一句话主题与事件摘要 |
| 建议分集方案 | `改编方案/分集规划.md` | 每个事件：建议切几集；每集从哪里开头、在哪里留钩子（行号）；理由 |

每读完一段20章就追加；一批读完后暂停，向用户汇报：事件列表、每个事件建议的集数和理由。

**用户决定。** 用户回复“按建议切”，或“E03切成4集、E05并成1集”。模型更新建议分集方案，并把最终决定写进进度（见3.3）。

**第三步：按用户的决定切集、删减、写入Wiki。**

1. 一个事件一轮：读这个事件的章节，按决定的集数切开，再在每一集里删减。
2. 删减标准：删掉这一句，观众会不会少知道什么、少感受到什么？都不会就删；后文会用到的伏笔不删；对白一字不改。好的小说可以一句不删。
3. 模型只给出每集保留的行号段，程序从原文截取拼接：
   - 出处记录写在`改编方案/分集切分/第NNN集原文.md`（每段来源、章节、行号；已有机制）；
   - 程序同时生成`项目资料/分集剧本/第N集分集剧本.md`：**只有原文正文**，没有出处标注和任何说明。这正是漫剧“入稿拆集”的产物位置，漫剧全自动和自由创作都能直接接上。
4. 全部切完后收尾：把造型表里的“第几章”回填为集号；写分集梗概（`项目资料/原作/分集梗概.md`，每集一句话）；提醒用户确认画面风格和比例。

## 2. 规则要点（写进Skill）

- 删减是剪辑，不是写作。可用的手段只有：剪掉、保留、调序（倒叙冷开场）、复用（上一集最后一句或最后一个画面作为这一集的开头）。不新增任何文字。
- 切集的头：第一个让观众产生疑问的画面或台词。切集的尾：一个问题刚提出、答案还没给的那一刻。一个事件能切几集，看里面有几个这样的问题点，以及删减后剩下的容量（一般一集一分半左右，最长三分钟）。这些是判断依据，不是硬门槛。
- 删减按整行（自然段）进行。一段里只有半句废话时整段保留，实测后再考虑按句删减。

## 3. 程序改动

### 3.1 事件文档类型

新增`adaptation_event`：路径`改编方案/事件/{entity}.md`，`entity_name`必填，文件名须以“E+数字_”开头，只在短剧路线使用。

### 3.2 分集剧本由程序生成

`episode_source_script`在短剧路线开放，content传`{"from_cut": N}`：程序读取并校验第N集原文切分，去掉出处标注，原样保存为`项目资料/分集剧本/第N集分集剧本.md`。模型传其他正文时拒绝，保证正文只来自原文。漫剧路线的原有用法（入稿时原样保存剧本）不变。

### 3.3 进度

- scheme阶段（等待用户决定时为review）新增`event_episodes`：`[{"event":"E03_噗叽偷食被收服","episodes":3}, ...]`，每项的事件文档必须存在，集数为正整数。
- writing阶段：每集登记`项目资料/分集剧本/第N集分集剧本.md`或`剧本/第NNN集/分集剧本.md`之一即可（后者为可选改写模式），二者至少有一。
- 其余阶段与校验不变（来源、章号顺序、切分不重叠、unused列出未使用的行号）。

### 3.4 全自动运行器

每批步骤改为：

1. **规划**（每20章一轮）：先补资料、事件文档，再追加建议分集方案，保存scheme进度和`planned_through`；最后一段以review保存，并写入建议的`event_episodes`。
2. **等用户决定**：审阅卡显示事件和建议集数；用户在对话里调整后点确认。
3. **切集**（一个事件一轮）：按`event_episodes`逐个事件发指令，切集、删减、保存切分和分集剧本；程序检查这几集的分集剧本在本次运行中已生成。
4. **收尾**：回填造型表集号、写分集梗概，保存cuts、writing、complete进度，提醒确认画面风格。

不再有逐集改写步骤。

### 3.5 界面（上一轮已同意）

- 全自动进度改成输入框上方的一个芯片，和选中Skill的显示方式一致，例如“全自动·改编 · 第1批 · 切集 E03”。点芯片展开审阅卡或暂停原因。
- 去掉进度条上的停止按钮，输入框右下角的停止按钮在全自动运行时停止整个运行。
- 芯片上显示全程已用时间（从点“开始”算起，等待用户决定的时间不计）。

## 7. 追加：事件跨段、跨批

用户提出：按20章一段读，可能第20–22章是一个事件。处理：

- **跨段**（同一批内）：段末事件没有结果时，事件文档标“未完”，暂不写建议分集；下一段开头先读这份事件文档，在同一事件里续写，不另起新事件。
- **跨批**：一批读完时仍未完的事件不进入本批`event_episodes`，起始章写进scheme进度的`carry_from`（程序校验须在本批范围内，并保留到完成）；运行器下一批从这一章开始读（批次起点改为动态的`batchFrom`）。
- 事件从本批第一章就开始、长过一整批时无法顺延，运行器暂停并要求在自然转折处拆成两个事件，避免反复读同一批。
- 先红后绿：运行器新增2项（续写与顺延指令、下一批起点；超长事件暂停），SDK删减流程新增`carry_from`校验与保留，Skill合同新增续写、顺延、拆分断言。focused 2406项，2403通过、2跳过、1失败（进行中的iOS任务）；scripts 222项通过；`vue-tsc -b`通过。
