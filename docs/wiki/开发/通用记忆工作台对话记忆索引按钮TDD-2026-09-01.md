# 通用记忆工作台对话记忆索引按钮 TDD

> 日期：2026-09-01  
> 状态：已实施，待真实模型与跨端验收  
> 范围：当前对话单轮回答的手动记忆索引创建  
> 前置：[[通用记忆对话独立App SDD]]、[[通用记忆工作台单一插件协议与统一执行链路升级优化TDD-2026-09-01]]、产品 Skill `jc-jiyi`

## 1. 目标

在每条已完成的 assistant 回答后提供“写入索引”按钮。用户点击后，模型用当前 `user -> assistant` 轮次生成简短的 `summary` 与 `keywords`，程序补齐对话身份、来源路径和 turn ID，并把一条 Markdown 记录写入当前对话的记忆索引。

```text
Raw 对话记录 = 完整正文唯一事实源
记忆索引 = 当前对话的可检索导航
jc-jiyi Skill = 记忆索引查询方法
写入索引按钮 = 用户确认的单轮索引创建动作
```

本 TDD 只解决“创建一条索引记录”。查询由现有 `jc-jiyi` Skill 和后续查询工具负责。

## 2. 用户合同

### 2.1 按钮位置

按钮出现在每条已完成 assistant 消息的操作区，与现有“保存到文件”并列：

```text
复制 | 保存到文件 | 为这条回答写入索引
```

按钮使用现有消息操作样式和图标系统，标题为“写入这条回答的记忆索引”。流式回答、空回答和失败回答不显示按钮；用户消息不显示按钮。

### 2.2 点击行为

点击后：

1. 程序读取当前对话的 user turn 和 assistant turn。
2. 程序向当前模型发起一次独立请求，只要求生成 `summary` 与 `keywords`。
3. 程序校验模型返回的 JSON，补入真实元数据并写入索引文件。
4. 成功后按钮显示“已写入索引”，并记录该 assistant turn 的已索引状态。

索引创建是用户点击触发的手动动作；普通聊天发送、流式输出和 Raw 保存不自动追加模型请求。

## 3. 存储合同

每个 conversation 对应一个索引文件：

```text
.raw/
  对话记录/<conversation-id>.md
  记忆索引/<conversation-id>.md
```

记忆索引属于当前项目的系统目录，沿用现有项目文件同步和隐藏目录边界。索引文件首段保存稳定身份：

```md
# 对话记忆索引

<!-- jc:conversation-memory-index conversation-id="conversation-xxx" source="../对话记录/conversation-xxx.md" version="1" -->
```

单条记录格式：

```md
- [2026-09-01 15:05](../对话记录/conversation-xxx.md#jc-turn-a124)
  - 简介：确定了对话记忆索引的运行时接入方式。
  - 关键词：记忆索引、Skill、上下文
  - 来源：user `u124`，assistant `a124`
```

完整用户消息、完整 assistant 回答、附件二进制和凭据继续保存在 Raw 或既有附件路径中，索引只保存导航信息。

## 4. 模型请求合同

### 4.1 输入

索引请求只携带当前轮次的最小必要内容：

```json
{
  "conversationId": "conversation-xxx",
  "userTurn": { "id": "u124", "content": "用户本轮输入" },
  "assistantTurn": { "id": "a124", "content": "模型本轮完整回答" }
}
```

请求不携带其它对话、不携带整个 Raw、不携带已有索引全文、不携带未被当前轮次引用的附件。

### 4.2 系统提示

索引请求使用短提示：

```text
请为这一轮已完成的用户问题和助手回答生成对话记忆索引。
只返回 JSON，不要返回 Markdown 或解释文字。
summary 是一到两句、可独立理解的事实摘要。
keywords 是 3 到 8 个与主题、实体、路径或决策相关的短词。
只概括输入中真实出现或明确确认的内容。
```

### 4.3 输出 Schema

```json
{
  "summary": "这一轮解决了什么、确认了什么",
  "keywords": ["关键词1", "关键词2", "关键词3"]
}
```

程序校验规则：

- `summary` 必须是非空字符串，长度上限由运行时常量控制。
- `keywords` 必须是字符串数组，去空白、去重并限制为少量条目。
- 其它字段忽略；解析失败返回可见错误，不写入索引。
- conversation ID、Raw 路径、turn ID、时间和 Markdown 链接全部由程序生成，模型输出不参与这些字段的信任判断。

## 5. 程序写入流程

```text
点击写入索引
  -> 锁定 conversationId / userTurnId / assistantTurnId
  -> 读取当前 Raw，确认两个 turn 仍存在且角色正确
  -> 调用一次模型生成 summary + keywords
  -> 解析并校验 JSON
  -> 读取或创建 .raw/记忆索引/<conversation-id>.md
  -> 按 assistantTurnId 幂等追加或更新一条记录
  -> 保存并重新读取索引文件
  -> 更新按钮状态和程序回执
```

索引写入使用现有项目文件服务和乐观 revision。并发点击、重复点击和网络重试使用 `conversationId + assistantTurnId` 作为幂等键，同一 assistant turn 保持一条索引记录。

## 6. 失败与回执

| 场景 | 行为 |
| --- | --- |
| 模型请求失败、超时或取消 | Raw 保持不变，索引保持不变，按钮恢复“写入索引”，显示真实错误 |
| 模型 JSON 无法解析 | 不写入索引，显示“索引内容格式无效” |
| 当前 turn 已被编辑或删除 | 拒绝写入，要求刷新当前对话 |
| 索引文件不存在 | 程序创建索引文件和父目录后写入 |
| 重复点击同一回答 | 返回已有记录，文件保持一条记录 |
| Raw 已保存、索引保存失败 | 对话继续可用，显示“对话已保存，索引写入失败” |
| 写入后复读校验失败 | 显示失败路径和原因，不显示“已写入索引” |

索引创建失败不会回滚已经成功保存的 Raw 对话，也不会伪造成功状态。

## 7. 与 Skill 的关系

- `jc-jiyi` Skill 继续保持查询单一职责，使用索引定位 Raw 中的精确 turn。
- 写入索引按钮直接调用索引摘要请求和程序文件服务，不启动 Skill 查询，不要求模型执行文件工具。
- 用户后续点击 `@记忆` 时，Skill 查询已经存在的索引并返回对应原始轮次。
- Wiki、写作或其它 Skill 可以把记忆查询结果作为输入继续工作；本 TDD不改变多 Skill 的现有加载方式，也不增加编排协议。

## 8. 安全与范围

- 目标索引路径固定在当前项目 `.raw/记忆索引/`，路径由程序拼接并校验。
- 索引查询和写入均绑定当前 conversation ID，项目切换时重新解析身份。
- 模型生成的 summary 只作为可检索摘要，Raw 才是事实来源。
- 索引文件沿用项目文字同步合同；不进入普通资料文件树和 Wiki 顶层导航。
- 本阶段不引入向量数据库、Embedding、后台自动任务、第二份聊天正文存储或跨对话索引。

## 9. TDD 实施顺序

### T1：索引格式与纯函数

先写测试，再实现：

- 生成索引头和单条记录。
- 解析已有索引并按 assistant turn ID 去重。
- 生成稳定的 Raw turn 深链。
- 非法 summary/keywords 被拒绝。

验证：新增 `conversationMemoryIndex` 定向单元测试、`git diff --check`。

### T2：单轮模型请求

- 从当前 user/assistant turn 组装最小请求。
- 解析 `summary + keywords` JSON。
- 复用现有 API 配置、重试、取消和 token 估算。

验证：请求 payload、解析失败、取消和重试测试；确认一次点击最多一次摘要请求。

### T3：项目文件写入

- 增加 `.raw/记忆索引/` 系统目录边界。
- 复用 `ProjectFileService` 创建、读取、写入和 revision 冲突处理。
- 写入后重读并返回确定性回执。

验证：Web/Desktop 文件服务测试、重复点击幂等测试、冲突测试。

### T4：消息操作区按钮

- 在 assistant 消息操作区增加“写入索引”。
- 按 turn ID 显示已写入状态。
- 复用现有 loading、错误和成功提示样式。

验证：工作台组件测试覆盖按钮显示、点击、成功、失败、重复点击和编辑后失效。

## 10. 验收矩阵

1. 一条正常 assistant 回答点击一次，生成一条索引记录。
2. 同一回答重复点击，索引文件仍只有一条对应记录。
3. 索引记录能通过 Raw 路径和 turn ID 定位原始 user/assistant 内容。
4. 模型失败、取消和 JSON 无效时，Raw 不变且索引不新增。
5. 切换到另一对话后，按钮和索引状态不串用。
6. 编辑历史后，旧 assistant turn 的索引状态失效，后续查询不会返回孤立链接。
7. Web、Desktop、Mobile 继续使用同一 Markdown 格式和项目文字同步合同。
8. 未点击“写入索引”的普通对话请求次数、上下文和费用保持现状。

## 11. 明确暂不实现

- 每轮回答自动生成索引。
- 为索引建立 Embedding、向量库或独立数据库。
- 使用第二个模型持续维护整份索引。
- 跨对话统一搜索或项目级全局记忆图。
- 在本按钮中执行 Wiki 写入、Skill 编排或其它文件操作。
