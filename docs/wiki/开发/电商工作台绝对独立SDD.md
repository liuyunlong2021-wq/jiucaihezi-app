# 电商工作台绝对独立 SDD

> 日期：2026-07-23
> 状态：已实施（2026-07-24 收尾）
> 范围：电商工作台的独立入口、单轮模型直连、项目定位记录和公共媒体接线
> 替代关系：本文替代 [[开发/电商工作台SDD]] 中电商绑定 Chat、创模式会话、AI 协作记录、工具循环或 OpenCode 的历史设计。旧文只保留演进背景。

## 1. 一句话目标

电商工作台是独立产品 surface：用户提供信息和原始图片，选择模型与 Skill，模型单轮直连返回结果；用户确认媒体计划后，复用公共媒体链。它不是 Chat 的子页面，也不属于文、武、创、道任何模式。

```text
用户字段 + 原始附件 + 选择的模型 + 指定 Skill
  -> 单轮直连模型请求（无工具、无隐式上下文）
  -> 当前结果 + 项目内定位记录
  -> 用户确认 MediaPlan
  -> 公共 CreationPanel -> mediaTaskStore
```

## 2. 已实施的独立边界

### 2.1 独立入口和挂载

- Rail 的“电商”入口直接激活 `EcommerceWorkbench`，不读写 `chatModeStore`，不切换创模式。
- 电商激活时 `ChatPanel` 不挂载，使用 `v-if`/`v-else-if` 选择电商工作台，不能以 `v-show` 隐藏 Chat 当作独立。
- 移动端也直接挂载 `EcommerceWorkbench`，不先进入 Chat。
- 离开或进入 Chat 不创建、恢复或清空电商运行；两边只共享应用壳、项目选择和公共服务。

### 2.2 单轮直连请求

`singleTurnWorkbench` 的模型请求固定为一条 `system` 和一条 `user`：

- `system` 是当前 Skill 内容、输出合同，以及“只分析本次字段和附件”的边界；Skill 是静态专业规则，可以使用，但不能执行工具或读取文件。
- `user` 只含本次表单字段和用户原始附件。图片按原始附件合同发送，其他文件保留文件名和原始值。
- `tools` 恒为 `[]`，`allowToolCalls` 恒为 `false`。一次用户动作对应一次模型请求，流结束即结束。
- 不读 Chat 历史、创模式会话、项目文件、Wiki、最近任务、MCP 或 OpenCode 上下文；失败显示当前 Provider 的真实错误，不换模型、不转交其他模式。

### 2.3 共享能力不是共享运行时

| 公共能力 | 电商如何使用 | 不带入的运行时 |
| --- | --- | --- |
| 模型目录和 Provider 配置 | 挂载时调用 `fetchModels({ skipOpenCode: true })`，展示公共模型选择器 | Chat 当前模型、OpenCode 目录投影或 sidecar |
| Skill 内容 | 当前用户明确选择的静态领域规则进入本轮 system 消息 | Skill 工具、Shell、网络调用、文件读取 |
| Direct Engine / NewAPI 附件请求 | 复用既有请求、流式文本、取消和错误合同 | 对话历史、工具循环、MCP、自动换模型 |
| `MediaPlanCard`、CreationPanel、mediaTaskStore | 用户确认后提交公共媒体任务 | Chat 消息、创模式会话、自动追加模型上下文 |
| 项目文件服务 | 保存该次运行的定位记录 | 项目扫描、Wiki 注入、独立历史数据库 |

### 2.4 项目记录

每次已保存运行的唯一定位文件是：

```text
jc-media/ecommerce/<run-id>/record.json
```

记录包含 `runId`、动作、模型、创建时间、状态、输出、缩略图和错误。页面不再显示“反推历史”或“商品图历史”列表；当前成功的自定义运行只提供“定位文件”按钮。项目文件是可追溯记录，不是电商自己的第二套历史 UI，也不创建 `wiki/电商/运行/`、`wiki/电商/结果/` 或 Markdown 镜像。

媒体任务继续由公共 `CreationPanel -> mediaTaskStore` 负责提交、轮询、项目落盘和画布结果。电商通过既有事件更新当前页面状态；不把媒体结果写回 Chat，也不为电商复制媒体客户端或任务系统。

## 3. 当前功能边界

电商工作台保留三个真实入口：商品图、参考图反推、反推生图。用户可选择模型、选择符合受限 `workbench.json` 声明的 Skill、输入字段和上传素材；模型输出最终中文提示词或可确认的媒体计划。

比例、模型和媒体参数只在公共 `MediaPlanCard` 中按当前媒体模型能力显示和确认。模型不得自行提交付费媒体任务；用户点击确认后才进入公共媒体链。

电商本地 store 中仍有 `surface`、`draftsBySession`、`__ecommerce_pending__` 等历史命名。这些现在只是工作台内部草稿命名空间和任务索引，不参与模型请求、Chat 会话、创模式会话或网络合同。本次不为改名做无关重构。

## 4. 明确不做

- 不创建或复用 Chat 消息、`conversationId`、`creative_*`、`ses_*`、OpenCode sidecar 或模式切换动作。
- 不新增 HTTP/SSE 客户端、Provider 注册、媒体 API、任务轮询、画布或项目文件系统。
- 不扫描或自动注入 Wiki、文件树、项目资料、历史运行或最近任务；跨运行复用必须由用户在当前字段中明确提供。
- 不把结果塞回 Chat、`.raw` 或任何模式专属存储。
- 不自动更换模型、使用后备模型、调用工具，或把失败变成其他模式任务。
- 不为记录文件增加历史页、双写 Wiki 结果页或媒体结果回写迁移。

## 5. 验收与证据

### 5.1 已验证的结构性验收

1. `WorkspaceLayout` 的电商入口不调用 `chatModeStore.setMode`；电商与 Chat 使用互斥挂载，而非隐藏的 Chat。
2. `EcommerceWorkbench` 只使用公共模型目录，调用 `fetchModels({ skipOpenCode: true })`，不等待 OpenCode。
3. 单轮请求的 `tools` 为 `[]`、`allowToolCalls` 为 `false`，消息只由当前 Skill、字段和附件构成。
4. 自动回归、TypeScript、Web 与 Desktop 构建已在实施提交时通过；实现提交为 `63940fdf`、`46ef35aa`、`a7c72b9e`。

“删除文、武、创、道四个模式后电商仍可运行”是架构判据：电商不能依赖它们。当前没有物理删除这些仍服务于其他产品功能的模式；以运行时依赖和挂载隔离验证电商独立性，而不破坏其他功能。

### 5.2 仍待人工验收

- 确认一次真实付费媒体任务，检查公共任务状态、项目落盘和画布结果。
- 在 Web、macOS Desktop、Windows/Intel Desktop 完成各自人工路径。

## 6. 成功定义

只保留应用壳、公共模型目录、公共 Skill 内容、项目文件服务和公共媒体任务能力时，电商仍能完成：

```text
商品信息 + 图片 -> Skill 约束的模型直连 -> 当前结果/定位文件 -> 用户确认 -> 公共媒体任务
```

这条链不需要 Chat、文、武、创、道或 OpenCode 运行时，即为绝对独立工作台。
