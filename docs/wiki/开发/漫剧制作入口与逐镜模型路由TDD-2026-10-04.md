# 漫剧制作入口与逐镜模型路由 TDD

## 极简路由修订（现行）

用户确认先更新 [[开发/漫剧制作合同]] 再实施：删除漫剧入口旁提示词模型选择器及模型偏好传递；只保留漫剧启用状态。十个业务入口不变，沿用官方 SkillRegistry 与渐进读取，不新增分类器或自动流水线。

路由顺序：本轮指定 Skill／模型 → 续改原产物与格式 → 自然语言明确交付物 → 明确新手求起步 → 其余新创作任务默认 H3。新手只建议当前一步；明确“带我做”且材料足够才执行第一步，不自动付费生成或推进整套项目。旧 `videoModel` 可留在旧数据中但不再读取或传递。

验证目标：选择器与状态链无残留；普通对话不收到漫剧设置；旧偏好不覆盖新请求；规则包含自然语言交付物、原格式续改、新手授权与非自动阶段；白名单和原有媒体提交边界保持。

本次验证：路由／导航目录／Harness 定向 67/67；官方内置 Skill 作用域 4/4；含工作台定向 164/165，唯一失败为既有文件树“新建窗口”旧断言。完整 focused 1795 项：1776 通过、1 失败、18 取消；取消项为未改动移动客户端补读重连用例的待定 Promise，单独运行同样 15 通过／18 取消。Vue TypeScript、Vite 构建、Desktop 产物审计、Skill 校验器、资源引用与索引、差异检查通过。

以下为初次实现证据，其中界面模型偏好已由本节及现行合同替代。

## 用户决定与边界

- 输入框下沿、权限右侧增加“漫剧制作”，直接选用 `jc-manju-zhizuo`。
- 将原 H3 总路由器改名并扩展为通用入口；原 `jc-daoyan-fenjing` 改名为 `jc-seedance`，保留验证过的导演表达与专项参考。Seedance 时间戳可有可无，用户要求优先。
- 前面八个制作 Skill 保留原有规则，模型只在最后一步按用户指定镜头或片段选择。H3 用 `h3-prompt-writing`，Seedance 2.5／SD2.5 用 `jc-seedance`；同集同轮可以混用。
- 界面选择只是当前未点名片段的默认值。用户本轮明确要求优先，可以随时换模型，不要求重做已有资料、风格、资产或工程台本。
- 默认写提示词；生成仍需现有影音能力及用户明确要求。路由器只提交到产品队列、不等待或轮询，产品后台的既有处理不变。

## 根因与复用

单纯给输入框插一句调用请求无法维持路线，也无法避免同名本地 Skill 覆盖产品内置版本。复用现有 `selectedSkillNames`、Harness 原生 `/skill-name`、点名后的通用 Skill 工具掩码、对话导航目录和 `public/skills` 打包链路。

增加一个随资源打包的 `manju-route.json` 清单，由 UI 与 Harness 共同读取。当前模式中的 @Skill 候选限定为路由器及十个子入口；Harness 在当前 agent 的 SkillRegistry 层登记确切内置版本，优先于项目或用户同名版本。模型上下文只注入点名入口，其他指令及专项资源由路由器按需读取。不是一次性把十一份全文塞入每轮上下文。

普通对话继续使用原来的 Skill 扫描和工具。退出漫剧路线后释放本 agent 的内置登记；不会改写或删除个人 Skill。系统文件能力与付费生成权限沿用原开关。

## 验证目标与已执行检查

1. 未发送前的选择在重开对话后恢复，新对话不继承；退出后不会被旧轮次重新启用。
2. 本次默认模型提示明确允许用户按镜头覆盖、同轮混用和可选时间戳，且普通对话不收到此提示。Session 可见用户正文不包含内部路线设置。
3. 两个末端入口均随包可用，同名本地定义不能覆盖当前模式的内置定义；普通对话不受影响。缺包或不兼容的同时点名在登记前报错，不留下半套状态。
4. 用已安装官方 `SkillRegistry` 与 `createScope` 验证真实登记、查询、同名优先级及退出释放。SDK 补丁连续运行两次结果一致。
5. 内置清单、目录、索引、引用资源及个人源文件一致；TypeScript、Vite 构建和 Desktop 产物审计执行。

具体测试统计和剩余边界见本轮 `hot.md`、`log.md`、来源索引记录。通用 Skill Creator 校验器不支持部分原 Skill 的 `triggers`／`compatibility` 扩展字段，本轮保留这些既有字段；包身份与资源按产品合同检查，没有为迎合该校验器改写前面的 Skill。
