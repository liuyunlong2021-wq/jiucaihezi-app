## 3. 现有唯一路径合同

以下相对实际唯一Wiki根；列的是当前工具实际路径，不是本轮新目录。资料版本通过`research_version=original/adapted`决定；省略仍走旧路径，不能因为兼容字段可省略就混用版本。

| 归档类型 | 当前路径 |
| --- | --- |
| source_material | `原始材料/<作品>/原文.md`；来源只创建，同内容重试幂等，不覆盖不同原文 |
| story_summary / episode_summaries | `项目资料/<原作或改编版>/故事梗概.md`、`分集梗概.md` |
| character_bio | `项目资料/<原作或改编版>/人物小传/<人物>.md` |
| story_background / world_rules | `项目资料/<原作或改编版>/故事背景.md`、`世界规则.md` |
| scene_research / prop_research | `项目资料/<原作或改编版>/场景/<场景>.md`、`道具/<道具>.md` |
| event_timeline / research_coverage | `项目资料/<原作或改编版>/事件线与发展阶段.md`、`阅读覆盖.md` |
| project_overview | `改编方案/项目总纲.md` |
| adaptation_episode_plan | `改编方案/分集规划.md` |
| screenplay | `剧本/第001集/分集剧本.md`等；工具填episode_number |
| production_progress | `制作进度.md`；只导航、状态和下一步，不替代正文 |

原作分集梗概不是改编正式分集规划。短剧场景/道具资料目前叫“场景”“道具”，不直接套漫剧的“场景说明”“道具说明”路径。

## 4. 逐Skill读写合同：现状与精准化建议

所有步骤都理解用户本轮消息，先沿真实index定位；事实依据必须落到正文。修订目标先读原文，保留未改部分。相同版本本轮读过可复用；文件修改后重读。以下“应明确”是下一阶段要补齐的合同，不表示当前运行时已强制执行。

### A. 项目资料 `jc-xiangmuziliao`

**已有：**按原作顺序分批阅读、同批提取各类资料；区分原文明示/推断/未知；记录覆盖；短剧只提取换皮所需内容，不预做正式建议分集。人物关系放小传内，关键场景道具各有权威档案，普通临时物不另建一页。

**应明确读取：**本轮指定来源文件及章节/段落范围、已有原作阅读覆盖、当前批次涉及的既有原作资料。保存原文不等于已经通读；增量提取不按每个人物/道具重读全书。

**输出：**原作版梗概、小传、背景/规则、必要场景/道具、事件线和阅读覆盖，使用现有research类型与original。缺少原文或后文时列具体范围，不编结局；不自行输出另一份正式分集规划。

**缺口：**应用内工具类型已明确，但短剧缺少像漫剧一样集中列出的精确路径与读取示例；下文通用资料场景仍有小说建议分集的说明，需要明确短剧分支优先级，不能把通用分支当成本次要求。

### B. 改编策划 `jc-duanju-cehua`

**已有：**六类可组合换皮方向、核心梗、人物关系/背景/规则等替换；保留原文吸引力。未授权的剧情不改；不因换皮自行重编人物命运。未变化事实关联原作，不复制整套资料。

**应明确读取：**本轮希望改变和保留的内容、原作故事梗概、相关原作人物/背景/规则/场景道具；涉及争议或等价替换的具体原文。已有项目总纲及改编版资料实际存在时先读再改，不重复选向。

**应明确读取：**有效项目总纲与必要新版资料、本次规划范围的原文正文和必要前后文、已有正式分集规划、已成稿集及邻集状态。原作覆盖和梗概只辅助定位，不能代替取材原文。修订整份规划时完整读取目标文件，保留其他集的规划。

## 6. 建议确认的最小业务合同

1. 是否沿用现有忠实重组/换皮边界：未授权内容继承，实质改变按用户范围执行；原作与改编版不复制未变化事实。
2. 是否保持一份正式分集规划，用稳定集号定位条目；不要先新增每集规划副本和第二套大纲。
3. 资料、规划与正文各自的精准输入是否按§4落实；新Wiki只补原作/改编版导航，具体文件按内容创建。
4. 默认规格继续由项目总纲承载，用户要求优先；正文中的核验说明是否保留同文，或另放现有进度/交付说明，另行确认。

确认后按“目录/类型合同→各Skill精确输入输出→缺陷测试与最小守卫→一集改编与一次定向修改验收”实施，不提前改上下文管理或增加流水线。
