# 通用记忆工作台 Skill 核心插件与统一插件架构 SDD

> 日期：2026-09-01  
> 状态：已实施，待真实平台验收  
> 范围：模型基础链路、Skill、文件、MCP、媒体、3D、Terminal 插件边界  
> 替代：领域专用 Agent、专用模型计划和并列 Agent 设计

## 1. 核心结论

产品只有一个基础 Agent Loop，最小输入输出关系是：

```text
用户信息 + 模型 = 输出
```

所有其他能力都是在这条基础链路上的插件：

```text
用户信息 + 模型 + 插件 = 带插件能力的输出
```

Skill 是产品最核心的插件。Skill 不只是提示词，也不是被动参考资料；Skill 的规则可以要求并驱动其他插件完成任务。

```text
Skill
  -> 规则、流程、格式、质量标准
  -> 声明需要的工具
  -> 驱动文件、MCP、媒体、3D、Terminal 等插件
  -> 根据真实工具结果继续完成任务
```

项目文件不是 Agent。Markdown、JSON、图片和其他资源都只是文件，不拥有独立模型循环、独立 JSON 协议或独立任务调度器。

## 2. 产品模型

### 2.1 基础链路

没有插件时，程序只负责：

1. 接收用户消息和必要的对话上下文。
2. 选择模型并发送请求。
3. 返回模型输出。

基础链路不读取 Skill、项目文件、MCP、媒体任务或历史资料，也不注入插件工具。

### 2.2 插件组合

有插件时，程序在同一条模型循环上增加插件规则、工具和资源：

```text
用户信息
  + 选中的 Skill 正文
  + Skill 声明的工具
  + 用户显式追加的插件
  + 真实插件 Observation
  -> 模型输出
```

插件之间没有 Agent 层级。Skill 是核心编排来源，但工具执行仍由各插件 Runtime 负责。

### 2.3 Skill 的权威性

选中的 Skill 对本轮任务拥有最高业务规则优先级：

- Skill 决定任务步骤、方法、输出格式和质量要求。
- Skill 可以声明文件、MCP、媒体、3D、Terminal 等工具。
- Skill 声明的工具必须进入本轮可用工具集合；不能因为用户没有重复点击对应插件而静默禁用。
- Skill 要求删除、移动、写入或调用外部服务时，程序必须执行、请求确认或返回真实不可用错误，不能擅自跳过。
- 工具不存在、未连接、平台不支持、路径越界、费用或安全策略不允许时，程序返回真实失败；不得伪造成功。

业务规则服从 Skill，程序安全边界不被 Skill 内容覆盖。两者不是同一层权限。

## 3. Skill 插件合同

### 3.1 Skill 包

每个 Skill 包至少包含：

```text
skills/<name>/SKILL.md
```

`SKILL.md` 包含标准 frontmatter 和正文。工具依赖使用机器可读的 `allowed-tools` 声明，正文负责解释如何使用这些工具。

示例：

```yaml
---
name: file-architecture
description: 设计并创建项目知识文件结构
triggers:
  - 创建项目结构
allowed-tools:
  - read
  - write
  - mkdir
  - edit
---
```

### 3.2 工具声明规则

- `allowed-tools` 是 Skill 的可执行能力合同，不是建议文本。
- 声明的工具按原名解析，支持内置工具、MCP 工具、媒体工具和 3D 工具。
- 工具声明无效、工具不存在或声明格式错误时，Skill 加载失败并明确报告原因。
- Skill 正文要求但 `allowed-tools` 未声明的工具属于 Skill 包错误，不由程序猜测或静默补全。
- 用户显式选择的插件可以追加工具，但不能削弱 Skill 已声明且平台可用的工具。

### 3.3 Skill 加载

Skill 选中后：

1. 加载完整 `SKILL.md`。
2. 解析 `allowed-tools`。
3. 校验工具是否注册、平台是否支持、连接是否可用。
4. 将 Skill 规则和合法工具集合注入同一模型循环。
5. 工具调用结束后把真实结果返回模型，继续服从 Skill 完成任务。

Skill 不隐式加载另一个 Skill，除非当前 Skill 明确声明并且产品允许 Skill 组合。

## 4. 插件分类

| 插件 | 提供内容 | 典型工具 |
| --- | --- | --- |
| Skill | 方法、规则、流程、格式和工具声明 | `skill` 资源加载 |
| 文件 | 用户授权的项目文件范围 | `read`、`write`、`edit`、`mkdir`、`move`、`delete` |
| MCP | 已连接外部服务 | `mcp__<server>__<tool>` |
| 媒体 | 文档、图片、音频和视频生成/导出 | 现有媒体工具 |
| 3D | `.jcscene` 创建、编辑和导出 | 现有 3D 工具 |
| Terminal | 用户授权的命令执行 | `terminal` |

所有插件共用：

- `runDirectChatCompletion`
- 工具 schema 校验
- 工具执行结果格式
- 取消和重试边界
- 审批机制
- 平台能力检查
- 用户可见状态回执

不得为任何插件新增独立 Agent、独立 Provider、独立循环或独立 Receipt 协议。

## 5. 文件插件边界

### 5.1 文件是唯一对象

项目内的知识资料、脚本、配置和产物都通过文件插件处理。目录是目录，页面是文件，不建立知识库专用抽象。

文件插件不拥有领域 Agent、专用模型 JSON、专用状态机或自动内容编排器。内容如何组织、如何生成文件、如何维护导航，由 Skill 的任务规则决定；程序只执行合法文件操作并返回真实结果。

### 5.2 文件安全边界

删除领域抽象不等于删除文件安全能力。程序仍必须保留：

- 用户授权目录范围限制
- 相对路径和越界校验
- 用户授权和必要确认
- 文件写入失败和取消处理
- 平台文件服务的真实错误
- 必要的写后存在性验证

这些是通用文件 Runtime 责任，不是领域 Agent 责任。

## 6. 统一执行流程

```text
用户消息
  -> 解析显式插件和选中 Skill
  -> 加载 Skill 正文与 allowed-tools
  -> 合并用户追加插件
  -> 求交集：已声明工具、已注册工具、平台可用、连接可用、安全允许
  -> runDirectChatCompletion
  -> 工具调用
  -> 真实 Observation
  -> 模型继续执行 Skill
  -> 输出和 Receipt
```

工具集合是程序确定的不可扩大集合。模型不能返回新的 Skill、插件或权限集合来扩大本轮能力。

插件工具调用不需要经过领域特殊分支，也不需要把模型输出转换成第二种中间计划。工具本身的参数 schema 就是调用合同。

## 8. 测试合同

必须先写红灯，再删除旧实现。

### 8.1 基础链路

- 无插件请求只发送用户信息和基础模型请求。
- 无插件请求不读取 Skill、文件或历史资料。
- 无插件请求不暴露任何工具。

### 8.2 Skill 能力

- Skill 声明 `write/edit/delete` 时，工具真实可用。
- Skill 声明 MCP 时，MCP 工具进入工具集合并可执行。
- Skill 声明 3D 时，3D 工具进入工具集合并可执行。
- Skill 声明媒体时，媒体工具进入工具集合并可执行。
- Skill 声明的工具不可用时返回真实错误，不静默降级。
- Skill 选中后不全量开放未声明工具。

### 8.3 文件能力

- 文件创建目录通过 `mkdir`。
- 文件创建和修改通过 `write/edit`。
- 文件删除和移动通过 `delete/move`，遵守确认和路径边界。
- 文件操作不越过用户授权目录。

### 8.4 组合能力

- Skill + 文件共用一个模型循环。
- Skill + MCP 共用一个模型循环。
- Skill + 3D 共用一个模型循环。
- Skill 可以在同一任务中按规则连续调用多个已声明插件。
- 任一工具失败或取消时，模型收到真实 Observation，不伪造成功。

## 9. 迁移顺序

1. 增加 Skill `allowed-tools` 解析和工具声明测试。
2. 让选中 Skill 声明的工具进入现有通用循环。
3. 增加 Skill 驱动文件、MCP、3D、媒体的组合回归。
4. 删除领域专用入口预读。
5. 删除 `wikiAgent`、`wikiTwoPhase`、`wikiPlans` 及无调用者的 `taskProtocol`。
6. 将领域文件访问迁移到普通文件服务并删除 `wikiRuntime`。
7. 更新当前架构文档和测试；历史文档保留为历史证据，不作为当前合同。

每一步独立提交；任何真实模型或跨平台失败只回滚当前步骤，不恢复 WikiAgent 或第二套模型协议。

## 10. 完成定义

1. 基础链路可以独立完成“用户信息 + 模型 = 输出”。
2. Skill 是唯一核心业务插件，可以声明并驱动其他插件工具。
3. 项目知识资料与其他项目文件使用同一文件插件，不存在领域层。
4. 所有插件使用同一个 Agent Loop、工具调用协议和真实结果协议。
5. Skill 声明的工具不会被静默禁用，未声明的工具不会被全量开放。
6. 生产代码不再包含领域专用 Agent、领域专用模型计划或领域专用 JSON 协议。
7. 用户现有项目文件、Skill、MCP、媒体和 3D 能力不因架构收缩而丢失。
