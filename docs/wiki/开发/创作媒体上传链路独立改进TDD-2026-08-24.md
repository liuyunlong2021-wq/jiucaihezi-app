# 创作媒体上传链路独立改进 TDD

> 状态：已实施安全与路由修复，Base64 性能项暂缓
> 日期：2026-08-24
> 范围：创作面板媒体上传与 Gateway 部署合同

## 1. 决策

审计后只保留两个确定性实施项，Base64 作为后续观察项：

1. Gateway 临时媒体上传必须校验真实凭据，而不是只判断请求头是否存在。
2. Gateway 代码中的媒体路由必须纳入部署配置和自动回归测试。
3. Base64 延迟转换暂不进入本 TDD，待单独测量后立项。

本 TDD 不引入 Cloudflare R2，不为 Boyesir 改造上传架构，不改对话框协议，不改变现有 `assetFlow` 分流合同。

## 2. 当前根因

### 2.1 鉴权根因

`gateway/src/index.js` 的 `requireMediaUploadAuth()` 仅检查 `Authorization` 或 `X-API-Key` 是否非空。任意伪造一个请求头即可进入上传处理，不能证明用户已登录或拥有有效 API Key。当前创作上传客户端只通过 `buildGatewayHeaders()` 发送 NewAPI 工作台 Key，不发送 `X-JC-Session`；因此不能简单改成“只接受 Gateway session”，否则会直接破坏现有创作上传。

### 2.2 部署合同根因

Gateway 代码实现了 `POST /api/creations/uploads` 与 `GET /media/creation/:token`，但 `gateway/wrangler.toml` 的显式 routes 未列出这两个路径。当前根域路由可能覆盖它们，但没有部署级合同测试，配置变更或 Cloudflare 路由收紧时可能出现生产 404。

### 2.3 Base64 性能项（暂缓）

`CreationPanel.vue` 的动态 AI 应用字段会把本地文件转成 Data URL；ComfyUI 本地上传也明确依赖 Tauri `data_base64`。这可能放大内存和 IPC 占用，但现有字段合同以字符串为主，不能只改一个上传函数解决。先不在本 TDD 改动。

## 3. 对话框边界

对话框使用 `runMemoryChat()` 和 `buildDirectMessages()` 独立发送链路：

- 文档附件优先解析为项目内可读文本。
- OpenAI 兼容的视觉、音频和文件消息按协议使用 `data:` URL 或 Base64。
- 对话框当前不调用 `/api/creations/uploads`。

因此本 TDD 的实施不得改变对话框附件格式、历史记录、文档解析或多模态消息合同。

## 4. TDD 验收设计

### 4.1 Gateway 鉴权

**红灯：**

- 无 `Authorization`/`X-API-Key`：返回 401。
- 伪造 `Authorization: anything`：仍返回 401。
- 无效 API Key：返回 401，且不得写入 KV。

**绿灯：**

- 有效 Gateway session 或经现有 NewAPI 认证边界确认有效的工作台 Key：允许进入文件类型、大小和 KV 写入校验。
- 鉴权失败不泄露 KV 是否存在、用户信息或内部错误。
- 现有登录、同步、健康检查行为保持不变。

凭据校验必须复用 Gateway 已有认证函数、服务端会话或 NewAPI 已存在的 Key 校验边界；在确认 NewAPI 校验端点前不得臆造新的 token 表或第二套用户身份系统。

### 4.2 部署路由

**红灯：**

- 静态合同测试能够发现 `wrangler.toml` 未覆盖上传和媒体读取路由。

**绿灯：**

- `wrangler.toml` 显式覆盖 `POST /api/creations/uploads` 与 `GET /media/creation/*`。
- Worker 路由测试验证方法、路径、鉴权、过期 token 和现有缓存行为。
- 部署配置与 README 的公开路由说明一致。

测试只验证路由合同，不宣称已完成 Cloudflare 生产发布；发布后需执行一次匿名 401、有效上传 2xx、读取 200、过期 404 的真实探测。

### 4.3 Base64 性能专项（另立 TDD）

暂缓。单独立项前必须先测量：动态 AI 应用字段、`newapi-upload`、`seedance-asset`、`rh-upload` 和 ComfyUI 各自的字节读取时机、峰值内存、IPC 大小及跨端差异。不得用 `assetFlow: none` 代表所有创作输入，因为动态字段可绕过该分流。

## 5. 实施顺序

1. 先为 Gateway 鉴权补红灯测试，再接入现有真实凭据校验。
2. 为 Worker 路由和 `wrangler.toml` 补红灯，再同步配置和文档。
3. 修正现有 Gateway 测试中的过时断言：健康检查应包含 `media.upload`；“旧路由已移除”不得再把真实存在的 `/api/creations/uploads` 当作 404。
4. 运行 Gateway 专项、focused、TypeScript 和 `git diff --check`。
5. 只有真实部署探测完成后，才把生产路由标记为已验收；Base64 性能项另开 TDD。

## 6. 非目标与风险

- 不建立 R2 私有桶、预签名 URL、完成确认接口或生命周期清理。
- 不把对话框的协议级 Base64 误判为存储缺陷。
- 不合并四种 `assetFlow`，不为一次使用抽象新的全局上传层。
- 不在本 TDD 改造 `File/Blob`、动态字段或 ComfyUI IPC；这些改动需要独立测量和跨端回归。

## 7. 证据

- `gateway/src/index.js`：`requireMediaUploadAuth()`、媒体上传/读取路由实现。
- `gateway/wrangler.toml`：当前显式 routes。
- `src/components/creation/CreationPanel.vue`、`src/runtime/creation/creationMediaRuntime.ts`：Base64 性能项的审计证据，当前不实施。
- `src/utils/directMessageBuilder.ts`、`src/runtime/memory/memoryChat.ts`：对话框独立附件与消息合同。

本文件不记录生产部署或真实渠道生成结论；这些仍待外部验收。

## 8. 本地实施结果（2026-08-24）

- `requireMediaUploadAuth()` 已复用 Gateway session；无 session 时通过现有 NewAPI `/v1/models` 对工作台 Key 做真实有效性校验。
- 上游 Key 校验增加 5 秒超时；NewAPI 不可用返回 502，避免把服务故障误报为 401。
- 无凭据、伪造凭据和无效 Key 均在 KV 写入前返回 401；有效 Key 上传回归通过。
- `wrangler.toml` 已显式加入上传与媒体读取路由；README Routes 与能力说明已同步。
- Gateway 测试从原先 `34 passed / 2 failed` 收口为 `38 passed / 0 failed`。
- 生产只读探测 `GET https://api.jiucaihezi.studio/v1/models` 返回 NewAPI 的 `x-new-api-version` 和 `Invalid token`，确认该校验路径未落到 Worker；未执行真实上传或外部渠道生成。
- Base64、对话框和 R2 未改动。

## 9. CloudFlare-ImgBed 评估（2026-08-24）

用户提供仓库：<https://github.com/MarSeventh/CloudFlare-ImgBed>。

本轮 GitHub 页面、Raw 文件和仓库克隆均因网络超时未取得可验证源码，因此不把该仓库的具体实现、许可证或部署参数写成已确认事实。

基于当前产品合同，暂不部署该项目：我们需要的是带鉴权的短时图片/视频/音频上传和供应商可读取的临时 URL；引入独立图片床会增加第二套上传、认证、存储和生命周期边界，且不能证明覆盖视频、音频或现有 `assetFlow`。现有 Gateway 已提供所需能力。

只有在产品明确需要永久图片资产库、图片管理后台或公开 CDN 图片服务时，才单独评估该仓库；不为 Boyesir 或当前上传修复引入它。
