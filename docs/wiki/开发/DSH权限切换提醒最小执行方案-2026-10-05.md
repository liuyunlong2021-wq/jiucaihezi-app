# DSH 权限切换提醒：最小执行方案

> 2026-10-05；状态：已实施，自动回归完成，原生点击待验收。官方核对快照：`5badb15009ae1756c3afe0ae0cef1faafc290ccc`，本仓随包 DSH `0.2.0-rc.2`。本轮工程剧本时间码改动不属于本方案。

## 1. 已核实的差异

| 链路 | 官方 | 本仓当前 |
| --- | --- | --- |
| 选择当前会话权限 | 选择器执行当前 Session 的 `/permission <preset>`，从 `permissions` 投影读取生效值 | `choosePermission()` 主要更新页面和 localStorage；`alignSessionPermission()` 在下一次发送前执行命令 |
| 告知模型 | 沙箱、审批当前值进入运行时上下文；审批策略改变时 `approval.setPolicy(agent, policy)` 另注入来源明确的切换消息 | 已复用官方命令，但运行中按钮没有立即送达当前 Agent |
| 一次性授权 | `approval/request` 作用域 waterfall 等待应答；面板仅本次允许／拒绝，取消后旧答复失效 | SDK 路径没有审批应答器；`ask` 无应答器返回 `unavailable`，不会自动出现批准卡片 |
| 切换失败 | 命令失败显形，生效值来自宿主事实 | 页面先改显示值；权限 RPC 完成等待没有自己的超时／取消收敛 |

以上可解释部分“显示已切换但任务仍被拒绝”的问题。没有用户实际失败会话的工具事件，尚不能证明全部长时间运行均由权限导致；`unavailable` 本身立即拒绝，模型反复尝试与请求悬挂须分别复现。

## 2. 产品合同

- 保留仅可查看、工作区内修改、完全权限三档。完全权限沿用现有官方确认文案和确认入口。
- 当前会话的生效权限以宿主 Session 为准；localStorage 只保存以后使用的偏好。选择后显示“切换中”，宿主确认后更新生效值，失败显示原因并保留原值。
- 运行中的权限切换送给当前 Session 的实际 Agent，不重建进程、不重发任务；新权限用于后续受限调用。已经执行的动作和已经启动的进程不承诺追溯撤销。
- 切换成功显示“已切换为……，后续操作使用新权限”。模型上下文与切换消息继续由官方服务负责，不另拼一段模拟系统提示词。
- 真正需要审批时显示工具、目标和理由，运行状态改为“等待你的授权”，提供“本次允许”“拒绝”；复用现有权限菜单作为“调整权限”入口。切换权限不等于回答已挂起的审批，卡片继续等待本次决定。
- 拒绝、停止、关闭运行、断连都必须结算待答请求；过期、跨会话、重复答复不能授权新的工具调用。DH 审批不使用旧内核的“始终允许”语义。
- 已经拒绝的工具不自动重跑；不得靠全文关键词猜测任务需要完全权限。仅依据明确审批请求和官方权限拒绝标记显示提醒，完整错误保留在工具步骤中；其他工具错误与模型／网络重试继续按现有链路处理。

## 3. 实施顺序与验证

### 第一步：先复现两个缺口

使用真实随包 SDK、回环模型替身与临时工作区：运行中从只读改工作区可写；工作区外操作请求一次性审批。先验证旧实现没有实时生效／没有审批面板；另外复现切换 RPC 不返回时停止操作能否收敛。

验证：红测来自真实工具调用、Agent 和通信，不能只检查源码字符串。

### 第二步：接通实时切换

- `src/services/deepSeekHarness.ts`：复用现有权限 RPC，新增对当前活动运行的切换入口和生效状态回执；权限退出 `runtimeKey`，作为 Session 状态处理，启动默认仍由 `DSH_PERMISSION_MODE` 配合发送前对齐负责。
- `scripts/prepare-deepseek-harness.mjs`：保留官方 `/permission` 命令执行路径，返回宿主派生的实际权限；需要订阅当前生效值时经同一 SDK 桥转发官方权限事件／投影，不手写权限事件。
- 权限请求使用可取消、有限等待的请求生命周期；复用现有超时机制，无现成机制时采用启动链已有的 15 秒标准。超时可能发生在宿主已经写入后：读取实际权限再确认显示，不能谎称已回滚宿主。
- `MemoryWorkbench.vue`：复用菜单和完全权限确认，只补切换中、成功与错误提示。无当前 Session 时只更新新任务偏好；加载已有 Session 时读回生效权限。

验证：同一 Agent、同一任务实时切换；同档不重复写事件；失败不伪装成功；超时可停止；恢复旧会话、跨会话及连续切换不串状态，最后的宿主生效值决定显示。

### 第三步：补一次性审批通信

- 在 SDK 所拥有的 Agent scope 挂声明依赖的轻量插件，监听官方 `approval/request`，通过现有 JSON-RPC／runner 通道传出并接回答复；不接入整套官方 React Web 客户端。
- `runner.mjs`、`deepSeekHarness.ts`：增加审批请求／答复桥接，使用运行、Session、Agent、请求与工具调用身份关联；宿主只接受 `allowed-once`／`rejected`，取消结算 `cancelled`，通道不可用结算 `unavailable`，沿用官方结果词汇。
- `desktopConversationRuntime.ts` 与 `MemoryWorkbench.vue`：复用现有运行级 approval 状态和卡片；DH 请求只提供本次允许／拒绝，区分旧内核审批，保留其原有功能。
- 请求由宿主 Agent 的取消信号与插件生命周期释放，不靠 Vue 页面卸载销毁。官方 `approval/asked`／`approval/decided` 仍由官方服务记录，不由界面补造。

验证：本次允许只释放关联的一次操作，不改变长期档位；拒绝不循环弹同一请求；停止后旧批准无效；多个会话不串审批；视图重挂仍能回答；断连／销毁可收敛。不覆盖已启动进程的行为，不把提权确认当作一次性授权。

### 第四步：回归与真实验收

回归三档限制、已有会话恢复、停止、工具时间线、模型重试、漫剧 Skill 作用域，以及 SDK 准备脚本幂等性。Desktop 真正点击验收“等待授权 → 本次允许 → 同一任务继续”和“运行中切权限 → 后续工具读取新档”。Windows 与 Intel Mac 未真实执行前不得登记已通过。

## 4. 范围

只补权限状态、提醒与审批闭环；复用现有通道、菜单、确认框和运行状态。此次不增加第四档、任务语义预判、自动提权、自动重试工具或新的权限管理产品。SDK 需要的适配继续集中在现有准备脚本与 runner；不直接手改 node_modules。

## 6. 本次实施与验证记录

- 权限退出 runtime key；菜单经当前宿主执行官方命令，回读派生权限后显示成功。15 秒控制请求期限覆盖发送等待和响应等待，停止信号可取消；回执丢失时回读已提交的真实状态，不假装回滚。
