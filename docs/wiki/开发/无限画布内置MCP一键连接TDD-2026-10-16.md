## 3. 接入合同

### 3.1 内置配置与运行时

固定 `id=infinite-canvas`、中文名「无限画布」、Desktop stdio。首期桥接基线固定 `@basketikun/canvas-agent@0.6.0`，MCP 参数为 `['-y', '@basketikun/canvas-agent@0.6.0', 'mcp']`，HTTP 服务使用相同版本去掉末尾 `mcp`。不用 `@latest` 让上线行为随上游漂移。

MCP 进程与 HTTP 服务是两个进程：只添加卡片或只 `tools/list` 成功都不等于画布可操作。首期复用现有 Node/npx 检测和安装引导，不新增 Node 下载器、不假设 Harness 随包 Node 已带可供 npx 使用的 npm。发布前核对该版本及传递依赖在三种桌面目标上的实际运行要求。

新增一个画布专用连接服务协调 native bridge 和现有 MCP client；普通 MCP 仍走原路径。原生侧只补需要的生命周期与安全读取，不拆通用服务管理平台。

### 3.2 一次连接的顺序

1. 原生侧读取 `~/.infinite-canvas/canvas-agent.json` 中已有连接信息，并检查该 loopback 服务；不把 token 写入 App 的 MCP 普通持久配置。
2. 服务存在且协议匹配、认证读取成功则借用，禁止再次启动占用端口。服务不存在才启动固定版本 HTTP 进程，捕获真实 URL/token；优先用已有配置路径，不重置 token、origins、workspace 或线程历史。
3. 健康检查通过且 token 验证成功后，调用现有 `connectMcpServer()` 的 SDK 连接和工具发现路径。原生层记录服务为 App 启动或外部借用。
4. 首次用户点击连接时打开固定可信站点：`/canvas?mode=new#agentUrl=<encoded>&agentToken=<encoded>&agentMode=tools`。凭据使用 URL 编码，仅在 fragment；不放查询参数、终端输出、聊天、遥测或诊断日志。
5. 网页消费并清理 fragment，建立 SSE，上报当前画布；保留页面会话的 tools 模式，刷新不回到 Codex 初始化。
6. App 显示两层实际状态：「MCP 已连接，等待画布」与「画布可操作」。后者至少需要认证读取返回有效 `projectId` 和节点/连线数组；`/health` 的 `hasCanvas` 不是完整就绪证明。

已有画布可用时首次连接优先复用，不自动创建另一个。恢复已启用扩展只准备服务与 MCP；打开网页仍由用户点击。「打开画布」在已有连接时不强制 `mode=new`，复用站点现有 recent/choose 导航能力；不要为了定位已有 Chrome 标签页新增浏览器自动化。

用户已有自定义无限画布 MCP 时保留原记录与 ID、参数、对话引用。内置连接前可识别同一固定包入口并复用其连接记录；无法确认时不自动合并、不按显示名覆盖，不启动第二个 HTTP 服务。默认恢复仍按原配置执行。

### 3.3 仅连接工具的网页模式

现有网页 `hello` 后可能调用 `/agent/codex/threads/reset`，连接后还会获取 Codex 历史、Skills 与模型。`headless` 只隐藏 UI，不能代替工具模式。

新增 `agentMode=tools` bootstrap 字段与页面会话状态；仅保留连接、快照、工具执行、确认和撤销，跳过上述 Codex 请求、聊天初始化和发消息入口。连接提示使用「韭菜盒子已连接」或「画布工具已连接」，不再误标「Codex 已连接」。原 Codex 模式保留全部功能，用户可显式切换。

本期无须改变 bridge HTTP/MCP 协议版本：新模式属于网页引导字段，协议仍按实际 `hello.protocolVersion` 校验。HTTP 服务当前可能恢复配置中已有的 Codex 线程；该后台准备的失败不能成为外部 MCP 的就绪条件，App 不等待 `conversation.status=ready`。新用户无已有线程且 tools 页面不发 Codex 请求时不需要登录 Codex。若测试发现现有服务后台恢复实际阻断外部工具，先在画布仓库修复并产出固定版本，再更新 App pin；不能给旧 npm 包传尚不存在的启动参数。

### 3.4 进程所有权与失败处理

- 多窗口并发连接使用原生侧单次启动协调；MCP 可按现有窗口连接，HTTP 服务每个端点仅一个。窗口重载不能重复起桥，也不能误杀其他窗口正在使用的桥。
- 断开/删除扩展清除对应工具并释放使用权；最后一个使用方离开时回收 App 自己启动的服务及其进程树。借用服务只断开自身 MCP，不能杀用户终端、Codex 或其他客户端启动的进程。
- App 退出与安装升级收尾接入现有原生进程回收路径；页面刷新不重新下载包，不旋转 token。启动中取消/关窗也必须收尾，禁止后台成功后重新打开网页。
- 缺少 Node/npm、npm 下载失败、端口被无关程序占用、token 无效、协议不匹配分别返回原因。端口冲突不杀进程、不随机换端口；旧配置损坏不覆盖原文件。
- 网页断开显示等待/断开，操作错误原样回传；不能因生图结果不确定而重提付费任务，不能把工具提交成功写成图片生成成功。
- 仅接受 loopback HTTP bridge 地址，网页打开目标固定为本产品域名；不接受外部返回的任意网站作为凭据承载页面。token 留在本机连接链路，不进入模型工具描述。
- 沿用现有工具超时，不增加后台轮询、重试次数、并发上限或下载超时常量。新增行为边界确有需要时单独说明，按仓库规则确认；本 TDD 不以猜测数值补默认值。

### 3.5 Agent 使用说明与权限

内置工具被当前对话选中时，通过现有工具描述补充简短规则，且必须经 Harness MCP 代理到达真实模型；仅在设置页加文案不算完成。保持服务器 ID 白名单及对话 MCP 提及，不因内置就把所有工具塞入每条普通聊天。

1. 先用 `canvas_get_state`，用户指向选区时读取 `canvas_get_selection`。
2. 明确要求在无限画布生图时调用 `canvas_generate_image`；视频/音频/文本使用对应 `canvas_generate_*`，批量节点与连线用 `canvas_apply_ops`。
3. 不因同名图片 Skill 缺少脚本或 `uv` 而阻断画布路线；明确选择其他 Skill/本地脚本的请求仍按用户指令执行。
4. 使用网页实际提供的模型 ID，包括必要的 provider 命名空间；用户明确型号不可用时返回原因，不静默换型号、不修改网页 API Key。未指定时保留画布既有默认行为。
5. 生成调用是提交；查询 `generation_get_status` 确认结果，失败展示真实错误。读取一次快照、创建配置节点或提交成功都不等于出图成功。

仍使用现有 App 工具审批和网页 `confirmTools`，不新增一套确认流程。新 tools 模式 bootstrap 不顺手关闭用户已保存的网页确认偏好；默认值与手动确认超时沿用现有实现。未连接或取消的操作不执行。当前快照可能截断长文本，媒体 `blob:` URL 也不能跨进程直接读取；本期不承诺完整长文/媒体二进制读取。

## 6. 真实桌面验收与交付门槛

1. 干净配置、有 Node/npm：点击一次连接；无字段填写、无终端操作；网页自动打开连接；对话选择无限画布后读到正确标题与选区。
2. 无 Node/npm：显示安装引导，安装后「重新检测并连接」可用；不报缺少 `uv`、不要求 Codex 登录，不把包下载失败误报为缺少 Node。
3. 服务已由用户终端/Codex 启动：复用；停用 App 扩展后原进程与用户浏览器标签页仍在。
4. App 自启服务：双窗口连接、重载、关窗、重启恢复和退出/升级收尾正确；重启不偷偷打开新网页/新画布。
5. 测试专用画布创建两文本节点并连线，修改、删除、撤销和刷新持久化；确认用户当前画布和项目文件未变化。
6. 用户授权的真实生成：明确在无限画布用指定模型生成，Agent 调用画布工具且网页出现结果；核对实际模型、状态及结果可查看。生成计费按真实请求记录，自动测试零付费。
7. macOS ARM、Intel Mac、Windows 分别登记结果，覆盖打包版 PATH、Windows npx shim、网页访问 loopback 的浏览器权限/CORS 与进程退出；未执行的平台留待验收。
