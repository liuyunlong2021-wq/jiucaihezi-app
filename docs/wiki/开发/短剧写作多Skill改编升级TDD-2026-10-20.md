# 短剧写作多Skill改编升级TDD-2026-10-20

## 目标与依据

用户确认：原作资料可复用；策划先建立新世界观、人物身份性格和关系，并联动场景、道具、事件线与发展阶段，再确定整体方案、分集规划和逐集剧本。场景道具按剧情重要性分层，不逐物重复通读。现行合同见 [[开发/短剧写作入口与Skill接入合同]]。

## 实施计划与验证

1. 锁定短剧路由装载和新旧资料隔离 → 新增回归先红，再接入共享路由清单与版本字段。
2. 拆分业务 Skill、补原作提取与制作交接 → 检查包内资源、原有文学写作规则与模式恢复。
3. 打通粘贴原文与固定归档 → 七万字级来源逐字比较、首尾歧义／跨轮失效／覆盖拒绝及重试检查。
4. 更新现行合同与导航 → 定向Node、focused Node、类型检查与差异检查；真实模型和原生人工验收另记。

## 根因与变更

原短剧只有 `jc-duanju + wiki-memory`，策划与落笔合在一份正文，不能通过短剧作用域加载项目资料Skill。原归档固定写入无版本的资料目录，无法同时管理原作与改编版；模型保存长文还需重新输出正文。

新增 `short-drama-route.json`、策划／分集／写作三份业务Skill。旧写作指标移入写作Skill；总路由只负责按需衔接。扩展现有 `jc-xiangmuziliao`，同次阅读补场景道具、事件阶段与覆盖。共享归档支持资料版本与新增类型，保留旧路径。来源按当前消息唯一首尾片段确定性截取，原文相同重试不重写。

Harness准备脚本更新来源快照，并在重跑时替换旧作用域方法和导入，避免重复声明或旧方法覆盖新方法。未新增代理、第三方依赖或固定流程执行引擎，语义阶段与确认状态由Skill和Wiki正文承接。

- 最终定向Node 35/35、工作台／导入／路由包149/149、7份宿主Skill校验、类型与差异检查通过。focused Node首轮2056通过／1跳过／1失败，为影音Grok型号与易红插件不匹配，未动相关已有改动。详情见本次 [[log]]；真实模型全篇理解、三集文学质量、桌面点击、跨平台安装包、生产发布均未执行。
- 来源保存只证明当前消息所选范围无损落盘，不证明用户粘贴前没有截断，也不证明任意模型能一次容纳完整长文。
