# 工程剧本合并短剧改编 Skill 方案（2026-10-29）

用户目标：**只保留一个改编专家 `jc-gongchengjuben`，产物只有「工程分镜剧本」**；短剧改编与漫剧制作共用它，漫剧侧不再把分集剧本转一遍。

用户明确收回的指令：**不去掉人物小传／场景说明／道具说明**。这三层中间物全部保留，本方案不碰 `materials` 契约。

## 1. 现状对账

| | `jc-duanju-xiezuo`（短剧第三步） | `jc-gongchengjuben`（漫剧 engineering） |
| --- | --- | --- |
| 入口 | `jc-duanju-pipeline` 的写作阶段 | `jc-manju-pipeline` 的 engineering 阶段 |
| 读 | 切分卡 ＋ 分集原文 ＋ 人物小传/场景/道具 ＋ 执行进度 | 来源剧本 ＋ 比例/风格 ＋ 人物小传 |
| 产物 | `episode_source_script` ＝ `项目资料/分集剧本/第N集分集剧本.md`（按场，带 `【场1 约40秒｜对白9秒＋其余31秒】` 与 `sources`） | `engineering_script` ＝ `剧本/<episode>/工程剧本.md`（逐镜台本） |
| 交付载荷 | `{adapted:{strategy, scenes:[{title,role,seconds,sources,text}]}}`，**程序硬校验**（见下） | 纯 Markdown，无载荷、无程序校验 |
| 白名单 | 仅 `short-drama` | 仅 `manju` |
| 归属阶段 | `adaptationStages` 的 `writing`（需 `项目资料/分集剧本` 或 `剧本/第NNN集/分集剧本.md` 存在且已登记） | `pipelineStages` 的 `engineering`（读 `style`／`source`／`cast` 门槛） |

`episode_source_script` 带 `adapted` 时由 `adaptedScript()` 做四类硬校验，这是短剧路线的护城河：

1. `sources` 的章节必须在目标章范围内，行号必须落在该章正文内且起止有序；`main` 场次还必须落在本集切分片段内（越界只能标 `cold`／`flashback`）。
2. 每场按正文重算对白秒（引号内字数 ÷4 ＋ 每段 0.5s 停顿），不得超过该场 `seconds`。
3. 全集总时长 ≤ 180 秒（`PLATFORM_MAX_SECONDS`）。
4. `cold`+`flashback` 合计 ≤ 25%。
   另外两条软警告：总时长不在本风格区间；与切分卡 `planned_s` 相差 >25%。

## 2. 目标形态

```
短剧改编（jc-duanju-pipeline）
  source → materials → scheme → cuts → writing ──► 工程分镜剧本（engineering_script）
                                                        │  每集一份，含场次出处与时间
                                                        ▼
漫剧制作（jc-manju-pipeline）
  plan → materials → style → assets → engineering ──► 已有则复用，不再重写
                                                        ▼
                                              prompts → complete
```

三条不变式：

- **一个 Skill**：`jc-gongchengjuben` 是唯一的改编与台本作者，`jc-duanju-xiezuo` 目录删除。
- **一个产物**：改编交付物是「工程分镜剧本」；`episode_source_script` 退化为「未改编集的原文直出」（程序仍能生成，漫剧仍能读），不再是改编稿主交付。
- **一套护栏**：出处行号、对白秒数、总时长、冷开场占比四项校验继续生效，只是挂到 `engineering_script` 上。

## 3. 三个决策（需你拍板）

**D1 护栏挂在哪**
- A（推荐）**迁移到工程剧本**：复用同一份 `{adapted:{strategy,scenes:[{seconds,sources,text}]}}` 载荷，`text` 里装逐镜台本；`adaptedScript()` 几乎不用改，只换产物与目标路径。镜头继承所在场次的 `sources`。
- B 只留在分集剧本：工程剧本无出处校验，改编稿必须先生成分集剧本 → 链路没变短，等于白合并。
- C 双产物：两样都出 → 与「只保留工程分镜剧本」冲突。

**D2 漫剧 engineering 阶段的行为**
- A（推荐）**本集已有工程剧本 → 直接复用并登记**，不重写；只有缺失或用户要求改时才重写。
- B 永远重写 → 用户抱怨的"再转化一遍"没解决。

**D3 「完整剧本（说明书式）」那套还留不留**
- `jc-duanju-xiezuo` 里有一节「用户明确要求写成说明书式完整剧本」的详细规则（三要素、逐招动作）。
- A（推荐）**并进来当「工程剧本的详细档」**，不再单列一套流程。
- B 直接删，只保留逐集改编。

## 6. 风险与应对

- **R1 工程剧本体积变大**：逐镜＋出处，单集 76 秒约 24 镜。对策：`sources` 只挂在场次头上，镜头不重复；正文保持"一句一个动作"。
- **R2 对白秒数统计口径**：`dialogueSeconds()` 只数引号内文字。工程剧本台词必须继续用中文引号，否则会被算成 0 秒而放行。对策：交付检查里加一条「台词必须带引号」，并在红测里锁。
- **R3 短剧侧无切分卡时无法改编**：`adaptedScript()` 依赖 `改编方案/分集清单.json` 与执行进度。短剧路线本来就有；但**漫剧路线单独用工程剧本时没有切分卡** → 必须保留"不带 `adapted` 的普通工程剧本"通道（现有行为），不能强制走载荷。
- **R4 漫剧 `source` 门槛**：已有工程剧本、没有分集剧本的项目，`rules.engineering_script` 的 `source` 会缺失。对策见 4.3-5，先红测再改。
- **R5 回滚**：S1／S2 纯文档可 `git revert`；S3／S4 必须保留 `episode_source_script` 原有通道不动，确保回滚后短剧路线照旧。

## 7. 本方案不做的事

- 不动 `materials` 阶段，不删／不改人物小传、场景说明、道具说明（用户已收回该指令）。
- 不改 `assets` 阶段的产物分工，角色仍是 assets 阶段一步出三格。
- 不改漫剧 `prompts` 阶段与视频模型契约。
- 不合并场景／道具／声音 Skill。
