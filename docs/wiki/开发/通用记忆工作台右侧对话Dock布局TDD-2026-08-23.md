# 通用记忆工作台右侧对话 Dock 布局 TDD

> 状态：已实施；自动验证和本地 Web/Tauri 核心交互通过，Desktop 多尺寸布局已由用户实测确认
> 日期：2026-08-23
> 分支：`0823fenqu`
> 范围：Desktop/Web 记忆工作台桌面布局；移动端继续使用现有抽屉/全屏布局

## 1. 用户目标

在查看资源预览或使用创作面板时，用户可以同时保留对话，并像 VS Code 一样自由调整对话区域宽度：默认舒适、可以缩到很窄、也可以拉宽；窄到不能承载完整对话时自动进入窄栏，而不是把文字挤坏。

## 2. 根因审计

当前 `MemoryWorkbench.vue` 的布局把聊天、资源预览都放在 `memory-main` 内，并在创作并排时用：

```text
项目树 280px | 对话 minmax(420px, 1fr) | 创作面板
```

`MEMORY_CHAT_MIN = 420` 同时承担“初始舒适宽度”和“不可缩小下限”两个职责；同时 `.memory-preview` 以绝对定位覆盖 `memory-main`，导致：

1. 对话无法收缩到 VS Code 式窄栏。
2. 创作面板打开时，中间区域被固定最小宽度挤压。
3. 文档预览无法和聊天同时操作；单改 Grid 列宽不能解决这个结构问题。
4. 设置抽屉虽然已是右侧浮层，但对话没有独立的停靠、恢复和紧凑状态。

本轮只调整工作台外层布局和 Dock 显示状态，不重写对话、资源预览、创作或设置业务逻辑。

## 3. 目标布局合同

### 3.1 桌面工作区

```text
无资源/创作：项目树 | 对话主区
资源预览打开：项目树 | 资源预览主区 | 对话 Dock
创作打开：    项目树 | 创作主区 | 对话 Dock
```

- `memory-main` 的聊天内容、顶部栏和 composer 整体作为右侧 Dock，不复制消息或输入状态。
- `.memory-preview` 和 `.memory-creation` 必须成为工作台外层的主区兄弟节点；不能继续用绝对定位覆盖聊天。
- 中间只存在一个主工作区：资源预览和创作面板二选一，不固定为三列。
- 创作主区使用 `minmax(0, 1fr)` 填满 Dock 之外的全部剩余空间；尺寸只由 Dock 左边界调整，不保留第二套创作宽度持久化和分隔条。
- 对话 Dock 只在资源预览或创作主区需要并行时停靠右侧；没有主区时聊天回到主区。
- 项目树仍可关闭；关闭后不改变 Dock 的宽度状态。
- 设置不进入主网格，继续作为右侧悬浮抽屉覆盖当前 Dock。

打开资源预览和打开创作面板必须互斥。切换到创作前先执行现有画布保存；切换到资源预览时关闭创作宿主，不丢失当前对话。

### 3.2 Dock 宽度与状态

宽度概念必须分离：

| 项目 | 合同 |
| --- | --- |
| 首次默认值 | 约 360px，仅用于首次打开或无历史值时 |
| 完整对话下限 | 约 220px；低于此宽度不再强行显示完整文字布局 |
| 窄栏宽度 | 约 56px；显示展开入口、状态和必要图标 |
| 最大宽度 | 由“可用宽度 - 主区最低可用宽度”计算；不再设置额外的 50% 上限 |
| 恢复规则 | 窄栏展开回上一次完整宽度；资源预览/创作切换后再次停靠也恢复该值 |

Dock 只有两种状态：

1. `expanded`：显示完整对话、消息列表和输入框。
2. `compact`：显示展开入口、运行/错误状态和必要图标，不渲染会溢出的标题与辅助文字。

完整态较窄时，顶部对话入口、新建对话和模型入口只隐藏文字并保留图标与原有触发行为；对话下拉菜单的内容、尺寸、行操作和滚动规则不改变。

拖拽从 Dock 左边界开始。宽度不小于完整态下限时保持 `expanded`；拖过下限立即吸附到窄栏宽度并进入 `compact`。从窄栏拖出或点击展开时恢复上一次完整宽度，不允许出现 `57-219px` 的半坏状态、负宽度或横向溢出。

### 3.3 响应式边界

- 桌面宽度足够同时容纳项目树、主区和 Dock 时使用停靠 Dock。
- 窗口不足时沿用现有响应式策略：先收起项目树；创作面板继续在现有 `max-width: 939px` 规则下全屏，不为本轮强行保留并排聊天。
- 主区最低宽度由资源类型决定；Dock 最大宽度只由该最低宽度和当前窗口计算，不得遮挡主区。
- 移动端不引入桌面三列和窄栏逻辑，保持现有对话主视图、创作全屏和设置全屏抽屉。

## 4. 非目标

- 不把文档、创作面板、对话固定成三列。
- 不复制一套新的聊天组件或消息状态。
- 不改变 Raw 对话持久化、媒体任务、文档编辑保存和创作画布保存链路。
- 不把设置改成主网格的一列，也不新增独立设置窗口。
- 不为未来多面板引入通用 Dock 框架；当前只有一个右侧对话 Dock。
- 不增加未读计数或通知系统；窄栏只复用现有运行和错误状态。

## 5. 红灯测试

实施前新增最小定向测试（优先放入 `src/components/memory/__tests__/memoryWorkbench.test.ts`，必要时补一个纯函数测试）：

1. 资源预览或创作打开时包含“主区 + 右侧对话 Dock”；`.memory-preview` 不再以绝对定位覆盖聊天，且不再以 `minmax(420px, 1fr)` 固定对话最小列。
2. 首次默认宽度与完整对话下限分离；默认值不是拖拽下限。
3. Dock 只有 `expanded` 和 `compact` 两态；宽度跨过阈值时吸附到窄栏，不渲染溢出的消息标题、模型文字或输入辅助内容。
4. 窄栏展开恢复最近一次完整宽度；资源预览/创作切换不重置用户宽度。
5. 最大宽度按“可用宽度 - 主区最低宽度”计算，主工作区保持 `minmax(0, 1fr)`，不出现横向溢出。
6. 资源预览和创作面板互斥；切换创作前仍调用现有 `flushCanvasSave()`。
7. 设置仍使用独立右侧浮层，打开设置不会修改主网格列宽或清空 Dock 状态。
8. 项目树关闭、窗口缩放和创作专注模式不会丢失 Dock 宽度状态；专注创作时 Dock 隐藏。
9. `max-width: 760px` 的移动端回归保持现有抽屉/全屏行为，不出现桌面 Dock 窄栏。

红灯必须先证明旧实现会因 `MEMORY_CHAT_MIN = 420` 和创作三列网格而失败，再进入实现。

## 6. 最小实施方案

1. 调整 `MemoryWorkbench` 外层 DOM/Grid：将聊天 `memory-main`、资源预览和创作面板设为可切换的主区/Dock 兄弟节点；复用现有消息、composer 和滚动状态。
2. 将现有创作拖拽分隔条模式复用于 Dock 左边界，新增一个完整宽度持久化值和一个 `expanded/compact` 状态。
3. 将“完整对话下限”和“窄栏宽度”作为两个常量；拖拽跨过阈值吸附到窄栏，不新增第三套渲染逻辑。
4. 窄栏只保留展开按钮、运行/错误状态和必要图标；不增加未读计数。
5. 保持 `MemoryMarkdown`、`CreationPanel`、`MemorySettings` 的现有业务挂载和保存链路；设置遮罩层级高于 Dock，创作专注模式隐藏 Dock 并继续全屏。

## 10. 实施结果

- `MemoryWorkbench.vue` 已将资源预览、创作面板和聊天 Dock 纳入同一外层布局。
- Dock 已支持 `expanded/compact` 两态、宽度持久化、拖拽吸附和移动端回退。
- 资源预览与创作面板切换前执行现有画布保存，失败时不切换主区。
- 首版曾用自指向 `.memory-workbench` 的 `Teleport` 移动预览节点；目标元素在组件首次渲染时尚不存在，打开文件后会打断 Vue 更新链路，连带造成设置、创作和文件打开看似全部失效。现已删除该 `Teleport`，预览直接作为工作台根节点的 Grid 子项，并增加禁止该结构回归的定向测试。
- 二次布局审计确认旧创作宽度拖拽与新 Dock 拖拽控制的是同一条边界，形成重复状态且会在宽屏留下空白；现已删除 `jcMemoryCreationWidth`、创作宽度状态及其监听，创作主区改为弹性填满。窄 Dock 顶栏按现有宽度状态显示图标，未改对话下拉菜单；Dock 边界增加常驻分隔线，文档大纲按文档容器宽度收紧。
- 并发审计确认资源切换必须复用同一次画布关闭 Promise，避免连续点击时丢弃后一次切换；预览与创作现共用 Dock 布局准备，窗口不足时先收起文件树，再校正持久化宽度。
- 层级审计确认 Dock 分隔条和紧凑栏只需局部 `z-index: 30`；设置抽屉/遮罩保持在其上方，避免浮层打开后仍可命中 Dock。
- 视觉复检将窄 Dock 顶栏的图标切换阈值提前到 `560px`，避免临界宽度出现无内容按钮；文档大纲折叠时退出 Grid 列并改为单列正文，只保留一个不占列宽的展开入口。
- 定向测试 `56/56`、TypeScript、`build:quick`、Web 产物审计和 `git diff --check` 已通过。
- 本地 Web 与 `pnpm tauri dev` 原生窗口均已实测：设置抽屉可打开、创作面板可挂载并填满中间剩余空间、窄 Dock 顶栏无文字截断、对话菜单保持原样、从创作面板点击文件可切换到资源预览，返回对话后设置仍可再次打开。旧 Vue 实例发生渲染异常后需硬刷新或重启，不能依赖 HMR 自行恢复。
- 用户已在 Desktop 多种 Dock 宽度下实测文档与创作布局，确认整体无明显问题；复检发现并修复临界宽度空白按钮及大纲折叠后空列。真实触控拖拽和移动端人工验收尚未执行。
- 2026-09-03 回归修复：对话切换和新建对话不再调用 `closePreview()`，也不清除 Markdown 编辑态或文档预览状态；只有用户关闭预览、打开另一中间资源、切换创作面板或切换项目才清理中间主区。根因是 `openResource()` 将 conversation 与 preview 共用清理路径。新增回归测试并通过 focused `1177/1177`；TypeScript、真实 Desktop/Web/Mobile 人工验收仍待执行。
