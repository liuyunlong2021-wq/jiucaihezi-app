## 1. 问题与目标

目前 Wiki 规则以 Skill 提供，但项目查询、来源校验、正式产物归档已是产品基础能力。其可达性仍耦合 Skill 选择：退出创作路线或未选 wiki-memory，可能同时失去索引预读、规则与归档工具。根因是基础能力的生命周期依附于业务 Skill，而不是缺少另一个保存工具。

终态：项目 Wiki 能力不依赖选择 Skill；三条创作路线继续决定内容生产步骤，原生 Wiki 负责资料与归档合同；官方 present 负责声明已有文件为本轮成果。用户可从同一对话打开剧本、图片、声音、视频和其他文件。保存、交付、用户确认是三个独立事实。

可验证目标：

1. 不选 wiki-memory，也能按项目索引查询和使用现有归档工具；不相关聊天不预读 Wiki 正文。
2. 漫剧、短剧、小说的现有来源、索引、草稿、确认、声音与分镜归档能力全部保留。
3. present 直接运行固定版本官方插件，不复制实现；交付历史可恢复，打开复用现有桌面入口。
4. 已有双链、媒体预览、文件树和创作路线操作保持可达，不重复显示同一成果。

| 能力 | 原生化后的合同 |

| 写入与索引 | 保留固定类型路径、先读后改、直属索引、双链校验、幂等及权限；未经要求不搬迁、改名、删除、覆盖 |
| 来源沉淀 | 保留故事与知识两套规则；机械结构拆分与语义分析两阶段；复用原生拆分，不自由写文件替代 |

| 记忆开关 | 项目 Wiki 与对话记忆区分；现有记忆开关继续控制对话记忆，不因原生化扩大历史读取 |
| 历史与个人 Skill | 不重写旧消息；旧 /wiki-memory 请求可识别为原生 Wiki 请求；不删除用户安装的同名或其他 Skill |

## 4. 原生化设计

### 4.1 生命周期与规则加载

复用官方插件与系统提示接口，为每个项目 Agent 注册原生 Wiki 能力，与创作路线 Skill 插件分离。注册一次、释放一次，恢复、切换路线、切换项目及重建 Agent 时不得残留旧项目状态或重复工具。规则资源随包分发，缺资源显式失败，不回落到过期 Skill 或静默丢工具。

轻量基础规则说明 Wiki 能力、索引与写入边界；故事/知识沉淀等长规则由相关操作按需提供。业务 Skill 改为引用原生合同，不再要求调用 /wiki-memory。不得将完整 Wiki 正文或两份长规则无条件塞进每次请求，也不另造模型意图分类请求。

继续以现有项目上下文预读索引：三条创作路线及明确 Wiki 操作可预读；普通对话通过原生能力入口使用既有索引读取逻辑。根识别失败不阻断无关聊天；已有库缺索引时按现有错误/修复流程处理，不假装不存在。

原 Wiki 入口可沿用位置改为原生操作入口；不新建角色选择器或多套知识库开关。原生能力不受 Skill 排他选择误禁，但不扩大文件权限。

### 4.2 偏好与数据兼容

旧 skillNames 中 wiki-memory 仅作为兼容输入，读取后转成当前原生入口语义，不继续向模型发送失效 Skill 手势；不改已有历史消息。三路线互斥和其他 Skill 选择保持原行为。仅在新偏好成功保存后移除旧依赖字段；失败保留来源、可重试，不清空整个偏好。

原生规则不再通过同名内置 Skill 覆盖用户文件；个人安装内容仍可由原有 Skill 管理机制处理。旧入口兼容应在应用显式选择/命令边界处理，不能全局替换普通正文字符串。

## 5. 独立 present 与联动

### 5.1 工具与事件

按官方配置挂载 @deepseek-ai/dsh-tool-present，保留官方 schema、数量限制、路径验证、权限与 deliverables/presented 事件语义。不改工具去调用 wiki_save_artifact，不新增数据库成果表，不自行合成官方交付事件。

交付覆盖 Session 文件系统可访问的真实普通文件；不主动扩权。工作区外路径是否允许由官方 fs/权限裁决。目录、缺失文件、符号链接等以固定版本官方行为为准，宿主不能绕过校验。

### 5.2 Wiki 联动与展示

正式产物先调用现有归档工具，确认真实回执，再按需调用 present，路径必须来自回执。saved_with_warnings 可交付已存在正文，但保留警告；归档失败不能交付猜测路径。交付失败不回滚已保存正文，不重复保存或重跑生成。

present 是独立模型工具，由原生规则指导需要文件交付时调用；不要求每次保存索引、草稿或查询都自动 present，不在宿主隐藏增加模型请求。

前端以官方成功交付事件作为成果声明依据，按 Session/turn/callId 恢复和去重；本轮相同规范路径合并展示，跨轮保留各自交付事实。实时流和历史读取走同一投影逻辑，失败调用不生成成功卡片。

复用当前双链、附件、媒体预览和文件打开入口。优先在现有消息成果区域呈现文件名、说明与打开操作；已有同一路径媒体卡或归档回执不再生成重复卡片，双链仍可用。结构化事件优先于正文链接猜测。

打开前沿用路径和权限检查；已删除文件显示不可用，可定位原路径；不自动重新生成、不从远程偷偷下载、不提供不存在的恢复承诺。切换项目、绝对路径和 Windows 路径必须按现有桌面命令合同处理，不拼接为任意 URL。
