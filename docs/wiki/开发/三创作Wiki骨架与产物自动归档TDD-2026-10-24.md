# 三创作 Wiki 骨架与产物自动归档 TDD

> 2026-10-24：用户批准执行；源码与自动化已完成，原生交互及真实模型行为待用户验收。

## 目标与范围

1. 右键“新建 Wiki”以子菜单提供通用、漫剧制作、短剧写作、小说创作。无命名弹窗；沿用通用目录操作，创作模板使用现有唯一项目 Wiki 并增量补齐骨架。类型不绑定本轮创作按钮。
2. 三创作路线生成的完整产物（含待审稿、完整方案/预览稿）经现有 `wiki_save_artifact` 自动归档；同一类型/集/章/实体修改写回同一路径，维护索引。普通聊天、解释、提问与错误不自动保存；用户本轮明确禁止保存仍遵守。
3. 来源原文保护与小说确认闸门保留：自动保存章节草稿不等于自动追加已确认来源。保存、采用、用户确认分开。
4. 不修改上下文压缩、AI Wiki 导航、其他文件生命周期；不加入 Git 自动提交或第二套版本库。本仓库尚未发现项目 Wiki 自动提交 Git 的链路，不能宣传自动替换由 Git 自动备份。

## 最小实施

- 骨架目录取自 `wiki-artifacts.json` 已有产物路径及路线归属，截断书名/集数等动态部分，补齐所有祖先 index。缺文件才创建，现有页面不覆盖；根识别沿用 wiki/docs/wiki 和开发知识库排除合同，多根先拒绝。
- 复用现有 `createWikiFolder`、索引与文件权限服务；子菜单沿原生展开交互接入现有右键菜单，不另加命名窗口。
- 复用现有 Wiki 原生插件，按 Agent 的 productionRoute 提供自动归档规则；普通模式明确只在用户要求时归档。Skill 判断产物类型，调用既有结构化工具，不对回复全文做关键词猜测，不把整个聊天当产物落盘。
- 三路线工具缺省写入采用“缺失创建/存在更新”；显式 create/update/append 语义保留，原始来源与已确认小说追加规则保持。写入版本条件、沙箱和读回校验保留；重复相同内容可不重写。
- 自动归档是否成功以真实工具回执为准。模型漏调用不能报已保存；真实渠道创作行为另做人工验收，不以提示词断言代替生产验证。

## TDD 门禁与步骤

1. 先红：模板目录/逐层链接、混合路线增量、保留用户正文、双根/占用拒绝；三路线重复写入、普通 create 保留与来源保护；菜单四类型/无弹窗、Agent 自动归档规则隔离。
2. 最小实施：先骨架与菜单，再原生归档默认行为与 Skill 规则；不扩大工具目录或引入新模型分类请求。
3. 验证：文件动作/文件树、归档 writer 与原生插件专项；真实 SDK + 本地模型替身验证路线切换和实际保存/更新；类型、完整 focused、桌面快速构建。原生点击、真实模型和跨平台未执行时单独标注。
