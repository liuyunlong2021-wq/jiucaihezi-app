# ZX 视频适配器多模型升级 TDD（2026-08-18）

> 范围：只升级 `zx-video-adapter` 与创作模型注册表，不修改 NewAPI，不影响 RunningHub 渠道。

## 已确认合同

- `grok-1.5-video-6s/10s/15s` 是同一核心模型的固定时长别名，均支持 `0~7` 张参考图；0 张为文生视频，1~7 张为参考图视频。
- Grok 与 Omni 创建、查询均走 `/v1/videos`；Seedance 创建、查询走 `/v1/video/generations`。
- `doubao-seedance-2-5-260628` 复用 Seedance JSON 合同：`seconds`、`metadata.ratio`、`metadata.resolution`，多模态 URL 放在 `metadata.content` 并显式声明 `role`。
- `omni-fast` 使用 JSON `images` URL 数组；`omni-v2v` 使用 JSON `video_url`。
- 上游网页当前只明确列出 `omni-fast`，未列出 `omni-v2v`；Seedance 网页也未列出 `doubao-seedance-2-5-260628`。这两个别名由本轮用户确认接入，代码合同通过单元测试，真实可用性仍需带 ZX Key 验证。

## 红灯

1. Grok 7 张参考图必须全部成为重复的 multipart `input_reference`；第 8 张在适配器边界返回 400。
2. Seedance 必须提交到 `/v1/video/generations`，图片生成 `reference_image` 内容项。
3. `omni-fast` 必须透传 `images`；`omni-v2v` 必须要求并透传 `video_url`。
4. 创作注册表必须公开 6 个 ZX 模型，并在提交前执行对应素材数量校验。

## 绿灯实现

- 将单图提取改为参考图列表，Grok 复用现有下载、大小和 SSRF 校验，最多处理 7 张。
- 在同一个 FastAPI 服务按模型分派三种最小请求格式，不新增适配器服务或依赖。
- 新增 Seedance 创建/查询路由；现有 `/v1/videos/{task_id}` 继续服务 Grok 与 Omni。
- `/v1/videos/{task_id}/content` 使用流式代理并在响应结束后关闭上游流，不在适配器内存中缓冲完整 MP4。
- 注册表只增加模型声明，继续复用现有 `newapi-direct`、素材上传和任务轮询运行时。
