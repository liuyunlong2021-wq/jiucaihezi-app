> 范围：只升级 `zx-video-adapter` 与创作模型注册表，不修改 NewAPI，不影响 RunningHub 渠道。

## 已确认合同

- `grok-1.5-video-6s/10s/15s` 是同一核心模型的固定时长别名，均支持 `0~7` 张参考图；0 张为文生视频，1~7 张为参考图视频。
- Grok 与 Omni 创建、查询均走 `/v1/videos`；Seedance 创建、查询走 `/v1/video/generations`。
- `doubao-seedance-2-5-260628` 复用 Seedance JSON 合同：`seconds`、`metadata.ratio`、`metadata.resolution`，多模态 URL 放在 `metadata.content` 并显式声明 `role`。
- `omni-fast` 使用 JSON `images` URL 数组；`omni-v2v` 使用 JSON `video_url`。
- 上游网页当前只明确列出 `omni-fast`，未列出 `omni-v2v`；Seedance 网页也未列出 `doubao-seedance-2-5-260628`。这两个别名由本轮用户确认接入，代码合同通过单元测试，真实可用性仍需带 ZX Key 验证。

## ZX 视频最终路由表

| --- | --- | --- | --- |
| `veo-3.1-generate-preview` | `/v1/videos`，注册表为 `newapi-direct` | **ZX 上游直连** | ZX 已兼容 APP/NewAPI 的标准 Veo 请求与结果合同，不需要协议转换；用户已真实生成成功。 |
| `veo-3.1-fast-generate-preview` | `/v1/videos`，注册表为 `newapi-direct` | **ZX 上游直连** | 与 Veo 3.1 相同，不进入 `zx-video-adapter`。 |
| `grok-1.5-video-6s` | `/v1/videos`，注册表为 `newapi-direct` | **ZX 上游直连** | 生产 NewAPI 渠道 Base URL 已由用户截图确认是 `https://img-api.zxcode.vip`；用户已真实生成并落盘。 |
| `grok-1.5-video-10s` | 同上 | **ZX 上游直连** | 与 6 秒共用同一生产直连渠道。 |
| `grok-1.5-video-15s` | 同上 | **ZX 上游直连** | 与 6 秒共用同一生产直连渠道。 |

| `omni-v2v` | `/v1/videos`，注册表为 `newapi-direct` | **`zx-video-adapter`** | 使用 ZX Omni JSON `video_url` 合同；结果下载与 `omni-fast` 共用带任务 Key 的流式代理。 |
| `doubao-seedance-2-5-260628` | `/v1/video/generations` | **`zx-video-adapter`** | ZX Seedance 使用独立创建、查询和多模态 `metadata.content` 合同。 |

RunningHub 的 `rh-gemini-omni-text-video`、`rh-gemini-omni-image-video`、`rh-gemini-omni-video-edit` 属于 RH 渠道，只进入 `rh-adapter`，绝不加入 `zx-video-adapter`。同理，RH Grok 与 ZX Grok 是两套模型、Key、价格和渠道配置，不能互相替代。

仓库仍保留 ZX Grok 的 JSON/multipart 协议转换代码和回归测试，作为历史实现与备用能力；这不代表生产 Grok 渠道正在使用适配器。当前生产事实必须以 NewAPI 渠道 Base URL 为准。

## 红灯

1. Grok 备用适配器若重新启用，7 张参考图必须全部成为重复的 multipart `input_reference`；第 8 张在适配器边界返回 400。
2. Seedance 必须提交到 `/v1/video/generations`，图片生成 `reference_image` 内容项。
3. `omni-fast` 必须透传 `images`；`omni-v2v` 必须要求并透传 `video_url`。
4. 创作注册表必须公开 6 个 ZX 模型，并在提交前执行对应素材数量校验。

## 绿灯实现

- 仓库保留 Grok 备用适配实现：将单图提取改为参考图列表，复用现有下载、大小和 SSRF 校验，最多处理 7 张；生产 Grok 当前不经过该实现。
- 在同一个 FastAPI 服务按模型分派三种最小请求格式，不新增适配器服务或依赖。
- 新增 Seedance 创建/查询路由；现有 `/v1/videos/{task_id}` 继续服务 Grok 与 Omni。
- `/v1/videos/{task_id}/content` 使用流式代理并在响应结束后关闭上游流，不在适配器内存中缓冲完整 MP4。
- `omni-fast`、`omni-v2v` 创建时按 ZX 原始任务 ID在适配器进程内保存本次渠道 Authorization；`/content` 仍要求调用方鉴权，但访问 ZX 上游时优先复用创建任务时的 ZX Key，不能把 APP 用户 Token误传给 ZX。该映射只存在于当前适配器进程，容器重启前创建的旧任务不具备映射。
- 注册表只增加模型声明，继续复用现有 `newapi-direct`、素材上传和任务轮询运行时。
