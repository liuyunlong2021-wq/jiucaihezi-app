# 通用记忆工作台 WikiAgent 索引渐进读取与确定性事务规范

> 日期：2026-08-29
> 状态：冻结现行规范；WikiAgent 是产品唯一 Agent；真实模型与三端平台仍待验收
> 规则依据：[[通用记忆工作台SkillAgent完整规则与渐进披露规范-2026-08-29]]；本文整合其规则，业务冲突以已选 Skill 为准，程序安全约束始终优先

## 0. 规范地位

本文是产品唯一 `WikiAgent` 的现行实施规范。旧 Wiki TDD 保留设计演进、测试和根因证据；与本文冲突时，以本文为准。

产品不创建 `FileAgent`、`MediaAgent`、`3DAgent` 或 `MCPAgent`。文件读写、媒体、3D 和 MCP 都是 WikiAgent 可调用的工具能力，不是并列 Agent。本文不创建第二套 Provider、模型循环、审批器、文件服务或平台适配器；WikiAgent 只是模型、Skill、真实工具 Observation 和确定性执行之间的薄协议。

Skill 不是 Agent，而是最高业务规则层：选中 Skill 时，Skill 直接约束 WikiAgent 的步骤、格式、必填项和质量标准；未选 Skill 时，WikiAgent 使用本文的默认规则。任何 Skill 都不能覆盖用户授权、路径边界、平台权限、费用限制、事务一致性、回滚和真实回执等程序安全约束。

## 1. 核心合同

`WikiAgent` 是产品唯一 Agent，以当前 Markdown Wiki 为本地知识核心，以真实工具 Observation 为补充事实，以解决本次任务为终点。工作台请求统一进入 WikiAgent；`@Wiki` 仅是兼容性的显式标记，不存在独立的 `@文件`、`@媒体`、`@3D` 或 `@MCP` Agent：

```text
第一阶段：证据获取
  当前任务 + Wiki 第一层 index.md + 可选完整 SKILL.md
  -> 模型按 Skill 判断现有资料是否足够
  -> 不足时只选择下一批任务相关路径
  -> 程序并发读取同层 index.md 或事实页并返回真实内容
  -> 足够时模型直接按 Skill 生成答案及最小 actions
第二阶段：程序组装
  -> 程序把最小 actions 补成完整、可校验的 Wiki 变更计划
第三阶段：程序执行
  -> 程序校验并执行白名单工具动作
  -> 如需修改 Wiki，至多执行一次 wiki apply 并重读验证
  -> 界面分别显示模型答案和各程序 Receipt
```

证据闭包只表示完成当前任务所需的全部事实，不表示读取整个 Wiki。任务完成是结束条件，模型轮数不是结束条件；完整 Skill 从首轮开始决定所需证据和最终处理方法，现有资料足够时不增加空规划轮次。

## 2. 三方职责

| 参与者 | 负责 | 不负责 |
| --- | --- | --- |
| 用户 | 描述任务；选择具体 Skill；连接并授权所需工具 | 理解内部 JSON、手工维护事务闭包 |
| 模型 | 理解任务；选择最小必要资料；应用 Skill 规则；生成答案和实际内容变更 | 猜路径、读写文件、伪造来源/指纹/回执、手工编排索引和日志 |
| 程序 | 读取真实入口和页面；执行已授权工具与 Wiki 事务；维护索引与链接；冲突检查、回滚、验证和回执 | 替模型决定创作内容、补造事实、根据关键词擅自扩大能力 |

一句话边界：**Skill 规定业务方法，模型负责语义，工具提供事实和动作，程序负责授权、确定性执行与真实回执。**

所有工具遵循同一最小合同：`schema` 描述可用动作，`Observation` 只返回真实事实/状态/错误，`Action` 必须经过程序授权和校验，`Receipt` 只由程序生成。工具不得自行改变 Skill 规则、扩展授权范围或伪造结果。

## 3. 激活与上下文边界

- 所有记忆工作台任务都由唯一的 WikiAgent 执行；`@Wiki` 可作为用户显式标记，但不再启动其他 Agent。
- 未选择 Skill 时，证据阶段使用本文默认读取规则，处理阶段使用本文默认输出规则。
- 选择具体 Skill 时，完整 `SKILL.md` 从首轮提供给模型，但在证据闭包完成前，模型只能按 Skill 要求判断所需资料，不得提前创作或写入。
- 初始输入只包含当前任务、Wiki 第一层入口、已选具体 Skill（如有）和已授权工具的必要 schema；后续 Observation 按读取计划逐轮加入。
- 不自动读取旧聊天、`.raw/对话记录`、全部附件、全部 Skill、整个项目或整个 Wiki。
- 用户显式给出的 Wiki 精确路径可以直接读取；模型按索引逐层选择路径是渐进披露约定，不是程序拒绝根内路径的权限门槛。
- WikiAgent 只能调用已经连接并获授权的工具能力。工具可以由 Skill 或用户任务触发，但不能绕过连接、审批、路径和费用边界。

### 3.1 能力组合状态

“无”不是另一个 Agent，而是没有附加 Wiki 上下文、没有选中 Skill 的最小状态。Wiki 与 Skill 是可独立开启的两个维度，实际只有四种组合：

| 状态 | Wiki 上下文 | Skill 规则 | 行为与能力 |
| --- | --- | --- | --- |
| 无 | 不读取 Wiki | 无 | 仅依据用户当前输入处理任务；不读取 Wiki、不执行 `wiki apply`；可按用户明确授权使用已连接的媒体、3D、MCP 或基础读写工具 |
| Wiki | 按索引渐进读取 | 无 | 使用 Wiki 事实和本文默认规则；可调用已授权基础读写、媒体、3D、MCP |
| Skill | 不读取 Wiki，除非 Skill 明确要求 | 完整 `SKILL.md` | 按 Skill 方法处理当前输入；Skill 可要求调用已授权工具，但不得自行获得 Wiki 或未连接能力 |
| Wiki + Skill | 按索引渐进读取 | 完整 `SKILL.md` | Skill 规定方法，Wiki 提供事实，WikiAgent 协调已授权工具并执行必要事务 |

默认不因关键词猜测开启 Wiki 或 Skill。只有用户显式选择 Wiki、具体 Skill，或 Skill 明确声明需要 Wiki 时，才进入对应状态。Skill 与工具默认说明冲突时，Skill 规则优先；程序安全约束始终优先于所有业务规则。

## 4. 索引渐进读取

Wiki 开启时，程序先读取根入口并把以下内容交给模型：当前任务、必要对话上下文、根 `index.md` 的真实内容，以及已选 Skill 的完整 `SKILL.md`（如有）。模型按 Skill 判断资料是否足够：不足时只请求下一批路径；足够时直接返回最终答案和最小 actions，不增加独立的空规划轮次。

### 4.1 默认路径

1. 程序使用 `wiki_context entry` 读取唯一 Wiki 根入口（项目类型决定为 `wiki/index.md` 或 `docs/wiki/index.md`）。
2. 模型按 Skill 判断资料是否足够：不足时只返回完成任务所需的最少直属路径，足够时直接返回 `answer + actions`。
3. 程序只校验路径位于当前 Wiki 根内；索引链接用于指导模型选择最小必要路径，不把未链接路径静默过滤。
4. 同层互不依赖的页面并发读取，成功内容全部保留，单页失败不清空其他结果。
5. 如果读到子 `index.md`，模型可以继续选择它直接链接的下一层路径。
6. 如果任务所需事实已经足够或没有合法下一层路径，模型直接完成任务；程序不要求空 `paths` 或额外的完成状态。

模型应从根入口逐层选择直属入口或事实页，不应请求目录、全库或无关页面；但程序不会因为路径没有出现在索引文本中就吞掉根内请求，而是返回真实内容、不存在或读取失败。证据阶段不要求读取整个 Wiki，只要求完成当前任务的证据闭包。

### 4.2 查询与搜索

索引导航是默认发现方式。`wiki_context search` 只用于用户明确要求关键词检索，或当前入口声明的范围内需要定位具体页面时；搜索只返回命中片段，模型仍需请求并读取精确页面后才能把它作为完整依据。

不得用搜索代替缺失的目录入口，也不得把搜索升级为全项目、Raw 或附件扫描。

### 4.3 缺失索引

目录非空却没有 `index.md` 时：

1. 程序不把目录内全部文件作为兜底发送给模型。
2. 程序记录“目录包含文件但缺少 index.md”，并列出未读取的目录。
3. 模型基于已经取得的资料继续回答，并明确本次覆盖不完整。
4. 如果用户要求修复结构，模型可以提出最小变更，程序通过一次 `apply` 创建入口并登记直属页面；不能在普通查询中静默修复。

这不是过度设计。它防止百万字 Wiki 因一个漏掉的入口突然退化成全目录读取，同时让用户知道哪些事实没有参与本次结果。

### 4.4 空入口与读取异常

以下情况都不能阻止用户拿到模型结果：

- Wiki 为空或根入口只有标题。
- `paths: []`。
- 页面不存在、读取失败或仅部分成功。
- ReadPlan 无法解析。
- 最终结构化结果无法解析。

程序把真实空值、错误和已成功资料交给模型。确认 Wiki 确实为空时，直接结束证据阶段，模型基于用户任务和 Skill 进入处理阶段；无法解析最终结构时，原始模型文本直接作为 `answer`，不执行任何副作用。

缺索引、读取失败或权限不足不能当作 Wiki 为空。程序必须把真实错误和未覆盖范围交给模型；模型可按 Skill 的降级规则继续处理，或明确告知用户无法完成。需要旧值才能安全执行的操作仍必须取得真实旧值。

## 5. 最小模型协议

### 5.1 Skill 主导的最小步骤

```json
{
  "paths": ["角色/index.md"]
}
```

或者现有资料足够时直接完成：

```json
{
  "answer": "给用户看的最终结果",
  "actions": [
    { "kind": "write", "path": "角色/关羽.md", "content": "正文" }
  ]
}
```

规则：

- 每轮只返回 `paths` 或 `answer + actions` 中的一种；同一路径不得重复。
- 不返回空 `paths`；资料足够或没有合法下一层时直接完成任务。
- 每轮优先请求当前索引声明的最小页面集合；程序只以 Wiki 根目录作为事实访问边界。
- 模型只负责语义路径、最终内容和最小动作，不填写 `reason`、`basis`、title、幂等键、索引、来源、日志、指纹或 Receipt。
- 程序兼容现有 `status/sufficient/changePlan` 旧格式，但不再要求模型生成这些字段。
- 结构解析应接受纯 JSON 或 JSON 代码块；首次没有可见正文时只纠正一次最小输出，不执行任何副作用。

### 5.2 证据读取结果

程序每轮按计划并发读取并返回真实 Observation，包括成功内容、空内容、不存在、读取失败、缺失索引和当前路径是否还有下一层。程序不替模型补造路径，也不在证据阶段执行写入、媒体生成、3D 保存或 MCP 副作用。

### 5.3 程序组装的执行计划

模型返回 `answer + actions` 后，程序才组装内部执行计划：

```json
{
  "answer": "给用户看的最终结果",
  "changePlan": {
    "reason": "写入关羽角色资料",
    "basis": ["角色/index.md"],
    "operations": [
      {
        "kind": "create",
        "path": "角色/关羽.md",
        "title": "关羽",
        "content": "# 关羽\n..."
      }
    ]
  }
}
```

只读、查询和无需落盘的任务由空 `actions` 映射为 `changePlan: null`。程序映射的 Wiki 操作只有：

| 操作 | 必要字段 | 含义 |
| --- | --- | --- |
| `mkdir` | `path`, `purpose` | 创建明确的内容目录 |
| `create` | `path`, `title`, `content` | 创建新的 Markdown 页面 |
| `replace` | `path`, `oldText`, `newText` | 精确替换唯一旧值 |
| `append` | `path`, `content`, `idempotencyKey` | 幂等追加内容 |
| `move` | `path`, `destination` | 移动或重命名页面/目录 |
| `trash` | `path` | 可恢复回收页面/目录 |

模型不直接输出上述完整 `changePlan`，也不输出 `indexChanges`、反向链接、日志修改、指纹、工具结果、成功声明或验证结论。模型需要改变真实业务状态时，可以在最小 actions 中明确操作 `hot.md`；程序不能自行猜测业务状态。

### 5.4 非 Wiki 工具合同

基础读写、媒体工具、3D 编辑器和 MCP 都接入 WikiAgent 的同一模型循环。WikiAgent 直接使用各工具已经注册的 schema，程序按原能力执行并返回真实 `Observation/Receipt`；不增加通用包装 JSON，不把领域计划改写成第二套任务协议。

所有工具先注册到 WikiAgent 白名单。工具是否展示给模型，取决于当前任务的授权、连接状态、平台能力和 Skill 要求；不必把完整工具目录一次性展示。模型只能请求当前已暴露的工具，未暴露或不存在的工具一律拒绝，并返回“工具未在 WikiAgent 白名单或当前能力未授权”的真实结果。

白名单不是按名称直接放行。程序仍必须校验工具 schema、参数、项目路径、用户授权、审批、费用、连接状态和平台权限；Skill 只能请求白名单工具，不能自行注册工具、扩大工具权限或绕过 WikiAgent 执行器。

- **基础读写**：负责已授权项目文件的读取和普通文件操作；路径、格式和写后验证由程序负责。Wiki 内容写入仍只能通过 `wiki apply`，不得用基础写工具绕过事务。
- **媒体工具**：负责图片、视频、音频等生成或处理；模型只能提交提示词、参数和已授权的素材引用，模型不得注入真实存储路径、账单结果或外部 URL。费用、模型可用性、媒体审批和写后验证由程序执行。
- **3D 编辑器**：负责 `.jcscene` 场景的读取、编辑、预览和导出；程序校验场景位于合法项目路径，保存、导出和覆盖均返回真实回执。
- **MCP**：只开放三个整体连接：`GitHub`、`Playwright`、`韭菜盒子创作`（对外开放）。授权、连接状态和展示以 MCP 整体为单位；MCP 内部可有多个接口，但 WikiAgent 不能把它们拆成独立 Agent、独立授权或隐式跨 MCP 调用。

工具调用失败、空结果或未连接时，真实 Observation 必须回到模型；不得伪造成功，也不得因此删除已经生成的答案。

## 6. 任务工作流

### 6.1 证据阶段与处理阶段

所有任务遵循同一顺序：

1. **证据阶段**：程序发送任务、根入口和可选 Skill；模型先判断资料是否足够，不足时规划 Wiki 读取，程序按层并发执行并返回真实 Observation。
2. **证据闭包**：当模型确认任务所需资料齐全，或确认 Wiki 为空、没有合法下一层时，证据阶段结束。缺失索引、读取失败和权限不足不等于 Wiki 为空。
3. **Skill 处理阶段**：模型使用完整 Wiki 证据和 Skill 规则生成答案。没有 Wiki 内容时，直接按用户任务和 Skill 处理，不虚构 Wiki 事实。
4. **程序执行阶段**：模型输出的工具动作只允许进入 WikiAgent 白名单；程序校验参数、授权、路径、审批和费用后执行并返回 Receipt。
5. **结果展示阶段**：界面展示模型答案、未覆盖警告和独立程序状态，不把模型文本当成执行成功证明。

证据不足时不得提前生成最终正文或执行副作用；模型确认现有资料已经形成证据闭包后，可以在当前轮直接返回最终正文和最小 actions。Wiki 变更仍通过一次 `wiki apply` 完成。

### 6.2 示例：`Wiki + Skill` 修改关羽角色提示词

用户任务为“`@Wiki + @角色提示词 Skill`，修改关羽的角色提示词”时：

1. 首轮发送当前任务、Wiki 根 `index.md` 和完整 `SKILL.md`。资料不足时模型只返回 `paths: ["角色/index.md"]`。
2. 程序读取并返回 `角色/index.md`。模型发现关羽页面后，请求 `角色/关羽.md`。
3. 程序读取并返回 `角色/关羽.md`，标记该路径没有下一层。证据闭包完成。
4. 模型使用关羽页面的真实内容和 Skill 规则生成新提示词，并输出 `replace` 或其他最小 Wiki 操作计划。
5. 程序校验计划、执行一次 `wiki apply`、重读验证并返回 Receipt，界面展示答案和状态卡。

如果首轮或后续读取确认 Wiki 没有任何相关内容，直接结束证据阶段，模型按用户输入和 Skill 的无资料分支生成结果；缺索引、读取失败或权限不足必须作为真实错误保留，不能伪装成“没有内容”。复杂任务只增加并列证据路径：同一层的角色、场景、道具和事件快照入口并发读取，直到 Skill 要求的证据闭包完成。

| 用户任务 | WikiAgent 行为 | 完成条件 |
| --- | --- | --- |
| 查询/总结 | 按索引读取必要事实并回答 | 有答案；列出实际依据和缺失覆盖；零副作用 |
| 根据 Wiki 创作 | 读取规范、状态、大纲、相邻正文及相关资产后创作 | 有完整内容；事实与实际资料一致 |
| 创建/更新/填充 | 先取必要旧值，再生成最小 `changePlan` | 答案存在；一次事务成功或返回真实失败 |
| 移动/整理/回收 | 读取目标、入口和影响范围，先展示完整预览 | 用户确认后事务执行；链接和入口验证通过 |
| 创建 Wiki | 模型生成最小 scaffold 计划 | 根入口存在；结构可导航；`validate` 通过 |
| 状态/健康检查 | 组合 `status + validate`，按需增加 `audit/graph` | 返回真实报告；默认不修改 |
| 巡检并修复 | 先只读报告，再处理唯一且用户要求的机械问题 | 修复后复检；歧义问题只报告 |
| 媒体生成/处理 | 依据 Skill 或用户任务调用媒体工具，接收真实 Observation 后继续 | 审批、费用、素材引用和输出回执真实；失败不伪报成功 |
| 3D 场景编辑/导出 | 读取或修改合法 `.jcscene`，由编辑器完成预览和导出 | 路径校验、保存/导出验证和回执通过 |
| GitHub、Playwright 或韭菜盒子创作 | 按 MCP 整体连接调用已授权接口 | 连接、授权、动作和结果均可追溯；不得拆分 MCP 授权 |

`health`、`overview.md` 和图谱质量报告是工作流或 Wiki 自身规范，不新增一套固定 Runtime action，也不是每个 Wiki 必须存在的文件。

## 7. 确定性 Wiki 事务

最终 `changePlan` 只能调用一次 `wiki apply`。媒体、3D 和 MCP 动作必须走各自已注册工具并返回真实 Receipt；它们不能绕过 Wiki 事务直接改写 Wiki。组合任务由 WikiAgent 按 Skill 规定顺序协调，程序必须在 Wiki 事务中：

1. 校验操作类型、Wiki 相对路径、依据和用户授权。
2. 校验已读取依据与目标文件指纹，拒绝并发覆盖。
3. 对 `move/trash` 校验完整预览和确认计划未变化；模型误提交的 `index.md/_index.md` 导航 `replace/append` 不得阻断业务操作，由程序忽略并自动修复入口。
4. 创建缺少的父目录。
5. 执行 `mkdir/create/replace/append/move/trash`。
6. 确保根目录和每个受影响内容目录存在 `index.md`。
7. 为新增/移动目标维护唯一直属导航；从旧入口移除失效导航。
8. 更新受影响的正向 WikiLink，并重新计算、检查反向引用。
9. 只有存在真实来源且当前 Wiki 配置了 `来源索引.md` 时登记来源；来源指纹由程序计算。
10. 只有实际发生变更且当前 Wiki 已存在 `log.md` 时追加事实日志。
11. 重读正文、受影响入口和链接，验证路径与内容指纹；入口中的重复直属导航由程序去重，不要求模型提交 `replaceAll`。
12. 任一步失败时恢复整个事务；恢复失败时返回明确恢复路径和未恢复项目。

事务校验失败时，先尝试程序可确定修复（去重导航、忽略模型索引维护、补齐受影响入口）再执行；只有无法安全确定修复的真实冲突才零写入。执行失败、取消或恢复不影响已经生成的模型答案。

### 7.1 模型计划的容错边界（2026-08-29）

程序是模型的执行层，不应把可自动修复的计划瑕疵变成用户任务失败。`wiki apply` 必须遵守以下优先级：

1. 先保留用户可见的 `answer` 和可执行的业务操作。
2. 再移除或归一化程序明确接管的派生操作：`index.md/_index.md` 导航、双链、日志和来源登记。
3. 再对重复导航、兼容 `_index.md`、缺失直属入口做确定性修复。
4. 只有路径越界、目标不存在、并发指纹变化、磁盘写入失败、无法恢复等真实条件才终止事务。

本次根因的固定回归：模型同时提交“创建业务页面”和“替换重复根入口”时，程序必须忽略索引替换、完成业务页面写入，并在同一事务中去重入口；不得因为旧文本多处命中而拒绝整批任务。

## 8. 索引、链接、来源和状态文件

- `index.md` 是逐层导航合同：根入口只指向直属分区/页面，分区入口只指向直属子目录/页面。
- `_index.md` 只作兼容读取；新建和受影响目录统一维护 `index.md`。
- 业务页保存事实，WikiLink 保存正向关系，反向引用由 Markdown 图实时派生。
- `来源索引.md` 保存“Wiki 位置 -> 来源角色 -> 真实来源 -> 已处理范围 -> 程序指纹 -> 时间”；没有真实来源时不登记。
- `log.md` 只追加已经真实发生的变更；文件不存在时不强制创建。
- `hot.md` 只保存当前必要状态；只有模型明确提交真实状态变化时才修改。
- `overview.md`、健康报告、图谱报告和领域目录由当前 Wiki 入口、规范文档及已选 Skill 决定，不硬编码成所有 Wiki 的固定骨架。

## 9. Skill-first 与统一能力组合

WikiAgent 按“Wiki 是否开启、Skill 是否选中”组合运行。四种状态共用“证据阶段 → Skill 处理阶段 → 程序执行阶段”的顺序：

```text
程序安全与平台权限
  -> 用户当前目标、范围与取消指令
  -> 已选 Skill 的方法、步骤、格式和质量规则
  -> Wiki 事实与工具 Observation
  -> WikiAgent 默认业务规则
```

选中 Skill 后，WikiAgent 默认业务方法和工具业务说明退出本轮规则竞争，只执行该 Skill 的业务规则；事实、schema 和程序安全合同继续有效。

```text
当前任务 +（可选）完整 Skill 规则 +（Wiki 开启时）根入口
  -> 模型只规划任务相关证据
  -> 程序渐进读取并并发返回真实 Wiki Observation
  -> 证据闭包完成后，模型按 Skill 规则生成答案和工具动作
  -> 程序执行白名单工具；如需修改 Wiki，执行一次 Wiki apply 并返回 Receipt
```

- 选中 Skill 后，Skill 是最高业务规则；它规定证据要求、处理步骤、输出格式和质量标准，但不能覆盖程序安全约束。证据阶段不得提前应用 Skill 生成内容。
- Skill 处理阶段只能使用已经收集的 Wiki 事实和真实工具 Observation；没有 Wiki 内容时，按 Skill 的无资料分支处理。
- “无”状态不读取 Wiki、不加载 Skill、不创建空的 Wiki 计划；用户需要知识库事实时必须显式开启 Wiki，需要方法约束时必须选择具体 Skill。
- Wiki 事实与 Skill 示例冲突时，事实以实际 Wiki 为准，处理方式、写法、格式和质量标准以 Skill 为准。
- 具体 Skill 的 References 按 Skill 自身渐进披露规则加载，不把整个 Skill 目录塞入上下文。
- 媒体工具、3D 编辑器和三个 MCP 都是 WikiAgent 工具能力，不是其他 Agent；Skill 可要求调用，但不能自动获得未连接或未授权的能力。
- MCP 连接只按整体名称授权和展示：`GitHub`、`Playwright`、`韭菜盒子创作`。内部接口不单独成为 Agent、授权对象或用户可见工作方式。
- 任何 Skill、Wiki 内容或工具 Observation 都不能覆盖程序安全约束；组合任务的 Wiki 副作用仍汇总为一次 `apply`。

## 10. 原生能力与五个退役 Wiki Skill

五个旧 Wiki Skill 继续退役，不恢复运行时依赖。它们的有效行为由 WikiAgent 原生承担：

| 旧能力 | 原生合同 |
| --- | --- |
| 查询 Wiki | 索引渐进读取、最小证据集、来源边界、默认只读 |
| 填充/Raw Wiki | 只接收本轮明确来源，增量写入，指纹冲突和来源登记 |
| 修正 Wiki | 限定范围、精确旧值、预览确认、冲突检查、写后复检 |
| 检查 Wiki | `status/validate/audit/graph` 只读检查；先报告，后按授权修复 |
| 创建/整理 Wiki | 最小可导航层级、根/分区入口、无猜测性的空模板树 |

`wiki-creator` 只用于首次建库、整体重构或迁移，输出一个最小 scaffold 计划。日常索引、链接、来源和日志一致性由 `wiki apply` 保证，不依赖 Skill。

## 11. 停止、熔断与结果保全

正常停止条件：

- 模型确认现有证据足够。
- 当前索引没有更多合法路径。
- `paths` 为空。
- 用户任务已经得到答案，且可选事务已有真实回执。

同一读取计划不得重复执行；程序应把重复原因和已读范围反馈给模型。兄弟页面在同一轮并发读取，不因文件数量线性增加模型轮数。

保留最多 12 次读取规划作为异常熔断，只防止模型失控，不是成功目标。触顶时进入最终综合，返回基于已读资料的答案并明确 `limit_reached` 和未覆盖范围；模型给出的合法业务变更照常进入执行校验，程序不得仅因触顶吞掉答案或变更计划。不得伪报未读取事实，也不得把全局 DirectEngine 上限改成 12。

只有权限不足、文件损坏、磁盘失败、持续 Provider 不可用、用户取消或无法恢复的事务错误等真实条件才可判为阻塞。

## 12. 界面与回执

- 纯查询/创作只显示模型答案；不展示内部 JSON 和读取轮数。
- 实际执行副作用时，答案下方显示独立程序状态卡：成功、失败或取消，以及受影响对象或路径。
- 状态卡只来自程序回执，不读取模型文本中的“已写入”“已完成”。
- 状态卡不重复正文，不拼接完整 `apply` 输出、指纹列表或内部调试内容。
- 缺索引、部分读取、熔断和未覆盖资料以简短警告展示；模型答案仍保留。
- 写入失败或用户取消时，答案继续可复制、编辑或再次提交。

## 13. 根因回归门禁

实施变更前先写红灯，至少覆盖：

1. 所有记忆工作台任务只进入 WikiAgent；无附加能力时不读取 Wiki、不加载 Skill，显式开启 Wiki 或选择 Skill 后才进入对应组合状态。
2. 初始只读取根入口，不自动扫描全 Wiki。
3. 模型优先读取当前入口直接链接或用户明确指定的路径；程序不因根内路径未出现在链接中而静默过滤。
4. 同层多路径并发读取；一页失败不丢弃其他成功页。
5. 子入口继续授权下一层，能够到达深层事实页。
6. `paths: []`、空入口、缺页和 ReadPlan 解析失败仍生成答案。
7. 非空目录缺 `index.md` 时不全目录兜底，答案包含未覆盖警告。
8. 重复计划不重复执行；读取规划触顶时保留答案，合法业务变更仍进入具体操作安全校验。
9. 最终 JSON 解析失败时显示原始模型文本，零副作用。
10. 查询任务 `changePlan: null`，零写入。
11. `create/replace/append/mkdir` 只调用一次 `apply`，并自动维护受影响入口。
12. `move/trash` 未确认、确认计划变化或存在活动入链时零执行。
13. 并发指纹变化时整批拒绝，正文、入口和日志均不产生半成品。
14. 写入失败可以完整恢复；恢复失败返回可操作的恢复信息。
15. 写入后正文、受影响 `index.md`、导航、链接和指纹通过重读验证。
16. 有真实来源才登记；现有 `log.md` 只在实际变更后追加；程序不猜 `hot.md`。
17. 模型答案与程序状态卡分离，任何工具错误都不删除答案。
18. Wiki 与 Skill 四种组合状态路由正确：无状态不读 Wiki/Skill，Wiki 状态渐进读取，Skill 状态只加载选中 Skill，Wiki + Skill 同时使用事实和规则且不加载其他 Skill。
19. `status/validate/audit/graph` 默认只读，歧义孤儿和语义问题不自动删除。
20. 退役五 Skill 的查询、填充、修正、检查和建库行为有原生等价测试，但运行时不读取旧 Skill 正文。
21. 模型误提交 `index.md/_index.md` 的 `replace/append` 不阻断同批业务写入；程序自动去重并维护直属导航。
22. 可自动修复的计划瑕疵不直接终止任务；只有真实越界、并发冲突、磁盘失败或不可恢复错误才返回失败。
23. 任何任务只有 WikiAgent 一个 Agent；不存在 FileAgent、MediaAgent、3DAgent 或 MCPAgent 的独立路由、循环和回执。
24. 未选择 Skill 时使用 WikiAgent 默认规则；选择 Skill 时完整 `SKILL.md` 同时约束读取、工具调用和最终输出。
25. Skill 可以覆盖工具业务默认说明，但不能覆盖路径、授权、费用、审批、事务、回滚和平台权限安全约束。
26. 媒体工具和 3D 编辑器返回真实 Observation/Receipt，素材引用、费用、`.jcscene` 路径和写后验证均由程序校验。
27. 只有 `GitHub`、`Playwright`、`韭菜盒子创作` 三个整体 MCP 可连接；内部接口不能拆成独立授权或隐式跨 MCP 调用。
28. 媒体、3D 或 MCP 失败、空值、取消和未连接时，模型答案仍保留，程序不伪造成功状态。
29. Skill 驱动的 Wiki + 工具组合任务最多执行一次 `wiki apply`，所有工具动作均有独立真实回执。
30. `Wiki + Skill` 首轮只发送任务、根入口和完整 `SKILL.md`；证据未闭包前模型不能生成最终正文或执行副作用。
31. 模型请求下一层索引时，程序按层并发读取并返回真实内容；证据闭包完成后才进入 Skill 处理阶段。
32. Wiki 确实为空时，模型按用户任务和 Skill 无资料分支继续；缺索引、读取失败和权限不足不会被误判为空 Wiki。
33. 无 Wiki、无 Skill 时不读取 Wiki/Skill；Skill-only 不读取 Wiki，除非 Skill 明确要求；Wiki-only 不加载 Skill。
34. 未在 WikiAgent 白名单、未暴露或未授权的工具调用均被拒绝，并向模型和用户返回真实原因。

完成门禁：Wiki 专项回归、完整 focused 测试、TypeScript、对应平台测试和差异检查通过。未执行的真实模型、Desktop/Web/Mobile、MCP 和付费能力组合必须标为未验证。

## 14. 禁止设计

- 用固定两次、三次、五次或 64 次模型请求定义成功。
- 让模型自己调用通用文件工具维护 Wiki。
- 要求模型输出 `indexChanges`、双链、日志、回执或验证结论。
- 结构化结果解析失败时删除模型正文。
- 因 Wiki 为空、入口缺失或读取失败而不给用户答案。
- 缺 `index.md` 时读取整个目录作为兜底。
- 自动扫描 Raw、全项目、全 Wiki、全部 Skill 或未选择能力。
- 把 `hot.md/log.md/来源索引.md/overview.md` 硬编码为所有 Wiki 必备骨架。
- 创建第二套 Provider、SSE、会话、审批、文件服务或总控 Agent Runtime。
- 为文件、媒体、3D 或 MCP 创建并列 Agent、独立模型循环或独立任务协议。
- 让媒体、3D 或 MCP 工具自行扩展 Skill 规则、授权范围或 Wiki 写入路径。
- 将 MCP 内部接口拆成多个用户可见能力或独立授权对象；当前只允许三个整体 MCP。
- 把完整 `apply` 回执拼接到模型回答正文。

## 14.1 同类阻断风险审计（2026-08-29）

以下设计与本次“重复 `index.md` 导航导致整批失败”属于同一类问题：程序把可恢复、可反馈或可局部降级的情况直接当成任务终止。按优先级记录如下：

| 优先级 | 当前设计 | 风险 | 正确方向 |
| --- | --- | --- | --- |
| P1 | 观察未完成时统一 `changePlan = null` | 空 Wiki、缺页或熔断会吞掉模型的可执行结果 | 删除覆盖率门禁；始终保留模型答案和变更计划，只按每个具体操作的路径、旧值、并发状态和事务能力判断能否执行 |
| P1 | `replace` 多处命中直接抛错 | 模型只差一个精度参数就导致整批任务失败 | 先返回命中位置给模型重规划；对程序接管的入口导航直接归一化，不走正文替换保护 |
| P1 | 读取路径因未出现在当前索引而被过滤 | 索引格式稍有差异就可能漏读关键页面 | 索引只负责渐进导航；根内路径直接读取并如实返回，根外路径才拒绝 |
| P2 | 相同读取计划直接抛出重复检索错误 | 模型重复规划一次就中断任务 | 把重复计划转为“已读资料”反馈；只有连续无进展才熔断 |
| P2 | `ReadPlan` 结构解析失败后停止递进 | 模型输出轻微格式偏差会减少可用上下文 | 已有宽容解析基础上，允许从纯文本/代码块提取最小路径；无法提取时继续最终回答 |
| P2 | 事务要求 `workspace.remove` 存在，否则所有 `apply` 失败 | 平台能力缺少恢复接口时，连可逆的新建也无法执行 | 新建/追加等不需要删除的操作可使用写前快照回滚；只有移动/回收等确实需要删除能力时才拒绝 |
| P2 | `reason`、`basis`、操作字段缺失直接解析失败 | 模型遗漏非业务关键字段会阻断结果 | 程序可用当前用户任务、已读路径和操作类型补齐可推导字段；不可推导时只拒绝该操作，不吞掉答案 |
| P3 | 单次操作数量或读取页数达到上限即禁止副作用 | 大 Wiki 或批量整理任务可能在已安全完成时被上限误伤 | 上限只防失控；对已验证的局部操作继续执行，并明确未覆盖范围 |

必要安全边界不属于上述误伤：路径越界、目标不存在、并发指纹变化、活动入链回收、用户取消、磁盘失败和无法恢复仍必须阻止写入并返回真实状态。下一轮修复应按 P1 → P2 → P3，不能再次用扩大 JSON 字段或增加循环次数掩盖职责边界。
