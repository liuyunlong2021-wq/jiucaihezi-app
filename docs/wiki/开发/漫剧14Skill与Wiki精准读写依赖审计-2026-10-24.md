# 漫剧 14 Skill 与 Wiki 精准读写依赖审计

> 2026-10-24。范围：当前 `production-skills.json` 的全部 14 个漫剧 Skill 主文件、相关参考与统一归档合同。只读审查，未修改 Skill、骨架或运行时；不代表真实模型执行验收。

## 1. 结论与阅读口径

现有专业创作规则较完整，但“业务资料叫什么”与“当前项目实际从哪个文件、哪个段落读取”之间尚未形成统一合同。8 个 Skill 主文件没有直接的 Wiki 指路：film-style、角色设计、角色格式、场景、道具、工程台本、H3、Seedance。原生 Wiki 系统规则仍可引导模型读取，不能据此断言它们必然漏读；但目前不能从每个 Skill 独立证明精准定位链路齐全。

以下按制作依赖排列，包含脑暴可选入口及 H3/Seedance 两条下游分支；不是每个任务必须顺序执行全部 14 个 Skill。两条视频路线各取所需，不互相作为强制前置。

路径用 `wiki/` 举例；现有根可能是 `docs/wiki/`。角色、场景、道具名称及文件名必须以真实 index/双链为准，不能直接拿显示名称猜路径。后文“应读”是待补齐的目标合同，“现状”是已核对的源码事实。

| 进度 | `wiki/制作进度.md` | 只导航当前状态和真实产物，不能取代事实正文 |

## 3. 逐 Skill 应读、应改与缺口

### 1）项目资料：jc-xiangmuziliao

- 应读：来源 index/来源记录 → 指定原文节点或原文范围；已有阅读覆盖页；同版本的梗概、背景、规则、小传，以及本批涉及的剧情场景/道具页。
- 精准取用：原文身份、事件因果、关系与认知时间、场景准入/空间、道具功能/持有变化，记录覆盖范围。需要整理整个来源时必须实际覆盖，不能以按需读取为由只读开头。
- 应写：`story_summary/episode_summaries/story_background/world_rules/character_bio/scene_research/prop_research/event_timeline/research_coverage` 的对应页面；人物一人一页。
- 现状：主文件“读取与依据”“完整改编项目”已有原文、覆盖、版本和索引复用要求，末段有归档类型。缺统一的当前作品/原作与改编版选择入口，不能只凭同名页面选版本。交付段还残留“仅讨论/预览不保存”的旧口径，与最新完整预览稿保存规则不一致。
- 不应读/改：不为提取资料加载全套视觉资产提示词；不把原作改成新皮，不把设计推导写成原文事实。

### 2）灵感脑暴：jc-manju-brainstorm（可选/可中途进入）

- 应读：总纲的已定方向/限制 → 当前目标片段或工程稿 → 涉及人物的小传、规则、必要资产；续做时定位当前已选节拍和待选问题。
- 精准取用：已选与待选、人物目标/认知、上一节拍结束状态、当前允许改动范围。无已有资料的新项目可直接接受用户输入，不强制先建全库。
- 应写：形成的完整工程片段用 `engineering_script`；完整项目方向用 `project_overview`；独立完整资产交给对应 Skill/类型。不把候选片段冒充定稿。
- 现状：主文件 L14 有 Wiki 规则与按需证据；参考 `assets-and-resume.md` 有专业交接及续做记录，但主要依赖持久对话。没有统一的自动落盘脑暴断点/已选节拍定位合同，也没有一份专属脑暴产物类型；缺集号时不能强造集号归档。
- 不应读/改：不因一场脑暴通读整季；未选候选不改人物正式身份或其他集稿。

### 3）项目风格与总纲：jc-film-style

- 应读：已有 `项目总纲.md` → 目标故事/文学剧本 → 同版本梗概、背景、世界规则、重要人物及关键场景资料；仅当前片段选向时读片段必要范围。
- 精准取用/更新：画幅、最终媒介、视觉风格、色彩与光源、摄影/表演方向、声音路线、分镜路线、空间锚点、资产清单。改一个字段保留其他已定字段和短剧改编方向。
- 应写：`project_overview` → `改编方案/项目总纲.md`。
- 现状：业务字段丰富，主文件 L8/L44 有已有方向继承和事实优先级；无 Wiki 定位及归档类型指路。需要补“先读现有总纲，沿原页更新”的项目接入合同；通用原生规则目前补充了总纲写入类型。
- 风险：没有从 Wiki 取到已有方向时，L44 允许默认设计值，可能把已有设定当缺失后重新设计。

### 4）角色形象：jc-juese-sheji

- 应读：总纲的媒介/风格/画幅/时代 → 当前人物小传与必要背景规则 → 已有 `资产/角色/<角色>.md` → 该角色实际选定的图片及当前造型状态。

### 5）角色画风与三格排版：jc-juese-geshi

## 4. 跨 Skill 的优先补漏

1. **固定项目基础信息的唯一位置。** 目前画幅/风格在项目总纲；优先把这一现有位置及字段说清，避免再生成另一份平行“项目基础资料”。如果用户决定独立拆页，需要同步全部读取入口、归档类型和现有内容，不可只改文件夹名字。总纲设计输出里“不写路径”不妨碍工具接入层保存到固定路径。
2. **每个 Skill 明确输入链。** `根index → 当前目录index → 目标正文 → 必要直接关联`。输入合同写资料角色、现有归档类型/路径示例、所需字段、缺失处理、版本选择和输出落点。不是每次固定读一串不相关页面。
3. **原作/改编版必须明确。** 当前模板支持两个版本，旧文件又可能无版本目录；改编片段应沿选定项目方案找到改编版人物/场景/规则，必要时再回原作取证，不能把同名原作页直接当最终设计。
4. **人物、场景、道具要有当前任务关联。** 当前每集 index 主要登记产物，没有机器可验证的本集/镜头到相关实体的必需映射。应在工程稿/资料正文或其 Properties 保存实际双链与范围，index 只导航，不抄整套设定；没有映射时必须从当前稿实际识别相关实体再沿索引定位。
5. **共用资产页定义章节所有权。** 角色设计/三格排版共用 `character_asset`，两份完整提示词不能互相抹掉；项目总纲也共用短剧改编方向与漫剧制作方向。指定修改节/字段，读原页保留无关节，再由现有完整文件更新工具写回。当前 Runtime 默认 upsert 不会自动替 Skill 合并语义章节。
6. **选定媒体的绑定要可找。** 提示词 MD、已生成图片、用户选中的当前参考三者分开。已有系统保留媒体文件/任务，但统一归档字段并没有规定每个资产页必须怎样登记当前选中图、来源和状态；应补当前参考路径/双链与用途，不能把“写过生图提示词”当成“已有参考图”。
7. **工程稿—声音—分镜—视频共用范围。** 保留真实集号、原镜号与片段范围，分镜记录格位映射；各稿的片段命名可不同但必须能定位同一范围，不靠文件名近似猜测。
8. **修订传播可定位。** 用户改比例/风格/资产/剧本后，指出受影响的真实下游页面；本轮只更新获授权范围。当前没有自动验证所有下游稿仍与最新上游一致的机制，不能宣传已有全链路失效重建。

## 5. 对“创建漫剧制作 Wiki”的反向要求

当前创建功能按产物路径创建目录及 index，不预生成包含真实内容的总纲、角色或剧本。这是目录骨架，不等于业务资料和引用关系已齐备。

应在下一步设计中补齐：

- **项目总纲入口/字段模板**：明确比例、媒介、风格、制作路线及适用范围，空缺写待设定，不生成假默认值。沿已有 `project_overview`；不先增加平行文件。
- **剧情资料与视觉资产的衔接**：`项目资料/场景` 与 `资产/场景` 等相互关联；已有视觉资产时从资产读设计，初次设计回剧情资料，不让资产依赖自己必须先存在。
- **按需出现的实体和分集页面模板**：角色页承载不同提示词版本和实际图绑定；当前集 index 导航剧本/工程/声音/分镜/视频。没有真实人物/集号时不批量生成空“第001集”等伪产物。
- **镜号/片段与来源关系**：随真实产物登记，而不是在创建空 Wiki 时猜测。

本轮只提出缺口，不执行上述骨架或 Skill 规则变更；上下文压缩也未修改。优先修正场景/道具/角色格式的默认值绕过问题、H3 项目输入接入和共享资产页覆盖问题，再补全 14 个 Skill 的精准输入合同。
