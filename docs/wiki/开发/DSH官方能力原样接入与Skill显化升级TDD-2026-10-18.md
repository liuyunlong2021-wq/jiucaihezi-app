## 1. 目标与判断标准

**官方决定 Agent 如何工作；韭菜盒子提供桌面界面、Skill 入口和自有工具。**

“照搬官方”指直接运行同版本官方实现，并通过它公开的配置、插件、工具和 SDK 接口接入；不复制一份循环、压缩器或子代理调度器到本仓，也不另设产品默认策略。用户通过官方支持的设置明确选择的配置可以保留。

可验证的终态：相同官方版本、profile、模型适配器、有效模型配置和输入，在原生官方运行时与 App 中产生相同的 Agent 执行语义。App 只增加已声明的自有工具与素材，除用户明确授权的Skill排他选择外，不因为按钮改变Skill正文、通用工具权限、上下文策略或子代理策略。

原生 DeepSeek 与 OpenAI 兼容中转使用不同的官方适配器，不能跨适配器要求请求和默认值逐字相同；比较必须在相同路由条件下进行。Skill对照还须使用相同的显式选择范围。

### 2.1 上下文窗口的确定方式（2026-10-18澄清）

“官方解析”指从已有能力数据取值，不是根据聊天内容探测真实窗口。按官方现有优先级：模型显式配置（经核实的渠道能力或用户设置）→同provider/model的内置目录→该适配器的官方回退值。官方模型发现接口能读取服务端报告的`contextWindow`、`context_length`等字段；只返回模型ID时无法知道容量。发现结果还须写入官方支持的模型配置，不能假定启动SDK会自动发现、保存或更新它。

我们当前所有中转使用自定义provider `jiucaihezi`；内置目录按provider与model精确匹配，不会因模型名里有DeepSeek就跨provider自动继承原生DeepSeek目录。因此只删除两个App常量，通常仍会落到官方pi-ai未知模型回退262144/32768。

用户后续确认：“我记得之前都写过，几乎都1M，只有本地部署不足。”实际找到唯一已有目录`src/data/modelContextWindows.ts`与`agentStore.availableModels`。实施采用：同provider/model条目中有效的`contextWindow`/`maxOutputTokens`优先 → 已有目录默认（云端1000000/128000、本地32768/4096，`:free`沿用32000/32000）。这些是产品已声明的接入容量，**不是已经实测每条中转均支持该容量**；Gateway后续声明更精确值会优先生效。不会把云端同名条目的容量借给本地条目，也不假装是原生DeepSeek路由。

模型配置进入官方`llm-pi-ai.providers[].models`字段；SDK初始化不再另设32K输出覆盖。父Agent、子代理与摘要请求按官方各自解析，不另加App预算。运行时标识包含provider及有效容量，目录变化会触发现有运行时交接。UI从官方`contextPressure`投影读取窗口与占用，未知显示“未提供”，不拿产品声明值冒充已观测窗口。

### 2.2 Agent执行默认策略的含义（2026-10-18澄清）

官方决定一次任务可持续执行多少步、模型失败如何重试、同时运行多少安全工具/子代理、何时压缩历史及如何等待后续工作。App不再额外加入“最多跑N轮”“失败再补重试M次”“强制所有工具串行”“按另一个比例提前压缩”“主任务先空闲就提前完成”等二次规则。这里的“不插入”是取消App另设策略，不是取消官方的轮次限制、重试、并发、压缩和调度；用户显式选择的官方设置仍有效。

自有工具内部的任务ID、素材处理、保存回执、业务校验与用户授权仍按自身合同执行，Skill排他范围和LibreOffice裁剪按已确认例外保留。

## 4. Skill 显化与保留能力

按钮只决定用户请求调用哪个Skill、携带哪些用户选中的素材。手势解析、Skill正文加载、包内资源、工具选择、委派和连续执行由官方机制负责；按钮不追加另一套执行提示词，也不修改Skill正文。用户明确要求排他选择这套Skill时，保留该范围限制及必要依赖；文件、终端、MCP等通用工具能力不随之关闭。此项是已授权产品适配，不宣称与未设范围的官方裸调用完全相同。

- 同一个Skill通过按钮或官方手势调用，在相同显式Skill范围下，其正文、资源路径和模型可用工具应等价；对比时固定正文版本，排除正常的目录时间戳等非语义差异。
- 漫剧、小说、短剧入口保留。内置业务Skill、路由资源及`wiki-memory`等依赖保留，通过官方插件与资源机制装载；优先让业务Skill的既有依赖指令生效，不由宿主暗中加一套工作流。
- 当前固定内置版本、自动注入`wiki-memory`、路线互斥与屏蔽`skill`分别审查。版本绑定可用于保证自有包资源完整；用户授权的Skill范围屏蔽保留，额外宿主强制流程要退役。不能把整个`manju-skills.mjs`直接删除来实现对齐。
- 共享`wiki_save_artifact`、影音任务、素材传递、文件树回执、画布入图、3D和本机工具保持可达；其路径校验、付费操作授权、任务幂等与结果持久化属于自有工具合同，继续保留。
- 项目文件、历史Session ID、权限档位、一次性审批、MCP、Computer Use、多窗口、更新能力与Windows/Intel Mac兼容均保留。

用户本轮复核明确保留“按钮排他选择自有Skill包”及LibreOffice裁剪。前一版TDD要求一概移除排他范围的结论撤回；需要退役的是散落于宿主的重复业务指令与非授权执行策略。旧记录保留为历史。任何功能消失都不能作为“已跟官方一致”的成功证据。

## 5. 测试方式与红绿目标

复用现有SDK、本地HTTP模型替身和官方Session存储测试，不新建执行引擎或通用测试框架。在隔离`DSH_HOME`中运行同版本未打补丁的官方对照组，以及App接入组；缺少宿主RPC的对照组通过官方内部服务测试夹具读取事实，不能为了对比给对照组打App补丁。

两组固定模型能力、输入、工具及返回值，比较解析后请求、工具schema、消息关联、Session事件和完成状态；归一化随机ID、时间、路径与分块边界，不断言模型自然语言逐字相同。普通对话没有自有工具时，官方通用能力目录不应因App包装而缩小；用户授权的Skill范围与LibreOffice裁剪作为明确例外登记。

## 6. 实施顺序与闸门

1. **G0 盘点并锁定边界** → 登记实际官方profile与全部差异，建立T01–T25对照夹具；执行当前回归基线，记录失败与尚缺测试。产物为差异表与真实红测证据。
2. **G1 恢复官方默认** → 先移除上下文、输出和子代理策略覆盖，再检查推理/图片/重试等表外覆盖；通过T01–T12。UI同步读取有效模型值，避免后端改了而界面仍显示旧常量。
3. **G2 Skill入口等价** → 保留用户授权的Skill排他范围，退役宿主重复业务指令与非授权路线强制，保持业务Skill、资源与自有工具；通过T13–T16及现有创作回归。用户显式选择的调用语义保留。
