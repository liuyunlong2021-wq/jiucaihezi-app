# 通用记忆工作台 Wiki 索引优先两阶段计划与入口维护 TDD

> 日期：2026-08-28
> 状态：阶段 1-3 已实施（阶段 4-7 待完成）
> 范围：`@Wiki` 的查询、创作、写入、建库、整理、移动、删除和索引维护

## 1. 结论

`@Wiki` 不再使用开放式工具循环。它采用固定的两阶段模型协议：

```text
用户任务 + Wiki 根 index.md
  -> 模型输出 ReadPlan
  -> 程序并发读取 ReadPlan 中的页面
  -> 模型输出最终内容 + WikiChangePlan
  -> 程序确定性提交并验证
  -> 程序回执
```

正常任务使用两次模型请求；资料确实不足时允许一次补充 ReadPlan，最多三次。不存在“为了达到循环数量而继续调用工具”的路径。

核心边界：

- 模型负责语义选择、正文和变更意图。
- 程序负责路径校验、文件读写、索引、双链、来源、日志、事务和验证。
- Skill 负责写作方法，不负责 Wiki 一致性。
- `index.md` 是 Wiki 的导航契约，不是可选装饰文件。

## 2. Index 契约

### 2.1 必须存在

在 Wiki 根目录和每一个用于存放 Wiki 内容的子目录中，都必须存在本地 `index.md`：

```text
wiki/index.md
wiki/角色/index.md
wiki/剧情/index.md
wiki/剧情/分集/index.md
```

空的临时目录不属于 Wiki 内容目录；一旦目录被创建为 Wiki 内容目录，程序必须同时创建其 `index.md`。现有 `_index.md` 只作为兼容读取，不作为新写入格式；迁移由明确的建库/整理任务完成。

### 2.2 内容规则

- 根 `index.md` 只列直属顶层目录或直属页面。
- 子目录 `index.md` 只列直属子目录或直属页面。
- 每个条目使用标准 WikiLink，目标必须是当前真实路径。
- 同一目录中同一目标只能出现一次。
- 目录、页面移动或删除时，旧目录和新目录的 `index.md` 必须同一事务更新。
- 新建页面、目录、分集、角色、场景、道具或伏笔时，目标目录没有 `index.md` 就自动创建并登记。
- `index.md` 更新失败，正文写入必须回滚；不得出现“正文成功、入口失败”。

### 2.3 程序硬不变量

模型提示词要求维护入口，但真正保证完整性的规则由程序执行：

```text
每一个受影响目录 => index.md 存在
每一个新增/移动目标 => 恰好一个直属入口条目
每一个删除/移动旧目标 => 旧入口条目被移除
所有入口目标 => 路径存在且在 Wiki 根目录内
```

任何不满足上述不变量的 `WikiChangePlan` 在 dry-run 阶段拒绝，不交给模型反复试错。

## 3. 两个内部系统提示词

这两个提示词是产品运行时协议，不创建成用户 Skill，也不依赖 `skill-creator` 生成。它们应作为版本化常量、JSON Schema 和测试存在。

### 3.1 WikiReadPlan Prompt

输入只有：当前用户任务、Wiki 根 `index.md`（或用户明确指定的页面）、已选具体 Skill 的名称/短摘要和已选 MCP 的名称/短摘要。

系统提示词必须要求模型：

1. 先理解任务的输出目标和事实约束，再选择最少的页面。
2. 优先选择根入口声明的直属入口；不得凭项目常识猜测路径。
3. 只返回完成任务必需的页面，不返回“顺便看看”的背景页面。
4. 同一页面只能出现一次；目录只能作为入口，不得把整个目录当正文读取。
5. 每个路径必须给出简短 `reason`，便于程序审计是否确实相关。
6. 找不到所需路由时返回 `missing`，不得用全库扫描兜底。
7. 读取清单必须是合法 JSON，不得混入解释文字。

结构化合同：

```json
{
  "paths": [
    {"path": "剧情/总纲.md", "reason": "确定下一集目标"},
    {"path": "状态/当前进度.md", "reason": "确定续写位置"}
  ],
  "missing": [],
  "sufficient": true
}
```

程序校验：路径必须位于 Wiki 根目录内、必须真实存在、不能重复；读取按路径并发执行，并把真实正文、标题、章节、路径和指纹返回给第二阶段。

### 3.2 WikiSynthesisAndChangePlan Prompt

输入为：用户任务、ReadPlan 实际读取结果、已选 Skill 正文/引用结果、已选 MCP 结果和当前 Wiki 入口摘要。

系统提示词必须要求模型：

1. 只根据实际读取结果创作或总结；没有证据的事实标记缺失，不得补写。
2. 返回最终回答和语义变更计划，不输出需要程序猜测的自然语言命令。
3. 任何新增、更新、移动、整理或删除都必须列出目标路径、操作类型、正文或旧值/新值、原因和证据路径。
4. 只要变更触及某个目录，就声明该目录的 `index.md` 需要同步维护；不能声明“稍后再更新入口”。
5. 新建目录必须同时声明创建 `index.md`；新建页面必须声明直属入口标题和摘要。
6. 续写任务必须把正文、确实变化的进度/角色/场景/道具/伏笔和入口放在同一批计划中；不变化的内容不重复覆盖。
7. 删除、移动、批量整理和完整覆盖只提出计划，不绕过程序确认策略。
8. 输出必须是合法 JSON，`answer` 与 `changePlan` 分离，不能让程序从答案正文中猜写入内容。

结构化合同：

```json
{
  "answer": "最终给用户的内容",
  "changePlan": {
    "reason": "续写并归档下一集",
    "basis": ["剧情/总纲.md", "状态/当前进度.md"],
    "operations": [
      {
        "kind": "create",
        "path": "剧情/分集/第28集.md",
        "title": "第28集",
        "content": "完整正文"
      },
      {
        "kind": "replace",
        "path": "状态/当前进度.md",
        "oldText": "第27集",
        "newText": "第28集"
      }
    ],
    "indexChanges": [
      {
        "directory": "剧情/分集",
        "path": "剧情/分集/第28集.md",
        "title": "第28集",
        "action": "add"
      }
    ]
  }
}
```

`indexChanges` 是模型的完整性声明，不是程序的唯一依据。程序根据 `operations` 再计算一次所有受影响目录，补齐缺失的 `index.md` 和直属链接；模型声明与程序计算不一致时，dry-run 返回差异并拒绝提交，避免静默漏记。

## 4. 运行时流程

### 4.1 预检

程序确定唯一 Wiki 根目录，读取根 `index.md`，检查根入口存在且可解析。用户明确指定页面时可直接把该页面加入第一阶段，不强制读取无关入口。

### 4.2 阶段一：ReadPlan

模型只得到任务和短入口，输出 ReadPlan。程序校验后并发读取精确页面；不扫描全 Wiki、不读取 Raw、不加载旧聊天记录。

### 4.3 阶段二：SynthesisAndChangePlan

模型得到真实读取结果后，输出回答和 ChangePlan：

- 只读任务：`changePlan` 为空，程序立即返回 `answer`。
- 写入任务：程序将 `changePlan` 转为现有 `wiki apply` 的批量操作。
- 资料不足：模型返回一次补充 ReadPlan；补读后重新进入阶段二。

### 4.4 程序提交

程序按以下顺序处理：

1. 校验所有目标路径、证据路径和操作类型。
2. 根据正文、移动、删除和目录变化计算受影响目录集合。
3. 为每个受影响目录确保 `index.md` 存在。
4. 更新直属入口、根入口、精确双链、来源登记和日志。
5. 执行指纹冲突检查和零落盘 dry-run。
6. 普通写入直接提交；危险操作沿用现有确认策略。
7. 重读正文、全部受影响 `index.md`、入口链接和指纹。
8. 验证失败时整批恢复并返回真实恢复状态。

## 5. `wiki-creator` Skill 边界

保留/创建 `wiki-creator`，但它只负责：

- 首次建库时根据用户资料提出最小目录结构。
- 为根目录和必要分区生成 `index.md` 草案。
- 用户明确要求时修复或迁移旧 `_index.md`。

它不负责日常写入的一致性，也不能替代运行时的 `WikiSynthesisAndChangePlan` 和程序硬不变量。日常每一次 Wiki 写入都必须自动维护入口，即使用户没有选择 `wiki-creator`。

不新增单独的 `wiki-maintainer` Skill 作为强制链路；把核心规则放在产品协议和程序校验中，避免 Skill 未触发时留下不完整入口。

## 6. 最小循环和终止条件

| 场景 | 模型请求 | 终止条件 |
| --- | ---: | --- |
| 指定页面总结 | 1 | 读取结果已提供，返回 answer |
| 普通 Wiki 查询 | 2 | ReadPlan 读取完成，返回 answer |
| Wiki 写入/续写 | 2 | ChangePlan 提交、索引和写后验证成功 |
| 首轮资料不足 | 3 | 一次补充 ReadPlan 后完成或明确缺失 |
| 计划非法/冲突 | 2-3 | 程序拒绝并返回具体错误，不自由重试 |

固定循环数只保留为传输或失控熔断，不参与成功判定。写入成功后由程序直接生成回执，不依赖额外模型请求。

## 7. 红灯测试

1. 根 Wiki 没有 `index.md` 时，普通查询停止并提示先建库；建库任务可创建它。
2. 新建任意 Wiki 子目录时，事务同时创建该目录的 `index.md`。
3. 在子目录新增页面时，子目录 `index.md` 和根入口按直属关系更新一次。
4. 移动页面时，旧目录和新目录的 `index.md` 同批更新，旧链接不存在。
5. 删除页面时，入口条目和受影响双链同批移除；仍有活动入链则拒绝。
6. 模型遗漏 `indexChanges` 时，程序从 operations 推导并拒绝不完整计划，不静默落盘。
7. 读取清单重复路径、越界路径或不存在路径时，不执行文件读取。
8. 两阶段正常写入最多两次模型请求；不得出现固定 12/64 轮循环。
9. 第二阶段只返回 answer 不含 changePlan 时，读任务成功，写任务显示未提交且不伪报成功。
10. 入口写入失败时正文回滚；恢复失败时返回 `recovery-required`。
11. `@Wiki + 具体 Skill` 中 Skill 只影响内容方法，不改变索引维护规则。
12. 三端对同一 Wiki 快照产生相同的 index.md 和链接结果。

## 8. 实施顺序

```text
1. 新增 ReadPlan/WikiSynthesisAndChangePlan schema 与红灯
2. 将 @Wiki 从自由工具循环切换为两阶段请求
3. 在 wiki apply 前增加受影响目录 index.md 不变量和自动补齐
4. 将导航、来源、日志、双链和写后验证纳入同一事务
5. 将 wiki-creator 限定为建库/迁移 Skill
6. 删除 Wiki 专用固定循环和重复检索补丁
7. 运行 focused、TypeScript 和三端真实模型验收
```

## 9. 完成定义

- ReadPlan 和 WikiSynthesisAndChangePlan 都有严格 schema、非法输入测试和真实路径校验。
- 普通 Wiki 查询和写入不再依赖开放式循环。
- 任意 Wiki 写入都不会产生缺失的根或受影响目录 `index.md`。
- 正文、入口、双链、来源和日志要么全部成功，要么全部恢复。
- `wiki-creator` 可用于首次建库和入口迁移，但日常写入不依赖它。
- 没有执行的真实模型、Desktop、Web、Mobile 场景只能标记为待验收。
