# 短剧改编：时间账与逐集改编TDD

> 2026-10-28。状态：**用户已确认，两阶段一起实施；源码已实施，自动化回归通过；真实标注质量、秒数贴近度和改编效果未验**（见第12节）。在 [[开发/短剧改编一遍标注与程序组装TDD-2026-10-28]] 的基础上，把拆集依据从“节拍数”改为**时间账**，并把“删减、压缩、影视化”落成独立的逐集改编步骤。保留：节点目录来源、按章号排序、行号截取、文件头资产链接、预设风格、全自动运行器与续做。

## 0. 用户口径

- 字数不是拆集依据，**内容**才是：看冲突在哪、升级在哪；无升级的嘴炮就是一集，要删减。
- **打斗动作和对白都占时间**；场景、穿着、武器描写在漫剧里是一张图，与字数无关。
- 核心是：**按内容规划时间，按时间改编剧本。**
- 重要度决定展开：小怪展示新技能一集搞定；决定命运的决战可以细写成很多集（动作、反应、旁人视角、原文已有的回忆与成长经历）。
- 切分没问题，下一步再改编：删减、压缩对白、影视化；第一集最重要，可把最矛盾、最有代入感的一段提前（冷开场），也可以顺叙，不变原著只做影视化处理，改编策略不止一种。
- 切分与改编要完全对得上。

## 2. 总体流程

1. **读＋标注**（每次约20章，一遍）：资产、事件文档，以及**回合**标注（动作单元、重要度、峰值、钩子、可闪回素材、跳过段）。
2. **程序切分**：算每个回合的自然时长和计划时长 → 算每个事件的集数 → 选切点 → 生成原文直出的分集剧本（保底，漫剧立即可读）、切分记录、**切分卡**、分集清单。
3. **逐集改编**（模型，每轮约3集）：按切分卡里的时间预算删减、压缩对白、影视化、选开场策略、细写；每场戏标时间和出处。**第一批先出样集**（第1集＋一个重大回合所在集），用户确认后再批量。
4. **收尾**：造型表回填集号，写分集梗概。

## 3. 时间账

### 3.1 参照表（动作单元，默认取中值，范围见说明）

| 单元 | 说明 | 秒（范围） |
| --- | --- | --- |
| 快招 | 一次出拳、踢击、斩、射箭 | 2（1.5–3） |
| 攻防 | 出招加格挡、闪避或受击反应 | 4（3–5） |
| 技能 | 起手、光效变化、激发、命中、反应 | 8（6–10） |
| 大招 | 大招或进化展示：蓄力、特写、全场反应、结果 | 15（10–20） |
| 走位 | 跑动、跳跃、换位、追逐 | 3（2–4） |
| 反应 | 受击倒地、表情特写 | 2（1–3） |
| 全景 | 战场全景、环境空镜 | 3（2–4） |
| 停顿 | 对峙、蓄势、情绪停顿 | 3（2–5） |
| 面板 | 系统提示、属性面板弹窗，每条 | 2.5（2–3） |
| 闪回 | 回忆闪回，每段 | 6（4–8） |

依据：动作片平均镜头长度约2秒（《量子危机》1.7秒，《谍影重重》多数打斗镜头约1秒），AI漫剧一个镜头建议3–5秒，所以一个镜头装1–2个动作单元，一场60秒的打戏约15–20个镜头。全局**节奏系数`pace`**（默认1）缩放单元秒数，样集后可调。

### 3.2 对白

对白秒＝引号内字数÷4（每分钟240字）＋每段对白0.5秒。由程序按正文精确计算。

### 3.3 回合的两个时长

- **自然时长**＝对白秒＋Σ（单元数×单元秒×pace）。
- **计划时长**＝自然时长×档位系数。档位由模型按重要度选：压缩0.6、如实1.0、细写2.0、决战3.0。细写和决战必须写理由；系数封顶3倍，用户可以按事件单独突破（如“E27展开到10集”），突破部分由改编细写补足。
- 细写只扩**表现**：动作单元、反应、旁人视角、原文里已有的回忆和成长经历；不新增事件、能力、结果、关系。

### 3.4 集数与切点

预设风格给出单集时长区间（秒）：

| 预设 | 最短 | 目标 | 最长 |
| --- | --- | --- | --- |
| 快节奏爽剧 | 60 | 75 | 90 |
| 标准剧情 | 75 | 90 | 120 |
| 大场面奇幻 | 90 | 120 | 150 |

平台硬上限180秒。

- 事件集数n＝round(Σ计划时长÷目标)，再夹在[⌈Σ÷最长⌉, ⌊Σ÷最短⌋]内（至少1集；区间为空时取下限）。
- 计划时长超过“最长”的回合，先按行（段落）边界、按累计自然时长切成⌈计划时长÷最长⌉份，份与份之间允许切开（改编时细写补足）。
- 切点只落在回合边界或上述份的边界，用动态规划选：各集计划时长与Σ÷n的偏差平方和最小，落在钩子回合末尾的切点有加分；**每集计划时长不得小于最短的一半**（避免碎片集）；事件只有一个回合且不超过最长，就是一集。

### 3.5 标注的新格式

事件里的`beats`和`delete`改为`rounds`和`skip`（旧格式拒绝，提示改用新格式）：

```json
{"event":"E27_强援联手与沼泽猎蟒","start":{...},"end":{...},
 "rounds":[{"chapter_heading":"第66章 …","line":48,"desc":"牵线备战","result":"局势平稳",
   "units":{"面板":2,"停顿":1},"tier":"压缩"},
  {"chapter_heading":"第67章 …","line":43,"desc":"巨蟒压制，猪突猛进险些被吞","result":"坏人占上风",
   "units":{"攻防":3,"技能":1,"反应":2},"tier":"细写","why":"主角队伍首次面对越级巨兽，关系到后文全部战局",
   "hook":true,"peak":true,"flashback_sources":[{"chapter_heading":"…","start_line":20,"end_line":30}]}],
 "skip":[{"chapter_heading":"第0章 …","start_line":14,"end_line":56,"reason":"主角技能树设定面板，已写进世界规则"}]}
```

- 回合的范围：从它的起点行到下一个回合起点的前一行；最后一个回合到事件终点。回合必须覆盖整个事件（第一回合起点＝事件起点）。
- `result`写这一回合结束时的局势变化（谁占上风、新人物登场、新信息）；无升级的嘴炮写成一个回合。
- **漏标诊断**：回合自然时长超过180秒，且没有`single:true`加`why`，就拒绝保存并提示“可能含多次局势变化，请拆成多个回合”。
- `skip`只放确定不进剧情的内容（设定面板、作者感言等），必须写理由；其余内容的删减判断全部放在改编步骤。
- 事件之间没有覆盖也没有`skip`的行，由程序记入分集清单的`gaps`，不再静默丢弃。

### 3.6 重大回合清单

清单里列出档位为细写、决战的回合（事件、回合、理由、计划集数），写入分集清单，运行结束时一并报告；不阻塞，用户一句话可调整。

## 4. 切分卡（切分与改编的接口）

程序为每集生成`改编方案/切分卡/第NNN集.md`（模型不能自己写这个类型），内容：

| 项 | 改编怎么用 |
| --- | --- |
| 所属事件，本集在事件中的位置（第x/n集） | 衔接上一集钩子与下一集开头，避免重复 |
| 回合清单：描述、结果、档位、自然时长、计划时长 | 决定哪里压缩、哪里细写 |
| 时间预算：目标区间，计划总秒；对白秒、单元清单 | 压缩对白、调整动作量 |
| 峰值回合和行号 | 冷开场候选 |
| 结尾钩子（本集最后一个回合的结果） | 结尾处理 |
| 可闪回素材的行范围 | 细写和闪回的来源 |
| 出场资产链接 | 与文件头一致 |
| 原文路径与行范围 | 出处校验 |

## 5. 逐集改编

### 5.1 做什么

模型读切分卡、本集原文和资产，一集一轮（每轮约3集）：

1. **删减**：去掉没有冲突、没有爽点的内容，系统面板压成一句或转成画面。
2. **压缩对白**：对白秒不得超过本场时间；保留意思、说话人、信息差。
3. **影视化**：场景、人物、道具、动作写成漫剧能直接出图的描述，一个画面一行；外貌服装不重复，靠资产链接。
4. **选改编策略**，写进文件头`strategy`：顺叙影视化（默认）、冷开场（把峰值回合提前几秒到十几秒再回到建置，演到该处不原样重演）、悬念开场、倒叙或闪回、交叉剪辑、细写扩展。第1集默认考虑冷开场，素材可取自后文，须标出处。
5. **细写**：只对计划时长大于自然时长的回合，规则见3.3。

### 5.2 保存与校验

沿用`episode_source_script`，短剧路线新增内容形式`{"adapted":{"strategy":"冷开场","scenes":[{"title":"…","role":"main","seconds":22,"sources":[{"chapter_heading":"…","start_line":12,"end_line":20}],"text":"…"}]}}`。程序生成文件：

```
---
event: "[[…]]"
strategy: 冷开场
seconds: 118
characters: …  scenes: …  props: …（按改编后正文匹配）
sources: ["第66章 12–20行", …]
---
【场1 约22秒｜对白9秒＋其余13秒】
……
```

- 硬校验（拒绝）：每场必须有`seconds`和`sources`；`main`的出处必须落在本集原文范围内；`cold`和`flashback`的出处可取目标章节内任意行，但合计不得超过本集总时长的25%；某场对白秒（程序按正文重算）超过本场时间；总时长超过180秒。
- 软校验（回执里警告，要求模型修正）：总时长超出预设区间；与切分卡计划总秒偏差超过25%。
- 保底：程序在切分时已生成原文直出版（正文只有原文）；改编保存用同一路径覆盖。未改编的集仍可被漫剧读取。
- 保真说明：改编后正文由模型改写，程序保证的是出处、时间和范围，**不保证零新增**，由样集抽检。

### 5.3 样集先行

第一批的第一轮读完、程序切分后：改编第1集和第一个含细写或决战回合的集（没有则取计划时长最大的集），暂停等用户在样集卡上选：继续批量改编、整体偏快（`pace`×1.2，重算并重出样集）、整体偏慢（`pace`×0.85，同上）、停止。确认卡上可关闭“样集先行”，也可选“只切分、不改编”。

## 6. 全自动运行器

每批：规划×N → （首批）样集改编 → 样集确认 → 逐集改编（每轮`adaptSize`集，默认3，跳过样集）→ 收尾。指令：

- 【全自动改编·规划】沿用，内容改为按回合标注和时间账。
- 【全自动改编·改编】第a–b集：读切分卡，按时间改编。
- 【全自动改编·收尾】沿用。

完成判断：规划看分集清单的`planned_through`；改编看区间内每集文件头出现`strategy`且内容在本次运行中变化；**收尾看分集梗概是否覆盖全部集号**（修复误判）。

## 7. 附带修复

- 道具一档一件：Skill明确“不写汇总档”，程序在分集清单的`warnings`里提示（道具档案含4个以上二级标题或6条以上加粗条目）。
- 场景档案要写别名（沿用项目资料Skill），文件头匹配继续用名字、别名、事件文档链接标签。
- 旧版分集清单（无时间账）不提供续做，提示重新规划。

## 9. 测试（先红后绿）

1. **时间账纯函数**：对白秒（含引号种类、段数）、单元秒（含pace）、自然与计划时长、封顶3倍、用户突破。
2. **标注校验**：回合必须覆盖事件；起点递增；未知单元名；细写和决战缺理由；自然时长超180秒的漏标诊断（含`single`放行）；`skip`缺理由；旧`beats`和`delete`格式被拒绝。
3. **集数与切点**：n的计算与区间夹取；超长回合内切；碎片保护；钩子加分；单回合事件为1集；各集计划时长偏差最小；决战级突破后的集数。
4. **切分卡与清单**：卡内各项齐全；`gaps`、`heavy`、`warnings`；模型直接保存`adaptation_card`被拒绝；原文直出版仍是只有原文的正文加文件头。

7. **界面**：确认卡的样集先行、每轮集数、只切分不改编；样集确认卡；进度芯片显示阶段。
8. **Skill合同**：时间账表、回合与档位、改编策略、出处与时间标注、道具一档一件。

## 10. 实施顺序

- **阶段一**：时间账、回合标注、切分、切分卡、清单与附带修复。完成后重跑塔防的规划，**先看切分卡和重大回合清单**，再决定是否进入阶段二。
- **阶段二**：逐集改编、样集先行、运行器与界面。

## 11. 风险与验收边界

- **动作单元计数是估计**：靠参照表范围、样集校准和`pace`缓解；以后漫剧出了真视频，还可以按实际时长校准。
- **细写扩张**：默认封顶3倍，决战级要写理由并列入重大回合清单。
- **保真**：改编由模型改写，程序只能保证出处、时间和范围，质量靠样集抽检和你的审阅。
- **调用量**：改编约“集数÷3”轮，124集约42轮；仍比逐集一轮少，且可以只切分不改编。
- 自动化测试只证明机制；回合标注是否准确、秒数是否贴近真实、改编是否好看，要用塔防前20章和样集实测。
