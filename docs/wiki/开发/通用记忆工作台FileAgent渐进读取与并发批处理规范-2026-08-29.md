# 通用记忆工作台 File Agent 渐进读取与并发批处理规范

> 日期：2026-08-29
> 状态：设计已确认，待按 TDD 实施
> 上位合同：[[通用记忆工作台显式能力Agent与统一任务协议TDD-2026-08-28]]

## 0. 核心决定

`@文件` 是用户授权路径范围内、以完成任务为终点的文件任务 Agent。它不是无限自主 Agent，但也不能用“一次模型请求”或上下文大小阻止用户明确要求的任务。

```text
用户任务 + 用户授权的文件/文件夹 + 已选 Skill
  -> 程序建立可信清单并归一化需要的文档
  -> 小任务：一次模型请求
  -> 复杂定向任务：按目录层级渐进读取
  -> 明确全量任务：受控并发批处理
  -> 模型给出最终 answer + 可选 actions
  -> 程序预览、审批、确定性执行和验证
  -> 模型答案 + 独立程序回执
```

用户决定授权边界，模型决定完成任务所需的内容，程序负责真实清单、读取、转换、并发、状态和执行。简单任务不增加流程；复杂任务允许模型与程序多段协作，直到取得用户要求的结果或遇到真实阻塞。

## 1. 三种执行路径

程序根据用户任务和授权范围选择最短且能完成任务的路径，不要求用户切换模式：

| 路径 | 适用任务 | 执行方式 |
| --- | --- | --- |
| 快速路径 | 一个或少量明确文件、新建明确文件 | 程序预读，模型请求一次，可选执行一次 |
| 渐进路径 | “从这个目录找出相关资料并回答/改写”等定向任务 | 临时目录索引逐层披露，模型选择最少必要子树和文件 |
| 全量路径 | “处理全部文件、逐个总结、整理整个桌面”等穷尽任务 | 完整文件账本、受控并发分批、最终综合和统一执行 |

任务规模只决定执行路径，不决定是否完成。程序不得因为目录大、层级深或一次上下文放不下就要求用户放弃已经明确授权的完整任务。

## 2. 能力边界

File Agent 只负责用户明确授权路径的以下动作：

- `read`：读取一个或多个精确文件，或用户明确选择文件夹中的受支持文档；多个文件受控并发读取，保留部分成功结果。
- `write`：创建或完整写入一个文本文件。
- `edit`：对一个文本文件执行精确替换。
- `mkdir`：创建明确指定的目录及缺少的父目录。
- `move`：移动或重命名一个明确指定的文件或目录。
- `delete`：回收一个明确指定的文件或目录。

File Agent 不负责：

- `glob`、`grep`、项目全盘扫描、未经用户授权的目录递归或模型猜测路径。
- 根据 Wiki 索引寻找资料；需要发现 Wiki 内容时使用 `@Wiki`。
- 自动读取相邻文件、旧聊天记录、全部附件、全部 Skill 或全部 Wiki。
- 自己创建 Provider、SSE、审批器、文件服务、长期会话或通用模型循环；全量任务只允许保存完成任务所需的临时可恢复账本。

## 3. 路径授权

程序只接受以下路径来源：

1. 用户在界面选择并形成文件标签的路径。
2. 当前用户消息中明确粘贴的项目内路径。
3. 当前用户消息中明确粘贴的项目外绝对路径；沿用现有审批规则。
4. 模型为“新建、移动、重命名、整理”生成的目标路径：明确目标任务使用用户给出的文件名和目录；“整理整个授权目录”可以在该授权根内生成分类目录，但不能移出授权根。

路径在进入模型和执行器前统一规范化。禁止 `..`、空路径、隐藏的根目录扩大、未经授权的项目外路径和对系统骨架、Raw 对话记录、画布记录的越权修改。

文件夹授权规则：

- 用户选择具体文件时，只处理这些文件。
- 用户选择文件夹且任务没有表达全量/递归含义时，默认先提供直属清单，模型按渐进路径请求必要子树。
- 用户明确要求“全部、整个、所有、包含子文件夹、递归”时，授权覆盖该文件夹完整子树并走全量路径。
- 递归授权只覆盖所选文件夹，不扩大到父目录、兄弟目录或软链接指向的外部目录。
- 目录清单由程序确定性生成，模型不能根据清单追加路径。

## 4. 文档格式归一化

模型不直接读取二进制 Office/PDF。程序在模型请求前复用现有文档转换链路，把每个来源转换为独立的 Markdown 可读表示，同时保留原始文件。

| 原文件 | 给模型的可读表示 |
| --- | --- |
| `.ppt/.pptx` | 按幻灯片编号组织的标题、正文、表格和可提取备注 |
| `.pdf` | 带页码边界的正文；扫描件返回 `ocr_required`，不伪造空内容 |
| `.doc/.docx` | 保留标题、段落、列表和表格结构的 Markdown |
| `.xls/.xlsx` | 按工作表分区的表格内容，保留工作表名称 |
| `.md/.txt/.csv/.json` 等文本 | 直接读取并保留来源路径 |

Desktop 复用内置 AnyDoc；Web/Mobile 复用现有云端文档转换。已存在的 Markdown 可读副本按原文件 SHA-256、转换器版本和输出 schema 判断：原件未变化则复用，原件变化则重新转换，用户手动编辑过的可读副本继续保留编辑结果。

多个文档不能无边界拼接，必须带来源元数据分别发送：

```text
<file path="资料/汇报.pptx" type="pptx" fingerprint="...">
[幻灯片 1]
...
</file>

<file path="资料/数据.xlsx" type="xlsx" fingerprint="...">
[工作表：预算]
...
</file>
```

单个文件转换失败时，将真实错误记入该文件状态；其他文件继续处理。扫描 PDF 不伪造空内容；存在显式 OCR 能力时交给对应能力，没有时标为 `blocked:ocr_required` 并在最终结果中明确告知。

## 5. 渐进路径：临时目录索引

复杂定向任务复用 Wiki Agent 已验证的渐进披露经验，但索引由程序根据用户授权目录临时生成，不写入磁盘：

```text
授权目录根清单
  -> 模型返回需要查看的直属子目录/文件
  -> 程序返回真实下一层清单或文件内容
  -> 模型继续选择，或确认资料充分
  -> 模型输出最终 answer + 可选 actions
```

临时索引只包含相对路径、类型、大小、修改时间和直属子项统计。模型只能请求当前索引列出的路径，不能跳出授权根、猜测不存在的文件或自动追加其他能力。同层独立路径可并发读取。

结构反馈保持最小且宽容：

```json
{ "status": "need_more", "paths": ["角色/关羽.docx", "剧情/第一卷/"] }
```

`status` 缺失时可以根据 `paths` 或 `answer` 推断；JSON 代码块可以解析；计划解析失败时保留原始文字，并只请求模型修正下一步路径或 actions，不删除已经生成的答案。重复计划不是立即失败：程序把已读取清单和重复原因反馈模型；只有没有新增读取、结果、文件状态或合法计划时才标记停滞并尝试一次纠正。

## 6. 全量路径：并发批处理

用户明确要求处理授权范围内全部内容时，程序建立完整文件账本，不能由模型决定遗漏哪些文件：

```text
程序递归清点授权子树
  -> 每个文件进入 pending
  -> 受控并发转换 Office/PDF
  -> 按当前模型上下文和文件边界组批
  -> 独立批次受控并发交给模型
  -> 每个文件进入 completed / retry / blocked
  -> 等待所有文件到达终态
  -> 模型综合全部成功结果和阻塞清单
  -> 生成最终 answer + 可选 actions
```

分批不使用固定文件数。程序为系统提示、Skill 和输出预留上下文，尽量保持文件完整；单文件超限时按 Word 标题、PDF 页、PPT 幻灯片、Excel 工作表等自然边界拆分，并保留路径和分段编号。

独立的转换和模型批次可以并发；共享目标文件的动作、批量移动、删除和 Wiki apply 必须在完整计划校验后有序执行。并发度由现有 Provider 限流和设备能力控制，不写成模型协议的一部分。

批处理使用任务级临时账本：`runId`、授权根、任务指纹、文件指纹、批次状态、暂存结果、失败原因和待执行动作。App 中断后继续未完成批次，已成功批次不重复执行；任务完成后清理临时状态。这是可恢复任务状态，不是聊天记忆。

全量任务的完成条件是授权范围内每个文件都有 `completed` 或真实 `blocked` 状态，并且存在最终答案和所有副作用的程序回执。`blocked` 文件必须逐项告知，不能伪报完整成功。

## 7. 模型反馈与程序配合

快速路径中，模型收到的内容只有：

- 当前用户消息。
- 用户本轮授权范围内文档的实际读取/转换结果或真实错误。
- 用户本轮明确选择的具体 Skill 规则。
- 每个已读取文件的规范化路径和程序保存的冲突指纹。

渐进路径额外接收当前层临时索引和已读取 Observation；全量路径接收当前批次内容或最终批次结果。所有路径都不发送旧对话、未授权项目清单、Wiki 入口或其他未选择能力。

模型只需返回最小结果，不直接生成完整 `TaskEnvelope`：

```json
{
  "answer": "给用户看的最终内容",
  "actions": [
    {
      "kind": "write",
      "path": "资料/结果.md",
      "content": "完整正文"
    }
  ]
}
```

约束：

- `answer` 必须存在；没有副作用时 `actions` 为空数组。
- `actions` 只允许 `write/edit/mkdir/move/delete`。
- 模型不得声称动作已经成功，也不填写工具结果、指纹、回执或审批状态。
- ActionPlan 无法解析时保留模型答案，只请求修正 actions；仍无法得到合法 actions 时不执行副作用，但不能抹掉内容结果。
- 程序把合法的最小结果映射到共享 `TaskEnvelope`，统一协议复杂度不暴露给模型。

程序不以固定模型轮数或“每轮结果数量必须减少”判断任务失败。以下任一变化都表示有效推进：新增真实读取、新批次完成、文件状态变化、新有效结论或新合法动作计划。只有文件损坏、权限不足、缺少已要求的 OCR、磁盘失败或 Provider 持续不可用等真实条件才能阻塞任务。

## 8. 确定性执行

程序在执行前一次性校验全部动作：

1. 动作属于 File Agent 白名单。
2. 源路径和目标路径均由当前任务授权。
3. 路径位于允许范围，没有越过项目根目录。
4. 写入、编辑、移动和删除前的真实指纹仍与模型请求前的快照一致。
5. 移动目标和新建目标不存在冲突。
6. 移动、删除、项目外写入等动作已经取得现有审批。

校验失败时零副作用。校验通过后按依赖执行完整动作计划；动作完成后重新读取或检查目标，验证存在性、内容指纹和源路径状态。程序回执记录动作、路径、执行状态、前后指纹及失败原因。

模型答案和程序回执相互独立：执行失败、取消或验证失败都保留 `answer`，不得把内部工具输出拼进回答正文。

二进制输出按目标扩展名选择现有格式生成器：新建 `.docx/.pptx/.xlsx/.pdf` 时生成新文件，不把模型文本直接写入二进制。阶段 4 不承诺原地保真编辑已有 Office/PDF；需要保留复杂排版时保留原件并输出新文件。Markdown/TXT 等文本仍使用普通 File Executor。

## 9. Wiki 路径的执行路由

File Agent 可以读取和操作用户明确指定的 `wiki/` 精确路径，但不得用普通文件写入器绕过 Wiki 一致性维护。

```text
普通项目路径
  -> 现有 File Executor

wiki/ 下的读取
  -> 现有精确文件读取器

wiki/ 下的 write/edit/mkdir/move/delete
  -> 程序转换为一次 Wiki apply
  -> 现有 Wiki Runtime 事务执行
```

这不是再次启动 Wiki Agent。File Agent 不读取 `index.md` 寻路，不做 Wiki 语义规划；程序只根据已经确定的目标路径选择正确执行器。

最小动作映射：

| File action | Wiki operation |
| --- | --- |
| 新文件 `write` | `create` |
| 已有文件 `write` | 以预读原文为 `oldText` 的完整 `replace` |
| `edit` | `replace` |
| `mkdir` | `mkdir` |
| `move` | `move` |
| `delete` | `trash` |

Wiki Runtime 继续负责父目录、受影响 `index.md`、导航双链、日志、冲突检查、回滚和写后验证。File Agent 不要求模型描述这些派生维护动作。

示例：

```text
用户：@文件 把整理后的关羽资料写入 wiki/角色/关羽.md
程序：读取精确路径；不存在则记录 missing
模型：返回 answer + write(wiki/角色/关羽.md)
程序：将 write 转为 Wiki create/replace，调用一次 Wiki apply
界面：显示 answer，并显示“已写入 wiki/角色/关羽.md”
```

直接用普通文件写入器创建 `wiki/角色/关羽.md` 会造成页面存在但 `角色/index.md` 不可发现，因此属于禁止实现。

## 10. Skill 组合

`@文件 + 具体 Skill` 使用同一三路径协议：

```text
当前消息 + 授权文件范围 + Skill 规则
  -> 快速、渐进或全量处理
  -> 模型 answer + 可选 actions
  -> 程序确定性执行
```

Skill 只决定如何分析、改写和组织内容，不能扩展路径、激活 Wiki 检索、MCP、Terminal、媒体或 3D。Skill 需要其他能力但用户没有显式选择时，模型返回缺少的连接，不自动扩权。

## 11. “整理桌面”标准流程

“帮我整理桌面文件夹”是全量路径的典型任务：

```text
用户通过选择器授权桌面目录
  -> 程序建立直属清单；用户明确要求子目录时才递归
  -> 模型先按文件名、类型、日期分类
  -> 只有无法判断的文档才解析正文
  -> 大目录按文件账本受控并发分类
  -> 程序合并成一份完整 mkdir/move 计划
  -> 展示创建、移动、保持不动和冲突预览
  -> 用户确认一次
  -> 程序执行、验证；失败时按反向动作恢复
  -> 返回模型总结和真实整理回执
```

外部桌面目录必须由系统文件夹选择器明确授权，不能仅凭“桌面”文字访问。默认忽略系统隐藏文件和软链接外部目标；不覆盖同名文件，不把文件夹移动进自身，不允许模型操作清单外路径。

移动前必须展示完整预览；同名冲突等待用户选择保留两份、替换或跳过。每个已执行移动都保存反向动作，中途失败时先停止依赖后继，再恢复已移动内容；无法恢复的路径必须逐项报告。

大型桌面按账本显示真实进度，例如“已分类 1830/2400、待处理 560、冲突 10”，不能用模型轮数代替完成度。

## 12. 界面与回执

- 输入区只显示用户选择的文件标签，不在正文重复插入 `@文件` 路径文字。
- 纯读取和纯回答只显示模型答案，不显示额外状态卡。
- 实际发生副作用时显示一张极简程序状态卡：成功、失败、取消，及受影响路径。
- 成功状态不复述完整正文；失败状态显示可操作的最短原因。
- 详细前后指纹保留在程序回执中，不作为默认界面噪音。
- 大型任务显示文件总数、已完成、重试、阻塞、冲突和待确认动作；不显示内部 JSON 或模型循环轮数。

## 13. 根因回归门禁

实施前先写红灯测试，至少覆盖：

1. 未选择或未明确路径时不读取、不扫描、不执行。
2. 多文件并发读取中一个失败，其他成功内容仍进入同一次模型请求。
3. 快速路径纯读取任务零副作用，模型只请求一次。
4. 新建文件任务无需预读，不增加空模型轮次。
5. 冲突指纹变化时零写入，并保留模型答案。
6. 写入失败或写后验证失败时保留模型答案，程序状态为失败。
7. `wiki/` 写入只调用一次 Wiki apply，不调用普通 `write/edit/mkdir/move/delete`。
8. Wiki 写入后正文、受影响 `index.md`、双链和日志通过现有 Wiki Runtime 验证。
9. `@文件 + Skill` 只加载已选 Skill，不暴露其他能力。
10. 模型结果解析失败时不执行动作，原始文本仍可见。
11. 选择文件夹默认只提供直属清单；未明确递归且模型未从直属清单请求子目录时，不进入子文件夹。
12. 复杂定向任务按临时目录索引渐进读取，不越过授权路径。
13. PPT/PDF/DOCX/XLSX 复用现有转换链路，单个转换失败不删除其他成功结果。
14. 全量任务超出单次上下文时自动分批，所有文件进入 completed/blocked 终态，不静默截断。
15. 二进制输出调用现有格式生成器，不用文本 `write/edit` 覆盖 Office/PDF 原件。
16. 结构解析失败保留答案和已完成结果，只纠正路径/actions，不整轮清零。
17. App 中断后从任务账本继续，已成功批次不重复处理。
18. “整理桌面”在移动前展示完整预览并确认；冲突不覆盖，失败可恢复。
19. Wiki 目标仍汇总为 Wiki Runtime 事务，不由并发批次直接写入。

完成门禁：File Agent 专项测试、既有文件与 Wiki Runtime 回归、完整 focused 测试、TypeScript 和差异检查通过。Desktop/Web/Mobile 未执行的真实路径与审批矩阵必须明确标记为未验证。

## 14. 实施删除项

阶段 4 实施时删除或绕开以下冲突设计：

- `@文件` 落入通用 `runDirectChatCompletion` 工具循环。
- File Agent 暴露 `glob/grep` 并允许模型扩大读取范围。
- 让所有任务强制使用同一种固定轮次流程。
- 用固定工具轮数补救未完成任务。
