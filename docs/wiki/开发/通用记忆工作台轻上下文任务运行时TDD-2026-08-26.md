# 通用记忆工作台口令激活无记忆任务运行时 TDD

> 日期：2026-08-26  
> 状态：第三段已实施（请求上限、第三轮限制、滚动工作集、写后收尾、最小工具路由、Raw 精确只读授权），真实模型验收待实施  
> 范围：统一对话入口、口令激活、短任务状态、工具按需挂载、有限工具循环、Raw 显式授权与真实模型性能验收
> 前置：先完成 [[通用记忆工作台原生Wiki能力与五Skill退役TDD-2026-08-26]]；本 TDD 直接消费其原生 Wiki 命令与入口合同，不再依赖五个 Wiki Skill

> Wiki 查询、根据 Wiki 创作和回答后的确认写入以 [[通用记忆工作台索引优先Wiki查询与确认写入TDD-2026-08-27]] 为专用合同：默认使用一次性 `wiki_context`，确认写入由程序直接完成，不走本 TDD 的通用 Wiki 工具循环。本 TDD 的 `3`/`5` 次请求上限和滚动工作集继续约束普通文件、Terminal、MCP、Skill、媒体与 3D 任务。

## 1. 用户决策

通用记忆工作台不拆成多个聊天模式，也不新增“专业创作模式”。产品只有一个统一对话入口：用户用当前口令激活当前能力，运行时只完成这一条单线程任务。

```text
产品能力：原生 Wiki、项目文件、Skill、媒体、3D、Terminal、MCP 全部保留
当前请求：只挂载本轮口令需要的能力
跨任务模型记忆：0
同一任务短期状态：最近 3 个完整问答轮，历史最多 12K tokens
默认长期事实源：当前项目 Wiki 与用户明确指定的文件
Raw 对话：默认不可见；用户本轮明确要求时，只读开放指定范围
普通 Wiki/文件任务：最多 3 次模型请求，不再继承 64 轮开放循环
执行方式：任务步骤串行；同一步互不依赖的只读工具并发
```

“所有工具都能使用”表示产品能力没有删除，不表示每次请求都把所有工具定义发送给模型。媒体创作继续打开现有创作面板，3D 继续打开现有 3D 编辑器对话框；它们由同一个用户入口激活，但不进入普通 Wiki/文件任务的工具负载。

## 2. 根因与纠偏

### 2.1 已确认根因

超过 9 分钟的简单文档任务中，本地文件工具单次约 `2-80 ms`，超过 `99.9%` 的时间消耗在模型请求等待与生成。旧链路同时存在：

1. 大文档以内联正文和 `read` 结果重复进入上下文。
2. 无关历史、Raw 提示和完整工具 schema 增大首轮输入。
3. 每个工具轮重新发送此前全部工具调用、参数和结果。
4. `read` 正文与大段 `edit.oldString/newString` 持续累积。
5. 记忆工作台未设置任务级上限，继承 Direct Engine 默认 `64` 轮。
6. 提示词只能建议模型收敛，不能保证它停止探索。

### 2.2 本轮纠偏

- 并发不是主要提速手段。只读工具本来就是毫秒级，并发只用于减少同一步等待，不替代模型请求收口。
- `64` 轮开放循环从当前产品可达链路中拿掉。普通 Wiki/文件任务最多 `3` 次模型请求；明确使用 Terminal 或 MCP 的任务最多 `5` 次。媒体面板与 3D 编辑器由用户显式操作驱动，不运行自主 `64` 轮对话循环。
- 不用另一个模型先分类。口令路由必须是本地确定性判断，不增加一次模型请求。
- 不建立摘要数据库、向量记忆、跨任务自动总结、Task Store 或多 Agent 编排。
- 写入成功由运行时验证并收尾，不再请求模型复述正文或宣布成功。

## 3. 产品语义

### 3.1 任务边界

- 一个“新建对话”是一个新任务，模型上下文从零开始。
- 同一对话中的“继续”“把刚才内容写入……”“缩短第二段”等追问属于同一任务。
- 同一任务最多保留最近 `3` 个完整 `user + assistant` 问答轮，历史正文最多 `12K tokens`。
- 当前用户消息始终完整保留，不因历史预算静默截断。
- 失败、取消、网络错误和内容过滤轮次成对排除。
- 工具调用、工具参数和工具结果不写入下一任务的模型上下文。

这不是长期记忆，而是完成“把刚才回答写入 Wiki”所需的最小短期状态。

### 3.2 统一入口与能力激活

首版只识别用户当前消息中的明确操作，不猜测隐含意图。路由优先使用用户明确选择的 Skill、MCP 或当前已打开编辑器，再使用当前消息中的目标与动作。

| 当前口令 | 本轮允许能力 | 明确禁止随请求发送 |
| --- | --- | --- |
| 查询、搜索、查看 Wiki | `wiki_search`、必要的 Wiki `read` | 写入、媒体、3D、Terminal、无关 MCP |
| 写入、更新、修正 Wiki | 目标 `read`、Wiki `write/edit`；确定性 Wiki 操作按需加入 `wiki` | 媒体、3D、Terminal、无关 MCP |
| 根据 Wiki/文件创作并写入文件 | `wiki_search/read/grep/glob` 与目标 `write/edit/mkdir` | 媒体、3D、Terminal、无关 MCP |
| 只查看本地文件 | `read/grep/glob` | 所有写工具及无关能力 |
| 明确管理文件 | 本轮点名的 `mkdir/move/delete` | 无关能力；`delete` 保留确认 |
| 明确使用 Skill | 用户选择或点名的一个 Skill，加该任务必需的最小文件/Wiki 工具 | 其他 Skill 全文与无关能力 |
| 明确使用 MCP | 用户选择或点名且已连接的 MCP 工具，加必需的最小文件/Wiki 工具 | 其他 MCP schema |
| 明确运行终端命令 | `terminal` 与必要的文件只读工具 | 媒体、3D、无关 MCP |
| 明确进行媒体创作 | 激活现有创作面板及该面板既有能力 | 普通 Wiki/文件工具循环继续运行 |
| 明确进行 3D 编辑 | 激活现有 3D 编辑器对话框及其既有控制链 | 普通 Wiki/文件工具循环继续运行 |
| 没有明确工具意图 | 不挂载工具，直接回答；缺少目标时询问用户 | 全部工具 |

同一口令包含多个明确步骤时，取所需能力的最小并集。例如“根据 Wiki 设定写入 `小说/第三章.md`”同时获得 Wiki 只读和目标文件写入能力。路由不应因出现“创作”二字自动加载媒体或 3D。

### 3.3 不新增产品模式

- 不增加“Wiki 模式”“专业模式”“高级模式”切换器。
- 不复制聊天界面、模型选择、项目状态或消息历史。
- 创作面板和 3D 编辑器继续使用现有 UI 与控制链，只改变它们从统一入口被激活的方式。
- 用户不需要知道内部工具名；口令是自然语言中的明确任务，不要求固定命令前缀。

## 4. 普通 Wiki/文件任务状态机

### 4.1 有限执行流程

```text
接收当前口令
  -> 本地确定性选择最小能力集
  -> 模型请求 1：回答，或提出同一步只读工具调用
  -> 并发执行互不依赖的 Wiki/文件只读调用
  -> 模型请求 2：回答、继续必要读取，或 write/edit
  -> 必要时模型请求 3：回答，或 write/edit
  -> 写入成功：运行时验证并直接结束
  -> 达到上限仍未完成：明确失败，不继续第 4 次模型请求
```

普通 Wiki/文件任务固定：

- 最多 `3` 次模型请求。
- 最多 `3` 个工具轮；第三次模型请求只允许返回最终回答或提交写入，不能再次搜索或读取。
- 同一失败工具调用不得原样重复。
- 达到上限后返回明确的未完成原因和最后进度，不自动重试新策略。
- HTTP 传输失败沿用现有有限重试，但必须与模型请求次数分别计数。
- 明确的超长全文任务若三请求无法完成，应提示用户缩小范围或拆分任务，不回退到 `64` 轮。

媒体面板和 3D 编辑器由各自现有 UI、控制链和审批边界负责，不使用自主模型循环。明确使用 Terminal 或 MCP 的单线程任务最多 `5` 次模型请求；达到上限明确结束。当前产品任何能力都不得重新启用 `64` 轮开放循环。

### 4.2 滚动工作集

模型请求不再携带从任务开始至今的全部工具轨迹。每次后续请求只包含：

1. 当前系统合同。
2. 当前用户消息及最多三轮短期任务状态。
3. 为满足工具协议所需的上一轮 assistant tool call。
4. 上一轮仍与当前步骤直接相关的工具结果。
5. 当前口令对应的最小工具定义。

当 `wiki_search -> read -> write` 前进到下一阶段时：

- `read` 得到正文后，较早的搜索结果退出工作集。
- `write/edit` 提交后，不再把正文、写入参数和旧读取结果发送给模型。
- 工具结果按内容去重；同一路径同一版本不重复进入请求。
- 单个读取结果超过当前模型可用输入预算时明确失败，不静默截断后继续创作。

### 4.3 写入即终点

- `write/edit` 返回成功不等于只相信提示字符串；运行时必须使用现有文件服务确认目标存在且版本、替换次数或修订号符合结果。
- 验证成功后由 App 显示确定性结果，例如“已写入 `wiki/规则.md`”，不再请求模型生成结束语。
- 验证失败时才允许在剩余请求预算内返回模型处理；没有预算则明确失败。
- 多个写入必须按模型给出的顺序串行执行；同一路径不允许并发写。
- 用户未指定目标文件时不能猜路径，先询问用户。

## 5. 并发合同

- 同一工具轮中互不依赖的 `wiki_search/read/grep/glob` 可以并发。
- 并发结果必须按原始 tool call 顺序回填，不能因完成先后改变模型输入。
- 读取依赖前一次搜索结果时必须进入下一步，不能伪并发。
- `write/edit/mkdir/move/delete`、Terminal、需审批操作和 MCP 默认串行。
- 取消信号必须同时终止当前并发读取；取消后不开始写入。
- 不新增任务队列、多线程 Agent 或后台继续执行。

## 6. Raw 对话合同

Raw 是用户控制的冷档案，不是模型自动记忆。

### 6.1 默认行为

- 新任务不注入 Raw 标题、摘要、正文、附件或路径提示。
- 模型不得自行搜索、读取或枚举 `.raw/对话记录`。
- `glob('**/*')`、项目根目录读取和普通 `grep` 不返回 Raw 对话。
- Raw 继续由 App 完整保存、展示、恢复和同步。

### 6.2 用户本轮显式授权

用户明确说“读取这段历史对话”、点名对话、或提供 Raw 对话路径时，可以在当前任务只读开放指定文件或指定目录范围。

- 授权只对当前用户消息和解析后的规范路径生效，不延续到下一轮或下一任务。
- 未点名范围时先询问，不默认开放整个 Raw。
- 路径必须在 Desktop 原生层完成大小写、`.`、`..`、分隔符、绝对路径和符号链接解析后再校验授权，不能只做前端字符串包含判断。
- Raw 永远不开放给模型 `write/edit/move/delete`。
- Terminal 读取 Raw 仍需现有用户确认；MCP 只有用户明确选择相应工具和范围时才能使用，不能借只读注解绕过本轮授权。

## 7. 附件与项目文件

- 有稳定 `readablePath` 的文本、Office、PDF 等附件只发送名称和项目路径，不内联 `textContent`、原始二进制或 data URL。
- 项目树引用文本文件只发送路径，不预读完整正文。
- 图片、视频、音频继续沿用现有原生媒体合同；只有媒体口令才激活相应能力。
- 用户要求全文时优先在一次 `read` 中使用允许的最大页长；确实超过模型输入预算时明确要求拆分范围。
- 工具读取正文只进入当前滚动工作集，不持久化为后续任务上下文。

## 8. 红灯测试

### 8.1 口令路由与工具最小集

1. “查询 Wiki 中的角色规则”只发送 Wiki 只读工具，不含 `write/edit`、媒体、3D、Terminal 或 MCP schema。
2. 下一轮“把刚才回答写入 `wiki/角色规则.md`”保留上一轮回答，只发送目标读取与 Wiki 写入工具。
3. “根据 Wiki 设定写入 `小说/第三章.md`”同时发送 Wiki 只读与文件写入工具，不发送其他能力。
4. 普通知识问答不发送任何工具定义。
5. 明确点名一个 Skill 或 MCP 时只加入该项，不加入完整 Skill/MCP 列表。
6. 媒体与 3D 口令激活现有面板/编辑器，不把普通文件工具循环继续到面板内部。
7. 路由过程不发起额外模型请求。
8. 含糊目标不会猜测写入路径，而是无工具询问用户。

### 8.2 有限循环

1. 普通 Wiki 查询在最多两轮只读后必须回答，不能产生第 `4` 次模型请求。
2. `wiki_search -> read -> write` 在第 `3` 次模型请求写入后由运行时结束。
3. 模型第三次仍请求扩大搜索时，运行时拒绝并返回上限错误。
4. 写入成功后 `sendChatCompletion` 调用次数不再增加。
5. 相同失败工具签名不能连续执行。
6. HTTP 重试与模型请求分别计数，重试不能重置任务上限。

### 8.3 滚动工作集

1. 第二次请求包含第一轮 tool call/result 和必要证据。
2. `read` 成功后，第三次请求不再包含更早的 `wiki_search` 结果。
3. 写入后不构造包含 `write.content`、`edit.oldString/newString` 或旧读取正文的新模型请求。
4. 同一路径同一修订的重复读取结果只保留一份。
5. 每次请求 token 估算包含系统提示、短期状态、工具定义和当前工作集。
6. 超过输入预算明确失败，不以 `max_tokens=1` 继续发送超窗请求。

### 8.4 并发与顺序

1. 同轮三个独立 Wiki/文件读取实际并发开始。
2. 回填顺序始终等于 tool call 顺序。
3. 搜索结果决定读取路径时分两步执行。
4. 写入、审批、Terminal 和 MCP 不进入只读并发段。
5. 取消并发读取后不执行后续写入。

### 8.5 Raw 授权

1. 未授权的相对、绝对、Windows、大小写变体和符号链接 Raw 路径全部拒绝。
2. 用户本轮明确点名的一个 Raw 文件可以读取，但同目录其他文件仍不可枚举。
3. 授权不延续到下一条用户消息和新任务。
4. Raw 写入、编辑、移动和删除始终拒绝。
5. Terminal 与只读 MCP 不能绕过未授权 Raw 范围。
6. App 自身创建、追加、重命名、列出和打开对话保持通过。

### 8.6 短期状态与附件

1. 新建对话首轮不包含其他对话内容。
2. 同一任务只保留最近三个完整问答轮，历史最多 `12K tokens`。
3. “把刚才回答写入……”能够取得上一轮回答。
4. 有 `readablePath` 的 `75 KB` 附件首次请求只含路径，不含正文哨兵。
5. 图片、视频和音频的现有 NewAPI content parts 测试保持通过。

### 8.7 能力保留

1. 产品能力注册表仍包含原生 Wiki、文件、Skill、媒体、3D、Terminal 和 MCP 能力；五个 Wiki Skill 不再是注册项。
2. 按需挂载不删除设置、审批、连接、创作历史或现有编辑器入口。
3. Desktop、Web、Mobile 只按各自已有能力路由，不给平台新增原本没有的能力。
4. 快速问答和当前项目文件预览不因路由器产生回归。

## 9. 最小实施顺序

```text
1. 锁定口令到最小工具集 -> 验证：8.1 红灯转绿，路由不调用模型
2. 给普通 Wiki/文件任务增加三请求硬上限 -> 验证：8.2 红灯转绿
3. 将全轨迹改为滚动工作集并实现写后运行时收尾 -> 验证：8.3 红灯转绿
4. 保留只读并发并锁定写入串行 -> 验证：8.4 红灯转绿
5. 将 Raw 改为规范路径上的本轮显式只读授权 -> 验证：8.5 红灯转绿
6. 跑能力、跨平台和真实模型回归 -> 验证：8.6、8.7 与第 11 节
```

不先重写整个 Direct Engine。优先复用现有工具定义、工具执行器、并发分段、审批和指标，在记忆工作台调用边界传入最小工具集、任务上限和滚动策略；只有共享引擎缺少必要钩子时才做最小扩展。

## 11. 验收

### 11.1 自动门禁

- 先证明第 8 节新增测试在旧实现上失败，再实施生产代码。
- 运行口令路由、Direct Engine、Desktop/Web Project Tools、Memory Chat、附件与 MemoryWorkbench 定向测试。
- 运行 `pnpm run test:focused`。
- 运行 `pnpm exec vue-tsc -b --pretty false`。
- 运行修改文件定向 `oxlint` 与 `git diff --check`。
- Rust 路径规范或授权若发生变化，运行对应 Rust 定向测试与完整 Rust 测试。
- 不把没有真实执行的平台、模型或安装包写成已通过。

### 11.2 真实模型前向

固定同一模型精确 ID、Provider、reasoning effort、项目快照和网络环境，每项连续执行三次：

#### A. Wiki 查询

口令：“查询 Wiki 中的指定规则并回答，不写文件。”

- `3/3` 只读取 Wiki 并正确回答。
- 每次最多 `2` 次模型请求。
- 请求体不含写入、媒体、3D、Terminal 或 MCP 工具定义。
- 三次中位总耗时不高于 `90 秒`，单次不高于 `2 分钟`。

#### B. Wiki/文档创作写入

使用约 `75 KB` 脱敏文档或同量级 Wiki 资料，口令明确指定来源、修改要求和目标文件。

- `3/3` 只修改指定目标并由运行时验证写入。
- 每次最多 `3` 次模型请求，写入后没有结束语请求。
- 首次请求附件正文哨兵 `0` 次，Raw 内容 `0` 次。
- 第三次请求不包含已经被 `read` 替代的搜索结果。
- 三次中位总耗时不高于 `3 分钟`，单次不高于 `5 分钟`，相对同环境旧基线至少提速 `2x`。

#### C. 短期追问写入

先让模型回答，再说“把刚才回答写入 `wiki/验收.md`”。

- 能准确取得上一轮回答。
- 写入这一轮最多 `1` 次模型请求。
- 写入成功后运行时直接结束。
- 新建对话后不能再引用该私有回答。

#### D. 能力激活冒烟

- 各执行一次用户明确点名的 Skill、MCP、Terminal、媒体面板和 3D 编辑器激活。
- 当前请求只出现被点名能力及其必要依赖。
- 原审批、平台差异、创作历史和编辑器交互保持可用。
- 这些专项能力不要求满足普通 Wiki/文件任务的三请求上限。

### 11.3 指标

每个任务记录但不记录正文或工具参数：

- 命中的本地路由名称。
- 实际发送的工具名集合。
- 模型请求次数与每次耗时。
- HTTP 重试次数。
- 工具轮数、并发段数与工具耗时。
- 每次请求估算 token 和滚动工作集大小。
- 总耗时与终止原因：模型回答、写入验证成功、用户取消、请求上限或错误。
