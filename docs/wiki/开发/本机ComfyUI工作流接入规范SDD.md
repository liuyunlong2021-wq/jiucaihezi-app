# 本机 ComfyUI 工作流接入规范 SDD

> 状态：已确认，作为后续本机 ComfyUI 工作流接入的最小合同。
> 范围：Desktop 本机执行；Web、Mobile 不暴露本机 ComfyUI。

## 1. 用户体验

用户在创作面板中选择一个已注册的本机 ComfyUI 工作流，填写提示词和该工作流声明的参数，在画布框选参考图后提交。App 自动把选中的媒体上传到本机 ComfyUI、填入工作流、提交 `/prompt`、等待 `/history` 完成，并把结果保存回当前项目。

用户不需要复制粘贴提示词，也不需要再打开 ComfyUI 手动选图。

## 2. 工作流来源与安全边界

1. 工作流必须先在本机 ComfyUI 手工运行成功，再导出 API 格式 JSON。
2. App 只注册审核过的工作流，不接受界面直接执行任意 JSON。
3. 接入定义必须明确生成节点、提示词节点、参考图节点、可编辑参数和结果节点。
4. 未声明的节点和字段原样保留，不由 App 猜测、重排或删除。

## 3. 参数映射

每个工作流由一份注册定义描述映射：

| App 参数 | 工作流字段 | 规则 |
| --- | --- | --- |
| 提示词 | 指定文本节点的 `prompt` | 每次提交覆盖 |
| 比例、时长、清晰度等 | 生成节点对应字段 | 只暴露工作流真实支持的选项 |
| 参考图 1 至 N | 指定 `LoadImage` 节点的 `image` | 先上传，再写入 ComfyUI 返回的文件名 |
| API Key | 生成节点的 `api_key` | 提交时临时注入，不写入工作流文件 |

以 `grok30s-api.json` 为例，生成节点 `7` 支持 `image1` 至 `image7`，对应的 `LoadImage` 节点为 `22、10、13、9、11、12、23`。这 7 个槽位是该工作流的能力，不代表所有 ComfyUI 工作流都支持 7 张图。

## 4. 参考图规则

- 参考图来自画布框选结果，不根据文件名猜测，也不让模型自动猜测。
- 默认顺序为从上到下、同一行从左到右。
- 面板显示编号缩略图，用户可以在提交前调整顺序。
- 选图数量超过工作流声明的 N 时拒绝提交；少于必填数量时给出明确提示。
- 每张图先通过 ComfyUI 标准上传接口写入本机，再把返回文件名填入对应 `LoadImage` 节点。

## 5. API Key

设置入口统一显示为 `API Key`，放在“本机 ComfyUI”设置中，不写死 Grok 名称。

- Key 只保存在用户本机的安全存储中。
- 提交工作流时按该工作流声明的服务商取 Key，并临时写入请求内存。
- 不把 Key 写入项目、Wiki、任务快照、导出的工作流 JSON 或云端日志。
- 同一服务商的多个工作流可以复用同一个 Key；换服务商必须单独配置。
- Key 为空时，在提交前阻止请求并提示配置位置。

## 6. 后续接入流程

1. 用户在 ComfyUI 安装并配置目标节点，填好自己的上游 Key，手工生成成功。
2. 导出 API JSON，确认 `/object_info` 中的节点输入真实存在。
3. 在注册定义中登记节点 ID、字段映射、参考图数量、结果节点和 Desktop 限制。
4. 增加映射与缺参校验测试，再做一次真实本机生成验收。

任何新工作流都不能直接复用 Z-Image 或 Grok 的节点 ID、参数默认值和参考图假设。
