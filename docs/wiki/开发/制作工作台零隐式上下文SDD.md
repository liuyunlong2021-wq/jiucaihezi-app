# 制作工作台零隐式上下文 SDD

> 日期：2026-07-22
> 状态：已实施，待人工验收
> 依据：`AGENTS.md`、[[开发/创作面板模式化架构SDD]]、[[开发/电商工作台绝对独立SDD]]、[[开发/韭菜盒子公共创作能力释放SDD]]
> 范围：制作工作台；不修改文、武、道、OpenCode 运行时或 Chat 创模式
> 公共媒体前提：[[开发/韭菜盒子公共创作能力释放SDD]] 的媒体合同已实施；本工作台只调用它

## 1. 一句话决断

制作工作台保留原“文件树 + 制作入口 + 创作面板”的 UI，但它不属于漫剧、电视剧、广告或任何题材。六个入口分别对应既有后端 Skill；每一次运行都是**零隐式上下文的显式产物运行**，不是同一个 Agent session 的折叠视图。

“零隐式上下文”不等于“零项目资料”。下游步骤可以使用用户在当前界面明确选中的资料，或用户明确建立的“项目 Wiki 绑定”所映射的资料；两者都必须在当前运行卡可见、可移除、可追溯。不能从 Chat、session、未关联 Wiki、热记忆、最近任务或工具循环自动补全。

```text
用户本次信息 + 用户选择的资料（可为空）+ 用户选择模型 + 当前步骤受限规则
  -> 一次 Direct 模型请求
  -> 本步骤结果卡
  -> 对应 Skill 的 Wiki 产物

需要出图或出视频时：
用户确认的提示词 + 用户选择的素材 + 媒体模型
  -> 公共 MediaPlan
  -> CreationPanel -> mediaTaskStore -> 项目 / 画布
```

模型推理、媒体计划和媒体提交是三件事。模型不调用工具；用户确认后，应用才通过既有公共媒体合同提交付费媒体任务。

## 2. 根因

[[开发/创作面板模式化架构SDD]] 的 UI 方向正确：Rail 选择模式、FileTree 是资源入口、中央显示步骤、右侧画布展示媒体。但它把漫剧操作台定义为“同一个 Agent session + 一层折叠皮”，步骤按钮只把 prompt 填入 Chat。

这使每次动作携带了不属于本步骤的内容：Chat 历史、创模式 session、热记忆、已连接工具、旧任务和消息持久化。旧 Skill 还默认读写 Wiki、搜索网页或依赖跨轮对话，导致输入、输出和实际依赖无法被用户准确看见。

电商工作台已经证明，问题不是少一个 Agent，而是把受限工作台调用错误实现成了 Chat 消息。制作工作台需要的是可见的用户信息、可选资料和 Skill 产物，不是不可见的对话记忆。

## 3. UI 决策

保留原 SDD 的四列空间结构：

```text
Rail 模式 | FileTree | 制作工作台 | CreationPanel / 编辑器
```

1. Rail 的“制作”打开 `ProductionWorkbench`，不是把操作台嵌入 `ChatPanel`。
2. Chat 继续作为独立 Rail 模式存在；制作工作台运行不读写 Chat 消息、session 或输入框。
3. FileTree 用于用户主动选择 Wiki、文件夹、文档或项目素材；不选择任何资料也能运行。
4. CreationPanel 继续是图片、视频任务和画布预览的唯一公共入口；工作台不复制媒体提交、轮询或落盘实现。
5. 六个入口是平权入口，不锁定、不要求按序完成。每步卡片只显示自身运行历史和可选的已有 Wiki 资料。

### 3.1 工作台主视图

```text
Rail        FileTree               制作工作台                     CreationPanel
----        --------               ----------                     -------------
对话        项目 / Wiki            [项目：未命名制作]             [画布]
制作        └ 剧本/                [资料：可选] [历史]            当前媒体任务
电商          └ 第一集/            风格 角色 场景 道具 分镜图 分镜视频  分镜 01：生成中
...           └ 角色/              ④ 分镜图 ⑤ 分镜视频           分镜 02：已完成
              └ 场景/                                               选中素材预览
              └ 道具/              当前步骤
                                    用户信息：[________________]
                                    资料：[第一集 1-12 场] [角色 3]（可选）
                                    模型：[GLM-5]
                                    [运行]  [运行记录]
```

中列没有 Chat 输出、消息气泡、输入框或“继续对话”。用户的文字补充是当前步骤表单字段；每一次点击“运行”都只创建当前步骤的一张运行卡。

### 3.2 冷启动：一句话也能开始

```text
制作工作台
----------
用户信息：[我想做一部雨夜武侠故事]
资料（可选）：[添加资料]
  -> 上传文档或参考素材 / 选择项目资料 / 关联项目 Wiki

[开始风格定调] [直接创建人物] [直接创建场景] [直接创建道具] [直接做分镜]

第一次运行：自动新建“未命名制作项目”和空 Wiki
风格  角色  场景  道具  分镜图  分镜视频
均可直接开始；结果按 Skill 写入 Wiki
```

用户信息可以是一句话、手写片段、表单字段、上传文件或 FileTree 选中的资料。它至少有一项非空才允许运行。主界面只显示一个“添加资料”入口；入口内可上传新文件、按 Wiki/文件夹范围勾选已有项目资料，或关联一个项目 Wiki 根目录。普通上传是本次运行附件；项目 Wiki 绑定是用户显式确认的项目级资料映射。无论哪种方式，都不读取全项目、`wiki/hot.md` 或最近会话。

### 3.3 运行与确认

```text
┌─ ① 风格定调 ───────────────────────────────────────────────┐
│ 用户信息：[我想做一部雨夜武侠故事]                            │
│ 已关联 Wiki：[长安] [管理]                                    │
│ 本次资料：[第一集 1-12 场] [风格设定] [管理]                  │
│ 补充：媒介 [自由选择 v]  画幅 [9:16 v]  风格偏好 [_______]   │
│ 模型 [GLM-5 v]                                             │
│                                             [ 运行风格定调 ]  │
├─ 运行 #r_01 · 待确认 ──────────────────────────────────────┤
│ 3 个风格候选：                                                │
│ [A 新海诚...] [B ...] [C ...]                                │
│ [确认 A 为项目风格] [编辑后重跑] [定位记录]                  │
└──────────────────────────────────────────────────────────────┘
```

确认操作把当前结果写为上游产物；它不是向 Chat 发送“A”。“编辑后重跑”创建新 `runId`，原运行卡和后续已引用版本保持可追溯。

### 3.4 资产、分镜和视频

角色、场景、道具和镜头都使用同一种稳定尺寸运行卡。资产步骤的一次运行可以返回多张对象卡；每张卡只有对象名称、一条可编辑提示词和一个“生成角色图 / 生成场景图 / 生成道具图”按钮。点击按钮即提交公共媒体任务，不在资产卡内展开第二层参数或确认编辑器。每个对象单独存储、单独重试。第⑤步可直接用用户信息生成导演工作本，也可选择已有剧本分场和资产；第⑥步仅显示用户选中的分镜图和视频参数，提交后右侧画布显示公共媒体任务状态。

```text
④ 分镜图： [导演工作本 已确认] [选择场次 1-3 v] [选择资产 8 项 v]
          [运行分镜图提示词] -> [镜头 01] [镜头 02] [镜头 03]

⑤ 分镜视频： [镜头 01 分镜图] [视频提示词] [Veo v] [9:16 v]
            [提交镜头 01 视频] -> 右侧 CreationPanel 任务卡
```

步骤条只显示各步骤是否已有产物，不表达前置锁定。每一步只要有用户信息、用户主动选中的资料或当前项目已确认的 Wiki 绑定资料就可运行；它不因某个 Chat session 存在、某条旧消息成功或最近任务完成而改变。

## 4. 项目、Wiki 与可选资料

项目和 Wiki 是结果的归档地，也是用户可选的增强输入，不是启动条件。用户没有项目时，第一次点击任一“运行”按钮自动创建项目和空 Wiki；用户没有 Wiki、没有剧本、只有一句话时同样可以运行。

| 用户提供 | 工作台行为 |
| --- | --- |
| 一句话或手写片段 | 直接作为当前 Skill 的用户信息；自动创建项目和空 Wiki（如尚未存在） |
| 文档或大纲 | 保存或关联为项目资源，并由用户选择是否作为本次输入 |
| 文件夹 | 展示其中可用项目资源，用户选择本次需要的条目 |
| Wiki 文件夹（仅本次） | 展示该根目录内的剧本分场、角色、场景、道具、风格资料，用户选择本次需要的条目 |
| 关联项目 Wiki | 用户选择一个 Wiki 根目录；系统识别中文实体目录与正文/分场目录，按用户选定单场的双链解析实际角色、场景、道具，直到用户改绑或解除 |

自动创建的项目默认命名为“未命名制作项目”；用户可在随后改名。空 Wiki 仅创建目录骨架，不预填题材、人物、风格或任何模型生成内容。

Wiki 文件夹的资料扫描是用户点击“选择 Wiki 文件夹”或“关联项目 Wiki”后的可见动作。它识别中文目录 `作品`、`角色`、`场景`、`道具`、`世界` 或 `世界观`；角色、场景、道具既支持平铺文件（如 `角色/林不凡.md`），也支持实体目录（如 `角色/林不凡/01-基础信息/基础档案.md`）。资料变化时，用户刷新清单或刷新绑定后才可使用新版本；不读取根目录外的 Wiki、`wiki/hot.md`、项目文件或最近会话。

### 4.1 显式项目 Wiki 绑定与场次双链解析

“关联项目 Wiki”不是把整个 Wiki 隐藏注入每个模型请求。它保存用户确认的根目录和结构索引；用户再选择一集或一场正文/场纲作为本次锚点。系统只解析该锚点正文中的 `[[双链]]`，再解析被双链指向的角色、场景、道具实体。锚点、已解析实体和实际读取的实体资料全部显示为“已关联 Wiki 资料”，用户可移除单条资料、重新选择场次、改绑或解除。

```text
用户选择：作品/正文/第 8 集/正文.md
  -> 解析该页明确双链
  -> 角色/林不凡、角色/温宁、场景/客栈大堂、道具/红伞
  -> 当前入口只接收这一场和这四个实体的资料
```

| 入口 | 当前 Wiki 锚点与解析结果 |
| --- | --- |
| 风格 | 用户选择的世界观、总纲、集纲或正文；不自动读取全库 |
| 角色 | 用户选择的单场/单集双链出的角色；一个角色实体对应一张提示词卡 |
| 场景 | 用户选择的单场/单集双链出的场景；场景卡只生成空镜资产 |
| 道具 | 用户选择的单场/单集双链出的道具 |
| 分镜图 | 用户选择的单场/单集正文，加该页双链出的角色、场景、道具实体 |
| 分镜视频 | 用户选定的分镜图和该镜头的已确认视频提示词 |

实体资料的读取也有明确边界：平铺实体读取该 `.md`；实体目录只读取当前入口所需的已确认资料页，例如角色读取基础档案、塑造、特点与当前状态，场景读取简介、外观、布局、细节与出场状态，道具读取简介、材质、外观、功能与归属流转。不能因为关联了角色目录就递归发送整个角色库。

若正文没有双链、双链目标不存在或目标不属于角色/场景/道具实体，系统只显示未解析状态并要求用户手动选择资料；不得用正文里的自然语言名字猜测实体。资源哈希变化时，该条资料标记为待刷新，在用户点击“刷新绑定”前不进入模型请求。运行记录冻结实际发送的资源 ID、链接目标和内容哈希，因此后续 Wiki 变化不会改写旧运行。

```ts
interface ProductionSourceRef {
  resourceId: string
  kind: 'script-scene' | 'outline' | 'character' | 'scene' | 'prop' | 'style' | 'storyboard-image' | 'reference'
  name: string
  mimeType: string
  contentHash: string
}

interface ProductionWikiBinding {
  rootPath: string
  schema: '中文实体双链' | '平铺实体文件'
  sceneAnchor?: ProductionSourceRef
  resolvedEntities: ProductionSourceRef[]
  createdAt: number
  refreshedAt: number
}

interface ProductionInput {
  userText: string
  sourceRefs: ProductionSourceRef[]
  attachments: WorkbenchAttachment[]
}
```

`ProductionSourceRef.kind` 是内部程序类别，不是目录名，也不在用户 UI 显示。用户始终看到中文 Wiki 路径和实体名，例如 `角色/林不凡/`、`场景/客栈大堂/`、`道具/红伞/`。

每次运行必须至少有非空 `userText`、`sourceRefs` 或 `attachments` 之一。`sourceRefs` 只可来自用户当次选择，或当前项目已确认 `ProductionWikiBinding` 的场次锚点及其双链解析实体；两类来源均在运行前显示。模型不递归读取用户选择的文件夹或 Wiki 根目录。

## 5. 单次运行与专属存储合同

```ts
interface ProductionWorkbenchRequest {
  step: 'style' | 'characters' | 'scenes' | 'props' | 'storyboard-images' | 'storyboard-video'
  modelId: string
  profile: { id: string; content: string; revision: string }
  input: ProductionInput
  artifactIds: string[]
  output: { kind: 'decision' | 'prompt-set' | 'media-plan'; heading: string }
}

interface ProductionArtifactRecord {
  runId: string
  step: ProductionWorkbenchRequest['step']
  input: ProductionInput
  inputArtifactIds: string[]
  modelId: string
  profile: { id: string; revision: string }
  status: 'running' | 'succeeded' | 'failed' | 'confirmed'
  result: { content: string; wikiPaths: string[]; mediaTaskIds: string[] }
  createdAt: string
}
```

每个 `ProductionArtifactRecord` 写入当前项目 Wiki：

```text
wiki/制作/运行/<run-id>.json
```

文本结果按 Profile 对应的 Wiki 类别写入；媒体文件本身仍由公共 `jc-media` 合同落盘，Wiki 只保存任务和媒体引用。工作台从 `wiki/制作/运行/` 扫描历史，不新建 Pinia Store、Chat 历史、后台队列或第二套轮询器。

约束：

1. 每次请求只发送当前 `userText`、当次选择或已确认 Wiki 绑定的场次锚点与双链解析 `sourceRefs`、附件、`artifactIds`、`modelId`、Profile 内容和输出合同；模型请求不能携带文件夹、Wiki 清单、Chat 或项目的未选内容。
2. 不追加 Chat 历史、创模式 session、`wiki/hot.md`、最近任务、MCP、工具定义、未关联项目资源、未被锚点双链指向的实体或绑定根目录外资源。
3. `artifactIds` 和 `sourceRefs` 必须属于当前项目且资源哈希有效；无效、跨项目或不存在的引用必须拒绝。
4. 重试只创建新 `runId`，不覆盖旧记录；“复用”只把用户选定产物填回当前表单，不自动发起请求。
5. 每张运行卡显示用户信息、当次选择资料、场次锚点、双链解析出的已关联 Wiki 实体、输入产物、模型、时间、状态和 Wiki 结果入口，不能伪装成消息历史；步骤受限规则只记录在运行记录中，不在用户 UI 展示。

## 6. 六个平权制作入口

六入口的终点是**分镜视频**；本 SDD 明确不做成片拼接、BGM、配音、字幕、剪辑时间线或 `video-composer`。入口是后端 Skill 的能力入口，不是题材分类，也不是强制流水线：漫剧、电视剧、广告、短故事或其他制作都使用同一组入口。

| 步骤 | 最小可运行输入 | 内部规则来源 | 显示与 Wiki 存储 |
| --- | --- | --- | --- |
| ① 风格 | 一句话、手写片段或任选资料 | `jc-film-style` | 风格候选卡 -> `wiki/世界观/style-design.md` |
| ② 角色 | 一句话角色描述、手写信息或任选资料 | `jc-character-prompt` | 角色设定卡/资产图 -> `wiki/角色/<角色名>.md`、`wiki/角色/<角色名>.design.json` |
| ③ 场景 | 一句话场景描述、手写信息或任选资料 | `jc-scene-prompt` | 场景卡和资产图 -> `wiki/场景/<场景名>.md`、`wiki/场景/<场景名>.design.json` |
| ④ 道具 | 一句话道具描述、手写信息或任选资料 | `jc-prop-prompt` | 道具卡和资产图 -> `wiki/道具/<道具名>.md`、`wiki/道具/<道具名>.design.json` |
| ⑤ 分镜图 | 一句话故事片段、手写分场或任选资料 | `jc-script-storyboard` 后接 `jc-storyboard-image` | 导演工作本/分镜图卡 -> `wiki/分镜/<场次>.md`、`wiki/分镜/<场次>.image.json` |
| ⑥ 分镜视频 | 一句话镜头描述、分镜图或任选资料 | 分镜视频 Profile | 视频提示词/任务卡 -> `wiki/分镜/视频/<镜头>.json` |

每步成功后的文本结果立即显示并写入对应 Wiki 路径，状态为“已生成”；用户可编辑、重跑或从 Wiki 再选入下一次运行。角色、场景、道具结果必须是对象卡集合，每张卡只含对象名称、一条可编辑提示词和生成按钮。若卡来自 Wiki 实体，卡必须冻结该实体路径和资源 ID；一个角色实体只对应一张角色提示词卡。按钮直接提交公共媒体任务，不展开额外参数卡；提交后的媒体任务引用和结果路径写回同一实体对应的 Wiki 产物及 `wiki/制作/运行/<run-id>.json`。

### 6.1 风格定调

运行卡展示模型给出的结构化风格候选，并立即写入 `wiki/世界观/style-design.md`。用户可选择、编辑或重跑；任何步骤都可以选择该结果作为输入，但没有它也能启动。选择不是发送“我选 A”的 Chat 消息。

### 6.2 角色、场景和道具资产图

角色、场景、道具各自使用独立 Profile。一次运行可以输出多张同类对象卡；每张卡仅含对象名称和一条可编辑提示词。一项失败或重做不覆盖其他资产。模型先输出这些提示词并写入对应 Wiki；只有用户点击该卡的生成图按钮，才把该提示词、该对象的明确参考图和媒体模型组成 `MediaPlan`。

场景资产必须是空镜，不自动包含角色。道具资产只引用用户选中的道具和场景/角色引用，或当前场次锚点双链解析出的同类实体；不从最近资产或聊天内容补素材。

### 6.3 分镜图

步骤④不是隐藏链式调用：

1. 用户提供故事片段、分场或任意已选资料，运行导演工作本；
2. 工作本立即显示并写入 `wiki/分镜/`；用户可选定其中任意场次/镜头运行分镜图提示词；
3. 用户确认提示词后，应用通过公共 `MediaPlan` 生成分镜图，并写回对应分镜 Wiki 产物。

每一次都是单独的运行卡和明确输入。分镜图可引用用户选择的角色、场景、道具资产，或当前场次锚点双链解析出的同类实体；不能按“项目最近资产”或正文自然语言名字猜测补齐。

### 6.4 分镜视频

步骤⑤逐镜提交：每次提交只含用户选择的分镜图、其已确认的视频提示词、视频模型和参数。它直接形成公共 `MediaPlan` 并由 `CreationPanel -> mediaTaskStore` 执行；不再调用 LLM 拼接成片，也不启用 `video-composer`。

批量提交只是一组独立逐镜媒体计划。单镜失败、重试和完成状态必须保留在各自的运行卡和记录中，不影响其他镜头。

## 7. Skill 与 Profile 边界

现有 `jc-film-style`、`jc-character-prompt`、`jc-scene-prompt`、`jc-prop-prompt`、`jc-script-storyboard` 和 `jc-storyboard-image` 是领域规则来源，但不能原样作为工作台运行内容：它们目前含 Wiki 读写、Pinterest/浏览器、工具执行或跨轮对话记忆。

每个工作台 Profile 必须：

1. 标注对应 `sourceSkillId` 和版本；
2. 只保留本步骤所需的领域规则、用户已选输入和结构化输出格式；
3. 不含 URL、Shell、文件读写、MCP、浏览器、工具调用或“回顾上轮对话”指令；
4. 将结果交由工作台按本节定义的对应 Wiki 路径写入，并在 `ProductionArtifactRecord` 中记录该路径；
5. 把需要用户确认的候选直接输出为工作台可选项，而不是 A/B/C/D Chat 消息。

Profile 是受限声明，不允许用户输入 Vue、网络调用或可执行代码。一个模型请求只加载一个当前步骤的 Profile；步骤④的导演工作本与分镜图提示词是两个显式请求，不把两个 Profile 拼成隐式链。

## 8. UI 状态与模型选择

1. 工作台顶部显示当前项目、Chat 同款模型选择器和一个可选资料入口；没有项目时首次运行自动创建项目与空 Wiki。“添加资料”内可上传、当次选择项目资料或关联项目 Wiki。关联后用户先选择单集/单场，工作台显示该场双链解析出的角色、场景、道具实体；已选择资料与已关联实体分组显示为可移除输入标签。资料列表打开时自动刷新，项目 Wiki 绑定仅在用户打开管理项时提供“刷新绑定”，不显示常驻刷新按钮。
2. 六入口条显示 `未运行`、`运行中`、`已生成`、`媒体生成中`、`失败`，不显示前置锁定或不可用状态。
3. 每一步都有模型选择器。全局模型设置仅作为初始默认值；运行卡和 `record.json` 必须冻结实际 `modelId`。
4. 六入口均可在无上游产物时直接运行；已有 Wiki 资料和工作台产物只是可选输入，不强迫按 UI 顺序逐项做完。用户显式关联项目 Wiki 并选择单集/单场后，各入口自动显示该场双链解析出的对应实体；这是一项可见的项目配置，不是隐藏上下文。
5. 右侧画布只预览由 `mediaTaskStore` 管理的图片和视频；中央工作台只展示结构化文本、对象提示词卡、状态和操作；不显示 Profile id 或人工成果文件名字段。
6. 页面离开时只按既有取消语义取消页面内未提交的 Direct 请求；已提交媒体任务仍由公共媒体链处理，不建立制作工作台后台任务队列。

## 9. 实施边界

需要做：

1. 基于电商的 `SingleTurnWorkbenchRequest` 提供六个制作 Profile 的无上下文 Direct 运行入口。
2. 用独立 `ProductionWorkbench` 替换旧 SDD 中“嵌入 ChatPanel 输入框上方”的操作台方案。
3. 复用 FileTree 的确定资源选择、Direct 原生附件合同、CreationPanel、`preparePublicMediaPlan()` 和 `mediaTaskStore`。
4. 实现首次运行自动建项目和空 Wiki，并为六入口建立受限 Profile、对应 Wiki 写入和 `wiki/制作/运行/` 历史读取能力。
5. 实现“关联项目 Wiki”的中文目录扫描、单集/单场选择、双链目标解析、实体资料收敛、可见资料标签、刷新/改绑/解除和请求前哈希校验；绑定仅注入场次锚点及其对应实体。

明确不做：

- 不把制作步骤接回 `ChatPanel.handleSend()`，不新建或切换 Chat session；
- 不让工作台运行时读取用户未选择或未关联的 Wiki、热记忆、Raw、消息历史或 AI 协作记录；当次选择与已确认项目 Wiki 绑定是仅有的 Wiki 输入来源，结果只写入对应 Skill 的 Wiki 路径；
- 不让 Profile 执行 MCP、Shell、浏览器、网络、项目文件读写或任意工具；
- 不修改 OpenCode SDK、sidecar、Provider、variant、文武道链路或普通 Chat 创模式；
- 不新建媒体 API、任务队列、轮询器、第二套媒体存储、成片组装、配音、BGM、字幕或剪辑能力；
- 不支持由最近任务、Chat、热记忆、正文自然语言名字、双链未指向实体或绑定范围外资料自动补齐步骤输入，也不按题材切换另一套运行时。

## 10. 测试与验收

每项行为先写失败测试，再做最小实现。自动测试至少证明：

1. 每次制作 Direct 请求只含当前用户信息、当前选择的文件/Wiki 条目、当前项目 Wiki 绑定的单集/单场锚点及其双链解析条目、当前附件、当前 `artifactIds`、模型、Profile 和输出合同；不含 Chat、session、未选择或未关联 Wiki、热记忆、MCP 或工具定义。
2. 仅输入一句话时，任一步均可运行，并自动创建项目和空 Wiki；没有用户信息、资料和附件时请求被拒绝。
3. 文档、大纲、文件夹和 Wiki 文件夹均可作为可选输入；用户关联项目 Wiki 并选择单集/单场后，六入口只显示并发送该页双链出的对应实体资料。Wiki 清单、绑定根目录、场次锚点和每条解析实体必须可见；未选择、未关联、双链未指向、哈希已变化或根目录外资源不得进入请求。
4. 每个成功文本结果都显示在当前运行卡，并按 Profile 写入对应 Wiki 路径及 `wiki/制作/运行/<run-id>.json`；角色、场景、道具结果必须拆为独立对象提示词卡，单卡生成媒体不得使用整段运行结果。
5. 多个角色、场景、道具或镜头的运行卡、Wiki 记录和重试互不覆盖；一项失败不影响其他项。
6. 分镜图和分镜视频只经 `preparePublicMediaPlan()`、`CreationPanel` 与 `mediaTaskStore.submitTask()` 提交；视频步骤没有成片拼接调用。
7. 运行历史可从 `wiki/制作/运行/` 恢复和定位，且扫描历史不会把记录自动注入下一次模型请求；已关联 Wiki 的场次锚点、双链目标和实体资料必须冻结在运行记录中，改绑或刷新不改写旧记录。
8. 普通 Chat 创模式、电商工作台、文武道以及公共媒体链行为不变。

门禁：相关 focused tests、`pnpm exec vue-tsc -b`、`pnpm run build:desktop`、`git diff --check`。人工验收覆盖 Desktop/Web 的一句话冷启动、自动建项目/Wiki、六入口任意直接启动、可选 Wiki 输入、对应 Wiki 写入、资产/分镜媒体任务、失败重试、历史定位和 Chat 隔离。

## 11. 完成标准

1. 用户只写一句话也可从六入口中的任一步启动；没有项目时系统自动创建项目和空 Wiki，并把结果归档到对应 Skill 的 Wiki 路径。
2. 用户也可主动选择文档、大纲、文件夹或 Wiki 文件夹；或者显式关联一个项目 Wiki 并选择单集/单场，使各入口使用可见的双链实体资料。第二大脑资料不会在未选择、未关联、双链未指向或哈希变化后自动作为模型上下文。
3. 每次模型调用的输入、模型、Wiki 产物和媒体任务都在当前工作台卡片与项目记录中可追溯；步骤受限规则仅保存在项目运行记录。
4. 制作工作台没有隐式 Chat、session、未选择或未关联 Wiki、热记忆、MCP、工具或最近任务上下文；已有 Wiki 只通过用户当前选择的条目，或已确认项目 Wiki 的单场锚点与其双链实体进入请求。
5. 用户明确选中的 Wiki 产物和显式关联项目 Wiki 的场次双链实体均可作为下游输入；Wiki 是可见第二大脑，不是隐藏记忆。
6. 图片与视频仍仅通过公共媒体合同提交和回流；产品不具备成片拼接能力。
7. 旧的四列 UI 价值保留，普通 Chat 与现有产品能力不退化。

## 12. 回退

制作工作台 Direct 入口失败时，只回退该入口；独立 Chat 模式、公共媒体合同和旧 Skill 文件继续存在。不得通过恢复“步骤预填 Chat prompt”来回退。
