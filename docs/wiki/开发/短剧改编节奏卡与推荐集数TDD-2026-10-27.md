# 短剧改编：节奏卡与推荐集数TDD

> 2026-10-27。状态：**用户已确认，源码已实施，自动化回归通过；真实效果未验**（见第6节）。在 [[开发/短剧改编删减式改编与漫剧交付TDD-2026-10-27]] 的基础上，把“推荐集数”从模型逐个事件临时猜测，改为项目级节奏卡加程序计算。

## 0. 用户口径

- 推荐集数要借鉴漫剧的项目风格（film style）：先定这部戏是什么节奏（张艺谋式、昆汀式、海贼王式动画……），再拆集。
- **风格后置**：模型至少读完前20章，才推荐项目风格；用户定好风格后，才出分集推荐。
- 推荐要更智能、更简单。

## 1. 问题

现在每个事件都让模型同时猜两件事：内容有多少（几次局势变化）和节奏多快（一次变化占多长）。前者读原文就能数清；后者是全剧统一的风格决定，却被逐个事件重复猜测，导致集数时松时紧、前后不一致。

## 2. 方案：模型数节拍，节奏只定一次，程序算集数

### 2.1 节拍

节拍是局势改变一次：新危险出现、新信息揭开、谁占上风、做出选择、爽点兑现。模型读原文时，把每个事件的节拍和行号列进事件文档；需要判断的只有轻重：

- 重拍（一场大战、一次进化展示、一个情感高潮）按2个算；
- 普通节拍按1个算；
- 轻拍（过渡性变化）按0.5个算。

每段规划保存进度时，同时登记每个事件的节拍数`event_beats`（按轻重折算后的数），程序按事件名累积，未完事件续写时更新。

### 2.2 节奏卡（读完前20章后推荐，用户确认）

第一批的第一段（前20章）读完后，模型根据故事梗概、事件和人物，按项目风格Skill推荐2–3个方向，每个方向包括：

- 参照：导演或具体作品，以及借它的哪种手法（如“海贼王：一场大战分多集铺开招式和反应”）；
- 分集节奏卡：单集目标时长范围；**每集节拍数**（标准值，以及紧凑、舒展两档）；哪类戏要展开（打戏、进化、情感）；对白的分量。

暂停等用户选择或修改。用户定好后，模型保存`项目风格/影片比例与风格.md`（含分集节奏卡），并在进度里登记`rhythm`：`{"reference":"…","beats_per_episode":3,"compact":4,"relaxed":2}`。之后各批沿用，不再暂停定风格。漫剧制作开工时本来就读这份项目风格，风格全剧只定一次。

### 2.3 程序计算推荐集数

一批读完后，程序按“节拍数 ÷ 每集节拍数”（向上取整，至少1集）为每个事件算出紧凑、标准、舒展三个集数，发给模型；模型据此写建议分集方案，补每集的开头、钩子和理由，不再自己报集数。理由里说明哪些重拍撑起了集数。

### 2.4 审阅时一键调松紧

审阅卡显示每个事件的三档集数，顶部有整体开关：紧凑、标准、舒展。切换后当场按已有节拍重算，不调用模型。用户可以再单独改个别事件（在对话里说），最后点确认；程序把最终集数写进`event_episodes`的指令发给模型保存。

### 2.5 用用户的决定自动校准

程序记录每个事件“标准推荐几集、用户定了几集”。用户确认后，按已确认事件的总节拍 ÷ 总集数，更新本项目实际的每集节拍数，下一批推荐按新值计算（同步更新进度中的`rhythm`，并提示“已按你的选择把每集节拍数从3调整为2.5”）。

## 3. 流程变化

第一批：

1. 规划第1段（前20章）：资料、事件文档（含节拍表）、`event_beats`。
2. **推荐项目风格**：2–3个方向及节奏卡，暂停等用户选择。
3. 用户确认后保存项目风格与`rhythm`。
4. 规划其余各段：资料、事件文档、`event_beats`。
5. 程序算三档集数，模型写建议分集方案（开头、钩子、理由）。
6. 审阅卡：整体松紧开关、单独调整；用户确认后保存`event_episodes`。
7. 切集删减、收尾（不变）。

之后各批跳过第2、3步；第5步使用校准后的每集节拍数。

## 4. 程序改动

- 短剧白名单加入`jc-film-style`（共10个）；`film_style`开放短剧路线。
- 进度：scheme阶段新增`event_beats`（`[{event, beats}]`，事件文档须存在，beats为正数，按事件名合并保留）与`rhythm`（`beats_per_episode`、`compact`、`relaxed`为正数），保留到完成。
- 运行器：第一批第1段后插入“推荐风格 → 等用户 → 保存风格”；一批读完后计算三档集数并发给模型写建议；审阅确认时带上用户选的档位；确认后按决定校准`rhythm`。
- 审阅卡：显示三档集数表与整体开关。
- Skill：`jc-duanju-fenji`写节拍表与轻重规则、按程序给的集数写建议；`jc-duanju-pipeline`写新步骤与指令；`jc-film-style`在短剧推荐时输出分集节奏卡（漫剧原有用法不变）。

## 5. 测试（先红后绿）

1. 进度：`event_beats`中事件文档不存在或beats非正数时拒绝；同名事件续写时更新；`rhythm`字段非正数时拒绝；二者保留到完成。
2. 运行器：第一批顺序为 规划第1段 → 推荐风格 → 等用户 → 保存风格 → 其余各段 → 建议分集 → 等用户决定 → 切集 → 收尾；第二批不再推荐风格。
3. 运行器：三档集数按节拍和节奏卡计算（向上取整、至少1集）；建议指令里带上每个事件的三档集数。
4. 运行器：用户选“紧凑”时写入event_episodes的指令使用紧凑档；用户决定后按总节拍 ÷ 总集数校准每集节拍数，下一批推荐使用新值。
5. 界面：审阅卡有整体松紧开关和三档集数表；切换不调用模型。
6. Skill合同：节拍轻重规则、风格推荐包含分集节奏卡、短剧白名单含项目风格Skill。
