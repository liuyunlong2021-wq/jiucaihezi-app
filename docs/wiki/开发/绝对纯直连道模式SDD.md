# 绝对纯直连道模式 SDD

> 日期：2026-07-23
> 状态：已实施，待 Desktop / Web 人工验收
> 范围：Desktop / Web 的道模式直连链路
> 原则：道模式只负责把用户本轮输入交给当前模型并返回模型结果
> 实现：`87c16924`；原生多媒体附件补充：`347d38f3`

## 1. 一句话目标

道模式是韭菜盒子的“绝对纯直连”模式：

```text
用户文字 / 原始附件
        -> 当前模型 + 当前 Provider/K
        -> 模型回复
```

道模式不调用工具、不读取项目、不查询 Wiki、不加载 Skill、不连接 MCP、不启动 OpenCode、不自动切换模型，也不把任务转交给创作面板。

## 2. 模式分工

### Desktop

```text
道：绝对纯直连模型
文：OpenCode Plan，负责分析与规划
武：OpenCode Build，负责文件、命令和完整执行
创：暂时保留的产品 Agent，负责媒体、Wiki、Skill 和产品工具
```

### Web

```text
道：绝对纯直连模型
创：项目文件、Wiki、Skill、媒体和产品工具
```

文武需要 OpenCode；Web 没有 OpenCode，因此继续保留 Web 创模式。电商工作台、制作工作台和创作面板属于公共产品工作台，不属于道模式能力。

本 SDD 不删除创模式，不迁移创模式工具，不重做工作台，也不把创模式改造成 OpenCode Agent。

## 3. 道模式合同

### 3.1 输入

- 使用用户当前选择的模型、Provider 和 K。
- 发送本轮用户文字和本轮原始附件。
- 支持当前 NewAPI 合同允许的图片、视频、音频、PDF 和其他文件。
- 不把附件替换成文件名、路径、摘要、抽帧结果或 Wiki 内容。
- 不携带项目目录、项目文件、`CLAUDE.md`、`AGENTS.md`、`wiki/hot.md` 或来源索引。

### 3.2 输出

- 只显示模型的文字、原生媒体结果和正常错误。
- 不显示工具调用卡片、审批条、Wiki 读取记录、Skill 加载记录或 OpenCode 时间线。
- 模型不支持当前输入时，直接显示当前 Provider/模型的真实错误；不换模型、不调用本地工具、不猜测补位方案。

### 3.3 发送约束

- 请求不包含 `tools`、MCP 工具、Skill 目录或工具相关系统提示。
- 不建立或恢复 OpenCode `ses_*` 会话。
- 不启动或连接 OpenCode sidecar。
- 不执行工具循环；每轮最多一次模型请求，流结束即结束。
- 不设置产品自创的固定输出长度、思考轮数或媒体处理流程。

## 4. 最小运行时

道模式可以复用现有 Direct Engine 的 HTTP、SSE、附件和错误处理，但必须使用“空工具、空项目上下文”的运行配置：

```text
Direct Engine
├── 当前模型 / Provider / K
├── 当前文字
├── 当前原始附件
├── 最小固定系统边界（可为空）
└── 模型回复
```

不得为道模式新增第二套模型客户端、媒体客户端、Skill 扫描器或会话数据库。已有创模式直连基础设施可以复用；工具执行、Wiki 运行时和媒体编排不进入道模式请求。

## 5. 会话边界

- 道、创、文、武共用一个可见 `conversationId` 和统一消息记录。
- 统一记录只保存用户文字、助手最终回复、原始附件引用、每轮模式/模型元数据和用户可见结果。
- 工具调用、Wiki 读取、Skill、MCP 和 OpenCode parts 属于运行过程；它们可以在统一 UI 中展示，但不能自动进入道模式上下文。
- 切换模式只改变下一轮的运行投影，不自动触发模型请求，也不把不同运行时的内部 session 硬合并。
- 道模式读取用户文字、助手最终回复和原始附件；创模式可以在本轮按需加入已加载能力结果；文武继续使用 OpenCode 官方 session 运行。
- 旧 `creative_*` 会话只作为历史数据处理；新道模式不建立新的专属会话数据库，也不扩张旧创模式历史结构。

## 6. UI 边界

- 道模式复用统一 ChatPanel 外壳、会话记录、模型选择器、附件上传器、消息气泡和错误提示。
- 道模式隐藏或不渲染工具审批、Skill 选择、Wiki 操作、终端状态、OpenCode 权限、Todo、Diff 和上下文工具面板。
- 道模式不因用户选择项目目录而自动携带项目内容；项目目录只对创模式、文模式和武模式生效。
- 道模式切换到创模式时保留可见文字和原始附件，但不携带旧工具过程；创模式从下一轮开始按需加载能力。
- 创模式切换到道模式时保留可见文字和原始附件，但过滤 Wiki、Skill、MCP、终端和项目扫描结果。
- 道模式不会把“生成图片/视频”改写成创作面板任务。当前模型能原生生成就由模型处理，不能原生生成就如实说明能力边界。

## 7. 与其他能力的关系

### 创模式

创模式是产品能力 Agent，不是道模式的增强版。它继续承载：

- 项目文件读取与写入
- 五个 Wiki Skill 和原生 `wiki` 工具
- Skill、MCP、受控终端
- 媒体编排、创作面板和媒体任务

创模式可以调用当前模型，也可以调用产品公共能力；但这些能力不能进入道模式。

### 文武模式

文、武继续代码级对齐 OpenCode。它们负责工具、权限、Skill、MCP、项目上下文和会话工作区。道模式不再注册 OpenCode `dao` Agent，也不修改 OpenCode 官方 Agent 循环。

### 工作台

电商工作台、制作工作台和创作面板是独立的产品工作台。它们可以使用公共模型调用、媒体任务和项目服务，但不依赖用户先进入道模式，也不把工作台步骤塞进道模式上下文。

## 8. 错误和取消

- 请求失败时保留用户文字和原始附件，允许用户重新发送。
- 取消只取消当前模型请求，不创建工具失败记录，不启动替代流程。
- HTTP、网络、超时、内容过滤和模型能力错误分别显示真实原因。
- 不把“模型没有能力”包装成“正在查询 Wiki”或“正在寻找替代工具”。

## 9. 验收标准

### 自动验收

1. 道模式请求不启动 OpenCode，不创建 `ses_*` 会话。
2. 道模式请求不包含 `tools`、Skill 目录、MCP 指令和项目文件内容。
3. 道模式发送文字、图片、视频、音频和 PDF 时，原始附件进入同一模型请求。
4. 道模式每轮最多产生一次模型请求，没有工具循环、工具事件或审批事件。
5. 道模式失败后附件和文字仍可重发。
6. 创模式、文模式和武模式现有工具、附件、会话和工作台行为不变。

### Desktop / Web 人工验收

| 场景 | 道模式预期 |
|---|---|
| 发送“你好” | 直接回复，不查 Wiki、不读文件、不显示工具状态 |
| 发送“分析这张图片” | 模型直接读取图片并回复，不读取项目目录 |
| 发送视频并要求分析 | 当前模型支持就直接分析；不支持就直接报真实错误 |
| 发送“查看这个项目文件夹” | 明确说明道模式不读取项目，提示切换创/武模式 |
| 发送“查 Wiki 里的角色设定” | 明确说明道模式不查 Wiki，提示切换创模式 |
| 发送“生成一张图片” | 只走模型原生能力；不自动进入创作面板或媒体任务 |
| 切换到创模式 | 创模式工具、Wiki、Skill 和媒体能力正常恢复 |
| 切换到文/武 | OpenCode 会话、权限、工具和附件合同不回归 |

## 10. 明确不做

- 不给道模式增加 Wiki 优先提示词。
- 不给道模式保留 `read`、`glob`、`grep`、`terminal`、`skill` 或 MCP 工具。
- 不给道模式加入自动换模型、Gemini 兜底、FFmpeg、OCR、Whisper 或媒体编排。
- 不把创模式、文模式、武模式合并成一套运行时。
- 不把 OpenCode Agent 改造成“半直连半工具”的特殊分支。
- 不为了统一 UI 重写文武 OpenCode 时间线或创模式工具摘要。

## 11. 对现有设计的替代关系

本 SDD 执行后，`docs/wiki/开发/道模式OpenCode第三主Agent SDD.md` 中关于“道模式使用 OpenCode `dao` Agent”的设计失效，改为历史设计记录。文武 OpenCode 对齐 SDD、创模式 SDD、媒体 SDD 和工作台 SDD 继续有效；只有与道模式边界冲突的部分以本 SDD 为准。

## 12. 实施顺序

1. 先写道模式纯直连失败测试：请求不能启动 OpenCode，不能携带工具和项目上下文。
2. 将当前 OpenCode `dao` 入口改为 Direct Engine 的空工具配置。
3. 把道模式接入统一对话记录和统一消息 UI，保留原始附件合同。
4. 验证道/创切换只改变运行投影，不丢可见文字和原始附件，不携带对方运行过程。
5. 收窄道模式 UI，只保留模型、附件、消息和错误。
6. 回归创模式、文模式、武模式、Web 项目工具和媒体工作台。
7. 完成 Desktop / Web 真实人工验收后，再决定是否隐藏 Desktop 创模式；本 SDD 不直接删除创模式。
