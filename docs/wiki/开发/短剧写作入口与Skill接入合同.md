# 短剧写作入口与 Skill 接入合同

> 共同归档规则：[[开发/漫剧与小说创作核心纲领与执行方案]]。漫剧制作遵循 [[开发/漫剧制作合同]]；小说入口见 [[开发/小说创作入口与Skill接入合同]]。

## 1. 入口与装载

Desktop 保留漫剧制作、短剧写作、小说创作三个互斥入口与会话偏好。点击短剧只选中 `jc-duanju` 与 `wiki-memory`，不自动读取、写作或生成媒体。短剧路由清单唯一准源为 `public/skills/short-drama-route.json`，选择器和 Harness 使用同一清单。

短剧模式允许 `jc-duanju`、`jc-xiangmuziliao`、`jc-duanju-cehua`、`jc-duanju-fenji`、`jc-duanju-xiezuo` 与 `wiki-memory`。Harness 在当前 Agent 作用域登记内置包，入口正文显式加载，子 Skill 按需读取，不重复注入业务说明。退出移除短剧选择，保留用户原先手选 Wiki 的偏好；共享项目资料 Skill 在漫剧路线仍保留。原有 `jc-duanju` 对话无需改名，原创、单场、续写、润色能力由路由交给写作 Skill。

## 2. 业务流程

未指定步骤、从头开始改编时固定按“原作项目资料落袋 → 探讨改编思路 → 明确核心梗的改编项目资料与整体方案 → 复用原生故事拆分拆原文 → 分集改编规划写入Wiki → 逐集改编正文写入Wiki”执行。原文完整收录与阅读覆盖是资料落袋的依据。用户无思路时提供人物、背景、题材、设定、剧情、结构六类具体改法，可组合而非六选一。已有原作或新版资料先复用，核验来源覆盖，只补缺口；明确指定单项任务直接接手，不强制补跑全流程。

| Skill | 职责 |
| --- | --- |
| `jc-duanju` | 总路由、阶段接手、长篇来源与进度交接 |
| `jc-xiangmuziliao` | 提取原作人物、关系、背景规则、场景道具、事件线与发展阶段 |
| `jc-duanju-cehua` | 改编思路与保留边界、联动重建新版项目资料、整体叙事方案 |
| `jc-duanju-fenji` | 阶段容量与正式分集规划、来源映射、人物状态、钩子承接 |
| `jc-duanju-xiezuo` | 原创／改编文学剧本、续写、修订、自检与逐集保存 |
| `wiki-memory` | 唯一根、真实索引、证据读取、归档规则与回执 |

策划先改世界规则，再重建人物身份经历、性格动机与关系、场景道具及事件因果，允许联动迭代。不能仅替换名字后直接沿用原作事件。新版资料稳定后确定视角、主支线、阶段高潮、信息释放与整体容量，再拆集；原文章节不等于短剧集数。

场景／道具按剧情影响分为核心详档、复用简档、临时物留事件。单次出现但影响身份、反转、胜负、结局的也属核心。资料锁定归属、功能、准入／取得条件、限制、代价、流转及关键状态；视觉细节交给漫剧制作，直接影响剧情识别的外观除外。人物关系留各人物小传，规则不重复维护。

## 3. 长文来源与覆盖

粘贴原文用共享工具的 `source_material`：`work_name`、`source_block`（当前用户消息文本块，从0开始）、`source_start`／`source_end`（各至少12字符且唯一）。Runtime 从消息截取包含首尾的原文，不采用模型传回正文，不归一化原文换行。当前 Agent 同路线下一轮也更新来源快照；来源不存在、歧义、顺序错误或超1MB拒绝。原文只创建；同路径同内容重试不重写，内容不同不覆盖。

该接口不会自动拆故事或做语义分析。已导入或附件来源沿既有能力读取，原生故事拆分仍保留原有显式启动边界：默认流程第四步引导用户在文件树选中原文并点击“故事拆分”，核对预览和实际节点索引后续做。已拆分则直接复用；不虚构模型可调用的拆分工具、不以普通文件写入模拟拆分。按章或连续可定位段落读取，同批提取各类资料，合并别名和状态；只对关键缺口定点回查。`research_coverage` 保存总来源、已读／未读范围、缺口与恢复位置，只有实际覆盖后才能声称通读。长文超过模型上下文时仍受具体模型容量约束，不能因存盘成功宣称模型完整读过。

## 4. Wiki 归档与确认

原有产物省略 `research_version` 时保持旧路径。项目资料支持 `original`／`adapted`，分别进入 `项目资料/原作/`、`项目资料/改编版/`；旧资料按索引关联，不自动搬迁删除。

| 类型 | 内容与落位 |
| --- | --- |
| `story_summary`、`episode_summaries`、`character_bio`、`story_background`、`world_rules` | 原有资料，可加版本字段；人物逐人独立 |
| `scene_research`、`prop_research` | 相应版本内场景／道具独立档，必填 `entity_name` |
| `event_timeline`、`research_coverage` | 相应版本内事件线与发展阶段／阅读覆盖 |
| `project_overview` | `改编方案/项目总纲.md`，包含方向、改编对应和整体方案 |
| `adaptation_episode_plan` | `改编方案/分集规划.md`，正式改编分集依据 |
| `screenplay` | `剧本/第NNN集/分集剧本.md`，必填 `episode_number` |
| `production_progress` | `制作进度.md`，仅记录导航、状态与下一步 |
| `source_material` | `原始材料/<作品>/原文.md` |

路径由 Runtime 决定并校验，模型不传任意路径、不手工重写索引。更新既有总纲须先完整读取、保留漫剧等其他章节并 update，不 append。原作建议分集不替代改编版正式规划。历史 `改编思路.md` 只读沿用，不自动迁移。

保存与确认分开：用户授权保存的完整待审产物可标记待确认；不能把保存成功等同用户确认。方向与新版资料、整体方案与规划、首集样稿是主要决策点；用户已明确委托的范围连续推进，不逐集重复确认。关键未决项影响因果时先交具体决策。

每集规划必须列出可直接定位读取的真实原文章节双链、使用段落／事件与改编用途；明确唯一主情绪点、基于原文的开场动作／台词（视觉、台词或两者结合）、具体结尾钩子与下集兑现。正文按索引实际读取原文，依据新版资料核心梗与规划精准改编，围绕主情绪推进。每集读取新版资料、规划、必要原作来源、前集实际稿与目标集旧稿。检查认知、身体／道具状态、规则代价、场景可达性、钩子兑现和下集承接，统计发声字数并估算时长。保存后核对真实回执再继续；部分成功报告警告并修复索引，不计为全部完成。进度页不替代实际正文；上游改动先评估受影响资料、规划和集稿再按授权修订。

## 5. 兼容与制作交接

默认目标90秒、每集一场戏、发声文本200–400字（含上下限），因果必须多场时如实拆场，用户或项目规格优先。策划将有效规格写入项目总纲，分集与正文共同读取；独立单项任务无总纲时沿用默认规格。已授权改编的新版事实优先于原作旧身份，未授权改变仍保留原作承诺。

文学剧本不写摄影机、光位、逐镜时码或模型视频提示词；用户切换漫剧制作后复用同一Wiki与确认剧本，继续工程台本及视觉资产。已有唯一规范资产档案就在该档补设计章节，资料页只关联；没有资产档时新建视觉档并关联剧情资料，避免重复事实。

只改 Desktop 现有链路，不扩展 Web/Mobile 产品范围，不删除桌面能力。内置 Skill 索引由脚本生成；源码修改不代表已安装App或发布包更新。

## 6. 2026-10-21 审计补齐

- 原创多集复用策划→分集→正文，免除原作提取、故事拆分与原文索引；原创单场／单集输入足够直接写作。
- 原文索引核验仅约束改编；末集以核心冲突、人物弧光和主情绪兑现为验收，不强留追更钩子。
- 短剧正式任务的完整项目资料、选定方向与核心梗、整体方案、分集规划、逐集正文和制作进度自动通过 `wiki_save_artifact` 归档，无需用户追加保存指令；`wiki-memory` 负责读写规则，工具负责实际落盘与索引。未选方案、讨论和未完成片段不自动归档，用户仅讨论／预览／不保存的要求优先；保存不等于确认。
- 每集先自检来源（改编）、核心梗、主情绪、强开头、人物认知与动机、场景／道具连续性、字数与估算时长、钩子／结局，修正后保存，核对真实回执再继续。应用内项目资料路径由统一工具合同决定。
- 本轮装载与归档回归23/23通过；未执行真实模型创作、人工桌面流程或安装包发布验证。
