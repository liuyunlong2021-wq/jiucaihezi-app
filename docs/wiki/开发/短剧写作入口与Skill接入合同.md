## 1. 用户入口

- Desktop 输入框下方依次显示「漫剧制作」「短剧写作」「小说创作」三个入口。点击只切换当前对话模式，不自动读取项目、写作或生成媒体。
- 三种模式互斥；每个对话分别保存并恢复模式偏好。`wiki-memory` 是短剧模式的必需依赖，用户原先手动选中的 `wiki-memory` 在退出模式时保留，否则移除自动加入的依赖。
- 已有漫剧模式对话中曾选择 `jc-duanju` 的历史选择迁移到短剧模式；新模式只恢复 `jc-duanju` 与 `wiki-memory`。三个旧个人 Skill 目录已按本次明确授权清理，`public/skills/jc-duanju` 是唯一准源。
- 短剧模式的 Skill 选择器只展示 `jc-duanju`、`wiki-memory`。漫剧模式白名单不再含 `jc-duanju`；小说模式仍只展示 `jc-novel`、`wiki-memory`。

## 2. `jc-duanju` 职责

`public/skills/jc-duanju/SKILL.md` 是短剧创作的唯一业务入口，整合原创短剧写作、既有作品改编方向和逐集落笔：

1. 原创短剧：按用户给定规格创作创意、分集大纲、单集文学剧本、扩写、续写和修订。
2. 改编方向：明确目标受众与规格、原作核心驱动、保留承诺与改编力度；以成对替换方案表达变化；检查替换与后续剧情之间的依赖。
3. 逐集改编：只读取目标集的原作依据、已确认方向、已完成前集和实际出场资产；保留原作因果并控制本集边界，不预写未要求的剧集。
4. 方向修订：先评估已完成剧集的影响并提交用户决策；未获确认不自动回改方向或剧本。

默认短剧规格保留快节奏、一场戏、60–120 秒及发声文本 400 字以内；用户或项目给出不同规格时按明确要求创作，并核对其与原作因果是否冲突。

## 3. 短剧与漫剧交接

- 短剧路线交付文学剧本，不写景别、摄影机运动、光位、逐镜时码或视频模型提示词。
- 文学剧本确认后，用户可切换到「漫剧制作」，从 `jc-gongchengjuben` 生成工程台本；继续由漫剧路线处理视觉方向、角色／场景／道具资产、H3 或 Seedance 视频提示词。
- 两条路线使用同一项目和 Wiki，按索引复用同一份剧本，不复制内容；切换路线不自动触发下游制作。
- 漫剧 Skill 路由遇到短剧方向或文学剧本任务时提示用户切换模式，不通过漫剧白名单调用 `jc-duanju`。

## 4. Wiki 与保存

- `wiki-memory` 负责唯一 Wiki 根、索引、读写冲突及真实回执；`jc-duanju` 负责正文与产物元数据；实际写入复用共享 `wiki_save_artifact`。
- 正式改编方向使用 `project_overview`，写入 `改编方案/项目总纲.md` 的“改编方向”章节；已有总纲必须先完整读取、保留其他章节并以 `write_mode=update` 提交整份新版，不对此类型使用 `append`。分集剧本使用 `screenplay` 与 `episode_number`，写入原生分集剧本路径。模型不得填写任意路径或手工维护索引。
- 用户只讨论、比较或预览时不保存。明确要求制定／保存正式方向、剧本或分集大纲时归档；“只在对话里”“不要保存”优先。
- 项目中已有旧版 `改编思路.md` 时可依据索引只读沿用；不新建、不自动迁移、不删除用户 Wiki 文件。

## 5. 实施边界

- 「短剧写作」入口位于漫剧与小说入口之间，不改变 Web、Mobile 范围，不影响桌面其他制作能力。
- `public/skills/index.json` 从内置 Skill 包生成；路由白名单与产品帮助文档同步维护。
- 本次源码执行不代表安装包更新或已安装 App 生效。自动化测试、桌面交互、真实模型及多平台验证需分别执行并记录。
