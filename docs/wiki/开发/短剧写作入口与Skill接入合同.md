## 1. 入口与装载

Desktop 保留漫剧制作、短剧写作、小说创作三个互斥入口与会话偏好。点击短剧只选中 `jc-duanju`，Wiki通过原生能力接入，不自动读取、写作或生成媒体。短剧路由清单唯一准源为 `public/skills/short-drama-route.json`，选择器和 Harness 使用同一清单。

短剧模式允许 `jc-duanju`、`jc-xiangmuziliao`、`jc-duanju-cehua`、`jc-duanju-fenji`、`jc-duanju-xiezuo`。Harness 在当前 Agent 作用域登记内置包，入口正文显式加载，子 Skill 按需读取，不重复注入业务说明。退出移除短剧选择，不影响独立原生Wiki能力；共享项目资料 Skill 在漫剧路线仍保留。原有 `jc-duanju` 对话无需改名，原创、单场、续写、润色能力由路由交给写作 Skill。

## 2. 业务流程

未指定步骤、从头开始改编时，按“原作落袋 → 确定新皮 → 原文组合分集 → 逐集换皮”推进。原先六步的原文与资料保存、六类讨论、核心梗、原生故事拆分、规划与正文归档能力保留，合并重复的阶段／事件重建，不强建平行故事。已明确指定单项或续做直接接手。

| Skill | 职责 |
| --- | --- |
| `jc-duanju` | 总路由、阶段接手、原文覆盖及进度 |
| `jc-xiangmuziliao` | 提取换皮所需资料；独立完整资料能力保留，短剧不预做建议分集 |
| `jc-duanju-cehua` | 六类可组合方向、核心梗和必要新皮资料；保留原创整体策划 |
| `jc-duanju-fenji` | 原文情绪关联、首尾切点、呈现顺序及体量；保留原创多集规划 |
| `jc-duanju-xiezuo` | 直接取原文换皮、自检并逐集保存；原创、扩写、续写、润色保留 |
| 原生Wiki | `wiki_read_guidance`、真实索引、`wiki_save_artifact`与回执 |

原文是内容，新资料是替换规则。默认全部继承对白、描述信息、动作、反应、支线、冲突、笑点、铺垫与伏笔；只执行已明确的新皮变化或实质改动，不因换背景、关系而自编事件。对白尽可能保留原句，只改必要词；描述可转动作、必要OS／旁白／闪回，信息与戏剧功能不丢。新皮无法承接时修新皮，不偷偷删戏、加戏或改变原作命运。改编的限制不禁止原创和明确授权的扩写。

分集先找承诺与落空、轻视与反击、铺垫与包袱等情绪关联，可跨章组合、前置冲突，再选开头和结尾，用短闪回／声音回忆在需要时补前因。发生顺序和观众获知顺序分开，不改变人物认知、事件因果或提前泄露核心谜底。首尾成对检查，局部兑现后留具体期待；末集收束。规划只留“集数｜主情绪｜开头｜原文组合与呈现顺序｜结尾钩子”，真实原文链接与段落范围放在组合栏，不建逐句台账。跨章移用标集数，中间未用内容继续安排，不漏原文或重复整戏凑字。

场景道具按需要沿既有唯一档案维护剧情功能与限制，不为换皮复制全套事实；原创仍可建立完整资料与整体方案。

## 3. 长文来源与覆盖

粘贴原文用共享工具的 `source_material`：`work_name`、`source_block`（当前用户消息文本块，从0开始）、`source_start`／`source_end`（各至少12字符且唯一）。Runtime 从消息截取包含首尾的原文，不采用模型传回正文，不归一化原文换行。当前 Agent 同路线下一轮也更新来源快照；来源不存在、歧义、顺序错误或超1MB拒绝。原文只创建；同路径同内容重试不重写，内容不同不覆盖。

该接口不会自动拆故事或做语义分析。已导入或附件来源沿既有能力读取，原生故事拆分仍保留原有显式启动边界：原作落袋阶段引导用户在文件树选中原文并点击“故事拆分”，核对预览和实际节点索引后续做。已拆分则直接复用；不虚构模型可调用的拆分工具、不以普通文件写入模拟拆分。按章或连续可定位段落读取，同批提取各类资料，合并别名和状态；只对关键缺口定点回查。`research_coverage` 保存总来源、已读／未读范围、缺口与恢复位置，只有实际覆盖后才能声称通读。长文超过模型上下文时仍受具体模型容量约束，不能因存盘成功宣称模型完整读过。

## 4. Wiki 归档与确认

原有产物省略 `research_version` 时保持旧路径。项目资料支持 `original`／`adapted`，分别进入 `项目资料/原作/`、`项目资料/改编版/`；旧资料按索引关联，不自动搬迁删除。

| 类型 | 内容与落位 |
| --- | --- |
| `story_summary`、`episode_summaries`、`character_bio`、`story_background`、`world_rules` | 原有资料，可加版本字段；人物逐人独立 |
| `scene_research`、`prop_research` | 相应版本内场景／道具独立档，必填 `entity_name` |
| `event_timeline`、`research_coverage` | 相应版本内事件线与发展阶段／阅读覆盖 |
| `project_overview` | `改编方案/项目总纲.md`，包含方向、改编对应和整体方案 |
| `adaptation_episode_plan` | `改编方案/分集规划.md`，正式改编分集依据 |
| `screenplay` | `剧本/第NNN集/分集剧本.md`，必填 `episode_number` |
| `production_progress` | `制作进度.md`，仅记录导航、状态与下一步 |
| `source_material` | `原始材料/<作品>/原文.md` |

路径由 Runtime 决定并校验，模型不传任意路径、不手工重写索引。更新既有总纲须先完整读取、保留漫剧等其他章节并 update，不 append。原作建议分集不替代改编版正式规划。历史 `改编思路.md` 只读沿用，不自动迁移。

保存与确认分开：用户授权保存的完整待审产物可标记待确认；不能把保存成功等同用户确认。方向与新版资料、整体方案与规划、首集样稿是主要决策点；用户已明确委托的范围连续推进，不逐集重复确认。关键未决项影响因果时先交具体决策。

每集规划必须列出可直接定位读取的真实原文章节双链、使用段落／事件与改编用途；明确唯一主情绪点、基于原文的开场动作／台词（视觉、台词或两者结合）、具体结尾钩子与下集兑现。正文按索引实际读取原文，依据新版资料核心梗与规划精准改编，围绕主情绪推进。每集读取新版资料、规划、必要原作来源、前集实际稿与目标集旧稿。检查认知、身体／道具状态、规则代价、场景可达性、钩子兑现和下集承接，统计发声字数并估算时长。保存后核对真实回执再继续；部分成功报告警告并修复索引，不计为全部完成。进度页不替代实际正文；上游改动先评估受影响资料、规划和集稿再按授权修订。

## 5. 兼容与制作交接

默认目标90秒、发声文本200–400字（含上下限）、一场主戏，必要短闪回／声音回忆与原作场次如实标注，用户或项目规格优先。策划将有效规格写入项目总纲，分集与正文共同读取；独立单项任务无总纲时沿用默认规格。已授权改编的新版事实优先于原作旧身份，未授权改变仍保留原作承诺。

文学剧本不写摄影机、光位、逐镜时码或模型视频提示词；用户切换漫剧制作后复用同一Wiki与确认剧本，继续工程台本及视觉资产。已有唯一规范资产档案就在该档补设计章节，资料页只关联；没有资产档时新建视觉档并关联剧情资料，避免重复事实。

只改 Desktop 现有链路，不扩展 Web/Mobile 产品范围，不删除桌面能力。内置 Skill 索引由脚本生成；源码修改不代表已安装App或发布包更新。
