## 2. 根因与实施

| 原问题 | 实施后的规则 |
| --- | --- |
| 首次启动 A/B/C 阻断明确续写、修订或复盘 | 明确任务直接进入；无明确任务且无可承接节点时才启动选择 |
| 大纲、章纲、续写、点评、确认混在九阶段串行流程 | 入口增加意图到阶段／参考的表；只执行当前任务或用户明确要求的多个产物 |
| 入口、引擎表和正文工作流各有引擎清单 | 选择只由 `references/engines/index.md` 定义；工作流只描述构思、起草、润色、检查的工作目标 |
| “挑1–3个”和“不能读多个”含义冲突，工作流固定链实际超过20个 | 简单任务可读0个；1个主引擎加0–2个条件引擎，当前任务共用最多3个不同引擎的额度，逐个读取 |
| 引擎名称有登记但没有资源链接 | 五份基础参考、路由表及100个引擎均用实际相对链接连接 |
| 旧扩展目录与 Agent／SKILL 标签诱发错误跳转 | 修正5份失效资源说明；旧编号仅作为方法标签，不产生新的调用或任务 |
| 写作批次把逐章确认改成每3／5／10章 | 分批交付不改变确认条件；确认必须唯一对应实际已保存草稿版本 |
| 产物类型被写成独立工具名 | 明确使用 `wiki_save_artifact` 与真实 `artifact_kind`；作品、章节、标题及确认字段按工具合同提交 |

章节仍按“草稿 → 用户明确确认 → 原文追加 → 确认记录”执行。只有实际工具回执决定保存状态；故事拆分由用户在文件树手动触发。共同归档规则继续遵守 [[开发/漫剧与小说创作核心纲领与执行方案]]。
