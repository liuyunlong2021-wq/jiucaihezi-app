# 短剧改编：逐章切分与逐集改编升级TDD

> 2026-10-24。用户最终收敛：只做改编，名称为“短剧改编”。本合同取代此前三类任务分流、跨章重组分集及默认硬凑90秒/200–400字的建议。保留历史记录与独立普通模式的旧写作资源，不把它们混入当前流程。

## 1. 唯一业务链

原文附件/路径＋基本改编思路 → 实际读取并原样保存原作 → 共用项目资料 → 完善改编方案 → 逐章定首尾、章内切分多集 → 每集只对照本集切分改编 → 自检、独立保存。

入口不再提供原创/优化三选一；有基本思路直接完善，不强迫重选换皮菜单。指定只做某章/集/步骤时尊重范围；已有资料和目标稿先读后复用，不重跑全书。自动执行仍由专业Skill完成创作，应用层只做归档、切分、状态与读取校验，不新增通用目标/子代理/后台工具，不修改DSH自身历史管理。

## 2. 项目资料共用与外貌采集

继续共用`jc-xiangmuziliao`，不是另建一个缩水的短剧资料Skill。小传包含身份、经历、心理/长期动机、关系与当时认知，并明确采集：

- 原文明示的脸型、五官、瞳/肤/发色、发型、体型轮廓、姿态、伤疤及标志特征。
- 衣饰款式、颜色、材质、纹样、磨损、配件和随身物。
- 首次出场、换装、受损和身份变化的章/场来源，不能把后期造型套回初登场。
- 原文未写的明确缺失，不设计原作事实；方案明确的设计进入改编版，不污染原作小传。

原作/改编版人物、场景、道具等沿现有research类型与版本保存。新建短剧Wiki补齐两套版本导航和切分目录，不为未变化字段机械复制完整档案，也不搬迁/删除旧库。

## 3. 逐章规划与真实切分

现有`jc-duanju-fenji`升级为逐章规划，保留内部ID；`adaptation_episode_plan`新库保存`改编方案/逐章规划.md`，已有旧`分集规划.md`继续原位使用，新旧同时存在时报歧义。

每章独立，可拆多集；每集是一段连续原文，不跨章拼集，不跨邻集取大段原文。规划记录真实章、来源、集号、主冲突/情绪、真实开头和结尾、切分路径。切点服从完整事件与对白因果，不为时长/字数凑指标。

新增`adaptation_cut`，现有wiki_save_artifact传episode_number及content JSON：source_path、chapter_heading、cut_start、cut_end。程序要求实际read来源且文件版本新鲜，从真实章范围按唯一首尾截取，保留正文字符/换行；不采用模型复写原文。每集保存`改编方案/分集切分/第001集原文.md`，包含来源哈希、章、集号、范围元数据。超过单产物1MB时提示章内自然拆分。

支持常见中文第N章/回/节/集、序章/楔子/尾声与Chapter N及Markdown形式；不支持的原作格式明确说明，不能把全书假装一章。附件先复用现有导入可读副本；不宣称已有任意PDF/Word自动转换能力。

文件来源先read，再用source_material、work_name及content JSON的source_path原样存入`原始材料/<作品>/原文.md`；贴文保留现有source_block/首尾截取。后续以持久原作副本为准，避免临时附件失效。原件不改写，同路径不同原文不覆盖；保存不等于模型已完整阅读。

## 4. 逐集改编的通用圣经

`jc-duanju-xiezuo`主文件以用户指定规则为准：

- 本集真实切分是内容边界。可在边界内扩写/缩写已有表达，不能新增事件、证据、能力、胜负、关系或未来认知。前后集只核对必要衔接，不大段搬入或重演。
- 动作优先，对话其次，旁白/OS最后；不用OS替代可拍信息，也不为禁OS造出角色不可能说的话。
- 先明确既有关系、认知、目标、恐惧、权力/威胁。情绪实际改变视线、呼吸、姿态、手部、说话节奏与行动选择。
- 主角承担自身关键选择，配角按自身动机行动；场次由威胁/承诺→行动→局势变化形成因果链。
- 闪回/切场由当前动作、道具、对白或威胁触发并返回冲突，内容仍在本集切分内。
- 动作有空间、发起、受力、阻碍与结果，服务目标且遵守力量规则。
- 首次出场用有依据的外形/服装、姿态、行为和反应建立识别与性格；不能为“出场显著性”捏造威压、新能力或围观事件。资料未知字段不冒充事实。
- 用户给出的落稿自检逐项执行，发现问题实际修稿，不仅写“自检通过”。

每集read有效方案、逐章规划、本集切分、涉及人物/场景/道具及目标旧稿，再保存现有`screenplay`唯一路径。守卫核对必读文件版本、切分源哈希与章边界；不能据此声称程序已证明成稿没有任何幻觉或跨集信息。文学动机、表演质量及扩缩写是否恰当仍需真实创作审阅。

- 阶段必须有实际文件，前置文件与源哈希变化拒绝推进，不能跳步。
