# 通用记忆工作台模型主导工具与审批 SDD

> 日期：2026-07-31  
> 状态：已实施，待人工验收  
> 范围：通用记忆工作台 Desktop / Web 的模型工具装配、文件操作与审批；不改主 Studio 文武模式的 OpenCode 工具系统。  
> 依据：`AGENTS.md`、[[开发/通用记忆对话独立App SDD]]、[[开发/通用记忆工作台原始素材与文档按需阅读SDD]]、[[开发/创模式MCP工具接入SDD]]、[[开发/Pi统一事实流升级SDD]]

## 1. 决断

通用记忆工作台是模型主导的工作台：**当前环境里真实可执行的工具交给模型选择，产品只负责能力边界、权限、安全、执行结果和过程展示。**

```text
用户提出目标
  -> App 提供当前平台真实可用的工具
  -> 模型自主决定是否调用、调用哪个、按什么顺序调用
  -> App 按工具风险自动执行或请求用户批准
  -> 真实结果返回同一模型继续完成任务
```

不得用中文关键词分类器替模型预判本轮需要哪个项目工具或 MCP，也不得要求模型先加载 Skill 才能获得基础工具。Skill 是专业方法说明，不是文件、终端或 MCP 的权限开关。

## 2. 根因

当前记忆工作台复用了创模式直连工具循环，但工具合同并不完整：

- 已有 `skill / wiki / read / glob / grep / write / edit` 和已连接 MCP。
- `read_url` 只在用户本轮明确提供网址时出现；`web_search` 只在用户选择 `@联网搜索` 时出现，这两条边界正确，继续保留。
- 记忆 Desktop 实际使用过滤掉 `terminal` 的 Web 工具定义，因此模型不能像主 Studio 一样在用户批准后调用本机命令。
- 没有独立的 `mkdir / move / delete`，模型无法在 Web 与 Desktop 统一完成空目录、移动、重命名和删除。
- Desktop 执行器支持绝对路径 `write/edit`，但记忆工作台没有主 Studio 的执行前审批，不能只靠工具描述中的“用户已批准”约束模型。
- [[开发/创模式OpenCode式Skill渐进工具加载SDD]] 提议“先加载 Skill，随后才开放基础工具”，会增加一次模型往返并可能错误剥夺模型能力，已被本 SDD 替代，不再执行。

问题不是模型工具太多，而是工具可见性和执行权限混在了一起。正确拆分是：**可见性由平台能力决定，是否调用由模型决定，是否执行由风险策略决定。**

## 3. 工具合同

### 3.1 记忆模式

| 工具 | 可见条件 | 执行规则 |
| --- | --- | --- |
| `skill` | 始终 | 自动；只加载用户已安装或内置 Skill |
| `wiki` | 始终 | 只读动作自动；写入动作沿用 Wiki 自身确认合同 |
| `read / glob / grep` | 始终 | 当前项目内自动执行；项目外只允许用户本轮明确提供或已授权的路径 |
| `write / edit` | 始终 | 当前项目内自动执行；项目外写入必须审批 |
| `mkdir` | 始终 | 当前项目内自动执行；复用 `ProjectFileService`，不新建文件系统协议 |
| `move` | 始终 | 当前项目内自动执行；同时承担移动和重命名，复用 `ProjectFileService` |
| `delete` | 始终 | 每次必须审批；Desktop 复用现有移入系统废纸篓能力，Web 明确提示删除浏览器本地项目资源 |
| `terminal` | 仅 Desktop | 每次调用进入与主 Studio 一模一样的三按钮审批；批准后才执行 |
| 已连接 MCP | MCP 已启用且连接成功 | 全部作为候选工具交给模型，不做中文关键词裁剪；外部写入或危险动作按其风险审批 |
| `read_url` | 用户本轮明确提供公网 URL | 自动；只能读取本轮列出的 URL，不等同联网搜索 |
| `web_search` | 用户本轮选择 `@联网搜索` | 自动；发送成功或切换模式后清除本轮开关 |

工具不存在、当前平台不支持、模型不支持 function calling 或 MCP 未连接时，返回真实错误；不自动换模型，不伪造结果。

### 3.2 快速模式

快速模式继续以无工具直答为默认：

- 本轮有文档附件时，只开放当前附件范围内的 `read / grep`。
- 本轮有明确 URL 时，只增加受限 `read_url`。
- 不开放 `write / edit / mkdir / move / delete / terminal / wiki / Skill / MCP`。
- `@联网搜索` 继续按现有显式单轮开关处理。

## 4. Terminal 审批

记忆 Desktop 不设计第二套审批组件，直接复用主 Studio 创模式现有审批条、按钮、文案生成和 Direct Runtime `beforeToolCall` 接口。

每次模型调用 `terminal` 时，先显示模型准备做什么，提供三个与主 Studio 一致的决定：

| 按钮 | 结果 |
| --- | --- |
| `拒绝` | 本次命令不执行，工具结果记为 `cancelled`，模型可改用其他方法 |
| `允许` | 只执行当前这一条命令；下一条命令再次询问 |
| `始终允许` | 仅本次发送产生的当前运行内不再询问；运行结束、停止、失败或切换会话后立即失效 |

“始终允许”不得写入 `localStorage`、数据库或系统配置，不得变成跨会话永久授权。用户停止生成时，正在等待的审批按拒绝结束，不能留下旋转中的工具步骤。

终端执行继续复用现有受控 `dev_run_command`、超时、失败重复保护和步骤 UI。不得复制 Shell 执行器，也不得引入 OpenCode sidecar；记忆 APP 仍是独立轻量产品。

Web 没有本机 Shell，不暴露 `terminal`，也不显示不可执行的占位工具。

## 5. 文件与路径安全

1. 所有项目文件工具继续只接受项目相对路径，拒绝绝对路径、`..`、空字节和越界符号链接。
2. `write/edit/mkdir/move` 的当前项目内操作可以自动执行，但必须显示真实工具步骤。
3. 项目外 `write/edit` 只有在用户本轮明确提供目标绝对路径且通过三按钮审批后才能执行；不能把历史消息中的路径自动视为授权。
4. `delete` 不进入“始终自动允许”的无确认集合。Desktop 优先移入系统废纸篓，不使用 `rm` 伪装删除；Web 删除前明确说明它删除的是浏览器本地项目资源。
5. `terminal` 获得批准不等于解除 App 路径和系统权限边界；命令失败时把真实错误返回模型，不弹出无限重试审批。

## 6. MCP 与工具数量

已启用且已连接的 MCP 工具属于模型候选能力池，不再使用 `classifyToolIntent()` 这类中文关键词分类器提前剔除。GitHub 等专用 MCP 应优先于泛化网页搜索，由模型根据工具名称、描述和当前任务判断。

本期不新增“能力发现中心”、工具向量检索或第二个路由模型。当前核心工具数量很小，直接提供更简单可靠。只有真实出现工具 schema 超过渠道限制或模型选择准确率下降的证据后，才另开 SDD 做渐进工具发现。

## 7. 最小实施

1. 从主 Studio 抽取并复用现有三按钮审批的最小共享组件/状态，不复制一整份 `ChatPanel` 逻辑。
2. 记忆 Desktop 工具清单增加现有 `terminal` 定义，并在 `runMemoryChat` 接入 Direct Runtime `beforeToolCall`。
3. 在现有项目工具合同增加 `mkdir / move / delete`，执行层复用 `ProjectFileService` / Web 项目文件适配器已有能力。
4. 给 `write/edit` 增加项目内外风险判断；移除记忆链路中无审批的绝对路径写入。
5. MCP 工具按连接态全量进入候选池，删除本链路中替模型做决定的关键词裁剪；保留 URL 与联网搜索的显式边界。
6. [[开发/创模式OpenCode式Skill渐进工具加载SDD]] 保留为历史讨论，但不得进入实施队列。

不新增依赖，不新增权限内核，不启动 OpenCode，不重写 Direct Engine。

## 8. 验收

### 自动验收

1. Desktop 记忆模式工具清单包含 `terminal / mkdir / move / delete`；Web 不含 `terminal`。
2. 快速模式无文档和 URL 时仍为零工具；有文档时只允许附件范围内 `read/grep`。
3. 当前项目内 `write/edit/mkdir/move` 成功执行并产生完整的 `start -> end` 步骤。
4. `delete`、项目外写入和每次 `terminal` 在真实执行前等待审批。
5. `拒绝 / 允许 / 始终允许` 与主 Studio 语义一致；“始终允许”只覆盖当前运行。
6. 停止、拒绝、参数错误、命令失败和成功均结束工具步骤，不留下等待态。
7. 已连接 GitHub MCP 在普通仓库查询中进入候选池，不因中文关键词未命中而消失。
8. `read_url` 与 `web_search` 继续严格区分，普通消息不获得联网搜索。

### 人工验收

| 场景 | 预期 |
| --- | --- |
| “新建资料/会议/目录” | 模型调用 `mkdir`，项目树出现空目录 |
| “把 A 移到资料目录并改名” | 模型调用 `move`，原路径消失且新路径可读 |
| “删除这个文件” | 执行前询问；拒绝后文件保留 |
| “运行本机命令处理这个文件” | 出现与主 Studio 一样的三按钮审批条 |
| Terminal 点“允许” | 只执行当前命令，下一条继续询问 |
| Terminal 点“始终允许” | 当前运行后续命令不再询问，新一轮恢复询问 |
| 提供 GitHub 仓库任务 | 模型可优先调用已连接 GitHub MCP，不被搜索工具抢走 |
| Web 使用同一任务 | 文件工具可用，`terminal` 不出现 |

## 9. 成功标准

```text
工具是否可用：由平台和连接状态决定。
工具是否调用：由模型决定。
工具是否执行：由权限与用户决定。
```

用户不需要理解工具路由，也不会因为模型拥有更强能力而失去对本机命令、项目外写入和删除的控制。

## 10. 实施记录（2026-07-31）

- 记忆 Desktop 已增加 `terminal / mkdir / move / delete`；Web 已增加三项文件工具但不暴露 `terminal`；快速模式继续只按当前附件和明确 URL 提供最小只读工具。
- 主 Studio 与记忆工作台共用同一个三按钮审批条；“始终允许”只保存在当前发送运行内，`delete` 每次仍需确认，停止或结束运行会清理等待中的审批。
- 项目内 `write/edit/mkdir/move` 自动执行；项目外路径必须出现在本轮用户文字中，项目外写入需审批；MCP 保留并执行标准 `readOnlyHint` 风险标注。
- 主 Studio 原工具清单未扩大；记忆专用工具清单独立装配。未新增依赖、权限内核、路由模型或 OpenCode sidecar。
- 自动验证通过：focused Node 1412/1420（8 个条件跳过）、Rust 401/402（1 个手工隔离测试忽略）、`vue-tsc -b`、Web 生产构建与产物审计、Desktop 生产构建与产物审计、`git diff --check`。
- 并发审计后补强：Direct Runtime 只执行本轮实际公开的工具，项目外路径改为完整边界匹配，快速模式只读取本轮附件；Desktop 移动拒绝覆盖既有目标，删除返回真实 missing 状态；切换项目、切换对话、停止或卸载会使当前审批与“始终允许”立即失效。
- MCP `readOnlyHint` 仍按标准 annotations 作为自动执行依据；这要求用户只连接自己信任的 MCP Server，不另建产品私有工具白名单。
- 待人工按第 8 节验证 Desktop 三按钮、Web 无 Terminal、删除拒绝、当前运行“始终允许”和真实 GitHub MCP 选择。
