# 通用记忆工作台模型主导工具与审批 SDD

> 日期：2026-07-31  
> 状态：已实施；2026-08-07 已迁出 Jina 网页工具；待真实模型与三平台人工验收<br>
> 范围：通用记忆工作台 Desktop / Web 的模型工具装配、文件操作与审批。<br>
> 依据：`AGENTS.md`、[[开发/通用记忆对话独立App SDD]]、[[开发/通用记忆工作台原始素材与文档按需阅读SDD]]、[[开发/Pi统一事实流升级SDD]]

## 1. 决断

通用记忆工作台是模型主导的工作台：**当前环境里真实可执行的工具交给模型选择，产品只负责能力边界、权限、安全、执行结果和过程展示。**

```text
用户提出目标
  -> App 提供当前平台真实可用的工具
  -> 模型自主决定是否调用、调用哪个、按什么顺序调用
  -> App 按工具风险自动执行或请求用户批准
  -> 真实结果返回同一模型继续完成任务
```

不得用中文关键词分类器替模型预判本轮需要哪个项目工具或 MCP，也不得要求模型先加载 Skill 才能获得基础工具。Skill 是专业方法说明，不是文件、终端或 MCP 的权限开关。

GE 不是传统聊天窗口，而是以 Markdown Raw 为完整账本的记忆工作台。每次发送必须明确分成三层：

```text
本轮用户消息             = 当前唯一任务，完成前只存在于本轮 UI / 请求
.raw/对话记录/*.md       = 已完成轮次组成的历史资料
当前平台工具             = 本轮可独立选择的执行能力
用户消息 + 完整助手回复   = Raw 的最小持久化单位
```

历史中曾经出现的“不要调用工具”“先别执行”只描述当时那一轮，不能关闭以后轮次的工具。只有本轮用户消息、当前平台能力和独立审批状态可以影响本轮工具执行。

## 2. 根因

### 2.0 工具与审批的历史根因（已解决）

记忆工作台最初复用了创模式直连工具循环，但工具合同不完整：

- 已有 `skill / wiki / read / glob / grep / write / edit` 和已连接 MCP。
- `read_url` 与 `web_search` 曾分别承担网址读取和显式联网搜索；2026-08-07 用户确认两者不属于核心产品，现已连同 Jina 适配器迁出。
- 记忆 Desktop 当时过滤掉 `terminal` 的 Web 工具定义，因此模型不能在用户批准后调用本机命令。
- 没有独立的 `mkdir / move / delete`，模型无法在 Web 与 Desktop 统一完成空目录、移动、重命名和删除。
- Desktop 执行器支持绝对路径 `write/edit`，但记忆工作台当时没有执行前审批，不能只靠工具描述中的“用户已批准”约束模型。
- 旧产品曾提议“先加载 Skill，随后才开放基础工具”；该方案会增加一次模型往返并可能错误剥夺模型能力，已被本 SDD 替代。

这部分已按本文第 3 至 6 节实施。结论继续有效：**可见性由平台能力决定，是否调用由模型决定，是否执行由风险策略决定。**

### 2.1 本次用户实测暴露的根因

当前发送链路先把用户消息追加进 Raw，再把 `saved.transcript.turns` 全量交给 `buildDirectMessages({ historyLimit: null })`。这同时造成两个问题：

1. Raw 中每一条历史用户消息都再次以 `role=user` 进入请求，旧指令和本轮任务没有结构边界。
2. 模型失败、取消或断网时，只留下用户问题而没有回答；Raw 记录了发送尝试，而不是用户真正需要的完整对话。

新增一句“以最后一条消息为准”的系统提示只能降低误判概率，不能改变输入结构。模型仍可能把历史里的“不能使用工具”理解为当前限制，于是出现用户连续要求执行，模型仍声称“没有允许调用工具”的现象。

### 2.2 横向结论

| 产品形态 | 当前任务 | 历史 / 项目资料 | 工具与权限 |
| --- | --- | --- | --- |
| 主 App 创模式 | 最后一条用户消息单独决定本轮目标和工具限制 | 在容量内装配最近完整问答，并按需读取项目热记忆 | 工具循环独立运行，真实结果返回模型 |
| Codex / Claude Code / OpenCode 类 Agent | 当前 Prompt 启动本轮 Agent loop | 会话上下文、压缩结果或工作区文件作为支持信息 | 工具由运行时提供，权限由独立审批层控制，不由旧聊天文字保存 |
| GE 通用记忆工作台目标 | 新发送消息是本轮唯一当前任务 | Raw 是完整 Markdown 账本，由模型带着当前问题按需 `read/grep` | 每轮重新由模型决定是否调用；执行仍受当前平台和审批状态约束 |

共同原则不是复制某个产品的内部架构，而是：**当前任务、历史资料、工具权限必须是三个不同概念。** GE 已经拥有 Raw 和基础文件工具，最小方案是使用现有能力完成隔离，不引入第二模型、任务规划器、摘要库或新记忆系统。

### 2.3 最终消息合同

发送顺序确定为：

```text
1. 用户点击发送
2. App 把当前 userTurn 保留在本轮 UI / 请求中，不写 Raw
3. 模型只把该 userTurn 作为当前任务；Raw 不展开成 user / assistant 消息数组
4. 记忆模式把当前 Raw 路径告诉模型；模型需要历史时使用现有 read / grep 按需查阅
5. 模型按本轮任务自主调用工具，工具真实结果返回同一模型
6. Direct Engine 得到完整最终回复后，以一次文件修订把 userTurn + assistantTurn 追加进 Raw
7. 追加成功后清空输入并结束本轮
```

Raw 记录完成的对话，不记录发送尝试。模型失败、用户停止或流式中断时，Raw 保持不变，输入内容和本轮附件留在界面供用户修改或重发，不追加空助手消息或失败占位消息。

工具可能在最终回复前已经真实改变项目文件。此时发生中断，不自动回滚文件、不自动重试工具，也不把半轮对话写进 Raw；界面保留真实工具步骤和错误，用户重新发送后由模型先检查当前项目状态再继续。

以下规则必须进入稳定的系统合同：

1. 当前用户消息是本轮最高优先级任务；历史只用于理解，不得覆盖本轮要求。
2. 用户说“继续”“按刚才的方案”或任务明显依赖前文时，模型先读取当前 Raw；独立问题不强制读取，避免无意义工具往返。
3. 历史中记录的工具同意或禁止均不构成权限状态。禁止只约束当时那轮，同意也不能替代 App 审批。
4. Skill、Wiki、附件、MCP 和工具结果是支持材料，不得改变本轮消息的当前任务身份。

### 2.4 当轮工具与审批合同

每轮开始时重新建立候选工具池：

```text
平台与连接状态 -> 决定哪些工具真实存在
本轮用户任务   -> 模型决定是否调用、调用什么
独立审批状态   -> App 决定调用能否执行
工具真实结果   -> 模型据此继续或回答
```

- 历史文字不得增加、移除或批准工具。
- 本轮用户明确说“不使用工具”时，模型只约束本轮；下一轮恢复正常自主选择。
- 本轮用户明确要求执行时，模型不得引用历史旧限制拒绝，但仍必须经过 App 当前有效的安全审批。
- “始终允许”是 App 内存中的当前对话审批状态，不是 Raw 内容；它可以跨该对话的多轮发送生效，但不替模型决定每轮是否需要工具。
- `delete`、项目外写入和 Terminal 的安全边界继续按本文既有合同执行，不能为了模型自主性绕过。

## 3. 工具合同

### 3.1 记忆模式

| 工具 | 可见条件 | 执行规则 |
| --- | --- | --- |
| `skill` | 始终 | 自动；只加载用户已安装或内置 Skill |
| `wiki` | 始终 | 只读动作自动；写入动作沿用 Wiki 自身确认合同 |
| `read / glob / grep` | 始终 | 当前项目内自动执行；项目外只允许用户本轮明确提供或已授权的路径 |
| `write / edit` | 始终 | 当前项目内自动执行；项目外写入必须审批 |
| `mkdir` | 始终 | 当前项目内自动执行；复用 `ProjectFileService`，不新建文件系统协议 |
| `move` | 始终 | 当前项目内自动执行；同时承担移动和重命名，复用 `ProjectFileService` |
| `delete` | 始终 | 每次必须审批；Desktop 复用现有移入系统废纸篓能力，Web 明确提示删除浏览器本地项目资源 |
| `terminal` | 仅 Desktop | 每次调用进入记忆工作台现有的三按钮审批；批准后才执行 |
| 已连接 MCP | MCP 已启用且连接成功 | 全部作为候选工具交给模型，不做中文关键词裁剪；外部写入或危险动作按其风险审批 |

工具不存在、当前平台不支持、模型不支持 function calling 或 MCP 未连接时，返回真实错误；不自动换模型，不伪造结果。

### 3.2 快速模式

快速模式与记忆模式共享当前对话上下文，工具权限固定为一个只读 `wiki_search`：

- 模型按需搜索当前项目 Wiki；`wiki_search` 只接受查询词、现行/全部范围和结果数量，不具备写入、修正、建图或任意文件读取能力。
- 不提供附件、项目引用、网址读取、联网搜索、Skill、MCP 或其他项目工具。
- 模式选择器是工具权限的唯一来源，用户消息不能增加或移除工具。
- 当前模型必须支持工具调用；不支持时返回真实错误，不静默降级为无 Wiki 能力。

## 4. Terminal 审批

记忆 Desktop 不设计第二套审批组件，直接复用记忆工作台现有审批条、按钮、文案生成和 Direct Runtime `beforeToolCall` 接口。

当前对话尚未授权时，模型调用 `terminal` 先显示准备做什么，提供三个一致的决定；点击“始终允许”后，当前 App 会话中的该对话不再询问：

| 按钮 | 结果 |
| --- | --- |
| `拒绝` | 本次命令不执行，工具结果记为 `cancelled`，模型可改用其他方法 |
| `允许` | 只执行当前这一条命令；下一条命令再次询问 |
| `始终允许` | 当前 App 会话内，该对话后续工具不再询问；其他对话不继承，删除对话或重启 App 后失效 |

“始终允许”不得写入对话 Raw、`localStorage`、数据库或系统配置，不得变成跨 App 重启的永久授权。用户停止生成时，正在等待的审批按拒绝结束，不能留下旋转中的工具步骤；已经授权的当前对话在本次 App 会话内继续有效。

终端执行继续复用现有受控 `dev_run_command`、超时、失败重复保护和步骤 UI。不得复制 Shell 执行器，也不得引入 OpenCode sidecar；记忆 APP 仍是独立轻量产品。

Web 没有本机 Shell，不暴露 `terminal`，也不显示不可执行的占位工具。

## 5. 文件与路径安全

1. 所有项目文件工具继续只接受项目相对路径，拒绝绝对路径、`..`、空字节和越界符号链接。
2. `write/edit/mkdir/move` 的当前项目内操作可以自动执行，但必须显示真实工具步骤。
3. 项目外 `write/edit` 只有在用户本轮明确提供目标绝对路径且通过三按钮审批后才能执行；不能把历史消息中的路径自动视为授权。
4. `delete` 不进入“始终自动允许”的无确认集合。Desktop 优先移入系统废纸篓，不使用 `rm` 伪装删除；Web 删除前明确说明它删除的是浏览器本地项目资源。
5. `terminal` 获得批准不等于解除 App 路径和系统权限边界；命令失败时把真实错误返回模型，不弹出无限重试审批。

## 6. MCP 与工具数量

已启用且已连接的 MCP 工具属于模型候选能力池，不再使用 `classifyToolIntent()` 这类中文关键词分类器提前剔除。模型根据工具名称、描述和当前任务判断是否使用 MCP。

本期不新增“能力发现中心”、工具向量检索或第二个路由模型。当前核心工具数量很小，直接提供更简单可靠。只有真实出现工具 schema 超过渠道限制或模型选择准确率下降的证据后，才另开 SDD 做渐进工具发现。

## 7. 最小实施

既有工具与审批部分已经实施。本轮只改消息装配，不重做工具系统：

1. `MemoryWorkbench.send()` 不再发送前调用 `appendMemoryTurn(user)`；本轮输入、附件和当前模式保留在现有组件状态中，成功落盘前不清空。
2. `runMemoryChat` 不再接收完整 `turns`，只接收当前 `userTurn` 和当前对话 Raw 路径，并把当前 turn 作为唯一 `role=user` 消息。
3. 记忆模式继续使用现有 `read / grep`，系统合同明确当前 Raw 路径和历史资料身份；不新增 `read_history` 之类重复工具。
4. 工具清单继续只由模式、平台和 MCP 连接态决定；不读取历史文字做工具裁剪或授权。
5. Direct Engine 成功返回完整回复后，通过现有 Raw mutation 边界在同一次 revision 写入中追加 `userTurn + assistantTurn`；标题首次命名也延后到成功之后，不为单一调用者新建持久化层。
6. 失败或取消时不写 Raw、不清空本轮输入、不自动重试；已经发生的工具副作用按真实状态保留。
7. 删除“最后一条消息覆盖历史限制”和“文件写完后才能声称完成”两条旧结构补丁提示；保留通用“不虚构未调用工具”、附件读取与安全审批合同。
8. 删除只断言补丁文案存在的测试，改为验证请求仅含当前 userTurn、Raw 失败时零新增 turn、成功时一次写入完整 user/assistant 对。

不改 Raw 格式，不迁移旧对话语义；仅在旧素材目录迁移时更新附件相对路径。不新增依赖或权限内核，不启动 OpenCode，不复制创模式上下文预算器，不重写 Direct Engine。

## 8. 验收

### 自动验收

1. 每次模型请求只包含本轮用户消息，不把旧 Raw turn 重新展开为历史 `role=user/assistant` 消息。
2. 模型失败、取消或流式中断时，Raw 新增 turn 数为 0；输入、附件和选择状态仍可重发。
3. 模型成功时，单次 revision 写入同时追加一个 userTurn 和一个 assistantTurn，不产生可见半轮。
4. 完整轮次写入冲突时保留输入和完整回复，重试同一轮写入且不重复 turnId。
5. 本轮消息说“立即修改”，历史曾说“不要调用工具”时，写入工具仍可由模型选择并真实执行。
6. 本轮消息说“不使用工具”时只影响本轮；下一轮工具池恢复，不继承该历史限制。
7. “继续刚才的方案”可通过现有 `read/grep` 读取当前 Raw 后完成；独立问题不被强制增加一次 Raw 读取。
8. Desktop 记忆模式工具清单仍包含 `terminal / mkdir / move / delete`；Web 不含 `terminal`。
9. `delete` 每次等待审批；项目外写入和 `terminal` 在当前对话获得“始终允许”前等待审批。
10. `拒绝 / 允许 / 始终允许` 继续按当前 App 会话中的当前对话生效，不跨对话、不跨 App 重启。
11. 已连接 MCP 的既有边界不变；`read_url`、`web_search` 与 Jina 适配器不再属于产品。

### 人工验收

| 场景 | 预期 |
| --- | --- |
| 历史说“不要调用工具”，本轮说“立即创建文件” | 模型以本轮为准并调用写入工具；历史不能关闭工具 |
| 本轮说“先讨论，不调用工具” | 本轮只回答；下一轮要求执行时正常获得工具 |
| 新建对话后直接提出独立任务 | 不读取空 Raw，直接回答或执行 |
| “继续上面没做完的内容” | 模型读取当前 Raw，再结合本轮要求继续 |
| 模型请求失败或用户停止 | Raw 不出现孤立用户消息；原输入仍可修改或重发 |
| 模型完整回答成功 | 用户消息与助手回答同时出现在 Raw |
| 工具已改文件但最终回复中断 | 文件保持真实状态，Raw 不写半轮，不自动重试工具 |
| “新建资料/会议/目录” | 模型调用 `mkdir`，项目树出现空目录 |
| “把 A 移到资料目录并改名” | 模型调用 `move`，原路径消失且新路径可读 |
| “删除这个文件” | 执行前询问；拒绝后文件保留 |
| “运行本机命令处理这个文件” | 出现三按钮审批条 |
| Terminal 点“允许” | 只执行当前命令，下一条继续询问 |
| Terminal 点“始终允许” | 当前对话后续命令不再询问；其他对话仍询问，重启 App 后恢复询问 |
| 提供 GitHub 仓库任务 | 模型可优先调用已连接 GitHub MCP，不被搜索工具抢走 |
| Web 使用同一任务 | 文件工具可用，`terminal` 不出现 |

## 9. 成功标准

```text
当前做什么：只由本轮用户消息决定。
历史是什么：Raw 只保存完成轮次，并作为按需查阅的资料。
工具是否可用：由平台和连接状态决定。
工具是否调用：由模型根据本轮任务决定。
工具是否执行：由独立权限与用户决定。
何时写 Raw：完整 user / assistant 轮次成功结束后一次写入。
```

用户不需要重复命令模型执行，也不需要理解上下文、工具路由或 Raw 的内部结构；同时不会因为模型拥有更强能力而失去对本机命令、项目外写入和删除的控制。

## 10. 实施记录（2026-07-31）
