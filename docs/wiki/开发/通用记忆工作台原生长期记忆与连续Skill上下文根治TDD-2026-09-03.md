# 通用记忆工作台原生长期记忆与连续 Skill 上下文根治 TDD

> 日期：2026-09-03
> 状态：合同已统一，待按 TDD 实施
> 范围：当前对话短期上下文、Skill 连续任务、Raw 自动索引、当前对话记忆查询
> 替代：“无显式能力不发送历史”、手动“写入 Wiki”索引、`jc-jiyi` 手动查询、Skill 每轮自动清空

## 1. 根因

当前四个局部设计组合后断开了连续任务：

1. Raw 完整保存当前对话，但只有“本轮已选能力”才装配最近三轮。
2. Skill 被当成一次性引用，每次成功回答后清空。
3. `skill-creator` 等 Skill 自身却要求“草稿 -> 测试 -> 反馈 -> 修改”的多轮流程。
4. 对话记忆是否记录、是否召回没有独立开关，旧对话内容可能在用户不需要时干扰当前任务。

“页面和 Raw 里看得到”不等于“模型请求里有上下文”，“已写入当前对话索引”也不等于“项目长期记忆可查”。

## 2. 唯一记忆模型

| 层级 | 唯一真源 | 职责 | 触发方式 |
| --- | --- | --- | --- |
| 工作记忆 | 当前 Raw 最近完整轮次 | 保持当前对话连续 | 每轮自动装配 |
| 情节记忆 | 当前 Raw 对话正文 + `.raw/记忆索引` | 找回当前对话较早回答 | 回答后自动索引，用户按回合开启查询 |
| 语义记忆 | `wiki/` 普通文件 | 保存用户确认的知识、决策和设定 | 现有“保存到文件”与 `wiki-memory` |
| 程序记忆 | Skill 包 | 规定任务怎么做 | 用户选择后在当前任务持续生效 |

Raw 仍是对话正文的唯一持久化真源。索引只导航，Wiki 只存用户要长期使用的知识，Skill 只存方法。

## 3. 统一合同

### 3.1 每轮都有短期上下文

1. 每次发送都调用现有 `buildCreativeContext()`，不再以 Skill、文件、MCP、媒体、Terminal 或记忆检索是否开启作为上下文开关。
2. 固定保留当前 user 消息，再从新到旧装入最多三个完整 user/assistant 轮次，最多七条消息。
3. 历史仍受现有 `24,000` token 上限和模型上下文容量约束；只淘汰完整旧轮次，不截断单条消息。
4. 失败、取消或内容过滤的 user/assistant 对继续按现有规则排除。
5. 显式能力只决定 Skill 和工具，不再决定对话历史。

### 3.2 Skill 在当前任务持续

1. 用户选中的具体 Skill 在后续轮次保持可见且继续装载，不在回答成功后自动清空。
2. 用户点击 Skill 标签的移除按钮或新建对话时结束该 Skill。不使用关键词、模型判断或隐藏超时猜测“任务已结束”。
3. 当前 user turn 记录本轮生效的 Skill 名称；重新打开对话时从最新 user turn 恢复，不创建第二份会话状态。
4. 旧 Raw 没有 Skill 字段时按“未激活”读取，不回写历史文件。
5. Skill 持续只保留业务方法和已声明的工具候选集；写入、删除、Terminal、MCP 和付费媒体仍执行现有安全、平台、连接和审批规则。
6. Skill 已删除、失效或当前平台不可用时显示真实错误并允许用户移除，不静默换成其他 Skill。

### 3.3 对话记忆开关与索引

右上角常驻两个独立按钮：`对话记忆` 和 `对话查询`。按钮始终可见；开启时显示绿点和亮色底，再次点击关闭。两个开关互不影响，状态属于当前对话；重开同一对话恢复原状态，新建对话默认同时开启，不继承上一对话。状态写入现有对话元数据，不写入每轮正文，不建立项目级开关。

按钮合同：

- `对话记忆`：新建对话默认开启；开启后允许本对话回答完成时自动建立索引；关闭后只停止后续自动记录，不删除已有 Raw 或索引。它记录的是 `.raw/记忆索引`，不是 `wiki/` 知识文件。
- `对话查询`：新建对话默认开启；开启后下一轮输入由程序自动预取一次 `memory_search`；关闭后下一轮不调用该功能。
- 两个按钮分别显示“已开启/已关闭”，不得用一个按钮状态推断另一个状态；状态变化不改变最近三轮短期上下文。
- 每次发送开始时锁定两个开关的快照；本轮生成、自动记录和工具白名单只使用该快照，发送途中切换只影响下一轮。

开启 `对话记忆` 后，`writeConversationMemoryIndex()` 与 `generateConversationMemorySummary()` 才作为回答收尾步骤执行：

```text
模型回答完成
  -> user + assistant 完整写入 Raw
  -> 回答在 UI 正常展示
  -> 自动生成 summary + keywords
  -> 程序校验结构
  -> 幂等更新该 assistant turn 的正链索引
```

1. 只有 `runMemoryChat()` 成功返回、Raw 已成功持久化且 `对话记忆` 已开启的 assistant turn 才自动索引。
2. 网络中断、用户停止、HTTP 失败、内容过滤和未完整回答不自动索引。
3. 索引是 Raw 派生导航；摘要或索引写入失败不得回滚、删除或改写已完成回答。
4. 自动索引不阻塞回答展示；消息右下角显示“正在记录对话”或“已记录对话”。
5. 自动记录失败时，原位置显示“未记录”，旁边保留“记录对话”按钮；用户点击后重试。
6. 重试仍使用 assistant turn ID 幂等 upsert，不得生成重复记录。
7. 重新打开对话时，只在该对话开启过 `对话记忆` 时检查已完成 assistant turn 与索引的差集，为遗漏项逐条补建；不开启时不补建。
8. 每条成功回答最多增加一次小型非流式摘要请求；复用现有 Provider 结构化输出和程序二次校验，不新建索引 Provider 或配置页。

原手动“写入 Wiki”按钮退役，索引动作统一命名为“记录对话”；`.raw/记忆索引` 不称为 Wiki。

### 3.4 当前对话原生记忆查询（对话查询开关）

`conversation_memory_query` 收口为 App 原生只读工具 `memory_search`：

```json
{
  "query": "分镜 Skill 测试用例",
  "limit": 5
}
```

1. 开启 `对话查询` 后，下一轮发送由运行时先用该 user 消息作为 query 自动调用一次 `memory_search`，读取当前对话索引及其关联 assistant 原文，再把结果交给模型；关闭时完全不调用。
2. **只查询当前对话的索引**，不跨对话查询；conversationId 由运行时自动提供，模型和用户参数都不能覆盖。
3. 用户未开启 `对话查询` 时，模型不得调用或间接触发 `memory_search`；最近三轮短期上下文仍按 24,000 token 合同提供。
4. 第一版复用现有 `queryConversationMemoryIndex`，只在摘要和关键词中打分；命中后才沿正链读取当前对话 Raw。
5. 同一 Raw 的多个命中只读一次，最多返回 `limit` 条原始 assistant 回答；没有命中时不得读取 Raw。
6. `对话查询` 开启后由程序保证调用一次；模型不得自行追加跨对话或第二套记忆查询。当前三轮已足够时，模型可以忽略空结果直接回答。
7. Wiki 或用户显式选择的项目文件是确定性事实源，优先级高于 `memory_search` 返回的历史回答；冲突时以显式文件为准。
8. 关闭“对话查询”只关闭历史索引检索，不删除 Raw、索引或最近三轮上下文；不建向量库、Embedding、独立数据库或第二套对话正文。

### 3.5 `jc-jiyi` 退役

- `jc-jiyi` 没有独立的创作方法，只是 App 内部索引的查询说明；其能力并入 `memory_search`。
- 从 Skill 选择器、绑定分支、提示文案和发行包中删除 `jc-jiyi`。
- 项目里已有的 `.raw/记忆索引` 不迁移、不重写，原生工具直接继续使用。

### 3.6 Wiki 与保存到文件

1. 不新增“沉淀到 Wiki”按钮。
2. 现有“保存到文件”继续保存用户选定的回答，用户选择 `wiki/` 时就是语义记忆沉淀。
3. 本阶段不把“保存到文件”改名为“沉淀到 Wiki”，因为它仍允许选择 Wiki 之外的目录。
4. `wiki-memory` 继续是 Wiki 的组织、查询、写入和检查方法；它复用普通文件工具，不接管 Raw、短期上下文或原生记忆索引。

## 4. 统一请求链

```text
用户消息
  + 最近三轮工作记忆
  + 当前持续 Skill（如有）
  + 本轮显式文件 / MCP / 媒体 / 3D / Terminal
  + 用户本轮开启“对话查询”后由运行时预取的 memory_search 结果（可选）
  -> 同一 runDirectChatCompletion Agent Loop
```

- `memory_search` 只有用户开启“对话查询”后才由运行时预取，不扩大项目写权限或外部能力。
- 未开启“对话查询”时，旧对话索引完全不进入模型请求；最近三轮短期上下文仍按 24,000 token 合同提供。
- 用户显式选择的 Wiki/项目文件优先于短期对话和 `memory_search` 的历史回答。
- Skill 是方法合同，不是对话历史的开关。
- 自动索引是 App 完成回答后的程序收尾，不是模型在主循环里自行决定的写工具。
- Wiki 与普通文件继续走现有文件插件，不恢复 Wiki Agent 或第二套模型循环。

## 5. TDD 测试矩阵

### T1：工作记忆与能力解耦

1. 未选择 Skill 或工具时，请求仍包含最近三个完整问答轮次和当前 user 消息。
2. 四个历史轮次只保留最新三个；超过 `24,000` tokens 时只删除完整旧轮次。
3. 有无显式能力得到相同的对话上下文，差异只在 Skill 规则和工具集。
4. 原“只回答当前用户消息，不要读取历史”的系统提示不再出现。

### T2：Skill 连续任务

1. 首轮选择 `skill-creator`，回答后 Skill 标签仍可见。
2. 第二轮只发送“那就测试一下”与测试内容，请求仍包含 `skill-creator` 完整规则、已声明工具和最近三轮。
3. 用户移除 Skill 后，下一轮不再加载它，但仍保留最近三轮。
4. 重新打开同一对话后恢复最新 user turn 记录的 Skill；旧 Raw 继续可读。
5. 新建对话不继承上一对话的 Skill，且“对话记忆”和“对话查询”均默认开启。

### T3：回答自动索引

1. 开启“对话记忆”后，成功回答写入 Raw 后自动调用一次摘要和一次幂等索引更新；关闭时不调用。
2. Raw 写入失败时不调用摘要或索引写入。
3. 摘要或索引写入失败时，已持久化回答保留，消息右下角显示“未记录”和“记录对话”按钮。
4. 点击“记录对话”重试仍使用同一 assistant turn ID，重复点击不产生重复索引。
5. 网络中断保存的不完整回答不自动索引，也不显示为已记录。
6. 重新打开对话时，仅对开启过“对话记忆”的对话补建缺失索引；不重复已有 turn，不扫描其他对话。
7. 原“写入 Wiki”操作和文案不再出现；成功状态统一为“已记录对话”。

### T4：当前对话 `memory_search`（对话查询开启后预取）

1. 普通对话默认不调用 `memory_search`；用户开启“对话查询”后下一轮发送必须由运行时预取一次，但不因此获得写工具。
2. **只查询当前对话的索引**，conversationId 由运行时自动传入，不接受跨对话查询。
3. 索引无命中时不读 Raw；同一 Raw 多条命中时 Raw 只读一次。
4. 孤链、越界路径和 conversation 标识不匹配的条目不返回。
5. 只返回限量命中原文与可复查来源，不注入全部对话历史；预取结果作为只读上下文交给模型。

### T5：退役与 UI 边界

1. `jc-jiyi` 不再出现在内置 Skill 目录、选择器、提示文案和发行门禁中。
2. `.raw/记忆索引` 旧文件不迁移、不删除，`memory_search` 可继续读取。
3. 不新增“沉淀到 Wiki”按钮；“保存到文件”保持现有任意合法 Markdown 目标能力和文案；对话索引动作只使用“记录对话”。
4. 对话框右上角常驻显示“对话记忆”和“对话查询”两个独立按钮；新建对话默认同时开启，开启态有绿点和亮色底，关闭态无绿点且不高亮。
5. 自动索引失败不阻止用户继续对话、切换对话或保存回答到文件；消息右下角显示“未记录”和“记录对话”重试按钮。

## 6. 实施顺序

1. 先写 T1 红灯，取消上下文与 `explicitCapabilitySelected` 的绑定。
2. 再写 T2 红灯，停止回答后清空 Skill，并在 Raw user turn 中保存最小 Skill 名称列表。
3. 写 T3 红灯，把现有手动索引回调接到“对话记忆”开启后的成功 Raw 写入后，补齐“未记录/记录对话”失败重试和重开差集测试。
4. 写 T4 红灯，将当前对话查询作为“对话查询”开启后的运行时预取接入现有请求链；不让模型自行决定是否跨对话检索。
5. 写 T5 红灯，退役 `jc-jiyi` 和手动“写入 Wiki”，保留“保存到文件”。
6. 运行定向测试、完整 focused、`vue-tsc -b`、格式检查和 `git diff --check`；然后再更新现行 SDD、`hot.md`、`log.md` 和来源索引为已实施。
7. 最后使用真实 Desktop/Web/Mobile 和至少一个云端、一个 Ollama/MLX Provider 验证连续 Skill、自动索引、当前对话手动召回和失败重试。

## 8. 不做

- 不新增“沉淀到 Wiki”按钮，不把任意目录的“保存到文件”错改名为 Wiki 专用动作。
- 不自动把每条回答写入 `wiki/`。
- 不自动选择、替换或结束 Skill。
- 不恢复 Wiki Agent、领域 Runtime、第二套 Agent Loop 或多 Skill 编排协议。
- 不新增向量库、Embedding、独立数据库、隐藏摘要 Store 或第二份对话正文。
- 不因索引成功声称 Wiki 已更新，不因自动测试声称真实平台已验收。

## 9. 完成定义

1. 不选任何能力的连续问答仍能看到最近三轮。
2. `skill-creator` 从草稿到测试的第二轮无需重选 Skill，且实际继续同一 Skill 工具流。
3. 开启“对话记忆”后，每条完成回答在 Raw 落盘后自动幂等建索引；失败不丢回答且显示“未记录/记录对话”可重试。
4. 用户开启“对话查询”后，下一轮由运行时预取原生 `memory_search`，模型可使用**当前对话**的更早已索引回答；关闭时完全不检索。
5. `jc-jiyi` 与手动”写入 Wiki”退役，旧 Raw 和索引无需迁移即可继续使用。
6. “保存到文件”与 `wiki-memory` 继续承担用户主动知识沉淀，未新增重复入口。
7. 定向测试、focused、TypeScript 和差异检查通过；真实 Provider 和三端结果分开记录，未执行不写成通过。
