# 通用记忆工作台本机 MLX 兼容服务接入 TDD

> 状态：已实施，真实模型协议验收通过
> 日期：2026-08-21
> 范围：Desktop 记忆工作台本地模型连接、模型列表与直连请求

## 1. 目标

让 Apple Silicon 用户把已经启动的 MLX OpenAI-compatible 服务接入记忆工作台，并复用现有模型选择、流式对话和工具调用链。

本次只负责连接本机服务，不负责安装 Python、下载模型、启动进程、管理缓存或更新 MLX。Web、Mobile、Intel Mac 和 Windows 的现有能力不变。

## 2. 根因与最小方案

旧 MLX 方案的问题不是推理协议，而是 App 内置模型下载、进程管理和约 500 行 Rust Runtime，只服务 Apple Silicon。该实现已按架构决策删除，Ollama 保留为外部运行时。

当前记忆对话已经统一发送 OpenAI 格式的 `/v1/chat/completions` 请求；`mlx_vlm server` 也提供同一协议。因此最小方案不是恢复旧 MLX Runtime，而是增加一个 Desktop-only 的本机 OpenAI-compatible 服务连接入口：

```text
mlx-vlm / LM Studio
  -> http://127.0.0.1:8081/v1/models
  -> 记忆工作台本地模型列表
  -> 现有 /v1/chat/completions、SSE、工具调用链
```

设置页显示“本机 MLX”，保留可调地址，默认 `http://127.0.0.1:8081`。连接时只读取 `/v1/models`；模型生命周期继续由用户使用的 MLX 工具管理。

## 3. 用户运行合同

首轮以 `orcarouter/Qwen3.8-27B-Uncensored-MLX` 的 6-bit 版本验收。Apple M1 Max、64GB 统一内存可以运行该档位；模型约 22GB，仍需给 macOS、KV Cache 和项目工具留出内存。首轮不使用约 27.5GB 的 8-bit，也不使用质量明显退化的 2-bit。

模型服务启动后必须满足：

```text
GET  http://127.0.0.1:8081/v1/models
POST http://127.0.0.1:8081/v1/chat/completions
```

默认上下文继续使用本地模型保守合同 `32K/4K`，不因为模型卡声明 `262K` 就直接扩大。只有真实长上下文验收和内存数据证明稳定后才调整。

该模型移除了大部分安全拒绝，不作为产品默认模型、不自动推荐、不向 Web/Mobile 暴露；用户主动连接后才进入本机模型列表。

## 4. 红灯测试

实施前先让以下合同在旧实现上失败：

1. 本机 MLX 连接器请求规范化后的 `${apiBase}/v1/models`，把有效 `data[].id` 保存为独立本地 Provider 模型。
2. 空模型 ID、非数组响应和非成功 HTTP 状态明确失败，不覆盖已经保存的 Ollama 或云端模型。
3. 选择 MLX 模型后，`resolveApiConfig()` 返回该本机地址、模型 ID 和本地 Provider，不要求 NewAPI Key。
4. 记忆对话仍使用现有 OpenAI 消息、SSE 和 `/v1/chat/completions`，不进入 Ollama `/api/chat` 分支。
5. Desktop 设置页显示地址输入和连接按钮；Web/Mobile DOM 不出现本机 MLX 入口。
6. Ollama 模型、云端模型和现有模型选择迁移测试保持通过。

## 5. 最小实施

1. 在现有 Provider 配置中恢复一个只表示外部 HTTP 服务的 `local-mlx` Provider；删除遗留的内置模型目录、隐藏模型和下载目录语义，不恢复旧 Runtime。
2. 增加一个与 `localOllamaRuntime.ts` 同级的最小连接函数，只调用 `/v1/models` 并保存模型列表。
3. `resolveApiConfig()` 为 `local-mlx` 返回用户保存的回环地址和占位 API Key，复用现有 OpenAI 请求链。
4. `agentStore` 把 MLX 模型与 Ollama、云端模型合并；模型 ID 冲突时以 Provider ID 区分选择来源。
5. Desktop 设置页增加一个地址输入和“连接”按钮；不增加下载、启动、停止、日志或进度 UI。

## 6. 禁入边界

- 不新增 Rust 命令、sidecar、Python 依赖或打包二进制。
- 不从 App 下载 Hugging Face 模型，不保存 Hugging Face Token。
- 不自动启动、停止或守护 `mlx_vlm server`。
- 不绑定单一模型仓库；任何满足 OpenAI-compatible 合同的本机 MLX 服务均可连接。
- 不把普通局域网或公网地址默认为本机模型；首版只接受 `localhost`、`127.0.0.1` 和 `::1`。
- 不声称所有 MLX 模型都支持视觉或工具调用；真实能力由模型与服务端决定，首轮分别验收文本和 Wiki 工具调用。
- 不修改 Web/Mobile 工具白名单、Gateway、同步协议或云端 Provider。

## 7. 验收

### 自动验证

1. 新增连接器、Provider 路由和 Desktop-only UI 合同测试先红后绿。
2. 运行 `apiConfig`、`providerConfig`、`memoryWorkbench` 相关定向测试。
3. 运行完整 `pnpm run test:focused`、`pnpm exec vue-tsc -b --pretty false` 和 `git diff --check`。
4. Web/Desktop 构建产物审计确认 Web 不包含可见的 MLX 设置入口，Desktop 的 Ollama 能力不变。

### 真实 Mac 验收

1. 在 Apple M1 Max 64GB 上启动 6-bit 服务，`curl http://127.0.0.1:8081/v1/models` 返回目标模型。
2. Desktop 点击“连接”，模型进入“本地模型”分组；不登录、不填写 NewAPI Key 也能发送“你好”。
3. 连续流式输出可停止，不产生重复正文；切回 Ollama 和云端模型后路由正确。
4. 记忆模式实际调用一次只读 Wiki 工具并得到结果；若模型工具调用格式不兼容，如实记录为模型能力限制，不在客户端增加猜测性修复。
5. 观察首次加载、32K 上下文对话和工具调用时的内存压力；没有真实验收前不得写成 262K 可用或 8-bit 稳定通过。

## 10. 最终界面合同与首次使用流程（2026-08-23）

### 10.1 功能设计逻辑

本机 MLX 入口只表示一个由用户自行管理的 OpenAI-compatible HTTP 服务，不表示模型下载器、模型目录管理器或进程管理器。设置页只提供：

- 服务地址输入，默认 `http://127.0.0.1:8081`；
- “连接 MLX”按钮；
- 连接状态和已识别模型数量。

连接成功后，App 请求 `${apiBase}/v1/models`，读取服务返回的 `data[].id`，保存为独立的 `local-mlx` Provider，并与 Ollama、云端模型合并。模型选择按 `Provider + model ID` 区分，避免同名模型互相覆盖。App 不读取用户模型目录，不下载 Hugging Face 文件，不保存 Token，也不启动、停止或守护 MLX 进程。

首版地址只接受 `http://localhost`、`http://127.0.0.1` 和 `http://[::1]` 回环地址；Web/Mobile 不显示本机 MLX 入口。连接后的请求继续复用现有 OpenAI `/v1/chat/completions`、SSE、工具调用和审批链。简单问答优先使用“快速”模式；需要 Wiki、项目文件或 Skill 时使用“记忆”模式。

### 10.2 用户第一次使用

1. 用户在系统外自行安装并启动任意满足 OpenAI-compatible 合同的 MLX 服务，模型下载、模型目录和 Python 环境由用户选择和管理。
2. 打开韭菜盒子 Desktop 的“设置”，找到“本机 MLX”。
3. 服务使用默认端口时无需修改地址；使用其它回环端口时，只填写完整服务地址，例如 `http://127.0.0.1:9000`。
4. 点击“连接 MLX”。App 只探测 `/v1/models`，成功后显示已识别模型数量；失败时保留原有模型和地址，不覆盖 Ollama 或云端配置。
5. 关闭设置，在顶部模型菜单的“本地模型”分组中选择刚识别的模型。
6. 先用快速模式发送一句短消息确认链路；需要项目知识时再切换记忆模式。服务重启、更换模型或更换端口后，回到设置重新连接即可。

### 10.3 用户不需要理解的内容

普通用户不需要在韭菜盒子里填写模型目录、模型仓库、API Key、Python 路径、启动命令或推理参数。出现连接失败时，唯一需要检查的是：外部 MLX 服务是否正在运行，以及填写的回环地址和端口是否与服务一致。
