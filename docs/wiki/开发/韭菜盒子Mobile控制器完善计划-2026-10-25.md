## 2. 根因：为什么始终控制不了

按 AGENTS §0 追溯，真实使用链路是"电脑开着韭菜盒子 → 手机打开 → 连上 → 选对话 → 发任务 → 看结果"。前四步就有结构性断点：

1. **每次重启都要重新配对。** `remote_bridge_start` 绑定 `0.0.0.0:0`（随机端口），地址 `local_ip:port` 写进配对 offer，手机凭证只存这个地址。电脑重启 App、重开桥或 DHCP 换 IP 后，手机拿旧地址必然连不上，配对页也没有改地址入口。信任本应锚定 Desktop Noise 公钥，却被绑在一个易变地址上。
2. **桥默认关闭，且不会自动恢复。** 只有设置页"开启"按钮会调用 `remote_bridge_start`，App 启动时不恢复。人不在电脑前就无法补开。
3. **只能控制电脑当前打开的那个对话。** `DesktopRemoteHost.assertCurrentSession` 拒绝非当前 Session（`SESSION_NOT_CURRENT`），手机无法选项目或对话。人不在电脑前时，"电脑上恰好开着对的对话"无法保证。
4. **出门就断。** 只有 LAN；Mini Relay 排在 G4。
5. **电脑睡眠/关窗即离线。** 无托盘驻留、无防睡眠（G5）。
6. **测试替身掩盖了 1–3。** Rust 端到端测试固定 `127.0.0.1` 与当前 Session，正好绕开以上全部断点。

V2 合同把"可靠同步"（G1/G2）排在"可达"（Relay/常驻，G4/G5）之前。协议是对的，但这个顺序让用户一个月里一次稳定使用都没有。**本计划把"连得上、选得到"提到最前面**，再在真实使用中完成 G1/G2 的正确性闸门。

**真机联调（2026-10-25，分支 `1025shouji-remote`，iPhone 13 Pro Max + 本机 Desktop dev）**：连续修掉四个真机才暴露的根因——
1. `18ea0221` iOS 自 09-29 起无法编译：`d343b08a` 把常量插在 `mobile_entry_point` 属性与 `run()` 之间，并引入未隔离的桌面专属 API。
2. `8f983244` 开着 Clash Verge TUN 时，默认出口是 `utun10`，配对码写成虚拟网卡地址，手机连接超时；改为只取物理网卡的私网 IPv4。
3. `025250b5` iOS capability 缺 `core:event:allow-listen`，手机订阅电脑推送被拒，页面停在「正在读取」，报错又被宽泛规则误翻成「相机权限被拒绝」；09-28「电脑执行了手机没反应」很可能同源。
4. `d17b81a0` 电脑还没打开对话时，手机已进入等待，却仍弹 `INVALID_CONTEXT` 红框；改为只显示等待提示。

已实测：扫码配对成功、手机连上 `192.168.0.26:56537`、电脑端代码改动后自动重启时桥自动开启且端口不变。

**真机实测（2026-10-25 21:35，同一分支，iPhone 13 Pro Max + 本机 Desktop dev）**：手机进入电脑当前对话（项目「1025全自动测试MiniMax」）并看到历史；手机发送「现在什么进度」，电脑收到并开始执行（加载 Skill `jc-manju-pipeline`、思考中），手机同步显示「电脑正在运行 · 正在执行」与停止按钮。同时暴露两个手机端显示问题：①运行中同一条用户消息显示两遍（官方会话快照里已有该轮，id 与电脑临时 `run.userTurn` 不同，手机只按 id 去重）；②只有工具过程、正文为空的助手轮次被画成空白气泡。**仍未实测**：审批、手动重启电脑端后免配对重连、换 IP 重连、切后台/断网恢复。

另：worktree 里 `src-tauri/resources/deepseek-harness/node_modules` 若是指向主目录的软链接，Tauri dev 复制资源时会跳过它，对话报「无法启动 MCP 进程: No such file or directory」；须用真实副本（APFS 下 `cp -cR` 克隆）。

真机闸门：配对一次 → 退出并重启 Desktop → 手机**不重新配对**即可连上；换一个 Wi-Fi 或 IP 后手动改地址仍可连。记录设备、版本、网络与结果。

### M3 异地

**M3a（零代码，先用起来）：Tailscale。** Mac 与 iPhone 装 Tailscale 并登录同一账号；M0 完成后，手机把电脑地址改成 Tailscale 主机名或 `100.x` 地址即可，Noise 端到端加密不变。这正是 [[架构/产品架构]] §3.2 里 vibetunnel 采用的"不自建中继"路线，适合你本人立即使用。产出：一页使用说明 + 一条蜂窝网络真机记录。

**M3a 实施状态（2026-10-25，源码与自动化）**：电脑上报的地址在局域网 IP 之后追加 Tailscale `100.64.0.0/10` 地址（按网段识别，macOS 上它是 `utunN`，按网卡名会被滤掉；Clash 的 `198.18.x` 不算）；手机配对页新增「编辑电脑地址」，手填地址不带端口时沿用配对端口。Rust 红→绿 2 条、界面 1 条。使用说明见 [[运维/手机在外控制电脑-Tailscale使用说明]]。**蜂窝网络真机验证未做。**

**M3b 实施方案（2026-10-25 用户确认：配对时带房间号与密钥，不用登录账号；先本地 TDD，部署前再问）**

用户反馈：让用户另装 Tailscale 是错误的产品设计；与 Codex 手机端一样，应由我们自己的中继让两端都只做出站连接，用户除了扫码配对什么都不用装。Tailscale 降为“已在用的人可选”。

- **房间**：Desktop 首次开启手机控制器时生成 `roomId`（128 位随机，hex）与 `secret`（256 位随机），存系统钥匙串，与 Noise 身份同级。中继只存 `sha256(secret)`，首个 Desktop 连接写入（房间号不可猜，先到先得即可）。
- **下发**：二维码 offer 增加 `relay: { url, roomId, secret }`；认证回包也附带同一 `relay`，已配对的手机在家连一次即可拿到，不必重扫。
- **连接**：Cloudflare Worker `api.jiucaihezi.studio/relay/v1/rooms/<roomId>/{desktop|mobile|data/<id>}`，`Authorization: Bearer <secret>`，Durable Object `RelayRoom` 一房一实例，Hibernation API。Desktop 常驻一条 `desktop` 控制连接；手机连 `mobile` 后中继给 Desktop 发 `{"type":"open","id"}`，Desktop 为它另开 `data/<id>`，中继把两条连接按原样转发二进制帧。Desktop 不在线时手机得到 503 `DESKTOP_OFFLINE`；密钥不符 403。
- **复用现有协议**：两端各做一个“本地隧道”——Desktop 把每条 `data` 连接接到本机 `127.0.0.1:<桥端口>`，手机在本机开临时端口接到 `mobile` 连接——Noise 握手、配对、认证与 M0–M2 全部业务一行不改；中继只见密文。
- **候选顺序**：上次成功的地址 → 其余局域网/Tailscale 地址 → 中继。心跳 `ping`/`pong` 由 Cloudflare 自动应答，不唤醒 DO。
- **未做**：部署（需用户同意）、蜂窝网络真机、撤销设备后轮换房间密钥（被撤销的手机仍过不了 Noise 设备认证）。

**M3b 实施状态（2026-10-25，源码与本地自动化）**：
- 中继：`gateway/src/relay-room.js`（`RelayRoom` DO + `handleRelay` 路由），`wrangler.toml` 新增 `relay/*` 路由、`RELAY_ROOM` 绑定与 `relay-v1` SQLite 迁移；`gateway/tests/relay.test.mjs` 8 条红→绿（密钥只存哈希、电脑离线 503、先到帧补发与双向转发、一端断另一端关、无主数据连接 404、控制连接顶替、房间 4 台上限与 1 MiB 帧上限、路由校验）。
- Rust：新增 `remote_relay.rs`（票据、出站 WebSocket、两端本地隧道，`tungstenite 0.26` + 已有 rustls/ring），电脑在钥匙串 `remote-bridge-relay-v1` 保管房间，开桥时常驻控制连接；offer 与认证回包带 `relay`；手机凭证存票据，候选最后加「relay」，配对取第一个完成 Noise 握手的地址。红→绿 8 条，含经测试中继的真实 Noise 认证连接与配对。
- **本地真实 Worker 验证**：`wrangler dev --local`（workerd 本地 DO）下，`real_relay_carries_bytes_between_phone_and_desktop`（`#[ignore]`）通过：desktop/mobile/data 三条 101，200 KB 往返完整，错误密钥 403。
- 手机：二维码解析接受并校验 `relay`，状态把「relay」显示为「云端中继」。
- **未做**：部署（等用户同意）、正式 `wrangler.toml` 的打包 dry-run（需先生成 `assets/`，部署脚本会做）、蜂窝网络真机、撤销设备后轮换房间密钥。

## 4. 不做

- 不在手机上运行 Agent、模型或 Skill；不镜像项目文件；不做远程桌面或终端复刻（V2 §12.2）。

- 不为 Mobile 删减 Desktop 任何现有能力；驻留、防睡眠与自动开桥都是可选新增。

## 5. 建议的第一个动作

从 M0 开始，按 TDD 先写三条红测：①重启后端口不变；②地址变更、公钥相同时可重连；③开过桥时启动自动开启。转绿后出一对 Desktop/iOS 包做 M0 真机验收，紧接着跑 M1。M0+M1+M3a 完成后，你本人即可在家里和外面控制电脑上的当前对话；M2 完成后可以任选对话。
