# 通用记忆工作台 Skill Agent 完整规则与渐进披露规范

> 日期：2026-08-29
> 状态：设计定稿，作为显式能力 Agent 的 Skill 专项规范
> 关联：[[通用记忆工作台显式能力Agent与统一任务协议TDD-2026-08-28]]、[[通用记忆工作台WikiAgent索引渐进读取与确定性事务规范-2026-08-29]]

## 1. 核心决定

Skill Agent 的唯一目标是：**用户明确选择具体 Skill 后，模型必须按该 Skill 的规则完成当前任务。**

```text
用户选择具体 Skill
  -> 程序解析并加载该 Skill 的完整 SKILL.md
  -> Skill 规则作为本轮高优先级执行合同注入模型
  -> 模型按 Skill 规则理解任务并决定是否调用已连接能力
  -> 程序执行工具并返回真实 Observation
  -> 模型继续处理，直到给出最终内容或可执行操作
```

Skill 不是普通参考资料，也不是模型可以自行决定是否采用的工具结果。
Wiki 是事实来源和导航，不是任务门禁；Wiki 为空、缺页或缺少 `index.md` 时，Skill 仍必须继续生效并完成可完成的任务。
单独选择具体 Skill 已足以启动本轮工作流；Skill 可以直接要求使用内置 Wiki、文件能力以及当前已连接的 MCP、媒体、3D 或 Terminal 能力，不需要重复使用 `@`。

一句话职责边界：**Skill 决定怎么做，能力 Agent 提供事实和动作，程序负责真实执行。**

## 2. 术语边界

### 2.1 Skill

Skill 是用户编写的方法包，定义任务的做法、格式和质量标准。Skill 不拥有项目文件、Wiki、MCP、Terminal、Provider 或会话。

### 2.2 Skill Agent

Skill Agent 是薄的执行协调层，负责：

- 绑定用户选中的具体 Skill；
- 将 Skill 规则注入模型；
- 为该 Skill 提供包内资源的安全读取范围；
- 让模型使用当前已连接的产品能力；
- 将真实工具结果继续交给模型；
- 保留最终答案和程序回执。

Skill Agent 不复制 Wiki Agent、File Agent 或 Direct Runtime 的执行器。

### 2.3 “受限资源读取”的准确含义

“受限”只表示**路径范围受限**：模型只能读取当前已选 Skill 包内的 `SKILL.md`、`references/`、`scripts/` 和 `assets/`，不能借此读取其他 Skill、系统目录或未授权项目文件。

它不表示规则被削弱，也不表示模型可以挑选规则：

- 已加载的 Skill 内容全部具有约束力；
- `SKILL.md` 始终完整加载；
- Skill 明确要求读取的资源，必须在最终输出前读取；
- 资源读取返回空值、缺失或错误时，必须把真实结果交给模型；
- 不得把未读取的资源说成已读取或已遵守。

## 3. Skill 内容合同

### 3.1 `SKILL.md` 是强制规则层

所有不可遗漏的内容必须放在 `SKILL.md`：

- 角色和任务目标；
- 工作步骤；
- 输出结构和格式；
- 必填字段；
- 禁止事项；
- 质量检查；
- 何时读取 references；
- 何时调用其他能力；
- 何时写入文件或 Wiki。

程序必须把完整正文注入本轮模型请求。不能只注入名称、描述、触发词或摘要。

### 3.2 `references/` 是 Skill 的渐进资料层

references 可以放模板、示例、图库、行业资料和详细规则。Skill 在 `SKILL.md` 中明确要求读取的 references 属于本任务必需资料；模型必须先读取，再按其内容输出。

为了避免上下文膨胀，不要求把所有示例和素材一次性塞入模型。**规则不能依赖模型可能永远不读取的隐藏文件；不能遗漏的规则必须回到 `SKILL.md`。**

### 3.3 `scripts/` 与 `assets/`

这些目录不是默认项目工具：

- 只有 Skill 明确要求时才读取或执行；
- 执行仍受当前已连接能力和平台权限约束；
- Skill 可以要求使用 MCP、Terminal 或文件能力，但不能突破路径安全和平台权限；
- 程序必须返回脚本或资源的真实成功、空值或失败结果。

## 4. 显式选择与绑定

### 4.1 只接受具体 Skill

```text
@jc-character-prompt     有效
@gpt-image-2-prompts     有效
@Skill                   无效
```

程序只使用用户从列表中选中的具体 Skill 名称，不根据自然语言猜测、不自动替换同名 Skill、不静默降级为其他 Skill。

### 4.2 选择后的硬绑定

用户选中 Skill 后：

1. 程序解析唯一的 Skill 身份和规范来源；
2. 加载完整 `SKILL.md`；
3. 将其作为本轮专属高优先级规则注入模型；
4. 不再让模型决定“是否加载这个 Skill”；
5. 不把 Skill 正文仅作为 `role=tool` 的普通回执；
6. 本轮模型必须按照该 Skill 的方法、格式和质量检查执行。

已绑定具体 Skill 后，程序不再向模型暴露通用 `skill` 加载器；Skill 正文和当前 Skill 包内资源由程序预先绑定。Web 端同样不提供 `skill` 工具，模型只能使用本轮已连接且可用的其他能力；Desktop 等支持动态 Skill 的平台也不得借此绕过已绑定 Skill 的边界。

用户任务决定要完成的目标，Skill 决定完成目标的方法。用户没有明确取消或更换 Skill 时，程序不能自行取消绑定。

## 5. 标准执行流程

### 5.1 首轮输入

首轮模型输入由以下部分组成：

```text
系统安全边界
+ 当前用户任务
+ 当前策略允许的短期上下文
+ 已选 Skill 的完整 SKILL.md
+ 已选 Skill 的资源清单
+ 当前已连接的能力 schema
```

不默认注入全 Wiki、全项目、全部 Skill、全部 MCP 或旧聊天记录。

### 5.2 模型与程序循环

```text
模型读取当前任务和完整 Skill 规则
  -> 按 Skill 当前步骤决定需要的读取或工具调用
  -> 程序执行调用
  -> 返回真实结果（成功、空、缺失或失败）
  -> 模型按 Skill 下一步骤继续决定调用
  -> Skill 流程完成后输出最终答案或程序操作
```

这是一个由 Skill 驱动的逐步执行过程，不以固定轮数作为成功标准。每一步工具调用都必须等待程序真实回执后才能进入下一步；没有下一步调用时直接展示模型结果。安全上限只用于防止失控，触顶时仍保留已经得到的答案和真实结果。

### 5.3 纯文本 Skill

如果 Skill 不需要外部资料或工具，直接用 `SKILL.md` 规则生成最终文本。程序不要求额外 JSON，也不把领域内容改写成通用协议。

### 5.4 需要资源的 Skill

如果 Skill 明确要求读取某个 references：

```text
模型提出 Skill 包内资源路径
  -> 程序校验路径属于当前 Skill 包
  -> 读取并返回真实内容
  -> 模型按资源内容和 Skill 当前步骤继续执行
```

资源读取失败不应伪造成功，也不应静默换读其他 Skill 的资料。

### 5.5 `@Wiki + @Skill` 的资料阶段

Skill 从第一轮就对模型可见，但在 Wiki 资料尚未收集完成前，模型只执行读取，不提前生成或写入最终内容：

```text
当前任务 + Wiki 根 index.md + 完整 SKILL.md
  -> 模型选择下一层 index.md 或目标文件
  -> 程序读取并返回真实内容
  -> 模型继续选择，直到资料足够或明确没有资料
  -> 模型按 Skill 规则处理最终资料
  -> 输出答案和必要操作
```

如果目标目录存在文件但没有 `index.md`，程序先返回该目录的基础清单（路径、文件夹/文件、格式、大小等），不自动读取全部正文；模型根据 Skill 和用户任务决定是否继续读取具体文件。没有继续读取指令时，直接基于现有事实返回结果，并向用户提示该目录未维护入口。

## 6. 与其他能力 Agent 的组合

### 6.1 `@Skill`

只使用具体 Skill。若 Skill 不要求外部资料或工具，直接按 Skill 输出；若 Skill 要求 Wiki、文件、MCP、媒体、3D 或 Terminal，程序直接提供当前已连接的对应能力，不要求用户重复 `@`。Skill 要求分步调用工具时，程序必须逐步执行：模型给出当前步骤指令，程序返回真实结果，模型再依据 Skill 进入下一步，直到 Skill 流程完成。

Web 端不注册、不展示也不执行通用 `skill` 工具；用户选择的具体 Skill 仍按完整 `SKILL.md` 执行。选中 Skill 的任务不得压缩或丢弃早期工具 Observation，后续步骤必须能看到此前真实回执。

### 6.2 `@Skill + @Wiki`

```text
Skill：规定创作或分析方法
Wiki Agent：沿 index.md 渐进提供真实事实
模型：用 Wiki 事实完成 Skill 规定的输出
程序：执行 Wiki 事务并返回回执
```

Skill 规则必须同时对 Wiki 读取阶段和最终综合阶段可见：

- Wiki ReadPlan 仍只使用 Wiki 的结构化协议；Skill 明确指定路径或资料时，程序直接按 Skill 指令读取；
- 最终综合必须遵守 Skill 的输出格式和质量规则；
- Wiki 缺页、空入口或读取失败作为真实 Observation 返回；
- 不因资料不完整而吞掉 Skill 生成的答案或合法变更计划。
- Wiki 只提供事实和导航，不得降低、替换或阻止 Skill 规则；Wiki 没有相关内容时，模型按 Skill 的无资料分支继续处理。

### 6.3 `@Skill + @文件`

Skill 规定如何处理文件内容，File Agent 负责读取、转换、写入和验证。内置文件能力可由 Skill 直接要求，不要求用户重复 `@文件`。

### 6.4 `@Skill + @MCP / @媒体 / @3D / @Terminal`

Skill 规定步骤和质量标准，对应能力 Agent 负责动作和真实结果。只要对应能力已连接，Skill 可以直接要求程序调用，不需要再次 `@`；未连接的外部能力必须返回真实缺少连接结果，不能伪造外部工具结果。

### 6.5 多 Skill

多个具体 Skill 可以同时选择，但程序必须把它们作为多个明确规则段注入模型，并保留名称边界。出现规则冲突时，模型必须指出冲突，不得静默拼接互相矛盾的输出标准。

## 7. 规则优先级

```text
系统安全与平台权限
  -> 用户当前任务目标
  -> 已选 Skill 的方法、格式和质量规则
  -> Wiki、文件、MCP、媒体或 3D 返回的事实
```

其中“用户任务目标”和“Skill 方法”是不同维度：用户说要做什么，Skill 规定怎么做。Wiki、文件、MCP、媒体或 3D 只提供事实和执行结果，不能覆盖 Skill 的方法、格式、必填项和禁止事项。用户明确要求改变 Skill 方法时，模型应说明偏离，而不是假称仍完全符合 Skill。

## 8. 失败与降级

以下情况必须把真实结果交给模型，不能直接吞掉任务：

- Skill reference 不存在；
- Skill reference 读取失败；
- Wiki 为空或缺页；
- Wiki 子目录缺少 `index.md` 但存在其他文件；
- 文件为空或格式转换失败；
- MCP 返回空值或错误；
- 某个工具调用失败；
- 资源重复读取或读取达到安全上限。

模型可以基于现有资料继续回答、采用 Skill 允许的降级方案或明确告知用户不足。

目录缺少 `index.md` 时，程序可以读取该目录的元数据清单作为观察结果，但不得因为入口缺失而阻止模型回答，也不得擅自把整个目录正文塞入上下文。

只有以下情况可以阻止副作用：

- 路径越界；
- 工具未连接、平台不支持或当前操作需要用户确认；
- 并发指纹变化；
- 用户取消；
- 磁盘写入失败；
- 无法恢复的事务错误。

无论工具失败还是 Skill 资料缺失，已经生成的用户可见答案都必须保留。

## 9. 程序执行边界

程序负责：

- 解析具体 Skill 和唯一来源；
- 注入完整 Skill 规则；
- 限制 Skill 资源路径；
- 校验工具白名单和参数 schema；
- 执行工具并回传真实 Observation；
- 执行 Wiki/File 等事务、回滚和验证；
- 独立显示程序状态卡。

程序不负责：

- 判断某条 Skill 规则是否“值得遵守”；
- 用摘要替代完整 `SKILL.md`；
- 让模型再次选择是否使用用户已选 Skill；
- 读取全部项目或全部 Skill 作为兜底；
- 因 Wiki 入口不完整而擅自扫描全部目录正文；
- 解析领域正文并替模型重写 Skill 结果；
- 把完整工具回执拼进最终正文。

## 10. 必须覆盖的回归测试

1. 选择具体 Skill 时，最终模型请求包含完整 `SKILL.md`，而不是只有名称或描述。
2. 未选择 Skill 时，模型请求不包含任何 Skill 正文。
3. Skill 明确要求的 references 可以通过当前 Skill 的 scoped path 读取。
4. 读取其他 Skill、系统目录或越界路径会被拒绝。
5. Skill reference 返回空值或失败时，真实 Observation 会回到模型，最终答案不会被程序吞掉。
6. `@Skill + @Wiki` 的 ReadPlan 和最终综合都能看到 Skill 规则。
7. 单独 `@Skill` 时，Skill 要求的 Wiki、文件、MCP、媒体、3D 或 Terminal 能力可以正常调用；未连接能力返回真实结果。
8. Skill 要求的固定输出字段、禁止事项和格式能在最终响应中保留。
9. 工具执行失败时不伪报成功，程序状态卡和模型答案独立显示。
10. Skill 来源为 `.agents/skills`、`public/skills` 或中心 Skill 时，界面展示内容与实际执行正文一致。
11. Wiki 子目录缺少 `index.md` 但存在文件时，程序返回基础文件清单，模型可选择继续读取或直接给出结果。
12. Skill 要求多步工具流程时，每一步都能收到真实回执并进入下一步，不能在第一步后提前结束。
13. Web 端工具定义和执行器均不包含通用 `skill`，动态调用得到明确的不支持结果。
14. 选中 Skill 的多步任务保留全部工具 Observation，早期步骤结果不会因历史压缩而丢失。

## 11. 禁止的过度设计

- 不为 Skill 再创建一套 Provider、SSE、文件服务或长期记忆系统；
- 不把所有 Skill 资源预加载进每一轮上下文；
- 不用大 JSON DSL 重写 Skill 的领域输出；
- 不让 Skill 使用未连接、平台不支持或未通过安全校验的能力；
- 不以固定循环轮数、Wiki 覆盖率或入口完整度吞掉模型答案；
- 不用另一个总控 Agent 覆盖 Wiki Agent、File Agent 或其他能力 Agent 的职责。

## 12. 最小实施顺序

1. 统一 `.agents/skills`、`public/skills` 和中心 Skill 的解析来源，建立“展示即执行”的单一正文。
2. 将已选 Skill 的完整 `SKILL.md` 注入专属系统规则，移除“伪造 Skill 工具回执作为规则”的路径。
3. 复用现有 `read`，增加当前 Skill 包内资源的 scoped 读取；不新增第二套文件服务。项目文件和 Skill 资源按路径命名空间分别校验。
4. 将 Skill 规则传入 Wiki Agent 的逐层 ReadPlan、缺少入口时的文件清单判断和最终综合请求；单独 `@Skill` 也允许 Skill 直接调用 Wiki。
5. 让统一执行器按 Skill 的工具步骤持续执行并回传真实 Observation，再增加上述回归测试，用真实 Skill 做一次 `@Skill`、`@Skill + @Wiki` 前向验收。

完成标准：**用户选中的 Skill 规则完整进入模型，模型需要的 Skill 资料可真实取回，模型输出遵守 Skill，程序只执行已授权能力并返回真实结果。**
