# 通用记忆工作台产品架构

> 更新：2026-09-25
> 现行依据：[[开发/通用记忆工作台单产品化分离SDD]]、2026-09-25 平台收缩决定（见第 3 节）

## 1. 唯一产品边界

本仓库只保留通用记忆工作台：**记忆工作台现在拥有的全部功能都保留；记忆工作台现在没有的功能全部迁出。**

归属判断按记忆入口的实际依赖闭包进行：从默认 `src/App.vue`、各平台入口、Gateway、同步服务、发布配置和门禁测试出发，直接或间接可达且维持现有能力所必需的代码、资源、配置、Skill 和服务都属于记忆工作台。模块名中出现 `Studio`、`OpenCode`、`creation` 或历史产品词，不能成为移动或删除依据。

OpenCode 产品、旧 Studio、文/武/道/创模式、电商、漫剧和制作工作台属于迁出范围。它们的 SDD 是历史与迁出依据，不再定义当前产品。

## 2. 当前能力闭包

- 项目中心、项目文件树、Harness 持久对话和完整项目文件能力。
- 项目内受限读写、附件、文档转换、站内预览、Markdown 阅读编辑。
- 标准 `.canvas` 项目地图、`.jccanvas` 创作画布、Desktop `.jcscene` 与 MP4 导出。
- 对话内图片、视频、音频生成及既有媒体任务链路。
- 登录、Provider、模型、用户 Skill、系统 Skill、MCP、审批和账号能力。
- Desktop、Web、Mobile 当前已经具备的平台差异能力。
- 文字云覆盖、Gateway、Web Production、桌面更新与移动端发布基础设施。

上述能力保留现有共享基础设施；旧产品专属代码已经迁出，分离门禁阻止其重新进入默认产品。

## 3. 平台边界

| 平台 | 目标边界（2026-09-25 起） |
| --- | --- |
| Desktop | **完整保留、只增不减**：完整记忆工作台、本机项目、项目工具、文档转换、用户 Skill/MCP、本地模型、`.jcscene` 和 FFmpeg MP4 导出 |
| Web | **仅下载、主页展示、教学与视频**；Web 端记忆工作台（“体验”）删除 |
| Mobile | 现有 App 冻结，不再作为独立工作台投入；目标形态是桌面 App 的控制器（选型待定） |

桌面端是唯一主产品，其能力不因平台收缩而减少：本次收缩不动任何桌面功能与代码。

> 本节于 2026-09-25 取代原“任何平台现有的记忆工作台功能都不能因分离减少”。收缩依据：Harness 只在 Desktop 进程内运行（`src/services/deepSeekHarness.ts` 持有 Session），Web 与 Mobile 无法复用，导致两端长期只能提供半残能力，继续维护只会分散精力。

2026-08-07 用户明确收缩网页工具边界：三端均移除 Jina `web_search` 与 `read_url`；Desktop 继续保留需审批的本机 Terminal，Web 与 Mobile 不补建替代网页工具。该决定不影响模型普通对话、项目文件、MCP、媒体或 3D 能力。

Windows 发布同时提供 NSIS 安装器和便携 ZIP。安装器声明 `downloadBootstrapper`，用于在目标机缺少 Microsoft Edge WebView2 Runtime 时给出可见安装引导；便携 ZIP 不携带运行时，仅适用于已安装 WebView2 的用户。

### 3.1 当前工作区布局

Desktop/Web 在打开资源预览或创作面板时采用“项目树｜主工作区｜右侧对话 Dock”：中间只承载文档预览或创作面板之一，对话仍复用原消息、输入框和滚动状态。没有资源预览或创作面板时，对话恢复为主区。

- 右侧对话 Dock 默认约 `360px`，可拖拽调整；完整态低于约 `220px` 时吸附为约 `56px` 的窄栏，展开后恢复最近一次完整宽度。
- 完整态宽度不足 `560px` 时，顶部对话、新建和模型入口切为图标，既有对话下拉菜单内容与操作不变。
- 文档大纲展开时保持粘性导航；折叠时退出 Grid 列，正文恢复单列全宽，只保留紧凑展开入口。
- 创作面板与资源预览互斥；切换前复用现有画布保存，同一关闭过程由同一个 Promise 承载，避免连续资源切换丢失后一次操作。
- 设置继续作为右侧悬浮抽屉，不进入主网格；窗口不足时先收起文件树，`940px` 以下沿用既有全屏/移动布局，不启用桌面 Dock 窄栏。

这套布局不引入通用 Dock 框架、不复制聊天状态，也不保留第二套创作宽度和拖拽状态。

### 3.2 移动端控制器：开源调研（2026-09-25）

结论：以 **Happy 为蓝本，但去掉 CLI 包装层** —— 桌面 Harness 已是进程内运行时，不需要包装命令行，只需要给 Session 加一条远程通道；配对/鉴权、审批 UI 与推送通知可直接借鉴。

| 项目 | 形态 | 可用 | 不适合 |
| --- | --- | --- | --- |
| [slopus/happy](https://github.com/slopus/happy)（MIT，23.9k★） | 手机 + Web + 桌面客户端；用 `happy claude` / `happy codex` 包装 CLI；端到端加密；权限批准推送通知；切回电脑按任意键 | **最接近目标形态**：session 列表 / 对话 / 审批 / 推送；分层（app / cli / agent / server）可借鉴 | 它的 session 由包装 CLI 产生，包装层对我们多余 |
| [amantus-ai/vibetunnel](https://github.com/amantus-ai/vibetunnel)（MIT，4.7k★） | 把终端会话代理到浏览器；菜单栏 App + 原生 iOS App；外网交给 Tailscale / ngrok / Cloudflare Tunnel / Pangolin | **不自建中继**的路子；会话录像（asciinema） | 形态是“终端投屏”，比控制器重；外部隧道需用户自行安装 |
| [omnara-ai/omnara](https://github.com/omnara-ai/omnara)（Apache-2.0，2.9k★） | 云端 agent 控制面（Go + Postgres + 沙箱/自有机器 + RBAC + Slack） | durable agent 状态、机器注册、通知与 RBAC 设计 | 方向相反：agent 跑在云端，与“本地工作台”定位冲突 |

下一步要定的第一个问题：**外网可达性** —— 自建中继（复用现有 Gateway 账号体系，`X-JC-Session`）还是复用 Tailscale 这类隧道。

## 4. 数据与同步

项目文件由 `ProjectFileService` 及平台适配器管理；Harness Session 是完整对话、工具轨迹、持久化与压缩的唯一运行时真相，对话选择器只保存标题、排序、工作区和 Session 映射。长期知识与正式作品仍以普通项目文件保存。

普通聊天不要求项目预先存在 `.raw`。文件树“建立改编 Wiki”按钮按需建立 Wiki 与 `.raw/文档|图片|视频|音频`；旧 `.raw/对话记录` 只作一次迁移来源，不再产生新对话双写或记忆索引。本期保留既有 `.raw/jc-media` 媒体保存链路，不把会话迁移扩张成媒体目录重构。

云端文字传输只有两个手动动作：

1. `上传并覆盖云端`：本地完整可同步文字快照覆盖云端；云端独有可同步文字删除。
2. `下载并覆盖本地`：云端完整可同步文字快照覆盖本地；本地独有可同步文字删除。

两个动作都不合并正文、不创建冲突副本、不自动双向同步。媒体、空目录、凭据、设置、Skill、MCP、Provider、Session 和 `.raw/.sync` 不比较、不传输、不删除。设置页只显示状态；项目中心是唯一操作入口。
