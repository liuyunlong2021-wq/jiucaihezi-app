# 服务器存储清理与 AnyDoc 生产切换

> 日期：2026-09-07
> 状态：已完成并验证

## 结论

- 本次治理的是服务器**磁盘空间**，不是运行内存；不应把两者混为一谈。
- 生产文档转换器已从 MarkItDown 切换到 `firecrawl-anydoc==0.2.3`；Web/Mobile 的 API、鉴权和操作方式不变。
- 扫描版/图片型 PDF 不属于 AnyDoc 的 OCR 能力，继续需要独立 GPU OCR 服务；不得将转换失败写成 OCR 成功。

## 已清理内容与成果

在确认不被运行容器使用后，清理了 Docker BuildKit 构建缓存、过期 NewAPI 日志、历史桌面更新包和过期生成输出。未删除运行中的容器、当前镜像、PostgreSQL bind mount、具名数据卷或生产配置。

| 项目 | 已验证结果 |
| --- | --- |
| Docker BuildKit 缓存 | 回收 `20.53 GB` |
| 首轮清理后根盘 | 已用由约 `69 GB` 降至 `34 GB`，可用由 `14 GB` 升至 `32 GB` |
| 日志、更新包和过期输出继续清理后 | 已用 `25 GB`，可用 `41 GB`，使用率 `38%` |
| `/opt/jiucaihezi/output` 历史输出 | 由约 `4.2 GB` 降至 `276 KB` |

### 输出目录的一天过期策略

已启用 `cleanup-jiucaihezi-output.timer`，每天 `08:00 CST` 清理 `/opt/jiucaihezi/output` 下超过 24 小时的文件。该策略只针对可再生成的输出，不能用于数据库、用户原件、服务配置或仍由任务引用的文件。

```bash
systemctl status cleanup-jiucaihezi-output.timer
systemctl list-timers cleanup-jiucaihezi-output.timer
```

### 后续正确清理顺序

1. 先用 `docker system df` 和 `df -h` 定位空间来源。
2. 清理前确认目标不属于运行容器、数据库 bind mount、具名数据卷或当前镜像。
3. 仅在确认无用后执行 `docker builder prune` 或按日期清理日志/产物。
4. 清理后立即复查 `df -h`、`docker system df` 和关键服务健康接口。

不要把 `docker system prune --volumes` 当作例行命令；它可能删除未来恢复或回滚需要的数据卷。

## 文档转换器切换

### 实现

- `document-converter` 保持 Python/FastAPI 外壳与 `POST /documents/markdown` 不变。
- 依赖由 MarkItDown 替换为 `firecrawl-anydoc==0.2.3`，与 Desktop 内置 AnyDoc 版本对齐。
- 转换使用 `anydoc.to_markdown()` 并置于 `asyncio.to_thread()`，避免阻塞 FastAPI 事件循环。
- 返回 `engine: "anydoc"`；20 MB 上传上限、Bearer API Key 校验、90 秒超时、临时目录清理与公开错误脱敏保持。

### 验收

1. 本地服务端单测 `5/5` 通过，Docker 镜像构建成功，容器内 `import anydoc` 成功。
2. staging 独立运行在 `127.0.0.1:8811`，真实 DOCX 返回 `status: "success"`、`engine: "anydoc"`。
3. 生产服务重建后仍绑定 `127.0.0.1:8810`；`GET /health` 返回 `{"status":"ok","service":"document-converter"}`。
4. 用户已在正式 Web 端上传租房协议 `.doc`，成功生成并打开 Markdown 副本。

现有 Nginx 与前端无需为本次切换修改；Web/Mobile 继续访问正式域名的 `/documents/markdown`，Desktop 仍优先使用本地 AnyDoc。

## 保留与回滚

- staging 使用 `document-converter-staging` 项目和 `8811` 端口，可保留作后续样本对照。
- 生产异常时先保留日志和当前容器状态，再回滚至切换前保留的 MarkItDown 镜像/Compose 配置；不得删除原件或 Markdown 副本。
- 后续应补充复杂 XLSX、PPTX、文本 PDF、加密/损坏文件和扫描 PDF 的真实样本矩阵；当前生产验收只覆盖成功 DOCX/Web 链路与健康检查。
