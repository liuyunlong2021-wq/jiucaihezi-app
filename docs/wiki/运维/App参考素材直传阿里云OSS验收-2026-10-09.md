## App 端到端验收

- 使用本机桌面预览版韭菜盒子 v2.2.25，在项目 `0910测试` 的创作面板放入一张合成参考图；选择 `特价渠道 MiniMax H3-768p`、图生视频、9:16、3 秒。
- 客户端通过 NewAPI 获取限对象、限时的 OSS 上传策略，再用原生 HTTP 将参考图直接上传 OSS；随后把私有对象的签名读取地址传给视频上游。此路径需要控制面经过 NewAPI，但素材字节不经过 ECS。
- 首次 App 尝试暴露了一个客户端问题：OSS 表单上传返回 HTTP 204，Tauri HTTP 桥接把空字符串作为 Response body，浏览器侧构造 `Response` 报错 `Response cannot have a body with the given status.`。按调用顺序，失败发生在视频上游请求之前。
- 修复位于 `src/utils/httpClient.ts`：HTTP 204、205、304 使用 null body；回归用例位于 `src/utils/__tests__/httpClient.test.ts`。本机预览包重建后重新执行一次生成，成功完成。
- 成片 `.raw/jc-media/视频/参考这张扁平插画_太阳缓慢向山后落下_天空颜色轻微渐变__dxwexg.mp4`，文件约 498 KiB，时长 3.0417 秒；在 App 预览中播放到 3/3 秒。
- 当时创作面板标价为 ¥0.08/秒，3 秒预估 ¥0.24；没有单独查询账户账单，实际扣费以 NewAPI 用量记录为准。

## 边界与后续开发

- 已验证的是**参考素材直传 OSS**。NewAPI 仍签发授权，App 仍把生成请求交给 NewAPI 转发；这是数据面直传，不是绕过 NewAPI 的账号、渠道和计费控制。
- 本次生成的 MP4 落在本机项目 `.raw/jc-media/视频/`，没有存到 OSS。生成结果存储/分发走 OSS 是另一项改造，不能从这次结果推断已经实现。
- `creation-temp/` 对象按一天生命周期自动过期；临时读取签名 URL 有效期约六小时。不要把该前缀当永久素材库。
- 后续发布客户端前，应在正式签名/公证的发行包中复测图生视频和至少一种图像任务；同时核对 NewAPI 用量记录、Bucket 临时对象及生命周期清理。若以后更换 OSS 区域或账号，重新核对 RAM 最小权限、私有读、生命周期、授权有效期与服务器时钟。
- 回滚材料保存在 `/root/jc-oss-switch-20261009T041511Z`；原媒体 Compose 文件仍保留。生产回滚应依照这次 `activate.sh` 备份执行，不要手工覆盖主 Compose 或删除备份。

## OSS 费用与资源包查询

阿里云控制台右上角 **费用 → 账单 → 账单详情**，选择产品 **对象存储 OSS**，月份 **2026-10**，按天或明细查看存储、外网流出流量、请求次数等计费项与应付金额。后付费账单存在出账延迟，不是每次上传即时扣款展示。[阿里云账单说明](https://help.aliyun.com/zh/user-center/bill-view)。

已购资源包的消耗与剩余额度：进入 **费用与成本 → 账户 → 资源包**，查看 OSS 存储包/下行流量包各自的剩余量与使用明细；账单中同时查看资源包抵扣量。存储包、下行流量包分别抵扣对应计费项，不应把余额扣款为零解释为没有用量。[资源包使用说明](https://www.alibabacloud.com/help/zh/user-center/offset-details-report)、[OSS 计费概述](https://help.aliyun.com/zh/oss/understanding-billing/)。

当前 OSS 用于参考素材：App 上传，供应商经公网读取参考图会产生 OSS 外网流出用量；生成成品仍由上游提供 URL，未统一存入 OSS。生成模型费用与 OSS 存储/流量/请求费用分别记账。实际当前消费金额尚未登录账单查询。
