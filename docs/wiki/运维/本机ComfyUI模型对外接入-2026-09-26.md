# 本机 ComfyUI 模型对外接入（jc- 前缀）

> 制定：2026-09-26 · 状态：**视频四个模型已端到端跑通；图片模型已按 2026-09-26 决定从创作面板与 NewAPI 撤下（服务器端保留）**
>
> 一句话：把本机 RTX 4090 上的 ComfyUI（经 `comfy-adapter`）接进 NewAPI，创作面板出现 4 个 `jc-` 开头的视频模型。

## 事实源

| 内容 | 唯一事实源 |
|---|---|
| 适配器代码与本机运行目录 | `comfy-adapter/`（本机 `D:\jiucaihezi-app\comfy-adapter`） |
| 模型 id、参数绑定、约束 | `comfy-adapter/workflows/*.meta.json` |
| 面板模型名、字段、路由 | `src/runtime/creation/creationModelRegistry.ts` |

| 对外合同自检 | `comfy-adapter/tools/verify_newapi_contract.py` |

## 链路

```text
创作面板 → NewAPI（鉴权/计费/渠道选择）
        → frps 容器 frps:8796（VPS，只绑在 new-api-new_new-api-network 容器内）
        → frpc（本机，kcp over UDP 7000）→ comfy-adapter :9000
        → ComfyUI :8188 → RTX 4090
```

⚠️ 适配器和 ComfyUI **必须跑在有 GPU 的那台 Windows 机器上**，VPS 只做中转。
隧道出口**不进宿主端口表**：`ss -ltnp` 在 VPS 上找不到 8796，只有同 Docker 网络的 NewAPI 能按容器名访问。
对公网只开放控制端口 **7000（TCP + UDP）**。

## 模型与命名

渠道里的公开模型名带 `jc-` 前缀，与创作面板下拉显示名一致；NewAPI 的模型映射把它换成适配器内部 id。

| 面板项 | 渠道公开模型名 | 适配器模型 id | 输入 |
|---|---|---|---|
| `jc-MiniMax H3 文生视频` | `jc-minimax-h3` | `minimax-h3` | 纯文字（显式禁止参考图） |
| `jc-MiniMax H3 首帧图生` | `jc-minimax-h3` | `minimax-h3` | 1 张首帧 |
| `jc-MiniMax H3 首尾帧` | `jc-minimax-h3` | `minimax-h3` | 2 张（顺序=首帧→尾帧） |
| `jc-MiniMax H3 参考生视频` | `jc-minimax-h3-ref2v` | `minimax-h3-ref2v` | 1~6 张参考图 + 比例 + 戏种 |

### 图片模型（`jc-qwen-image-2.1`）已撤下 —— 2026-09-26

图片模型在**创作面板**与 **NewAPI** 都已移除，**服务器端（`comfy-adapter` 模板、工作流、渠道映射）原样保留**：将来在另一台机器单独跑图片时，把注册表里那份规格接回来就能用，不用重做适配。

原因不是质量，而是**显存装不下两套栈**：H3 的权重（UNET 19.53GB + 32B CLIP + 多个 LoRA + 潜空间上采样）与 Qwen-Image 栈合计超过 48GB；而用户的真实用法是图片、视频交替，每次切换都要整栈重载，切换过程会把显存顶满、甚至卡死 ComfyUI。取舍记录见 `docs/wiki/log.md` 的 2026-09-26 条目。

对外文档保留在 `docs/wiki/运维/韭菜盒子本机ComfyUI图片模型API对外接入-2026-09-26.md`，接回去时无需重写。

后三个共用同一个适配器 model：同一份 H3 工作流靠「图填进哪个槽位」区分模式，面板侧用三个 `.slice` 入口把画布选图落到 `first_frame` / `last_frame` / `images`。

### 对外接口（与其它韭菜盒子模型一致）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/v1/images/generations` | 文生图（JSON）。适配器仍支持，但该模型已从 NewAPI 撤下，对外不再公开 |
| POST | `/v1/images/edits` | 图片编辑（multipart，字段 `image`）。同上，已撤下 |
| POST | `/v1/videos` | 视频提交，立即返回 `id`（任务插件通道下宿主会移除 legacy `task_id`，客户端请读 `id`） |
| GET | `/v1/videos/{task_id}` | 轮询，完成时带 `metadata.url` |
| GET | `/v1/videos/{task_id}/content` | 成片下载，支持 Range |

用户新做的画布「30秒文武双修.json」整体替换了 `minimax-h3-ref2v` 的模板；对外模型名、渠道映射、接口不变，换的是模板与参数面。

| 项 | 内容 |

| 新增模块 | SemanticBridge（节点 56/55/58）、ChunkFeedForward（54，chunks=2/seq=4096）、`easy cleanGpuUsed`（68）、`RunningHub Deepcleaner`（69，Purge Model，在输出路径上） |
| 参数面 | `prompt` / `seed` / `duration`（1~28 秒）/ `aspect_ratio` / `reference_images`（1~6 张）/ **`mode` 戏种（0 文戏、1 武戏）** |

三个语义变化（用户 2026-09-27 决定）：

1. **戏种改为面板开关**：`mode` 绑到新模板节点 65（`easy anythingIndexSwitch`）的 `index`，只切节点 47 的 LoRA 强度（文 0.5 / 武 1.0）。V3 是两个开关（64 管 lms LoRA、69 管首采 megapixels），`megapixels` 现在固定 0.4MP。旧 meta 的 `bind.mode → 64/69.index` 直接沿用会往 `Float` 和 `RunningHub Deepcleaner` 写非法输入，所以必须重绑。
2. **HIGH 不再拼细节增强词**：V3 的 HIGH prompt 走 `ConcatTextOfUtils(增强词 + 用户词)`，新图 7/14 都直接吃节点 28 —— 有意去掉，不要补回。
3. **时长上限 28 秒**：实测请求 30 秒会被算式补到 736 帧（≈30.7s），成片最后约 2 秒无效；28 秒 → 685 帧（≈28.54s）。适配器 `constraints.clamp.duration` 与面板 `max` 都设 28，超出的请求会被 clamp（已验：请求 30 → 归一化后 28）。
4. **四个 jc 视频模型统一 28 秒**：兄弟模板 `minimax-h3-video.meta.json` 的 `constraints.max_length` 从 501（≈20.9 秒）放到 685（28 秒），面板的文生 / 首帧图生 / 首尾帧三项同步，`JC_H3_DURATION_FIELD` 上限 15 → 28（四个模型共用）。那 501 是**适配器自设的运行时保护** —— 节点自身的 `length` 输入没有 max（只有 `min=5` / `step=17`），所以放大安全；`dry_run` 实测 `--duration 28` → `length: 672`（28.00s），不再被截断成 20.9 秒。

## 更换本机 H3 上采样模型（2026-09-30 实测）

这套 App 不读取浏览器里打开的 ComfyUI 画布：创作面板经 NewAPI、frpc、`comfy-adapter`，将适配器缓存的 API 工作流提交给本机 ComfyUI。改画布或只放权重文件不会改变 App 的工作流；仅替换权重无需重新部署 App / 云端。

1. 确认目标 `.safetensors` 完整放在 `D:\Comfy-Desktop\ComfyUI-Shared\models\latent_upscale_models\`。**使用磁盘上的完整文件名**，包括下载重名生成的 ` (1)`；不要按截图或网盘标题猜名称。可对照原权重检查 safetensors 键、形状及 dtype，并从 ComfyUI `GET /object_info/MiniMaxH3LearnedLatentUpscaleT8Advanced` 检查 `model_name` 和 `precision` 可选值。文件存在、静态检查通过都不等于显存和完整出片已验证。
2. 找到实际调用的适配器模型。`jc-minimax-h3-ref2v` 对应 `D:\jiucaihezi-app\comfy-adapter\workflows\minimax-h3-ref2v.json`，双采上采样为节点 `13`，只改 `inputs.model_name` 为精确文件名、`inputs.precision` 为目标精度；`scale_by`、连线和其他节点不动。`jc-minimax-h3` 的文生/首帧/首尾帧共用 `workflows/minimax-h3-video.json`，**当前模板没有此上采样节点**，不能仅替换字段就让这三个模式用上新模型。若改节点 ID/接线、外部参数或输出，还需检查相应 `.meta.json` 的 `bind`、`output_node` 和约束。
3. 检查 JSON 与差异，再用适配器环境执行 `D:\jiucaihezi-app\comfy-adapter\.venv\Scripts\python.exe D:\jiucaihezi-app\comfy-adapter\app.py --check`。先确认 ComfyUI `/queue` 没有运行/等待任务、适配器 `/health` 中 `tasks.active` 与 `inflight` 均为 0：适配器任务表只在内存，重启会使旧任务无法轮询。然后 `Stop-ScheduledTask -TaskName comfy-adapter`，等待 9000 端口释放，`Start-ScheduledTask -TaskName comfy-adapter`；确认 `http://127.0.0.1:9000/health` 的 `adapter` 与 `comfyui` 均为 `ok`。模板启动时加载，单改 JSON 不会热更新；只改已有模型选项通常不必重启 ComfyUI，新文件未出现在节点选项中时才重启 ComfyUI。
4. 从 App 提交**一笔**对应模式的测试并等待成片。用本机 `GET http://127.0.0.1:8188/history?max_items=10` 定位新 `prompt_id`，检查 `status.status_str=success`、上采样节点实际 `inputs.model_name`/`precision`、输出节点有视频，且 `execution_cached` 没有跳过上采样节点；同时在 `comfy-adapter/logs/adapter.log` 核对对应任务 `succeeded`。只看 `/health` 或 `app.py --check` 不足以证明模型真的参与生成。出现 `HTTP 500 do_request_failed / upstream error` 且适配器与 ComfyUI 都没有新任务时，先查 NewAPI / frpc 链路，不要直接归因于新权重。

本次实例：参考生模板节点 `13` 从 `minimax_h3_latent_upscaler_3d_fp16.safetensors` / `fp16` 切换为 `h3_upscaler_sharpness_2000steps_v0.1_fp32 (1).safetensors` / `fp32`，保持 `scale_by=1.5`。两个文件均为 322 个同键同形状张量，新文件为 F32；ComfyUI 历史任务 `97192b22-11ed-4d80-b58e-f20f7ced3052` 为 `success`，节点 `13` 输入确为新文件 / `fp32`，输出节点 `21` 产出视频；适配器任务 `task_20260930_5acc746a4569` 为 `succeeded`，耗时约 90 秒。这里验证的是**此参考生配置能够跑通**，不是其它三种模式或未来任意权重都兼容。

## 排障与坑

| 现象 | 原因 / 处理 |
|---|---|
| `model_price_error` | 模型未配价格。图片写 `ModelPrice`，视频写 `ModelBillingMode` + `ModelBillingExpr`，改完 `docker compose restart new-api` |
| `request blocked: port N is not allowed` | NewAPI 的 SSRF 端口白名单。查 `fetch_setting.allowed_ports`，**必须是字符串数组** |
| frpc 报 `proxy [comfy-adapter] already exists` | 有残留的旧 frpc 进程还挂着会话（本机 `Get-Process frpc` 查，全部停掉再重启计划任务） |
| 面板发的 `resolution` 打断请求 | 面板会残留别的模型的 `'720p'`/`'2k'`；适配器已丢弃非数值 `resolution` 并告警 |
| 单张参考图被忽略 | 面板单图发的是 `image` 而不是 `images`，适配器两个都收 |
| 文生视频被选图后静默变参考生 | 面板侧对该模型声明了「最多 0 张参考图」拦下 |
| 参考图 7 张以上跑不完 | 双采工作流会击穿 48GB 显存且无法 interrupt，适配器与面板都卡在 6 张 |
| 冷启动首张特别慢 | ComfyUI 刚起或刚跑过别的模型，首张多花 10~30s 加载权重；别频繁重启 |
| 出口 IP 看着不对 | 到 ipify 显示 `45.137.183.58`，到 VPS 的 UDP 出口是 `58.208.246.161` —— 不同目的地走不同出口，属正常；防火墙因此没写死来源 IP |
| 适配器 `/health` 503 或面板报「ComfyUI 不可达」 | **先看 8188 有没有监听**，多半是 ComfyUI 没跑。Comfy Desktop 的安装记录（`%APPDATA%\Comfy Desktop\installations.json`）`"portConflict": "auto"` 会在 8188 被占时**静默换到下一个空端口**（本次已实测漂到 8189），而适配器固定连 8188 → 必然连不上。根因修法是把该安装的「端口冲突」改成 `ask`（合法值只有 `ask`/`auto`，从 `app.asar` 源码确认），让它显式询问而不是静默漂移 |

| 面板报错但后台其实生成成功了，错误内容是适配器返回的 JSON | 适配器的**异步提交必须回 200**（`adp/api.py` 的 `_submit_task`）。NewAPI 只把 200 当中继成功，收到 202 会判为失败、把上游响应体塞进 `message` 丢回面板，所以看到的就是那个 `generation.task` JSON。提交体还要同时带 `id` 与 `task_id`。仓库里其它适配器（shanhai / boluo / xiaoyi / kik / zx-video）都是这个约定。 |
| 重启适配器后，刚出的任务查不到了 | 任务表**只在内存**。重启后 `/v1/videos/{id}` 与 `/v1/videos/{id}/content` 一律 404，而成片其实还躺在 `static/` 里（可直接用 `/files/<name>` 取）。所以重启前先确认没有在途任务；重启后旧任务无法回收，重跑即可。 |
| 改了 `workflows/*.meta.json` 却像没生效 | 模板在**进程启动时**加载并缓存。改完必须重启适配器（`Start-ScheduledTask -TaskName 'comfy-adapter'`），否则跑的还是旧绑定 —— 本次「比例选竖屏却出横屏」就是这么来的。 |
| 图片/视频交替调用后 ComfyUI 卡住、`/health` 探不通 | 两套权重在 48GB 显存里无法共存（H3 栈 ≈ UNET 19.5GB + 32B CLIP）。当前取舍是**本机只跑视频**；若日后要长期混跑，两条路：给适配器加「换模板前 `POST /free {"unload_models":true,"free_memory":true}`」，或让 ComfyUI 带 `--disable-smart-memory` 启动（主动把模型换出到内存，本机 63.9GB 内存够用）。注意**别用真跑一笔去验证接口合同** —— 那会触发换栈，反而把队列顶爆。 |

### 本机进程模型（别乱杀）

- 计划任务 `comfy-adapter` 拉起的适配器**天然是父 + 子两个 python 进程**，命令行完全相同，只有**子进程**持有 9000 监听。看到两个不要当残留去重杀，杀一个会把整对带走。
- `/health` 返回 **503 不代表适配器挂了**：它的语义是「适配器活着，但 ComfyUI 探不通」，body 里会带 `comfyui: unreachable` 与具体错误。
- 重启：`Start-ScheduledTask -TaskName 'comfy-adapter'`（隧道是 `comfy-frpc`）。计划任务**不会**自动拉起已退出的进程，State 会停在 `Ready`。

### Windows 侧操作坑（本次踩到）

- **`ssh host '...'` 里的双引号会被 PowerShell 吃掉**，远端 SQL 直接语法错误。可靠做法：把远端脚本/ SQL 写成文件，用 `Get-Content -Raw | ssh host bash -s` 喂进去。
- **管道的字符编码会破坏中文**：`Get-Content -Raw | ssh ...` 会把中文变成 `?`（写进数据库就是真损坏）。含中文的 SQL 一律 **base64 编码后传输**，远端 `base64 -d | bash -s`（或 `| psql`）。
- **管道还会带入 `CR`**：直接 `cat >` 会把密钥写成 50 字节。用 `base64 -d` 或显式去掉 `\r`。
- 传密钥后要**比对 sha256**，不要靠打印确认。

## 产物地址（`public_base_url`）为什么不用公网域名

适配器完成任务时会在任务响应里回一个 `metadata.url`。NewAPI 代理 `/v1/videos/{id}/content` 时会去拿这个地址，**而 NewAPI 跑在 Docker 容器里** —— 给它 `https://comfy.jiucaihezi.studio` 这种公网地址，等于绕一圈 Cloudflare 再回到隧道，还得额外配 DNS + nginx `/files/`。

所以 `public_base_url` 直接写成 **`http://frps:8796`**：NewAPI 在同一个 Docker 网络里、端口已在 SSRF 白名单内，直接可达。

代价：第三方客户端从任务响应里读到的 `metadata.url` 在他们的环境里不可用。对外接入合同本来就要求走 NewAPI 的 `GET /v1/videos/{task_id}/content`，不受影响；**如果以后真要让第三方直连产物**，再单独加 `comfy.jiucaihezi.studio` 的 DNS + nginx `/files/` 反代到 `http://frps:8796`，并把 `public_base_url` 改回公网地址。
