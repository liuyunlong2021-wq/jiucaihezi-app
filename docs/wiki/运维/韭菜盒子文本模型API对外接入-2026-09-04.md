# 韭菜盒子文本模型 API 对外接入文档

> 本文用于第三方 APP、网站和工具接入韭菜盒子 NewAPI 文本模型。  
> 接入方只需要使用韭菜盒子 API 地址和自己的 API Key，不需要了解任何上游渠道信息。

## 1. 接入信息

| 项目 | 内容 |
|---|---|
| Base URL | `https://api.jiucaihezi.studio` |
| 接口路径 | `POST /v1/chat/completions` |
| 完整地址 | `https://api.jiucaihezi.studio/v1/chat/completions` |
| 认证方式 | `Authorization: Bearer <YOUR_API_KEY>` |
| 接口格式 | OpenAI Chat Completions 兼容格式 |

请求头：

```http
Authorization: Bearer <YOUR_API_KEY>
Content-Type: application/json
```

`<YOUR_API_KEY>` 替换为用户在韭菜盒子 NewAPI 中创建的 API Key。

## 2. 模型名称

模型名称以韭菜盒子 NewAPI 当前“模型列表”中实际显示的名称为准。

第三方 APP 不应自行猜测或修改模型名，直接使用 NewAPI 返回的模型名称即可。

可以通过模型列表接口查询当前可用模型：

```http
GET https://api.jiucaihezi.studio/v1/models
Authorization: Bearer <YOUR_API_KEY>
```

示例：

```bash
curl --location 'https://api.jiucaihezi.studio/v1/models' \
  --header 'Authorization: Bearer <YOUR_API_KEY>'
```

典型响应：

```json
{
  "object": "list",
  "data": [
    {
      "id": "模型名称",
      "object": "model",
      "owned_by": "jiucaihezi"
    }
  ]
}
```

## 3. 非流式请求

### 请求

```bash
curl --location 'https://api.jiucaihezi.studio/v1/chat/completions' \
  --header 'Authorization: Bearer <YOUR_API_KEY>' \
  --header 'Content-Type: application/json' \
  --data '{
    "model": "YOUR_MODEL_NAME",
    "messages": [
      {
        "role": "system",
        "content": "你是一个专业、准确的助手。"
      },
      {
        "role": "user",
        "content": "请用一句话介绍韭菜盒子。"
      }
    ],
    "temperature": 0.7,
    "max_tokens": 1000,
    "stream": false
  }'
```

其中：

- `YOUR_MODEL_NAME` 替换为 `/v1/models` 返回的实际模型名。
- `messages` 至少包含一条 `user` 消息。
- `stream: false` 表示等待完整结果后一次性返回。

### 响应

```json
{
  "id": "chatcmpl-example",
  "object": "chat.completion",
  "created": 1750000000,
  "model": "YOUR_MODEL_NAME",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "韭菜盒子是一套兼容 OpenAI API 的模型中转服务。"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 20,
    "completion_tokens": 18,
    "total_tokens": 38
  }
}
```

读取模型回复时，使用：

```text
choices[0].message.content
```

## 4. 流式请求

流式请求适合聊天窗口、实时输出和需要降低首字延迟的 APP。

### 请求

```bash
curl --location 'https://api.jiucaihezi.studio/v1/chat/completions' \
  --header 'Authorization: Bearer <YOUR_API_KEY>' \
  --header 'Content-Type: application/json' \
  --no-buffer \
  --data '{
    "model": "YOUR_MODEL_NAME",
    "messages": [
      {
        "role": "user",
        "content": "请详细介绍一下韭菜盒子。"
      }
    ],
    "stream": true
  }'
```

### 流式响应

服务会返回多个 Server-Sent Events 数据块：

```text
data: {"id":"chatcmpl-example","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"role":"assistant","content":"韭菜"},"finish_reason":null}]}

data: {"id":"chatcmpl-example","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"content":"盒子"},"finish_reason":null}]}

data: {"id":"chatcmpl-example","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"content":"是一套 API 服务。"},"finish_reason":null}]}

data: [DONE]
```

第三方 APP 应：

1. 按行读取 `data:` 内容。
2. 忽略空行。
3. 解析 JSON 数据。
4. 依次拼接 `choices[0].delta.content`。
5. 收到 `data: [DONE]` 后结束本次请求。

## 5. 请求参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `model` | string | 是 | NewAPI 当前可用的模型名称 |
| `messages` | array | 是 | 对话消息列表 |
| `stream` | boolean | 否 | 是否启用流式输出，默认 `false` |
| `temperature` | number | 否 | 输出随机性，通常为 `0` 到 `2` |
| `max_tokens` | integer | 否 | 最大输出 Token 数 |
| `top_p` | number | 否 | 核采样参数，通常为 `0` 到 `1` |
| `stop` | string / array | 否 | 停止生成条件 |
| `presence_penalty` | number | 否 | 降低重复主题倾向 |
| `frequency_penalty` | number | 否 | 降低重复词语倾向 |
| `response_format` | object | 否 | 需要结构化 JSON 输出时使用 |
| `tools` | array | 否 | 模型支持时用于工具调用 |
| `tool_choice` | string / object | 否 | 控制工具调用方式 |

建议第三方 APP 先只使用以下最小字段：

```json
{
  "model": "YOUR_MODEL_NAME",
  "messages": [
    {
      "role": "user",
      "content": "你好"
    }
  ],
  "stream": false
}
```

确认基础调用成功后，再逐步增加其他参数。

## 6. 消息格式

### system 消息

用于设定助手身份和行为规则：

```json
{
  "role": "system",
  "content": "你是一个专业的中文助手。"
}
```

### user 消息

用于发送用户问题：

```json
{
  "role": "user",
  "content": "请总结下面这段文字。"
}
```

### assistant 消息

用于传入历史助手回复：

```json
{
  "role": "assistant",
  "content": "好的，请发送需要总结的内容。"
}
```

### 多轮对话

```json
{
  "model": "YOUR_MODEL_NAME",
  "messages": [
    {
      "role": "system",
      "content": "你是一个专业助手。"
    },
    {
      "role": "user",
      "content": "什么是 API？"
    },
    {
      "role": "assistant",
      "content": "API 是应用程序之间通信的一组接口。"
    },
    {
      "role": "user",
      "content": "请举一个实际例子。"
    }
  ]
}
```

## 7. 第三方 APP 配置方式

如果 APP 支持 OpenAI 兼容接口，填写：

```text
API Base URL: https://api.jiucaihezi.studio/v1
API Key: 你的韭菜盒子 API Key
Model: 从 /v1/models 获取的模型名称
```

如果 APP 要求填写不带 `/v1` 的根地址，则填写：

```text
https://api.jiucaihezi.studio
```

不要重复拼接路径。例如：

```text
正确：
https://api.jiucaihezi.studio/v1/chat/completions

错误：
https://api.jiucaihezi.studio/v1/v1/chat/completions
```

## 8. 错误处理

| HTTP 状态码或错误 | 原因 | 处理方式 |
|---|---|---|
| `401 Unauthorized` | API Key 缺失、错误或已失效 | 检查 `Authorization` 请求头 |
| `403 Forbidden` | 当前 Key 没有访问权限 | 检查 Key 权限和分组 |
| `400 Bad Request` | 请求格式或参数错误 | 检查 `model`、`messages` 和 JSON 格式 |
| `404 Not Found` | Base URL 或接口路径错误 | 检查是否重复或遗漏 `/v1` |
| `429 Too Many Requests` | 请求频率过高或并发过多 | 降低并发并按退避策略重试 |
| `model_not_found` | 模型名不存在或不可用 | 重新调用 `/v1/models` 获取模型名 |
| 余额不足 | API Key 对应账户余额不足 | 充值后重试 |
| `500` | 服务端内部错误 | 稍后重试，并保留请求 ID |
| `502` / `503` | 当前模型服务暂时不可用 | 稍后重试或更换可用模型 |
| `524` / timeout | 请求处理超时 | 延长客户端超时时间，避免立即重复提交 |

对于 `429`、`502`、`503` 和网络超时，建议采用有限次数重试，例如最多 2 到 3 次，并逐步增加等待时间。

对于 `400`、`401`、`403` 和 `model_not_found`，不要盲目重试，应先修正请求或配置。

## 9. 安全要求

- API Key 只能放在服务端环境变量或安全配置中。
- 不要把 API Key 写入前端 JavaScript、移动端公开包或 Git 仓库。
- 不要把 API Key 写入日志、截图或公开文档。
- 如果 API Key 泄露，应立即在 NewAPI 中禁用或删除并重新创建。
- 第三方 APP 不应把用户完整对话内容写入公开日志。
- 不要在同一个请求中重复发送多个认证头。

服务端环境变量示例：

```bash
export OPENAI_BASE_URL="https://api.jiucaihezi.studio/v1"
export OPENAI_API_KEY="<YOUR_API_KEY>"
```

## 10. 兼容范围

当前对外文本接口遵循 OpenAI Chat Completions 兼容格式：

```text
客户端
  -> https://api.jiucaihezi.studio/v1/chat/completions
  -> 韭菜盒子 NewAPI
  -> 当前配置的文本模型
```

模型名称、价格、分组、速率限制和可用性以韭菜盒子 NewAPI 当前配置为准。第三方 APP 不应把某个模型名、价格或分组写死为永久配置，建议启动时或定期读取 `/v1/models`。

图片接口和视频接口请分别使用对应的对外接入文档，不要把文本请求发送到 `/v1/images/*` 或 `/v1/videos`。
