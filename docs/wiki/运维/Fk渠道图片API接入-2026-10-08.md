## 接入方式

第三方调用合同另见 [[韭菜盒子Fk渠道图片API对外接入-2026-10-08]]；本页仅记录内部插件、渠道和上游转换。

复用现有 `fk` Task Plugin 和 Fk 渠道，不另建图片插件。插件 `0.2.0` 同时声明 `openai_video`、`openai_image`；NewAPI 按 `meta.models` 接受模型，插件 hook 再按模型 ID 分流图片和视频。

客户端请求 NewAPI `POST /v1/images/generations` 或 `POST /v1/images/edits`。插件在服务端转换为 Fanke `POST /api/open/v1/image/generate`，携带渠道 Bearer Key 和 `X-Public-Model-Ids: 1`；再以 Fanke 返回的 `jobId` 调用 `/api/open/v1/image/status?jobId=...` 轮询。成功后把 `resultUrls[]` 转成 OpenAI `data[].url`。NewAPI 主机在客户端请求期间轮询，不把 Fanke jobId 暴露给客户端。

FK 插件 `openai_image.decodeRequest` 同时接受 JSON 与 multipart：JSON 中的 HTTPS 参考图通过 `imageUrls` 转发，multipart 文件则通过插件文件引用作为重复 `images` 字段转发。Fanke 没有 `/v1/images/edits` 上游端点；插件负责将 NewAPI edits 请求翻译到它的 generate API。

待客户端构建发布后，App 的本地参考图图生图走 JSON 路径：App 先向 NewAPI 申请私有 OSS 上传授权，再由 App 原生 HTTP 把图片字节直传 OSS；随后把短期签名 HTTPS 地址放进 `imageUrls`，向 NewAPI 发 JSON `/v1/images/edits`。这样 NewAPI/ECS 与 FK 插件不再中转本地图片字节。第三方仍可按本页后文使用 multipart。

## NewAPI 渠道配置

1. 上传并启用 `newapi-plugins/fk.plugin.js`，版本 `0.2.0`，插件 key 仍为 `fk`。
2. 编辑现有 type 61 Task Plugin 渠道，确认绑定 `fk`。Base URL 推荐 `https://ai.fanke2026.xyz`；插件也接受 `https://ai.fanke2026.xyz/api/open/v1`。
3. 渠道 Key 使用 Fanke 账号 API Key。模型目录/图片生成请求附带 `X-Public-Model-Ids: 1`，调用方无需另填此头。

## 当前开放图片模型

仅保留映射表中的 6 个模型。GPT 系列支持 1K/2K/4K、最多 10 张参考图；Banana 型号支持 1K/2K/4K、最多 8 张参考图。

支持比例：`auto`、`1:1`、`9:16`、`16:9`、`4:3`、`3:4`、`3:2`、`2:3`、`5:4`、`4:5`、`21:9`。`imageSize` 使用 `1K` / `2K` / `4K`，不要传 `resolution` 当供应商字段；固定画质型号不传画质字段。

## 任务与结果处理

- 生成提交必须保存 Fanke `jobId`。处理中状态 `submitted` 按 3 秒间隔查询；NewAPI 插件在服务端完成轮询。
- Fanke 返回 `status=success` 后，还要检查 `resultAvailable=true` 和非空 `resultUrls`。插件将这些链接转换成 OpenAI 图片响应；结果链接需保留查询签名并尽快下载。
- `n` 和 `response_format` 不改变 Fanke 行为；当前每次生成按实际结果张数结算。不要在超时后盲目重提，先用已有 jobId 查询。
- 用量字段为 `image_count`；视频已有 `seconds`、`seconds_480p`、`seconds_720p` 字段保持不变。新旧模型价格表达式分别按各自 usage field 配置。

按模型设置 NewAPI 定价表达式：GPT 四款使用 `tier("base", u("image_count") * 0.08)`；Banana 2 使用 `tier("base", u("image_count") * 0.2)`；Banana Pro 使用 `tier("base", u("image_count") * 0.3)`。
