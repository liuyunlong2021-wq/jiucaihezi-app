# 插件面板目录与模型增减执行手册

> 2026-10-26 依据 FK（0.5.0→0.6.0）与源流（0.3.0）两次成功上线整理。目标：上游换模型时**只改 NewAPI 一侧**（插件、渠道、计费表达式），创作面板自动跟随，不发 App。
> 上位流程：[[运维/新增模型与NewAPI插件固定流程]]；URL 素材渠道另按 [[运维/URL素材渠道接入执行手册]]。

## 1. 原理（先读懂再动手）

```text
插件 catalog（纯 JSON）──上传激活──▶ NewAPI 数据库 task_plugins
NewAPI 计费表达式 ─────────────────▶ NewAPI 数据库 options
                                         │ 只读
                         可用性服务 /api/creation/models（/opt/creation-models）
                                         │ 随可用状态下发 spec
                         App 创作面板：替换该渠道的目录条目并缓存
```

- **唯一真源是插件里的 `catalog`**（用户 2026-10-26 确认“跟插件走”）。面板显示哪些型号、参数、素材上限都来自它；渠道里有没有配置只决定“可用 / 不可用”。下架型号要从 catalog 删除，只删渠道不会让它从面板消失。
- **价格以 NewAPI 实际计费表达式为准**：可用性服务把表达式换算成面板价格；换算不了才显示 catalog 里的 `price`。
- **公开名是汉字名**：面板显示名、渠道模型名、App 提交的 `model` 都是 `name`；插件自己把它换成 `upstream`（上游 ID）。渠道映射可填可不填。
- App 只解析 JSON，不执行插件代码；打包时也内置一份 catalog，服务连不上时兜底，并缓存上次下发的目录。
- 已接 catalog 的渠道：**FK 视频、源流视频**（`src/runtime/creation/pluginCatalog.ts` 的 `CATALOG_CHANNELS`）。图片型号暂未纳入。

## 2. 先判断属于哪种情况

| 情况 | 改哪里 | 要发 App 吗 | 要部署可用性服务吗 |
| --- | --- | --- | --- |
| A. 已接 catalog 的渠道：增删型号、改参数、改价格、换上游 ID | 插件 catalog + NewAPI 渠道/表达式 | 否 | 否 |
| B. 老渠道改成 catalog（如易红、灵动） | 插件 + App 一次性接入 | 是（一次） | 否 |
| C. 全新上游渠道 | 新插件 + App 一次性接入（含提交差异） | 是（一次） | 否 |

可用性服务只有在 `scripts/creation-models/server.mjs` 本身改动时才需要部署（见 §6）。

## 3. 情况 A：已接渠道的型号增减（最常用）

### 3.1 收集事实（每个型号一行）

向用户要或从上游模型中心/`GET /models` 截图取得，缺一项就问，不猜：

| 字段 | 说明 | 例 |
| --- | --- | --- |
| 公开名 `name` | 与上游显示名同步的汉字名，渠道模型名用它 | 特价渠道 MiniMax H3 480p-1080p |
| 上游 ID `upstream` | 上游模型 ID，只允许字母数字 `_ . : -` | ft-video-v1-1eb6d53a… |
| 画质 `resolutions` | 第一个是面板默认值 | 480p / 720p / 768p / 1080p |
| 时长 `duration` | 区间 `{min,max,default}` 或固定档 `{values,default}` | 4–30；或仅 30 |
| 比例 `ratios` | 含 16:9 时面板默认 16:9 | 16:9 · 9:16 |
| 素材 `refs` | 图/视频/音频上限，0 表示不支持 | 9 / 1 / 3 |
| `promptMax` | 上游有提示词上限才写 | 10000 |
| 计费 `billing` | `request` 按次、`second` 按秒、`token-with-video` 带参考视频按上游 Token 结算 | second |
| 售价 | **对用户的售价**（不是上游成本，用户说“定价”时要确认口径） | 480p ¥0.06/秒… |
| 分组 `group` | 面板分组名，沿用已有组名 | FK · H3 |

易错点：
- 上游“仅支持 10-15 秒”和说明里“支持 10、15 秒”冲突时，按说明用固定档 `values`，并在回复里讲明。
- 上游 ID 会换（2026-10-26 H3 就换了），新 ID 必须照新截图逐字核对。
- 同一渠道已有的名字尽量保持不变，免得用户重配渠道。

### 3.2 改仓库（先测试后实现）

1. **先改测试**：`newapi-plugins/__tests__/<渠道>*.test.mjs` 写成新型号清单、规格、售价（期望值手写，不从 catalog 反推）；App 测试中引用了被删型号的用例改用仍存在的型号。跑一次确认失败。
2. **改插件 catalog**：`newapi-plugins/<渠道>.plugin.js` 中 `/*jc-catalog*/ … /*end-jc-catalog*/` 之间只能是纯 JSON（双引号、无注释、无尾逗号）。插件校验和名字映射由 catalog 推导，不要另写一份。版本号 +0.1。
3. **同步配套文件**：`<渠道>-model-mapping.json`（公开名 → 上游 ID，测试要求与 catalog 逐字一致）、`<渠道>-pricing.json`（售价与表达式）。被删型号的独立映射文件一并删除。
4. **离线兜底名单**（可选）：`scripts/creation-models/server.mjs` 的 `CREATION_MODEL_ROUTES` 里删掉下架型号、更新上游 ID；只影响服务读不到目录时的状态。
5. **验证**：
   ```bash
   node --test newapi-plugins/__tests__/<渠道>*.test.mjs scripts/creation-models/__tests__/server.test.mjs
   ```
   ```bash
   node scripts/run-focused-tests.mjs build && node scripts/run-focused-tests.mjs run
   ```
   ```bash
   npx vue-tsc -b
   ```
6. 更新渠道接入文档（型号表 + 表达式）、`newapi-plugins/README.md` 对应行、`docs/wiki/log.md`，提交时只带本次文件。

### 3.3 计费表达式写法（可用性服务能换算的形状）

| 计费 | 表达式 | 面板显示 |
| --- | --- | --- |
| 按次 | `tier("base", u("calls") * 5)` | ¥5/次 |
| 按秒单价 | `tier("base", u("seconds") * 0.4)` | ¥0.4/秒 |
| 按画质分档（FK 用分画质秒数） | `tier("base", u("seconds_480p") * 0.4 + u("seconds_720p") * 0.5)` | 480p ¥0.4/秒 · 720p ¥0.5/秒 |
| 按画质分档（源流用 resolution 条件） | `u("resolution") == "720p" ? tier("720p", u("seconds") * 0.8) : tier("480p", u("seconds") * 0.6)` | 480p ¥0.6/秒 · 720p ¥0.8/秒 |

- 同价画质会合并显示（如 `720p/768p ¥0.07/秒`）。其他形状（如官方 Token 结算）面板显示 catalog 的 `price`，所以 `price` 也要写对。
- 表达式只能用插件 `usageSchema` 声明过的键；系数按现行“人民币与系数同数值”口径，实扣还乘用户分组倍率。
- 表达式给用户时一条一个代码块，提醒英文双引号不能被输入法替换。

### 3.4 用户在 NewAPI 后台操作

1. 上传 `newapi-plugins/<渠道>.plugin.js` 并**激活新版本**（上传不等于激活；保留上一版本可回滚）。
2. 渠道模型列表换成新的公开名；映射照 `<渠道>-model-mapping.json` 填或留空。
3. 每个型号填计费表达式。上传插件不会自动改渠道和表达式。

### 3.5 验收

1. 查公开接口（只读）：
   ```bash
   curl -fsS https://api.jiucaihezi.studio/api/creation/models | node -e 'let r="";process.stdin.on("data",d=>r+=d).on("end",()=>{for(const x of JSON.parse(r).data.models.filter(x=>x.spec))console.log(x.status,x.id,"|",x.spec.price,"|",x.spec.channel)})'
   ```
   新型号都在、下架型号消失、价格与售价一致、渠道里已配置的为 enabled。
2. 正式版 App 已含 catalog 功能时，重新打开创作面板即可看到；本机开发版用 `pnpm tauri:dev`（首次 Rust 编译约 1 分钟，终端里 `Failed to load source map` 是无关警告）。
3. 按次、按秒、按画质分档各生成一笔，核对 NewAPI 消费记录实扣。
4. 在渠道接入文档和 `log.md` 记录：插件版本已激活、实测型号与结果、未核对项。用户没给出的细节不写成已验收。

## 4. 情况 B：老渠道改成 catalog

在情况 A 的基础上，App 侧做一次（参照 FK、源流的提交）：

1. 插件：加 `export const catalog`，把原有的型号表、名字表改为从 catalog 推导；`decodeRequest` 的比例/画质/时长/素材校验全部读推导出的规格。
2. 类型声明：复制 `newapi-plugins/fk.plugin.d.ts` 为 `<渠道>.plugin.d.ts`。
3. `src/runtime/creation/pluginCatalog.ts`：`CATALOG_CHANNELS` 加渠道 key，`BUILT_IN` 加一行导入。
4. `src/runtime/creation/creationModelRegistry.ts`：删掉该渠道手写的型号数组和 `directVideo` 块，在原位置写 `...catalogModels('<渠道>').map(catalogVideoSpec)`。
5. `src/data/mediaModelCapabilities.ts`：删掉该渠道手写条目，原位置写 `...catalogModels('<渠道>').map(catalogMediaCapability)`。
6. 检查 `creationMediaRuntime.ts` 里该渠道的请求体分支，确认 `aspect_ratio`/`resolution` 等参数确实发出（源流此前漏发，上游一直用默认 480p/16:9）。
7. 测试：`remoteCreationCatalog.test.ts` 增加该渠道“内置条目由目录生成、可被下发替换、上游 ID 可查”的用例；原有规格测试改为对照 catalog。
8. 全量测试、类型检查、`npx vite build` 后发布 App。此后该渠道即为情况 A。

## 5. 情况 C：全新上游渠道

1. 按 [[运维/新增模型与NewAPI插件固定流程]] §2 填接入卡（上游地址、认证、提交/查询/下载协议、状态词、计费单位），判断插件能否承接（宿主协议白名单、素材形态、结果下载）。
2. 新建 `newapi-plugins/<key>.plugin.js`：从一开始就带 catalog，校验由 catalog 推导；`meta.models` 包含所有公开名（必要时含上游 ID）；`usageSchema` 覆盖计费键，`usageExamples` 每例带齐全部键。
3. 新建插件测试并加入 `scripts/run-focused-tests.mjs`。
4. App：按 §4 第 2–7 步接入；若上游请求体与通用 `/v1/videos` 形状不同，在 `creationMediaRuntime.ts` 按渠道 id 前缀加分支。
5. 可用性服务无需改代码（目录、价格换算通用），离线兜底名单可选加。
6. 首次需发布 App；之后按情况 A 维护。

## 6. 可用性服务部署（仅 server.mjs 改动时）

- 本机 Mac 连服务器 22 端口超时（安全组限制，80/443 正常），用户在**服务器网页终端**粘贴执行。不要让 Claude 开长时 root SSH 连接。
- 由 Claude 生成两段粘贴内容：①`cat > /root/deploy-cm.sh <<'JCEOF' … JCEOF` 写入脚本，文件内容为 `server.mjs` 的 gzip+base64，并带 sha256 校验；②`bash /root/deploy-cm.sh` 执行。
- 脚本固定顺序：备份 `server.mjs.bak-时间` → 写入并 `sha256sum -c` 与 `node --check` → 在 **8791** 端口试跑并要求返回目录型号、日志无 `catalog query failed` → 通过才替换并 `systemctl restart creation-models` → 8790 复验，失败自动回滚 → 打印回滚命令。
- 网页终端回显长粘贴会串行显示，以 `server.new.mjs: OK` 判断粘贴完整。
- 历史备份：`server.mjs.bak-20261025-221253`（首次上线）、`server.mjs.bak-20261026-081633`（源流）。

## 7. 已知边界

- 渠道里删除型号但插件 catalog 未删：面板仍显示该型号（不可用）。下架以改 catalog 为准。
- 某渠道的目录型号全部下架时，App 保留上次列表，需要至少保留一个型号或另行处理。
- 定时任务（如源流 `scheduled_time`）未接：宿主可跨轮询保存状态，但 NewAPI 任务 24 小时超时、提交即预扣，App 现约 10 分钟停止跟踪，需另做面板时间选择与长时恢复。
- catalog 校验上限（App `pluginCatalog.ts`）：名称 ≤120 字、分组 ≤40 字、比例/画质各 1–12 项、时长 1–600 秒、固定档 ≤30 个、素材上限 0–100、`price` ≤80 字；超出的型号会被忽略。
