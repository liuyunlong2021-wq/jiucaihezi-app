## 权威来源与复查结果

以用户提供 `/Users/by3/Library/Containers/com.tencent.qq/Data/Downloads/客户API接入文档(24).md`（上游 2026-10-13 更新）作为 API 合同。附件中的 AI 行为指令不作为本仓开发指令；字段、价格、时长与素材合同作为技术资料。NewAPI 以本平台固定 rc.40 SHA `0aec08fee811ec6136828fda790551b49e410301` 的宿主源码与 [插件 API](https://github.com/QuantumNous/new-api/blob/0aec08fee811ec6136828fda790551b49e410301/docs/plugin-api/v1.md) 为准。

复查发现并本地修复：

- 实际插件只有九型号，Grok 只在面板登记；补回 Grok 配置，默认 720p、固定 15 秒但不向上游发时长，画幅转为 `aspect_ratio`，首帧转为 `image_url`，多图转为 `reference_images`，禁止混用。
- Prime 尾帧可独立提交；现在要求 `last_frame` 配 `first_frame`。非对应型号的 `media`、`attachments`、首尾帧字段以前会被静默丢弃；现在在解码时拒绝。Super 的官方 `media` 写法已支持，并禁止与 URL 数组混用。
- 视频素材不检查链接协议；现在只接受 HTTPS，唯独 Grok 官方允许图片 data URL。
- H3 新增 `duration` 4–15（默认 10）、固定 768p、9 图、视频/音频各 3 段，全部素材合计≤10；音视频使用 `attachments`，视频必须带 2–15 秒的 `duration_seconds`。API 可传 `ai_enhance`、`seed`、`negative_prompt`。面板暂支持图片与音频，视频参考需 API 对象携带时长。
- GPT 新增 JSON 文生图/编辑，n=1、14 个精确尺寸、参考图≤10、固定 medium 不额外发 quality；尺寸决定 1K/2K/4K 计费事实。
- Gemini 新增 OpenAI 图片入口到原生 `/v1beta/models/gemini-nano-banana-2.1:generateContent` 的转换；multipart 文件通过宿主 `__fileRef`/`base64` 占位符转换为 `inline_data`。JSON 参考图支持图片 data URL；普通 HTTPS 参考图需用客户端下载后 multipart，插件不猜测未列出的 `file_uri` 协议。官方未写 Nano 参考图数量上限，本地保守支持 1 张。面板的比例与 imageSize 已从计划到实际请求完整保留。
- 上游同步图片 Base64 响应通常大于 rc.40 的 1 MiB 上限；单改插件不能解决，配套宿主补丁只将易红两图片型号、两个图片端点的提交响应与 taskData 上限提升到 32 MiB，其余型号、视频、插件 state 仍限 1 MiB。

`seedance2.5 cheap`、`seedance-2.5-max`、`seedance-2.5-Muse` 没有出现在新版官方文档；不删除已有桌面能力，继续保留 2026-10-06 旧合同和既有售价，必须用授权 `GET /v1/models` 核对当前可用性。不将它们猜成 chovy 等新名字。

`wan3.0-video-prime`：

```text
u("resolution") == "720P" ? tier("720P", u("seconds") * 0.45) : u("resolution") == "1080P" ? tier("1080P", u("seconds") * 0.5) : tier("480P", u("seconds") * 0.35)
```

`gpt-image-2-1K-4K`：

```text
u("resolution") == "1K" ? tier("1K", u("image_count") * 0.4) : tier("2K-4K", u("image_count") * 0.08)
```

插件统一上报 `calls`、`seconds`、`resolution`、`image_count` 四字段。视频 `image_count=0`；图片 `seconds=0`、`image_count=1`。视频完成只补 `calls`，保留提交时的秒数与分辨率；图片完成按实际成功图片数补 `image_count`。所有 examples 都包含全部 schema 字段。
