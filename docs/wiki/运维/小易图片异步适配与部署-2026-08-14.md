# 小易图片与视频异步适配部署

> 实施日期：2026-08-14
> 状态：生产适配器与模型可用性服务已部署且健康；GPT 官方渠道和两项 Gemini 图片模型均已在 App 真实生成成功。

## 目标与边界

不修改 NewAPI 官方源码。NewAPI 继续负责用户鉴权、渠道选择、计费和任务持久化；独立 `xiaoyi-image-adapter` 负责把 NewAPI 现有 `/v1/videos` 异步任务合同转换为小易图片或视频异步接口。小易生图、生视频统一使用 `https://image.xiaoyiapi.xyz/v1`。

```text
App -> NewAPI /v1/videos
    -> xiaoyi-image-adapter
    -> 小易 /v1/images/generations/async 或 /v1/images/edits/async
    <- 小易 /v1/images/tasks/{task_id}
    <- NewAPI /v1/videos/{task_id}
```

## 本次根因与修复

1. NewAPI 的视频任务合同在未传 `seconds` 时默认按 4 秒处理，可能导致图片价格乘 4。App 的小易图片请求现固定提交 `seconds=1`，仍按单张任务计费。
2. NewAPI 会在转发前应用模型映射。适配器除六个公开模型外，也接受映射后的隐藏 canonical `gpt-image-2`，但 `/v1/models` 不公开该名称。
3. 小易轮询的一次网络错误、429 或 5xx 不能代表图片任务失败。适配器将这些瞬时错误保持为 `processing`，避免 NewAPI 永久失败并退款。
4. NewAPI 的 OpenAI 类型任务不会保存提交时的渠道 Key，而小易要求提交和查询使用同一 Key。因此每个图片渠道只能配置一把 Key，任务运行期间不得换 Key。
5. Gemini 图片合同为 1K/2K/4K，支持 `1:1`、`16:9`、`9:16`、`4:3`、`3:4`、`3:2`、`2:3`、`5:4`、`4:5`、`21:9`。NewAPI 图片任务只可靠保留标准 `size`，因此 App 必须先把比例与分辨率换算成 `size`，适配器再原样转发；例如 `16:9 + 2K -> 2048x1152`。换算结果必须保持精确比例、两边均为 16 的倍数、最大边不超过 3840、总像素不超过 8,294,400，不得静默改写成其他比例。
6. Web 的 GPT Base64 大图已允许在可信创作结果落盘路径突破默认 12 MB Data URL 限制；普通不可信 Data URL 仍受原限制。
7. GPT 参考图限制保持最多 8 张、单张 20 MB、总计 64 MB；Gemini 按上游合同允许最多 10 张、单张 10 MB。两类入口均只接受 `image/*`。
8. 小易适配器若转发 App 的 `response_format=b64_json`，完成轮询会把整张图片写进 NewAPI 任务响应。生产排查已确认小易、适配器和 NewAPI 任务记录均为 `completed`/`SUCCESS`，但 Desktop 任务卡仍停在 `processing`。适配器现在固定使用上游默认 URL 结果；App 收到短 URL 后沿用既有下载和项目落盘链路。此规则只适用于小易异步适配器，不能倒推修改旧 GPT Image 2 直连的 Base64 合同。

## NewAPI 配置

每个质量渠道保持独立，不把多个价格档合并进同一渠道：

- 渠道类型：`OpenAI`
- Base URL：`http://xiaoyi-image-adapter:8793`
- 每渠道只保留该渠道明确支持的模型名
- 每渠道只配置一把小易 Key
- 关闭上游模型自动同步和自动添加
- 现有前三个 GPT 模型映射可以保留；适配器已兼容映射后的 `gpt-image-2`

## 生产部署

服务器沿用 `/opt/jiucai-repo` 稀疏仓库和 `/opt/<adapter>` 独立运行目录：

```bash
set -euo pipefail

cd /opt/jiucai-repo
git fetch origin main
git checkout main
git pull --ff-only origin main
git sparse-checkout add xiaoyi-image-adapter

mkdir -p /opt/xiaoyi-image-adapter
rsync -a --delete \
  /opt/jiucai-repo/xiaoyi-image-adapter/ \
  /opt/xiaoyi-image-adapter/

cd /opt/xiaoyi-image-adapter
docker compose config
docker compose up -d --force-recreate --build
docker compose ps
docker compose logs --tail=100
```

容器内健康检查：

```bash
cd /opt/xiaoyi-image-adapter
docker compose exec -T xiaoyi-image-adapter \
  python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8793/health').read().decode())"
docker compose exec -T xiaoyi-image-adapter \
  python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8793/v1/models').read().decode())"
```
