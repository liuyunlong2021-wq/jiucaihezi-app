> 日期：2026-10-08

## 结论

小易当前提供 OpenAI 兼容图片接口，并为长任务提供异步提交与查询：

- 文生图：`POST /v1/images/generations/async`
- 图生图：`POST /v1/images/edits/async`，multipart 文件字段 `image` 或重复 `image[]`
- 查询：`GET /v1/images/tasks/{task_id}`，提交和查询使用同一 Bearer Key
- 成功结果：`result.data[]` 中的 `url` 或 `b64_json`

NewAPI `v1.0.0-rc.40` 的 `openai_image` Task Plugin 协议支持异步上游：NewAPI 在 `POST /v1/images/generations` 或 `POST /v1/images/edits` 请求期间轮询任务终态，再返回标准 OpenAI ImageResponse。App 侧继续读 `data[].url` / `data[].b64_json`，并立即下载图片 URL 落盘；不需要把小易任务号暴露给客户端。

```text
App /v1/images/generations 或 /v1/images/edits
  -> NewAPI rc40 openai_image Task Plugin
  -> 小易 /v1/images/{generations|edits}/async
  -> NewAPI 以同一 Key 轮询 /v1/images/tasks/{task_id}
  <- 标准 OpenAI ImageResponse（优先 URL）
  -> App 下载图片并保存
```

依据链接：[小易图片接口](https://xiaoyiapi.xyz/docs/api/images/)、[小易 Grok 图片接口](https://xiaoyiapi.xyz/docs/api/grok-images/)、[小易异步图片接口](https://xiaoyiapi.xyz/docs/api/async-image-generation/)、[NewAPI rc40 发布](https://github.com/QuantumNous/new-api/releases/tag/v1.0.0-rc.40)、[NewAPI 图片路由源码](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.40/router/relay-router.go)、[NewAPI Task Plugin API](https://github.com/QuantumNous/new-api/blob/main/docs/plugin-api/v1.md)。

## NewAPI 配置

1. 在插件页上传 `newapi-plugins/xiaoyi-image.plugin.js`（key `xiaoyi-image`，version `0.1.1`）并激活。插件声明 `openai_image`，无自定义 URL 路由；`meta` 不得声明 `channelTypes`，渠道类型在后续的 type 61 渠道配置中选择。
2. 新建或按模型隔离配置 type 61 `Task Plugin` 渠道，选择 `xiaoyi-image` 插件。
3. Base URL：`https://image.xiaoyiapi.xyz`，不要附加 `/v1`。
4. 渠道 Key：当前小易 API Token。NewAPI 会在图片提交和每次轮询中使用该 Key；任务运行时不要更换 Key。
5. 渠道模型需与插件 `meta.models` 精确匹配。确认小易 `/v1/models` 对该 Token 开放目标 GPT Image 或 Grok Image 模型，并配置对应价格表达式。
6. 现有 GPT Image 2.5 1K 和 GPT Image 2 1K 映射可用：

   | App 模型 | 小易上游模型 |
   | --- | --- |
   | `gpt-image-2-1k` | `gpt-image-2` |
   | `gpt-image-2.5-1k` | `gpt-image-2.5` |
   | `gpt-image-2.5-flare-1k` | `gpt-image-2.5-flare` |
   | `gpt-image-2.5-sunburst-1k` | `gpt-image-2.5-sunburst` |
   | `gpt-image-2-超分` | `gpt-image-2.5-CF` |
   | `gpt-image-2.5-flare-CF-超分` | `gpt-image-2.5-flare-CF` |
   | `gpt-image-2.5-sunburst-CF-超分` | `gpt-image-2.5-sunburst-CF` |
   | `grok-imagine-image-2.0` | `grok-imagine-image-2.0` |
   | `grok-imagine-image` | `grok-imagine-image` |

   插件也接受 `gpt-image-2.5-官方` 及 flare/sunburst 同名别名。最终可用模型以 Token 的 `/v1/models` 为准。

## 图片请求与轮询

NewAPI 对外只接受 OpenAI 图片协议。文生图请求 JSON 经过 `openai_image` 插件变为小易 `/v1/images/generations/async`；有参考图时使用 `/v1/images/edits` multipart，插件把上传文件逐个转发到小易 `/v1/images/edits/async`。多图字段按上游合同转为重复 `image[]`。

插件请求上游时固定要求 `response_format=url`，避免将大张 Base64 图片写入 NewAPI 任务快照。NewAPI `rc40` 的 OpenAI ImageResponse presenter 会根据客户端 `response_format` 输出 URL 或在必要时下载 URL 转成 Base64。URL 可能是小易归档公共链接，也可能是短期签名上游链接；App 应在返回后立即下载。

小易任务轮询状态映射：`queued` / `pending` / `running` / `processing` / `in_progress` -> NewAPI `IN_PROGRESS`；`success` / `succeeded` / `completed` -> `SUCCESS`；`failed` / `failure` / `error` -> `FAILURE`。未知状态不会被伪装成仍在生成。

NewAPI `openai_image` 对客户端是同步图片响应；小易任务在服务端轮询。官方协议默认最多等待 600 秒；超时返回 `504 task_timeout`，NewAPI 中已提交的任务仍会由后台轮询收尾。客户端无需调用 `/v1/videos/{id}` 或 `/v1/images/tasks/{id}`。

## NewAPI Task 用量

插件上报 `image_count`。Task Plugin 的模型定价表达式按插件 usage schema 写，例如单价 `$0.08/张`：

```text
tier("base", u("image_count") * 0.08)
```

系数是美元单价。NewAPI Task 表达式直接返回本次美元总价，不要沿用 token 计费的 `/1000000` 换算。若后台模型已有价格表达式，按目标插件的 task 用量语义复核后保存。

## 验收清单

部署后分别使用 GPT Image 与 Grok Image 完成：

1. 文生图：NewAPI `/v1/images/generations` 成功返回标准 `data[]`。
2. 图生图：NewAPI `/v1/images/edits` 上传一张与多张图片；确认小易收到文件并据此生成。
3. 任务生命周期：NewAPI 请求日志或 Task 记录显示提交、同 Key 轮询至成功，失败状态与错误信息正确。
4. 下载落盘：返回 `data[].url` 后 App 能下载图片并保存至项目；若调用 `b64_json`，响应仍可解码并保存。
5. 计费：NewAPI 账单按实际生成张数核对。
