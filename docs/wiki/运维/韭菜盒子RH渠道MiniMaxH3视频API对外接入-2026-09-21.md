### 当前请求构造示例

以下 JavaScript 展示请求结构，`nodes` 必须是发现后已覆盖本次输入的**完整**节点列表，不可只放修改过的几个节点：

```javascript
const webappId = '2101840271142117377'
const request = {
  model: 'rh-aiapp',
  prompt: '图1和图2两个人在掰手腕',
  duration: 3,
  seconds: '3',
  metadata: { rh_aiapp: { version: 1, webappId, nodeInfoList: nodes } },
  webappId,
  nodeInfoList: nodes,
  extra_fields: { webappId, nodeInfoList: nodes },
}
// 将 request 序列化为 JSON，POST 到 /v1/videos。
```

`duration`、`seconds`、`images` 和画幅等通用字段只作兼容镜像；生成输入以完整节点中的实际值为准。单独修改通用字段而不修改对应节点，不能保证改变生成结果。

### 参数校验与升级边界

- 缺少应用 ID 或完整节点、节点重复/过期、节点值为空、metadata 版本无效或与兼容字段冲突，会在创建上游任务前被拒绝。业务错误码为 400；经过网关后的外层 HTTP 状态以实际响应为准。
- 当前实现对通用 `rh-aiapp` 要求节点集合与发现结果完全一致，并拒绝空值；这是当前实现限制，可选空字段尚不能假定受支持。
- 不再用固定应用 ID 或工作流保存的占位图、默认时长兜底。缺参拒绝提交不等于已验证网关账单不扣费或自动退款。
- 此次修复同时涉及客户端传参和服务端读取。只更新服务端，不会更新已安装桌面 App 的提交代码；旧客户端如果仍发送完整兼容字段可能可用，缺参客户端会被拒绝。
- `Fetch is aborted` 表示请求被中止，不能仅据此认定缺节点或上游生成失败。有任务 ID 时查询原任务；没有时结合提交日志排查上传、提交或客户端超时。

## 模型与计价

8 个应用的请求字段、比例取值和响应格式完全相同，只有参考图数量不同。请求里 `model` 固定写 `rh-aiapp`，用 `webappId` 选应用：

| 应用名 | 用法 | `images` 上限 | 写进 `webappId` 的编号 |
| --- | --- | --- | --- |
| `Minimax-h3 文生视频` | 纯文字生成视频 | 0 张，**不能传图** | `2093604127250149377` |
| `Minimax-h3 首帧图生视频` | 指定首帧，补出后续画面 | 1 张 | `2093571735550521345` |
| `Minimax-h3 首尾帧` | 同时指定首帧与尾帧 | 2 张 | `2093579373894000642` |
| `Minimax-h3 多参双图` | 两张参考图 | 2 张 | `2093654136997900290` |
| `Minimax-h3 多参3图` | 三张参考图 | 3 张 | `2093662476146667522` |
| `Minimax-h3 多参-4图` | 四张参考图 | 4 张 | `2093651661213491202` |
| `Minimax-h3多参5图` | 五张参考图 | 5 张 | `2093706819385516034` |
| `文武双修` | 九张参考图 | 9 张 | `2101840271142117377` |

应用名**逐字敏感**：`Minimax-h3 文生视频` 这类名字里有空格，`Minimax-h3多参5图` 这个名字里没有空格，`Minimax-h3 多参-4图` 里的短横线也不能省。第一列是客户端下拉里显示的名字，用干对照；**`webappId` 请传末列的编号**。

### 三个统一参数（创作面板口径）

下三项在客户端「创作面板」里是统一的，八个应用不用逐个适配；对外调用对应下表最后一列的字段：

| 面板控件 | 取值 | 面板默认 | 对外字段 |
| --- | --- | --- | --- |
| 时长 | `1`～`28` 的整数（秒），滑块 | **5 秒** | `duration` |
| 画幅 | 8 个取值，见「比例与画面尺寸」，浮层 | **`9:16`** | `ratio` |
| 画面质量 | 面板不暴露这个控件 | 固定 `0.9` | 无，不作为请求字段 |

`duration` 与 `ratio` 不传时按该应用自身的设置出片，建议始终显式传。

**时长上限只有面板在管**：RH 的时长节点（如文武双修的 `27:value`）是裸 `FLOAT`，公网 `app-info` 实测它自报 `min/max = ±9.2e18`、`step 0.1`，`rh-adapter` 的 `apply_ai_app_inputs` 也只写值、不校验范围。上限取 `28` 是因为同一张画布 30 秒会被算式补到 736 帧（≈30.7s），最后约 2 秒无效。

**面板「应用」下拉只展示文武双修**（2026-09-27 用户决定）：服务器 `app-directory` 目前返回 14 项，其余 13 项（7 个 Minimax-h3 变体、5 个数字人/语音类、图音生视频）一律不上面板，但它们仍可用 `webappId` 发起调用。

按秒计费，实际扣费以响应中的 `charged_points` 和账户账单为准，**客户端不要写死单价**。

参考图张数是**上限**：少传不报错，超过上限返回 400。

### 怎么选

| 需求 | 用哪个 |
| --- | --- |
| 只有文字描述 | `Minimax-h3 文生视频` |
| 有起始画面，要它继续演 | `Minimax-h3 首帧图生视频` |
| 起始和结束画面都定好了 | `Minimax-h3 首尾帧` |
| 要角色、场景、道具各自保持原样 | 按参考图数量选 `Minimax-h3 多参双图` / `多参3图` / `多参-4图` / `Minimax-h3多参5图` / `文武双修` |

`Minimax-h3 首帧图生视频` 与 `Minimax-h3 多参双图` 都收 2 张图，但语义不同：前者是「从这张演到那张」，后者是「这两张都是参考，画面由提示词决定」。三类模型不能互替。

## 创建任务

接口为异步接口，成功后返回任务 ID。

```bash
curl --location 'https://api.jiucaihezi.studio/v1/videos' \
  --header 'Authorization: Bearer <YOUR_API_KEY>' \
  --header 'Content-Type: application/json' \
  --data '{
    "model": "rh-aiapp",
    "webappId": "2093706819385516034",
    "extra_fields": {
      "webappId": "2093706819385516034"
    },
    "prompt": "生成一段图1和图2和图3三个男人在图5的大树下结拜的电影片段，图4的人群在围观。",
    "images": [
      "https://example.com/man-1.png",
      "https://example.com/man-2.png",
      "https://example.com/man-3.png",
      "https://example.com/crowd.png",
      "https://example.com/tree.png"
    ],
    "duration": 5,
    "ratio": "9:16"
  }'
```

最小响应示例：

```json
{
  "id": "<task_id>",
  "task_id": "<task_id>",
  "object": "video",
  "model": "rh-aiapp",
  "status": "queued",
  "progress": 0
}
```

创建成功只表示请求已被受理，视频此时还没生成。轮询和下载始终使用创建时返回的 `id`。

## 请求字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `model` | 是 | 固定 `rh-aiapp`，其它值返回 400。 |
| `extra_fields.webappId` | 是 | 上表末列的 RH 应用编号，例如 `2101840271142117377`（文武双修）。**必须放在 `extra_fields` 里，服务端只从这里取**；只写顶层 `webappId` 会返回 `500 No webapp ID for model: rh-aiapp`。不在上表内的编号返回 400。 |
| `webappId`（顶层） | 否 | 可选，与 `extra_fields.webappId` 同值。创作面板会把两份都发（顶层那份给平台转发层），但**只有 `extra_fields` 里那份被真正使用**。为兼容建议两处都写。 |
| `prompt` | 是 | 视频内容描述，纯文本。长度上限由服务端决定，建议不超过 2000 字符。 |
| `images` | 见上表 | 参考图数组，每项是公网 `http(s)` URL 或内联 `data:` URI。张数为上表的**上限**，可以少传；超过上限返回 400。 |
| `duration` | 否 | 视频时长（秒），`1`～`28` 的整数。不传时按该应用自身的设置。面板滑块是唯一的上限约束，服务端不校验。 |
| `ratio` | 否 | 画幅，取值见下节。短式（`9:16`）与工作流枚举长串都接受。不传时按该应用自身的设置。 |

画面质量不是请求字段，服务端统一按 `0.9` 处理，客户端不需要也不应该传。

### 比例与画面尺寸

`ratio` 支持 8 种取值：

```text
16:9   9:16   1:1   4:3   3:4   3:2   2:3   21:9
```

分辨率不是独立参数，由 `ratio` 决定：需要竖屏短片用 `9:16`，横屏用 `16:9`。取值必须是上面 8 个之一，其它写法返回 400。

### 参考图要求

`images` 的每一项支持两种写法，服务端都会转存成 RunningHub 能识别的文件令牌：

- **公网 URL**（推荐）：`http://` 或 `https://` 开头的可直接访问地址。
- **内联 `data:` URI**：`data:image/png;base64,...`，适合小图，不必先上传。

已有公网 URL 可以直接填；本地文件先上传到临时素材接口，再把返回的 URL 填进 `images`：

```bash
curl --location 'https://api.jiucaihezi.studio/api/creations/uploads' \
  --header 'Authorization: Bearer <YOUR_API_KEY>' \
  --form 'file=@./reference.png'
```

响应示例：

```json
{
  "url": "https://api.jiucaihezi.studio/media/creation/<token>"
}
```

- 单张图片不超过 20 MB，支持 JPG/PNG/WebP 等常见格式。
- 临时素材接口返回的 URL **15 分钟后失效**，请在上传完成后 15 分钟内创建视频任务。
- 图片链接需要在 **60 秒内**能被服务端完整读取；服务端抓到图后会先把文件转存到 RunningHub，再提交任务。
- URL 必须能由公网直接访问：内网、回环和云元数据地址（如 `127.0.0.1`、`10.x`、`192.168.x`、`169.254.169.254`）会被拒绝并返回 400。
- 图片地址请直接指向文件本身，不要依赖跳转：服务端不跟随重定向，遇到 302 会当作抓取失败。
- 抓取失败返回 `502`，文件超限返回 `413`，均**不会**退化成提交空参考图。

## 查询任务

建议每 5 秒查询一次，直到 `status` 为 `completed` 或 `failed`：

```bash
curl --location 'https://api.jiucaihezi.studio/v1/videos/<TASK_ID>' \
  --header 'Authorization: Bearer <YOUR_API_KEY>'
```

状态说明：

| 状态 | 含义 |
| --- | --- |
| `queued` | 已受理：参考图转存或排队中。 |
| `in_progress` | 生成中。 |
| `completed` | 已完成，读取 `url`。 |
| `failed` | 失败，读取 `error`，停止轮询。 |

这几个模型的成片较长，生成期间停留在 `in_progress` 是正常的，**不要因为等待时间较长就重复创建任务**。

## 下载成片

完成后通过 `/content` 获取视频二进制，不要按 JSON 解析：

```bash
curl --location 'https://api.jiucaihezi.studio/v1/videos/<TASK_ID>/content' \
  --header 'Authorization: Bearer <YOUR_API_KEY>' \
  --output result.mp4
```

也可以直接使用查询响应里的 `url`。该地址不承诺永久有效，请及时把成片转存到自己的存储。

任务数据由平台保留一段时间（当前为 7 天，与平台其它视频模型一致），超过保留期后查询和下载返回 `404`。

## 错误处理

| 状态/错误 | 原因与处理 |
| --- | --- |
| `400` | 模型名不是 `rh-aiapp`、`webappId` 认不出、提示词超长、`duration` 不在 `1`～`15`、`ratio` 不在 8 个取值内、**参考图数量超过上限**（最常见），或参考图地址不是公网可直连地址。修正请求后按新任务重新提交。 |
| `401` / `403` | API Key 缺失、错误，或账号没有该模型权限。 |
| `402` | 余额不足。 |
| `404` | 任务编号不存在，或已超出保留期。 |
| `413` | 单张参考图超过 20 MB。压缩或换图后重发。 |
| `429` | 查询过快。降低查询频率后重试。 |
| `500`、`502`、`503`、`504` | 服务暂不可用。稍后继续查询原任务，不要在客户端把它改成最终失败。 |

**例外：** 如果 `500` 的响应体里带 `No webapp ID for model: rh-aiapp`，那不是服务故障，是请求里漏了 `extra_fields.webappId`（只写了顶层那份就会这样）。补上重发即可，不必等待重试。

另一个需要区分的 `502`：响应体提到参考图抓取失败（服务端需要在 **60 秒内**把图片下载下来）。这种情况重试同一个请求没用，换一个能公网直连的图片地址重发；图片地址不要依赖跳转，服务端不跟随重定向。

参考图数量超过上限占了 400 的绝大多数：`Minimax-h3 文生视频` 带了 `images`、`Minimax-h3 多参3图` 传了 4 张，都会直接返回 400。少传不报错。
