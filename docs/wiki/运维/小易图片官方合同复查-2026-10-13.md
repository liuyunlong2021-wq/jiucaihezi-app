# 小易图片官方合同复查

日期：2026-10-13。插件 `xiaoyi-image` 本地升级为 **0.1.2**，没有更改模型列表或价格，未上传生产或发起付费生成。

## 来源与链路

实际通过 HTTPS 读取官方 [图片接口](https://xiaoyiapi.xyz/docs/api/images/)、[异步图片](https://xiaoyiapi.xyz/docs/api/async-image-generation/)、[Grok 图片](https://xiaoyiapi.xyz/docs/api/grok-images/)；网页中的示例仅作为 API 合同。web 读取器无法打开，使用本机 curl 下载原始 HTML 并解析正文，未读取网站凭据。

基础地址 `https://image.xiaoyiapi.xyz`、Bearer、`/v1/images/generations/async`、`/v1/images/edits/async` 和 `/v1/images/tasks/{task_id}` 均正确。编辑用 multipart image/多图 image[]，逐文件保留宿主 fileRef；轮询使用同一令牌，成功取 result.data 中 URL/Base64，失败取 error.message；未知状态不伪装运行中。

插件向上游固定请求 response_format=url，普通结果为小易归档公开地址，归档失败可为短期签名地址，均完整保留。App 已有返回后下载落盘链路。旧模型别名映射继续保留；账号是否可用必须由该 Key 的 /v1/models 确认，不能因文档示例没有列出别名就删除桌面能力。本文未复查小易视频或 Gemini 原生端点，亦未新增型号。

## 复现与修复

新夹具在0.1.1复现五个失败场景后，0.1.2修复通过：

- n=12 原样发出，但 extractUsage 预扣只算10；现在 n 必须为正安全整数，请求、JSON/multipart、用量均使用相同数量，不对实际数量静默截断。文档未给统一上限，模型/账号的最大数量仍由上游校验，最终按实际返回图片数结算。
- background/output_format 原来被静默丢弃；现在文生图JSON与编辑multipart完整保留用户明确给出的官方字段。具体型号是否支持由上游判断，不为所有模型擅自开放面板选项。
- JSON文生图中带 image/images/image_url 等参考图原来被忽略；现在要求走multipart编辑。官方尤其明确Grok放入JSON不会触发编辑，不能假装使用了参考图。
- Grok size 与 aspect_ratio 原来可能互相矛盾；现在要求显式像素尺寸，明确指定比例时校验一致性，允许单边像素取整误差。App现行计划已把ratio/resolution转换成匹配size，通常不另传aspect_ratio，链路无需更改。
- status=success 但 result.data 没有有效URL或Base64原来直接判成功，后续render才失败；现在标UNKNOWN并给出明确原因。结算只统计有效图片条目，排除仅revised_prompt或空项。
