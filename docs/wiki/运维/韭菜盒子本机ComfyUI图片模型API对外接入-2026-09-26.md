# 韭菜盒子本机 ComfyUI 图片模型 API 对外接入

> 本文档是韭菜盒子 NewAPI 的公开接入合同，只描述韭菜盒子接口，不包含上游服务、内部适配器或密钥信息。
>
> ✅ **已上线（2026-10-02 起）**：`jc-qwen-image-2.1` 已接回 NewAPI，与[[运维/韭菜盒子本机ComfyUI视频模型API对外接入-2026-09-26|本机 MiniMax H3 视频]]共用同一台 RTX 4090。
> 两套权重不能同时常驻显存，ComfyUI 会在图片/视频之间**重载**，所以**图片与视频交替调用时，下一笔会多几十秒**（同一类型连续调用没有这个代价）。
> 与视频模型共用同一个队列（**单并发**）：两边同时提交会互相排队。
>
> 适用对象：需要通过第三方客户端调用 `jc-qwen-image-2.1` 的用户。
>
> 该模型跑在本机工作站的 RTX 4090（48 GB 显存）上，**单并发**：请在客户端里串行调用。同时提交多个任务会排队，排队等待过久会被拒绝（见「错误处理」）。

## 接入信息

| 项目 | 值 |
| --- | --- |
| Base URL | `https://api.jiucaihezi.studio` |
| 生成图片 | `POST /v1/images/generations` |
| 图片编辑 | `POST /v1/images/edits`（multipart），或直接给 `/v1/images/generations` 传参考图 |
| 上传参考图 | `POST /api/creations/uploads` |
| 认证 | `Authorization: Bearer <你的 API Key>` |

## 模型与计价

| 模型名 | 能力 | 计价 |
| --- | --- | --- |
| `jc-qwen-image-2.1` | 文生图；带参考图则为单图 / 多图编辑 | `0.2/张` |

同一个模型名同时覆盖文生图和图片编辑：**不给参考图＝文生图，给参考图＝编辑**。返回的图数量与 `n` 一致，按张计费。

## 文生图

```bash
curl --location 'https://api.jiucaihezi.studio/v1/images/generations' \
  --header 'Authorization: Bearer <YOUR_API_KEY>' \
  --header 'Content-Type: application/json' \
  --data '{
    "model": "jc-qwen-image-2.1",
    "prompt": "一只绿色的小野驴，卡通",
    "size": "1080x1920",
    "n": 1
  }'
```

## 图生图 / 图片编辑

参考图可以是公网 `http(s)` URL、`data:` base64 URL，或先用临时素材接口上传后拿到的 URL。**不接受**本地文件路径。

```bash
curl --location 'https://api.jiucaihezi.studio/v1/images/generations' \
  --header 'Authorization: Bearer <YOUR_API_KEY>' \
  --header 'Content-Type: application/json' \
  --data '{
    "model": "jc-qwen-image-2.1",
    "prompt": "把背景换成夜晚的森林",
    "size": "1080x1920",
    "images": ["https://example.com/input.png"]
  }'
```

| 传法 | 说明 |
| --- | --- |
| `image` | 单张参考图（字符串） |
| `images` | 多张参考图（字符串数组），**最多 10 张**，按顺序生效 |
| `/v1/images/edits` | multipart：文件字段 `image` / `image[]` / `images`，其余为普通文本字段 |

## 请求字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `model` | 是 | 固定 `jc-qwen-image-2.1`，其它值返回 400。 |
| `prompt` | 是 | 画面描述。 |
| `size` | 否 | 输出尺寸，取值见下方尺寸表。默认 `1080x1920`。 |
| `image` / `images` | 否 | 参考图，给了就是编辑模式，最多 10 张，单张 ≤ 20 MB。 |
| `n` | 否 | 生成张数，1–4（传更大的值最多只出 4 张，按**实际**张数计费）。默认 1。 |
| `steps` | 否 | 采样步数，默认 40，上限 100。 |
| `seed` | 否 | 随机种子；不传由服务端随机。 |
| `response_format` | 否 | 只支持 `url`（默认）。返回 `https://api.jiucaihezi.studio/files/<文件名>` 公网直链；传 `b64_json` 会内联 base64 并**在本渠道失败**（原因见「响应格式」）。 |

### 尺寸（1K / 2K × 常规比例）

API 收的是**像素串**（形如 `1080x1920`）；「1K / 2K」是创作面板里的显示档位，不是接口取值。

| 档位 | 1:1 方图 | 16:9 横屏 | 9:16 竖屏 | 4:3 横屏 | 3:4 竖屏 | 3:2 横屏 | 2:3 竖屏 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1K | `1024x1024` | `1024x576` | `576x1024` | `1024x768` | `768x1024` | `1024x680` | `680x1024` |
| 2K | `1448x1448` | `1920x1080` | `1080x1920` | `1664x1248` | `1248x1664` | `1768x1176` | `1176x1768` |

约束：宽高都是 **8 的倍数**、最长边 ≤ **2048**、总像素 ≤ **210 万**。

**不支持 4K**：模板上限是最长边 2048。传别的尺寸不会报错，但服务端会按上面的约束**等比缩到上限内**（例如传 `2048x2048` 会缩到约 `1448x1448`），所以请直接用表里的取值。

## 响应格式

图片以 **URL** 返回（`url`，本线路的默认值）：

```json
{
  "created": 1790388607,
  "data": [{ "url": "https://api.jiucaihezi.studio/files/20261002-1bdf2827d388463d.png" }]
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `data[].url` | 图片直链，公网可达、`Content-Type: image/png`；支持 `HEAD` 与 `Range`，`curl -o` 即可落盘。 |
| `created` | 平台填写的 Unix 秒。 |

除了 `created` 与 `data`，**不要依赖其它字段**（不要去找 `model` / `prompt_id` / `elapsed_seconds`，它们不属于对外保证）。

`n > 1` 时 `data` 数组有多项，按张计费（`0.2/张`）。图链与任务一起 **24 小时**后失效，请及时转存到自己存储。

**为什么不再内联 base64**：平台的**任务插件**把提交响应落库的上限是 **1 MiB**，而本机出的是 2 MB 级 PNG，编码成 base64 约 2.8 MB，会直接报 `502 task submit response exceeds size limit`。所以经本渠道请用 `url`；`b64_json` 只在直连适配器（本机 `127.0.0.1:9000`）时才有意义。

## 错误处理

| 状态/错误 | 原因与处理 |
| --- | --- |
| `401` / `403` | API Key 缺失、错误或无该模型权限。 |
| `400` | 模型名、`size`、参考图数量（超过 10 张）或参考图格式不合法。 |
| `413` | 只在临时素材上传接口出现：单文件超过 20 MB。 |
| `429` | 队列已满或排队等待超时（`server_busy`）。本模型**单并发**（在途 1 个、排队上限 4 个、排队等待上限 5 分钟）。图片是**同步接口**，所以排队结果直接体现在 HTTP 状态码上。收到后请降低并发、稍后重试，不要连打。 |
| `503` | 本机 ComfyUI 不可用（未启动或正在加载模型），稍后重试。 |
| `502` 且 `message` 含 `exceeds size limit` | 请求了内联 base64（`response_format: b64_json`）而图超过宿主 1 MiB 落库上限。改用 `url`。 |
| `5xx` / `502` | 服务或上游暂时不可用，稍后重试。 |

耗时参考（RTX 4090，40 步）：`1024x1024` 约 30 秒；`1080x1920` 约 35–50 秒；参考图越多越慢。首次调用（冷启动）可能多 10–30 秒；**刚跑过本机视频模型时再多一次重载（几十秒）**。

## 接入边界

- API Key 只放在 `Authorization` 请求头，不要写入前端公开代码、日志或提交记录。
- 参考图必须放在能被服务端读取的地方：公网 URL，或先用 `POST /api/creations/uploads` 转存（单文件 ≤ 20 MB，返回 URL **15 分钟**后失效，请在 15 分钟内提交任务）。
- 服务端读取单张参考图的超时是 **30 秒**；放在慢速或不稳定的主机上会失败。
- 本模型为**单并发**本地推理，请以串行方式调用；批量任务建议客户端排队而不是并发提交。
- **同步接口，超时给足**：一次请求要等 30–50 秒（正好接在视频任务后面时还要多几十秒重载），**客户端超时建议 ≥ 90 秒**，别用 30 秒默认值。
- 与视频模型**共用同一块显卡与同一个队列**：图片/视频交替调用时下一笔会多几十秒（重载），同类连续调用没有这个代价。
- 生成结果是一张 **24 小时**有效的图链（公网可达），平台不代为长期托管，请自行转存。
