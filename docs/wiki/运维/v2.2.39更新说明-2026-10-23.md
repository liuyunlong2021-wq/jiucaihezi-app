# v2.2.39 更新说明

> 版本：`2.2.39` ｜ 日期：2026-10-23 ｜ 发布提交：`c909a1e3` ｜ 上一版：`v2.2.38`
>
> 状态：tag 已推送，三平台发布流程见 Actions 实际结果；本文只写**代码层面已落地**的变化，真实收费、跨平台与用户项目升级不在本文验收范围内。

## 0. 一句话

这一版把「输入框里的 `@` 到底干什么」理顺了：`@排版` 改名 `@Office`、重复的 `@文件` 下线、每个 `@` 只给自己那份能力；创作面板补齐了参数复制与图片切分，表格能导 CSV；桌面安装包改由 R2 + 下载域名分发（旧地址 302 兼容）；设置里的「一键登录」换成灰色的「多端同步」占位——**现在填 Key 就能用**。

## 1. 用户会直接看到的变化

### 1.1 输入框芯片改名与下线

| 旧 | 新 | 说明 |
| --- | --- | --- |
| `@排版` | `@Office` | 选择器描述：「导出文档、表格、幻灯片、PDF、网页和长图」。内部 id 一直是 `media`，**历史会话、开关状态、工具白名单全部不受影响** |
| `@文件` | 无（已下线） | 本机读写与终端一直由底部「权限」档控制，这个芯片只是把权限档切到完全权限的重复开关 |

`@文件` 下线的依据：`fileToolsSelected` 直接取 `permissionTier === 'danger-full-access'`，点它和点权限按钮是同一件事。移出 `@` 菜单后，本机能力没有任何减少。

### 1.2 `@Office` 能导出 CSV

`create_document` 新增 `format: csv`：

- 表格数据导 CSV，Excel / WPS / Numbers 双击直接打开；
- 写文件时带 UTF-8 BOM，否则 Windows Excel 打开中文表头是乱码；
- 零依赖，没有引入新库。

**产品目前不生成 `.xlsx`。** 需要公式或图表的，导出 CSV 后在表格软件里另存。

### 1.3 每个 `@` 只给自己那份能力

| 芯片 | 创作相关工具 |
| --- | --- |
| `@Office` | `get_creation_context`、`add_creation_result_to_canvas` + `create_document` / `create_html` / `export_markdown_slides` / `export_markdown_png` |
| `@3D` | `get_creation_context`、`add_creation_result_to_canvas` + 四个 3D 工具 |
| `@影音` | 上面全部 + 媒体目录/任务六个工具 + `submit_creation_task`（唯一的付费口） |

两处收紧：

1. **影音生成策略不再灌进别的芯片**：`buildMediaPlanPolicy` 与批量媒体确认文案原来用 `mediaSelected || avSelected` 判断，只选 `@Office` 也会把 `jc-media-plan` 那套规则塞进系统提示，模型会拿文档需求去凑生成计划。现在只看 `@影音`（或 Skill 自己声明的 media/av）。
2. **影音目录工具只在 `@影音` 注册**：`list_creation_models` / `get_creation_model` / `get_creation_task` / `list_creation_history` / `cancel_creation_task` / `retry_media_persistence` 带 `mediaCatalog` 开关，由 `avSelected` 控制。

`get_creation_context` 与 `add_creation_result_to_canvas` 留给 `@Office` / `@3D` 是**故意的**：以前只开 `@Office` 时它俩不存在，模型会绕去用 CLI 硬做，测试里锁着这条回归。

**未选 Skill 时仍按官方 DSH「自动选」语义**（用户 2026-10-23 裁定），不封锁 Skill。

### 1.4 设置里的「一键登录」→ 灰色「多端同步」

- 桌面端账号页原来的「一键登录」位置，换成 disabled 的 **「多端同步 · 即将开放」**，留给以后的多端同步，hover 提示「即将开放：现在填写模型调用 Key 就能用」；
- **不再按登录状态收起 Key 输入框**。原来 `loggedIn && !advancedOpen && !apiKeyDraft` 会把输入框整个藏起来，登录过又没配 Key 的人会以为登录就能用、还找不到输入口；
- 设置里的「同步」页移除（同步仍在**项目中心**：上传/下载项目文字资料）；
- 手机端账号页冻结，登录入口一行未动。

过时文案一并清理：Key 缺失提示、云端必需提示、登录成功状态都不再提「账号登录 / 云端同步」。

### 1.5 创作面板

- **下线 10 款模型**（GPT2.0 图生图/文生图、Midjourney Fast Imagine、ZX Seedance 三款、Seedance 2.5 两款、菠萝 H3 视频两款）。合同与按 id 调用保留，只是菜单不可见；jc 本机整组移到菜单最后。
- **生图菜单排序**：FK 图片组排到灵动前面。原来 `灵动seedace2.5` 没进顺序表，`indexOf` 返回 `-1` 把它顶到了最前。
- **新增 `mj_relax_imagine`**（Midjourney Relax 生图，T8 渠道，¥0.2/张）：
  - 只用 `t8-mj` 插件 0.3.0 **直连 T8**，不需要部署服务，忽略渠道 Base URL；
  - 面板可选比例，由插件拼成 `--ar`（`--ar 9:16` 实测回 1632×2912）；
  - 目前仅文生图；与 ZX 渠道互不复用。
- **图片切图**：媒体查看器与中心预览加「切图」，把 MJ 四宫格按 2×2（可选 1×2 / 2×1 / 3×3）切开，点格子勾选后存入项目「图片」并排队加入画布。纯本地裁剪，不调用付费接口。
- **复制参数**：面板上的「复制参数」把类型/模型/模式/比例/分辨率/时长/价格写成一行 `[创作参数] …`，粘到 `@影音` 输入框接着写提示词即可。

### 1.6 `@影音` 与创作面板打通

### 1.9 下载地址

下载页地址**不变**（`https://api.jiucaihezi.studio/download/`），但安装包字节从 R2 出：

```text
用户点下载 → api.jiucaihezi.studio/updates/2.2.39/文件
           → 302 → downloads.jiucaihezi.studio/2.2.39/文件（R2 CDN）
```

已实测（2026-10-23）：三个平台的旧地址都返回 `302` 到 R2，R2 直连 `200` 且 `cache-control: immutable`。细节见 §3。

**但应用内「检查更新」这一版不会升到 2.2.39。** 官方 OTA 清单 `updater.json` 目前仍是 `2.2.27`（2026-10-09）；推广 OTA 是独立门禁，需要手动开 `promote_updater: true` 并跑完三平台 A→B 升级验收，本版按规则跳过（v2.2.38 也跳过了）。也就是说：**新用户从下载页装到 2.2.39；老用户想升级要自己重新下载安装包**，点「检查更新」不会有反应。

#### 怎么手动推广 OTA

等 tag 发布那次 Actions 跑完，再手动触发一次（不重新构建，只重跑校验 + 推广）：

```bash
gh workflow run build.yml --ref main \
  -f publish_tag=v2.2.39 \
  -f native_platform=all \
  -f promote_updater=true
```

界面路径：Actions → **Build Desktop App** → Run workflow → 分支选 `main`，填上面三个输入。

三个输入都是必需的：

| 输入 | 值 | 为什么 |
| --- | --- | --- |
| `publish_tag` | `v2.2.39` | 让三个构建 job 跳过（`if: inputs.publish_tag == ''`），直接用 Release 里已有的签名字节；同时 `promote-updater` 的 `if` 要求 `publish_tag != ''` |
| `native_platform` | `all` | 值是 `windows` 时 `promote-updater` 会被拒（`inputs.native_platform != 'windows'`） |
| `promote_updater` | `true` | 默认 `false`，不开就永远只发下载页、不推 OTA |

这次会依次重跑：R2 上传与双向校验 → 服务器提交 → 装重定向 → 校验 302 → 推广 `latest.json` → **三平台 A→B 原生升级验收**（基线 `v2.2.22`）→ 推广 `updater.json`。前面几步同版本同平台是幂等的，不会覆盖已发布字节。

推广成功的标志：

```bash
curl -s https://api.jiucaihezi.studio/updates/updater.json | grep '"version"'
# 应输出 2.2.39
```

推广后所有 ≤2.2.39 的在线用户都会收到升级提示，所以务必等 `verify-native-upgrade` 三个平台都绿。中途任一步失败，`updater.json` 保持 2.2.27 不动，影响面为零。

## 2. 过程体验与会话修复

| 问题 | 根因 | 现在 |
| --- | --- | --- |
| 过程里出现 `读取文件 /Users/…/src-tauri/target/debug/skills/…`，像在翻源码 | 路径参数按 80 字符**从头**截断，正好切掉文件名 | 路径类键按**尾部**保留，显示 `…/skills/jc-new-user-guide/references/2-….md` |
| 带图提问时第一步 `FS_NOT_FOUND` | 图片已内联送达，却又被提示「用 read_image 读」；模型去重抄 `attachments/v1/objects/xx/<64 位十六进制>`（无扩展名无文件名），抄错一个字符就 404。日志实测正确路径 5 次、抄错 4 次 | 删掉这句指路。`read_image` 只在模型声明图片输入时才工作，内联时不必读、没视觉时读必定被拒、格式不支持时读回来还是那个格式 |
| 上游重试了 5 次，界面只显示 1 次 | `retryId` 标识整组重试却被当成单次尝试的键，客户端按 ID 合并 | 配对键改成 `retryId + attempt`，组内每次尝试分开显示 |

视频提示保留（`[本轮引用的视频不能直接读取，用 @jc-watch 抽帧看。]`）：视频永远不能内联，`read` 读回来是二进制，只有抽帧一条路，而这条在工具说明里查不到。

## 3. 下载路线改走 R2

安装包不再由 API 服务器持续传输，改由 Cloudflare R2 + 下载域名 CDN 分发。

### 3.1 地址怎么变

| 用途 | 地址 | 行为 |
| --- | --- | --- |
| 新地址（R2 直连） | `https://downloads.jiucaihezi.studio/{version}/{filename}` | CDN 直出 |
| 旧地址（兼容保留） | `https://api.jiucaihezi.studio/updates/{version}/{filename}` | `302` 精确跳到上面那条，`Cache-Control: no-store` |
| 官网下载页的清单 | `latest.json` | 已推广到 2.2.39；里面的下载 `url` 仍是旧地址，请求时 302 到 R2 |
| 应用内更新清单（OTA） | `updater.json` | 入口字段公钥不变，但**未推广**：仍是 2.2.27（见 §1.9） |

- R2 对象 key 就是 `{version}/{filename}`，桶 `jiucaihezi-releases`。
- 重定向是**每个文件一条 nginx `location` 精确匹配**，不用通配，避免跳到不存在的对象。
- 官网、旧版 App、官方自动更新客户端都不用改，继续用旧地址也能下到。

### 3.2 一个版本的发布顺序

```text
① 三平台最终签名字节就绪
② 本地 sha256sum 生成 R2-SHA256SUMS（覆盖每个资产 + 历史摘要，不重复）
③ 上传 R2（IfNoneMatch='*' 版本对象不可覆盖，Cache-Control: immutable）
④ 上传后 get_object 回读，比对长度 + SHA-256
⑤ 从 downloads 公开域名逐个取回校验：
     全文 SHA-256、Range 206、If-Range 断点续传、故意错的 ETag 必须回 200
⑥ 提交服务器 /opt/updates/{version}（flock 串行；同名文件逐字节 cmp，禁止覆盖）
⑦ 写 nginx 重定向（先备份到 /etc/nginx/backups，nginx -t + reload）
⑧ HEAD 旧地址逐个确认 302 到 R2 精确地址
⑨ 原子推广下载清单
```

顺序上有两个刻意的安排：

- **先 R2 后服务器**：R2 校验没过，服务器那边的目录和清单一个字都不动。
- **⑦ 之后 ⑧/⑨ 任一失败就回滚**：`configure-r2-downloads.py ... rollback` 恢复上一份 nginx 配置并 `exit 1`，不会留下「重定向装了但清单没推广」的半成品。

### 3.3 必传资产

DMG（aarch64 / x64）、Windows `setup.exe`、Windows **便携 `zip`**、两个 `app.tar.gz` 及其 `.sig`、`SHA256SUMS`。缺任何一个、出现重名歧义、或摘要与 `R2-SHA256SUMS` 不符，直接中止发布。

### 3.4 边界

- 安装包是**公开、按版本长期保留**的资产，与私有临时素材桶彻底隔离：脚本硬校验 account 与 bucket 名，误配私有桶会直接报错。
- 服务器源文件保留不删，作为回滚来源；R2 不做版本自动过期清理。
- 正式 OTA 推广仍走独立门禁，存储迁移不改变用户升级渠道；本版 `updater.json` 未推广（仍 2.2.27）。
- 只迁移本次发布的版本：老版本（如 2.2.38）的下载地址没有被加 302，仍由服务器直出，源文件保留。
- 发布 job 加 `concurrency: desktop-download-publish` 且 `cancel-in-progress: false`，避免两次发布同时改清单。
- 发布工具取本次工作流版本（`ref: github.ref`），安装包字节仍按 tag 取，不受影响。

合同与验收细节见 [桌面安装包R2分发合同](../开发/桌面安装包R2分发合同-2026-10-22.md)。
