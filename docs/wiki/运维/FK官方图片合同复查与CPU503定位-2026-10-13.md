## 当前 503 的发生层

`system_cpu_overloaded (current: 100.0%, threshold: 90%)` 来自 NewAPI 性能准入中间件，在渠道选择和供应商请求之前 `c.Abort()`。固定 rc.40 [performance.go](https://github.com/QuantumNous/new-api/blob/0aec08fee811ec6136828fda790551b49e410301/middleware/performance.go) 与 [system_monitor.go](https://github.com/QuantumNous/new-api/blob/0aec08fee811ec6136828fda790551b49e410301/common/system_monitor.go) 表明检测值为系统 CPU 采样，不能仅凭这个错误归因于 FK 不可用，也不能把它当成参数错误。

用户正在同机执行易红宿主 Docker/Go 构建。构建结束后的输出：NewAPI 容器 CPU 0.04%、Postgres 0.01%；`ps %cpu` 是进程期间的占用统计，临时 ps 进程显示 100% 不能证明现在整机满载。此前错误与编译期间竞争系统 CPU 的时间相符，但未拿到报错瞬间的进程采样，因果关系按推断记录。当前没有依据关闭或抬高服务器性能阈值。

## FK 请求合同复查

现行六图片型号均在新官方目录中。显示名 `FK-image2` 对应公共编号 `ft-image-v1-211f28f47b0355abb1798f72eb65f22d`，不是把显示名直接传给上游。

- 服务端提交标准 `/api/open/v1/image/generate`，JSON 参数 `model/prompt/ratio/imageSize/imageUrls`；Bearer 与 `X-Public-Model-Ids: 1` 正确。
- App FK 图生图把本地素材经 OSS 换 HTTPS URL，以 JSON 发给本平台 `/v1/images/edits`；插件把 facade 路径转换为标准 generate。它没有向 FK 请求不存在的 `/v1/images/edits`。
- 外部 multipart 编辑使用重复 `images` 字段及宿主 fileRef，boundary 由宿主生成。
- 查询标准 `/api/open/v1/image/status?jobId=...`，没有混成 taskId；结果读取 resultUrls，并完整保留签名查询参数。文件结果是 URL，FK 不依赖易红 Base64 大响应补丁。
- 六型号的现有参考上限与官方一致：前四项10图，Banana 两项8图；其余新增到官方目录的六型号不因此次复查擅自开放。

独立修复到插件 **0.2.1**：

1. 错误 imageSize 以前被清空并使用上游默认档；现在拒绝非法档位、画幅与超量参考图，避免规格/价格与意图不符。
2. 同时传文件和URL会丢掉URL；现在明确拒绝混用，不静默删素材。mask 局部编辑官方不支持，明确拒绝。
3. `success=false` 是请求失败，不能只因 status/resultUrls 看起来成功就结算成功；解析时拒绝并保留上游错误信息。
4. 必须保存真实 jobId，删除伪造即时任务编号的兜底。提交时 `resultAvailable=false` 不得立即报成功；查询必须明确 resultAvailable=true 且 resultUrls 非空才完成，否则继续查询原任务，不重复生成、不因为结果暂不可用就宣告失败退款。
5. error 对象以前显示 `[object Object]`；现在提取 error.message/errorMessage/字符串 error。

旧视频端点、协议、计费与六图片型号售价保留。新官方图片文档不是八个现行视频型号的完整视频合同，不能据它宣称所有视频型号、参考视频 Token 计费或所有平台已验收。
