# @影音 MCP/CSP 根因、多行输入丢失与候选卡顿

> 日期：2026-10-10 · 检查的安装版：v2.2.27

## 连接失败与产品根因

用户粘贴的连接诊断包含 `methods=initialize,notifications/initialized,tools/list`、Node 命令和空 stderr。它说明 MCP 握手已完成，并已向服务请求工具列表；失败发生在客户端处理 `tools/list` 的阶段。`src/services/mcpClient.ts` 使用 MCP SDK 的默认 `Client`，其默认 `AjvJsonSchemaValidator` 会在 `listTools()` 缓存服务端提供的 `outputSchema` 时动态编译 JSON Schema。Ajv 用 `new Function` 生成校验函数，当前 Tauri WebView 的 CSP `script-src` 未允许 `unsafe-eval`，所以编译被拒绝，连接被关闭并呈现为断开。

这不是媒体 Key、NewAPI 或图片模型故障，也不是安装包缺少 `creation-mcp/index.mjs`。不要为了让 MCP 客户端通过而给 App 放开 `unsafe-eval`。

更上游的设计根因是：App 把自有 `@影音` 工具注册成 `dsh-mcp-client → stdio MCP 子进程 → 本机桥接 → App Store`，于是本机内置功能错误地依赖 MCP 客户端握手。用户的设计是 App 内置媒体工具直接调用 App 已配置的媒体模型与 Key。

修复方向已落实为 Harness 随包原生工具插件：`@影音` 直接注册模型列表、上下文、提交、历史、取消、重试落盘和显式入画布工具；排版/3D 内置工具也由同一原生插件注册。工具经现有本机鉴权桥接调用 `creationMcpBridge.ts` 的 App Store/executor，不创建用于这些能力的 MCP stdio 子进程。媒体任务仍由 `mediaTaskStore.submitTask` 和 `creationMediaRuntime` 执行；`api/media-generation.ts` 从 App 设置读取媒体 API Key。外部 MCP 服务器由用户选择 `@MCP` 时继续使用独立链路。

「韭菜盒子创作」已从 App 的 MCP 内置目录移除，旧的同 ID 安装记录会在 MCP 配置加载时清除。App 内 `@影音` 通过原生 Harness 工具调用内置媒体能力，不经过 MCP 客户端；通用 `@MCP` 代理仍保留。本轮没有点击重试或提交图片任务。

## 输入文字被 @影音 选择清空

v2.2.27 的近期提及改版在 `selectMention` 中用 `getCursorPosition` 计算 token 范围。旧实现通过 `Range.toString()` 计数，而 `getPlainText` 为 `DIV`、`P`、`LI` 和 `BR` 补入换行。多行草稿中的两个偏移坐标不一致；光标靠后时，`replaceComposerSuggestion` 可能覆盖更大范围，连同提示词正文一起删除。

修复让光标测量在编辑器克隆中插入不可冲突的标记，并用与 `getPlainText` 相同的 DOM 到文本归一化结果定位标记。若选择不在编辑器内，安全回退到文本末尾。没有改动发送时主动清空输入的既有行为。

## 文件多时提及卡顿

综合 `@` 候选函数在空查询时调用 `files.list(owner)`，Desktop 适配器用 `dev_list_files` 最多遍历 1000 项；查询词精确为「影音」时，也先等待 Skill 目录加载，再调用递归 `dev_search_project_paths`。候选结果的显示上限不限制前面的文件树遍历，所以大项目会放大等待。

现在空查询只显示工具、Skill 和会话候选，不枚举项目文件；与工具 ID 或显示名完全匹配时直接返回工具候选，不等待 Skill 或文件搜索。输入非空文件名仍走现有搜索链路。

## 修改与验证

- 修改 `src/services/deepSeekHarness.ts`：App 内媒体/排版/3D 工具走原生 Harness 插件；只有用户选择外部 `@MCP` 时才创建 MCP 客户端服务器条目。
- 从 MCP 内置目录删除「韭菜盒子创作」，旧同 ID 配置按过期条目清理，并移除对应卡片专属的配置分支。通用 `@MCP` 代理仍使用本机桥接与 MCP 子进程。
- 新增 `src-tauri/resources/deepseek-harness/plugins/creation-tools/`：原生工具读当前 App 模型/上下文并调用本机桥接，不持有或传递媒体 Key。
- `src/services/mcpClient.ts` 的 CSP/Ajv 限制没有通过放宽 CSP 规避；该通用 MCP 客户端仍需无动态代码生成的 validator 才能处理有 `outputSchema` 的 MCP server。
- 修改 `src/composables/useContentEditable.ts`：让 contenteditable 光标偏移与纯文本换行归一化一致。
- 修改 `src/components/memory/MemoryWorkbench.vue`：空查询跳过全项目列表，精确工具匹配提前返回。
- 更新 `src/components/memory/__tests__/memoryWorkbench.test.ts` 既有断言以符合空查询行为。
- `pnpm run typecheck`、Harness 插件文件 `node --check` 与 `git diff --check` 通过；本轮未运行测试。
- 源码修复尚未重建或发布安装包，当前运行安装版仍是 v2.2.27。未连接 MCP，未执行任何生图任务。
