# 3D 工具丢失与多实例桥接隔离

日期：2026-10-19。用户反馈 @3D 生成位置关系图明显变慢，并授权立即修复。

## 根因证据

官方 sessionQuery 只读追踪「列车」会话：本轮未调用 create_3d_scene，Agent 转而操作窗口、查询外部 3D 模型，再建立 train-blocking 网页工程、安装 Three.js/Vite/Playwright；npm 缓存权限失败后重试。此证据不能解释为内置渲染变慢。

真实 SDK 启动日志明确报 `mcp-bridge.json` ENOENT。旧代码将所有 App 共用的全局发现文件在任意 App 退出时无条件删除；插件加载本地目录失败只打印 stderr，模型仍会继续执行，最终绕行其他工具。

## 最小修复与保留边界

1. 每个 App 持有独立 `mcp-bridge-<pid>.json`，权限沿用 600；resolve_creation_mcp 从所属 Rust AppState 返回该文件路径，内部 Harness 原生工具及 MCP 子进程固定使用该路径。
2. 全局 mcp-bridge.json 保留供外部客户端兼容发现；退出只清理本实例文件，以及仍属于自己 token 的全局文件。旧安装版即使仍误删全局文件，新版内部工具也不依赖它。
3. 只将实例路径传入环境及 MCP 配置，不把桥接 token 写进 route YAML。官方子进程会清除 TOKEN 等凭据变量，因此不依赖凭据隐式继承，不绕过官方过滤。
4. 插件目录加载失败向上报错；发送前通过官方 tools.get 检查已选入口的必要工具。SDK 检查等待官方 loader 完成，避免异步目录尚未注册时误报；缺失时在 prompt 和订阅前终止，不把缺工具的请求交给模型。
5. @3D 要求 create/inspect/edit/export 四项齐备；@排版和 @影音 同样检查各自必要工具。付费提交仍只由 @影音 放行，外部 MCP 原有失败隔离不变。沿用现有执行器、.jcscene、图片回传与原生 DSH Agent，不另建 3D 网页工程。

## TDD 与验证边界

- 红测：模拟一个 App 退出误删另一实例发现文件；真实插件在无共享发现文件时缺少全部 3D 工具；目录失败被吞掉；SDK 不支持必要工具检查；缺工具仍开始订阅。
- 绿测：独立路径下真实完整 3D schema 注册；MCP 默认桥接调用走所属实例；加载失败可观察；缺工具不发送 prompt；共享文件删除后实例连接保持。无真实收费模型请求。
- MCP/原生桥接定向 9 项通过；生命周期及补丁等定向 32 通过、1 跳过；扩大 Node 回归 2021 通过、1 跳过、1 失败，唯一失败为已有灵动定价断言，未修改无关渠道。类型检查通过。Rust 最终 494 通过、2 忽略；开发版重启后所属桥接返回 200、独立文件权限 600，真实 SDK 只读检查四项 3D 工具 ready，全程未发送模型消息。详情见操作日志。
- 尚未做：真实双安装包启动/退出、Windows/Intel Mac、安装升级、真实模型重新生成的性能验收；不宣称这些已通过。未打包发布。
