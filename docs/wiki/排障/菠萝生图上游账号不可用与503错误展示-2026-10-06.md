## 15:22 的 524 补充核对

用户报告「衣服换成红色」在 15:22:23 收到 HTTP 524 HTML。随后只读读取同一用户、同模型、同渠道的 15:22:39 错误详情：

- 上游请求 ID：`202610060720221101263028268d9d6XGz7czOb`。
- 请求路径：`/v1/images/edits`，原生格式。
- 选中 #136，9 ms；上游 HTTP 503，140854 ms；一次尝试耗尽；错误来源「上游响应」。
- 错误正文：`No available compatible accounts`；此条 NewAPI 日志费用 $0。
- 渠道编辑页已只读确认：启用、OpenAI 类型、API 地址 `https://aimanplay.cn`，映射 `gpt-image-2-菠萝` → `gpt-image-2`。其余三个菠萝模型也有对应原名映射。取消退出，未更新配置或查看密钥。

请求 ID 的时间部分对应北京时间约 15:20:18.477，至 APP 15:22:23 约 124.5 秒；后台则在约 140 秒后才记录上游 503。公网 `api.jiucaihezi.studio` DNS 此时解析为 Cloudflare 地址，而供应商 `aimanplay.cn` 解析为非 Cloudflare 地址。[Cloudflare 官方 524 说明](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/cloudflare-5xx-errors/error-524/)列出的默认 Proxy Read Timeout 为 125 秒。由此高度怀疑公网 Cloudflare 先结束同步连接，使 APP 收到 524，随后 NewAPI 才收到供应商 503。尚未取得此次完整 524 页面中的 Host／Ray ID，不能把具体超时节点或同一请求关联当作已独立证实。

目前需要处理的两项服务问题：

1. 菠萝恢复渠道凭据对应的 `gpt-image-2` 兼容账号可用性；这条错误无法靠 APP 重试、改下载或增加轮询解决。
2. 韭菜盒子公网入口需要支持菠萝的同步长请求。文档要求客户端与服务端最长等待 1800 秒，APP 当前图片请求为 300 秒，而普通 Cloudflare 代理的读取时限更短。仅把 APP 超时改为 1800 秒不能解决外层 524。应在核实生产入口后选择支持长请求的媒体入口，或服务端转换为持久异步任务；不能直接假定整个 API 域名可取消代理，其 `/auth/*`、`/sync/*` 等仍有 Worker 路由。

本轮仅追加排障证据，未实施生产入口调整、供应商账号恢复或新的运行时代码修复。

## APP 的独立缺陷与最小修复

`src/api/media-generation.ts` 的 JSON 请求将绝大多数 503 响应正文丢弃，multipart 请求将全部 503 正文丢弃，统一显示“服务暂时不可用 (503)，请稍后再试”。这隐藏了此次上游的明确原因。

修复：两种请求均保留 HTTP 状态和响应正文前 200 字；空响应仍保留现有提示，NewAPI 无渠道提示保留并附原文。不增加自动生成重试，避免重复提交付费任务。
