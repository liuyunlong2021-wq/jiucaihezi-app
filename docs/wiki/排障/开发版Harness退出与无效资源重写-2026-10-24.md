# 开发版 Harness 退出与无效资源重写

日期：2026-10-24。状态：已修复确认的无效资源写入、加载失败误报与退出信息缺失；截图原场景复测待完成，未发布。

## 现象与证据边界

用户截图显示「还没有对话」「DeepSeek Harness 已退出」，用户确认来自开发版窗口。

- `deepSeekHarness.ts` 的 transport `onclose` 触发这条错误，原来只取 stderr，丢弃已有的退出码与信号。截图没有这些信息，无法确定当次退出原因。
- `MemoryWorkbench.vue` 打开项目时先清空当前对话；会话发现失败后只写 `error`，无对话分支仍显示「还没有对话」。这不能证明持久历史被删除。
- `/tmp/jc-tauri-dev-wiki-templates-20261024.log` 当日记录大量 `dsh-sdk-jsonrpc-server/lib/index.js changed. Rebuilding application...`，也记录页面重载与旧 realm 回收。它们是开发链路干扰证据，不足以直接归因截图那次退出。

## 确认的根因与修复

Harness 准备脚本在内容完全相同时仍对 SDK server、Skill 注册、生产服务与 Agent loop 执行 `writeFileSync`。重复执行准备与补丁测试会更新资源文件，触发 Tauri dev watcher 重启 App。

复现先在临时 SDK fixture 中应用补丁，再把六个目标文件的时间固定到过去，再次执行准备：修复前五个文件的修改时间被更新，断言失败。修复后统一比较内容，只在实际变化时写入，六个文件修改时间均保持不变。保留真正资源变化后的正常重编译。

另外区分项目加载中、加载失败和无对话三种状态；失败显示「重新加载对话」，重走现有项目发现链路。不会自动重复发送生成消息，不新增第二套会话存储、抢锁或强杀机制。退出错误保留已有退出码、信号和 stderr 尾部，便于继续查证。

## 后续：重新加载仍失败，确认历史 3D 偏好兼容缺口

用户再次截图显示 `jiucaihezi_session_ui` 的 `preferences` 记录不符合 schema。只读定位到小胖宣传片项目对应的 `jc-v1-conversation-8de65abe-3e7a-4efb-a285-f4ff1e8d985e.json`：记录包含 `manju`、`novel`、`shortDrama` 与 `scene3d: { enabled: true }`。当前 v1 schema 漏掉历史 `scene3d`，又使用 `.strict()`，使整个 domain 打开失败，点击重载会重复遇到同一记录。该次错误已可具体归因，不能用开发版无效重启解释。
