# FK 视频参考图 R2 上传与系统代理连接中断

## 合同卡与范围

用户报告 FK H3 图生视频 `HTTP 请求失败: error sending request`，要求紧急排查。沿用既有 NewAPI 授权、R2 预签名 PUT、视频提交及 content 取回，不修改渠道、模型、价格、凭据或新增代理。修复仅让固定 R2 临时参考素材 PUT 绕过系统代理，保留其余桌面网络能力。

## 证据与根因

- 本机任务 `mtask_mvrtnv61_mj80`：15:57:51 创建，15:59:53 失败，约122秒；再次提交 `mtask_mvrur95g_mgbi`：16:28:29创建，16:29:25失败，约56秒。均无轮询地址，失败阶段 submit。第二次没有达到120秒，不能将全部失败解释为超时。
- 开发日志在两次失败前均出现 `/__jc_api/api/creations/r2/upload-url`。调用链先完成参考图上传，再 `POST /v1/videos`。原图6291298字节，单张图片。
- 当前授权、小文件及原图 curl PUT 返回200；小文件约1秒，原图无显式代理约12秒、显式本机HTTP代理约1.8秒。curl成功不能证明App原生上传正常。
- 使用本机App已编译的reqwest 0.12.28库、同一原图和新鲜签名URL复现：默认请求超时；显式代理出现 `connection closed before message completed`；另有 `Connection reset by peer (os error 54)`。这些底层原因原先被 `.without_url()` 的顶层 Display 隐藏。
- 对照：同一Rust实现 `.no_proxy()` 连续两次200（约2.47秒、3.70秒），中间显式 `http://127.0.0.1:7897` 上传失败（约19.8秒，连接提前关闭）。默认路径另两次20秒超时。系统代理配置为127.0.0.1:7897。加User-Agent并不能稳定修复，不采用该方案。

已定位的故障边界是 **Rust经过本机代理的R2上传连接**；未定位代理软件/网络内部为什么关闭该连接。没有证据指向Workers套餐额度或FK模型参数，升级Workers不解决此断点。

## 修复与验证边界

- Rust只对HTTPS、固定R2域名、`/jiucaihezi-media-test/creation-temp/`下的PUT禁用代理；GET、NewAPI请求及其他主机不变。
- 复用既有 `download_error_detail` 保留HTTP请求底层错误链并移除签名URL；JS补上申请授权或R2上传阶段，保留AbortError取消语义。
- JS媒体运行时59项通过，TypeScript检查通过。Rust HTTP专项19项通过，git diff --check通过；开发版自动重编译与重载，用户随后确认开发版重试生成成功。
- G0/G1：合同与自动化回归；G2：本机实际授权/同图上传对照；未调用收费视频模型，未核对账单，未发布安装包，Windows/Intel实机及安装包发布后的App完整图生视频待验。不能将本机上传对照扩写为全渠道验收。
