# 3D 编辑器空白与高度为零（2026-08-17）

> 状态：已在当前 `pnpm tauri dev` 真实窗口中修复并由用户确认。

## 现象

- 点击白模编辑器后，有时完全打不开；有时只出现预览外壳，内部高度为 0，场景、人物和工具全部不可见。
- 连续调整布局、组件 `key` 或状态变量名都不能稳定解决，甚至会让“还能打开但高度为 0”退化为完全打不开。
- 这不是 `.jcscene` 内容丢失，也不是单纯 CSS 高度问题。

## 完整根因链

### 1. 开发版曾加载旧前端资源

`src-tauri/src/lib.rs` 使用了无效的 `#[cfg(dev)]`，导致 `pnpm tauri dev` 仍可能从 `tauri://localhost` 加载旧 `dist`，源码修改看似没有生效。

修复为 Rust 标准的 `#[cfg(debug_assertions)]` 后，Debug App 才稳定连接 `http://localhost:1420`。排障时必须先确认当前窗口实际加载 Vite，不能用已安装旧包或重新构建的 App 代替当前开发窗口。

### 2. 人物骨骼仍含 Vue 响应式代理

真正导致编辑器挂载失败的是 `parseScene3DDocument()` 内的 `quaternion()`：它完成校验后直接返回输入四元数数组。人物数据来自 Vue 响应式场景时，`character.bones.*` 因此仍是 Proxy。

编辑器初始化撤销历史时执行：

```ts
structuredClone(document)
```

WebKit 无法克隆 Proxy，首先抛出：

```text
DataCloneError: The object can not be cloned.
```

`setup()` 随即中止，组件的 `setupState` 为空；模板继续渲染后又抛出变量 `undefined`。界面最终只剩外壳，所以看到的“高度为 0”和模板变量错误都是连锁症状，不是根因。

## 最小修复

共享解析器只改一行，让骨骼四元数返回普通新数组：

```ts
return [...result]
```

不增加 CSS 高度补丁、重试、第二套场景状态或兼容层。所有进入 `.jcscene` 编辑、撤销历史和增量编辑的调用者都通过同一个解析入口获得可克隆纯数据。

回归测试必须包含响应式人物与嵌套骨骼，并验证：

```ts
assert.doesNotThrow(() => structuredClone(scene))
```

普通人物场景没有 `character.bones`，旧测试因此没有覆盖到这层嵌套 Proxy。

## 成功排障经验

1. 先确认运行的是当前源码：检查 Debug WebContent 是否连接 Vite；不要通过构建新 APP 来验证 `tauri dev` 问题。
2. 保留同一次挂载的错误顺序。最后看到的模板 `undefined` 可能只是第二个异常；本次第一条异常才是 `DataCloneError`。
3. 当组件 `setupState` 为空时，应优先查 `setup()` 是否提前抛错，不要继续改模板变量名。
4. 高度为 0 可能是子组件根本没有挂载。先查运行时异常，再查 CSS。
5. 修共享数据边界，不修每个调用者。解析器返回纯数据后，撤销、保存、动画和编辑链路同时恢复。
6. 自动测试必须覆盖真实数据形态。本次关键差异是“响应式对象 + 人物骨骼嵌套数组”，只有普通积木场景不足以防回归。
7. 运行态验收使用用户已经打开的开发窗口，并记录可核查尺寸和错误状态，不以类型检查通过代替真实渲染。
