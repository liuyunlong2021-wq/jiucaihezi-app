# 3D 角色坐姿未应用与 Agent 增量姿态接口修复

> 2026-10-19；源码修复，安装版与真实模型回合待验收。

## 现象与证据边界

用户截图中 Agent 声称九人均设为 sitting，但多数真实人物仍站立，9 号经用户手动切换后坐下。没有读取用户原始场景文件和工具调用记录，不能断言当次只改了名字，或确认每个对象最终字段。

## 根因

- 创建工具及 `.jcscene` 校验接受 `pose`，基础几何人物读取它；但 `Scene3DEditor.hydrateCharacter` 加载 Storyboarder 模型后只恢复 `character.bones`，忽略对象 `pose`，导致文件中的 sitting 与画面脱节。
- 编辑器手动姿态按钮直接把预设写为骨骼四元数，因此手动有效。
- `edit_3d_scene` 原来只暴露新增、移动、删除和镜头，没有修改已有对象的姿态与旋转操作；混入已有操作的额外字段此前会被忽略。

## 修复合同

- Storyboarder 加载时先恢复绑定骨骼，再使用编辑器已有 sitting / crouching / lying 预设，最后恢复明确保存的手动骨骼。默认 standing 保持旧绑定姿态，已有手工编辑继续保留。
- 增量新增 `{action:"pose",target:"角色ID",pose:"sitting"}` 与 `{action:"rotate",target:"座椅ID",to:[0,3.141592653589793,0]}`；旋转为对象绝对 XYZ 欧拉弧度，仅支持独立对象。
- 明确换姿态时清除旧手动骨骼，避免旧姿态覆盖新要求；位置不变，需要用 move 配合座面高度与方向。标签不代表姿态。
- 不支持的操作字段报错，整批验证成功后仍只写回一次，失败不部分写回。
