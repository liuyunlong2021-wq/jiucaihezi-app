# 创作面板异步保存方法缺失（2026-08-13）

> 状态：根因修复、代码审计、Web 交互回归和 Desktop 构建审计完成；真实 Desktop 安装包点击待发布后验收。

## 现象

- 创作任务完成后出现：`创作画布保存失败: ...flushCanvasSave is not a function`。
- 创作面板随后无法正常打开、收起或随项目切换。
- 这是 App 前端组件时序错误，不是项目、画布或生成素材损坏。

## 根因

`MemoryWorkbench` 通过 `defineAsyncComponent` 按需加载 `CreationPanel`。组件刚挂载或正卸载时，Vue ref 可能已经存在，但异步子组件还没有通过 `defineExpose` 暴露 `flushCanvasSave()`。

旧调用只保护 ref 不为空：

```ts
await creationPanelRef.value?.flushCanvasSave()
```

因此 ref 是临时组件代理、方法尚不存在时仍会强制调用，抛出 `is not a function`，并中断关闭、切项目等后续流程。旧 TypeScript 类型又把该方法声明为必定存在，掩盖了真实运行时状态。

## 最小根治

- 将组件 ref 合同改为 `flushCanvasSave?`，准确表达异步加载期间方法可能尚未暴露。
- 外层统一使用方法级可选调用：`await creationPanelRef.value?.flushCanvasSave?.()`。
- 子组件加载完成后仍执行原有保存；尚未加载完成时没有可保存的画布，跳过调用并继续生命周期流程。
- 不修改 `CreationPanel` 内部保存、画布 owner、任务 gate 或持久化逻辑。

## 防复发门禁

`memoryWorkbench.test.ts` 同时锁定三件事：

1. ref 类型中的 `flushCanvasSave` 必须可选。
2. 外部调用必须同时保护 ref 和方法。
3. `creationPanelRef.value?.flushCanvasSave()` 这种不安全调用不得重新出现。

仓库审计确认，`CreationPanel` 外部只有这一处 `flushCanvasSave` 调用；子组件内部调用均发生在自身代码作用域内，不存在“方法尚未暴露”的问题。

## 下次排查

看到 `xxx is not a function` 且目标来自异步 Vue 组件 ref 时：

1. 用 `rg` 搜索全部调用者和 `defineExpose`，先区分“方法根本不存在”与“异步时序中暂时不存在”。
2. 检查是否只写了对象级可选调用 `ref.value?.method()`；这不保护方法本身。
3. 对异步组件代理使用 `ref.value?.method?.()`，并让 TypeScript 类型同步标为可选。
4. 在调用方增加禁入测试，防止以后恢复成强制调用。
5. 连续快速打开、收起面板并检查错误日志；再跑类型检查和目标平台构建。

不要在每个按钮或入口分别加 `try/catch`，也不要吞掉已加载画布的真实保存失败；根因只在共享生命周期调用处修一次。
