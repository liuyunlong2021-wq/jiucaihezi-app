# MCP 选择器卡顿与候选按入口加载

> 日期：2026-10-07 · 目标版本：v2.2.19

## 根因与官方对照

输入框的 `@MCP` 芯片属于韭菜盒子的 UI。原先点击它调用 `mentionOnInput('mcp__')`，共用候选函数先等待 Skill 目录、整理全部 Skill，再以 `mcp__` 搜索项目文件，最后才返回内存中的 MCP 候选。

桌面 `files.searchPaths` 调用 `dev_search_project_paths`。该命令递归遍历项目目录，40 是匹配结果上限，不是扫描条目上限；查询没有命中时仍遍历全部目录。MCP 候选因此等待一次不需要的项目搜索。选择器初始化和关闭时的 `clear()` 也会重新加载候选，原先没有关闭状态的加载边界。

对照项目安装的官方 `@deepseek-ai/dsh-client-ui-input-trigger@0.2.0-rc.2`、`dsh-file-reference-local` 与官方仓库：候选按 source 注册；专用 launcher 可以只打开一个 source；过期请求通过 generation 和 AbortSignal 管理。文件候选由独立 provider 提供索引、缓存与失效。MCP 插件在运行时连接和发现工具，不要求输入候选先搜索项目。

- [官方输入触发器](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/ui-input-trigger/README.md)
- [官方本地文件候选](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/context/file-reference-local/README.zh.md)
- [官方 MCP Client](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/mcp/mcp-client/README.md)

## 精准修复

- `MemoryWorkbench.vue` 使用 `mentionScope = all / skill / mcp` 明确入口。MCP 芯片以空查询打开 MCP 范围，从 `mcpStore.allMcpTools` 生成服务器候选，在任何异步加载之前返回；兼容手打的 `mcp__` 查询。
- 弹层关闭时候选直接为空，初始化与清空不再触发目录加载；等待 Skill 目录期间关闭或切换入口，返回后停止后续项目查询。
- Skill 入口保留专用候选与过滤。普通手打 `@` 保留工具、Skill、MCP 与项目文件；正在使用专用入口时继续按该入口过滤。
- 复用 `useFilteredList` 的请求版本校验和清空行为，阻止关闭或切换后旧结果覆盖弹层。综合列表中选中 MCP 总入口后保持 MCP 选择器打开。
- 不改 MCP 连接、授权、调用、会话挂载及桌面能力；不引入文件索引缓存或第二套 UI 框架。
