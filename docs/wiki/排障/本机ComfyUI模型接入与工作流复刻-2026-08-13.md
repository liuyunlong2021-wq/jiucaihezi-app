# 本机 ComfyUI 模型接入与工作流复刻

> 日期：2026-08-13
> 状态：Z-Image Turbo 已在 macOS Desktop 开发版完成真实生成验收；本页是后续接入本机 ComfyUI 模型的实施与排障基线。

## 已确认的链路

韭菜盒子 Desktop 的创作面板可把本机模型作为 `local-comfy` 路由提交：`/prompt` 提交工作流，`/history/{prompt_id}` 等待完成，`/view` 读取结果；桌面端再下载结果并写入项目媒体。

本机实际 ComfyUI 地址为 `http://127.0.0.1:8000`，不是常见默认示例端口 `8188`。旧保存的 `8188` 值需要迁移为 `8000`，否则会在提交阶段失败。

Z-Image Turbo 在创作面板提供 `720p`、`1080p` 及 `16:9`、`9:16`、`4:3`、`3:4`、`1:1`。运行时把两项转换为 8 的倍数宽高后写入 ComfyUI 的 `EmptyLatentImage`。

## 接入规则

1. 先在 ComfyUI 手工运行目标工作流，确认模型文件、LoRA、采样器、正负提示词、尺寸和保存节点均可成功，再导出 API 工作流作为事实来源。
2. App 不按模型名重新拼一套“看似相同”的最小工作流。必须保留手工工作流里已经验证的节点、连线和参数，只替换用户真正需要填写的节点。
3. 为每个接入模型明确输入映射：提示词写入哪一个文本节点，比例/分辨率写入哪一个尺寸节点，参考图或视频写入哪一个输入节点。没有确认映射前不在 UI 暴露该模型。
4. 固定工作流中其余值原样保留，包括 LoRA 顺序与强度、负面提示词、采样器、scheduler、VAE、保存节点和文件名前缀；它们不是可随意删减的实现细节。
5. 后续 MiniMax H3 或其他模型按同一方法独立接入，不能复用 Z-Image 的节点 ID、模型文件名或工作流假设。

## Z-Image Turbo 已验证映射

当前本机工作流使用：

| 用户输入 | ComfyUI 节点 | 写入字段 |
| --- | --- | --- |
| 提示词 | `CR Text (47)` | `text`，再连到 `CLIPTextEncode (24)` |
| 分辨率与比例 | `EmptyLatentImage (21)` | `width`、`height` |

已保留的已验证节点：`UNETLoader (18)`、`LoraLoaderModelOnly (23 -> 14)`、`CLIPLoader (12)`、`VAELoader (11)`、正负 `CLIPTextEncode (24/16)`、`KSampler (22)`、`VAEDecode (17)`、`SaveImage (46)`。

`KSampler` 的已验证参数为 `steps=4`、`cfg=1`、`sampler_name=dpmpp_2s_ancestral`、`scheduler=simple`、`denoise=1`。随机种子使用 ComfyUI 同级的大整数范围；低范围旧种子会显著放大 4 步 Turbo 工作流的成片波动。

## 本轮错误与根因

| 现象 | 根因 | 已采用的处理 |
| --- | --- | --- |
| `/prompt` 请求失败 | 本机 ComfyUI 实际运行在 `8000`，App 保留了旧的 `8188` | 统一默认值并迁移旧保存地址 |
| 任务已完成但 App 报 `The string did not match the expected pattern.` | WebKit 前端 Blob/Base64 转换与后续保存链路不兼容 | 返回受限的本机 `/view` 地址，由 Desktop 后台下载并落盘 |
| 能生成但画面不按既有工作流表现 | 初版手写最小节点图，遗漏 `CR Text`、LoRA 和原负面提示词 | 改为复刻真实 API 工作流，只覆盖提示词和尺寸输入 |
| 修改后仍像旧版本 | 孤立的旧 Tauri 调试窗口失去 Vite `1420` 服务，无法热更新 | 重启 `pnpm tauri:dev`，并用运行中前端模块确认实际加载代码 |
| 同一提示词结果差异大、部分图发糊 | 采样参数并未缺失；随机种子不同，旧窗口还在使用低范围种子 | 以 ComfyUI 已成功种子做 A/B 对照，确认工作流正确后重启到新种子实现 |

提示词中出现不可见控制字符时，应先记录提交到 `/history` 的真实文本再判断；本轮它不是采样器或连线缺失的证据。不得仅凭成图肉眼判断节点是否接通。

## 最小验收顺序

1. `GET /system_stats`、`/object_info` 和所需模型列表均可读；记录真实端口与运行设备。
2. 手工 ComfyUI 与 App 使用同一提示词、同一尺寸、同一种子提交；比较 `/history` 中的完整节点 JSON。
3. 两份 JSON 除允许替换的输入节点与 `client_id` 外应一致；不一致时先修映射，不调采样参数。
4. 确认 `/view` 返回有效媒体，Desktop 项目目录已落盘，任务状态为成功。
5. 才允许开放随机种子；随后以多次随机生成观察模型正常波动，不把单张坏图误判为节点断链。

## 验证与边界

- 已通过：本机 ComfyUI `0.32.0`、MPS、Z-Image Turbo 的 API 提交、历史轮询、结果读取与用户真实 Desktop 成图验收；TypeScript、`localComfyRuntime`、`comfyUiRuntime` 和 URL 安全定向测试通过。
- 未通过/未做：MiniMax H3 及任何其他 ComfyUI 工作流尚未接入；Web、Mobile 不暴露本机 ComfyUI；未构建或发布三平台正式包。
