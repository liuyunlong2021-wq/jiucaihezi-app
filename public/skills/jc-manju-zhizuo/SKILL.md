# jc-manju-zhizuo｜漫剧制作路由器

用户选用本 Skill 后，在当前漫剧任务及其后续同一创作流程中，只从下表十个 Skill 选择业务流程，直到用户明确更换路线。普通文件、图片读取和影音提交工具仍可使用。表中的相对路径固定指向本路由器所在的同一套 Skill 目录；不要因名称相似改选其他业务 Skill。

| --- | --- |

## 从当前材料接手

- 先判断用户本轮要的交付物、目标集数与已有材料，只读取本轮必需的 Skill。用户明确已有的方向、剧本、参考图和提示词可直接作为输入，不强制补跑前面的阶段、不重新询问已给出的选择。
- 用户说“从风格开始”就进入风格；有参考图只要排版就进入 `jc-juese-geshi`；有工程台本只要视频提示词就按用户本轮指定模型进入对应入口；已有完整提示词只要提交就走提交规则，不重写提示词。
- 缺少真正影响本轮交付的输入时才询问该缺口。已有材料即使没有本路线规定的文件名，也按内容复用。
- 用户选择的十个业务入口不能覆盖的专门流程，说明缺口并请用户决定路线，不悄悄加载名单外 Skill。

## 完整项目的默认衔接

1. **项目资料**：用 `jc-xiangmuziliao` 整理原作。项目内保存故事梗概、分集梗概、故事背景、世界规则各一份文档，每个人物独立一份小传；人物关系放在对应小传里。沿用原集数，小说暂拟分集须标注建议状态。
2. **创作方向**：用 `jc-film-style` 讨论并落实画幅、国家地域、时代、成片媒介、节奏、视觉、摄影机、剪辑及表演风格。表演风格须写情绪外化程度、对白方式、身体动作幅度、潜台词和人物差异；用户已有明确选择时直接采用。后续步骤共同读取已确认方向。
3. **小说落笔，按需执行**：仅有小说、梗概或故事素材而需要工程台本时，用 `jc-duanju` 写出分场文学源稿。把目标集的原文、相邻章节承接、分集任务、人物小传、背景规则及用户已指定的风格作为当前输入；保持原著大情节与跨集因果。已有可用剧本直接跳过。改编稿与原作资料分别标明依据，确认后的实际分集变化再同步到分集梗概。
4. **资产与工程台本可并列推进**：角色走所属环境中的单幅形象设计 → 用户选定／手动带入参考图 → 风格排版。角色环境图默认采用已定画风；真人生活照也是用户可选路线。场景、道具分别用各自 Skill。工程台本以完整原始／确认改编剧本为台词动作依据，以目标集梗概、相关人物小传、背景规则和创作方向为戏剧与表演依据；不必等待所有资产图完成。资产图获得后只核对具体外貌、空间与道具，不重写已确认剧情。
5. **视频提示词，逐镜／逐段选模型**：依据用户本轮指定的镜头或片段、工程台本、实际参考素材及已定方向选择 `h3-prompt-writing` 或 `jc-seedance`。前面的资料、风格、资产与工程台本共同复用；生成模型不绑定整部项目或整集。保留完整对白、动作、人物状态、空间和声音连续，具体路由见下节。

完整项目先定统一资料和方向，再按用户指定集数推进。提示词是可独立交付的产物，完成文字工作不会自动触发付费生成。

## 视频模型自由路由

- 本轮用户明确指定的模型与镜头范围优先于界面默认值、上轮选择及项目历史。支持同一集、同一请求里分别给不同镜头或片段指定不同模型；不能以已经选过模型为由拒绝切换。
- MiniMax H3 → `h3-prompt-writing`；Seedance 2.5／SD2.5 → `jc-seedance`。同一请求包含两种模型时分别输出对应提示词，并在文件名或提示词外标明镜头范围和目标模型，不将两套格式揉成一条提示词。口述名称不明确时仅在无法判断目标模型的情况下询问。
- 界面默认模型只是本轮未点名片段的后备选择；没有默认且当前要写视频提示词时才询问要哪个模型。其他制作阶段不必先选视频模型，不自行推荐或替用户挑选模型。
- 仅转换用户指定范围。切换模型从同一工程台本及资产重新表达该范围，已有另一模型的提示词保留；不要求重做项目资料、风格、资产或工程台本。
- H3 片段按自然切点与 4–15 秒合同处理；H3 输入模式及参考标签取决于实际素材。Seedance 片段按用户要求及所选具体型号的真实时长、素材数量和参数能力处理，不套 H3 时长和字段。
- 工程台本作为确认的创作依据，保留台词、动作、表演因果、镜头顺序、空间连续与段间承接。提示词时间戳按用户习惯及目标 Skill 合同：`jc-seedance` 可有或无时间戳，用户明确要求优先；不因工程台本带时间码就强制成品带时间戳。H3 按其自身格式合同表达时间。内部始终核对时长和节奏负荷。
- 全片时间与片段内时间分别记录，不更改工程台本的全片时间。提交前核对提示词目标模型与实际提交型号属于同一系列；不把 H3 提示词直接当 Seedance 提示词提交，反之亦然。

## 角色的两步分工

- `jc-juese-sheji` 接收相关人物小传、故事背景、世界规则和已确认画风，设计一个角色在所属环境中的形象、造型与当下状态。环境与光影帮助人物成立，面貌或关键身份部位和造型须清晰可读；不套三格、中灰背景或无头人台。角色类型与画风分别处理，原作年龄、身份、形体与用户指定属性优先。
- `jc-juese-geshi` 接收已选定参考图、画幅和目标画风，只处理身份一致的排版与风格，不重新随机设计脸、发型、身材、服装。已有合适参考图时直接进入这一步。
- 环境图未显示的背面或隐藏结构须标明未定，不能当成参考图已锁定的事实。四足、蛇形等非人角色可由 `jc-juese-sheji` 设计，但现有 `jc-juese-geshi` 人形模板不适配时须说明版式缺口，先保留环境图或按用户明确需求适配版式，不改成类人身体来套模板。
- `jc-shuaigemeinv` 保留为独立写真 Skill，已移出本路由的十个业务入口；本漫剧流程的角色设计统一进入 `jc-juese-sheji`。

## 图片与视频：仅提交，不等待

- 默认只写／整理提示词。用户明确要求“提交”“生图”或“生成视频”时，使用当前可用的异步影音提交工具，不调用会阻塞到成片完成的替代工具。
- 韭菜盒子工具可用时，读取 `get_creation_context` 与 `list_creation_models` 返回的实际上下文、模型与字段，按真实 schema 把提示词、参考媒体和参数一起传给 `submit_creation_task`。不虚构模型ID、价格、接口字段或参考图数量限制。
- 每个任务使用稳定的 `requestId`；同次提交重试沿用同一ID，避免重复付费。收到任务号后立即记录模型、目标角色／集／镜头或片段和状态“已提交到产品队列”，报告任务号并结束该任务的提交阶段。返回本地任务号不代表上游已接收或生成已成功。
- 提交后不调用 `get_creation_task`、历史列表或等待工具轮询，不主动下载、验收或拼接结果，不启动定时查询。用户后来要求查某个任务时才读取一次当前状态；自动持续跟踪仍需用户明确要求。
- 产品内部后台处理不由 Skill 改动。当前工具没有异步提交能力时，交付提示词、参考素材及参数供手动提交，并说明能力缺口；不伪称已提交、不自建媒体API或轮询脚本。
- 后续步骤需要生成结果时，等待用户带入／选定图片后再继续依赖它的工作；可先完成不依赖结果的工程台本和其他文字任务，不用重复查询来推动流程。

## 文件与续做

在有明确项目目录的多轮制作中，用一份简短的 `制作进度.md` 记录目标集、已完成产物路径、用户已确认的方向、各镜头／片段已指定的模型与提示词路径、待补材料及提交任务号。仅作索引，不复制原作或整份提示词；单项临时请求不强建项目目录与进度文件。

用户改动人物、风格或某集剧情时，指出相关资产、工程台本与提示词的受影响范围，按本轮要求更新。已有确认材料作为后续依据；各 Skill 的默认制作顺序、画幅、媒介和节奏服从用户明确选择，不额外插入声音或其他分镜 Skill。
