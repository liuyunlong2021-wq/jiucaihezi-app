# jc-manju-zhizuo｜漫剧制作路由器

用户选用本 Skill 后，在当前漫剧任务及其后续同一创作流程中，只从下表十个 Skill 选择业务流程，直到用户明确更换路线。普通文件、图片读取和影音提交工具仍可使用。表中的相对路径固定指向本路由器所在的同一套 Skill 目录；不要因名称相似改选其他业务 Skill。

| 当前要交付的内容 | 唯一入口 |
| --- | --- |
| 原作故事梗概、分集梗概、每人人物小传、故事背景、世界规则 | [jc-xiangmuziliao](../jc-xiangmuziliao/SKILL.md) |
| 把小说或故事素材落成可拍摄的短剧文学剧本，或用户要求的剧本修订 | [jc-duanju](../jc-duanju/SKILL.md) |
| 确定比例、国家地域、媒介、视觉／摄影／剪辑／表演风格、节奏与空间方向 | [jc-film-style](../jc-film-style/SKILL.md) |
| 单个角色在所属环境中的形象、造型与状态，支持真人、二维、三维及非人角色 | [jc-juese-sheji](../jc-juese-sheji/SKILL.md) |
| 把选定人物参考图转为指定画风和横竖屏三格排版的中文图生图提示词 | [jc-juese-geshi](../jc-juese-geshi/SKILL.md) |
| 空镜场景设定图、生图提示词和空间结构 | [jc-scene-prompt](../jc-scene-prompt/SKILL.md) |
| 剧情道具设定图、生图提示词和多视图资产 | [jc-prop-prompt](../jc-prop-prompt/SKILL.md) |
| 把文学剧本或分场文本改为逐镜、带连续时间码的工程台本 | [jc-gongchengjuben](../jc-gongchengjuben/SKILL.md) |
| 用户本轮指定 MiniMax H3 的视频提示词 | [h3-prompt-writing](../h3-prompt-writing/SKILL.md) |
| 用户本轮指定 Seedance 2.5／SD2.5 的导演视频提示词 | [jc-seedance](../jc-seedance/SKILL.md) |

## 路由优先级

按以下顺序处理本轮请求，只读取命中入口的正文及其必要资源：

1. **明确指定 Skill 或模型**：直接执行清单内指定入口。H3 对应 `h3-prompt-writing`；Seedance／SD2.5 对应 `jc-seedance`。本轮明确指定优先于历史；Skill、模型或交付物实质冲突时只澄清冲突，不擅自替换。
2. **明确续改已有产物**：使用该产物对应的 Skill 和原格式。“继续修改刚才那份”不触发模型转换；新任务不继承上次模型。
3. **明确指定交付物**：用户不用记 Skill 名。“整理故事资料”“写短剧”“定画风”“设计角色”“三格参考图”“设计场景”“设计道具”“工程台本”分别对应上表入口，不落入 H3 默认。
4. **明确求起步引导**：只有“不知道从哪开始”“第一次做”“带我做”等明确请求才进入下节，不因消息短或材料少判断用户是新手。
5. **其余未指定创作请求**：默认使用 `h3-prompt-writing` 生成 MiniMax H3 视频提示词，不询问默认模型。

只完成用户要求的任务，不自动补跑其他制作阶段；明确要求多个任务时才按必要依赖使用多个入口。已有资料、方向、剧本、参考图和提示词按内容复用，不要求固定文件名。已有提示词只要提交时不重写。缺少实质影响当前交付的输入才询问，其余采用目标 Skill 默认规则并标明必要假设。清单不能覆盖的专门流程说明缺口，请用户决定，不加载名单外业务 Skill。

## 新手起步

先利用已有消息与附件；不知道现有材料时只问：“你手上已经有故事、小说或剧本了吗？没有的话，说一句你想拍的故事也可以。”根据材料与目标推荐当前一步：

| 材料与目标 | 起点 |
| --- | --- |
| 一句想法，先试做一个片段 | `h3-prompt-writing` |
| 小说或长故事，要分集漫剧 | `jc-xiangmuziliao` |
| 想法或梗概，要先写剧本 | `jc-duanju` |
| 已有剧本，需要视觉与表演方向 | `jc-film-style` |
| 剧本和方向齐备，需要逐镜拍摄安排 | `jc-gongchengjuben` |
| 已有镜头或台本，要视频提示词 | 默认 H3，明确 Seedance 则用 `jc-seedance` |

只问“该从哪开始”时给一个建议和简短理由，不执行制作；明确“带我做”且材料足够时执行推荐的第一步，不自动推进整套流程。引导不授权付费生成。对外用产物名称而非要求记住 Skill ID；完成后必要时给一个下一步建议，不执行、不每轮重复教学。

## 资料依赖，不是执行顺序

- 项目资料分别保存故事梗概、分集梗概、故事背景、世界规则，每个人物独立一份小传并记录关系；原作事实、推断、改编建议和已确认设定须区分。
- 后续任务复用已确认的创作方向；改编稿与原作分开，确认的分集变化再同步到分集梗概。已有可用剧本不重写。
- 工程台本复用剧本、分集任务、人物资料、世界规则和创作方向，不要求先生成资产；后来补入参考图只校准外观、空间和道具，不擅改剧情。
- 上述依赖不授权调用其他 Skill 或创建缺失的整套资料。当前交付所需材料不足时只问必要缺项。

## 视频模型自由路由

- 本轮用户明确指定的模型与镜头范围优先于历史。支持同一集、同一请求里明确给不同镜头或片段指定不同模型；不能以已经选过模型为由拒绝切换。
- MiniMax H3 → `h3-prompt-writing`；Seedance 2.5／SD2.5 → `jc-seedance`。同一请求包含两种模型时分别输出对应提示词，并在文件名或提示词外标明镜头范围和目标模型，不将两套格式揉成一条提示词。口述名称不明确时仅在无法判断目标模型的情况下询问。
- 没有提示词模型选择器。按路由优先级，续改原产物保留原格式；新的未指定视频提示词默认 H3，不要求用户先选模型，不锁定全项目模型。
- 仅转换用户指定范围。切换模型从同一工程台本及资产重新表达该范围，已有另一模型的提示词保留；不要求重做项目资料、风格、资产或工程台本。
- H3 片段按自然切点与 4–15 秒合同处理；H3 输入模式及参考标签取决于实际素材。Seedance 片段按用户要求及所选具体型号的真实时长、素材数量和参数能力处理，不套 H3 时长和字段。
- 工程台本作为确认的创作依据，保留台词、动作、表演因果、镜头顺序、空间连续与段间承接。提示词时间戳按用户习惯及目标 Skill 合同：`jc-seedance` 可有或无时间戳，用户明确要求优先；不因工程台本带时间码就强制成品带时间戳。H3 按其自身格式合同表达时间。内部始终核对时长和节奏负荷。
- 全片时间与片段内时间分别记录，不更改工程台本的全片时间。提交前核对提示词目标模型与实际提交型号属于同一系列；不把 H3 提示词直接当 Seedance 提示词提交，反之亦然。

## 角色的两步分工

- `jc-juese-sheji` 接收相关人物小传、故事背景、世界规则和已确认画风，设计一个角色在所属环境中的形象、造型与当下状态。环境与光影帮助人物成立，面貌或关键身份部位和造型须清晰可读；不套三格、中灰背景或无头人台。角色类型与画风分别处理，原作年龄、身份、形体与用户指定属性优先。
- `jc-juese-geshi` 接收已选定参考图、画幅和目标画风，只处理身份一致的排版与风格，不重新随机设计脸、发型、身材、服装。已有合适参考图时直接进入这一步。
- 环境图未显示的背面或隐藏结构须标明未定，不能当成参考图已锁定的事实。四足、蛇形等非人角色可由 `jc-juese-sheji` 设计，但现有 `jc-juese-geshi` 人形模板不适配时须说明版式缺口，先保留环境图或按用户明确需求适配版式，不改成类人身体来套模板。
- `jc-shuaigemeinv` 保留为独立写真 Skill，已移出本路由的十个业务入口；本漫剧流程的角色设计统一进入 `jc-juese-sheji`。

## 图片与视频：仅提交，不等待

- 默认只写／整理提示词。用户明确要求“提交”“生图”或“生成视频”时，使用当前可用的异步影音提交工具，不调用会阻塞到成片完成的替代工具。
- 韭菜盒子工具可用时，读取 `get_creation_context` 与 `list_creation_models` 返回的实际上下文、模型与字段，按真实 schema 把提示词、参考媒体和参数一起传给 `submit_creation_task`。不虚构模型ID、价格、接口字段或参考图数量限制。
- 每个任务使用稳定的 `requestId`；同次提交重试沿用同一ID，避免重复付费。收到任务号后立即记录模型、目标角色／集／镜头或片段和状态“已提交到产品队列”，报告任务号并结束该任务的提交阶段。返回本地任务号不代表上游已接收或生成已成功。
- 提交后不调用 `get_creation_task`、历史列表或等待工具轮询，不主动下载、验收或拼接结果，不启动定时查询。用户后来要求查某个任务时才读取一次当前状态；自动持续跟踪仍需用户明确要求。
- 产品内部后台处理不由 Skill 改动。当前工具没有异步提交能力时，交付提示词、参考素材及参数供手动提交，并说明能力缺口；不伪称已提交、不自建媒体API或轮询脚本。
- 后续步骤需要生成结果时，等待用户带入／选定图片后再继续依赖它的工作；可先完成不依赖结果的工程台本和其他文字任务，不用重复查询来推动流程。

## 文件与续做

在有明确项目目录的多轮制作中，用一份简短的 `制作进度.md` 记录目标集、已完成产物路径、用户已确认的方向、各镜头／片段已指定的模型与提示词路径、待补材料及提交任务号。仅作索引，不复制原作或整份提示词；单项临时请求不强建项目目录与进度文件。

用户改动人物、风格或某集剧情时，指出相关资产、工程台本与提示词的受影响范围，按本轮要求更新。已有确认材料作为后续依据；各 Skill 的默认制作顺序、画幅、媒介和节奏服从用户明确选择，不额外插入声音或其他分镜 Skill。
