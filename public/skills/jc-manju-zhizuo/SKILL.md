## 分镜图路线

用户要求“MiniMax H3四宫格／四格分镜图／成片级分镜图提示词”时，进入 `cinematic-four-panel-frames`，每格为继承资产、光影与画风的成片瞬间，不误入H3视频提示词入口。只交付分镜生图提示词、必要的参考绑定与映射表，不生成图片或视频。

用户要求“Seedance简笔分镜＋资产参考图”时，进入 `seedance-storyboard-assets`，分镜只控制镜头与动作，独立资产控制身份，最终画风按项目设定；不套成片级四格。仅请求普通Seedance视频提示词仍用 `jc-seedance`。已明确模型与交付物直接路由；只说分镜图且上下文无法确定两条路线时，再询问成片四格还是简笔宫格。

## 路由优先级

按以下顺序处理本轮请求，只读取命中入口的正文及其必要资源：

每轮工程台本新建、续写、修订或脑暴工程预览，都重新读取内置 `jc-gongchengjuben/SKILL.md`，单人对话和递物同时读取其 [镜头可见内容方法](../jc-gongchengjuben/references/shot-visibility.md)。先确定每镜主体、类型、可见身体与入镜物件，再只用该范围写正文；不能先写全场互动再口头声称删掉画外信息。单人画面段及表演括号不写画外人物名字、代称或所有格，物件入镜不代表递物者／持物人的手入镜，原台词不受此限制。默认过肩规格不带画外人物名；已锁定的具名规格不变，正文仍按单人范围。历史规则不代替当前文件，更新规则不授权重写未指定的确认产物。交付前将稿内每项角色、物件与动作对照可见清单，先实际改稿再输出。

用户明确要求把已有角色文字提示词“按格式整理”“按geshi格式”“转三格设定图”“改横竖屏三格排版”时，使用 `jc-juese-geshi`，不要求先生成角色图片。此类角色格式转换优先于普通续改路由，不继续交给原角色设计Skill重做人物。只说“改格式”但未指明对象时，先从上一份产物判断：角色三格由geshi处理，H3／Seedance视频格式由各自Skill处理；无法判断时只问要改哪种格式。

1. **明确指定 Skill 或模型**：直接执行清单内指定入口。H3 对应 `h3-prompt-writing`；Seedance／SD2.5 对应 `jc-seedance`。本轮明确指定优先于历史；Skill、模型或交付物实质冲突时只澄清冲突，不擅自替换。
2. **明确续改已有产物**：使用该产物对应的 Skill 和原格式。“继续修改刚才那份”不触发模型转换；新任务不继承上次模型。正在脑暴中的“A”“混搭”“继续”“后面按推荐”承接 `jc-manju-brainstorm` 的当前选择点；用户要求对已有产物脑暴时，仅该范围进入脑暴，保留其他已确认内容。
3. **明确指定交付物**：用户不用记 Skill 名。“整理故事资料”“写短剧”“定画风”“设计角色”“三格参考图”“设计场景”“设计道具”“工程台本”分别对应上表入口，不落入 H3 默认。“角色声音／音色／九维”进入 `jc-shengyin-sheji`，“声音导演／声音稿／对白音效编排”进入 `jc-shengyin-daoyan`。“脑暴”“给几个发展方向”“对白／招式／角色／场景／道具候选”“每句／每个动作给选项”进入 `jc-manju-brainstorm`；要求工程脚本／工程剧本／拍摄台本而只有灵感、画面或零散对白动作时，也进入该技能，选定后交接工程台本。已有完整剧本只要工程转换时直接进入 `jc-gongchengjuben`；不能仅因消息短强制脑暴。
4. **明确求起步引导**：只有“不知道从哪开始”“第一次做”“带我做”等明确请求才进入下节，不因消息短或材料少判断用户是新手。
5. **其余未指定创作请求**：默认使用 `h3-prompt-writing` 生成 MiniMax H3 视频提示词，不询问默认模型。

“设计角色面相／骨相／体相”“根据性格设计长相”“帅哥／美女写真”“人物肖像提示词”属于明确角色交付物，使用 `jc-juese-sheji`，不落入 H3 默认；该技能内部融合形体与写真参考，不加载名单外个人技能。用户要角色候选或脑暴时先用 `jc-manju-brainstorm`，选定后回到同一角色技能。

只完成用户要求的任务，不自动补跑其他制作阶段；明确要求多个任务时才按必要依赖使用多个入口。已有资料、方向、剧本、参考图和提示词按内容复用，不要求固定文件名。已有提示词只需整理时保留原文，不改写为媒体提交。缺少实质影响当前交付的输入才询问，其余采用目标 Skill 默认规则并标明必要假设。清单不能覆盖的专门流程说明缺口，请用户决定，不加载名单外业务 Skill。

用户在漫剧路线里要求完整原创短剧、小说改编方向或分集短剧文学剧本时，不从本清单挑选旧的 `jc-duanju`；告知用户切换输入区的“短剧写作”入口继续。文学剧本完成后，用户可以切回“漫剧制作”，再用 `jc-gongchengjuben` 生成工程台本。从灵感创作用户指定的工程片段由 `jc-manju-brainstorm` 在本路线承接，不要求先切到短剧写作。

## 新手起步

先利用已有消息与附件；不知道现有材料时只问：“你手上已经有故事、小说或剧本了吗？没有的话，说一句你想拍的故事也可以。”根据材料与目标推荐当前一步：

| 材料与目标 | 起点 |
| --- | --- |
| 一句想法，先试做一个片段 | `h3-prompt-writing` |
| 一句想法，要写工程脚本或逐节拍给选项 | `jc-manju-brainstorm` |
| 小说或长故事，要分集漫剧 | `jc-xiangmuziliao` |
| 想法或梗概，要先写短剧文学剧本 | 切换到“短剧写作”入口 |
| 已有剧本，需要视觉与表演方向 | `jc-film-style` |
| 剧本和方向齐备，需要逐镜拍摄安排 | `jc-gongchengjuben` |
| 已有镜头或台本，要视频提示词 | 默认 H3，明确 Seedance 则用 `jc-seedance` |

只问“该从哪开始”时给一个建议和简短理由，不执行制作；明确“带我做”且材料足够时执行推荐的第一步，不自动推进整套流程。引导不授权付费生成。对外用产物名称而非要求记住 Skill ID；完成后必要时给一个下一步建议，不执行、不每轮重复教学。

## 资料依赖，不是执行顺序

- 项目资料分别保存故事梗概、分集梗概、故事背景、世界规则，每个人物独立一份小传并记录关系；原作事实、推断、改编建议和已确认设定须区分。
- 后续任务复用已确认的创作方向；改编稿与原作分开，确认的分集变化再同步到分集梗概。已有可用剧本不重写。
- 工程台本复用剧本、分集任务、人物资料、世界规则和创作方向，不要求先生成资产；后来补入参考图只校准外观、空间和道具，不擅改剧情。
- 完整文学短剧由独立“短剧写作”入口完成；漫剧制作从已确认文学剧本继续进入风格、资产、工程台本或视频提示词，也可通过脑暴选定当前工程片段的对白与动作。脑暴过程中按当前需要读取风格、资产和工程技能，不自动生成缺失的整套资料，也不调用名单外短剧 Skill。

## 工程台本与视频提示词分工

- `jc-gongchengjuben` 负责导演决策：人物状态与潜台词、触发与反馈、表演过程、动作特效因果、景别机位、空间连续、声音切点及时间预算。确认台本是下游创作依据。
- `jc-seedance` 负责忠实转写、实际素材与声音绑定、模型适配和格式，不替工程台本补戏。表达缺口可等义澄清；导演缺口与模型限制须回指原镜头，按用户授权先修订工程台本再转换，不偷偷增删、重排或重设表演。
- 直接给故事请求 Seedance 提示词时，允许该 Skill 读取同套 `jc-gongchengjuben` 的导演规则与必要专项，在内部设计后只交付当前提示词；这项资源依赖不授权自动生成一份额外工程台本或串跑制作阶段。两者随同一内置包提供，不依赖个人 Skill 目录。

## 视频模型自由路由

- 本轮用户明确指定的模型与镜头范围优先于历史。支持同一集、同一请求里明确给不同镜头或片段指定不同模型；不能以已经选过模型为由拒绝切换。
- MiniMax H3 → `h3-prompt-writing`；Seedance 2.5／SD2.5 → `jc-seedance`。同一请求包含两种模型时分别输出对应提示词，并在文件名或提示词外标明镜头范围和目标模型，不将两套格式揉成一条提示词。口述名称不明确时仅在无法判断目标模型的情况下询问。
- 没有提示词模型选择器。按路由优先级，续改原产物保留原格式；新的未指定视频提示词默认 H3，不要求用户先选模型，不锁定全项目模型。
- 仅转换用户指定范围。切换模型从同一工程台本及资产重新表达该范围，已有另一模型的提示词保留；不要求重做项目资料、风格、资产或工程台本。
- H3 片段按自然切点与 4–15 秒合同处理；H3 输入模式及参考标签取决于实际素材。Seedance 片段按用户要求及所选具体型号的真实时长、素材数量和参数能力处理，不套 H3 时长和字段。
- 工程台本作为确认的创作依据，保留台词、动作、表演因果、镜头顺序、空间连续与段间承接。提示词时间戳按用户习惯及目标 Skill 合同：`jc-seedance` 可有或无时间戳，用户明确要求优先；不因工程台本带时间码就强制成品带时间戳。H3 按其自身格式合同表达时间。内部始终核对时长和节奏负荷。
- 全片时间与片段内时间分别记录，不更改工程台本的全片时间。交付前核对提示词目标模型与用户指定系列一致，不将H3与Seedance格式混用。

## 角色的两步分工

- `jc-juese-sheji` 接收相关人物小传、故事背景、世界规则和已确认画风，结合相术形体素材与帅哥美女审美设计角色五官、身材、稳定记忆点、造型和当下状态；每条提示词附媒介相容的不完美细节及两个到三个随机灵感词。环境与光影帮助人物成立，身份与造型清晰可读；用户指定单人写真、棚拍或纯背景时沿用。角色类型与画风分别处理，原作年龄、身份、形体与用户指定属性优先，不套三格、中灰背景或无头人台。
- `jc-juese-geshi` 接收已选定参考图或已有角色文字提示词、画幅和目标画风，只处理身份一致的排版与风格，不重新随机设计脸、发型、身材、服装。已有合适参考图或角色文字提示词时直接进入这一步；明确要求整理成三格格式时，不强制先出图。
- 环境图未显示的背面或隐藏结构须标明未定，不能当成参考图已锁定的事实。四足、蛇形等非人角色可由 `jc-juese-sheji` 设计，但现有 `jc-juese-geshi` 人形模板不适配时须说明版式缺口，先保留环境图或按用户明确需求适配版式，不改成类人身体来套模板。
- `jc-shuaigemeinv` 独立技能继续保留，不属于本路由的十四个业务入口；其写真设计方法已融合为 `jc-juese-sheji` 包内参考，漫剧路线中的帅哥美女与角色形象统一使用后者。

## 提示词交付边界

本路线到文字与提示词为止，包括视觉资产、分镜、视频和声音提示词。即使用户在此路线说“生图／生成视频／生成音频／提交”，也不调用媒体工具；交付当前可准备的提示词与素材绑定，说明实际生成请到独立创作面板操作，不自动代交。子Skill的生成、等待、图像验收与重绘方法只用于分析用户已带入的结果，本路线不执行生成动作。不虚构任务号、上传、试听或生成成功。

## 声音融入提示词

每次输出包含发声角色的视频提示词，先按相关索引读取角色声音档，缺维度时调用 `jc-shengyin-sheji` 的设计规则补齐；用户已有声音与实际录音绑定优先，设计补充标明暂定。年龄感、音高、明暗、厚薄、共鸣、气息、颗粒感、口音、稳定表达习惯九维必须逐角色完整写入每条独立提示词，不只链接档案或写“沿用音色”。每段只展开实际发声角色，静默角色不新增声音。

九维放入目标提示词已有主体／说话人描述，参考录音按实际职责绑定；具体台词保留原文，当前情绪、气息、声量与表演另在当句表达。H3现有字段、顺序、标签与Skill资源保持原样，九维译入其已有主体／说话人字段；Seedance放入角色参考描述，无角色图时放入首次发声镜头，不虚构图号。纯视觉生图提示词不塞不可见的声音描述，声音身份另归档。

`jc-shengyin-daoyan` 负责用户要求的声音导演稿，或当前提示词需要的对白／音效／环境声编排；不自动另产整集声音稿。若已有声音导演稿，按镜号取对应事件融入视频提示词，与台本核对；不改变已确认对白、OS／旁白和关键声音，不为配乐模板强加音乐。声音制作可用模型原生音画、已有音轨、后配或混合方案，由项目选择决定，不锁供应商。

交付前检查每条提示词的发声角色九维齐全、跨段身份一致、台词与声音事件保真、实际素材绑定和时长负荷正确。只核验已完成的文本与已有素材，不声称生成效果已验证。

## 短剧改编版资料交接

同项目已有短剧新版资料时，先沿索引复用已确认的人物、场景、道具、世界规则与剧本；原作只作追溯，不重新套回旧设定。核心场景／道具的剧情功能、归属、规则和关键状态是视觉设计约束；普通造型细节可在本路线细化。已有唯一规范资产档案时在原档补设计章节，资料页只关联，不重复维护同一事实；没有视觉档时按既有资产类型创建并双链关联新版剧情资料。切换路线不自动补跑任何制作步骤。
