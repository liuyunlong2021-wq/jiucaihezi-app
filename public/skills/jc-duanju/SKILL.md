# 短剧写作

先判断用户当前要的产物与已有项目阶段，只读相关 Skill 正文，不把全部业务规则再次拼进系统提示。点击模式仅切换路由，不自动启动任务。

## 路由

- 提取或补充原作资料 → [jc-xiangmuziliao](../jc-xiangmuziliao/SKILL.md)。已有资料沿真实索引复用，核对覆盖范围，只补缺口。
- 六类组合换皮方向、核心梗与必要的新项目资料；原创多集整体方案 → [jc-duanju-cehua](../jc-duanju-cehua/SKILL.md)。
- 原文情绪组合、首尾切点与简洁分集规划；原创阶段容量 → [jc-duanju-fenji](../jc-duanju-fenji/SKILL.md)。
- 原创单场／单集、逐集改编、续写、润色 → [jc-duanju-xiezuo](../jc-duanju-xiezuo/SKILL.md)。
- 所有读取、保存、索引和回执 → 原生 Wiki（先调用 `wiki_read_guidance`）。

明确指定任务、续改产物或已有完整资料时直接接手，不强制重走上游。原有原创、扩写、续写和润色能力保留。工程台本、视觉资产提示词与视频由独立漫剧制作路线承接，共用同一项目Wiki，不自动启动下游。

## 改编原则

原文是内容，新项目资料是替换规则，单集体量是组织尺度。改编直接对原文做排列组合与换皮，不从梗概、大纲重新创作故事。全部继承原文的对白、描述信息、动作、事件、人物反应、冲突、笑点、铺垫与伏笔；没有明确授权的内容不删、不增、不乱改。对白尽可能保留原句，只替换新皮必需的姓名、称呼、物件和设定词。描述可转换为动作、对白、必要OS／旁白或闪回，但不能因此新增事实或丢信息。

发生顺序与呈现顺序分开：原作因果和人物当时认知保持成立，允许跨章选材、冲突前置、倒叙、短闪回与声音回忆，将原作的承诺与落空、铺垫与包袱、轻视与反击组合到同一情绪单元。不能把重排变成角色预知后文。新皮无法承接原文时先修替换规则或报告具体冲突，不擅自另编事件。

只保留原文、新项目资料、简洁分集规划与逐集正文作为创作依据，沿用现有进度和索引，不加逐句台账或平行故事规划。原创、明确扩写及用户明确授权的情节修改按其范围执行，不把换皮的保真边界误套为禁止原创。

## 共同规格与归档

用户或已确认项目规格优先；未指定时默认每集目标90秒、全部发声文本200–400字（含上下限）、默认一场主戏；改编需要的短闪回、声音回忆及原作场景变化可保留，标清时间与场次。策划将有效规格写入 `project_overview`，分集与正文按同一规格执行；单项任务没有总纲时沿用这些默认值，不为补总纲阻塞任务。自然语速和必要动作共同估算时长，不加速念词或用空镜凑90秒。

在当前项目执行正式短剧任务，包括从头开始、单项产物或续做时，完整的项目资料、选定方向与核心梗、整体方案、分集规划、逐集正文及制作进度均须通过 `wiki_save_artifact` 写入 Wiki，无需用户另说“写入Wiki”。原生 Wiki 规定读写与回执，实际落盘由该工具完成，不以读取 Skill 或聊天展示代替保存。讨论中的六类备选、未选想法与未完成片段不自动入库；方向选定后保存决策及保留边界，完整待审产物标待确认。用户明确仅讨论、预览或不要保存时优先遵从。无项目或唯一Wiki根不可用时报告缺口，不能声称已保存。

## 原创多集

“从零创作十二集”等无原作的原创多集任务，先由 `jc-duanju-cehua` 根据用户创意探讨方向，建立核心梗、人物、世界、事件阶段与整体方案；再由 `jc-duanju-fenji` 做逐集规划，最后由 `jc-duanju-xiezuo` 逐集创作并归档。免除原作资料提取、原文收录、故事拆分与原文章节索引，来源标注用户设定及原创规划。关键方向未定先讨论，已有设定复用；原创单场／单集且输入足够仍直接写作，不强建整季资料。

## 从头开始的改编流程

用户未指定步骤、从头开始时按四步推进；已指定步骤或中断续做时沿真实产物接手，不重跑。原有六步中的资料落袋、六类方向讨论、明确核心梗、原生拆分、分集及逐集归档能力全部保留，只合并重复规划。

1. **原作落袋**：完整收录原文，调用 `jc-xiangmuziliao` 整理换皮需要的人物、关系、背景、规则及场景道具；不先生成建议分集。资料保存后复用原生故事拆分及已有节点索引；未拆时按 `wiki_read_guidance(topic="story")` 引导用户从文件树执行，核对结果后继续，不用自由写文件模拟拆分，也不把保存冒充已拆完。
2. **确定新皮**：调用 `jc-duanju-cehua`，无思路时提供人物、背景、题材、设定、剧情、结构六类可组合方向；选定后形成含核心梗和必要替换关系的新项目资料。默认保留原作全部内容，不重建一套新事件线。
3. **组合分集**：调用 `jc-duanju-fenji`，先找原文的情绪关联，再选开头和结尾，将相关原文重排后按体量校准。简洁规划记录集数、主情绪、开头、原文链接与呈现顺序、结尾钩子。跨章移用不遗漏中间内容，规划写入Wiki。
4. **逐集换皮**：调用 `jc-duanju-xiezuo`，按规划顺序实际读取原文，执行替换，不根据梗概自由补戏。自检“有没有漏、有没有多、有没有换错”，修正并核对保存回执后继续下一集。

方向或替换规则未定且影响因果时先讨论，不把待确认当已确认；已给定或委托决定的范围直接执行。正式产物自动归档，不逐步索取保存许可；只讨论、预览或不要保存的要求优先。体量冲突优先重新组集，不以删原文、加台词或异常语速凑规格；无法兼容时报告具体冲突。

## 长篇来源与决策

粘贴长文用 `wiki_save_artifact` 的 `source_material` 类型从当前用户消息精确截取，传 `source_block` 和首尾唯一原文片段 `source_start`／`source_end`，不让模型重抄正文。回执成功后再按真实文件分批读取。首尾片段包含在保存范围内；不得纳入用户任务说明、Skill或Wiki上下文。当前消息没有完整来源时，沿附件或已导入文件读取；无法定位则说明缺口，不能用摘要冒充原文。收录不等于完成故事拆分，不冒称已执行原生分析。

原作覆盖记录写入 `research_coverage`，标明来源路径、总范围、已读／未读位置和缺口；按章或可定位连续段落读取，同批提取各类资料，跨批合并别名和状态。完成实际覆盖后再称全篇整理完成；无结局或截断如实标注。原作资料用 `research_version=original`，新版资料用 `adapted`；旧资料保留原位并由索引引用，不自动搬迁。

改编方向与新版资料是第一处主要决策点，整体方案及分集规划是第二处，首集样稿校准表达。已明确给定或委托决定的范围直接执行；待确认内容可以按授权保存为待确认，不冒称确认。未决内容会改变下游因果时先交付具体决策，不继续把它当已定事实。连续写作不每集重复询问，按授权范围推进。

## 进度与归档

共享 `wiki_save_artifact` 的类型和字段决定路径，禁止手写平行Wiki或手动重复维护索引。使用 `production_progress` 记录来源覆盖页、已确认资料与方案、分集规划、各集状态和实际路径、下一步及待决项。以正文和真实工具回执为准，进度页只作导航。

新世界改变人物行动、场景准入、道具功能或事件结果时，回查相关依赖并联动修订；不要只替换名词。改动已确认上游前先说明下游影响，按用户授权更新，保留无关内容。中断恢复先查进度和相关索引，不扫描全库、不重写已完成稿。
