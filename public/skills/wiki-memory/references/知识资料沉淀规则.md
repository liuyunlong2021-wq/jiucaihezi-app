# 知识资料沉淀规则

用于把技术书、论文、规范标准、内部文档、方法论文集这类**要学到手或要常查**的非叙事物料，沉淀成可追溯、可续跑、可定点检索的 Wiki。

叙事类物料（小说、故事、剧本）走 [故事资料沉淀规则](故事资料沉淀规则.md)，不读本文件。

## 与故事规则的共同点

两阶段、Runtime 负责机械拆分、分析页是分析状态的唯一真源、原始分段与分析分离、一个事实只有一个权威位置、`index.md` 只导航不复制事实、目录只在有真实内容时创建。上面这些一字不改，本文件只写差异。

## 差异一：语义字段不同

故事型物料的实体是人物、地点、道具、关系；知识型物料的实体是**框架、术语、技法、反模式、关键判断**。粒度停在节点（章/节/篇），没有"场次"这一级，也不再往下切情节拍。

## 目标结构

```text
<Wiki>/
├── index.md
├── 原始材料/
│   ├── index.md
│   └── <作品>/
│       ├── index.md
│       ├── 来源.md
│       ├── 原文.md
│       ├── 原文节点/
│       └── 节点分析/
└── 知识/
    ├── index.md
    ├── 术语索引.md
    └── 速查.md
```

`知识/` 是知识型资料的横向层：把散在各节点里的概念、判断串成一个可检索面。它只放**别处没有**的内容，与 `创作/` 同级，只在第一次产生真实内容时创建。

## 第一阶段：无损结构拆分

与故事资料完全相同，复用产品原生的拆分能力，模型不得用多次写入模拟。

### 先剔目录区

技术书几乎都带目录页，而目录行本身就是 `第一章 xxx …… 12` 这种形状，会被当成章节边界。不处理的话，一本 17 章的书会被拆成 34 个节点：前 17 个是目录行，后 17 个才是正文，并且会报“重复编号”“章节序号存在倒序”。

所以在拆分前先把目录区从 `原文.md` 里删掉（保留正文第一行标题之前的内容，删掉中间那一段目录）。中文书的目录行通常带点引线（`……` 或 `......`）和页码；英文书带 `Contents` 标题或 `Page` 列。删完重新跑一次拆分预览，**看到重复编号或倒序警告就要回头检查目录，不要直接确认**。

### 显式指定拆分标记词

不要依赖自动识别。实测一本真实书籍：自动识别选了“独立数字段号”，给出 **138 个节点**（正文里的行首裸数字、页码、图号全部被当成边界），而用标记词「章」是干净的 **17 章**。原因是自动识别按候选数量打分，正文里散落的行首数字会淹没真正的章节标题。

- 中文书：标记词填 `章`（前缀/后缀由 Runtime 自动判断）
- 英文书：填 `Chapter` 或 `Part`
- 看到节点数远大于书的章数，就是选错了标记词或目录没剔干净，回去改，不要往下走

### 节点要求

- 每个叶子节点保存连续原文切片，不总结、不改写、不清洗公式与代码；表格和代码块在被切成节点时必须完整保留，宁可整段留下也不要跨节点劈开。
- 表格、代码、公式密集的书，拆前先确认这些结构在转换后的 Markdown 里还在。转换阶段就没保住的东西，拆分阶段救不回来——这时应回去换提取方式，而不是将就。

## 第二阶段：逐节点语义沉淀

### 用什么选节点

原生 `prepare_story_analysis` **可以**用来选待处理节点并校验来源哈希：它是只读的，返回节点 ID、原文、来源哈希和"该节点是否已有完成的分析页"。知识型资料沿用它的**选择**能力。工具书一章常常很长，用 `progress` 分段推进：`nextOrder` 是本次起点之后第一个未分析节点的序号（0 表示这段已清空），回传给 `startOrder` 就只处理指定区段；`analyzed`/`remaining` 是整本进度，不要把它们当成"本段剩余"。

原生 `commit_story_analysis` **不适用**于知识型资料：它的语义字段、落盘目录（角色/场景/道具/关系）和页面类型都是为故事资产设计的，提交它只会产出形状错误的分析页。因此本阶段的**落盘由模型按本文件直接写**，代价是没有 Runtime 的证据与唯一性校验，所以下面每一条纪律都必须自己守住。待知识型实体获得原生链路后，这一段改为走原生提交。

### 落盘位置与分析页格式

写入 `<作品>/节点分析/<与原文节点同名的文件>`，Properties 镜像原生分析页的形状（除了 `type`），以便将来接入原生链路时不用改格式：

```yaml
---
type: knowledge-node-analysis
id: "<原文节点的 id>.analysis"
source: "[[../原文节点/0001]]"
source_hash: "<从原文节点 frontmatter 原样复制>"
analysis_status: complete
---
```

`source_hash` 必须从原文节点原样复制，不要自己算也不要改。它把分析页锚定到它当时读的那一版原文，是绕过原生提交后唯一剩下的版本锚。

绕过了原生提交，索引也就没人代办了：所有节点分析页写完后，要自己 **创建 `<作品>/节点分析/index.md` 并把「节点分析」登记进 `<作品>/index.md`**，否则这份分析在导航里是隐形页面。`analysis_status` 只使用与原生合同一致的 `complete` 与 `needs_review`。

正文按需保留下列小节，**没有证据的小节留空，不要为了填满而推测**：

```markdown
## 核心主张
<1-3 句：这一章最重要的一件事>

## 框架
- **<作者给的原始名称>**：<一句话它是什么>
  - 何时用：<具体情境>
  - 怎么做：<步骤或判据>

## 关键术语
- **<术语>**：<一句话定义>

## 技法
- **<技法名>**：<步骤>

## 反模式
- **<要避免什么>**：<为什么会失败>

## 关键判断
- 当 <X> 时，做 <Y>，因为 <Z>
- 阈值与默认值：<作者明确给出的数字、比例、经验法则>

## 证据归属
- 原文明确事实：<…>
- 模型归纳：<…>
- 待确认：<…>
```

### 精度纪律

- **保住作者的精确命名**。"The 5 Whys" 不等于"多问几次为什么"，"记分卡"不等于"打分表"。框架的专名是它的检索键，改名即失效。
- **抽取结构，不是写摘要**。产出的是工具箱：命名框架、可执行原则、技法、反模式、作者的判据。不是这一章讲了什么。
- **分析页必须综合，不得复制原文长段**。原文永远在原文节点里，需要原文时用双链指过去。复制会同时破坏单一真源和版权边界。
- **反模式与"什么时候不适用"必须写**。只写"怎么用"的知识页在真实处境里会误导人。
- **密度优先，不靠字数凑**。写不出东西就留空并在"核心主张"里注明这一章单薄。

### 用途分档

落盘前问用户一次，只问一次：**要精读还是要备查**。

- 精读：每个框架写全"何时用/怎么做"，并至少复现一个作者讲过的具体例子（一张填好的表、一段对照、一个被走完的决策），放在 `## 实例`。
- 备查：只写决策要点，省略例子，`## 关键判断` 是重点。

档位影响篇幅，不影响是否写反模式与证据归属。

## 横向层：术语索引与速查

### `知识/术语索引.md`

**只放映射，不放定义。** 定义的真源是分析页。

```markdown
# 术语索引

用途：按概念定位节点。定义在对应分析页，本页不重复。

- **<术语>** → [[原始材料/<作品>/节点分析/0001|ch01]]、[[原始材料/<作品>/节点分析/0005|ch05]]
```

写索引的时机：节点分析页写完后，把本节点里"值得按概念检索"的条目登记上去。同一术语出现在新节点时只追加链接，不复制定义。路径按运行时索引里的真实路径写，不得凭记忆拼。

### `知识/速查.md`

**只放别处没有的判断**：决策规则、分支、阈值、权衡矩阵、识别气味（"看到 X，你大概在 Y 上出问题了"）。每行尽量带出处节点。

不放：术语定义（那是术语索引指向的分析页）、章节摘要（那是分析页）、原文摘录（那是原文节点）。这一页的价值在于它是判断，不是关键词表。

## 定点检索

以概念或术语为锚点时：

1. 读 `知识/术语索引.md` 定位节点；索引里没有就说明尚未沉淀，不要凭已有知识回答。
2. 读对应分析页取框架、术语、判据与证据归属。
3. 需要原文措辞、公式或代码时，再读分析页指向的原文节点。
4. 分析页不存在或 `analysis_status` 不是 `complete` 时，直接读原文节点，并说明语义沉淀尚未完成。

不得把术语索引的一行映射、或分析页里的一句概览，当作该概念的完整表述。

## 增量

同一份 `原文.md` 追加新章节后重新拆分即可：老节点内容未变则跳过，新章节才建节点；分析阶段只处理没有 `complete` 分析页的节点。不要为"新版"另建一个作品目录。

## 禁止

| 不要做 | 为什么 |
| --- | --- |
| 把原文长段、整张表、大段代码抄进分析页 | 双真源 + 版权边界；用双链指原文节点 |
| 在术语索引里写定义 | Index 只导航；定义只在分析页 |
| 给同一个框架建第二个页面 | 一个概念一个权威位置 |
| 把不同译法当成不同术语各占一行 | 用同一行合并链接，或写进该术语的别名 |
| 用摘要替代原文节点 | 原文节点是无损切片，是取证真源 |
| 用 `commit_story_analysis` 落知识型分析页 | 它的字段与目录为故事资产设计，会产出形状错误的页面 |
