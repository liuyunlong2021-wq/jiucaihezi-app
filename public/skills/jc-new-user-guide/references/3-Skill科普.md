# Skill 科普

## 什么是 Skill

Skill 是产品最核心的插件，也是给 AI 写的强制执行合同。它规定某类任务怎么做、输出什么格式以及如何验收；只有用户明确选择具体 Skill 后，AI 才读取并遵守它。

打个比方：你请了个助理，Skill 就是你给助理写的"工作流程手册"——第1步干啥、第2步干啥、遇到什么情况怎么处理。

## Skill 的标准结构

每个 Skill 有三个部分：
- **SKILL.md** — 主文件，写清楚干什么、怎么干（建议控制在 500 行以内）
- **references/** — 参考资料，需要时再读（模板、规范、指南）
- **scripts/** — 可执行脚本，自动干活用的（可选）

## 怎么创建自己的 Skill

用 skill-creator——它是专门帮你写 Skill 的 Skill。

说「帮我创建一个 Skill，用于 XX」，它会一步一步引导你：
1. 确定 Skill 叫什么名字
2. 写描述和触发词
3. 设计工作流程
4. 生成完整的 SKILL.md 文件

Skill 本身是插件。Skill 规则中声明或要求的文件、MCP、媒体、3D、Terminal 等工具，必须进入本轮授权并真实调用；工具返回什么就以什么为准。平台确实不提供的工具必须明确报错，不能静默跳过。

Skill 不负责保存对话历史，也不等于 Wiki。当前对话的最近三轮由工作台自动保留；更早的当前对话回答由“查询”开关控制的原生 `memory_search` 查找；项目长期知识使用 Wiki 普通文件和 `wiki-memory`。

## 什么时候使用 Skill

- 需要固定方法、格式或质量标准时使用，例如角色设计、分镜、排障报告或创建 Skill。
- 只问一个事实、做简单解释或不需要固定流程时，不必选择 Skill。
- 需要查询项目长期资料时选择 `@Wiki`；它是能力入口，不是抽象的 `@Skill`。
- 已选 Skill 会持续到点击标签上的移除按钮或新建对话；新建对话不会继承上一对话的 Skill。
- Skill 不会自动替你选择其他 Skill、跨对话读取历史或扩大文件/MCP/媒体等权限。

## skill-creator 怎么用

| 想干啥 | 怎么说 |
|--------|--------|
| 创建新 Skill | `帮我创建一个Skill，用于[你想干什么]` |
| 修改 Skill | `帮我改一下 [Skill名]，让它能 [新功能]` |
| 检查 Skill | `审计一下 [Skill名]，看看有没有问题` |
| 优化 Skill | `优化一下 [Skill名] 的描述/触发词` |

在“我的 Skill”点击“修改”时，工作台会自动选择 Skill Creator，并填入精确 Skill ID 和中央 Skill 路径。Skill Creator 必须先按 Skill ID 读取已安装的真实 `SKILL.md`，修改后展示安装卡；用户点击确认后才覆盖原 Skill。中央目录通常是 `~/.agents/skills`，不要把输入框里的展示路径当作加载参数，也不要让它用 Terminal 搜索。

## 常见问题

### Skill 和普通对话有什么区别？
普通对话：模型直接回答当前问题，并自动看到当前对话最近轮次。Skill：AI 先读你选中的说明书，再按其中流程执行——更稳定、更可控。

### Skill 能调用工具吗？
能。Skill 可以声明需要文件、MCP、媒体、3D 或 Terminal，但只有用户本轮选择且平台可用的能力才会加入授权；规则要求调用时就必须真实调用。平台不可用的工具会返回明确错误，不会假装完成。

### Skill 应该拆分多细？
一个 Skill 只做一件事。如果一个 Skill 干了 7 件不同的事，就该拆了。
