# 文件与索引使用完整指南

> 给完全不懂技术的人。看完就能用。

## 基本概念

项目里的长期资料就是普通文件。Markdown、图片、音频、视频、Office、PDF、画布和索引都按真实文件保存；没有隐藏的专用知识库，也没有必须由某个 Agent 接管的目录。

## 核心概念（可以不看）

- **.raw/** — 原材料。会话、参考资料和过程记录保留在真实位置，AI 不复制、不移动、不删除
- **项目文件** — 保存对话沉淀、资料、索引和产出
- **index.md** — 需要时由所选 Skill 按规则维护的导航文件
- **hot.md** — 当前状态、风险和下一步
- **log.md** — 普通 Markdown 文件，可按所选 Skill 规则记录状态变化
- **来源索引.md** — 普通 Markdown 文件，可按所选 Skill 规则登记来源和处理范围

新建记忆空间只创建项目所需的最小普通文件和目录，不猜项目类型，不预建业务结构，也没有每轮自动读取的隐藏文件。

## 工具与 Skill

Skill 是最核心的插件。Skill 规则要求调用文件、MCP、媒体、3D 或 Terminal 时，系统必须把对应工具加入本轮授权并真实执行；工具返回错误就如实返回。没有选择 Skill 时，也可以直接选择并使用任一当前平台提供的工具。

基础对话不依赖项目、SQL、索引或任何工具：用户信息加模型即可得到回答。需要读写项目文件或运行工具时，先选择项目和对应工具。

## 项目文字同步

登录同一账号后，Web、Desktop 和已安装的支持版本 Mobile 可以在项目中心上传或下载允许的文字资料。媒体二进制、原始附件、空目录、凭据、设置、Skill、MCP、Provider、Session 和 `.raw/.sync` 不参与同步。这里描述的是同步能力，不代表 Mobile 已在 App Store 或其他公开渠道上架；下载状态以正式发布页为准。

项目中心只有两个方向明确的动作：

- **上传并覆盖云端**：以本地完整文字快照覆盖云端同名项目。
- **下载并覆盖本地**：以云端完整文字快照覆盖本地同名项目。

两者都不合并、不创建冲突副本、不自动双向同步。操作会显示扫描、上传/下载和完成进度；离线时内容仍先保存在本机。

## 文件读取方式

所有页面都是普通文件。App 不把 `README.md`、`CLAUDE.md`、`index.md`、`hot.md` 或其他页面固定注入每轮对话；模型只在当前问题需要时查询或读取相关内容。项目里已有的 `CLAUDE.md` 仍是普通用户文件，不迁移、不删除、不覆盖。

## 文件操作

查询、规划、写入、巡检和修正都通过普通文件工具完成；如何组织步骤由用户选择的 Skill 决定，也可以直接选择单个工具完成。

## 完整操作：七步走

下面每一步都是**完整指令**，照抄粘贴到对话框，改一下方括号里的内容就能用，不用自己拼词。

### 1. 新建记忆空间

点击“新建记忆空间”创建最小项目文件。若不知道后续该建什么，再说：

```text
请根据我的目标规划最小文件结构，先给方案，等我确认后再创建：
[完整描述你的目标、资料和常见问题]
```

### 2. 填内容

```
请把本轮已确认的内容写入指定项目文件：
只使用本轮对话中已经确认的信息，不扫描其他历史资料；
为重要结论登记文件路径、原始来源、处理范围和写入时指纹。
```

### 3. 查进度

```
请查看当前项目文件状态：
说明当前结构、最近确认事实、风险和下一步入口。
```

### 4. 搜东西

```
请查询项目文件：
关键词：[你想查的角色名/设定名，比如"张三"或"世界观"]
```

### 5. 画关系图

```
请以 资料/角色/主角.md 为种子生成一层局部关系图，
保存为 资料/角色/主角-关系图.canvas。
```
生成后可直接在韭菜盒子的项目地图中查看；导出到 Obsidian 时才使用标准 JSON Canvas。

### 6. 体检

```
请对当前知识库做全库巡检：
检查导航断链、歧义链接、孤儿候选，
检查已登记来源是否变化、丢失或无法验证，
并检查主题「[要核对的事实或规则]」在相关页面中有没有明确矛盾。
```
查出问题只会列清单，不会自己改。普通未解析链接和孤儿页面只是待确认候选，不会被自动删除。

### 7. 改错

```
请预览这一项已确认修正：
文件：[项目内的 Markdown 路径]
旧值：[唯一旧值]
新值：[唯一新值]
原因：[为什么错]
依据：[用户决定或可靠证据]
```
确认预览无误后再执行。语义冲突先由你决定哪个对，再形成这样一条精确修正。

## 项目做大了：加分类

项目刚建的时候分类往往是猜的——比如小说一开始只建了"角色、世界、剧情"，写到一半突然觉得伏笔太多该单独建个本子记，直接粘贴：

```
请给项目文件加一个新分类：
新分类：[分类名，比如"伏笔"]
用途：[一句话说明放什么内容，比如"追踪伏笔埋设和回收进度"]
```

规划操作会先确认用途和归属，再建最小目录。如果新分类需要理解旧内容并填充确认事实，仍分两步执行；不要让结构规划和内容沉淀混成一次未经确认的批量改写。

是否拆分分类由实际用途决定，不能只看文件数量。

## 速查表

| 指令 | 干什么 |
|------|--------|
| `新建记忆空间` | 创建最小项目文件和原始资料目录 |
| `按需求完善文件` | 根据目标规划并扩展最小文件结构 |
| `写入项目文件` | 写角色/大纲/日志 |
| `查看文件状态` | 看进度 |
| `查询[关键词]` | 搜东西 |
| `生成关系图` | 画关系网 |
| `巡检一下` | 健康检查，出问题清单 |
| `执行修正` | 把清单上的问题改掉 |
| `加个分类` | 给项目文件建新的子目录 |

## 常见问题

### 小说太长会卡吗？

不会。基础初始化不猜测业务目录；需要什么再按目标规划、确认和扩展。

### 能自己改文件吗？

可以，也可以让 AI 按你确认的范围精确修改。

### 项目资料会和代码混在一起吗？

按项目目录和命名管理即可；`.raw/` 是独立的原始资料目录。

### 多个项目怎么切换？

每个项目有自己的文件，工具只访问当前项目授权范围。

### 怎么同步到 GitHub？

项目文件和 `.raw/` 都是普通文件夹；如果你自己用 Git 管理项目，可以按自己的仓库规则提交。它和韭菜盒子的云端覆盖操作是两套独立机制。

### 想重建？

不要直接删除原文件或 `.raw/`。想重建结构时，先保留现有资料并让 AI 规划；涉及迁移、合并或删除时，先明确确认范围。

### 巡检查出问题，为什么不直接帮我改了？

巡检只负责查、不负责治。查错和改错分开可以避免批量误改；查完说一声「执行修正」再进行精确修改。

### 修正官会不会瞎改我的设定？

不会。能直接判断该改成什么的（比如漏改的错别字、断开的链接）它会直接改；但遇到两处设定说法不一样（比如档案说角色左脸有疤，正文写成右脸），它一定会先问你哪个对，不会自己挑一个改掉。
