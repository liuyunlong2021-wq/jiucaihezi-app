# 改编策划

## 输入与顺序

原创多集无原作时，以用户创意与已有设定为依据建立核心梗、人物、世界、场景道具、事件阶段及整体方案，不要求原作资料、改编对应或故事拆分，不虚构原作来源。下文原作提取与改编对照只适用于改编任务；原创项目资料省略 `research_version`，仍复用相同归档类型。

先按 Wiki 索引复用原作资料及覆盖记录；改编任务原作资料不足时回交 `jc-xiangmuziliao` 补相关来源。区分原作明示、推断与未知。已有确认方向或新版资料直接续改，不另起一套。

1. 明确目标受众与规格、原作核心吸引力、期望情绪、保留承诺和允许改变的边界。信息已有则复用；缺口不影响当前工作可先做。用户已有思路时围绕其方向探讨；没有思路时必须提供下表六类可组合选项，结合原作分别给出具体改法、保留的吸引力与代价。允许多选、混搭、局部采用或委托推荐组合，不要求六选一，也不默认六类全改。
2. 形成改编思路，说明为什么改、改变哪些基础及预期影响。不能仅用现代→古代等名称映射代替策划。
3. 建立新版项目资料，联动推导世界规则→人物处境与身份经历→性格动机与关系→行动选择→事件结果→人物关系变化。允许反复修正，不各自独立生成互相冲突的设定。
4. 新版资料稳定后形成整体方案：叙事视角、起终点、主支线、发展阶段、阶段高潮、人物弧光、信息释放与伏笔回收、事件保留／合并／重排／替换／删除及容量。故事发生阶段与呈现顺序分别说明。

## 无思路时的六类改编选项

| 换皮方式 | 具体做法 |
| --- | --- |
| 人物换皮 | 修改姓名、性别、年龄、职业、身份、人物关系 |
| 背景换皮 | 都市改古代、国内改国外、现代改末世、现实改架空 |
| 题材换皮 | 霸总改黑帮、赘婿改修仙、豪门争斗改宫斗 |
| 设定换皮 | 系统改成神秘遗产、重生改成预知未来、金手指换能力 |
| 剧情换皮 | 保留核心爽点，重新设计冲突、反转、事件和解决方式 |
| 结构换皮 | 调整主线、叙事视角、人物动机、故事顺序及结局 |

以上为选择维度与示例，不是预设答案。基于当前原作解释各类如何落地，组合后检查世界规则、人物动机与因果是否兼容；记录用户选定和不采用的改变，不擅自替用户确定关键方向。

## 新版资料

- **核心梗**：用一句话讲清“谁＋独特处境／设定反差＋核心冲突＋持续吸引观众的情绪／爽点”，再说明如何支撑主线和持续分集；不以题材标签、换皮清单或泛泛的逆袭复仇替代。写入新版故事梗概，并在项目总纲中关联，其他资料与整体方案围绕它保持一致。
- 故事背景与世界规则：制度、势力、力量来源、边界、代价及限制。现实题材不强造能力体系。
- 每人独立小传：身份、经历、性格反差、欲望、恐惧、软肋、底线、策略、说话方式、变化与命运。人物关系留在小传中，交代利益、情感、相互认知及阶段变化，双方事实一致。
- 场景：归属、用途、准入条件、剧情功能、必要空间关系、特殊规则及变化。
- 道具：持有者、来源与取得条件、功能、触发与限制、代价、流转、损坏或消耗、证据及伏笔作用。
- 事件线与发展阶段：事件的起因、行动、结果、依赖、人物当时认知；各阶段起点、目标、阻碍、转折及结束状态。最后汇总新版故事梗概。

场景／道具按剧情影响分层：核心项独立详档，复用项简档，临时普通物只留事件中。只出现一次但影响身份、反转、胜负、结局的也属核心。先锁剧情功能与规则；造型材质灯光等交给漫剧视觉制作，直接影响识别或因果的外观例外。优先关联已有唯一新版实体档，后续视觉制作在同一规范档案补设计章节，不复制同一事实。

每项关键改变记录“原作元素及来源→原功能→新版设定→保留或改变的功能→受影响事件与补救”。例如统治／审判机构不能仅换成没有权力机制的神庙；认证身份兼开封印的剑需要重建两种功能与代价。真实神话名称与项目原创设定分开，不把创作补充说成神话史实。

将有效制作规格写入项目总纲：用户／已确认规格优先，未指定则目标90秒、发声文本200–400字（含上下限）、默认每集一场戏，因果必须多场可拆场。后续分集与正文沿用该规格。

## 校验与交付

逐项检查人物在新规则中是否有动机、能力与机会行动；关系能否支撑合作／背叛；场景是否可达；道具如何取得使用；新事件是否有因有果；保留承诺与结局是否仍成立。全作真相与人物当时认知分开。存在关键缺口时列具体决策，不能留给逐集补洞。

正式任务的完整资料与选定方向按总路由共同归档规则自动调用 `wiki_save_artifact`，无需额外保存指令；只讨论的备选不归档。

归档新版资料用 `research_version=adapted`，类型对应 `story_summary`、`character_bio`、`story_background`、`world_rules`、`scene_research`、`prop_research`、`event_timeline`。正式方向、保留边界、改编对应和整体方案用 `project_overview`；先读已有总纲，完整保留漫剧等其他章节后 update，不 append。记录待确认／已确认与依据版本，保存不等于确认。

修改已确认方向或资料前列出受影响资料、规划、剧集及“不受影响／小改／重写”理由，用户决定范围后再改；沿用已授权范围，不反复索权。分集拆解交给 `jc-duanju-fenji`。
