# 短剧改编：项目总纲

理解用户本轮思路，读取wiki_read_guidance(overview)，沿真实index定位`项目资料/原作/故事梗概.md`、本次涉及的人物小传、背景/规则、场景/道具和必要原文章节。旧库沿实际索引查找，原作、改编版、用户新要求分别辨清；刚生成的聊天或index摘要不能代替read正文，同版本本轮已读可复用，修改后重读。已有明确改编思路就直接完善，只有影响主题、人物身份或因果的关键缺项才合并询问。

项目总纲是用户审阅的规划书前半部分，写给人看：短句、具体，不写空话。

## 改编规则

- **可以**：删减、压缩设定和水文；把相邻章节的事件组成一集；倒叙开场；把设定化成画面或一句台词随用随给；补强人物性格和表达方式。
- **不可以**：编造原作没有的事件、能力、胜负和关系；改变因果；改变台词的意思和信息差。
- 每集不超过3分钟，下限不限；用户或项目另有规格的以用户为准。
- 剧本是供漫剧制作直接使用的小说化电影剧本；原作没写的外形由逐集改编按设计Skill创作，总纲只记录用户明确的整体风格要求。

## 项目总纲写什么

保存到`改编方案/项目总纲.md`，依次写：

1. **主题**：一句话（如“莫欺少年穷”“三十年河东三十年河西”）。写明它分别落在哪些人物的性格和关键选择上。主题是气质，不是口号：不让人物说教，不写旁白点题。
2. **卖点发动机**：
   - 爽点发动机：观众追着看的那件事。爽点类型因题材而异：升级、打脸、发糖、揭秘、反转等。例：种田防御流里新种子进化出新功能，相当于钢铁侠的新装备、奇异博士的新魔法。
   - 冲突发动机：主角始终要面对的压力。例：生存压力、兽灾、对手逼迫。
   - 两者怎么互相推动。例：为了活下去，才必须进化出新的防御。
   - 爽点怎么逐步加码，冲突和对手怎么逐步加压。
3. **人物**：主要角色各写一段摘要并链接到改编版人物小传（见下节）。
4. **必要设定清单**：观众必须知道的最少规则，以及各自适合用什么画面或台词带出；不单独成戏，其余设定不进剧本。在第几集带出由分集规划决定。
5. **大结构**：篇章表，如“第1–10集：对抗兽灾”。每篇写篇章目标、核心冲突、篇章高潮、结尾转折。长篇可以先按梗概写初稿，集数范围在每批分集规划完成后回填和修订。
6. 原作来源与本次章节范围；用户思路；未决项。

## 人物：取长补短

原作者往往想象力强、人物塑造弱。改编时为主要角色补上鲜明的性格，只补性格和表达，不改事件。写进改编版人物小传（`character_bio`，`research_version=adapted`），已有档案先read再补：

- **性格与成长经历**：成长经历决定他说话办事的逻辑，为什么这样说、这样做。
- **说话方式**：写出能把他和别人区分开的地方。同一个意思，性格不同说法就不同。
- **人物变化**：起点、终点和促成转变的事件；集号在分集规划完成后回填。
- **补了什么**：原作哪里扁平、这次怎么补，标明属于改编设计。

补的性格必须说得通原作里他做过的事：原作里临阵退缩的人，不能补成一往无前的果敢。人物关系、当时认知、力量边界和动机必须能承接原作实际事件。具体怎么把性格塑造鲜明，可参考[人物塑造方法](references/人物塑造方法.md)，按需选用。
