# 改编策划

## 输入与顺序

改编先沿原生Wiki索引读取原作资料与必要原文，已有新皮直接复用，资料缺口定点补充，不按每个对象重读全作。原文是内容，新项目资料只定义如何替换；不能因换背景或关系就重新编排人物命运、冲突和结局。

先讨论用户希望改变什么及保留原作的吸引力。无思路时完整提供下表六类可组合选项，并结合原作给具体做法；可混搭、局部采用或委托推荐，不能六选一，也不默认全改。选定后建立一份简洁的新皮合同与必要实体资料，分集交给 `jc-duanju-fenji`。

原创多集无原作时，仍根据用户创意建立核心梗、人物、世界、事件阶段和整体方案，再交分集；不要求原文、替换对照或拆分。下文的全部继承与不增不删仅适用于改编，原创资料省略 `research_version`。

## 无思路时的六类改编选项

| 换皮方式 | 具体做法 |
| --- | --- |
| 人物换皮 | 修改姓名、性别、年龄、职业、身份、人物关系 |
| 背景换皮 | 都市改古代、国内改国外、现代改末世、现实改架空 |
| 题材换皮 | 霸总改黑帮、赘婿改修仙、豪门争斗改宫斗 |
| 设定换皮 | 系统改成神秘遗产、重生改成预知未来、金手指换能力 |
| 剧情换皮 | 默认将原作冲突、反转及解决过程换成新设定的等价表达；实质改剧情须逐项明确授权 |
| 结构换皮 | 调整呈现顺序、叙事视角和信息揭示；改变动机、主线或结局须明确授权 |

这些是选择维度，不是自行改剧情的许可。选择人物、背景或题材换皮不授权删加事件；剧情和结构选项也只有用户明确指定的实质改动才执行，其余仍全部继承。默认不要求用户逐条确认换名、换称呼等已授权替换。

## 新项目资料

- **核心梗**：一句话讲清谁、独特处境／设定反差、核心冲突及持续情绪吸引力；继承原作的吸引力，不另造故事。
- **人物与关系替换**：原人物→新人物，必要身份、称呼、关系、说话方式及保留的动机。改称呼如“爸→哥”不能连原句一起删掉；关系变化须能承接原有戏剧功能。
- **背景、场景、道具与规则替换**：旧元素→新元素及相同剧情功能、能力边界与代价。例如兼具认证和开封印功能的物件，换皮后两项功能都能成立。
- **改变边界与规格**：未明确改变的全部沿用，另列用户已授权的实质情节变更。默认90秒、全部发声文本200–400字；一场主戏可配必要短闪回与原作场景变化，不为场次或字数删内容。

沿用原有唯一人物、场景、道具、背景与规则档案，只补实际变化所需的资料。未变化的事实关联原作，不复制一套；不强制另建阶段方案或新版事件线来替代原文。换皮导致某段原文不成立时，优先修新皮，无法解决就列具体冲突，不偷偷删戏或另编补洞。全作真相与人物当时认知分开。

## 校验与交付

检查新皮是否能完整承接原作的对白、动作、描述信息、冲突笑点与因果；关键替换有依据，未授权情节没有改变。只输出选定的新皮合同及必要资料，不重复生成自由改编故事大纲。

正式产物自动调用 `wiki_save_artifact`：核心梗、替换关系、改变边界与规格用 `project_overview`；确需建立的新版资料用 `research_version=adapted` 及既有 `story_summary`、`character_bio`、`story_background`、`world_rules`、`scene_research`、`prop_research`，用户确需新版事件线时仍可用 `event_timeline`。已有总纲先完整读取，保留漫剧等无关章节后update，不append。解释和未成稿讨论不写；完整预览稿自动保存，明确不要保存时不写；保存不等于确认。

修改已确认新皮先指出受影响规划和剧集，沿授权范围更新，不自动重写旧稿。原创项目继续复用原有资料类型与整体规划能力。
