# 漫剧提示词流水线

用户明确要求“一条龙、自动流水线、全流程”时使用。用户只要求单个产物时用对应专业Skill。只执行用户指定剧集和模型；MiniMax对应H3，Seedance对应Seedance。模型、集数、可读剧本或确认的比例/风格无法确定时合并询问必要缺项，不猜测、不默认切换模型。所有步骤读取用户本轮修改要求；项目事实从Wiki读取，历史仅辅助指代。

**用户明确要求优先于本Skill和下游Skill的默认路线**（如不生图、纯文生、不用参考图、不建人物小传）：默认值只在用户没说时生效。只有违反模型硬限制（每段时长、参考图上限）或缺少无法推断的事实时才暂停，不能因为“默认规则要求参考图”而 blocked。

## 全自动成片

宿主“全自动成片”模式会发送带固定开头的指令，花钱的参数（集数、模型、预算）已由用户在确认卡授权，这里只负责文字产物：

- **【全自动成片·入稿】**：只做入稿；用户在剧本之外提出的制作要求（如镜头、时长、风格补充）不在本轮执行，原样记住，供后续单集执行。读取本轮剧本（粘贴、附件或引用文件），按集拆分，每集用 episode_source_script 原样保存（episode_number 为集号，不改写、不删减正文）；已存在且内容相同的集不重复保存。再检查 `项目风格/影片比例与风格.md` 是否已确认比例与风格，没有则按 [项目风格](../jc-film-style/SKILL.md) 询问并保存；已确认但缺“参考图方式”或资产清单缺“参考图”标记时，读原文后只按该Skill的判断规则补这两项（依据本轮剧本与用户要求），其他字段不改。本轮不执行 plan 及之后阶段，不保存 pipeline_checkpoint；结束时列出已保存的集号与大致字数，再用几句话给不看剧本的用户写制作判断与风险：参考图方式及理由、要建参考图的资产、文字带过的资产；用户要求与模型限制或项目风格的冲突（如要求纯文生但某实体需要跨段一致）、缺少的资料、可能超出单段时长的内容。风险只写在汇报里，不写进项目风格。
- **【全自动成片·第N集】**：按下文固定阶段执行指令中的那一集，同时遵守本对话入稿消息里用户提出的制作要求，剧本用该集分集剧本，比例/风格沿用已确认内容，从 plan 连续执行到 complete，中途不向用户提问或等待确认；确实无法继续时按合同保存 blocked 进度并写明原因。不提交生图或视频，由宿主根据进度自动处理。
  - **参考图按段决定**：只有需要跨镜保持外观一致的角色、场景、道具才建资产并带图；空镜、氛围、一次性画面的段 refs 为空，按纯文生写（H3 用 T2VA，Seedance 不写@图行）。同一集可以有的段带图、有的段不带。指令写明“纯文生”（plan limits 的 max_refs 为 0）时，用于广告、纪录片、宣传片等：materials 只写故事梗概及必要的场景说明，不建人物小传；assets 阶段不写任何资产提示词、outputs 为空；工程剧本资产清单写“无（纯文生）”；每段 refs 为空。
  - 全自动的 assets 阶段，角色**一步出三格参考图提示词**：read 影片比例与风格和该角色的人物资料，直接读取 [角色形象](../jc-juese-sheji/SKILL.md)，一次完成骨相、五官、身材、造型设计与三格排版，按项目比例套它自带的 9:16／16:9 模板，写成完整三格人物设定图提示词，只保存 character_format；不单独生成或保存 character_asset（角色生图提示词）。场景、道具、声音照常。宿主用三格图作为视频的角色参考图。
  - 指令写明“本集已有进度到某阶段”时（例如宿主用 H3 已定稿的进度派生出 Seedance 进度到 engineering），按「输入与恢复」先用该阶段原 outputs 保存 running 进度，再续做之后的阶段；项目资料、资产与工程剧本两条路线共用，不重写，只按本路线写视频提示词。
- **【全自动成片·第N集·审片修改】**：用户看完本集视频写了修改意见（按段号或整集）。只改意见涉及的内容，中途不提问：
  1. 意见涉及剧情、台词、表演、镜头顺序或时长时：先用原工程剧本以 `{"stage":"engineering","status":"running","outputs":[原工程剧本],"duration_seconds":原值}` 重开进度，read 工程剧本、本集来源剧本与相关人物小传后按意见修改并保存 engineering_script，再保存 engineering 进度（时长变了就写新的 duration_seconds）。
  2. 只涉及画面表现（运镜、光线、动作细节、构图）时：工程剧本不动，直接以 `{"stage":"prompts",...}` 从 prompts 重开。
  3. prompts 阶段只重写受影响的片段；未受影响的片段保持原文件一字不改（宿主按提示词指纹只重出改动的段），segments 仍按整集完整登记，再保存 complete。
  4. 修改需要本集未登记的新资产时不硬改：以 blocked 说明需要新增哪个资产，由用户在自由创作里补齐。

## 输入与恢复

1. 调用 wiki_read_guidance(overview)，沿真实index定位当前Wiki；没有库时第一次归档按共享合同创建。
2. 剧本使用用户引用的可读文件或已保存的分集剧本。短剧改编生成的分集剧本最前面有文件头（`---`之间，列出所属事件和本集出场的角色、场景、道具的资产链接），文件头是资产链接，不是剧本内容：不写进工程剧本，但出场人物小传、场景、道具直接按它读取（资料目录默认是 `项目资料/场景`、`项目资料/道具`，短剧布局或旧库可能叫 `场景说明`、`道具说明`，按实际索引读取）。粘贴输入先用source_material原样截取保存，不改写来源。多集分别执行，不能把全季当作一集。
3. 查 `制作流水线/<H3或Seedance>/第x集进度.json`。有进度就读取实际已存文件，先用当前已完成阶段及原outputs保存running checkpoint以恢复运行态，再继续未完成阶段；来源或前置产物改变时从plan重新核对，不复用过期下游。用户要求续做时不要自动覆盖已经完成且未受影响的其他集。
4. 每个阶段先实际保存产物，再保存pipeline_checkpoint。只有回执成功才推进；索引警告先修复/明确报告，不能报整个Wiki归档完成。

## 固定执行阶段

- **plan**：确认模型、集号、剧本路径和已确认比例/风格，保存初始checkpoint。不可生成媒体。
- **materials**：实际读取 [项目资料](../jc-xiangmuziliao/SKILL.md) 并完成本集范围的故事梗概、人物小传、场景、道具及必要背景/规则（资料目录默认是 `项目资料/场景`、`项目资料/道具`，短剧布局或旧库可能叫 `场景说明`、`道具说明`，按实际索引读取，两种目录名都算资料）；道具只建符合其“道具判定标准”的剧情道具与角色标志物，日常物件写进场景的陈设；群众与无独立戏份的配角写进场景的“人群”，不建人物小传；需要完整来源时实际读完，不能从简介冒充全文。分别保存对应类型。
- **style**：用户已确认比例/风格直接填入film_style，不重新推荐另一套方向；缺明确风格才按 [项目风格](../jc-film-style/SKILL.md) 从故事梗概和本轮消息生成并等待必要确认。
- **assets**：只为需要跨镜保持一致的实体建资产（见「参考图按段决定」），没有就以空 outputs 保存本阶段。项目风格资产清单已标“参考图”的按它执行：标“文字带过”的不建（程序会拒绝），本集出现的“需要”项照建；清单外的新实体按同一规则判断。先read影片比例与风格；每个实体先read对应人物资料、场景说明或道具说明，再按真实实体分别读取 [角色形象](../jc-juese-sheji/SKILL.md)、[场景](../jc-scene-prompt/SKILL.md)、[道具](../jc-prop-prompt/SKILL.md)，有发声角色时读取 [角色声音](../jc-shengyin-sheji/SKILL.md)。场景说明记有“人群”的，每个群体按 [人群群像](../jc-renqun/SKILL.md) 保存一份 crowd_asset（跨集复用，已有则不重做）。本集用到人物小传“造型表”里尚未建立的造型时，按 [服装](../jc-fuzhuang-prompt/SKILL.md) 同阶段保存 costume_asset 与 character_look（entity_name 均为“角色名·造型名”），宿主先出身份图与服装图再融合成该造型的三格参考图；已有造型直接复用。各自输出并保存独立提示词；不生成图片，不虚构已存在参考图。
- **engineering**：先read本集来源剧本、比例/风格及出场人物小传正文，再读取 [工程剧本](../jc-gongchengjuben/SKILL.md)，交付影片比例/风格、整集资产清单和逐镜正文。按该Skill的体检条款核对本集资料：人物小传缺长相、场景缺空间与光、道具缺形制时，先按对应设计Skill补齐并保存该资料，再逐镜改编；只做本集，删掉不推动剧情的内容、把动作与打戏扩写到节拍级。提前按选定模型上限设计自然切点，记录整集时长预算。已确认声音稿存在时继承，不额外增加未经要求的内容。
- **prompts**：H3实际读取 [H3](../h3-prompt-writing/SKILL.md)，Seedance实际读取 [Seedance](../jc-seedance/SKILL.md)，每段不超过 limits.max_seconds（未给时30秒）。只有用户选择分镜路线时才额外使用对应分镜Skill。每段按本段需要保持一致的入画资产生成有序参考图占位，即使图片尚未生成也写全，本段没有这类资产就不写占位，正文引用同一编号，提交正文不写待上传等操作备注；逐段read工程稿/对应分镜和所需资产正文，不用刚生成的聊天内容代替。逐段完整转写，不加速对白、不删动作、不机械截断；片段承接角色、位置、持物、场景、光线与声音状态。每段时间从0起。工程镜映射、全片时间与未实测的预算只记在工程稿/进度中，不写入Seedance提示词。
- **complete**：核对所有阶段文件仍存在、视频段连续覆盖工程总时长、格式与参考占位一致，保存完成checkpoint，再报告真实路径与时长预算。

模型上限是产品分段策略，不代表任意供应商都支持该时长。若单句对白/动作无法在上限自然完成，保持内容因果重新拆镜；无法兼容时明确报告冲突，不谎报短时长。

## 进度调用合同

使用既有wiki_save_artifact，artifact_kind="pipeline_checkpoint"，episode_number与video_model必填。content传JSON字符串。阶段严格为plan → materials → style → assets → engineering → prompts → complete。

- plan：`{"stage":"plan","source_path":"项目内真实剧本路径","outputs":[]}`。全自动指令给出 `"limits":{...}` 时原样写入 plan（如 `"limits":{"max_seconds":28,"max_refs":6}`）：程序据此校验每段时长与参考图张数，工程分段与视频提示词都按它设计；不写时两条路线都默认30秒。
- 中间阶段：`{"stage":"materials","outputs":["wiki/项目资料/故事梗概.md", "其他真实路径"]}`；每阶段只登记已成功写入的实际文件，不传示例占位。
- engineering另传 `duration_seconds`（整集时间预算）。
- prompts另传 `segments:[{"path":"wiki/剧本/视频提示词/Seedance/第1集001视频提示词.md","start_seconds":0,"end_seconds":28,"refs":["角色/顾云舟","场景/石道"]}, ...]`，使用整集连续时间、实际模型/集数/序号，末段终点等于工程总时长；outputs包括每段视频提示词。每段必传refs（纯文生段为 `[]`）：按参考图编号顺序列出资产ID（`角色|场景|道具/实体名`，即assets阶段登记的资产），数量不超过 limits.max_refs。Seedance：数量等于本段@图行数，第N个ID的实体名须出现在@图N行。H3：refs 不为空用 Ref2VA，`<Picture N>` 从1连续编号，数量等于本段不同的 `<Picture N>` 个数，第N个ID的实体名须出现在含 `<Picture N>` 的行（subject_definitions 逐行定义）。refs只记在进度里，不写进提示词正文。
- complete：`{"stage":"complete","outputs":[]}`，其他事实由程序继承校验，不手造files或source_hash；程序将最终status写为completed，不能同时blocked。
- 已完成的集只能从 engineering 或 prompts 重开（审片修改），更早的阶段要从 plan 重新规划。

程序拒绝跳阶段、缺文件、上游已变化、时长超限与片段漏覆盖；被拒绝后修复具体问题再试，不能以普通write篡改进度绕过校验。若缺资料不能继续，以当前已完成阶段的outputs记录 `status:"blocked", reason:"具体缺项"`，然后说明暂停原因。用户取消立即停止，重新明确继续后才恢复。

自动执行不逐步重复索要保存许可，不在中途只总结“下一步会做什么”就结束。修改目标文件先读取原文，其他内容保持；最终不得宣称已生图、已生成视频或已完成实测时间验收。
