# 资产脑暴、插入与续做

资产候选先帮助用户决定叙事用途与身份，再用专业技能落实外观和格式。只补当前片段所需内容，不把一个灵感扩成整套资产制作。

## 按资产职责交接

| 用户要决定什么 | 候选重点 | 选定后使用 |
| --- | --- | --- |
| 角色 | 关系、目标与行为差异；外观设计与剧情身份分别标记 | [角色形象](../../jc-juese-sheji/SKILL.md) |
| 已选人物图的版式 | 复用实际身份，选择画幅与参考板需求 | [角色格式](../../jc-juese-geshi/SKILL.md) |
| 场景 | 空间、动线、视线、出入口如何承载当前冲突 | [场景设计](../../jc-scene-prompt/SKILL.md) |
| 道具 | 谁持有、何时可见、如何触发或改变当前节拍 | [道具设计](../../jc-prop-prompt/SKILL.md) |

每个候选给一个具体描述、一条叙事用途与对台本的影响。遵守已定时代、媒介、画幅和人物身份，不凭空替换既有角色或地点。项目资料技能负责整理来源事实，不用它把脑暴候选伪造成原作资料。

用户选择的是文字设计时，标记“文字方案已选”；只有用户选定实际图片才能称“参考图已定”。临时人物甲／乙、卧室与普通陈设可用于先写戏；后补图仅校准可见结构，隐藏布局和未显示部位仍不能凭图断言。

## 写到一半插入灵感

用户说“床头应该放一张孩子的画”时：

1. 记住当前节拍、人物进入状态、已选对白和待回应的位置。
2. 核对已有孩子、画的来源与持有等事实。项目尚未确定孩子是否存在，就把“家中孩子画的／亲戚孩子送的／未来育儿计划中的画”作为互斥提案，不能默认成立。已有事实明确没有孩子时，不把画自动解释成亲生孩子的作品。
3. 给少量候选用途，例如日常痕迹、引出共同记忆、引发对照顾责任的质问；每项写出人物如何注意到画、具体动作或台词以及下一步影响。
4. 用户选定后按请求交付道具提示词，或只登记文字设计继续写戏。做完资产回到原选择点，不重新启动风格与角色问卷。
5. 若影响之前镜头，指出具体节拍／镜头，按用户授权局部更新并检查后续承接。纯外观补全不重写已确认剧情。

同轮交付专业资产并恢复脑暴时，将资产提示词放在独立内容块，块内完整遵循对应技能格式；块后简短提示原写作位置并继续待选节拍。专业技能的“只输出提示词”约束其资产产物，不阻止本技能在块外完成用户已要求的续做。仅请求独立资产时不额外附上剧情。

用户明确要生图时遵循漫剧入口异步提交合同；返回任务号后可继续不依赖图片的文字任务。需要实际图作为身份或空间依据时等待用户选图，不以自行想象的“生成结果”继续。

## 续做记录

持久对话内保留简短状态：当前目标与片段、已选节拍、暂定设计、待选问题、人物／空间结束状态、用户委托代选范围、相关正式产物路径。候选和原文只保留一处依据，不反复复制整套资料。

中断后从真实记录恢复，先简短提示当前位置，再给当前未定节拍的选项。指代唯一的“A”“继续”直接承接；有多组候选时澄清所属选择点。新任务不自动继承上一任务的委托代选授权。

用户明确要跨对话保存脑暴过程时，遵循 wiki-memory 的唯一 Wiki、读取目标与普通写入规则，在独立记录中标记已选／暂定／候选并链接正式资料。讨论本身不触发建库，不用正式剧本归档类型存候选。已有制作进度只记录当前位置及记录链接，正式项目事实仍保存在其权威页面。不能确认保存位置时询问位置；工具未可用时交付可复制记录并如实说明未保存。
