# Skill 创建器

创建能提供实际帮助、且不会限制无关任务的 Skill。假设模型已经具备通用能力，只写会改变它判断或提升任务质量的内容；保留用户意图和范围，删掉重复、泛化或猜测性的规则。

## 工作方式

1. 从当前对话提取目标、触发场景、用户已作出的选择和成功标准。只有缺失信息会实质改变结果时才追问。
2. 在当前项目文件树创建草稿目录 `.raw/jc-media/文档/skill-<skill-name>/`，用文件工具写入 `SKILL.md` 和确实需要的配套资源。简单 Skill 只保留 `SKILL.md`。
3. 编辑已有 Skill 时，按准确 ID 调用 `skill_creator_load_installed_skill` 读取可编辑版本，再在项目内建立草稿；不要直接覆盖已安装文件。
4. 指令写清目标、适用场景、真实约束和必要的操作方式。详细参考资料按需放入 `references/`；可重复且能明显提高可靠性的自动化才放入 `scripts/`。
5. 完成草稿后调用 `skill_creator_validate` 检查必要格式和包内路径，展示草稿内容及需要用户决定的地方。这个结构校验不要求运行 Skill 或模拟任务。
6. 草稿可供安装时调用 `save_skill` 准备安装卡。安装卡由用户点击后才安装；准备安装卡不等于已经安装。
7. 根据用户对草稿的反馈直接修改，并重新做必要的结构校验。

## 默认不做测试

创建或修改 Skill 时，不主动创建 `evals/`、测试提示词或基准，不运行 `run_skill_tests`，不做新旧版本比较，也不打开评审器。只有用户明确要求测试、评估或比较时，才使用对应工具。

## Skill 内容与目录

- `name` 使用简短的小写字母、数字和连字符；`description` 简洁说明用途和适用场景。
- `SKILL.md` 只保留共享目标、必要约束和清楚的执行指引；按需再添加 `references/`、`scripts/`、`assets/` 或 `agents/`。
- 不为简单 Skill 添加空目录、占位文件、重复说明或无调用者的资源。修改已有包时，先看清配套文件是否仍被正文或宿主使用，再决定是否保留。
- 使用祈使句和具体表达。针对开放任务给出目标与判断标准；只有偏离会造成实际问题时才规定固定步骤。
- 保留必要的安全、授权和外部操作边界。用户授权某项任务，不代表额外的安装、发布或外部写入也已授权。

## 韭菜盒子运行方式

- 草稿只写入当前项目的 `.raw/jc-media/文档/skill-<skill-name>/`，使用项目文件工具；生命周期工具统一传同一个 `draft_path`。
- 用户要求修改「我的 Skill」时，用 `skill_creator_load_installed_skill` 按 Skill ID 读取。草稿可见后用 `save_skill` 准备安装卡，由用户确认安装。
- 不假设 Web/iOS 可以访问桌面本地目录或运行本机脚本。配套脚本只有在当前平台提供相应执行能力且任务确实需要时才运行。
