# Skill 创建器

用于创建新 Skill、修改已有 Skill，并把它整理成宿主可以发现和加载的标准目录。

## 工作边界

先判断用户是在创建新 Skill、修改已有 Skill，还是只想讨论方案。不要因为普通写作、普通代码修改或一次性任务自动创建 Skill。

创建或修改前，先确认这些信息；能从当前对话明确推断的就直接复用：

1. Skill 要完成什么任务。
2. 哪些用户请求或上下文应该触发它，哪些相似请求不应触发。
3. 期望产物和输出格式。
4. 是否需要脚本、参考文档、模板或其它资源。
5. 成功标准，以及会影响安全、权限、路径或外部副作用的边界。

用户只想构思时，不要擅自写文件。用户已经给出清晰要求时，直接执行，不要重复询问已知信息。

## 标准目录

每个 Skill 是一个目录，至少包含 `SKILL.md`：

```text
skill-name/
|-- SKILL.md
|   |-- YAML frontmatter
|   `-- Markdown instructions
|-- agents/       可选的宿主界面元数据
|-- scripts/      可重复、确定性的辅助脚本
|-- references/   只在特定模式需要的参考资料
`-- assets/       输出所需的模板、图标或其它资源
```

目录名和 frontmatter 的 `name` 必须使用小写字母、数字和单连字符，且保持一致。不要为了看起来完整而创建空目录、占位文件、README 或重复说明。

## 编写 SKILL.md

frontmatter 至少包含 `name` 和 `description`。description 必须同时说明能力和触发场景；把发现条件放在 description，不要只写一个宽泛的主题名。可保留宿主支持的可选元数据，但不要臆造工具依赖。

正文只写会改变模型决策的内容：

- 任务目标和适用边界。
- 必须保持的事实、格式、命名和权限约束。
- 根据输入选择工作模式的规则。
- 明确的输出结构和验收条件。
- 需要时再读取的 references、scripts 和 assets。

不要重复宿主已经强制执行的通用政策，不要把一次失败经验扩展成所有场景都必须遵守的僵硬规则。解释关键约束为什么重要；只有会造成真实错误、数据损失或权限越界时才使用绝对措辞。

保持入口精简。共享规则放在 `SKILL.md`，较长的模式说明放进 references，并在正文中说明何时读取。不要为了达到固定行数增加内容。

## 创建流程

1. 从当前对话提取目标、输入、输出、工具、步骤和用户已经做过的修正。
2. 补齐会影响结果的缺口，尤其是边界条件、文件格式、命名和权限。
3. 先拟定最小可用的 Skill 结构，避免过早添加脚本和资源。
4. 编写 `SKILL.md`，再从触发、流程、输出和异常边界审阅一遍。
5. 用 `scripts/quick_validate.py <skill-directory>` 校验 frontmatter、命名和未完成占位符。
6. 对新增或修改的脚本实际运行最小验证；纯说明性 Skill 不强行增加评测闭环。
7. 向用户说明完成了什么、保留了哪些边界，以及还需要用户确认的事项。

## 修改已有 Skill

保留原 Skill ID、目录名和已有资源。先读取目标 Skill 的 `SKILL.md`，必要时再读取相关 references、scripts 或 assets。只改用户要求和确实需要修正的部分，不要顺手重写无关内容。

在桌面端，用户从 Skill 管理入口发起修改时，输入中会提供 Skill 目录的绝对路径，并授予本次会话相应的文件权限。使用该路径读取和修改目标文件；不要猜测路径，不要写入其它 Skill，也不要把修改偷偷复制到临时目录。

新建 Skill 时，使用用户指定的 Skill 根目录。若用户没有给出路径，先询问目标位置；不要默认写入 Claude、Codex 或其它提供商专用目录。

## 资源与脚本

只有在重复工作或确定性要求足以抵消维护成本时才添加脚本。脚本必须：

- 使用当前机器可获得的明确运行时，不假定安装了某个提供商 CLI。
- 通过参数接收路径，不把用户目录、项目目录或临时目录硬编码成唯一方案。
- 对缺失文件、权限错误和无效输入给出清晰错误。
- 在交付前用一个最小真实样例验证。

`agents/openai.yaml` 仅作为可选的界面元数据使用。需要修改它时，先读取 `references/openai_yaml.md`，只修改确实需要的字段；不要把 OpenAI、Claude 或其它提供商的运行时名称当成宿主工具依赖。

## 验收清单

交付前确认：

- `SKILL.md` 存在且 frontmatter 可解析。
- `name`、目录名和索引 ID 一致。
- description 能准确触发目标任务，并排除最相近的误触发场景。
- 正文没有引用当前会话不存在的专用工具、CLI 或编排机制。
- 所有被正文引用的资源确实存在。
- 新增脚本已做最小运行验证。
- 没有把 `.DS_Store`、`__pycache__` 或 `.pyc` 纳入 Skill 包。
- 没有未经用户同意覆盖真实 Skill 或其它项目文件。

## 宿主适配

本 Skill 面向韭菜盒子记忆工作台。使用宿主当前可见的文件工具、Skill 选择和模型能力，不假定 `claude -p`、Codex 专用命令、MCP 服务或其它提供商 CLI 存在。

当前桌面流程以用户提供的绝对路径和会话文件权限为准：

- 修改已有 Skill：在授权的 Skill 目录内读取和更新文件。
- 创建新 Skill：在用户授权的 Skill 根目录下创建新的小写连字符目录。
- 需要用户查看或进一步编辑时，保留完整目录结构和清晰路径。
- 没有得到路径或写入授权时，先询问，不用临时目录冒充最终草稿位置。

不要调用 `skill_creator_commit_draft`、`skill_creator_load_installed_skill`、`save_skill` 或其它未在当前会话工具面中明确提供的工具。不要输出伪造的工具结果、安装令牌或安装卡。若宿主明确提供后续安装流程，按宿主返回的真实结果继续；否则只交付已校验的 Skill 目录和路径。

```commands
用途：[描述Skill要做什么]
触发词：[逗号分隔]
把标准 SKILL.md + references/ + scripts/ + assets/ 结构写进用户指定的 Skill 根目录。
修改已有 Skill: 请用 Skill 缔造器帮我修改 Skill「[Skill名]」：
修改要求：[描述要改什么]
保持 SKILL.md 格式规范。
```
