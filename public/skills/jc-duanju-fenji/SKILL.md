# 事件标注：读一遍，程序按时间切集

短剧改编分两步：**先按内容规划时间（本Skill），再按时间改编剧本**（[工程剧本](../jc-gongchengjuben/SKILL.md)）。本步**只标注、不改写，不新增任何文字**：模型读一遍、把判断都标清楚，切集、删减标记、拼接由程序完成。

先读取本轮要求、wiki_read_guidance(overview)、已有事件文档和人物等资料，再用read读本段原文（每次只读指令或用户指定的章节，一般20章一段；章节点目录时读对应的章节点文件，不读整本原文）。原文识别不到任何章标题时，整篇按一个单元处理，章标题写`全文`。

## 一遍做完

读每一章时同时完成：

1. **资产**：按[项目资料](../jc-xiangmuziliao/SKILL.md)写或更新人物小传（不限于人类；造型表记从哪一行开始、原文依据；声音特征；别名）、场景（含陈设、人群）、重要道具（一档一件）、世界规则（含能力的视觉规则）、故事梗概，以及[项目总纲](../jc-duanju-cehua/SKILL.md)（主题与事件摘要）。
2. **事件文档**：一个完整的冲突（起因、对抗、结果）是一个事件。用wiki_save_artifact(adaptation_event)保存，entity_name为“E序号_一句话概述”，如`E03_噗叽偷食被收服`，序号全书连续。写章节与行号范围、涉及的人物场景道具（链到档案）、冲突、爽点和回合表。
3. **回合**：事件内**局势每变化一次是一个回合**（新危险出现、新信息揭开、谁占上风、做出选择、爽点兑现）。拆集看内容，不看字数：一个9000字的章节只有一个冲突，可以只是一集；一千字里有三个冲突，就是三个回合。回合是切集的最小单位，程序只在回合边界切（回合太长时才在回合内按行切）。每个回合标：描述`desc`、结果`result`（局势变成什么样）、动作单元`units`、档位`tier`、`hook`（结果是问题已抛出、答案未给，适合作集尾）、`peak`（本事件最想让人看到的高潮，改编时可提前作冷开场）、`flashback_sources`（可闪回的原文行范围，如这场战斗之前埋下的伏笔）。
4. **跳过段 skip**：逐句问——**删掉这一句，观众会少知道什么、少感受到什么？** 都不会就放进`skip`（设定介绍、重复、凑字数的内容），必须写`reason`。后文会用到的伏笔不删；好的小说可以一句不跳。跳过按整行（自然段）进行，一段里只有半句废话时整段保留。没有被事件覆盖也没有跳过的行，程序会列进分集清单的`gaps`，不会再静默丢弃。

## 时间账

内容都占时间：**打斗动作和对白一样占时间，描写是画面，与字数无关。**

- **对白**：程序按引号内的字数计，每分钟240字（每秒4字），每段对白再加0.5秒停顿。不用你估。
- **动作**：按动作单元数量估，写进回合的`units`（名字→个数）。一个镜头约3–5秒，装1–2个单元；下表取中值，范围见括号。

| 单元 | 说明 | 秒（范围） |
| --- | --- | --- |
| 快招 | 一次出拳、踢击、斩、射箭 | 2（1.5–3） |
| 攻防 | 出招加格挡、闪避或受击反应 | 4（3–5） |
| 技能 | 起手、光效变化、激发、命中、反应 | 8（6–10） |
| 大招 | 大招或进化展示：蓄力、特写、全场反应、结果 | 15（10–20） |
| 走位 | 跑动、跳跃、换位、追逐 | 3（2–4） |
| 反应 | 受击倒地、表情特写 | 2（1–3） |
| 全景 | 战场全景、环境空镜 | 3（2–4） |
| 停顿 | 对峙、蓄势、情绪停顿 | 3（2–5） |
| 面板 | 系统提示、属性面板弹窗，每条 | 2.5（2–3） |
| 闪回 | 一段回忆插入 | 6 |

- **打斗按回合数**：每一方一次有效攻防是一个回合内的几个单元；坏人占上风、好人占上风是**两个回合**（局势变了），不要写成一个。
- **重要度档位 `tier`**：计划时长＝自然时长（对白＋动作单元）×系数。**压缩 0.6**（过场、铺垫）、**如实 1**（默认）、**细写 2**、**决战 3**（最多展开3倍）。细写和决战是最重要的决策，**必须写`why`**：这一段为什么值得展开（改变主角命运、全书最强对手、后文反复回扣……）。重要的决战可以细写成很多集（动作、反应、旁人视角、原文里已有的回忆），小事件一集带过。
- **`single`**：一个回合自然时长超过平台上限180秒，几乎一定含多次局势变化，程序会拒绝并要求你拆；确属一次连续冲突才标`"single":true`并写`why`。
- 第1集特别重要（可冷开场）：把后文最抓人的画面选作`peak`，改编时程序和你都能用上。

## 保存标注

本段读完后保存一份wiki_save_artifact(adaptation_annotation)，entity_name写这几章的范围（如`第001-020章`），content为JSON：

```json
{"rhythm":{"name":"大场面奇幻","min":90,"target":120,"max":150},
 "planned_through":"第20章 完整标题",
 "events":[{"event":"E03_噗叽偷食被收服",
   "start":{"chapter_heading":"第3章 完整标题","line":12},
   "end":{"chapter_heading":"第5章 完整标题","line":40},
   "rounds":[
     {"chapter_heading":"第3章 完整标题","line":12,"desc":"食物不见了","result":"噗叽被怀疑","units":{"停顿":1,"走位":2},"tier":"如实","hook":false},
     {"chapter_heading":"第3章 完整标题","line":15,"desc":"追到树洞","result":"主角占上风","units":{"攻防":3,"大招":1},"tier":"细写","why":"主角第一次使用新能力，后文反复回扣","hook":true,"peak":true,
      "flashback_sources":[{"chapter_heading":"第2章 完整标题","start_line":8,"end_line":10}]}],
   "skip":[{"chapter_heading":"第3章 完整标题","start_line":20,"end_line":24,"reason":"世界观设定，已写进世界规则"}]}]}
```

- 行号就是read显示的行号；位置须在本批章节的正文内，回合、跳过段须在事件范围内。**回合要覆盖整个事件**：第一个回合从事件起点开始，之后各回合起点依次递增，每个回合管到下一个回合起点之前。来源有多个文件时，可在位置里加`source_path`区分。
- `rhythm`首次保存时必带（按所选短剧风格，见下）；`min`、`target`、`max`是每集的秒数，`max`不得超过平台上限180秒；之后可省略。
- 段末还没有结果（未完）的事件标`"unfinished":true`，下一段先读它的事件文档再续写，整体重交（同名事件会被替换），不要另起新事件。一批读完仍未完的事件照样标unfinished，下一批会从它的起始章开始读；如果它从本批第一章就开始（长过一整批），在自然转折处拆成两个事件。

程序在保存标注的同一次调用里：按每个回合的计划时长（对白秒＋单元秒，乘档位系数）和所选风格的每集秒数，为每个事件定集数，把切点落在回合边界（优先落在`hook`回合的末尾，避免碎片集），生成每集的切分记录、**切分卡**（`改编方案/切分卡/第NNN集.md`：回合、计划时间、峰值、结尾钩子、可闪回素材）和原文直出的`项目资料/分集剧本/第N集分集剧本.md`，集号按事件顺序连续，结果记在`改编方案/分集清单.json`（含`gaps`、`heavy`细写与决战清单、`warnings`）。回执里会写“已组装第a–b集”；向用户报告时一并说明有哪些回合被标成细写或决战。

分集剧本最前面有一个**文件头**（`---`之间），只放链接：`event`（所属事件）、`characters`、`scenes`、`props`（本集正文里出现的角色、场景、道具，按首次出现排序，别名也算）。程序从事件文档链出的资产里挑，事件文档没有链接时按名字在全库资产里找，所以事件文档里要把涉及的人物、场景、道具链全，档案里写清别名（姓名/称谓/别名行）。这一步生成的**正文只有原文**，一个字不改；改编由下一步完成。

## 三种短剧风格

| 风格 | 每集秒数（min / target / max） | 适合 |
| --- | --- | --- |
| 快节奏爽剧 | 60 / 75 / 90 | 逆袭、打脸、都市、系统流：一集一个爽点，切得密 |
| 标准剧情 | 75 / 90 / 120 | 多数网文改编、情感、悬疑：冲突与情绪均衡 |
| 大场面奇幻 | 90 / 120 / 150 | 玄幻、仙侠、末世、种田进化：一场大战或一次进化可独占一集 |

依据：平台单集不超过3分钟、建议约90秒，每20–30秒一处情绪节点。全自动时风格由用户在确认卡选定，指令里会给出rhythm；自由改编时按用户选择，用户没说就问一次。

## 事后调整

- 用户说“E03改成4集”时，保存一条重切标注（entity_name如`调整`）：`{"recut":{"event":"E03_噗叽偷食被收服","episodes":4}}`。程序重组这个事件及之后各集，被重切的集恢复为原文直出，集数变少时多出来的旧集由程序清理。
- 样集后用户觉得整体偏快或偏慢时，保存`{"replan":{"pace":1.2}}`（pace是动作单元秒数的系数，默认1，范围0.5–2）：程序按新系数重新切集，已改编标记清空，需要重新改编。

用户明确要求改写成完整剧本（场次、说明书式）时，才使用[工程剧本](../jc-gongchengjuben/SKILL.md)里的“完整剧本”一节。普通模式明确请求原创分集时保留[独立写作旧规则](references/独立写作旧规则.md)，本改编流程不加载。
