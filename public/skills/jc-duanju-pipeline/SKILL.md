# 短剧改编流水线

本入口只有改编这一条流程。用户给出原文附件/路径与基本思路，要求改编或连续完成时，直接组织下面步骤；指定只做某一步/章/集时尊重范围，不强跑全书。已有明确思路不再给原创/优化三选一。来源或关键改编目标缺失时一次合并询问必要项，其余按授权连续执行，不逐步询问保存许可。

## 来源与恢复

先wiki_read_guidance(overview)，沿真实index确定唯一Wiki根。用read读取用户实际原文；附件优先复用现有导入后的可读文本/Markdown副本。不是所有PDF/Word都可直接read，无法读取或提取时说明实际缺项，不虚构转换工具。粘贴原文用source_material原样截取；附件/路径文件先read，再用source_material、work_name和content的JSON `{"source_path":"已read的原文路径"}` 原样存入`原始材料/<作品>/原文.md`，不传source_block。后续source_paths、chapters和切分统一引用这份持久副本，并实际read；入库不等于通读。文件原件保持原样，不用模型复写原作。路径在项目外时也先使用现有read权限读取，不能用归档工具绕过沙箱。

读取`改编方案/执行进度.json`及当前实际文件；来源或上游变化先重新核对，不复用过期下游。冷恢复先按原阶段登记当前outputs以恢复运行态，再处理未完成部分；原作在项目外时本轮先read原路径，不能仅凭旧进度授权访问。未完成集稿实际读取核对，不能把同名文件存在当作质量通过。

## 逐步执行

1. **source**：确认真实原作、用户思路与目标章范围，保存初始进度。
2. **materials**：实际读取[项目资料](../jc-xiangmuziliao/SKILL.md)，按本次章范围提取原作梗概、全部必要人物关系/动机/认知、五官/体型/服装、背景规则和场景道具。原文明示、推断、未交代分清，人物造型变化记来源章，不设计原作未给出的五官。research_version=original。
3. **scheme（改编规划书）**：read原作梗概与必要人物等资料，实际读取[项目总纲](../jc-duanju-cehua/SKILL.md)写主题、发动机、人物、必要设定和大结构，人物性格写进改编版人物小传；再read总纲和本批原文，实际读取[事件筛选与分集规划](../jc-duanju-fenji/SKILL.md)写分集表、删减清单和倒叙说明。分集规划按“每次读10–20章、追加保存”推进，直到本批读完。两份都保存后，以`status:"review"`保存scheme进度并停下，向用户汇报：主题、两台发动机、篇章结构、分集表（每集讲什么、冲突、爽点、钩子）和删减了什么。用户确认或提出修改并改完后，再以running保存scheme继续。用户在本次请求中明确说不用审，才可以不停。

**分批推进**：长篇每一批（如100章）都走一遍source→complete，每一批的规划书都以review暂停给用户审。下一批开始时，source传新的`chapter_range`；集号接着上一批往下排（episodes不必从1起）；先read已有总纲和分集规划，修订大结构和人物变化，把新一批的分集追加到分集规划，不另起一份。
4. **cuts**：按已确认的分集规划，每集保存adaptation_cut多段切分（可跨章、倒叙片段标flashback），核对回执。
5. **writing**：逐集read总纲、分集规划、该集真实切分、必要人物/场景/道具和已有目标稿，实际读取[逐集改编](../jc-duanju-xiezuo/SKILL.md)。每集按“开头—冲突/爽点—钩子”写；动作优先、对话其次、OS最后；人物按各自性格说话；写清场景、人物造型和剧情道具，打戏逐招写清；原文没写的外形按设计Skill创作。只在本集切分内扩缩写，不增事件、能力、胜负。每集自检实际修正后独立保存，再补写本集新出现的改编版资料，核对回执再继续。
6. **complete**：核对全部集稿、来源/切分/规划未变化，保存完成进度后报告真实路径。不得把哈希或格式检查称为文学质量验收。

## 全自动改编

用户选了“全自动·改编”时，程序按批次逐步发指令，每条指令是一个新回合。只做指令里的那一步，做完保存对应进度就结束本回合；中途不向用户提问、不等待确认，确实无法继续时以当前有效阶段保存`status:"blocked"`并写明原因。每回合先read完成这一步需要的文件，不凭上一回合的聊天内容。

- **【全自动改编·入稿】**：只把用户给的原文原样入库（source_material），并以默认范围保存source进度，让程序识别章节；不整理资料、不规划。
- **【全自动改编·资料】「起」至「止」**：先以指令给的chapter_range保存source进度，再整理这批章节的原作资料，保存materials进度。
- **【全自动改编·规划】「起」至「止」**：读这几章，筛选事件、编集，追加到分集规划（第一段先写或修订项目总纲及改编版人物小传）；保存scheme进度，`planned_through`写这一段最后一章的完整标题。指令注明“本批最后一段”时，按指令以review或running保存。
- **【全自动改编·切分】**：按已确认的分集规划，从指令给的集号起保存本批各集adaptation_cut，再保存cuts进度。
- **【全自动改编·第N集】**：写第N集剧本并补写本集新出现的改编版资料；不保存writing进度。
- **【全自动改编·收尾】**：保存writing进度（登记本批全部剧本及写作中改动过的改编版资料），再保存complete进度。

## 进度合同

使用现有wiki_save_artifact，artifact_kind=adaptation_checkpoint，content传JSON，无需video_model或episode_number。阶段顺序固定source→materials→scheme→cuts→writing→complete；outputs只填真实成功保存的当前阶段文件。

- source：`{"stage":"source","source_paths":["真实原文路径"],"outputs":[]}`。默认范围为文件中全部可识别章节；改连续多章（如每批100章）时传`chapter_range:{"source_path":"真实路径","from":"第1章 完整标题","to":"第100章 完整标题"}`，程序展开为逐章；不连续的章传`chapters:[{"source_path":"真实路径","chapter_heading":"原文完整章标题"}]`，两者只传一个。识别不到章标题的短篇由程序登记为`全文`。
- materials：`{"stage":"materials","outputs":["wiki/项目资料/原作/故事梗概.md","本次其余实际资料路径"]}`。
- scheme：outputs包括`wiki/改编方案/项目总纲.md`、分集规划（新库`wiki/改编方案/分集规划.md`，旧库按真实回执）及实际改编资料；等待审阅时加`"status":"review","reason":"等待用户审阅规划书"`，程序不会自动催促继续。
- cuts：`{"stage":"cuts","episodes":[1,2],"outputs":["wiki/改编方案/分集切分/第001集原文.md","wiki/改编方案/分集切分/第002集原文.md"]}`。episodes是本次连续目标集号，不一定从1起。程序检查除倒叙外按原文顺序、集间不重叠，并在进度中写出`unused`（未使用的原文行号），向用户汇报时与删减清单对照。
- writing：登记所有目标集的实际`wiki/剧本/第001集/分集剧本.md`等，以及写作中新增或更新的`wiki/项目资料/改编版/**`资料；改过的改编版资料必须在本次outputs中重新登记，原作资料、切分和总纲在写作阶段不可改。
- complete：`{"stage":"complete","outputs":[]}`，程序写status=completed。sources、files和chapters等事实由程序继承，不手造哈希。

不能继续时在当前有效阶段登记原outputs与status=blocked、reason具体缺项；不能报完成。用户取消立即停止；无进展时具体报告，不无限循环。不用普通write篡改切分/进度绕过校验。
